## 2. ★v3 를 복제하지 않는다 — 이건 v3 와 다르다

| | 왜 |
|---|---|
| v3 가 v1·v2 를 복제한 이유 | **비교 대상**이라서. 빌려 쓰면 그쪽이 바뀔 때 이쪽이 조용히 바뀌어 비교가 오염된다 |
| rudder 가 v3 를 복제하지 **않는** 이유 | **측정 대상**이라서. 복제하면 사본을 재게 되고, v3 가 바뀌어도 옛 v3 를 계속 재게 된다 — 측정이 틀린다 |

대신 계약을 시험이 지킨다:

| 시험 | 무엇 |
|---|---|
| `test_no_v3_mutation.py` | rudder 가 v3 를 **고치지 않는다** (정적 + 실행 중 + 전역 상태) |
| `test_runner_identity.py` | rudder 러너가 v3 `run_episode` 와 **같은 Φ·거래·결정** |

## 3. 무엇을 어떻게 재나

```
하루를 굴린다 ──▶ t0 에서 갈라 두 세계를 H=3시간 굴린다
                     정책 창    시장을 평소대로  · 1분 epoch 토큰 기록
                     안팔기 창  시장을 아예 안 염
                  Y = Φ(정책) − Φ(안팔기)          ← 맞혀야 하는 값
                     ↓
              소형 LSTM 이 매 epoch **최종 Y** 를 예측
                     ↓
              기여도  c_t = g_t − g_{t−1}          Σc_t = g_T ≈ Y
```

토큰 13칸 — 시계 3 · 상태 2 · **행동 4** · 비용증분 4 (`tape.py`).
행동 4칸이 따로 있는 이유는 **관문 B** 다: 지우고도 예측이 안 나빠지면 모델은
행동이 아니라 "몇 시냐" 를 외운 것이다.

## 4. 자격시험 A~F

| | 무엇을 보나 | 문턱 |
|---|---|---|
| A 예측 | held-out 상관 | ≥ 0.5 |
| **B 행동제거** | 행동 칸을 지우면 나빠지나 | ≥ +10% |
| C 반복성 | 초기값 3개의 상위 20 epoch 순위 | ≥ 0.5 |
| **D 순서섞기** | 순서를 섞으면 나빠지나 | ≥ +10% |
| E 보존 | Σ기여도 = Y | ≤ 10% |
| **★F 개입** | 그 epoch 에 **실제로 개입**하면 부호가 맞나 | ≥ 70% |

**필수 A·B·D·F.** C·E 미달이면 "순위 용도만"(표본 추출기)으로 제한한다.

★F 는 다른 RUDDER 연구가 못 하는 검증이다 — 우리에겐 반사실 시뮬레이터가 있다.
A~E 는 *"모델이 뭔가 배웠다"* 를 보지만 F 는 *"그게 우리가 재려던 것이냐"* 를 본다.

## 5. 통과하면 무엇에 쓰나 — **표본 추출기 먼저**

지금 [[YR-222]] 의 병목은 *"신호가 오차보다 작다"* 이고, 라벨 40건을 **균등 간격**
으로 뽑는다(`v3.stage.RolloutBudget.stride`). 대부분이 아무 일도 안 일어난 epoch 다.

| | 지금 | RUDDER 추출 |
|---|---|---|
| 표본 선택 | 균등 간격 | **기여도 상위 epoch** |
| 예산 | 세계 96개 | 세계 96개 (동일) |

**이 쓰임은 순위만 맞으면 된다** — 정책 학습에 기여도를 직접 넣는 것([[YR-224]])
보다 문턱이 훨씬 낮다. 그래서 4단계(추출기)와 5단계(정책 연결)를 **반드시 나눈다.**

## 6. ⚠️ 알고 쓰는 한계

- **epoch 몫이지 개별 행동 몫이 아니다.** 한 epoch 안의 배분은 반사실이 답한다(분업).
- **논문 그대로가 아니다.** RUDDER 는 한 궤적 안의 리턴을 분해하지만 우리는
  **두 궤적의 차이**를 분배한다. 최적 재분배 보증이 그대로 성립하지 않는다 —
  성립 여부는 관문 E·F 로 실증한다.
- **모델도 낡는다.** 정책이 바뀌면 궤적 분포가 바뀐다. 재학습 주기를 사전등록한다.
