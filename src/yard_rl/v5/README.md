# v5 — 통합 블록 PPO 구현·디버깅판

v4의 코드·시험·스크립트를 독립 복사한 뒤, 통합 블록 정책을 추가했다.
기준 커밋: `6d42455cbb1c61c5667c50d38776c4372148c417` (2026-09-09).
복사 당시 미추적 v4 스크립트 두 개도 사본에 포함했다. 원본은 수정하지 않는다.
작업 명세: `.claude/docs/dashboard-task-specs/YR-302-v5-unified-ppo-debug.md`.

## 새 학습 경로

`python -m yard_rl.v5.ppo`가 새 PPO(실제 선택 결과로 정책을 갱신하는 방법) 진입점이다.
기존 `train/`, `eval/`, 반사실 교사는 비교용 사본이며 **새 PPO 실행에서 사용하지 않는다**.
복사된 옛 주석의 v3/v4 설명은 역사적 설명이다. v5 동작은 이 문서가 기준이다.

```text
21블록의 연속 세계 → 60초 경계의 블록 상태·누적비용 확인
  → 판매 / 구매 / 크레인 결정: 같은 정책망, 역할과 후보만 달라짐
  → 다음 60초 경계: 새로 늘어난 비용을 음수 보상으로 기록
  → 지정 구간 수가 모이면 PPO 갱신 → 같은 세계에서 계속
```

즉 선택마다 미래 세계를 복제하지 않고, 본 실행이 남긴 경험으로 배운다.

## 학습 계약

- 판매·구매는 v4의 공개 특징과 후보를 유지한다. 구매는 BUY/REJECT 구분 비트가 있다.
- 크레인은 자기 블록 요약, 작업 종류, 본선/트럭 구분, 소요시간, 현재 대기,
  빈주행·재조작·위치와 앞 크레인의 선택만 본다. 미래 실현 도착값을 입력하지 않는다.
- 하나의 공유 줄기에 행동 점수 출력과 가치 출력이 붙는다. 역할별 독립 망은 없다.
- 크레인은 이름순으로 조건부 선택한다. 이미 고른 크레인과 충돌하는 후보는
  선택 **전** 물리 검사로 가린다. 선택 후 규칙이 다른 작업으로 바꾸지 않는다.
- `dry_run_commit`은 현재 예약의 실행 가능성 검사이며 미래 반사실 시뮬레이션이 아니다.
- 같은 블록의 한 구간 내 선택들은 **묶음 행동**이다. 선택 확률의 로그를 합쳐
  그 블록의 PPO 확률비를 계산한다. 사건 하나마다 별도 비용을 부과하지 않는다.
- 보상 = `−(현재 누적비용 − 직전 누적비용) / 1,000,000`.
  터미널 비용은 한 번만 계산하며 모든 블록에 같은 협력 보상을 준다.
  블록별 보상 21개를 다시 합쳐 터미널 비용이라고 보고하지 않는다.
- 할인과 GAE(이후 보상과 가치 추정을 섞는 계산)는 사건 횟수가 아니라 경과 초에 따른다.
  기본 할인 0.999, GAE 감쇠 0.95는 **60초 기준**이다.
- 구간 끝에서 남은 가치를 추정하여 연결한다. 학습 묶음 종료는 세계 종료가 아니다.
- 매 묶음 동안 가중치는 고정한다. 갱신 직후 다음 묶음의 가치도 새 망으로 다시 읽는다.
- 시뮬레이터 예외는 그대로 실패한다. 몰래 WAIT로 바꿔 성공 처리하지 않는다.
- 모델은 CPU 전용 디버깅 구현이다. 아직 속도·성능 우위는 검증하지 않았다.

## 실행

저장소 루트에서 WSL의 기존 `yard-rl` 가상환경을 사용한다.
필요 패키지는 `scripts/v5/requirements-debug.txt`에 명시했다.

```bash
PYTHONPATH=src python -m pytest tests/v5/test_ppo_units.py -q
bash scripts/v5/debug_ppo.sh --seconds 7200 --load 300 --output outputs/v5/ppo-debug
bash scripts/v5/debug_ppo.sh --eval --checkpoint outputs/v5/ppo-debug/policy.pt \
  --seconds 7200 --load 300 --output outputs/v5/ppo-replay
```

기본 실행은 시뮬레이션 2시간, 하루 트럭 300대 규모의 **배선 검사**다.
두 날짜를 연속 생성하고 중간에 멈추므로 작업 마감·도착 분포를 2시간으로 줄이지 않는다.
중단은 다음 동기화 경계(최대 60초 뒤)에서 이뤄진다.
기본 학습 기록은 60구간마다 갱신한다. 이것은 사전 통지창이나 미래 계산창이 아니다.
출력 폴더가 이미 있으면 덮어쓰지 않고 거부한다.

학습 횟수는 양의 정수만 허용한다. 잘못된 시각·끊긴 수집 구간·블록 수가 다른
가치 기록은 즉시 거부한다. 정책 변화가 너무 커 갱신을 중단하면 `early_stopped`와
중단을 일으킨 변화량(`max_kl`)을 함께 기록한다. 수치가 무한대가 되면 실패 처리한다.

전체 시험은 `PYTHONPATH=src python -m pytest tests/v5 -q`로 실행한다.
옛 반사실·규칙 정책의 하루 단위 반복 시험도 포함하므로 짧은 PPO 실행보다 오래 걸린다.
복사본 검사는 `tests/v5/v4-copy-manifest.json`에 고정한 **복사 당시 커밋**과 비교한다.
현재 개발 중인 v4 파일이 추가·수정되어도 독립적인 v5의 기준을 바꾸지 않는다.
옛 `train` 경로도 하루·월 단위 학습 모두 **모델 생성 전에** 지정 시드를 적용한다.
이전 사본의 시드 누락을 고친 것으로, 새 PPO 초기화에는 영향을 주지 않는다.

`policy.pt`는 가중치·최적화 상태 보관 파일이다. **물리 세계 재개 파일은 아니다**.
`--checkpoint`는 가중치를 읽어 새 세계를 시작한다. `--eval`은 탐색·학습 없이 최대확률 선택이다.

## 30일 연속 실행 (YR-306)

새 실행기는 `python -m yard_rl.v5.ppo.continuous`이며, **깨끗한 별도 worktree**에서 실행한다.
WSL에서는 그 worktree에 맞는 `GIT_DIR`·`GIT_WORK_TREE`를 지정해야 한다.

```bash
bash scripts/v5/train_continuous.sh --seed 9900306 --days 30 --output /absolute/new/run-dir
```

- 하나의 물리 세계에서 첫날 준비 → 2~29일 학습 → 마지막 날 정리 → 2시간 배수.
- 첫날·마지막날에도 정책은 추첨으로 행동하지만 학습 자료·가중치 갱신에는 넣지 않는다.
- 기본 PPO 설정은 위와 같다. 초기 점유율 45%, 날짜별 기존 가중 부하 추첨을 유지한다.
- 학습 구간 끝에서 남은 가치를 추정하여 연결한다. 세계를 종료한 것으로 처리하지 않는다.
- `manifest.json`: 코드 커밋·소스 해시·시드·전체 설정·날짜 계획.
- `status.json`과 `events.jsonl`: 시뮬레이션 1시간마다 진행 상태, 매 학습 갱신 기록.
- `days.json`: 날짜 경계 사이 실제 누적비용 차이·학습 횟수·물리 검사 결과.
  기존 도착일별 집계는 `cohort_reports.json`으로 별도 보관하며 두 비용을 혼동하지 않는다.
- `initial.pt`, `day_01.pt`~`day_30.pt`, `final.pt`: 정책·최적화 상태 저장.
  물리 세계 재개용이 아니다. 실패하면 원인을 남기고 같은 코드·시드를 새 폴더에서 재실행한다.
- `admissions.json`: 트럭 투입·누락 수, 누락 오더 번호·블록·시각·사유와 본선 투입 결과.
  누락을 처음 발견한 투입 검토 시점에 저장하고 즉시 중단한다. 트럭은 그 경계의
  학습 갱신보다 먼저 검사한다. 본선은 당일 투입 직후 검사하여 이후 진행을 막는다.
  원래 허용하던 본선 물량 일부 축소는 기록하되, 새 실패 조건으로 바꾸지는 않았다.
- `cohort_live.json`: 하루가 끝날 때마다 기존 도착일별 잠정 집계를 저장한다.
- `month_result.json`, `cohort_reports.json`: 월 실행이 반환하면 최종 검증 **전에** 저장한다.
  파일 존재만으로 성공은 아니다. `status.json`의 `completed`와 성공 보고서를 확인한다.
- 실패하면 가능한 범위에서 `failed-policy.pt`, `partial_report.json`도 보존한다.
  부분 보고서는 마지막 정책 경계까지의 값이며 실패 시각의 최종 총비용이 아니다.
  저장 오류가 겹치면 그 오류도 남기되 원래 실패를 덮어쓰지 않는다.
- 짧은 연결 검사는 `--days 3 --debug-load 60`으로 첫날·학습일·마지막날을 모두 통과시킨다.

이 첫 실행은 연속 학습의 작동·기록을 확인한다. 규칙 대비 성능과 현실타당성을 판정하지 않는다.

## 의도적으로 이번에 바꾸지 않은 것

- v4 엔진·작업 시간·오더 스키마·원화 비용식.
- 본선 마감 임박에 따른 새로운 비선형 비용, 통지창 6시간 확장.
- 시간 이연은 v4 그대로 최대 120분 후보이며 기존 예약창 필터를 유지한다.
- 게이트 밖 이연 대기비용은 v4 비용식에 없으므로 새로 추가하지 않았다.
- 고부하 장기 성능 판정: 첫 연속 실행은 규칙 정책과의 비교 평가가 아니다.

따라서 실행 성공은 연구 성능·현실타당성 통과가 아니다.
