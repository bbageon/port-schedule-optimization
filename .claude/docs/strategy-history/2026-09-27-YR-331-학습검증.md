# YR-331 — 적정부하 보상 실제 학습·검증 결정 기록

2026-09-27. 이 문서는 실행 전후 결정 경위와 설정을 보존한다. 결과는 별도 결과 절에 붙인다.

## 사용자 지시와 범위

전날 문헌 조사와 수식 검산을 마친 뒤 사용자가 “학습하고 잘되는지 확인해봐 그럼”이라고 지시했다.
이는 승인되지 않은 후속 제안이 아니라 실제 연결·학습·평가의 실행 지시다. 터미널 간 판매는 범위에 넣지 않는다.
한 터미널 21블록·42크레인의 기존 공유 신경망을 유지하고 비용 보상에 부하 변화 한 항만 선택적으로 더한다.
모방 학습·별도 가치망·후보 변경·새 관측 특징·단가 변경·GPU 이식은 함께 수행하지 않는다.

## 실행 환경 결정

- 기존 `.venv-jax`는 Anaconda 패키지를 상속해 torch와 numpy를 함께 가져올 때 OpenMP 중복 초기화로 종료됐다.
- 중복 런타임 오류를 숨기는 환경변수는 쓰지 않고 별도 venv를 만들었다.
- Python 3.13.9, torch 2.14.0+cpu, numpy 2.3.5, scipy 1.16.3, pyyaml 6.0.3.
- WSL 복구는 Docker 등 타 작업 중단을 동반하므로 수행하지 않았다. 결과 범위는 **CPU v6**다.
- 진행 중인 YR-327의 GPU 파일 열 건은 수정·stage하지 않았다. 실행 소스는 별도 clean worktree에 고정했다.
- 최초 기록기 연결에서 `manifest['ppo']` 키 누락으로 세계 생성 전 종료했다. `373f0140`에서 수정하고 새 출력 디렉터리로 시작했다.

## 작업량 계산의 구체적 계약

원래 예약 게이트 시각을 보존하고 통지된 주문만 센다. 아직 알 수 없는 실제 미래 완료시간은 읽지 않는다.
끝나지 않은 주문은 재예약으로 창 밖으로 밀려도 원래 요청이 창에 들어오면 계속 남는다.
동일 블록의 미착수 작업은 두 크레인의 고정 능력 비율로 나눈다. 이미 수행 중이면 담당 크레인 한 대에만 남은 분량을 넣는다.
진행률은 선택 때 이미 공개된 실행 계획 길이와 현재까지 흐른 시간으로 구한다.
미래 실현 서비스시간을 거꾸로 읽거나 빈 이동·선제 재정리를 새 유효 작업으로 세지 않는다.
현재 H21의 두 크레인은 블록 전체를 공유한다. 부분 구역 크레인 프로파일은 이 어댑터가 거부한다.
이미 한 번 결정한 예약·게이트 진입·반출·본선·진행 중 작업은 다시 공간 판매할 수 없어 고정 분량이다.
목표 부하 계산기는 실제 작업을 배정하지 않는다. 기존 후보·물리 제약이 실행을 결정한다.

원래 비용 보상과 보조 항은 별도 저장한다. 신경망만 두 항의 합으로 학습하고 실제 비용 보고에는 보조 점수를 원화처럼 더하지 않는다.
60구간 수집 종료나 유한 입력의 시간 제한은 실제 종료가 아니므로 다음 부하 점수와 가치 추정을 유지한다.

## 검토한 대안과 채택하지 않은 이유

- 80%를 최적값으로 지정: 문헌이 보편값을 뒷받침하지 않고 작업 종류별 서비스시간도 달라 기각.
- 새 보상 결과를 보고 세기나 창을 조정: 독립 비교가 깨지므로 이번 실행에서는 금지.
- 학습 보상에 외부 지연 비용까지 동시에 추가: 무엇 때문에 결과가 달라졌는지 분리되지 않아 채택하지 않음.
- 실패 시드의 주문 5건 삭제·상자 5개 추가·다른 시드 교체: 수요와 물리 계약을 바꾸므로 수행하지 않음.
- GPU 포팅 완료를 기다리거나 WSL 전체 재시작: 현재 사용자 지시를 실행 가능한 CPU 경로로 검증할 수 있어 불필요.
- 예전 게이트의 PASS 승계: `authorize-next` 재검이 `저장된 scenario PASS 재계산 실패`였으므로 승계하지 않음.

## 지연·완료 감사와 판정 계약

지연 원점은 **최초 예약 게이트 시각**이다. 통지 시각을 원점으로 쓰면 정상 사전 통지까지 대기료처럼 청구한다.
현재 비용의 게이트→출문과 원래 요청→출문을 모두 기록하며, 뒤로 미뤄 평가창에 들어오지 않은 주문도 원래 수요 분모에 남긴다.
원래 요청 기준 환산금액은 민감도 진단이다. 재예약 시간이 전부 실제 운전기사 유휴나 법정 청구라는 주장은 하지 않는다.
각 비교는 원화 비용 감소 외에 원래 요청 기준 비용·미완료 트럭·미완료 본선 작업·본선 유휴가 악화되지 않아야 한다.
구매 호출·수락·확정 공간 거래·확정 시간 거래·실제 완료를 구분한다. BUY 건수만으로 성공을 선언하지 않는다.
첫 세 쌍의 진단은 최종 확증이 아니다. 결과가 나쁘거나 입력/물리 가드가 실패하면 그 사실을 포함해 보고한다.

## 증거 보존
