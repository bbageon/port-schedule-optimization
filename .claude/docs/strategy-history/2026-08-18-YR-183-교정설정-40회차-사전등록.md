# YR-183 사전등록 — 교정 설정으로 동결 예산 40회차

- **작성 2026-08-18 · 실행 전 동결** (이 문서 커밋 이후 수정 금지)
- **목적**: 서사 B 의 **마지막 열린 구멍**을 닫는다 — "충분히 학습시키면 규칙을
  넘는가".

## 1. 왜 지금 · 무엇이 바뀌었나

[[YR-185]] 가 학습 병목(보상 0 이 91% → critic 붕괴)을 특정하고 교정했다.
교정만으로 argmax 효과가 76% 늘고 규칙과의 격차가 **96.6 → 40.9** 로 줄었다.
그러나 **회차는 여전히 동결 예산의 25%(10/40)** 였고 곡선은 마지막까지 개선
중이었다.

따라서 이 판은 **단순 40회차가 아니라 교정 설정으로 40회차**다. 교정 없이
돌리면 이미 아는 병목을 다시 겪는다.

**답할 질문은 하나**: 남은 **40.9 를 학습량으로 메우는가.**

## 2. YR-185 사전등록의 실패를 반복하지 않는다

지난 사전등록은 두 군데가 잘못됐다. 이번엔 명시적으로 고친다.

| 지난 실패 | 이번 조치 |
|---|---|
| 판정축을 "안 팔기 대비"로 잡아 **판별력 0**(대조군도 이미 넘던 축) | **주판정 = 규칙 대비** |
| **모드 미명시** — 두 모드가 부호까지 달랐다 | **주판정 모드 = argmax**(배포 방식). 추첨도 **함께 보고**(사전 약속) |

## 3. 동결 — 학습

| | |
|---|---|
| 설정 | **YR-185 ②③ 교정** — 0 보상 하위표집 `ZERO_KEEP=0.15` + 정책 `1/p` · 가치 `1.0` 비대칭 가중 |
| 팔 | `fixed15` (고정 +15분). 48칸·견적망은 이 판에 올리지 않는다 |
| 집행 | `ADOPTED_C0_GUARD` (동결) |
| 회차 | **40** × 4 에피소드 = 160 에피소드/시드 |
| **시드** | **5개** — 8,400,000 / 8,500,000 / 8,600,000 / 8,700,000 / 8,800,000 |
| 병렬 | 시드 5 × 워커 4 = **20 코어** (4 코어는 다른 세션 몫) |

`ZERO_KEEP`·학습률·클립·엔트로피·미니배치·grad clip 은 YR-185 와 **동일**하다.
바뀌는 축은 **회차 하나**(10 → 40)와 **시드 수**(1 → 5)뿐이다.

## 4. 동결 — 평가

| | |
|---|---|
| **평가일** | **새 대역 9,500,000 ~ 9,505,000 (6일)** — 기존 전 대역과 무겹침 |
| 팔 | `K`(안 팔기) · `greedy`(규칙) · `fix40`(교정 40회차 × 5시드) |
| 모드 | **argmax**(주) + **추첨 씨앗 11·22·33**(병행 보고) |
| 비교 | 같은 날 짝지어, 독립단위 = **날**(n=6) |

**규칙(`greedy`)도 이 새 대역에서 다시 잰다** — 기존 −170.05 는 다른 6일 값이라
그대로 인용하면 안 된다.

## 5. 동결 — 판정

**주판정**: `fix40 − greedy` (argmax, 총비용)

| 결과 | 뜻 |
|---|---|
| 95% CI 전체가 **0 미만** | **학습이 규칙을 넘었다** → 서사 A 재검토 |
| CI 가 0 을 포함 | **구분 불가** → 서사 B 유지, "동급"으로 기록 |
| CI 전체가 **0 초과** | **못 넘었다** → **서사 B 확정, 마지막 구멍이 닫힌다** |

`|t| ≥ 2.57` (df=5, 양측 95%). 5시드는 날별로 평균해 독립단위를 날로 유지한다.

**함께 보고(판정 아님)**: 추첨 모드 결과 · `fix40 − K` · 학습 곡선 40회차 ·
critic rms 추이 · 시드 간 흩어짐.

## 6. 동결 — 하드 가드 (위반 시 그 셀 실격)

1. 투입 = 3,600 전건
2. `policy_exceptions == 0`
3. 실행 트리 `code_dirty == False`
4. 5시드 × 6일 전 셀 존재

## 7. 하지 않는 것

- 결과를 보고 판정축·모드·평가일·시드를 바꾸는 것.
- 규칙 기준선을 약화시키는 것 — `gain_margin` 은 코드 기본값 동결.
- 40회차 중간 지점의 가중치를 골라 쓰는 것(**마지막 회차 고정**).
- 이 판정으로 실제 항만 운영 대비 개선율을 주장하는 것.

## 9. 비용

회차당 약 15.5분(YR-185 실측) × 40 = **시드당 약 10.3시간**. 5시드가 20코어에서
동시에 도므로 **벽시계도 약 10~13시간**이다. 평가는 42판 약 40분.

## 10. 개정 (2026-08-18 · §1~9 원문 무수정)

> 사전등록 규약상 원문은 고치지 않는다. 아래는 **append 개정**이다.

### 무엇을 바꾸나

**판정 시드를 5개 → 3개**로 줄인다: `8,400,000` · `8,500,000` · `8,600,000`.

### 왜 — 자원 제약 (결과 때문이 아니다)

20코어에 20프로세스를 올렸더니 **시드마다 진행 속도가 3배 벌어졌다**(실측
6.4시간 경과 시점).

| 시드 | 회차 | 회차당 | 40 완주까지 |
|---|---|---|---|
| 8,400,000 | 18/40 | 21분 | 7.9시간 |
| 8,500,000 | 19/40 | 20분 | 7.1시간 |
| 8,600,000 | 15/40 | 26분 | 10.7시간 |
| 8,700,000 | 6/40 | **64분** | **36.5시간** |
| 8,800,000 | 6/40 | **64분** | **36.5시간** |

다섯을 다 기다리면 **36시간**이고, 그중 3배 느린 둘 때문이다. 원인은 자원
경합(메모리 대역폭·스케줄러)으로 추정하며 학습 내용과 무관하다.

### ★편향이 아님을 증거로 남긴다

"느린 시드가 성적도 나쁘면 나쁜 시드를 버린 것"이 된다. **아니다** — 같은
회차에서 두 군이 구분되지 않는다.

| iter | 빠른 3시드 평균 Φ | 느린 2시드 평균 Φ | 차 |
|---|---|---|---|
| 0 | 2922.9 | 2916.1 | **−6.8** |
| 3 | 2830.2 | 2837.7 | **+7.5** |
| 5 | 2666.8 | 2663.0 | **−3.8** |

부호가 오가고 크기도 회차 간 변동(수십~수백)에 비해 무시할 만하다.
**선택 기준은 벽시계 하나**다.

### 판정 지표는 아직 안 봤다

위 Φ 는 **학습일**(8400036~) 의 **학습 중** 값이다. 사전등록한 판정 지표는
**새 대역 9,500,000~ 에서 argmax 로 잰 `fix40 − greedy`** 이고, 이는 학습이
끝나야 측정한다. **아직 한 번도 계산하지 않았다.**

### 통계에 미치는 영향

독립단위는 **여전히 날(n=6)** 이다. 시드는 날별 평균을 만드는 데만 쓰이므로
5→3 은 **날별 평균의 정밀도만 약간 낮춘다**(판정 자유도 불변). CI 폭이 조금
넓어질 수 있고, 그 경우 `INCONCLUSIVE` 가 나오기 **쉬워진다** — 즉 이 개정은
"넘었다"를 주장하기 **불리한 쪽**이다.

### 느린 두 시드는 죽이지 않는다

계속 돌린다. 나중에 완주하면 **사후 관찰(판정 아님)** 로 덧붙인다.
5시드 결과가 3시드 판정과 다르면 그것도 그대로 박제한다.

### 바꾸지 않는 것

평가일(9,500,000~9,505,000) · 판정축(**규칙 대비**) · 모드(**argmax** 주,
추첨 병행 보고) · 하드 가드 4종 · 대응 계획 3종 — **전부 그대로**다.
