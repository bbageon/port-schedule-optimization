## 결정 (사용자, 감사 권고 채택 — "해당 피드백 참고해서 진행")

1. **lead 계약 동결**: 사전 예고 **30분**(`ANNOUNCE_LEAD_S` — 판매 검토 창과 동일),
   WIP 정의 = **터미널 내부 트럭 + 진입이 확약된 예고 트럭 = L**.
   근거: 내부만 L 로 유지하며 예고를 얹으면 실부하가 L 을 넘어 정책 간 비교가 깨진다.
   구현 실제: `WipAdmissionController` 의 `deficit = L − inside − pipeline` 이 이미
   이 정의였고, 자격 하네스만 lead=0 이었다 — 하네스 배선(`lead_s=ANNOUNCE_LEAD_S`)으로 동결.
2. **재자격은 최종 SELL 환경과 정확히 같은 환경으로 1회**: 같은 날 통과한 lead=0
   재자격(트리 `11c58c1`·W1~W9 전항 PASS)은 **중간 자격(이력)으로 강등** — 최종 환경과
   달라 최종 자격으로 쓰지 않는다. 두 번 돌리기 방지를 위해 lead 계약·부채 보정을
   재자격 앞으로 당겼다.
3. **YR-162 를 A/B 로 분할**: 0B 결과가 없는데 "결론이 뒤집히는가"를 먼저 검사할 수
   없다 — A(0B 전) = 방어 경로 발화만, B(0B 후) = GO/STOP 방향 유지 + 잠금평가 오차 축.
4. **순서 10단계 고정** (Dashboard README 작업 순서 항목이 정본): 정본 결정 ✅ →
   lead 동결 ✅ → 부채 보정+최종 재자격 → 현실성 게이트 재계산 → 162A → 160+151 배선 →
   resolver 관통 shadow → 0B → Q30+학습 → 162B 포함 K/Q30/S 잠금평가(= H-21 최종실험).
   V-21 은 별도 후속 장.

## W1 관측점 재정의 (완화 아님 — 제어점 정의)

lead=30분 smoke 에서 투입 **직전** 관측(inside+pipeline)은 54~60 으로 출렁였다 —
60초 사이 이탈분만큼 낮게 읽히는 **측정 시점 인공물**이다(컨트롤러는 매 격자에서
정확히 L 로 채움·구 lead=0 스냅샷 측정도 사실상 투입 직후 값이었다). W1 은 **격자
투입 직후 계약량**(inside+pipeline+admitted)으로 판정한다. 투입 실패·pool 소진·SKIP
누적은 여전히 L 미달로 잡히므로 검출력은 보존된다. 정정 후 smoke: held min=max=60.
