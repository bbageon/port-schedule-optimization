# YR-103 게이트→블록 이동·동적 블록 혼잡도 사용자 결정

- **기록일**: 2026-07-27
- **상태**: 설계 등록. 구현·성능 검증 전
- **관련**: YR-089 시간계약, YR-099 다중블록 재배정, YR-101 음성 결과,
  YR-102 분해 quote

## 1. 결정 경위

YR-099의 제한조건 오라클은 반입 재배정의 물리적 상한 `−22.41
[−32.12,−12.70]`을 보였지만, 공개정보 단일 quote는 `+3.08`, YR-101 K=5는
`+3.54 [−4.12,+11.20]`로 실패했다. 이 결과만으로는 다음 둘을 분리할 수 없다.

1. 공개정보에 좋은 재배정을 구분할 신호가 없다.
2. 신호는 있지만 full-episode quote의 분산과 다후보 선택편향이 가린다.

사용자는 실제 데이터에 예약·ETA, 실제 gate-in, 실제 block-in, 작업완료, gate-out과
터미널 내부 혼잡정보가 존재한다고 정정했다. 따라서 “데이터가 없다”는 진단을 철회하고,
**각 정보가 발생한 시점에 정책 상태가 갱신되는가**를 먼저 확인하는 방향으로 바꿨다.

이어 사용자가 다음 환경·혼잡 계약을 제시했다.

- 게이트 진입→블록 진입: 3~7분
- 블록 혼잡도:

```text
0.30 × 트럭 대기열
+ 0.25 × 평균 대기시간
+ 0.20 × 크레인 작업부하
+ 0.15 × 블록 장치율
- 0.10 × 진입도로 지연
```

## 2. 현재 코드 감사 스냅샷

### 이동시간

- `TerminalGenParams` 직접 기본값은 600초(10분)다.
- 현실 보정·`CongestionSpec` 경로는 평균 210초이고 σ=12%·±2σ 절단이라
  약 160~260초(2.66~4.34분)다.
- 생성 경로에 따라 10분과 3.5분이 갈리며, 사용자 180~420초 범위는 아직 없다.
- 기존 YR-089 결과는 평균 210초 계약에서 나온 과거 증거라 소급 변경하지 않는다.

### 혼잡도

현재 하나의 실시간 블록 혼잡점수는 없다.

- `CongestionSpec`: 트럭 강도·피크·초기 장치율·본선압력을 정하는 시나리오 다이얼
- `lane_congestion_*`: 크레인 작업이 예약한 자기·인접 lane 점유
- `backlog_external`: 현재 WAITING/RELEASED 외부작업 수
- `queue.wait_mean_s`: 전체 블록이 아니라 pruning 뒤 후보의 평균
- `load_imbalance`: 절대 부하가 아니라 크레인 사이 불균형
- `fill_ratio`: 초기 생성값만 있고 실행 중 장치율은 state에 없음
- 실제 `B−A`와 갱신 ETA: 시간장부에는 있으나 합성 혼잡과 transfer state에 미배선

즉 “터미널 내부 혼잡정보가 있다”는 사용자 정정은 맞지만, 현재 것은 여러 개의 분리된
신호이고 제안한 블록 종합지표와 같지는 않다.

## 3. 채택한 설계

### 3.1 이동시간

향후 opt-in 환경에서 `B−A` 지원범위를 180~420초로 둔다. 실측 전 시작 분포는
중심 300초·σ 60초 절단정규를 assumed로 기록한다. 외부 시스템의 갱신 ETA가 있으면
그 값을 우선하며 분포는 fallback·시뮬레이션 생성에만 사용한다.

정보 경계는 다음과 같다.

- 예약 전후: 예약+예상 준수오차+예상 이동시간
- 실제 gate-in 뒤: 실제 gate-in+현재 이동예측으로 ETA 재계산
- 실제 block-in 뒤: 실제 `B−A`는 label·보정에 사용
- 완료·gate-out: 비용·학습정답이며 이전 결정 입력으로 역주입 금지

### 3.2 혼잡도

트럭 수·초·비율을 그대로 더하지 않고 Q/W/L/F/D를 각각 0~1로 만든다.

- Q: 전체 WAITING 외부트럭 수
- W: 후보 pruning과 무관한 전체 WAITING 평균대기
- L: 모든 YC의 실행 잔여초+대기작업 예상 서비스초를 가용 YC 시간으로 나눈 절대부하
- F: 실행 중 컨테이너 수/물리 slot 수
- D: 해당 블록으로 오고 있으나 아직 block-in하지 않은 공개 작업별
  `(예상 gate→block−180)/240`의 평균. 대상이 없으면 0

양의 항 가중치 합은 0.90이어서 제안식은 `[0,1]` 안에 있지만 이론상 최대가 1은 아니다.
첫 검증에서는 사용자 가중치를 그대로 보존하고 결과를 본 뒤에만 재척도 여부를 정한다.

사용자 수식은 그대로 `C_minus` 후보로 보존한다. 다만 `−D`는 도로 지연이 블록 유입을
늦춰 **당장 내부압력을 완화한다**는 뜻일 때만 맞는다. 전체 터미널 혼잡이나 목적지
비용을 뜻하면 부호는 `+D`가 맞다. 그래서 `minus/zero/plus`를 결과 열람 전에 동결해
비교하고, 실제 TransferResolver의 경로시간 비용은 항상 양수로 별도 계산한다.

## 4. 검토한 대안과 기각·보류 사유

### 제안식을 바로 reward에 더하기 — 기각

트럭 대기·부하·장치율은 기존 terminal cost와 겹친다. 다시 더하면 과거 OLD 목적의
interference proxy처럼 한 proxy가 목적을 지배할 수 있다. 첫 단계는 state·진단 전용이다.

### 현재 lane congestion을 블록 혼잡으로 이름만 변경 — 기각

현재 lane 값은 차량 교통이 아니라 YC 작업 reservation 점유다. 대기열·장치율·도로시간을
대신하지 못한다.

### YR-102 추정기 변경과 동시에 상태 추가 — 기각

성과가 변해도 추정기 때문인지 새 정보 때문인지 알 수 없다. YR-103을 별도 작업으로 두고
도착갱신·혼잡·분해 quote를 축차 ablation한다.

### 도로 지연을 무조건 음수 또는 양수로 확정 — 보류

음수는 단기 block pressure, 양수는 terminal congestion/route cost라는 서로 다른 의미다.
실현된 다음 15~30분 비용 예측력을 보고 이름과 부호를 확정한다.

## 5. 동결 설정과 판정

- 이동 support: 180~420초
- 시작 중심/σ: 300/60초, D5 assumed
- 재검토 시점: 최초 배정·ETA 갱신·실제 gate-in·유의한 혼잡변화, lock 전
- 혼잡 원료: 전체 queue·전체 평균대기·절대 YC workload·runtime fill·예상 진입지연
- 사용 위치: state·진단·단순 baseline만. reward·terminal cost 직접 가산 금지
- 주평가: terminal total cost, 평균 B→C/A→O, 본선, 완주·backlog·안전
- P95: 보고용
- 정보안전: 미래 actual 값 변조에도 결정시점 feature 불변

현재 공개 snapshot을 고정하고 숨은 미래를 반복 생성해 공개정보 기대 상금을 먼저 잰다.
그 값이 0이면 YR-102나 더 큰 신경망으로 가지 않고 데이터·결정시점 한계로 판정한다.
양수인데 현재 quote만 실패하면 추정기·상태표현 문제로 분리한다.

## 6. 적용 범위와 되돌릴 조건

적용범위는 문헌·사용자 가정 기반 다중블록 시뮬레이션이다. 실제 부산항 터미널의
구간별 도로교통이나 SLA를 확정한 값이 아니다.

다음이면 재검토한다.

- Level 3 로그에서 `B−A`가 3~7분 밖에 체계적으로 분포
- 도로항 부호가 신규 seed에서 불안정
- 종합점수가 실제 다음 구간 비용과 무상관
- 기존 분리 feature가 합성점수보다 더 잘 일반화
- state 추가가 기존 정책 차원을 깨고 성능 이득이 없음
