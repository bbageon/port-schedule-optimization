# 반출 공급 보존 — 결정과 증거

2026-11-16. 사용자: 앞선 합성 입력·신경망 검토 다음 순서에 “응 진행해줘”.
정책 구조를 곧바로 바꾸지 않고, 발견된 입력 결함을 먼저 바로잡는 순서로 진행했다.

## 발견과 경로 정정

ao에서 배경 후보 41개 중 5개를 거절했다. 전부 15,000건이며,
9934102:44, 9934104:1, 9934112:315, 9934116:13, 9934118:361건이 반출에서 반입으로 바뀌었다.
합계 734건. 원래 at 문서의 `terminal_stream.build_diurnal` 경로 표기는 일반 원인 설명이었다.
실제 v7 하루 경로는 `stage.vessels.build_diurnal_v3`다. 같은 fallback 코드가 복제되어 있었다.

블록 초기 재고에서 본선 적하 대상을 먼저 제외하고 트럭 반출 대상을 뽑았다.
블록별 재고보다 두 수요의 합이 크면 부족분을 GATE_IN으로 만들었다.
터미널 전체 재고가 부족하다는 뜻은 아니며, 본선이 없는 다른 블록에는 당일 대상이 아닌 재고가 있었다.
이 상태에서 시드만 재추첨하면 생성기의 적용 범위를 조용히 좁히므로 근본 수정으로 볼 수 없었다.

## 대안과 선택

1. 정상 시드만 계속 사용: 앞선 ao 임시 조건부 은행에는 가능하나 임의 배경 공급 보존을 고치지 못한다.
2. 상자 추가 생성: 총재고·장치율까지 늘어나므로 선택하지 않았다.
3. 트럭을 다른 블록에 배정하거나 본선 양적하 방향 변경: 요청 또는 본선 작업을 바꾸므로 선택하지 않았다.
4. 미래 반입·양하와 연결: 장기적으로 가능한 모델이나 생산·대기·동일 컨테이너 계약을 새로 바꿔야 한다.
   이번은 기존 “당일 반출은 초기 재고에서” 계약을 유지하는 한 축 보정으로 한정했다.
5. **같은 총재고의 초기 블록 배치만 보정**: 당일 사용하지 않는 최상단 상자를 부족 블록에 배치한다.
   위치는 규격·높이·여유 슬롯을 지키는 후보에서 전용 난수열로 뽑으며 작업 비용을 최적화하지 않는다.

5번은 합성 초기 상태의 조건부 구성이다. 실제 야드에서 작업 없이 상자를 옮겼다는 뜻이 아니다.
새 대상이 상단 쪽에 있고 기존 대상 위 방해 상자 수가 바뀔 수 있다는 한계를 사전등록했다.
적재 위치의 외부 근거가 생겼다는 주장은 하지 않는다. 배치 실패 때는 원본 불변·부족 원장·예외를 보장한다.

## 동결 설정

- 코드/사전등록 고정점 `305d0eca`; 정책·보상·본선·입력 요청/시각 난수열 불변.
- 재고 전용 난수열 `v7:initial-stock:{seed}`. 기존 주문/본선 대상을 보존하며 새 대상은 SUPPLY 접두로 식별.
- 검사: ao 원장 배경 41개와 새 seed=9935000..9935019, 각 3,500/7,500/15,000건, 총 183개.
- 수요: 방문 연결 demand-profiles의 observed_visit_links, 곡선은 ao 학습 곡선 24개의 평균.
  시간대 안 분별 형판과 정보 프로필은 기존 설정. 관련 파일 해시는 campaign.json에 고정.
- 실행 점검: 9934102·15,000건 SF_SPT/FIFO, 9934100·3,500건 SF_SPT legacy/preserve.
  24시간 입력+2시간 배수, 후보 무제한, 계획 재사용, 교사/재배정 없음.
- 다음 곡선 비교: 원래 학습 곡선 첫 3개와 원래 seed=9934100/101/102,
  3부하×평균/변동×SF_SPT/FIFO/LWKR=54회. 한 쌍의 초기 상태와 작업 속성은 동일하다.
- 최초 authorize-next는 at 명세에 기계가 읽는 “3대 게이트 보정 대상” 표기가 없어 거절됐다.
  기존 대상 scenario_validity 선언의 표기만 수정한 뒤 허용됐다. 게이트 기준을 완화하지 않았다.

## 실행 증거 스냅샷

- 183개 모두 공급·대상·용량·크기·공중 적재·방문 제약 검사 통과. 반복 생성 일치.
- 기존 5개 실패에 더해 새 배경 6개에서 554건 발견:
  9935000:163, 9935004:325, 9935008:4, 9935009:10, 9935016:45, 9935019:7.
- 합계 11개 입력, 1,288건 전환이 0건으로 바뀌었다. 정상 172개는 schedule/scenarios 정확히 동일.
- 총재고 19,656개·규격별 수 보존. 블록별 936개 고정에서 보정 입력은 904~1,065개(약 62.8~74.0%)다.
- 회귀 42건+40건=82건 통과. 초기 공급 5건은 42건에 포함한다.
- 정상 실행: 수정 전후 평균 15.959358분, 24시간 미완료 18, 26시간 미완료 0.
  후보·선택·사건·작업·기록·결과 해시와 원자료 모두 동일.
- 부족 입력 실행: SF_SPT 129.694822분, 미완료 24/26시간 2,245/1,535;
  FIFO 186.087233분, 미완료 3,824/2,762. 접수 누락·중복·정책 예외·지연된 방문 연결 없음.
  이는 관측창 내 체류 평균이다. 고물량을 완주·정상상태라고 주장하지 않는다.
- 곡선 쌍 입력 18개도 재검사했고, 두 팔의 초기 상태·본선·작업 대상과 속성은 같다.

## 적용·해석·되돌릴 조건

기본은 preserve, 보정 없는 검사는 strict, 과거 fallback 재현만 legacy다.
다른 v3/v6/legacy 생성기는 수정하지 않았다. 원래 36개 배경은 새 은행으로 복원하고 옛 조건부 은행은 보존한다.
공급 보존 축의 통과만 허용한다. 새 학습·성능 개선·실항만 적재 재현·지속운영 타당성은 이번에 얻지 않았다.
추후 실제 장치율·초기 배치 근거와 어긋나거나 보정 빈도가 크게 늘면 이 초기 상태 구성 방식을 재검토한다.
정책 성능이 좋아졌다는 이유로 보정 시드 또는 위치를 골라서는 안 된다.
