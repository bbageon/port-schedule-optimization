# 2026-07-30 — BlockQ-v2 전환 로드맵 (외부 4·5차 피드백 + 검토 종합)

## 4차 피드백 (아키텍처 제안) 요지

절대 총비용 Q 하나에 후보 순위·완주·유휴 판단·장기 본선효과를 다 맡긴 설계가 문제의
중심. 제안 = **기준선 잔차 공동 순위정책**: 중앙 공동조합 평가·안전검사·실행가능성
검사는 유지, ①전체비용 회귀 → SF-SPT 기준 Δ 학습 ②실행 후보 1개 → 상태당 기준선+K후보
라벨 ③자유 WAIT → 기본 제외(필요 시 DEFER_UNTIL(사유, 기간) 명시 행동) ④작업 무관
REPOSITION → PREPOSITION(future_job, target_bay) ⑤600s 비용 → +종결 잔여비용(J_H)
⑥Q 상시 대체 → 예측 Δ < −안전여유일 때만 개입, 그 외 SF fallback. 배포 시 반사실
rollout 금지(학습 교사만). 검증 순서 = 오프라인 순위 확인 후에만 에피소드 실행.

## 검토 (2026-07-30, 세션 내 회신) 요지

방향 동의 — 확증 결함 4개(순위 오류·유휴 풍선·초기화 불안정·완주 붕괴)를 각각 겨냥하고,
2세대의 유일한 실증 성공(창중 이송 = 규칙 기준 + 계산된 개선 개입)과 같은 패턴. 단
6축 동시 변경이라 단일축 사다리로 분해 필요. 조건부: PREPOSITION 은 생성이 아니라
표현·평가 연결이 실차이(생성기는 이미 ETA 기반), K-후보 선별의 자기 편향 주의, 안전여유·
잔여비용 식은 사전동결 대상, DEFER 는 YR-050 계약 검토 선행.

## 5차 피드백 (순서·축 정정) — 확정 사항

1. **기준행동 교체는 순위 처방이 아니다**: 같은 상태의 모든 후보에서 같은 기준값을
   빼므로 **상태 내 순위 불변**. SF 기준의 실제 용도 = 개입 게이트·나쁜 초기화 시 SF
   복귀·개선량 해석 → 사다리 6단으로 이동. "기존 라벨로 즉시 가능" 철회 확정(SF 선택
   미기록 — 재라벨 런 필요).
2. **YR-131 축 분리**: 131-a(후보 확대만, Huber 유지) → 실패 시에만 131-b(손실만 순위로).
3. **600s 변별 신호 소멸은 아직 가설**: 혼잡 구간별 |D| 평균·분산·최선-최악 차·최대
   개선량이 0 으로 주는지 직접 확인 필요 → YR-131 관찰 부속으로 동결.
4. **게이트 명칭 분리**: 물리적 안전 = mask·resolver / 운영 보호 = SF fallback 게이트
   (운영 게이트는 물리 안전장치가 아님).
5. **세대 표기**: 3세대 아님 — 상위 구조(TOS→TransferResolver→단일 Block Q→블록 내부
   안전 resolver) 불변이므로 **2세대 BlockQ-v1(전체비용 회귀) → BlockQ-v2(상태당 K-후보
   잔차·순위)** 로 기록. 3세대는 권한·계층 자체가 바뀔 때.

## 확정 10단 사다리 (각 단 = 단일축·자기 실증 후 다음)

1. ~~YR-130~~ 완료·기각 (갱신량 아님) → 2. **YR-131-a** K-후보만 (Huber 유지) →
3. 필요 시 **YR-131-b** 순위손실만 → 4. 모두 실패 시 결정 분해·상태 별칭·라벨 반복성·
크레인 관계정보 검사 → 5. 순위 살면 **종결 잔여비용** 추가 → 6. **SF-SPT 기준 재라벨**
(개선량 해석 + fallback 게이트 검증) → 7. **PREPOSITION** 단일축 → 8. **DEFER_UNTIL**
단일축 → 9. 현행 시간·비용계약에서 단일 Block Q 검증 → 10. 검증된 Block Q 를
TransferResolver 와 결합.
