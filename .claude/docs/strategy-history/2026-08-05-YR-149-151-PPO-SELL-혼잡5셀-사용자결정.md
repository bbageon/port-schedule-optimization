# YR-149·151 — PPO SELL 구축과 5부하 데이터 시험 사용자 결정

## 1. 사용자 결정

사용자는 source 판매작업을 중앙 계산기가 고르는 데서 멈추지 않고, **각 Block PPO가
`SELL`을 직접 학습**하도록 다음 세대를 진행하기로 했다. 동시에 기존에 정한 트럭 부하
`50·75·100·125·150`의 합성 실험자료가 실제로 서로 다른 혼잡상태를 만드는지도 시험한다.

실제 TOS 연동은 계속 제외한다. 외부 TOS는 최초 작업·블록·예약·ETA를 이미 발행했다는
입력 배경이고, 연구 안의 TransferResolver가 시뮬레이터 owner만 원자 변경한다.

## 2. 확인된 현재 상태

- Block PPO는 한 블록 안 2개 YC의 공동 실행순서만 학습한다.
- 명시적인 SELL/BUY head는 아직 없다.
- YR-133의 source top-1은 계산식이며 YR-149 정렬 표본 17건 중 실제 비용 개선 6,
  악화 11이었다. 이는 PPO가 우월하다는 증거가 아니라 새 학습 질문의 근거다.
- 실제 gate-in 뒤 블록 도착까지 3~7분이라 큰 계산·협상을 하기에는 창이 짧다.
- 공개 ETA는 미리 존재하므로 첫 PPO SELL은 **미도착 반입의 30분 예측창**을 쓴다.

## 3. 채택 아키텍처

```text
TOS 최초배정 입력 → 각 Block PPO ─ ExecutionHead(블록 안 실행)
                               └ TransferHead(KEEP/OFFER_SELL)
                                                  ↓
                              receiver 계산견적 → TransferResolver
                                                  ↓
                                  KEEP 또는 시뮬레이터 원자 재배정
```

- SELL은 크레인 이동·서비스 행동이 아니라 별도 작업목록 결정이다.
- PPO는 원소유 작업을 유지한 채 offer만 낸다.
- PPO는 목적지 선택·owner 변경·rollback을 하지 않는다.
- receiver는 BUY를 학습하지 않고 부담/불가 사유만 계산한다.
- Resolver가 허용블록·용량·version·비용을 확인하고 최종 확정한다. 현재 gate-in 전 이송을
  거절하는 엔진에는 0단계에서 PRE_GATE 원자 transaction을 추가한 뒤 동결한다.

## 4. 한 번에 한 축

첫 YR-151에서는 YR-148의 채택 실행 PPO와 안전장치를 고정한다. 별도 transfer adapter·
TransferHead·critic만 학습한다. 실행 PPO 동시 미세조정, receiver 학습, 양하, 다건 matching은
섞지 않는다.

비교군은 다음 세 개다.

1. `K`: 이송 없음.
2. `Q30`: PPO와 같은 30분 시점·후보·정보의 계산견적 + 같은 receiver/Resolver.
3. `S`: PPO SELL 발의 + 같은 receiver/Resolver.

`S`가 `Q30`만 이기면 계산식의 나쁜 발의를 걸렀다는 뜻이고, `K`까지 이겨야 SELL 이송의
절대 비용가치를 인정한다. 완주·backlog·본선·A→O 보호도 함께 통과해야 한다.

## 5. 30분 ETA 결정창

- 실제 gate-in이 아직 발생하지 않은 PRE_ADVICE/PLANNED 반입만 대상이다.
- 공개 예상 블록도착이 현재부터 1,800초 안이면 후보가 된다.
- ETA가 창에 진입하는 시각, 공개 ETA 변경, 작업완료·장비·용량 변화 때 재검토한다.
- 실제 미래 gate-in/block-in/O, 미통지 사건은 보지 않는다.
- review 중 ETA version 변경이나 gate-in 발생 시 offer가 만료된다. 수락되면 gate-in 전에
  실행 블록·owner·미래 arrival event를 즉시 원자 확정하고 TOS 최초배정 이력은 보존한다.

이 결정창이 현재 gate-in 기반 YR-133과 다르므로 YR-151 0단계에서 후보 노출·누출·사건순서를
먼저 검증한다. 단순 초단위 재계산은 하지 않는다.

## 6. 혼잡 5셀의 정확한 뜻

기존 채택 셀은 `A/B=50/50·75/50·100/50·125/50·150/50`이다. 숫자는 **첫 4시간의
블록별 외부트럭 작업 수**이며, 터미널 합계는 `100·125·150·175·200`이다. 동시 체류대수는
아니다. B는 50으로 고정하고 source A 부하만 높여 재배정 기회를 만든다.

각 셀은 `gaussian=False` exact count와 A150 master trace의 nested 부분집합을 쓴다. 정책
비교 전에 다음을 자격시험한다.

- A150에서 A50/75/100/125의 nested job-id와 B50의 5셀 byte 동일성.
- 동일 초기적재와 본선 start/completion/ETD/moves/cadence/physical-minimum 직접 assert.
- deadline·fill·flow비율을 포함한 full config digest와 정책군별 동일 roster.
- 시간가중 활성 WIP(`A≤t<O`), queue, 평균 A→O, YC busy율, 처리량.
- 4h/6h backlog와 drain-to-empty.

`50/75/...`를 결과 전에 양호·보통·혼잡이라고 부르지 않는다. 4h·6h backlog와 사전 drain
cap으로 `CLEAR/BUSY/OVERLOADED`를 사후 기계 분류한다. 따라서 트럭 수가
증가해도 실현 혼잡지표가 달라지지 않으면 “혼잡 5단계”가 아니라 “입력 부하 민감도”로만
보고한다.

YR-149는 이 데이터 자격과 SF+계산견적 기준선을 만든다. PPO SELL의 성능은 YR-151에서만
판정한다. YR-150은 ARR 숫자를 동시대수로 재사용하지 않고 YR-149 실현값으로 보정한
`WIP-CAL` 정상상태 보조실험이다.

## 7. 실행 순서

1. 진행 중 YR-149에서 5셀 데이터 자격·계산견적 기준선을 동결한다.
2. YR-151 0단계에서 30분 ETA 후보·PRE_GATE 원자성·정보안전·노출을 검증한다.
3. shadow에서는 배선·정보안전만 검사한다. 실행하지 않은 행동으로 PPO를 학습하지 않는다.
4. train simulator에서 SELL 행동을 실제 resolver에 적용한 자기 궤적으로 on-policy 학습한다.
5. K/Q30/S를 신규 seedbank와 5셀에서 비교한다.
6. YR-151이 통과한 뒤에만 YR-150 정상상태에 learned-SELL 군을 추가한다.

## 8. 주장 상한

- 합성 2블록·2YC 환경에서 PPO SELL의 비용효과까지만 주장한다.
- 50~150을 DGT의 실측 혼잡등급이라고 부르지 않는다.
- 실제 TOS 연동·현장 소유권 변경·운영 배포 가능성은 주장하지 않는다.
