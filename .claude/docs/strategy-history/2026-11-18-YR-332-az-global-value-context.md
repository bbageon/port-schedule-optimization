# YR-332-az: 전역 대기 정보의 설명력을 먼저 확인하는 결정

## 가설의 범위와 대안

가설은 같은 지역 후보 상태에서 전역 외부 트럭 대기 규모가 남은 비용 예측에 추가 설명력을 갖는가다.
전역 정보 부족이 이미 확정된 원인이라는 주장은 아니다. 양수 학습 신호 비율을 성공 기준으로 쓰지 않는다.
검토한 대안은 비용망 눈금 추가 조절, 선택망에도 전역 입력 추가, 본선·트럭별 여러 상태 동시 추가,
개별 행동의 반사실 비용 분리, 그리고 보상창 축소였다. 이번에는 모두 제외했다.
그 이유는 기존 증거에서 남은 예측 문제를 직접 겨냥하는 한 축 비교를 지키고 원인을 분리하기 위해서다.
본선 상태를 추가하지 않았다는 한계는 남는다. 외부 트럭 대기 합계 하나가 터미널의 충분한 상태는 아니다.

문헌도 중앙 비용 예측이 언제나 좋다고 보장하지 않는다.
MAPPO의 전역 정보 활용 원리와 중앙 평가자 분석의 편향·분산 경고를 함께 확인했다.
따라서 새로운 정보를 넣자마자 강화학습 예산을 쓰지 않고 같은 경험의 예측 비교를 앞에 둔다.
공유 표현은 예측 진단에서는 고정한다. 정책 비교에서는 기존처럼 공유하여 비용 손실이 표현에 영향을 준다.
공유 표현까지 분리하는 별도 아키텍처 실험은 포함하지 않는다.

## 정보 시점·단위 계약과 구현 검토

각 블록은 `run_until_decision`까지 독립 전진한다. 결정 중 다른 객체의 대기를 합산하면 미래가 섞일 수 있다.
초기0과 기존review의 전 블록 동기화 지점에서만 읽기 전용 관측을 만든다.
관측은 공개 접수와 원장 갱신 후 저장하며 기존 사건·결정·접수 주기를 늘리지 않는다.
review가 같은 시각의 블록 사건보다 먼저 돌아올 수 있음을 엔진에서 확인했다.
이 동률은 실제 처리 순서를 따르며 나중에 처리될 도착·시작을 관측 당시 상태에 역으로 넣지 않는다.
활성 블록의 시각 일치, 모든 블록의 미래 시각 부재, 합계, 결정시각 이하 관측을 검사한다.
대기는 `kpis.waiting_count()`의 블록 도착 후 서비스 시작 전 외부 트럭 오더다.
이는 물리적 차량 줄 길이도, 방문 수·본선 작업 대기 합계도 아니다.
동일 프로파일을 블록들이 공유하므로 profile.block_id를 결정 블록 식별자로 쓰면 잘못될 수 있다.
실제 terminal의 simulator 객체→block key 대응을 사용하도록 구현했다.
24시간 뒤에는 기존 동기화review가 호출되지 않으므로 관측은24시간 값으로 남는다.
학습은24시간 전 결정만 사용한다. 배수 구간의 오래된 관측은 별도로 기록하며 미래 값으로 채우지 않는다.

입력은 `log1p(total_waiting_orders)/log1p(21*10)`이며 상한을 자르지 않는다.
상수는 기존21블록×블록 대기 눈금10에 따른 고정 단위다. 평가자료로 분모를 고르지 않는다.
두 군 모두 같은66→64→1 비용망이고 zero군은 마지막 입력을0으로 만든다.
기존65열을 그대로 복사하고 새 가중치 열을0으로 두므로 처음 예측과 작업 선택은 같아야 한다.
원자료에는 실제 관측을 양 군 모두 보존하고 신경망 입력0과 구분한다.
새 경험 저장 형식v2는 관측 근거·실제 신경망 입력을 명시한다. 구형 저장 함수가 이를 조용히 버리지 않게 한다.
과거 소스·해시는 그대로 과거 커밋에 보존한다. 현재 코드를 바꿔 과거 해시 검사 통과를 주장하지 않는다.

상세 수치·감사 통과·원격 공개 근거는최종보고서와verification/publication JSON에 보존한다.
최종 감사는 통과했다. 블록 스냅샷4,271,442개·결정 관측152,797개를 원장과 대조했고
동일 타임스탬프의 범위 판정이 필요한 사례는0개였다. 원장 계산과 관측 대기가 정확히 일치했다.
전체 캐시 목표·전역 입력·메타데이터가 원표본과 일치했고 저장 모델의 모든 예측값도 정확히 재생됐다.
Transformer 표현189건 점검의 최대 절대차는9.54e-7, 독립RMSE 계산의 최대 절대차는2.28e-9였다.
물량·시간대별 독립 계산도 같았고 예측 진입 조건 미통과 판정이 재확인됐다.
24시간 전 관측 지연은평균9.14초·중앙값5.34초·95%가32.13초 이내·최대59.99초였다.
대기 입력은0~4,090오더, 변환값0~1.55395였고 상한 절단은 없었다.
24시간 뒤 결정10,881건은 마지막 관측을 사용해 최대7,199.72초의 지연이 있었고 학습에서 제외됐다.

원격 공개 검사는 첫 실행에서 미실행PPO의 난수 세 항목을 빈 배열로 기록해 실패했다.
하네스는 모든 난수 항목이 비어 있지 않은 정수 목록이어야 하므로 "절대 시드 목록 미기록"으로 판정했다.
실제 실행 난수는campaign/표본에 모두 있었으며, 실행하지 않은 단계의 빈 항목만 공개 도구에서 제외했다.
동작 시험 입력·행동·업데이트 난수도 공개 기록에 명시했다. 판정 하네스의 검증 기준은 바꾸지 않았다.
첫 실패 판정과 공개 명세는current-gates-initial.json/publication-initial.json으로 보존했다.
원자료·보고서·고정 학습 코드와 숫자는 바꾸지 않고 공개 도구만 수정하여 다시 검사한다.
