# v3 리뷰 대응 정밀 검토 — 사용자 범위 수정 반영

2026-09-14 · 연결: YR-317(리뷰 개정 묶음).
**현행 전략은 이 문서와 연결된 두 상세 문서다.** 앞선 전략은 최초 판단 이력으로 보존한다.
이번 작업은 코드·기존 원자료의 읽기 전용 감사와 전략 수정이다. 신규 시뮬레이션·재학습은 0회다.

## 1. 사용자가 정한 범위

사용자는 예약 정원·최소 통지 여유·일정 변경 부담을 이번 개정의 새 실험으로 넣기보다,
결론에 물리적으로 불가능한 행동을 막는 제약층의 필요성과 후속연구를 명시하자고 결정했다.
이 결정을 채택한다. YR-317-b는 **결론·한계·후속연구 서술**로 바꾸며 다른 실험의 선행에서 뺀다.
정원 실험·외부 대기 비용 신설·손익분기 단가 실험·새 제약층 구현은 이번 개정 범위 밖이다.

권장 결론 초안:

> 본 연구는 시간대별 예약 정원과 운송사의 일정 변경 부담을 충분히 반영하지 않은
> 시뮬레이션에서 제안 구조를 평가했다. 실제 적용을 위해서는 통지 여유, 차량의 이동·작업 일정,
> 예약 용량에 비추어 실행할 수 없는 변경을 제외하는 제약층이 필요할 것으로 보인다.
> 일정 변경과 외부 대기의 경제적 부담을 반영하고 이러한 제약 아래에서 순편익을 검증하는
> 작업은 후속연구로 남긴다.

비용 부담은 물리적 가능 여부와 다른 문제이므로 두 한계를 구분해서 적는다.
실험조건 설명에도 미적용 사실을 한 문장 남긴다. 결론으로 이관했다고 실험 가정이 사라지지는 않는다.
이 대응은 Reviewer 1의 해당 항목을 **추가 실증 대신 주장 범위 제한으로 처리**하는 전략이다.
심사자가 요청한 현실 제약 실험까지 해결했다는 답변은 하지 않는다.

## 2. 정밀 검토에서 새로 확인한 사실

| 발견 | 코드·자료 근거 | 전략에 미치는 영향 |
|---|---|---|
| 기존 학습 전 모형은 진짜 초기값이 아님 | `month_loop.on_day`는 학습 뒤 저장. `history[0]`에 라벨 55건·손실 기록 | `ckpt_000`은 첫날 학습 후 모형으로 정정. 실제 학습 전 비교는 새 초기 가중치 저장 필요 |
| 판매 후보는 각자 KEEP과 비교 | `branchpool.run_job_with`, `loop._collect`, `labels.add_seller` | 임의 a-b/b-c 비교 반례를 실제 v3 결함으로 적용하지 않음. KEEP 비교와 일반화 오차를 검사 |
| 거절 제거에도 수락망 점수는 남음 | `Buyer.respond`는 `always_buy`에서도 망 실행, resolver는 그 값으로 정렬 | 거절권과 수락망 전체 제거를 서로 다른 비교로 구성 |
| 기존 추가 평가에 미투입 트럭 존재 | 수락망 평가 28일: 재배치 없음 1,919·전체 745·거절 제거 675대 | 누락 이유·대상 보존 확인이 성능 실험보다 먼저 필요 |

수락망 비교 비용 차이 2.9491억은 합계로 존재한다. 그러나 위 미투입 차이를 확인하기 전에는
같은 작업을 모두 처리한 순수 정책 효과로 확정할 수 없다. 미투입의 원인과 영향 크기는 현재 집계만으로 모른다.
`V3Announcer`에는 종료창 밖, 반출 대상 없음, 투입 예외의 세 경로가 있으므로 용량 문제로 단정하지 않는다.
한산·보통·혼잡 민감도 자료에서도 미투입이 관찰됐다. 해당 자료 역시 진단 증거로 한정한다.

이는 새 예약 정원 도입과 별개다. 이미 약속한 **동일 수요를 보존한 평가인지**의 문제다.
YR-317-g를 기존 투입 장부·실패 판정의 직접 보정 후보로 등록한다. 새 운영 제약·비용 항을 추가하지 않는다.

## 4. 두 행동 비교 문제의 정확한 답

앞선 문서는 임의의 a-b와 b-c 비교를 예로 들었다. 코드를 더 따라가 보니 실제 v3는
**KEEP 대 특정 SELL 좌표**의 쌍을 사용한다. 이 차이를 반영해 설명을 정정한다.

같은 상태에서 K를 유지 비용, C(a)를 후보 a 실행 후 비용이라 하면 변경 후보의 목표는
`(C(a) − K) / 2`다(단위 정규화 제외). 따라서 변경 후보끼리의 이상적인 목표 순서는 비용 순서와 같다.
하지만 KEEP 목표는 `(K − C(a)) / 2`라 어느 후보와 비교했는지에 따라 달라진다.
실제 망이 KEEP까지 함께 최소값을 고르므로 **변경 여부의 문턱과 미관측 후보 일반화**는 따로 검증해야 한다.
또 수락망의 거절 행은 제안 특징을 지운다. 어떤 제안을 거절하는지의 일부 정보가 사라지는 문제도 별도 검사한다.

권장 대응은 수식을 정확히 설명한 뒤 고정 상태에서 모든 후보의 실제 비용과 선택 결과를 대조하는 것이다.
일반적인 순위 논증만 보강하거나 손실이 작다는 그림만 추가하는 것으로 끝내지 않는다.
상세 표집·분기·판정 계약은 [선택 정확성 설계](2026-09-14-v3-review-ranking-detail.md)에 둔다.

## 5. 통계·제거 비교·민감도를 한 번의 자료 수집으로 연결

독립 30일 실행 20개를 같은 정책 8종으로 평가하는 것을 예산용 기본안으로 제안한다.
월 단위 비용 차이가 주표본이다. 28일×20을 독립 560일로 세지 않는다.
최종 월 개수는 별도 진단의 변동·원하는 정밀도와 계산 예산으로 사전 고정한다.
20이 확증을 보장하는 숫자는 아니다. 평가 결과를 보고 수를 늘리지 않는다.

8종은 재배치 없음, 공간·시간 규칙, 시간 규칙, 전체, 시간만, 공간만,
거절권 제거, 수락망 완전 제거다. 신규로 필요한 것은 수락망 완전 제거 비교와 정확한 측정·검사 배선이다.
학습 효과는 진짜 초기값을 저장하는 별도 재학습 묶음에서 검증한다.
수락망 제거 효과가 있어도 수락망만 유일한 설계라고 주장하지 않는다. 단순 수락 규칙과의
추가 비교는 “학습된 수락이 단순 규칙보다 낫다”는 주장을 넣을 때 사전 고정한다.

비용 민감도는 **기존 네 비용 항의 가중치만** 바꿔 같은 실행을 재합산할 수 있다.
새 일정 변경 비용은 추가하지 않는다. 수요 연속성·긴 운영기간은 궤적이 바뀌므로 별도 실행이다.
계산 수량과 통계·하드가드·서술 기준은 [반복·제거 비교 설계](2026-09-14-v3-review-evaluation-detail.md)에 둔다.

## 6. HCI와 재현성에서 이번에 해야 할 최소 작업

HCI(사람과 시스템의 상호작용) 대응은 먼저 **사용자·업무·권한을 원고에 명시**한다.
터미널 담당자는 운영 상태와 변경 제안을 검토하고, 운송사 배차 담당자는 일정 변경 가능 여부를
협의하며, 운전자는 확정 안내를 받는 사용 맥락을 제안한다. 소프트웨어 Buyer와 사람의 동의는 구별한다.
현재 구현된 내부 정책 흐름과 후속연구의 사람·운영 시스템 연동은 그림에서 구분한다.
새 제약층·사용자 승인 기능을 이번 v3에서 구현한 것처럼 묘사하지 않는다.
사용자 과업 평가는 심사위원의 맥락 명확화 요구를 넘는 추가 연구이므로 이번 필수 실험으로 고정하지 않는다.
HCI 효과를 실증했다고 주장하려면 별도 사용자 평가가 필요하다는 제한은 유지한다.

처리시간은 `MarketBridge.review` 전체와 `Market.step`·두 망·resolver를 중첩 계측한다.
합계를 이중으로 더하지 않고 전체 구간을 직접 잰다. 입력 동기화·후보 생성·확정까지 포함한다.
빈 결정주기와 실제 제안이 있는 결정주기를 나눠 중앙/P95/P99/최대·60초 초과율을 기록한다.
P95는 100회 중 느린 5회가 시작되는 값이다. 외부 통신·사람의 응답은 미측정 구간으로 둔다.
첫 1,000회만 재지 않고 하루 시간대와 부하를 고르게 포함한 상태를 사전 선택한다.

## 7. 검토 결과와 남는 제한

이번 개정의 중심은 **현재 비용·환경 가정 아래의 정책 검증을 신뢰할 수 있게 만드는 것**이다.
물리적 실행 가능성과 운송사의 경제적 부담은 사용자가 정한 대로 결론·후속연구에서 다룬다.
반복 시드가 늘어도 합성환경이라는 Reviewer 2의 한계는 남으므로 특정 항만 실성능으로 확대하지 않는다.
선택 정확성·공간 추가·수락망 추가·학습 기여 중 어느 하나가 실패하면 해당 주장만 축소한다.
