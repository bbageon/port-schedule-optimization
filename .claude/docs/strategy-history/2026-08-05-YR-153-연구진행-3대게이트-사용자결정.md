# 2026-08-05 — YR-153 연구 진행 3대 게이트 사용자 결정

## 1. 결정 배경

실험이 길게 이어졌지만 사용자가 가장 먼저 알고 싶은 것은 새 기법의 수가 아니라 다음 세 사실이다.

1. 현재 정책이 규칙보다 실제로 좋아졌는가.
2. Dashboard에 적힌 설명이 실제 실행 코드와 원자료에 맞는가.
3. 생성 시드가 항만에서 가능한 사건·부하 흐름인가.

앞으로 이 셋을 확인하지 않은 채 새 가설을 연속해서 추가하면, 성능이 없는 정책을 정교하게 설명하는
데 시간을 쓰거나 잘못된 환경 위에서 성과를 주장할 위험이 있다.

## 2. 채택한 원칙

세 항목을 모든 연구 단계의 공통 게이트로 둔다. 상태는 `PASS`, `FAIL`, `INCONCLUSIVE`만 쓴다.

- `PASS`: 다음 목표 단계로 이동할 증거가 충분함.
- `FAIL`: 충분한 표본 또는 하드 계약으로 미달이 확인됨.
- `INCONCLUSIVE`: 표본·자료·구현이 부족해 아직 판단할 수 없음.

실험 실패는 오류가 아니므로 원자료와 판정은 먼저 저장한다. 게이트는 결과 삭제가 아니라 다음 주장과
작업 범위를 제한한다.

## 3. 성능 게이트

주지표는 최종 터미널 총비용이며 후보−SF-SPT의 짝지은 원정밀도 신뢰구간을 쓴다. 트럭 A→O,
본선 지연, 완주, backlog, 물리 위반은 보호 지표·하드 가드다. 결과를 반올림한 뒤 통과 여부를
판정하지 않는다. 최소검출가능효과가 사전 관심효과보다 크면 `효과 없음`이 아니라 `INCONCLUSIVE`다.

## 4. 신뢰성 게이트

실행 시점과 완료 기록 시점이 다르므로 두 번 검사한다.

1. 실행 시점: commit, dirty 여부, 절대 시드, 전체 설정, 사전등록, 산출물 hash를 결과에 기록.
2. 완료 시점: Dashboard ID가 한 상태 파일에만 있는지, spec 상태와 같은지, evidence 경로와 commit이
   실제 존재하고 origin에 반영됐는지 검사.

이번 코드 감사에서 기존 `evalkit.judge_primary()`가 표시용 3자리 신뢰구간으로 판정하던 결함을 찾았다.
이는 신뢰성에 직접 영향을 주므로 YR-153 범위에서 원정밀도 판정으로 수정한다.

## 5. 현실성 게이트

현실성은 한 개의 `realistic=True`로 처리하지 않는다.

- 내부타당성: 사건 순서, 미래정보 누출, 물리·안전, 소유권·비용 장부, 달성 가능한 마감, 결정론.
- 지속운영 타당성: 평가창 끝까지 도착, warm-up 분리, 도착률≈완료율, WIP·backlog 안정성.
- 외적 타당성: 공개자료·문헌 보정 수준과 실제 운영 이력의 자료등급.

현재 50·75·100·125·150은 4시간 유한 도착 건수다. 사후 BUSY/OVERLOADED 분류는 회복시험의
결과일 뿐, 실제 터미널의 양호/보통/혼잡 등급으로 곧바로 이름 붙이지 않는다.

## 6. 새 가설 허용 조건

세 게이트가 모두 통과하면 새 진단을 만들지 않고 연구 목표의 확증·잠금평가로 진행한다.
미통과가 있으면 그 항목을 직접 해결하는 단일축 보정만 허용한다. 성능이 충분한 검정력으로 실패했을
때도, 특정 손실 기제가 독립 시드에서 반복되고 그 기제를 없애면 개선될 반사실 근거가 있어야 새
가설을 등록한다. 그렇지 않으면 해당 정책 범위를 닫는다.

## 7. 결정 당시 상태

- 최종 성능: 지속 유입 조건의 SF-SPT 대비 전체 터미널 비용은 아직 미확정.
- 코드·증거: YR-149의 Dashboard·spec·경로·origin commit은 일치했지만 원자료 실행 스탬프가
  `git_dirty=true`이고 전체 설정이 비어 있어 신뢰성 게이트는 FAIL. 공용 판정 결함 1건도 수정 중.
- 시드 현실성: 문헌 보정 단일블록 물리는 가능한 범위이나 지속 유입 안정성과 실제 운영자료 대조는 미완.

따라서 다음 허용 범위는 YR-151 0A(신뢰성) → YR-150(현실성) → YR-151 0B(성능)이며,
각 단계는 한 게이트만 직접 닫는다.
