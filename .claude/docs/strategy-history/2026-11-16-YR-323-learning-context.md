## 사후 점수 계약 반례와 후속 등록

학습은같은 크레인의후보 점수 차이만 보지만 `CentralResolver`는모든 크레인/후보 절대 점수를 오름차순으로 정렬한다.
모든 서로 다른 작업 조합이 가능한 장난감 oracle과 실제 배정기에서C1(A0,B1),C2(A2,B10)는C1A/C2B를 고른다.
C1의두 점수에100을 더하면C1(A100,B101),C2(A2,B10)가 되어C1B/C2A를 고른다. 두 크레인의차이는−1/−8로 동일하다.
즉 크레인 내 차이 손실은같아도공동 배정은다를 수 있다.100은 반례 값이며비용·보상에 새로 넣지 않았다.
`score-offset-audit.json`에 실제resolver호출·소스지문을 남겼다. 이는훈련망의악화 원인을측정한 실험이 아니다.
저장 망에서적용 조건·발생 빈도를 읽기 전용으로 확인하는au를backlog에 등록했다. 자동 중심화·추가층·재학습은하지 않았다.

마지막 원격 포장 검사에서Windows CRLF가Git의core.autocrlf=input에 의해LF로 저장되어파일지문이 달라지는 문제를 발견했다.
새 네 보고서 트리만.gitattributes의-text로 고정하고 원래바이트를 다시 stage했다. 숫자·원래해시·실험입력을 고치지 않았다.
기존 동결 소스 중bank.json과multiscale-minute-calibration.json의저장 바이트도 원래해시와 같게 보존했다.
`publication-byte-audit.json`은Git index의메타데이터·동결소스·검증값을 직접 대조한다. 이전 중간 커밋의줄바꿈 차이는최종공개에서보정했다.
