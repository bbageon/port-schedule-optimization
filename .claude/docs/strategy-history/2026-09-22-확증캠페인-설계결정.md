- 따라서 수직형 Y05/Y14 결함과 같은 원인이며, 그때 만든 "실행 가능 후보 우선" 구현을

## 2. 수정은 교착 전용이 아니다 — 그래서 새 사전등록이 필요하다

시험이 못박았다: 같은 시드·같은 하루에서 두 모드의 비용이 **다르다**
(2,819,950 vs 2,894,949원). 예산이 꽉 찬 **모든 순간**에 후보 집합이 바뀐다.

→ ①기본값을 `legacy` 로 두어 기존 80건은 글자 하나 안 바뀌고 재현된다
  ②수정 엔진의 결과는 기존 80건과 **직접 비교 불가** → [[YR-318]] 새 사전등록.

이 사실은 시험을 쓰다가 발견했다. 처음 쓴 시험은 *"작은 하루에서는 두 모드가 같다"* 를
가정했고 **실패했다**. 가정이 틀린 것이지 코드가 틀린 것이 아니었다.

## 3. 처리시간 계측에서 무엇을 뺐는가

`MarketBridge(measure_latency=True)` — 60초 검토 주기당 후보 구성·채점·경합 해소·확정.

**뺀 것**: ①시뮬레이션 진행 자체 ②학습 전용 스냅샷 복제. 평가 시점에 존재하지 않는
비용이라 넣으면 이중 계산이다. 이 범위를 결과의 `scope` 문자열에 박아 둔다.

⚠️ 아직 **측정값이 없다**. `NO_REALLOC` 은 결정 주기 자체가 없어 표본이 0이다.
실제 수치는 정책 팔이 도는 [[YR-318]] 에서 나온다. 원고는 "측정되지 않았다"를 유지한다 —
**장치를 만든 것과 측정한 것은 다르다**.

## 4. 확증 캠페인 설계 — 세 번 고쳤다

### 4.1 규칙 대조군이 0개라는 발견

동결 규약(`.claude/docs/architecture/06-학습과-판정.md:103`)은 주판정 축이 **규칙 대비**이고
*안 팔기 대비는 판별력 0*(YR-185 실패)이라고 못박는다. 기존 80건에 규칙 팔이 **하나도 없다**.
즉 지금 원고에는 "학습이 규칙보다 낫다"는 증거가 구조적으로 존재하지 않는다.
→ `SLOT_LL`(시간만)·`SPACE_TIME_LL`(블록+시간)을 넣는다. 둘 다 이미 엔진에 있다.

### 4.2 학습 3판을 어떻게 판정에 넣을 것인가 — 세 번 바꿨다

- **1안(폐기)**: 학습판마다 캠페인을 따로. → 결과 병합이 취약하고 짝 통계가 깨진다.
- **2안(폐기)**: 세 판을 각각 확증하고 5% 예산을 셋으로 나눠 98.33% 구간.
  → 같은 규약 표가 *"격자: 다중비교 방지 — **주판정 하나만** 미리 고정"* 이라고 적는다. **규약 위반.**
- **3안(채택)**: 월마다 세 판의 비용을 평균한 **파생 열** `RL_TIME_mean` 을 만들고
  `28d:SLOT_LL-RL_TIME_mean` **하나만** 확증한다(95%).
  추정 대상이 *"이 학습 절차가 만들어내는 정책"* 이 되어 규약을 지키면서
  **"잘 나온 판만 고르기"가 구조적으로 불가능**해진다.
  추가 안전장치: 구간이 0을 넘어도 **세 판의 부호가 갈리면 확증으로 쓰지 않는다.**

### 4.3 학습 3판 = 환경 시드와 초기화 시드를 함께 바꾼다

`--init-seed` 를 환경 시드와 같게 **명시**한다. 추정 대상이 "학습 시드 효과"가 아니라
"학습 절차 전체를 다시 돌린 결과"이므로 둘을 함께 바꾸는 쪽이 사전등록 문장과 일치한다.
`ckpt_init.pt` 는 이미 저장되므로 **무학습 대조군을 추가 비용 0으로** 얻는다.

## 5. 실행기를 어디까지 일반화했나 (그리고 무엇을 안 건드렸나)

- **안 건드린 것**: `independent_eval_checks.paired_summary` — 80건의 동결 계약.
  새 통계는 `campaign_checks.py` 로 **따로** 만들었다.
- `campaign_specs(cfg)` — 열 하나 = `label` + `arm` + `checkpoint`. 한 팔을 학습 판마다
  여러 열로 둘 수 있다. 기존 `yr317.independent-evaluation.v1` 설정은 동결값과 **정확히**
  같아야 통과하고, 새 캠페인은 사용 완료 시드·진단 대역·미지의 팔을 기계가 거절한다.
- **공급 사전검사를 우회했다** — 그 검사는 `manifest.repro.checkpoint_sha256` 이 캠페인
  체크포인트와 같기를 요구한다. 가중치가 셋인 캠페인은 구조적으로 통과할 수 없다.
  대신 **월별 입력 지문 전수 대조**(`expected_month` × 20)로 바꿨다. 실제로 이번 실행의
  입력을 지키는 것은 그쪽이다.
- 시드 은행 생성기에 `--base/--count/--created-date` 추가. 기본값은 기존 대역이라
  기존 사전등록 파일이 그대로 재생성된다.
- 공급 보정 입력 생성기(`audit_supply_plan.py`)는 **고칠 필요가 없었다** — 시드를
  은행 요약에서 읽으므로 새 대역에 그대로 쓴다. 출력 폴더가 있으면 거절하니 커밋 해시로 짓는다.
- 열 이름은 파일명 안전 문자만 허용한다. 처음에 `RL_TIME:n1` 로 지었는데 열 이름이
  `outputs/` 아래 **폴더 이름**이 되고 저장소는 Windows 파일 시스템 위에 있다 — 콜론은
  거기서 깨진다. 여섯 시간 뒤가 아니라 설정을 만들 때 거절하도록 검사를 넣었다.
- 설정을 손으로 쓰지 않는다(`make_campaign_config.py`) — 지문 오타 하나가 1,000 CPU-시간을
  버린다. 미완성 학습·계약 불일치 학습·누락 입력을 생성기가 거절한다.

## 6. 남은 판단

- 기존 80건은 **재실행하지 않는다**(사용자 결정 범위 ①). 사전등록 표를 그대로 두고
  결함을 한계에 공개한다. 수정 엔진의 판정은 새 대역에서 한 번만.
- 캠페인 결과가 C·D(규칙을 못 이김)로 나오면 논문의 기여를 *학습 성능*이 아니라
  *반사실 라벨 구조와 계측 방법*으로 다시 쓴다. 이 문장을 **결과 보기 전에** 사전등록에 적었다.
