# P95 평가계약 정정 — 채택 게이트에서 보고용 진단으로

> 기록일: 2026-07-27
> 상태: **사용자 결정 — 향후 평가계약에 적용**
> 적용 대상: YR-041 재집행, YR-099 후속, YR-014 최종평가와 이후 신규 실험
> 비적용: 이미 동결·완료된 사전등록과 원자료의 수치 변경

## 1. 한 줄 결정

> P95는 학습목표·후보선택·채택 거부조건에서 제외하고 `B→C`와 `A→O`의
> **보고용 꼬리 진단값**으로만 남긴다. 장기대기 보호는 시간비용, SLA 초과량과
> mandatory 우선처리로 판정하며, 실제 터미널이 P95 SLA를 제공할 때만 하드 게이트를
> 다시 검토한다.

P95는 트럭 100대 중 오래 걸린 상위 5대 부근의 시간이다. 분포 끝부분을 보여주는
유용한 설명값이지만, 현재 표본과 계약에서는 정책의 합격·불합격을 단독으로 결정할
근거가 아니다.

## 2. 이 결정이 필요해진 경위

과거 본선 인지 정책은 본선 지연을 줄이는 대신 구 `S→B` 대기 P95를 8~12분
악화시키는 사례를 만들었다. 당시에는 이를 막기 위해 assumed(실측 아닌 가정)
`δ=3분` 비열등 게이트와 mandatory 필터를 함께 사용했다.

그러나 YR-089가 시간계약을 다음처럼 정정했다.

```text
B = 실제 블록 도착
S = YC 작업 시작
C = 작업 완료
A = 실제 gate-in
O = 실제 gate-out

S−B = 순수 YC 대기, 진단용
C−B = 블록 처리시간, BlockPolicy 책임·학습 구간
O−A = 터미널 턴타임, 최종 운영 KPI
```

YR-041-a 잠금 하네스는 새 계약의 `B→C` 또는 `A→O` P95가 아니라
`p95_wait_min`, 즉 구 `S→B` P95를 읽었다. 따라서 보고된 `−10.4분`은
블록 처리시간이나 터미널 턴타임의 꼬리 개선 증거가 아니다.

동시에 현재 비용·후보 계약은 이미 장기대기를 별도로 다룬다.

- 엔진은 `B→C` 점유시간과 SLA 초과시간을 구간별로 적분한다.
- 비용에는 일반 트럭 시간과 `long_wait` 초과면적이 함께 들어간다.
- 외부트럭이 SLA의 80%에 도달하면 후보를 mandatory로 올린다.
- mandatory 후보는 pruning에서 제거되지 않고 resolver에서 먼저 고려된다.

다만 이 장치들이 P95를 수학적으로 보장하는 것은 아니다. 여러 mandatory 작업의
동시 발생, 긴 서비스·재조작, 물리 경합과 게이트 외생시간은 꼬리를 만들 수 있다.
그래서 P95를 완전히 삭제하지 않고 보고용 경보로 남긴다.

## 3. 새 평가 계층

| 순서 | 지표 | 역할 |
|---|---|---|
| 0 | 안전·물리 위반 0, 완주율 1.0, backlog 0, 검열 회피 0 | 무조건 하드 guard |
| 1 | terminal total cost, 본선 계획완료 초과비용 | 주 채택 판정 |
| 2 | 평균 `B→C`와 블록 점유면적 | BlockPolicy 직접 성과 |
| 3 | 평균 `A→O`와 terminal truck area | 최종 터미널 성과 |
| 4 | `long_wait` 초과면적, SLA 초과 건수·비율·초과시간 | 장기대기 보호·진단 |
| 5 | P50·P95·최댓값 `B→C`, `A→O` | 보고용 분포 진단, 판정 가중치 0 |
| 별도 | `S→B` 평균·P95 | YC 병목 설명용, 턴타임 주장 금지 |

실제 SLA가 아직 없을 때 SLA 임계값은 문헌 보정 stress 가정으로만 표시한다.
실 SLA인 것처럼 운영 채택 근거로 쓰지 않는다.

## 4. 학습·후보선택 계약

- P95를 reward나 Q-network 표적으로 직접 넣지 않는다.
- P95를 rollout 후보 순위나 transfer quote 순위에 넣지 않는다.
- 에피소드 분위수는 일부 트럭이 완료된 뒤에야 계산되고 작은 표본에서 불연속적으로
  움직이므로 행동별 신용 배분에 부적합하다.
- 학습은 현재처럼 누적 시간비용과 기준선 대비 비용차를 사용한다.
- 장기대기 보호가 필요하면 `long_wait` 면적과 실제 SLA 초과량을 직접 사용한다.

## 5. 과거 결과의 재해석

1. YR-071·073·074의 P95 개선은 당시 구 `S→B` 지표의 역사적 증거로 보존한다.
   이를 `B→C`나 `A→O` 개선으로 소급 해석하지 않는다.
2. YR-080의 `δ=3분` 채택 판정은 assumed 조건 아래의 당시 판정이다. 실제 SLA에
   근거한 최종 채택 판정으로 승계하지 않는다.
3. YR-041-a의 `S→B P95 −10.4분`은 참고값으로만 남긴다. 후보 JR1800의 기각은
   본선 비열등 실패(`berth` 신뢰구간 상한 `+9.9 > δ 5.0`) 때문이므로 그대로다.
4. YR-100 후보비교의 P95 값도 동일하게 구 `S→B` 진단값으로 표시한다.

## 6. 함께 고정한 최근 파이프라인 해석

- YR-100이 낮춘 것은 **현재 반응형/CALC 본선 실행타이밍 경로의 우선순위**다.
  긴 lookahead와 목적지 행동을 포함한 단일블록 계획 전체가 불가능하다는 증명은 아니다.
- YR-099의 오라클 `−22.41`은 2블록·시점 0·반입 1건·완벽정보 조건의
  **잠재 상한**이다. 현재 공개정보 quote는 `+3.08`로 개선을 확인하지 못했다.
- YR-101 ensemble quote도 `+3.54 [−4.12,+11.20]`, 실현개선 3/8로 기각됐다.
  K=5 표본평균만으로는 공개정보 quote의 분산·선택편향을 해결하지 못했다.
- 다음 등록 진단은 저분산 비용분해 quote YR-102다. 이 역시 배포 성과가 아니라
  오라클 잠재 상한의 회수 가능성을 확인하는 실험이다.
- 이 P95 계약 정정은 total cost와 소유권 불변식으로 판정한 YR-101의 기각 결과를
  소급 변경하지 않는다.

## 7. 검토한 대안

| 대안 | 판정 | 이유 |
|---|---|---|
| P95를 모든 결과에서 삭제 | 기각 | 평균이 좋아지는 동안 소수 트럭이 희생되는지 발견하기 어려움 |
| P95 비열등을 계속 하드 게이트로 사용 | 기각 | 작은 표본에서 3~4대가 값을 좌우하고 `δ=3분`은 실 SLA 근거가 없음 |
| P95를 직접 reward로 최적화 | 기각 | 희박·불연속 신호라 행동별 책임 귀속이 어렵고 proxy gaming 위험 |
| SLA 초과면적·초과율로 꼬리 보호, P95는 보고 | 채택 | 현재 비용·mandatory 계약과 직접 정렬되고 의미가 명확함 |
| CVaR·분위수 RL 도입 | 보류 | 실제 꼬리 SLA와 충분한 표본을 확보한 뒤 별도 연구로 판단 |

## 8. P95 하드 게이트 재도입 조건

다음 조건을 모두 만족할 때만 신규 사전등록으로 재도입한다.

1. 실제 터미널 계약이나 SLA가 95백분위 목표를 명시한다.
2. 대상 시간이 `S→B`, `B→C`, `A→O` 중 무엇인지 확정된다.
3. 허용한계 `δ`와 표본 집계단위가 실제 자료나 운영 합의로 정해진다.
4. 셀별 트럭 수와 분위수 신뢰구간 방법이 결과 열람 전에 동결된다.

또는 평균·점유면적·SLA 초과량이 모두 개선됐는데도 특정 소수 트럭의 심각한 희생이
반복 재현되면 재검토한다. 재도입하더라도 우선은 평가 제약으로 사용하고 직접 reward는
별도 검증 없이는 사용하지 않는다.
