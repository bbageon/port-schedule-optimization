# WAIT-WAIT 정책 최적화 우선·배포 안전 분리 — 사용자 결정

## 1. 결정

YR-145의 `WAIT+WAIT` 실패를 곧바로 금지·강제대체하지 않는다. 연구 목표는 예외처리로
성공시키는 것이 아니라 **정책이 진행할 때와 기다릴 때를 스스로 구분하도록 최적화하는 것**이다.

순서는 다음으로 동결한다.

```text
정책 최적화(YR-147, 마스크 없음)
→ 단일블록 행동공간 검증(YR-143)
→ 배포 안전장치(YR-146)
→ 블록 간 판매·수용 견적(YR-133)
```

## 2. YR-145에서 실제로 일어난 일

high-loose/910017, PPO 초기화 123000에서 본선 적하 2건이 남았다. 두 크레인의 동시
SERVE는 물리적으로 불가능했지만 한 대씩 작업하는 두 공동행동은 가능했다.

| 공동행동 | PPO 예상비용(낮을수록 좋음) |
|---|---:|
| `SERVE+WAIT` | 14.2435 |
| `WAIT+SERVE` | 13.2208 |
| `WAIT+WAIT` | **12.5055** |

PPO가 전원 대기를 가장 싸다고 오평가했다. 실행 뒤 두 크레인이 모두 양보 상태가 됐고 미래
사건이 없어 재결정이 열리지 않았다. 따라서 “물리적으로 아무 행동도 불가능”이 아니라
**정책 순위 오류와 재개방 없는 WAIT 계약의 결합**이다.

## 3. 금지를 먼저 쓰지 않는 이유

- 하드 마스크가 있으면 완주해도 정책이 배운 것인지 안전층이 대신한 것인지 구분할 수 없다.
- 실제로는 구조적 대기와 전략적 대기가 모두 존재하므로 모든 WAIT에 고정 벌점을 주면
  유효한 기다림도 제거한다.
- PPO는 확률 정책이라 학습만으로 운영상 0건을 보장할 수 없다. 따라서 **최적화와 보장**을
  서로 다른 실험·주장으로 분리한다.

## 4. 정책 최적화 계약

원시 WAIT를 `DEFER_UNTIL(trigger, expiry)`로 바꿔 무엇을 언제까지 기다리는지 명시한다.
같은 상태·같은 난수에서 전원 대기와 안전한 진행 후보의 후속비용을 짝지어 비교한다.

```text
D_wait = C_H(WAIT+WAIT) - min C_H(안전한 진행 후보)
```

양수면 전원 대기가 손해이고 음수면 실제로 기다리는 편이 낫다. PPO는 이 부호·순위를
보조목표로 학습하되, DEFER 의미 교체와 순위손실은 같은 실험에서 동시에 바꾸지 않는다.
희귀 교착상태 추가도 앞 단계가 미달일 때만 별도 단일축으로 연다.

## 5. 판정과 허용 주장

연구 판정에서는 `WAIT+WAIT` 마스크를 사용하지 않는다. 회피 가능한 전원대기율, 정상 대기
선택 정확도, v2 비용, A→O, 본선 초과, 완주·backlog를 신규 시드로 함께 본다.

- 허용: “마스크 없이 정책의 회피 가능한 전원대기가 감소했고 운영비용이 개선/유지됐다.”
- 금지: 안전장치가 막은 결과를 “PPO가 학습했다”고 표현.
- 배포: YR-146에서만 진행 후보가 있는데도 전원 대기를 고르면 거부하고, 진행 후보가 전혀
  없을 때 최소 안전 escape를 확정한다.

## 6. 실제 환경과의 대응

같은 레일의 두 크레인 중 한 대가 일하고 한 대가 양보하는 것은 정상이다. 작업이 없거나
설비·하류가 막힌 구조적 대기도 정상이다. 반면 실행 가능한 작업이 남았는데 두 대가 영구
정지하는 것은 운영 교착이며, 실제 배포에서는 ECS/watchdog 성격의 YR-146이 최종 차단한다.

## 7. Dashboard 영향

- 기존 YR-146 “엔진 강제 탈출 우선”은 배포 안전장치로 유지하되 YR-147·YR-143 뒤로
  순연한다.
- 마스크 없는 정책 최적화는 YR-147로 분리한다.
- YR-143의 선결을 YR-145에서 YR-147로 올리고, 연구 평가에서는 YR-146 guard를 끈다.
- YR-133은 YR-143과 YR-146 뒤에 연다.
