# 2026-07-28 — 게이트 정비 6건, 첫 유의 판정, 그리고 새 엔진 결함

사용자 지시 순서(YR-107 → 108 → 110 → 착수 4게이트 → YR-105-b)를 그대로 집행했다.
7축 병렬 정찰(읽기 전용) 후 구현 → 판정런. **정찰이 브리핑을 반증한 곳이 여러 곳**이라
그때마다 설계를 바꿨다. 그 경위를 남긴다 (요약하지 않는다 — 판단 근거가 사라지면 재발한다).

## 왜 정찰을 먼저 돌렸나

설계감사(2026-07-27)가 지목한 5건은 전부 "코드가 이렇게 되어 있을 것"이라는 **추정 위에**
쓰여 있었다. 실제로 YR-109 집행 때 그 추정 중 하나("구조적 상수 제거 → 분산 감소")가
틀렸음이 드러났다. 그래서 이번에는 **구현 전에 코드를 읽히는 단계**를 넣었고, 실제로 7축 중
**4축에서 브리핑이 부정확**했다.

## 브리핑이 틀렸던 곳 (전부 기록)

| 축 | 브리핑 | 실제 |
|---|---|---|
| 게이트 A | "dmult=1.0 클램프조차 달성 불가" (전 본선) | **적하(LOAD)만**. 양하는 안벽 버퍼로 뽑아내므로 STS 단독 하한이 **정확**. 부족분도 145~172초로 YR-109 가 제거한 상수(991~1148초)의 1/6 |
| 게이트 A | "이송 대수가 처리율 상한" | 아니다. AGV 3대×180초 = 60초 간격 ≥ 케이던스 132~152초 → 전 실행에서 `transfer_wait=0`. 케이던스가 60초 아래로 가야 구속된다 |
| 게이트 C | "현재 n 의 df 로 목표 n 을 푸는 순환이 evalkit 에 있다" | **evalkit 에는 없다**. evalkit 은 상수 z(1.96+0.84)를 박아 뒀다. 순환 결함은 **코드 밖**에 있었다 — 보드가 인용한 "필요 n 17/21/24"는 df=7 을 고정한 **커밋되지 않은 임시 계산** 결과 |
| YR-108 | "셀 BASE 간격 100 < 대역 offset 200 이라 충돌" | 아니다. 인접 셀은 **부하수준이 달라 애초에 충돌하지 않는다**. 진짜 원인은 같은 부하수준 두 셀의 BASE 가 정확히 200 차이 + offset 도 200 간격 → **공명** |
| 게이트 D | "같은 epoch 다중 이송 → 용량 초과 경쟁조건" | 이미 막혀 있었다(`_reserved_inbound`). 진짜 구멍은 **부분 commit 이 만드는 고아 job** 과 `_open_txn` 키 충돌 |

## 정찰이 새로 찾은 것 (브리핑에 없던 것)

1. **YR-107 규칙 결손** — YR-100-[3]에서 학습 arm 6개가 healthy 에 걸려 전부 탈락하자,
   사전등록 규칙("guard 통과 arm 중 Δtotal 최소")이 **다른 선택지가 없어 오라클을 후보로
   자동 지명**했다. 라벨 실수가 아니라 규칙의 구조적 구멍이다 → `is_deployable()` 신설.
2. **없는 arm** — "공개정보 rollout 참고군"의 실체(`PredictiveRollout`)는 판정 하네스에
   한 번도 등록된 적이 없다. 잘못 붙인 라벨이 아니라 **없는 것을 있다고 적은 것**이다.
3. **지식 유실형 오류** — YR-087 보고서(2026-07-25)는 같은 정책을 "오라클(진짜 미래 사용,
   상한)"으로 **정확히** 라벨했다. 이틀 뒤 YR-100/041 에서 그 라벨이 사라졌다. 사람 눈에
   의존한 라벨은 이미 한 번 실패했으므로 **원자료마다 기계로 박제**한다(`uses_future_truth`).
4. **재현 불가 evidence** — YR-109 가 board 에 박제한 원자료를 만든 **스크립트가 저장소에
   없었다**. 표를 재생산할 수 없는 evidence 는 연구 기록으로 성립하지 않는다.
5. **영구 죽은 코드** — `yr099_midrun_review` 의 채널 분해 블록은 `chan` 키가 만들어지지
   않아 조건이 항상 False 였다. 결과 JSON 에 늘 빈 dict 가 쓰였고, 코드만 읽으면 판정이
   붙은 것처럼 보였다.
6. **퇴화 채널의 거짓 증명서** — `other` 채널은 4개 항 가중치가 전부 0이라 항상 sd=0 →
   구 규칙 `MDE ≤ δ` 가 자동 성립 → "효과 없음(δ 이상 배제)"이 **반드시** 발행된다.
   우연이 아니라 구조적 재발이다.
7. **라벨 체계의 구멍** — "유의하면서 δ 보다 작다"는 5번째 상태가 실제 데이터(move 채널)에
   이미 있었는데 라벨 4종에 자리가 없어 사람이 손으로 처리했고, 같은 보고서의 규칙이
   바로 그 행위를 금지하고 있었다.

사용자가 제안한 "보수적으로 선택 21"보다 **24**가 필요하다. 실행비용은 무시 가능하다
(1 arm 1 시드 0.8초) — 표본을 아낄 이유가 처음부터 없었다는 뜻이기도 하다.

## 판정 결과 — 검정력 처방이 실제로 작동했다

본선 악화 방지 필터(VGUARD), 선택대역 n=24, 정합마감 ON, 지문 배정 대역:

| 채널 | n=8 (구) | **n=24 (신)** |
|---|---|---|
| 트럭 (1차) | +2.24 [−0.84,+5.32] **검출 실패** | **+3.26 [+1.90,+4.62] 유의(악화)** |
| 본선 | +2.57 [−7.07,+12.22] 검출 실패 | +0.37 [−3.82,+4.55] **효과 없음(TOST)** |

부호는 그대로이고 표본만 늘렸는데 **처음으로 유의**해졌다. 방향은 사전등록 가설의 **반대**다
— "본선을 지키려 이송을 막는다"는 축은 비용만 지불하고 얻는 게 없다. 채택하지 않는다.

## 확증런은 무효 — 새 엔진 결함(YR-112)

n=48 확증런이 하드 guard 에 걸렸다(3시드 완주 0.994·backlog 1). 추적 결과 **포화가 아니라
활성(liveness) 결함**이다: 결정 스트림이 t=15682.8초에 끊기는데 평가창은 36000초까지 남아
있고, 두 크레인 모두 유휴이며, 미완 작업(`J-OUT-065`)은 blocker 0 으로 **즉시 서비스 가능**
했다. 드레인 창을 3배로 늘려도 동일.

이 결함이 중요한 이유: **미완 작업은 비용에 계상되지 않는다.** 즉 결함이 있는 시드는
"비용이 낮게" 나오고, 그 왜곡이 arm 마다 다르면 비교 자체가 오염된다. 표본의 6%가 그랬다.

**시드를 빼서 넘어가지 않았다.** 평가계약 0순위가 금지한 "검열 회피"가 정확히 그 행위이고,
YR-098 사례에서 제외 시 추정치가 −6.338→−5.388 로 움직인 전례가 있다. 원자료는 전부
보존하고 판정만 무효로 표기했다(종료코드 2).
