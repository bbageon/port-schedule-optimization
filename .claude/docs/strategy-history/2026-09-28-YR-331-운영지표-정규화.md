# YR-331-e — 원화 없는 운영 지표 정규화의 결정과 실행

## 1. 결정 경위

사용자는 이전 대화에서 근거 없는 보상 분모 1,000,000의 출처와 필요성을 물었다.
YR-331-d는 이를 별도 기준 규칙의 할인 누적 원화 비용 표준편차 37,620,956.31299437로 바꿨다.
그 작업은 91검사와 6시간·6회 갱신으로 보상 눈금·학습 실행을 검증했지만 원화 네 단가의 근거는 확정하지 않았다.
사용자는 “그러면 애초에 원화비용을 쓰지 않고, 정규화해서 넣으면 되는거아냐?”라고 범위를 명확히 했고,
이어 “정규화를 어떻게 적용할지 기존 연구를 검토하고 적용해서 학습까지 진행해봐”라고 실행을 지시했다.

따라서 이번에는 단가를 다른 단가로 바꾸지 않고, 원화 장부의 원료인 네 물리 지표를 직접 읽기로 했다.
기존 d의 원화 정규화는 명시적 비교 모드로 남기고 새 기본값은 운영 지표 정규화로 설정했다.
이는 수치 크기만 조절하는 변경이 아니라 네 목적의 상대적인 교환 비율도 바꾸는 설계다.
정규화 자체가 경제적 중요도·적정 혼잡도·정책 우월성의 근거가 된다고 주장하지 않는다.

기존 연구 게이트(다음 단계의 자격 검사)는 독립 보정 시드의 공급 부족으로 현실성 보정을 먼저 요구했다.
`authorize-next`도 scenario_validity 선결조건을 이유로 성능 단계 착수를 거부했다.
새 사용자 지시가 구현과 실제 학습을 직접 요구했으므로 해당 진단만 수행하는 예외 범위를 spec에 먼저 남겼다.
기존 공급 부족을 해결했다거나 실제 항만 성능시험의 자격을 얻었다고 바꾸지 않았다.

## 2. 검토한 대안과 선택 이유

1. **d의 원화 합계/고정 눈금 유지**: 구현은 안정적이지만 원화 환산을 없애라는 이번 요청을 충족하지 못한다.
2. **초·횟수 그대로 합산**: 단가를 제거하지만 단위·집계 규모가 다른 항목의 크기에 보상이 지배될 수 있다.
3. **최댓값·최솟값으로 0~1 변환**: 지속 유입에서 미완료 시간의 고정 최댓값이 없고 범위 밖 절단은 큰 손실을 가릴 수 있어 채택하지 않았다.
4. **매 학습창마다 평균·표준편차 재추정**: 별도 기준은 필요 없지만 정책·혼잡에 따라 목적 간 환산 비율까지 변한다. 이번 진단에서는 고정 비교가 목적이므로 기각했다.
5. **전문가 해의 완료시간으로 나누기**: 작업장 오프라인 배차 논문이 사용하지만 우리 지속 유입 입력에는 사전에 계산한 대응 기준해가 없다.
6. **선택 — 목적별 할인 누적값의 표준편차를 별도 기준 운전에서 고정**: 기존 할인·수집 주기를 유지하면서 원화 단가 없이 네 지표를 직접 정규화한다.

Dong 등의 쌍 자동적재크레인 연구는 빈 이동·간섭·대기 증가를 물리 시간 보상으로 사용한다.
Toure 등의 통신 스케줄링 연구는 기준정책 자료의 목적별 보상 통계로 표준화한다.
Stable-Baselines3 공식 구현은 할인 누적 보상의 표준편차를 보상 눈금으로 사용한다.
이번 방식의 별도 자료 고정·평균 미제거·절단 없음·동일 가중치는 이들을 참고해 정한 자체 설계다.
문헌이 우리 식 전체나 네 항 0.25의 최적성을 직접 검증했다는 식으로 인용하지 않는다.

## 3. 동결한 수식과 물리 장부

`x=(truck_s,vessel_s,empty_s,rehandles)`는 각각 트럭별 진입~출차/현재 누적초,
선박별 중단초의 합, 크레인 빈 이동초, 재취급 횟수다. 본선은 기존 병렬 작업열 평균 규약을 유지한다.
선박 톤수·원화 단가를 곱하지 않는다. 미완료 트럭과 완료된 과거 작업도 기존 누적 장부에 남긴다.

```text
z_i,t = 0.999^(Δt/60) z_i,t-1 + Δx_i,t
s_i = std(z_i,t), 기준 시각 86400 < t ≤ 259200
r_t = −Σ_i 0.25 × Δx_i,t / s_i
```

기준 시드 9911000, 부하 3500/5000/7500, KEEP+SF-SPT 규칙, 갱신 0회.
60초 간격 4321경계 중 첫날을 제외한 2880개의 할인 누적값으로 모집단 표준편차를 계산했다.
원래 [고정 입력](../../../outputs/reports/yr331_training/calibration-v2/seed-data.json.gz)을 수정하지 않았다.

| 지표 | 표준편차 | 할인 누적값 평균 |
|---|---:|---:|
| 트럭 체류초 | 2752293.040596188 | 5385063.588402867 |
| 본선 중단초 | 15890.260680352783 | 38340.37358824252 |
| 빈 이동초 | 6921.155043461583 | 24458.68017429103 |
| 재취급 횟수 | 974.113315579791 | 3293.991895845647 |

평균은 진단으로만 기록하고 보상에서 빼지 않는다. 초를 분으로 바꾸면 해당 기준도 60으로 나눠 동일 보상을 유지한다.
기준 측정 2일의 각 항 손실 기여는 2.0739178107/2.5553106444/3.3082131676/3.1443980397이다.
비중으로는 18.7146%/23.0585%/29.8526%/28.3743%이며 매 순간 25%를 강제하지 않는다는 뜻이다.
비유한 수·음의 누적 증가·기준 분산 0을 임의 분모로 덮지 않고 실패로 중단한다.

## 5. 사전 판정과 알려진 한계

세 쌍 평균 운영 손실이 이전 보상·규칙보다 작고, 각 쌍의 원요청 시간·트럭/본선 잔여가
두 비교군보다 늘지 않아야 진단 성공이다. 입력·물리·정보 경계의 유효성도 필요하다.
성능 향상 확증·최적 혼잡도·실제 항만 효능은 주장하지 않는다.
기존 진입 이연의 장부 한계는 원요청 시간으로 별도 감시하며 이번에 보상 시계를 함께 바꾸지 않는다.
독립 보정 입력의 부족(YR-331-c), 독립 수용 상한 확인(YR-331-a), 실제 운영자료 확보는 별개다.
배열판 보상 계산은 구현·검사했지만 시장·고정 화물 갈래 이식은 미완료여서 실제 연구 학습은 CPU에서 했다.

## 6. 실행 과정에서 발견해 바로잡은 사항

- 낮은 수준의 과거 원화 회계 시험은 원화 값을 흉내내므로, 새 기본값을 쓰면 물리 장부가 없어 9건이 실패했다.
  해당 시험의 계약을 `legacy-krw`로 명시한 뒤 추가 검사 16건이 통과했다. 초기 실패 로그도 보존한다.
- 첫 2시간 점검에서 실제 신경망 갱신 2회는 성공했으나, 중간 시각의 투입수를 하루 총 주문수와 비교한 검사식이 실패했다.
  입력의 기존 통지 시각 내림 규칙에 따라 그 시각까지 등록될 주문 수를 계산하도록 검사만 고쳤다.
  입력·물리·보상·학습 설정은 바꾸지 않았다. 두 번째 점검은 320건 등록·누락 0·2회 갱신·저장 복원까지 통과했다.
- 3일 중단점에는 사전 통지된 4일차 주문도 등록될 수 있다. 첫 쌍에서 두 모델 모두 16606건으로 일치했다.
  “3일 부하 합 16000건”과 등록된 수가 다른 이유이며, 원본 5일 입력을 임의로 잘라 맞추지 않았다.
- 실제 학습창을 기준으로 일별 train 표기를 기록하도록 수정했다. 원본 DayPlan·cohort_live의 train은 원래 5일 계획의 속성이다.
- 기준 JSON이 배포 패키지 안에도 원본과 같은 바이트로 포함됨을 검사했다. 지문은 `846fcd616ccbbe6ee00f19436d841058a8bab1db48b384a66c42bf1aa9a60b4c`.
- 실행 동결 뒤 배열 코드 검토에서 실제 v5 설정 객체에 reward_mode가 없다는 호환성 문제를 발견했다. `b32c344c`에서 과거 모드로 명시 변환하고 음수 초기 물리 장부도 거부하도록 보완했다. 해당 3검사 통과. CPU 연구 실행은 `9a8fce42`로 계속 고정했고 그 경로의 수식·물리·입력을 바꾸지 않았다.

## 7. 재검토 조건

기준 입력·장부 정의·할인율이 달라지면 같은 기준값을 무심코 재사용하지 않는다.
환경이나 목적 변경 시 기준 수집·비교 계약을 다시 등록하며, 평가 자료로 눈금을 맞추지 않는다.
기존 모델을 새 눈금으로 읽지 않도록 체크포인트의 모드·자료 지문·비중을 검사한다.
성능이 미달하면 이번 구현 검증과 결과를 보존하고, 즉석 가중치 변경이나 표본 추가로 성공 사례를 찾지 않는다.
