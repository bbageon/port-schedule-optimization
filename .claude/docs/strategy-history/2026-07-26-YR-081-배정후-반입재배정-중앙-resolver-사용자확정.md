# YR-081/099 — TOS 배정 후 반입 재배정·중앙 Transfer Resolver 확정

- **기록일**: 2026-07-26
- **상태**: 사용자 아키텍처 결정 · 구현/성능 미검증
- **적용 단계**: 단일 블록 정책 확정 뒤 다중 블록 확장
- **상세 구현 작업**: [YR-099](../dashboard-task-specs/YR-099-post-tos-inbound-transfer-resolver.md)

## 1. 결정 요약

TOS(Terminal Operating System)는 연구가 수정하거나 대체하는 대상이 아니다. TOS가 작업과 최초 담당 블록을 정해 전달한다는 전제에서 연구 레이어가 시작된다. 다중 블록 확장 때 허용할 새 결정은 **재배정 가능한 반입 작업의 실행 블록 변경**뿐이다.

각 블록의 공유 Q 정책은 자기 상태에서 작업을 내보낼 때 줄어드는 비용과, 다른 작업을 받을 때 늘어나는 비용을 계산한다. 중앙 `TransferResolver`는 `KEEP`과 구체적인 `A→B` 후보를 비교하고, 용량·슬롯·시간·소유권 제약을 통과한 최저비용안을 원자적으로 commit한다. 수신 블록이 없거나 commit이 실패하면 작업은 원래 블록 A가 계속 처리한다. 중앙 resolver는 QMIX가 아니라 결정론적 제약 최적화기다.

## 2. 결정 경위

1. 최초 구상은 `블록 Q → 야드 관제 → 터미널 통합계획기`였으나 사용자가 TOS가 이미 상위
   배정을 수행하며 연구 통제영역이 아니라고 정정했다.
2. `TRANSFER_OUT`보다 최초 배정 경매를 쓰자는 안도 같은 이유로 기각됐다. 연구는 TOS의
   최초 배정을 바꾸지 않고 **배정받은 뒤**부터 시작한다.
3. 사용자는 단일 블록 Q에 “이 반입 작업이 없으면 내 블록 비용이 얼마나 낮아지는가”를
   평가하는 판매 행동을 요구했다.
4. 단순 판매 요청만 보내고 작업을 미확정 상태로 두는 설명은 기각됐다. 판매는 반드시
   수신 블록·슬롯·경로가 정해진 실제 재배정으로 끝나거나 원소유 블록으로 복귀해야 한다.
5. 이에 따라 블록 Q는 판매/수용 한계비용을 내고 중앙 resolver가 실제 `KEEP/A→B`를
   확정하는 구조로 동결했다. QMIX는 협조학습기일 뿐 거래·예약·rollback 장치가 아니므로
   초기 구조에서 제외한다.

현재 코드 감사에서 반입 `GATE_IN` 작업은 사전 배정 결정 이벤트 없이 `BLOCK_ARRIVAL`에서 처음 `WAITING`이 된다. ETA wake도 반출 `GATE_OUT`에만 있다. 따라서 실제 블록 도착 전 재배정을 연구하려면 배정 통지와 별도 transfer decision epoch가 새로 필요하다. 현재 `CandidateQNet`도 YC의 물리 후보만 채점하므로 transfer는 별도 head와 resolver 계약으로 분리해야 한다.

이 결정은 과거 [일반화 3단계 전략](2026-07-20-일반화-3단계-전략-사용자승인.md)의 “상위 야드 관제가 작업·차량을 배분한다”는 범위를 **후속 대체**한다. 과거 문서는 당시 결정 스냅샷이므로 수정하지 않고, 현행 범위는 본 문서와 YR-081/099 spec을 따른다.

## 3. 연구 경계와 필수 운영 가정

```text
외부 TOS: 작업 생성·최초 담당 블록 배정
    ↓ 읽기 입력
연구 레이어: 배정 후, 허용된 반입 작업만 실행 블록 재최적화
    ↓ 확정된 실행 블록
블록 정책: 블록 내부 YC 작업순서·목적지 최적화
    ↓
기존 안전 resolver/ECS: 물리 실행
```

- TOS 배정 알고리즘·최초 배정 경매·선석/QC/YT 전역 배분은 범위 밖이다.
- `tos_assigned_block_id`는 감사용 원본으로 불변 보존한다.
- `execution_block_id`만 중앙 resolver가 허용 범위에서 바꾼다.
- 실제 PoC에는 후단 실행 블록 변경과 차량 경로 갱신을 받아들이는 인터페이스가 필요하다.
- 그 인터페이스가 없으면 본 구조의 주장은 다중 블록 시뮬레이션 방법론에 한정하고 실운영 자동 재배정을 주장하지 않는다.

## 4. 동결 아키텍처

```text
TOS 최초 배정: inbound job j → block A
                    ↓
       A BlockQ: OutRelief(A,j)
       B BlockQ: InBurden(B,j)
       C BlockQ: InBurden(C,j)
                    ↓
          deterministic TransferResolver
     KEEP(A,j) / TRANSFER(A→B,j) / TRANSFER(A→C,j)
                    ↓
       prepare → validate → atomic commit/rollback
                    ↓
        최종 소유 블록의 기존 ExecutionQ가 처리
```

호환되는 블록들은 하나의 정책 파라미터를 공유하되 상태와 작업목록은 각자 가진다. 서로 다른 블록 형상·크레인 구조는 `block_profile` 조건 입력 또는 구조군별 정책으로 분리한다.

## 5. 블록 Q의 두 출력

```text
공유 BlockEncoder
  ├─ ExecutionQ: SERVE / PRE_REHANDLE / REPOSITION 채점
  └─ TransferQuoteQ:
       OutRelief = 작업을 내보낼 때 감소하는 블록 비용
       InBurden  = 작업을 받을 때 증가하는 블록 비용
```

`SELL_INBOUND`는 YC가 수행하는 물리 action이 아니다. 배정 검토 이벤트에서 source Q가 내는 판매 후보와 가격이다. receiver Q는 별도 `BUY` 행동을 실행하지 않고 같은 quote head의 수용 모드로 비용을 답한다. 실제 실행 action은 resolver가 만든 구체적인 `TRANSFER(job, source, receiver)`다.

## 6. 결정 시점

1. `TOS_ASSIGNMENT_RECEIVED`: 재배정 가능한 반입 작업과 공개 ETA를 처음 받음.
2. 작업이 고정 계획창에 들어올 때 `TRANSFER_REVIEW`를 1회 개방.
3. 마감 전 크레인 고장·계획변경·부하 급변 때 제한적으로 재검토.
4. `reassignable_until` 이후, YC 예약·작업 시작 이후에는 mask.
5. `reassignable_until`이 제공되지 않으면 fail-closed로 재배정을 금지한다.

계획창보다 먼 작업은 이득 0으로 오판하지 않고 다음 review를 예약한다. 반복 매도·진동을 막기 위해 작업당 최대 이전 횟수, cooldown, 최소 순이득 margin을 사전등록한다.

## 7. 한계비용 계산

공개된 ETA와 현재 상태만 사용해 같은 예측표본·같은 난수로 짝지은 반사실 rollout을 수행한다.

```text
OutRelief(A,j) = J_A(with j) - J_A(without j)
InBurden(B,j)  = J_B(with j) - J_B(without j)

Gain(A→B,j)
  = OutRelief(A,j) - InBurden(B,j)
    - RouteCost(A→B,j) - RiskMargin(A→B,j)
```

`J`에는 블록 처리시간 `B→C`, 장기대기, 본선 지연, 이동·재조작, 평가창 끝 backlog의 잔여가치를 포함한다. 작업을 source에서 뺀다고 terminal ledger에서 삭제하지 않는다. 예약 `T_appt`, 실제 gate-in `A`, 최종 gate-out `O`, deadline은 이전 전후 동일 job_id로 계속 추적한다. 미래 실제 도착시각·미통지 고장·미통지 계획변경은 입력하면 안 된다.

처음에는 공개정보 예측 rollout으로 quote 정답을 만들고, 이후 `TransferQuoteQ`가 평균과
불확실성을 빠르게 예측하도록 증류한다. 불확실하면 `KEEP`이 기본값이다.

## 8. 중앙 resolver의 최적화 계약

작업 하나에는 `KEEP`과 feasible receiver별 `TRANSFER`를 모두 생성한다. 여러 작업이 동시에
열리면 개별 greedy로 수신 용량을 중복 사용하지 않도록 batch matching으로 푼다.

```text
maximize  Σ Gain(j,A→B) · x[j,A→B]
subject to
  작업별 최종 소유 블록 정확히 1개(KEEP 포함)
  receiver 슬롯·규격·용량·경로·마감 제약
  동일 슬롯·차량·공유자원 중복 예약 금지
  이미 ASSIGNED/RUNNING인 YC 작업 이전 금지
```

점수가 같으면 `(job_id, source_block_id, receiver_block_id)` 완전순서로 결정한다.
resolver는 학습하지 않으며 같은 상태와 quote에는 항상 같은 결과를 낸다.

## 9. 원자적 commit과 rollback

```text
OWNED(A)
  → PREPARED(A→B): B 슬롯·용량·경로 임시예약, version 재검증
  → COMMITTED(B): owner/queue/route/ledger 연결을 한 transaction으로 변경

어느 검사라도 실패
  → 임시예약 전부 해제
  → OWNED(A) 유지
```

- source queue에서 먼저 삭제하지 않는다.
- 성공 시에만 A에서 제거하고 B에 삽입한다.
- 실패·수신자 없음·순이득≤0은 rollback이 아니라 정상 `KEEP`이다.
- stale quote는 `assignment_version`과 TTL로 거부하고 새 snapshot에서 다시 푼다.
- replay에는 제안 action이 아니라 **실제로 commit된 소유권 결과**를 기록한다.

## 10. QMIX를 초기 구조에서 제외한 이유

QMIX는 중앙집중 학습·분산 실행에서 local Q를 단조 mixer로 합치는 학습법이다. 작업 매칭,
슬롯 예약, 중복 방지, 소유권 변경, transaction rollback을 제공하지 않는다. 또한
`A는 큰 이득/B는 손해지만 합계는 이득`인 이전은 단조 표현과 맞지 않을 수 있다.

초기 비교는 명시적 한계비용과 결정론적 resolver로 수행한다. 공유 YT·도로 등 비가산
상호작용 때문에 scalar quote가 반복적으로 잘못된 배정을 만든다는 증거가 있을 때만
중앙 공동가치망·coordination graph·QMIX 계열을 별도 ablation으로 연다. 그 경우에도
물리 commit과 rollback은 resolver가 담당한다.

## 11. 검토 후 기각한 대안

- **최초 배정 경매**: TOS 통제범위를 침범하므로 기각.
- **판매 요청만 출력**: 처리 주체가 미확정될 수 있어 기각.
- **source Q 단독 삭제**: 모든 블록이 작업을 떠넘기는 reward gaming과 orphan job 위험.
- **Q 간 자유형 메시지/PPO 통신/LLM 관제 선도입**: 메시지 의미와 제약이 이미 명시적이며
  검증면만 커짐. 명시 quote+resolver가 기준선이다.
- **QMIX가 resolver를 대체**: 학습과 transaction의 역할 혼동이므로 기각.
- **크레인 자체의 블록 이동·지정 반출 target 변경**: 현재 물리·업무 범위 밖.
- **미지정 공컨 반출의 블록 간 선택**: 별도 terminal request 문제로 분리하고 이번 action에서 제외.

## 12. 구현·검증 게이트

- **G0 계약**: owner 정확히 1, 중복·유실·시간장부 reset·물리위반 모두 0; commit 실패 시 A 유지.
- **G1 상금**: 고정 TOS 배정 대비 공개정보 paired-rollout resolver의 터미널 총비용 개선을
  신규 seed에서 짝지은 신뢰구간으로 확인. 없으면 QuoteQ를 학습하지 않는다.
- **G2 근사**: QuoteQ가 rollout의 이전 순위와 순이득을 재현하고, no-transfer 기준보다
  빠르면서 terminal KPI를 악화시키지 않아야 한다.
- **필수 보고**: `A→O` 평균·P95, `B→C`, berth overrun, rehandle, 추가 차량거리,
  이전·거절·rollback·stale quote 수, 결정시간, 완주율·backlog.
- 평균 하나로 채택하지 않는다. 안전·완주 guard를 먼저 통과하고, 비열등 margin은 실 SLA
  근거를 확보해 사전등록한다.

## 14. 되돌릴 조건과 주장 한계

- TOS/게이트가 실행 블록 변경을 받을 수 없으면 자동 재배정 경로를 닫는다.
- G1에서 상금이 없으면 TransferQuoteQ·학습 통신은 만들지 않고 독립 블록으로 복귀한다.
- scalar quote가 공유자원 외부효과를 일관되게 오판하면 중앙 joint scorer를 비교한다.
- 이 문서는 사용자 결정과 연구 설계 스냅샷이며 구현 완료·성능 개선 증거가 아니다.
