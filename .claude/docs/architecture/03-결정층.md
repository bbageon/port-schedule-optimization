**채점망 1개 → Seller·Buyer 두 행위자**, 그리고 **교사–학생 분리**다.

## 1. 두 층이 세계를 통해서만 만난다

```
① 크레인 층 ─ 블록 안: "비는 크레인 2대로 어떤 작업을 할까"
     ↕  (직접 통신 없음. 야드 상태로만 상호작용)
② 재배치 층 ─ 블록 사이: "이 트럭을 다른 블록으로 보낼까 / 미룰까"
```

## 2. ① 크레인 층 — **동결** (v3 에서 변경 없음)

`JointPairNet(250)` · **97,410 파라미터** · `requires_grad=False` · 매 iteration 해시
검사. 계보: 규칙 → 증류(YR-073) → PPO(YR-139) → 채택(YR-143 C0). **두 대를 함께
정한다**(같은 블록의 두 대가 서로 방해하므로 조합 단위 `argmin`).
**왜 안 배우나**: 오라클 상한이 트럭 1대당 **+0.18분**인데 재배치 축은 −2.6분 —
**14배 차이라 여기 집중한다.**

### ★오라클은 비교군이 아니라 진단용 상한이다

우리 오라클 = **정보 반칙**(완벽 ETA) + **계산 반칙**(BEAM wide). [[YR-070]] 이 이미
답을 냈다 — **완벽정보 이득 0.0**, 헤드룸은 **조율**에서만 6~9%, SF-SPT 가 천장 근접.
*"넘어야 할 상대"* 가 아니라 **"애초에 상금이 얼마인가"** 를 잰 것이다.
논문 비교군은 문헌 표준(규칙 · **메타휴리스틱 GA/TS** · 소규모 **B&B 최적성 격차**)을
따르고 오라클은 진단 열로만 둔다 → [[YR-213]].

### ⚠️ 지금 바닥이 규칙보다 나쁘다

구 2블록 학습분을 얼려 쓰므로 **`A − R` = +59.97**(대당 +1.00분)로 **규칙보다
비싸다**([[YR-180]]). 그런데 **계획법 원본이 코드에 그대로 있다**
(`JointRolloutGreedy`·`BeamLookahead`) — 채택 망의 계보가 규칙 → **증류** → PPO 라,
**증류 전 원본**을 배차로 쓰면 문헌 표준에 맞고 바닥도 튼튼해진다 → [[YR-213]].
**재배치 축 결론은 안 흔들릴 것으로 본다** — [[YR-180]] 이 재배치 이득을 규칙 배차
위(−158.13)와 얼린 정책 위(−166.69)에서 **거의 같게** 쟀다.

## 3. ② 재배치 층 — **학습 대상** (v2 현행)

`SellQNet` **5,633 파라미터**(21→64→64→1)가 **비용**을 낸다. 선택은 `argmin`(평가) ·
ε=0.15·σ=0.20(학습). 가중치 **1벌을 21블록이 각자 실행**한다.
**행 = 21차원 = 블록 7 + 후보 6 + 좌표 8** —

| 부분 | 내용 |
|---|---|
| 블록 7 | inside/10 · pipeline/10 · crane_backlog/3600 · occupancy · vessel_slack/3600 · announced_30/10 · n_cands/6 |
| 후보 6 | ETA 잔여 · is_out · size40 · gate 잔여 · 이송 이력 · 이연 이력 |
| 좌표 8 | is_space · is_time · dst_load · dst_free · route_delta · defer_s · src_load_after · **src_load** |

**행에 목적지가 들어간 것이 v2 의 성과다**(구판 PPO 는 14차원이라 [[YR-175]]·
[[YR-177]] 이 났다). **⚠️ 그래도 결정은 전부 중앙 배정기가 한다** — 받는 블록에
거절권이 없어 **붐비는 곳에 떠넘길 수 있다.**

## 3-1. ★v3 변경 ③ — Seller·Buyer 를 **독립 행위자**로

**두 문제를 한꺼번에 고친다.** ① 학습 목표가 원래 세 조각의 뺄셈인데
(`D_i = R_src − B_dst − ΔC_route`) 망 하나가 **결과만** 보면 양쪽이 다 커도 차가
작을 때 **신호가 상쇄된다.** ② **받는 쪽에 거부권이 없다.**

### 계약 — 상호 동의가 있어야 거래다

```
Seller A :  a ∈ {KEEP, SELL(공간, 블록 b), SELL(시간, 슬롯 k)}
Buyer    :  a ∈ {REJECT, BUY}        공간 → 목적지 블록 · 시간 → 목표 슬롯
거래 후보 (A, B, j)  ⇔  SELL_A(j)  ∧  BUY_B(A, j)
```

**★시간 축의 Buyer 는 "목표 슬롯"이다.** 블록이 안 바뀌어 상대가 없어 보이지만
실제 **VBS 예약 슬롯에는 용량이 있어**(`RES_AVL_CNT`) 차면 거절한다 — 그래야
"상호 동의가 있어야 거래"가 **양 축에서 성립**한다. 지금 엔진은 `TIME@k` 에 가상
용량을 안 갱신한다 → [[YR-176]].

**Resolver 는 동의 없는 edge 를 만들거나 강제할 수 없다** — 동의된 것 중에서
**용량·소유권을 지키며 매칭만** 한다(동의 edge 가 없으면 `RESOLVER_KEEP`).
**이게 "시장"이라는 이름에 맞는 유일한 형태다** — 서사 B 의 본 주장이 *"재배치
**시장**"* 인데 중앙이 다 정하면 배정이지 시장이 아니다.

### 어떻게 배우나 — 반사실 라벨 (PPO 불필요)

선택지가 **이산**이므로 각 세계를 굴려 비용을 재고 싼 쪽을 고르면 된다
(`Φ_H(KEEP)` vs `Φ_H(SELL…)` · `Φ_H(REJECT)` vs `Φ_H(BUY)` — 같은 snapshot·난수).
**회귀만으로 끝난다** — v1 에서 무너진 critic([[YR-180]] 보상 91%가 0)을 안 들인다.
라벨은 [[YR-204]] 교사가 만든다.

### 정보 경계

Seller 는 **자기 블록 + 자기 후보 작업**을, Buyer 는 **자기 블록 + offer message** 만
본다. **다른 Buyer 의 응답은 못 본다**(동시 결정) — 경쟁 입찰이 아니다.

### 왜 나은가 — 셋

**① 신용 배분이 행위자별로 갈린다**(내놓은 쪽 / 받은 쪽) **② 떠넘기기가 구조적으로
막힌다**(받는 쪽에 거절권) **③ 표본이 2배** — Buyer 라벨은 **채택 안 된 목적지에도**
붙는다. **문헌**: 시장 기반 MRTA(Dias et al. 2006)의 매도·매수 호가 · 차분 보상
(Wolpert & Tumer 2002)을 **양쪽으로 쪼갠** 형태.

**⚠️ 정정 — 계산량은 안 줄어든다.** 구 판의 *"O(N²)→O(N)"* 은 **틀렸다** — Buyer 값이
작업에 따라 달라져(`Buyer(dst, job)`) 21 × 20 = **420회** 평가가 여전히 필요하다.
**진짜 이득은 신용 배분·거부권·표본 수**다.

### 남는 위험

| 위험 | 대응 |
|---|---|
| 초기 Buyer 전량 거절 → **거래 0** | 탐색 설계 · 표본 0 회차면 중단([06](06-학습과-판정.md)) |
| **비정상성** — 상대가 변하면 라벨도 변함 | 라벨을 **회차마다 다시** 만든다 |
| `R_src` 가 여전히 가정 | 반사실(축 ②)이 **먼저** 들어와야 의미 있다 |
| 두 망의 눈금 어긋남 | 같은 `Q_SCALE` 동시 학습 · `Q_SCALE` 재실측 |

**순서 = 계약 → 라벨 → 학생**: [[YR-203]] → [[YR-204]] → [[YR-205]].

## 4. 결정 절차 — **최초 통지 1회** ([[YR-203]])

**v2 의 "60초마다 재검토"가 사라진다.** 공개 ETA 가 창에 **처음 들어온** 60초
epoch(`0 < ETA − now ≤ WINDOW`)에서만 판단하고 **즉시 잠근다** — 창 안에서 반복
제안·거절되면 **학습 표본이 중복**되고 **공로가 왜곡**되기 때문이다.

### 한 epoch 안의 순서

```
① 이번 epoch 에 처음 자격을 얻은 작업 J_t 를 모은다
② 각 Seller 가 KEEP / SELL(공간 b · 시간 슬롯 k) 을 고른다   (SELL 은 방송)
③ 각 Buyer(블록 또는 슬롯)가 BUY / REJECT 로 독립 응답
④ Resolver 가 동의 edge 만 모아 batch 확정 — 전역 한계비용 최소 쌍 반복 선택,
   가상 대기열(q)·용량(vcap) 갱신
```

**순열 불변**(동점은 `(cost, offer_key, coord)` 사전순) · `GATE_OUT` 은 공간 판매
불가라 시간·KEEP 만 · **자격은 게이트 진입 전까지**(`gate_in_observed` 면 제외).
**크레인 층은 기다리지 않는다** — 재배치는 그 블록의 **작업 목록을 바꿀 뿐**이라,
한 트럭 기준으론 "재배치 → 도착 → 크레인" 이지만 전체로는 **동시에 돈다.**

## 5. 계약 상한

| | 값 | 뜻 |
|---|---|---|
| `ANNOUNCE_LEAD_S` · `WINDOW_S` | 1,800초 | 통지 리드 = 검토 창 (겸직 — 아래) |
| 격자 | 60초 | 결정 주기 (판단은 **작업당 1회**) |
| 이연 슬롯 | **30분 칸** | v3 — 구 `DEFER_DELTA_S=900` 고정 대체 (아래) |
| `MAX_ENTRY_DEFERRALS` · `MAX_TRANSFERS` | **1** | 작업당 이연·이송 상한 (A→B→C 금지) |

### ⚠️ 이연량을 고정하지 않는다 (v3 변경)

v2 는 `DEFER_DELTA_S = 900초` **고정**이라 "미룰까 말까"만 정했다. 블록이 언제 비는지는
상황마다 다른데 15분은 **짧으면** 여전히 붐비는 시각에 도착하고 **길면** 이미 빈
블록에 기사가 헛기다린다. **v3 는 "어느 칸으로 갈까"를 고른다** — **이산 슬롯**이라
반사실 라벨이 되고 실제 VBS 예약과 모양이 같다.

**대가**: 세계가 `KEEP + 공간 + 슬롯 K개` 로 늘어 rollout 이 는다. **완화** — 후보를
**공개 예측으로 좁힌다**(대기가 SLA 아래로 내려가는 첫 칸 ±1 = **3칸**). 값 판단이
아니라 **실현 가능성 필터**라 규칙 계산이 정당하다(§6). `K` 는 [[YR-203]] 에서 동결.

### ⚠️ v3 에서 갈라야 하는 상수

`ANNOUNCE_LEAD_S` 하나가 **통지 리드**와 **검토 창** 을 겸한다. [[YR-190]] 에서 리드가
트럭마다 다른 분포가 되면 겸직이 깨지므로 창은 **`min(리드, WINDOW_CAP)`** 이 된다.
**★창을 상수로 두면 실험이 무효다** — 후보 자격이 창 기준이라 5시간 전에 통지해도
후보가 되는 건 도착 30분 전이고, 리드를 바꿔도 동작이 안 바뀐다. 뚜껑
(`WINDOW_CAP = 7200초`)은 계산량 상한 — [[YR-190]] 착수 시 동결.

## 6. 비용이 아니라 제약으로 다루는 것 (v3 유지)

**물리적으로 불가능한 것은 벌점이 아니라 후보에서 제거한다** — 용량 초과
(`free_slots − vcap ≤ capacity_margin`) · 크레인 충돌(`feasible_mask`) ·
재조작 용량(`rehandle_capacity_ok`). 대기·주행·지연·본선만 **비용함수**다.
**벌점으로 때려 넣은 곳이 없다.**
