## 1. 두 층이 세계를 통해서만 만난다


## 2. ① 크레인 층 — **동결** (v3 에서 변경 없음)

`JointPairNet(250)` · **97,410 파라미터** · `requires_grad=False` · 매 iteration
해시 검사. 계보: 규칙 → 증류(YR-073) → PPO(YR-139) → 채택(YR-143 C0).

**두 대를 함께 정한다** — 한 행 = `ctx_a + blk_a + ctx_b + blk_b`, `argmin`.
후보는 크레인별로 만들되 **결정은 조합 단위**다(같은 블록의 두 대가 서로 방해).

**왜 안 배우나**: 오라클 상한이 **트럭 1대당 +0.18분**(두 번 확증). 재배치 축은
−2.6분 — **14배 차이라 여기 집중한다.**

**⚠️ 한계**: 구 2블록 무대 학습분을 21블록에 얼려 쓴다. 이 무대에서는 규칙보다
비싸다(`A − R` = +59.97, 대당 +1.00분).

| 부분 | 내용 |
|---|---|
| 블록 7 | inside/10 · pipeline/10 · crane_backlog/3600 · occupancy · vessel_slack/3600 · announced_30/10 · n_cands/6 |
| 후보 6 | ETA 잔여 · is_out · size40 · gate 잔여 · 이송 이력 · 이연 이력 |

**행에 목적지가 들어간 것이 v2 의 성과다.** 구판(PPO)은 행이 14차원이라 목적지가
없었고, 배정기가 좌표를 따로 계산하다 [[YR-175]](부호 오류)·[[YR-177]](기준
불일치)이 났다. 지금은 **정책과 배정기가 같은 망으로 같은 행**을 채점한다.

## 3-1. ★v3 변경 ③ — 망 하나를 Seller·Buyer 둘로

### 지금 무엇이 문제인가: 라벨이 이미 둘인데 망이 하나다

학습 목표는 처음부터 **세 조각의 뺄셈**이다 ([04b](04b-학습-잣대.md) §1) —
`D_i = R_src − B_dst − ΔC_route` (판 쪽이 번 것 − 산 쪽이 치른 것 − 주행 차이).

**망 하나가 이 뺄셈의 결과만 본다.** 두 큰 수의 차라서 양쪽이 다 커도 차가 작으면
**신호가 상쇄돼 사라진다.** 어느 쪽을 잘못 봤는지도 알 수 없다.

### v3: 조각마다 망을 둔다

| 망 | 질문 | 입력 | 라벨 |
|---|---|---|---|
| **Seller** | "이 트럭을 내놓으면 우리 블록이 얼마나 편해지나" | 출발 블록 9 + 후보 6 | `R_src` |
| **Buyer** | "이 트럭을 받으면 우리 블록이 얼마나 힘들어지나" | 목적지 블록 9 + 후보 6 | `B_dst` |
| (없음) | 주행 차이 | — | `ΔC_route` 는 **계산값** — 배울 게 없다 |

**배정기가 셋을 조립한다**: `점수 = Seller(src) − Buyer(dst) − ΔC_route`.
지금의 좌표 8차원은 **두 망의 입력으로 흡수**되고 따로 두지 않는다.

### 왜 이게 나은가 — 셋

**① 신용 배분이 갈린다.** 손해가 났을 때 "낸 쪽이 잘못"인지 "받은 쪽이 잘못"인지
라벨 수준에서 구분된다. 지금은 합쳐진 값 하나뿐이다.

**② 계산이 제곱에서 선형으로 준다.** 지금은 21블록 × 20목적지 = 420행을 매번
채점하지만(O(N²)), v3 는 Seller 21회 + Buyer 21회 = **42회**로 끝난다(O(N)).
조합은 뺄셈이라 공짜다. **반사실(H=1h)의 연산량을 감당하는 근거**이기도 하다.

**③ 표본이 늘어난다.** 거래 1건에 라벨이 1개 → **2개**. 게다가 Buyer 라벨은
**채택 안 된 목적지에도** 붙일 수 있다(반사실로 굴리면 나오므로).

**문헌 위치**: 시장 기반 다중로봇 과제 배분(Dias et al. 2006)의 매도·매수 호가와
같은 구조. 차분 보상(Wolpert & Tumer 2002)을 **양쪽으로 쪼갠** 형태다.

### 남는 위험

| 위험 | 왜 |
|---|---|
| `R_src` 라벨이 여전히 가정 | "남았더라면"은 미관측 → 반사실(축 ②)이 먼저 들어와야 의미 있다 |
| 두 망의 눈금이 어긋남 | 각자 학습하면 편향이 서로 안 맞을 수 있다 → **같은 `Q_SCALE` 로 동시 학습** |
| 상쇄가 사라져 분산이 늘 수 있음 | 차가 아니라 절대량을 배우므로 목표 크기가 커진다 → `Q_SCALE` 재실측 필요 |

**그래서 순서가 계약 먼저, 라벨 다음, 학생 마지막**이다 —
[[YR-203]](요청·Resolver 계약) → [[YR-204]](반사실 라벨) → [[YR-205]](학생 actor).
[[YR-203]] 은 **누가 무엇을 요청하는지**를 못박고, 반복 제안·거절이 만드는
**표본 중복과 공로 왜곡**을 먼저 없앤다.

## 4. 두 관문

**v3 에서도 두 관문 구조는 유지**한다. 1관문의 채점만 Seller 로, 2관문의 채점만
Seller−Buyer−ΔC 로 바뀐다.

### 1관문 — 블록이 제안 (60초 격자)

각 블록이 자기 후보를 훑어 **한 건만** 내놓는다.

| 모드 | 동작 |
|---|---|
| `defer_decision=False` (구) | 최소 Q < 0 일 때만 제안 — **판단을 여기서** |
| `defer_decision=True` ([[YR-195]]~) | **무조건 최악 하나 지목** — 순위만, 판단 안 함 |

### 2관문 — 중앙 배정기가 좌표 결정

전 블록 제안을 모아 **동시에** 처리한다. `GATE_IN` 은 다른 블록 20곳(공간) ∪
+15분 이연 ∪ KEEP, `GATE_OUT` 은 +15분 이연 ∪ KEEP — **공간 불가**(위치 고정).

```python
while remaining:                       # 전역 한계비용 최소 쌍 반복 선택
    best = min over (offer × coord) of cost
    q[dst] += 1; q[src] -= 1           # 가상 대기열 갱신 (볼록 비용 재계산)
    vcap[dst] += 1                     # 용량 검사
```

**KEEP 의 값**: `0 − sell_margin` (구) 또는 좌표마다 `+margin_axis` ([[YR-200]]).
**순열 불변** — 동점은 `(cost, offer_key, coord)` 사전순.

## 5. 계약 상한

| | 값 | 뜻 |
|---|---|---|
| `ANNOUNCE_LEAD_S` | 1,800초 | 통지 리드 = 검토 창 |
| `WINDOW_S` | 1,800초 | 판매 검토 창 |
| 격자 | 60초 | 결정 주기 |
| `DEFER_DELTA_S` | 900초 | 1회 이연량 |
| `MAX_ENTRY_DEFERRALS` | **1** | 작업당 이연 상한 |
| `MAX_TRANSFERS` | **1** | 작업당 이송 상한 — A→B→C 금지 |

### ⚠️ v3 에서 갈라야 하는 상수

`ANNOUNCE_LEAD_S` 하나가 **두 역할**을 겸한다 — 통지 리드이면서 검토 창이다.
[[YR-190]] 에서 리드가 **트럭마다 다른 분포**가 되면 이 겸직이 깨진다.

| 역할 | v3 |
|---|---|
| 통지 리드 | 트럭별 (실측 분포 — [02](02-무대.md) §4) |
| 검토 창 `WINDOW_S` | **상수 유지** — 계산량 상한이라서 |

즉 "5시간 전에 알아도 검토는 도착 30분 전부터"가 된다. 리드가 긴 트럭의 이점은
*더 오래 검토*가 아니라 *더 일찍 후보에 들어옴*이다.

## 6. 비용이 아니라 제약으로 다루는 것 (v3 유지)

**물리적으로 불가능한 것은 벌점이 아니라 후보에서 제거한다** — 용량 초과
(`free_slots − vcap ≤ capacity_margin`) · 크레인 충돌(`feasible_mask`) ·
재조작 용량(`rehandle_capacity_ok`). 대기·주행·지연·본선만 **비용함수**다.
**벌점으로 때려 넣은 곳이 없다.**
