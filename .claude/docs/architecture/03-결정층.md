## 1. 두 층이 세계를 통해서만 만난다

```
① 크레인 층 ─ 블록 안: "비는 크레인 2대로 어떤 작업을 할까"
     ↕  (직접 통신 없음. 야드 상태로만 상호작용)
② 재배치 층 ─ 블록 사이: "이 트럭을 다른 블록으로 보낼까 / 미룰까"
```

## 2. ① 크레인 층 — **동결** (v3 에서 변경 없음)

`JointPairNet(250)` · **97,410 파라미터** · `requires_grad=False` · 매 iteration 해시
검사. 계보: 규칙 → 증류(YR-073) → PPO(YR-139) → 채택(YR-143 C0).
**두 대를 함께 정한다** — 한 행 = `ctx_a + blk_a + ctx_b + blk_b`, `argmin`(같은
블록의 두 대가 서로 방해하므로 조합 단위).

**왜 안 배우나**: 오라클 상한이 트럭 1대당 **+0.18분**(두 번 확증)인데 재배치 축은
−2.6분 — **14배 차이라 여기 집중한다.** ⚠️ 구 2블록 무대 학습분을 21블록에 얼려
쓰므로 이 무대에서는 규칙보다 비싸다(`A − R` = +59.97).

## 3. ② 재배치 층 — **학습 대상** (v2 현행)

`SellQNet` **5,633 파라미터**(21→64→64→1)가 **비용**을 낸다(확률이 아니다).
선택은 `argmin`(평가) · ε=0.15·σ=0.20(학습 탐색). 가중치 **1벌을 21블록이 각자
실행**한다(중앙학습·분산실행).

**행 = 21차원 = 블록 7 + 후보 6 + 좌표 8**

| 부분 | 내용 |
|---|---|
| 블록 7 | inside/10 · pipeline/10 · crane_backlog/3600 · occupancy · vessel_slack/3600 · announced_30/10 · n_cands/6 |
| 후보 6 | ETA 잔여 · is_out · size40 · gate 잔여 · 이송 이력 · 이연 이력 |
| 좌표 8 | is_space · is_time · dst_load · dst_free · route_delta · defer_s · src_load_after · **src_load** |

**행에 목적지가 들어간 것이 v2 의 성과다**(구판 PPO 는 14차원이라 목적지가 없어
[[YR-175]] 부호 오류·[[YR-177]] 기준 불일치가 났다). **⚠️ 그래도 결정은 전부 중앙
배정기가 한다** — 받는 블록에 거절권이 없어 **붐비는 곳에 떠넘길 수 있다.**

## 3-1. ★v3 변경 ③ — Seller·Buyer 를 **독립 행위자**로

**두 문제를 한꺼번에 고친다.** ① 학습 목표는 원래 세 조각의 뺄셈인데
(`D_i = R_src − B_dst − ΔC_route` · [04b](04b-학습-잣대.md) §1) 망 하나가 **결과만**
보면 양쪽이 다 커도 차가 작을 때 **신호가 상쇄돼 사라지고** 어느 쪽이 틀렸는지도
모른다. ② **받는 쪽에 거부권이 없어** 붐비는 블록에 밀어넣을 수 있다.

### 계약 — 상호 동의가 있어야 거래다

```
Seller A :  a ∈ {KEEP, SELL}                    자기 블록만 보고 스스로 고른다
Buyer  B :  a ∈ {REJECT, BUY}                   offer 를 보고 스스로 고른다

거래 후보 (A, B, j)  ⇔  SELL_A(j)  ∧  BUY_B(A, j)
```

**Resolver 는 동의가 없는 edge 를 새로 만들거나 강제할 수 없다.** 동의된 것들
중에서 **용량·소유권·동시오더 제약을 지키며 매칭만** 한다. 여러 Buyer 가 같은
작업을 원하면 하나만, 한 Buyer 가 여러 작업을 원하면 배치 용량 안에서만.
`SELL` 인데 동의 edge 가 없거나 배치에서 안 뽑히면 `RESOLVER_KEEP` 으로 잠근다.

**이게 "시장"이라는 이름에 맞는 유일한 형태다** — 논문 서사 B 의 본 주장이
*"블록 간 재배치 **시장**"* 인데, 중앙이 다 정하면 시장이 아니라 배정이다.

### 어떻게 배우나 — 반사실 이진 라벨 (PPO 불필요)

행위자마다 선택지가 **둘뿐**이므로, 각 세계를 굴려 비용을 재고 싼 쪽을 고르면 된다.

```
Seller :  Φ_H(KEEP)   vs  Φ_H(SELL)        같은 snapshot·난수로 H=1h 씩
Buyer  :  Φ_H(REJECT) vs  Φ_H(BUY)
```

**회귀만으로 끝난다** — v1 에서 무너진 critic([[YR-180]] 보상 91%가 0)을 다시
들이지 않는다. 라벨 생성은 [[YR-204]] 교사가 맡는다.

### 정보 경계

| 행위자 | 볼 수 있는 것 |
|---|---|
| Seller | 자기 블록 상태 + 자기 후보 작업 |
| Buyer | 자기 블록 상태 + **Seller 가 공개한 offer message** |

**Buyer 는 다른 Buyer 의 응답을 못 본다** — 동시 결정이라 구조적으로 불가능하다.
경쟁 입찰이 아니라 **각자 자기 값만 보고 응답**한다.

### 왜 나은가 — 셋

**① 신용 배분이 행위자별로 갈린다** — 손해가 났을 때 "내놓은 쪽"인지 "받은 쪽"인지
라벨 수준에서 구분된다. **② 떠넘기기가 구조적으로 막힌다** — 받는 쪽에 거절권이
있다. **③ 표본이 2배** — 게다가 Buyer 라벨은 **채택 안 된 목적지에도** 붙는다.

**문헌 위치**: 시장 기반 다중로봇 과제 배분(Dias et al. 2006)의 매도·매수 호가.
차분 보상(Wolpert & Tumer 2002)을 **양쪽으로 쪼갠** 형태다.

**⚠️ 정정 — 계산량은 안 줄어든다.** 구 판에 *"O(N²)→O(N)"* 이라 적었으나 **틀렸다.**
Buyer 값은 어느 작업이냐에 따라 달라지므로(`Buyer(dst, job)`) 제안 21 × 목적지 20 =
**420회** 평가가 여전히 필요하다. **진짜 이득은 계산량이 아니라 신용 배분·거부권·
표본 수**다.

### 남는 위험

| 위험 | 대응 |
|---|---|
| 초기에 Buyer 가 전량 거절 → **거래 0** | 탐색 설계 필요. 표본 0 회차면 즉시 중단([06](06-학습과-판정.md) 하드가드) |
| 두 학습자의 **비정상성** — 상대가 변하면 내 라벨도 변함 | 반사실이 **그 시점 정책 기준**이므로 라벨을 회차마다 다시 만든다 |
| `R_src` 가 여전히 가정 | 반사실(축 ②)이 **먼저** 들어와야 의미 있다 |
| 두 망의 눈금 어긋남 | 같은 `Q_SCALE` 로 동시 학습 · 절대량을 배우므로 `Q_SCALE` 재실측 |

**그래서 순서가 계약 → 라벨 → 학생**이다: [[YR-203]] → [[YR-204]] → [[YR-205]].

## 4. 결정 절차 — **최초 통지 1회** ([[YR-203]])

**v2 의 "60초마다 재검토"가 사라진다.** 공개 ETA 가 재배치 창에 **처음 들어온**
60초 epoch 에서만 판단하고, 결과가 KEEP 이든 재배정이든 **즉시 잠근다**.

```
이전 epoch: ETA − now > WINDOW        아직 자격 없음
현재 epoch: 0 < ETA − now ≤ WINDOW    ← 이번 배치 J_t 에 최초 1회 포함
결정 후    : allocation_decided = True  다시 거래하지 않는다
```

**왜 바꾸나**: 같은 작업이 30분 창 안에서 반복 제안·거절되면 **학습 표본이
중복**되고 **공로가 왜곡**된다. 한 번만 결정하면 그 왜곡이 사라진다.

### 한 epoch 안의 순서

```
① 이번 epoch 에 처음 자격을 얻은 작업 J_t 를 모은다
② 각 Seller 가 작업별로 KEEP / SELL 을 고른다      (SELL 은 방송된다)
③ 각 Buyer 가 그 offer 에 BUY / REJECT 로 독립 응답
④ Resolver 가 동의 edge 만 모아 batch 로 확정
      while remaining:  best = min over 동의 edge of cost
                        q[dst] += 1; q[src] -= 1     가상 대기열 갱신
                        vcap[dst] += 1               용량 검사
```

**순열 불변** — 동점은 `(cost, offer_key, coord)` 사전순. `GATE_OUT` 은 공간 판매
불가(컨테이너 위치 고정), 시간 이연과 KEEP 만 가능.

### ⚠️ v3 에서 갈라야 하는 상수

`ANNOUNCE_LEAD_S` 하나가 **통지 리드**와 **검토 창** 두 역할을 겸한다.
[[YR-190]] 에서 리드가 트럭마다 다른 분포가 되면 이 겸직이 깨진다 —
검토 창은 **`min(리드, WINDOW_CAP)`** 으로 리드를 따라가되 뚜껑을 씌운다.

**★창을 상수로 두면 실험이 무효다.** 후보 자격이 창 기준이라 5시간 전에 통지해도
후보가 되는 건 도착 30분 전이고, 그러면 리드를 바꿔도 동작이 한 줄도 안 바뀐다.
뚜껑(`WINDOW_CAP = 7200초`)은 계산량 상한이다 — 값은 [[YR-190]] 착수 시 동결.

## 6. 비용이 아니라 제약으로 다루는 것 (v3 유지)

**물리적으로 불가능한 것은 벌점이 아니라 후보에서 제거한다** — 용량 초과
(`free_slots − vcap ≤ capacity_margin`) · 크레인 충돌(`feasible_mask`) ·
재조작 용량(`rehandle_capacity_ok`). 대기·주행·지연·본선만 **비용함수**다.
**벌점으로 때려 넣은 곳이 없다.**
