## 0. 데이터를 셋으로 나눈다

한 트럭의 방문에 얽힌 데이터는 **출처와 시점이 다르다.** 섞으면 정보 경계가 샌다.

| | 무엇 | 출처 | 정책 |
|---|---|---|---|
| **① 오더** | 터미널이 **외부에서 받는** 작업 지시 | 코피노 | ✅ 전부 |
| **② 시나리오 파라미터** | 재현을 위해 **시드에서 고정**하는 외생값 | 실험 설계 | ❌ 전부 |
| **③ 실행 기록** | 시뮬레이션이 진행되며 **남는 사실** | 엔진 | 지난 것만 |

**②를 오더에서 분리하는 것이 v3 의 첫 결정**이다. 그러면 **오더 레코드에 미래가
한 조각도 없어** 정보 경계가 **구조로** 보장된다.

실제 터미널에는 ②가 없다 — 트럭이 그렇게 움직일 뿐이다. 우리는 **실험을
재현해야** 하므로 그 움직임을 시드에 고정한다. **②는 시뮬레이션의 필요이지
도메인의 일부가 아니다.**

DGT 로그는 ①과 ③이 한 줄이다(로그이므로). 대조할 때 감안한다.

## 1. ① 오더 — 코피노 1통으로 확정 (6)

**코피노 1건 = 오더 1건 = 컨테이너 1개.** 20피트 2개를 실었으면 **오더 2건**이다.

| 필드 | 타입 | 뜻 | 정책 |
|---|---|---|---|
| `docKey` | str | 방문 고유키. **블록명 접두 없음** | ✅ |
| `inOut` | int | **반출 0 · 반입 1** | ✅ |
| `copinoNoticeTime` | float | 코피노 접수 — **터미널이 알게 된 순간** | ✅ |
| `inOutReserveTime` | float | 기사가 신고한 **반출입 예정 시각** | ✅ |
| `conLoc` | str | 배정 블록 (**기정**) | ✅ |
| `conNo` | str | 컨테이너 번호 (**기정**) | ✅ |

**`copinoNoticeTime` 과 `inOutReserveTime` 은 함께 들어온다** — 코피노 한 통에
"지금 접수했고, 이때 들어가겠다" 가 같이 담긴다.

**규격(`size`)은 넣지 않는다** — 오더 1건 = 컨테이너 1개이므로 개수 정보가 불필요하다.
(작업 시간이 규격에 따라 다르면 그때 다시 본다.)

## 2. ② 시나리오 파라미터 — 정책 비가시 (3)

**오더가 아니다.** 시뮬레이터가 트럭을 움직이는 데 쓰는 외생값이며 **레코드에
노출하지 않는다.**

| 값 | 무엇을 만드나 | 코드 |
|---|---|---|
| 실현 게이트인 | `gateInTime` | 시드에서 추출 |
| 진입 주행 소요 | `blockInTime = gateIn + 주행` | `arr = realized + travel_s` |
| 출문 주행 소요 | `gateOutTime = jobDone + 출문` | `r.gate_out = t + exit_travel_s` |

**왜 소요시간인가**: 재배치하면 목적지가 바뀌어 `blockInTime` 이 달라진다.
**소요는 트럭 고유값**이라 블록이 바뀌어도 유지된다.

**DGT 와 방향이 반대다** — 로그에는 `blockInTime` 이 이미 있고 소요를 거기서
유도한다. 우리는 결과를 적는 게 아니라 **만들어야** 한다.

## 3. ③ 실행 기록 — 이벤트 종료마다 (7 · 초기 `None`)

| 필드 | 언제 | 기록 API |
|---|---|---|
| `gateInTime` | 게이트 진입 | `TimeLedger.register()` |
| `blockInTime` | 블록 도착 | `.block_arrival()` |
| **`serviceStartTime`** | 크레인이 잡음 | `.service_start()` |
| `jobDoneTime` | 작업 완료 | `.job_done()` |
| `gateOutTime` | 출문 | `.job_done()` 이 함께 확정 |
| `prevConLoc` | **판매 확정** — 기존 `conLoc` 을 보관하고 `conLoc` 을 새 블록으로 | `record_swap()` |
| `conSwapReason` | 〃 — 사유 | 〃 |

**`gateInTime` 도 기록이다** — 값은 ②가 정하지만 **레코드에는 그 시각이 지나야
나타난다.** 그래서 정책이 오더를 읽어도 미래를 못 본다.

**`moveLoc` 은 두지 않는다** (2026-08-20 결정) — `conLoc` 이 **항상 현재 블록**을
가리키고, 바뀔 때 옛 값이 `prevConLoc` 으로 간다. 필드 둘이 "어느 게 지금인지"를
헷갈리게 만드는 것보다 낫다.

### ★`serviceStartTime` 은 왜 필요한가 (지울 수 없다)

보상 계산의 **두 곳**에서 쓰인다.

**① 크레인 점유 시간** — "기다린 시간"과 "작업한 시간"을 가른다.

```python
occupy = job_done − service_start
b_dst  = own + blocked_dst × occupy/3600 + vessel_pressure(..., occupy)
                              ↑ "내가 크레인을 잡은 동안 뒤차 N대가 밀렸다"
```

없으면 `blockIn → jobDone` 을 써야 하는데, 그러면 **줄 서서 기다린 20분까지
크레인 점유로 센다**(실제 작업은 3분).

**② 누가 "대기 중"인지 판정** — `_waiting_at()` 이
`block_arrival ≤ t < service_start` 로 큐를 센다. 없으면 **작업 중인 트럭까지
대기로 센다.**

**유도 불가**: `service_start = job_done − 작업시간` 인데 작업시간이 트럭마다
다르다(재취급·규격). 표준 180초(`SVC_REF_S`)는 **예측용**이지 실측이 아니다.

**⚠️ DGT 에는 이 필드가 없다.** 실데이터로 가면 `occupy` 를 계산할 수 없어
**보상의 큰 항이 사라진다.** (2026-08-18 인계 회신에서 이 결손을 "영향 낮음"이라
적었으나 **정정한다** — 위 두 용도를 보면 영향이 크다.)

## 4. 파생 (저장하지 않음)

| 값 | 식 |
|---|---|
| **`turnTime`** | `gateOutTime − gateInTime` — 트럭 총 체류 |
| 리드타임 | `gateInTime − copinoNoticeTime` — 얼마나 미리 알았나 |
| **예약 준수 오차** | `gateInTime − inOutReserveTime` — 약속을 지켰나 |
| 진입 주행 | `blockInTime − gateInTime` |
| 대기 | `serviceStartTime − blockInTime` |
| 작업 | `jobDoneTime − serviceStartTime` |
| 출문 주행 | `gateOutTime − jobDoneTime` |

**저장하지 않는 이유**: 시각 다섯 개에서 전부 유도된다. 중복 저장은 불일치의 원인.

## 5. v2 에서 버리는 것

| 필드 | 왜 |
|---|---|
| `job_id`·`block`·`arrival_s`·`size_ft40` | 구 이름 |
| `requested_flow` | **합성 인공물** — 생성기가 "반출로 만들고 싶었다"를 기록 |
| `fallback_reason` | **합성 인공물** — "꺼낼 컨테이너가 없어 반입으로 바꿈" |
| `size_class` | 오더 1건 = 컨테이너 1개이므로 불필요 |
| `travel_base_s` | **읽는 곳 0** — `layout.gate_to_block_s(conLoc)` 로 계산 가능 |
| `travel_s`·`exit_travel_s` | 오더가 아니라 **② 시나리오 파라미터** 로 이동 |
| `schema` | 행마다 반복할 이유 없음 — **파일 머리에 한 번** |

두 인공물은 **실데이터에 없는 개념**이다. BNCT 명세가 `fallback_reason` 을
`conSwapReason` 에 대응시켰으나 **완전히 다른 것**이라 정정했다(2026-08-18).

## 6. 리팩토링 — 현 구현과의 차이

```contract
order_fields_target   = 6
record_fields_target  = 7
```

| | 현 상태 | v3 목표 |
|---|---|---|
| 이름 | **두 벌** — 구 키가 동작, 새 키는 소비처 0 | 한 벌 |
| 시각 | ①②③이 **전부 같은 값**(`arrival_s`) | 셋으로 갈림 |
| `inOut` | 문자열 `'GATE_IN'`/`'GATE_OUT'` | **정수 1/0** |
| `docKey` | `'Y01:D-00000'` | 블록 접두 없음 |
| 기록 5시각 | 장부에만 · 오더와 **연결 안 됨** | 병합 |
| `prevConLoc` | 필드는 있으나 `record_swap()` **미호출** | 판매 확정 시 갱신 |
| `block_worked`(=moveLoc) | 있음 | **삭제** |

**값이 안 바뀌는 단계(이름·구조)와 바뀌는 단계(리드타임 분포)를 나눈다** —
한 커밋에 섞으면 회귀 원인이 안 갈린다.
절차 → `docs/data-handover/2026-08-20-오더-스키마-확정안.md`
