# 01 — 오더 스키마: 트럭 1대의 데이터 계약

> **확인일 2026-08-20** · 코드: `integrated/terminal_stream.py`(생성) ·
> `integrated/order_schema.py`(규격) · `integrated/time_contract.py`(장부)

## 0. 경계 — 입력과 출력을 섞지 않는다

```
오더(스케줄)  = 시뮬레이터에 넣는 것    "이 트럭이 언제·어디로 온다"
시간 장부      = 시뮬레이터가 만드는 것  "실제로 언제 도착·서비스·완료·출문했다"
```

DGT 로그는 **한 줄에 둘이 섞여** 있다(로그이므로). 우리는 나뉜다.
**미래 실현값을 오더에 넣지 않는다** — 넣으면 정책이 미래를 볼 통로가 생긴다.

## 1. ★시각이 셋이다

| # | 필드 | 뜻 | 정책 |
|---|---|---|---|
| ① | `copinoNoticeTime` | 코피노 접수 — **터미널이 알게 된 순간** | ✅ |
| ② | `inOutReserveTime` | 기사가 **"이때 들어가겠다"고 신고**한 예정 시각 | ✅ |
| ③ | `gateInTime` | **실제로** 게이트에 들어온 시각 | ❌ ③ 이후만 |

```
리드타임  = ③ − ①    "얼마나 미리 알았나"       DGT 실측 중앙 1.27h
예약 준수 = ③ − ②    "약속 시각을 지켰나"
```

**⚠️ 현 구현은 셋이 전부 같은 값**(`arrival_s`)이다. 두 개념이 소멸해 있다.
확정안 §6 의 "B — 값까지 벌리기"가 이것을 고친다.

## 2. 오더 — 생성 시 확정 (12)

| 필드 | 타입 | 뜻 | 정책 | 현 구현 키 |
|---|---|---|---|---|
| `docKey` | str | 방문 고유키 | ✅ | `job_id` (블록 접두 있음 — 제거 대상) |
| `inOut` | enum | `GATE_IN`/`GATE_OUT` | ✅ | `flow` |
| `copinoNoticeTime` | float | ① 통지 | ✅ | **없음** |
| `inOutReserveTime` | float | ② 예정 | ✅ | **없음** |
| `gateInTime` | float | ③ 실현 진입 | ❌ | `arrival_s` |
| `conLoc` | str | 최초 배정 블록 | ✅ | `block` |
| `conNo` | str\|None | 대상 컨테이너(반출) | ✅ | `target` |
| `sizeClass` | (str,str,str\|None) | 규격 | ✅ | `size_ft40` (불리언) |
| `travelBaseSec` | float | 게이트→블록 **기준** 주행 = 거리÷속도 | ✅ | `travel_base_s` |
| `travelSec` | float | 그 트럭의 **실현** 진입 주행 | ❌ | `travel_s` |
| `exitTravelSec` | float | 블록→게이트 출문 주행 | ❌ | `exit_travel_s` |
| `schema` | str | 규격 판번호 | — | `schema` |

**왜 주행은 시각이 아니라 소요인가**: 재배치하면 목적지가 바뀌어 `blockInTime`
이 달라진다. **소요시간은 트럭 고유값**이라 블록이 바뀌어도 유지된다.

## 3. 진행하며 갱신 (7 · 초기 `None`)

| 필드 | 언제 | 장부 API |
|---|---|---|
| `prevConLoc` | 판매 확정 — 기존 `conLoc` 보관 | — |
| `moveLoc` | 〃 — 실제 작업 블록 | — |
| `conSwapReason` | 〃 — 사유 | — |
| `blockInTime` | 블록 도착 (B) | `TimeLedger.block_arrival()` |
| `serviceStartTime` | 크레인이 잡음 (S) | `.service_start()` |
| `jobDoneTime` | 작업 완료 (C) | `.job_done()` |
| `gateOutTime` | 출문 (O) = C + 출문주행 | `.job_done()` 이 함께 확정 |

**장부는 이미 단계마다 갱신한다** — `TruckTimes(gate_in, block_arrival,
service_start, job_done, gate_out)`. 오더 레코드로 이어주면 **DGT 로그 한 줄과
필드 대 필드로 맞는다**(우리가 `serviceStartTime` 하나 더 갖는다).

## 4. 삭제 대상

| 필드 | 왜 |
|---|---|
| `job_id`·`block`·`arrival_s`·`size_ft40` | 구 이름 — 새 이름으로 이관 |
| `requested_flow` | **합성 인공물** — 생성기가 "반출로 만들고 싶었다"를 기록 |
| `fallback_reason` | **합성 인공물** — "꺼낼 컨테이너가 없어 반입으로 바꿈" |

두 인공물은 **실데이터에 없는 개념**이다. BNCT 명세가 `fallback_reason` 을
`conSwapReason` 에 대응시켰으나 **완전히 다른 것**이라 정정했다(2026-08-18).
