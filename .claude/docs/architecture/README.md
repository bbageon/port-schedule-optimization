### ★값은 문서에 한 벌만 둔다

각 문서 상단의 **```contract 블록**이 정본이고, 스크립트가 **그것을 읽어** 코드와
대조한다. 기대값을 스크립트에 박아두면 복사본이 셋(코드·문서·스크립트)이 되어

### 아키텍처가 바뀌면

| 상황 | 무엇을 고치나 |
|---|---|
| 코드가 바뀌어 값이 달라짐 | **문서 contract 블록만** — 스크립트는 안 건드린다 |
| **새 계약값**을 추가 | ①문서에 `key = value` ②스크립트 `GETTERS` 에 대응 1줄 |
| **새 종류의 검사**를 추가 | 스크립트에 로직 추가 (예: 정보경계 같은 규칙 검사) |

배선 안 된 키는 **미배선으로 보고**된다 — 조용히 넘어가지 않는다.

### 실패하면

**둘 중 하나가 틀린 것**이다. 어느 쪽이 옳은지 판정하고 양쪽을 맞춘다.
코드가 옳으면 문서를, 문서가 옳으면(= 의도한 설계) 코드를 고친다.

### 결함 추적

문서가 "결함"이라 적은 것이 **고쳐졌는지도** 본다. 고쳐졌으면
`★고쳐짐 → 문서 갱신 필요` 로 알린다 — 문서가 낡는 것을 막는다.

## 이 문서를 고쳐야 할 때

- 코드를 바꿔 구조가 달라졌을 때 — **같은 커밋에서** 이 문서도 고친다
- 교차검증에서 불일치가 나왔을 때 — 어느 쪽이 옳은지 판정하고 양쪽을 맞춘다
- **결과를 보고 고치지 않는다** — 판정 계약은 사전등록이 정본이다
