# 06 — 학습과 판정 (v3 설계 · 축 ③)

> **성격**: to-be 설계. 코드가 여기에 맞춰진다. → [index](README.md)
> **관련 코드**: `experiments/yr189_q_train.py` · `yr195_margin.py` ·
> `yr200_axis_margin.py` · `integrated/repro.py`

**★판정 규약은 v3 에서도 안 바꾼다.** 사전등록·하드가드·짝비교·대역 관리는
**세대와 무관한 심판 규칙**이다. 바꾸면 v1·v2 와 비교가 끊긴다.
바뀌는 것은 **학습 쪽**뿐이다 — 교사–학생 2단.

## 1. 학습 계약 (v2 현행 · Q 회귀)

| | 값 | 왜 |
|---|---|---|
| 방식 | **후버 회귀** (`smooth_l1`, β=1.0) | PPO 아님 — 문맥 밴딧 위 비용 회귀 |
| 목표 | `Q(고른 행) ← −D_i / Q_SCALE` | 부호 반전: 이득 → 비용 |
| `Q_SCALE` | **20.0** | 목표를 O(1) 로. **비판정 시드에서 실측** 후 동결 |
| 학습률 | 3e-4 | yr139 앵커 승계 |
| 회차 | 16 × 4 에피소드 | YR-183 실측: 곡선이 iter 11~13 에서 평평 |
| 재생 버퍼 | 150,000 (FIFO) | off-policy — 라벨이 직접 관측이라 편향 없음 |
| 갱신 | 회차당 600 step · 미니배치 256 · grad clip 1.0 | |
| 탐색 | 제안 ε=0.15 · 좌표 σ=0.20 | **학습 중에만**. 평가는 0 |
| critic | **없음** | 붕괴할 critic 이 없다 |

### ★정직한 명명

라벨 `−D_i` 가 **그 거래의 실현 손익**이라 부트스트랩이 없다. **시간차 학습이 아니라
문맥 밴딧 위의 비용 회귀**다. 논문에 "Q 학습"이라 쓰지 않고 **"차분 신용 라벨을 쓰는
조합 행동공간 비용 회귀"**. 문헌: difference rewards(Wolpert & Tumer 2002) ·
COMA(Foerster 2018). **우리 발명이 아니다.**

### ⚠️ 알려진 설정 결함

| | 실측 |
|---|---|
| σ 를 **절대값**으로 고정 | 목표 눈금이 줄어 상대 강도 1.8배 → **8.7배** ([[YR-193]]) |
| 버퍼 FIFO 축출 | iter 10 부터 초기 넓은 탐색 데이터가 통째로 밀려남 |

**v3 에서 둘 다 고친다** — σ 를 상대값으로, 버퍼는 초기 탐색분을 남기는 축출로.
다만 [[YR-193]] 의 근거였던 3시간 창 관측이 22시간에서 뒤집혔으므로(관측 7)
**전제를 다시 재고 나서** 손댄다.

## 1-1. ★v3 학습 계약 — 교사–학생 2단

배포 시점에 반사실 rollout 을 돌릴 수 없으므로 **라벨 만드는 쪽과 결정하는 쪽을
분리**한다.

| | 교사 ([[YR-204]]) | 학생 ([[YR-205]]) |
|---|---|---|
| 하는 일 | 그 거래만 취소한 세계를 **H=1h 굴려** `D_i` 산출 | 그 라벨을 회귀로 배움 |
| 언제 | **학습 때만** | 학습 + **배포·판정** |
| 속도 | 느림 (후보 1건당 rollout 1회) | 즉시 추론 |
| 산출 | `R_src` · `B_dst` 두 조각 | Seller 망 · Buyer 망 |

**교사는 망이 아니다** — 시뮬레이터를 두 번 굴리는 절차다. 학습할 파라미터가 없다.

### 두 단계를 따로 판정한다

**4단계(교사만)는 학습 없이 끝낼 수 있다** — 교사 라벨로 잡음 하한을 재측정해
v2 라벨보다 설명력이 높은지만 본다. **낮으면 5단계(학생)를 안 한다.** 안 그러면
"학생이 못 배운 건지 라벨이 나쁜 건지"를 못 가른다.

**새 하드가드 — 교사 누출 금지**: 판정 실행에서 `rollout_calls_during_eval == 0`.
교사 라벨이 학생 **입력**에 섞이면 미래가 새어 들어온다([05](05-정보경계.md) §3).

## 2-1. ★대조군 — 고전 배차 규칙을 재배치 축으로 번역 ([[YR-211]])

지금까지 비교 상대는 `greedy`(`UnifiedNetGain`) 하나였는데 그건 **우리 비용식에서
직접 유도한 자체 휴리스틱**이라 순환적이고 문헌에 이름이 없다.

| 팔 | 누구를 옮기나 | 어디로 |
|---|---|---|
| **No Reallocation** | — (최초 배정 유지) | — |
| **FCFS** | 먼저 통지된 트럭 | Least-Loaded |
| **SPT** | 예상 작업시간 짧은 트럭 | Least-Loaded |
| **EDD / Least Slack** | SLA 여유 최소 트럭 | Least-Loaded |
| **Nearest** | 트리거된 전건 | 주행 증가 최소 |
| `NetGain` (현행) | 순이득 최대 | 순이득 최대 목적지 |
| **Proposed RL** | 학습 | 학습 |

**번역이 필요한 이유**: 고전 규칙은 *"다음에 어느 작업을 처리할까"*(sequencing)를
정하는데 우리 축은 *"어디로·언제"*(assignment)다. 게다가 재배치는 결정이 **둘**
(누구를 + 어디로)이라 목적지 규칙을 짝지어야 한 팔이 완성된다.

**공통 트리거를 고정한다** — 고전 규칙에는 "안 옮긴다"가 없다. 출발 블록의 공개
예상 대기가 상위 `k`% 일 때만 후보를 만들고 **`k` 는 전 팔 동일**하게 동결한다.
안 그러면 고전 팔이 무차별 재배치를 해서 실제보다 나빠 보인다.
**전 팔이 공개 정보만 쓴다** — `FIFOPreference` 의 누출([[YR-107]])을 반복하지 않는다.
**부하별로 방향이 갈리면** 세 수치를 다 적고 "어느 부하 구간에서 유효한가"로 쓴다.

### [[YR-207]] 은 왜 판정이 아닌가

단위만 원화로 바꾸는 것이므로 **정책 순위가 안 바뀌어야 정상**이다. 순위가 바뀌면
그건 개선이 아니라 **환산이 틀렸다는 신호**다. 그래서 대역을 안 쓰고, 대신
**전환 전후 순위 일치**를 검사한다.
