# 참조 — 안벽·야드 병목과 장비 배치 (2026-09-06 조사)

> **용도**: [[YR-248]] 크레인층 RL 의 본선 축 설계 근거. 논문 레퍼런스 후보이기도 하다.
> 조사 계기: 우리 무대에서 **본선 유휴가 Φ의 0.84%뿐**이라 크레인이 본선을 배울 재료가
> 없다는 것이 드러났고, *"현실에서는 야드가 못 대줘 배가 서는 일이 있는가"* 를 확인했다.
>
> ⚠️ 아래 인용 수치는 **검색 결과 요약에서 얻은 것**이다. 논문에 실을 때는 원문 PDF 로
> 재확인해야 한다 — 여러 편이 인증 벽에 막혀 초록·요약만 봤다.

## 1. 병목 원리 — 야드트랙터가 모자라면 안벽 크레인이 선다

| 출처 | 확인된 진술 |
|---|---|
| Berth and quay crane allocation … yard truck deployment (Transp. Res. E, 2021) | *"안벽 크레인 생산성은 작업자 생산성과 **배치된 야드트랙터 수**에 달려 있다"* — **병목 원리(bottleneck principle)** 로 명시 |
| Scientific Reports (2025) DDQN 트럭 스케줄링 | 트럭이 안벽·야드·본선을 잇고, **낮은 트럭 가동률·과도한 안벽 크레인 대기·장비 완료시간 지연**이 최적화 대상 |
| MDPI JMSE 14(8):749 (2026) | 차량 흐름 교란(운전자·야드 작업자 미숙 등)이 심하면 **안벽 크레인이 차량을 기다리며 선다** |

**→ 우리가 세운 인과(야드 공급 부족 → 배 유휴)는 이 분야의 표준 모형이다.**

## 2. 야드가 본선 지연으로 이어진다

| 출처 | 확인된 진술 |
|---|---|
| Multi-agent RL, block assignment + YC redeployment (Adv. Eng. Inf., 2026) | **야드 혼잡이 안벽 작업에 상당한 지연**을 유발하고 컨테이너 적체를 낳는다 |
| Dynamic yard crane dispatching (Adv. Eng. Inf., 2011) | **야드 크레인 운영이 터미널 전체 성능의 잠재적 병목** |
| 종합 리뷰 (Flex. Serv. Manuf. J., 2020) | 안벽은 재항시간 최소화를 보지만 **야드가 물류사슬의 결정적 병목**이 된다 |
| JMSE 10(11):1650 (2022) | 야드 크레인 배치와 반입 트럭 도착을 **본선 종속 시간창**으로 함께 최적화 |

**→ "야드 크레인 판단이 배의 재항시간을 좌우한다" 가 이 분야의 표준 문제 설정이다.
   우리 [[YR-248]] 이 하려는 것과 같다.**

## 3. 규모 — 얼마나 큰 손실인가

- **33초 지연 → 크레인당 2.1시간, 야드 규모에 따라 하루 50시간 이상** 생산성 손실
- 자카르타 국제 컨테이너 터미널 사례: 가동률 99% · **성능 효율 84%** · 종합효율(OEE) **71%**
  → 가동은 하는데 **성능에서 16% 를 잃는다**. 그 상당 부분이 대기다.

**→ 현실 터미널의 안벽 크레인 성능 손실은 10~20% 대다. 우리 무대의 0.84% 는 이 범위 밖이다.**

## 4. 장비 비율 — 트럭 몇 대가 크레인 하나를 먹여 살리나

| 출처 | 수치 |
|---|---|
| Determining the optimal number of yard trucks in smaller container terminals (ETRR, 2021) | **크레인당 9대** 배치해야 42슬롯 블록에서 최고 GCR. **16대는 과투자** — 오히려 혼잡 |
| Lutfianto (ITATS) | 150개 미만 물량에 **크레인 2 + 내부트럭 7** ≈ 크레인당 3.5대 |

⚠️ **대수만으로 비교하면 안 된다.** 터미널마다 왕복거리가 달라 **대수 × 왕복시간**이 실제
공급능력이다. 비교 가능한 양은 **공급 간격**(= 왕복시간 ÷ 대수)이다.

## 5. 우리 무대와의 대조 (2026-09-06 실측)

```
STS 처리 간격     130.9s   (27.5 moves/h · 스트림 1개)
야드 공급 간격     60.0s   (트랙터 3대 × 왕복 180s → 180/3)
                            ─────────────────────────
                            공급이 수요보다 2.18배 빠르다
```

`TransferFleetSpec.move_time_s` 주석이 **"본선↔야드 왕복"** 이라 180s 는 왕복이다.
즉 우리 트랙터는 **3분 만에 한 바퀴**를 돈다 — 현실 터미널(왕복 5~10분)보다 빠르다.

**결과**: 버퍼가 마르지 않아 배가 굶지 않고, 본선 유휴가 Φ의 0.84% 에 그친다.
크레인이 본선 일감을 뒤로 미뤄도 **손해가 발생하지 않으므로**, 비용을 낮추도록 학습하는
정책이 본선 축을 **무시하는 것이 합리적**이다. 신호(`is_vessel` 꼬리표)는 이미 있는데
**결과가 없다.**
