# 정책 설계 현황과 우회책 점검 (2026-08-07)

> "정책이 어떻게 설계됐고 어디까지 왔는지, 우회책은 없는지" 한 자리에 정리한다.
> 수치·판정은 board done row 와 결과 JSON 에서 그대로 옮겼다.

## 1. 정책은 무엇인가

한 야드 블록 안에 크레인 2기가 있고, **다음에 어떤 작업을 할지**를 고르는 것이 정책이다.

**행동 4종** (`integrated/candidates.py`)

| 행동 | 뜻 |
|---|---|
| `SERVE` | 지금 대기 중인 트럭·본선 작업을 처리한다 |
| `PRE_REHANDLE` | 곧 올 트럭의 컨테이너 위를 **미리** 치워 둔다 |
| `REPOSITION` | 크레인을 미리 옮겨 둔다(위치조정) |
| `WAIT` / `DEFER` | 지금은 아무것도 안 한다 |

**학습 방식**: 중앙에서 두 크레인의 **공동 후보**를 한 번에 평가하는 PPO(BlockQ-v4).
비용은 v2 계약(부드러운 증분비용, κ 동결)을 쓴다.

**아직 만들지 않은 것**: 블록 **사이**로 작업을 넘기는 `SELL` 학습 head 와 그 critic
(YR-151). 지금 블록 간 이송은 **계산식 견적기**(`transfer_quote.py`)만 있다.

## 2. 어디까지 왔나 — 판정 이력

### 통과한 것

| ID | 무엇 | 판정 |
|---|---|---|
| YR-146 | 배포용 교착 탈출 안전장치 "대기 허가증" | **채택**(2차 통과, 1차는 개입률 초과로 기각) |
| YR-148 | 사전 이동 있음 vs 없음 | **REMOVE_SUPERIOR** — 사전 이동 **없는** 구성이 우월 |
| YR-133 | 블록 간 판매 견적기 | **기능 통과**, 비용효과는 **미확증** |
| YR-149 | 5부하 데이터 자격 | **자격 통과**(하드 8/8) |

| YR-150 0·1단계 | N블록 엔진 계약 · H-21 자격 | **계약 9종·자격 10종 통과** |

### 한 줄 요약

**규칙(SF-SPT) 기준선보다 학습 정책이 터미널 비용을 줄인다는 증거는 아직 없다.**
지금까지 통과한 것은 대부분 **계약·안전·자격**이고, 성능 축은 열리지 않았다.
현재 3대 게이트: 성능 **미확정** · 신뢰성 **통과** · 현실성 **FAIL**(외부 앵커 5종).

## 3. 우회책 점검 — 지금 걸려 있는 것 전부

"연구적 개선 대신 공학적 우회로 넘어간 것이 없는가"를 항목별로 본다.
**[정직한 계약]** = 한계를 밝히고 쓰는 정당한 선택, **[갚아야 할 빚]** = 없애야 할 우회.

| # | 무엇 | 왜 그렇게 했나 | 분류 |
|---|---|---|---|
| 1 | **채택 구성이 코드에 없다** — 전역 플래그 기본값이 기각된 쪽 | 실험마다 전역을 갈아끼우며 커 옴 | **[갚아야 할 빚]** YR-160 |
| 2 | 게이트 진입 **후** 이송의 횟수 상한이 엔진에 없다(생성기 mask 에만) | 골든 경로라 0A 에서 안 건드림 | **[갚아야 할 빚]** YR-154 |
| 3 | 결과 JSON 의 `self_sha256` 이 자기검증 불가 | 파일에 자기 해시를 덧쓰는 구조 | **[갚아야 할 빚]** YR-155 |
| 4 | 게이트 증거가 board 편집만으로 무효화 | 작업트리 파일을 대조하는 설계 | **[갚아야 할 빚]** YR-156 |
| 5 | 외부 앵커 5종 중 4종 미확보·1종 위반 | 공개자료 한계 | **[정직한 계약]** FAIL 로 박제, YR-158 |
| 6 | 야드 배치가 **1차원 등간격 합성** | 블록 좌표·도로망 공개자료 없음 | **[정직한 계약]** 주장 범위에 명시 |
| 7 | 같은 블록 안 주행편차 σ를 60초→**5초**로 축소 | 편차 대부분을 블록 거리로 설명 | **[정직한 계약]** 지원범위에서 결정된 값 |
| 8 | 2블록 하네스가 목적지를 **일부러 무시**하는 주행 함수 사용 | 골든 결과 바이트 보존 | **[정직한 계약]** 테스트로 잠금 |
| 9 | N=3 동시확정 검사에서 발의 임계를 **강제로** 음수 | 코드 경로 도달 확인용 | **[정직한 계약]** 성능 판정에 미사용 |
| 10 | 블록 배경 생성이 `n_external=1` 로 만든 뒤 그 트럭을 버림 | 기존 생성기 재사용 | **[갚아야 할 빚]** 소규모·가독성 문제 |
| 11 | 관측시간 종료를 `drain_window_s=0` 으로 만들며 파라미터 검증 우회 | 시나리오 객체엔 검증이 없음 | **[갚아야 할 빚]** 소규모 |
| 12 | 부하 5종이 **서로 다른 시드** — 부하 효과의 인과 비교 아님 | 1단계는 자격 확인이 목적 | **[정직한 계약]** YR-157 에서 해소 |

### 우회로 **가지 않은** 것 (연구 원칙 준수)

- 하이브리드 결합·레이어 추가로 성능을 만들지 않았다. 기각된 축은 **완화 없이 기각**으로 박제했다.
- 임계·시드·표본을 결과를 보고 바꾸지 않았다. 부하가 전부 CLEAR 로 나왔을 때도 총량을
  올리지 않고 별도 사전등록(YR-157)으로 분리했다.
- 게이트를 통과시키려고 앵커 범위를 지어내지 않았다 — **FAIL 을 그대로 받았다.**

## 4. 다음에 무엇을 해야 하나

성능을 말하려면 **세 가지가 먼저** 필요하다.

1. **YR-158** 외부 앵커 확보·게이트→블록 시간 정본 결정 → 현실성 게이트를 닫는다.
2. **YR-157** 부하 대역 확장 → 지금 대역은 혼잡비 1.03~1.09 로 **정책이 좋아질 여지가 없다.**
3. **YR-160** 채택 배포 구성 단일 정의 → 그래야 "무엇을 비교했는지"가 확정된다.

그 뒤에야 **YR-151 0B-H** 에서 규칙·계산식·학습 정책의 시간당 터미널 비용을 처음 비교한다.
