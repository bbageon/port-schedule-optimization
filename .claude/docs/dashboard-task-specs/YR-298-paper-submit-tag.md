# YR-298 — 제출 시점 커밋에 `paper-v3-submitted` 태그

- **상태**: backlog 🟡 · 2026-09-06
- **분류**: Paper
- **선행**: [[YR-297]] v4 세대 복사

## 왜 아직 안 박았나

[[YR-297]] 계획에는 *"제출 시점 태그도 함께"* 가 있었지만 **박지 않았다.** 현재 HEAD 가
실제 제출된 PDF 와 같은 상태라는 보장이 없기 때문이다 — 제출 이후에도 논문 세션이
수정 커밋([[YR-293]]·[[YR-294]] 등)을 쌓았다. **틀린 커밋에 그 이름을 박으면 가짜 기록**이 되고,
리비전 방어 실험이 그 기준점을 믿고 돌기 때문에 조용히 틀리면 손해가 크다.

분기 시점은 확실한 사실이라 `v4-split` 로 이미 고정돼 있다. 이 row 는 **다른 사실**을 다룬다.

## 할 일

1. 논문 세션에서 실제 투고본 PDF 를 확정한다 (`docs/paper/v3/submission/main.pdf` 와
   투고 시스템에 올라간 파일이 같은지).
2. 그 PDF 를 만든 커밋을 찾는다 — `git log --oneline -- docs/paper/v3/submission/` 로
   후보를 좁히고, 필요하면 해당 커밋에서 다시 컴파일해 쪽수·수치를 대조한다.
3. `git tag -a paper-v3-submitted <해시> -m "투고본 — 이 커밋의 코드·문서가 논문의 정본"`
4. push (`git push origin paper-v3-submitted`).

## 완료 조건

태그가 가리키는 커밋에서 컴파일한 PDF 가 투고본과 **쪽수·핵심 수치 일치**. 불일치하면
태그를 박지 말고 원인을 먼저 기록한다.
