# YR-332-z — 본선 작업 마감 필드가 시각 재배치 때 옮겨지지 않는다

- **상태**: backlog
- 등록: 2026-11-07. 상위 [[YR-332]], 발견 작업 [[YR-332-t]] 코드 대조.
- 잠재 결함 한 축. 현재 판정 경로의 결과를 바꾸지 않는다는 점을 먼저 확인한 뒤 고친다.

## 무엇과 왜

본선 스트림의 시작 시각을 무대에 맞춰 옮길 때(`terminal_stream.py:_retime_vessels`) 계획 완료·
출항 예정·물리 하한과 작업 해제 시각은 함께 옮겨진다. 그러나 각 본선 작업의 마감 필드
(`scenario_gen.py`의 `deadline = 원래 계획 완료 + 1,800초`)는 옮겨지지 않는다.

이 필드는 후보 수 상한을 쓸 때의 우선 점수(`candidates.py:_score`)와 KPI의 본선 지연
(`kpis.job_completed`)에만 쓰인다. 후보 수 제한이 없는 v7 기본 평가(YR-332-v·t)에서는
점수로 후보를 고르지 않으므로 선택에 영향이 없고, 공식 비용에도 들어가지 않는다.
학습 정책의 본선 여유 입력은 옮겨진 선박 계획을 쓰므로 이 필드와 무관하다.

## 완료 기준

1. 이 필드를 읽는 모든 경로를 나열하고, 후보 상한을 쓴 과거 실행(예: 상한 12 비교)의 영향 범위를 적는다.
2. 재배치 시 마감도 같은 차이만큼 옮기는 수정과 회귀 시험을 추가한다.
3. 후보 제한 없는 기본 평가의 결과·해시가 바뀌지 않음을 확인한다. 바뀌면 원인을 따로 보고한다.
