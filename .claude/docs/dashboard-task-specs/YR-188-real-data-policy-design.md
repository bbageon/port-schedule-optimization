# YR-188 — 실데이터를 정책이 어떻게 쓰는가 (설계)

- **Epic**: RL / **Priority**: 🟠 / **등록일**: 2026-08-18 / **상태**: backlog
- **3대 게이트 보정 대상**: `performance` (단 선행 조건이 많다)
- **1줄**: 새 정보의 **대부분은 정책 상태가 아니다.** 어디에 넣을지를 먼저 가른다.

## 0. 원칙 — 왜 "다 넣기"가 답이 아닌가

두 가지가 막는다.

**① 프로젝트 규칙** (AGENTS.md 연구 설계 원칙 2)

> 강화학습 정책 최적화는 **핵심 정보만으로 먼저** 구성하고, 효과가 실증된
> 뒤에만 부가 정보를 추가한다 — **한 번에 한 축씩, 각 추가는 자기 실증을 동반**

**② 진단된 병목이 정보가 아니다** ([[YR-185]])

```
보상의 91% 가 0  →  critic 붕괴  →  기준선 소멸  →  PPO 가 REINFORCE 로 퇴화
```

이걸 고친 것만으로 규칙과의 격차가 96.6 → 40.9 로 줄었다. **정보를 더 넣어서
줄인 게 아니다.** 지금 상태를 늘리면 어느 축이 들었는지 못 가린다.

**따라서 상태 추가는 마지막이다.** 그 전에 훨씬 값어치 있는 자리가 셋 있다.

## 1. 새 정보를 네 곳으로 가른다

| 곳 | 무엇이 들어가나 | 값어치 | 선행 |
|---|---|---|---|
| **A. 환경 보정** | 준수 오차·주행·도착 곡선·반입출 비율 | **최상** | 없음 |
| **B. 견적 라벨** | `expWaitingMin`·실현 4시각 | **최상** | 데이터 |

| **D. 정책 상태** | 준수 이력·`upperCount`·`size_class` 등 | **마지막** | A~C + 실증 |

## A. 환경 보정 — 정책을 안 건드린다

가정 넷을 실측 분포로 바꾼다([[YR-187]] §1단계). **정책 코드는 한 줄도 안
바뀐다.** 그런데 **모든 수치의 의미가 달라진다** — "문헌 보정" → "실측 보정".

이것만으로 주장 게이트가 한 단계 올라간다. **가장 싸고 가장 크다.**

## B. 견적 라벨 — 결함 2건을 우회한다

현재 우리 견적 경로에 결함이 둘이다.

| | |
|---|---|
| [[YR-175]] | 견적망이 "그 칸 예약이 늘면 부담이 준다"고 답한다(부호 오류) |
| [[YR-177]] | 공간·시간 좌표를 **다른 자로** 잰다(기준 불일치) |

**터미널이 이미 `expWaitingMin`(예상 대기 분)과 `blcWaitingCarCount`를
계산해 둔다.** 이걸 쓰면 두 결함을 **고치는 게 아니라 우회**한다.

### 세 가지 쓰임 (택일 아님)

1. **정답지 교체** — 견적망을 `expWaitingMin` 으로 지도학습. 우리가 만든
   "실현 부담" 라벨(부호가 뒤집힌 그것)을 버린다.
2. **직접 사용** — 견적망 없이 터미널 값을 resolver 에 그대로 넣는다.
   가장 단순하고, 기준 불일치(YR-177)도 자동 해소된다(양쪽 다 같은 출처).
3. **대조군** — 우리 계산식 vs 터미널 값 vs 견적망 3자 비교.
   **어느 견적이 좋은지 처음으로 정량 비교**할 수 있다.

**권장은 2 → 3 순서다.** 먼저 가장 단순한 것으로 갈아끼우고, 그 다음
우리 것이 더 나은지 본다. 지금은 비교 대상이 없어 "좋다"를 말할 수 없었다.

**주의**: `expWaitingMin` 산출식을 모르면 우리 비용 정의와 단위가 어긋난다.
[[YR-187]] 추가 요청 5번이 이것이다.

## C. 행동 제약 — 불법 행동을 못 하게 한다

### C-1. `restrictedEntryDateTime` — 이연 가능 범위

지금은 **모든 트럭을 +15분 미룰 수 있다**고 가정한다. 실제로는 오더마다
반입 제한 시각이 있다.

→ **행동 마스크**로 쓴다. 상태가 아니다. 제한 시각을 넘기는 이연은
**후보에서 제외**한다.

**효과 예측**: 시간 이연은 지금 1건당 **+14.28분 손해**다. 불법 이연이
섞여 있었다면 그 손해의 일부는 **애초에 못 했을 행동**이다. 마스크를 씌우면
시간 축 손해가 줄어들 수 있다 — 검증 대상이다.

### C-2. `VBS_RES_AVL` — 시간대 슬롯 용량

[[YR-176]] 이 크레인 처리량으로 **유도하려던 값의 정본**이다. 제도적 상한이
실재하므로 유도를 버리고 이 값을 쓴다. YR-176 은 이미 이 이유로 **보류** 중.

## D. 정책 상태 — 마지막, 한 축씩

**A~C 를 끝내고, 그 상태에서 정책이 규칙을 넘는지 본 뒤에** 착수한다.
넘지 못하면 상태를 늘리는 것은 순서가 틀린 처방이다.

### 후보를 값어치 순으로

| # | 특징 | 왜 새로운가 | 정보 경계 |
|---|---|---|---|
| **1** | **예약 준수 이력** (트럭 또는 `dispatchGroup` 단위 과거 `reserved_s`−`gate_in_s` 통계) | **지금 정책이 원리적으로 가질 수 없는 정보.** "이 트럭은 예약을 안 지키는 편"을 알면 이연 판단이 달라진다 | ✅ 과거는 공개 |
| 2 | `upperCount` (적재 상단 개수) | 재조작 필요량 → **작업 시간 예측**. 지금은 모든 작업을 같은 시간으로 본다 | ✅ 공개 |
| 3 | `size_class` (ISO 4자리) | 냉동·탱크·오픈탑은 작업 시간이 다르다. 지금은 20/40 이분법 | ✅ 공개 |
| 4 | 블록 큐 관측 (`blockInSeq` 로 재구성) | 지금은 대기열 **길이**만 본다. 순번을 알면 **언제 내 차례인지** | ✅ 공개 |
| 5 | `dispatchGroup` | 같은 배차 그룹은 함께 움직인다 — 한 대를 옮기면 나머지도? | ✅ 공개 |

**1번이 압도적이다.** 나머지는 "숫자가 정확해지는" 것이고, 1번은 **없던 축이
생기는** 것이다.

### 추가 절차 (축마다 동일)

```
① 그 특징 하나만 추가 (다른 것 동결)
② 같은 시드·같은 평가일로 재학습
③ 규칙 대비로 판정 — 모드 명시
④ 개선이 유의하지 않으면 되돌린다
```

**한 번에 하나.** 다섯을 한꺼번에 넣으면 실패했을 때 원인을 못 찾는다.
YR-185 에서 정확히 그 이유로 ②③을 묶고 나머지를 건드리지 않았다.

## 2. 순서

```
A 환경 보정   →   B 견적 라벨 교체   →   C 행동 제약   →   [규칙 대비 재판정]
                                                              ↓ 넘으면
                                                          D 상태 한 축씩
                                                              ↓ 못 넘으면
                                                          서사 B 유지·D 착수 안 함
```

**C 다음의 재판정이 분기점이다.** A~C 는 정책을 안 건드리고도 성능을 바꾼다
(환경이 정확해지고, 견적이 정확해지고, 불법 행동이 사라진다). 그 상태에서도
규칙을 못 넘으면 **상태를 늘려서 넘을 가능성은 낮다.**

## 4. 하지 않는 것

- **새 정보를 한꺼번에 상태에 넣는 것.** 원칙 위반이고 디버깅이 불가능해진다.
- A~C 를 건너뛰고 D 로 가는 것 — 가장 싼 것을 안 하고 가장 비싼 것부터 하는 셈.
- `expWaitingMin` 산출식을 모르는 채 우리 비용과 섞는 것 (단위 불일치).
- 실데이터가 오기 전에 D 를 설계 이상으로 진행하는 것.
