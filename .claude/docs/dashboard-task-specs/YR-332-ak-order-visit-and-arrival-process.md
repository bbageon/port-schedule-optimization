# YR-332-ak — 오더·차량 방문 단위 확인과 도착 몰림 보정

**상태**: done

등록: 2026-11-12, aj의 실제 오더 감사에서 확인한 현실성 차이의 후속이다.
- **3대 게이트 보정 대상**: scenario_validity(만든 입력이 실제 자료의 흐름과 맞는가).
신경망·보상·물리 장비를 함께 바꾸는 성능 가설이 아니다.

## 무엇과 왜

- 진입 오더 34,304건은 차량 식별값·진입 시각 기준 28,265묶음이다.
- 여러 오더가 있는 묶음은 5,505개, 해당 오더는 11,544건이다.
- 그중 반입과 반출이 함께 있는 묶음은 3,653개다. 다른 컨테이너 작업을 중복 삭제하지 않는다.
- 같은 날짜·시간대별 건수를 맞춰도 분별 몰림 지수는 오더 1.772 대 층화 대조 0.275다.
- 차량·시각 묶음으로 계산해도 1.281 대 0.330이다. 전체 물량 차이만의 결과는 아니다.
- aj의 시간대 보정은 24칸의 비중만 맞추며 분 단위 몰림·오더 연결은 구현하지 않는다.

## 먼저 정의를 확인

1. 제공 자료의 수집 범위와 `visit_id` 생성 단위를 확인한다.
   차량 식별값+동일 시각이 실제 한 방문인지는 아직 미확정이다.
2. 한 차량의 반입·반출이 함께 있을 때 관측 작업 순서와 실제 선후 제약을 구분한다.
   완료 순서만 보고 선행 작업을 의무화하지 않는다. 서로 다른 오더를 합쳐 없애지 않는다.
3. 진입 후 취소 210건(완료 기록 11건)의 취소 의미를 확인한다.
   수집·예약 정정 취소와 실제 작업 수요 취소를 구분하고 원자료 행은 보존한다.
4. 성과 지표가 오더별 진입→완료인지, 방문별 진입→연결 작업 전체 완료인지 명시한다.
   기존 오더 지표를 말없이 차량 지표로 바꾸지 않는다.

## 한 축씩 보정

1. 단위·연결 정의를 먼저 고정한다. 필요한 연결 계약 변경은 별도 전후 동일성 검사로 끝낸다.
2. 그다음 시간대별 총량·작업 구성·물리 조건·고정 정책을 유지하고 도착 간격 생성만 바꾼다.
   실제 날짜별 분포·군집 도착을 재현하는 최소한의 방법을 선택하고 난수를 사전 고정한다.
3. 날짜 간 변동, 반입/반출의 시간대 결합, 동일 방문 내 작업 관계를 한꺼번에 변경하지 않는다.
4. 같은 자료로 모형을 만들고 독립 검증했다고 주장하지 않는다. 이미 본 13일은 개발용이다.
5. 모델을 추가 학습하기 전에 오더 보존·컨테이너 공급·당시 공개 정보·같은 입력 재현을 확인한다.

## 완료 기준과 연결

- 방문·오더 단위, 누락·취소 처리, 확인된 관계와 미확정 관계를 기록한다.
- 같은 물량/시간대에서 도착 간격·분별 몰림·유형별 동시 유입을 자료와 대조한다.
- 보정 전후의 고정 정책 결과를 작업 유형·미완료 수와 함께 보고한다.
- i/f의 운반·대기열 의미는 별도로 확인하며 임의 숫자로 닫지 않는다.
- 환경 조건 확인 뒤 323-d의 학습 진단, 새 미사용 기간 확보 뒤 323-e의 최종 평가로 연결한다.
