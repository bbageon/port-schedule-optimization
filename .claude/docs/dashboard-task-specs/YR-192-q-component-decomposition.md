- **1줄**: YR-189 는 **기구 전체 대 기구 전체**를 잰다. 이득(또는 손해)이 **제안에서
  왔는지 배정기에서 왔는지**는 이 실험이 아니면 알 수 없다.

## 왜 필요한가

YR-189 의 `q` 팔은 두 곳을 동시에 바꾼다.

| | 제안(어느 작업을 낼까) | 배정기(어디로·언제) |
|---|---|---|
| `greedy` | 규칙 `UnifiedNetGain` | 계산식 `cost_given_queue` |
| `q` | **학습 Q** | **학습 Q** |

그래서 YR-189 결과는 "학습된 판매 기구가 규칙 판매 기구를 이긴다/못 이긴다"까지만
말할 수 있다. 사전등록 §5-1 이 이 한계를 실행 전에 못박았다.

[[YR-179]] 는 정확히 반대 설계였다 — 배정기를 고정해 제안 축만 분리했다.
그때 얻은 것이 "규칙이 학습보다 낫다"였다.

## 설계 (4팔 · 2×2)

| 팔 | 제안 | 배정기 |
|---|---|---|
| `RR` | 규칙 | 계산식 | ← YR-179 `greedy` 와 동일 |
| `QR` | **Q** | 계산식 |
| `RQ` | 규칙 | **Q** |
| `QQ` | **Q** | **Q** | ← YR-189 `q` 와 동일 |

`QR − RR` = 제안 축의 기여. `RQ − RR` = 배정기 축의 기여.
`QQ − QR − RQ + RR` = 상호작용(두 곳을 같이 바꿔야 생기는 몫).

**구현 부담은 작다** — `QSellPolicy` 와 `q_scorer` 는 이미 **독립 인자**다.
`UnifiedSellOrchestrator(policy=…, q_scorer=…)` 조합만 바꾸면 4팔이 나온다.
