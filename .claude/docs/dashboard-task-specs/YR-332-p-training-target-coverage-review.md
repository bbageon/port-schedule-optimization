# YR-332-p — 크레인 학습 표적·비교 표본 진단과 개선안 검토

- **상태**: backlog
- 실행 승인: 2026-11-05 사용자 6단계 실험의 4단계. 표본 선정은 [[YR-332-q]], 입력 추가는 [[YR-332-r]]로 분리.
- 사전등록: `docs/research/v7-discharge/six-step-prereg.md`.
- 등록: 2026-11-05. 사용자 요청: 기존 연구·상용 시스템·최신 기술을 검토, 재현율과 효과 우선.
- 상위: [[YR-332]], 연계: [[YR-332-c]]·[[YR-332-g]]·[[YR-332-o]]. 구현·학습은 미실행.
- 첫 실행 범위는 아래 표적·표본 진단이다. 새 학습법 채택은 진단과 연구 게이트 판정 후다.

## 현재 코드에서 확인한 사실

1. 기본 크레인 학습은 `crane/train.py`의 반사실 교사 경로다. v7의 다른 PPO 경로와 구분한다.
2. 하루 최대 64개 결정을 뽑고 선택 작업·다른 작업을 각각 기본 3시간 재생한다.
   비교 1건당 두 세계이며 재생 전에 터미널 복제가 있다. 실제 표본 수는 이보다 작을 수 있다.
3. 대안은 같은 mandatory 여부를 가진 실행 가능 후보 중 현재 정책이 가장 높게 평가한 다른 작업이다.
   `_labelable`은 크레인 ID 순으로 첫 비교 가능한 쌍을 반환한다. 다양성 부족은 가능한 위험이며
   편중 크기·학습 손실의 원인이라고 아직 실증하지 않았다.
4. `teacher.py`는 두 비용의 평균을 빼고 그날 격차 중앙값(하한 포함)으로 나눠 각 후보 표적을 만든다.
   `fit.py`는 두 표적을 개별 SmoothL1 회귀로 학습한다. 결정 단위 학습/검증 분리는 이미 있다.
5. 정책 입력은 후보별 9칸이다. 작업 네 흐름은 별도 표시하지 않고 본선 여부로 합친다.
   8번째 후보 수는 현재 트럭 대기열의 중복이다([[YR-332-g]]). 집합 간 관계 학습은 없다.
6. 현재 비용 경로는 `reward/phi.py`의 원화 네 항이다. v6 정규화 보상이 그대로 연결됐다고
   해석하지 않는다. 이번 검토로 비용 항·단가·가중치를 임의 변경하지 않는다.

## 첫 진단: 같은 작업의 표적이 상대에 따라 바뀌는가

같은 상태에서 설명용 비용 A=10, B=20, C=100이라면 A의 짝 중심 표적은
B와 비교할 때 -5, C와 비교할 때 -45이다(나누기 전). A의 입력이 같아도 답이 다르다.
이는 코드 수식의 성질이다. 실제 학습 실패의 지배 원인인지는 별도 측정해야 한다.

- 같은 상태·여러 대안에서 표적 충돌과 후보 입력 동일/근접 비율을 기록한다.
- 후보와 대안이 같아도 정보가 부족해 장기 비용을 구분 못 하는 경우를 분리한다.
- 비용 순위가 재생 지평을 늘려도 유지되는지 표본 진단한다. 두 가지를 같은 시각에 자른다고
  종료 경계의 행동 의존 편향이 항상 사라지는 것은 아니다.
- 비교 가지의 미래 오더·잡음은 같은 외생 사건 스트림을 사용한다. 정책은 실현 미래를 못 본다.

## 검토안 A: 두 작업의 차이를 직접 학습

[RankNet, ICML 2005](https://www.microsoft.com/en-us/research/publication/learning-to-rank-using-gradient-descent/)은
후보 쌍의 우열로 순위 함수를 학습하며 실행 때는 후보별 점수만 계산한다.
우리 적용안은 같은 상태의 `점수(A)-점수(B)`가 실제 비용 차이/우열과 맞도록 학습하는 것이다.
모든 후보 쌍을 실행 때 비교하는 구조로 만들 필요는 없다.

첫 대조는 같은 입력·표본·초기 망·계산 예산에서 **손실식만** 바꾼다.
현재 회귀, 비용 차이 회귀, 우열 순위 손실을 후보로 사전 지정하고 결과를 보고 조건을 바꾸지 않는다.
비용 크기를 쓰는 경우 정규화 통계는 학습 자료로 정하고 평가 자료로 맞추지 않는다.
비용 항의 정당성과 학습 숫자의 크기를 다루는 정규화는 별개다.
순위 손실의 개선도 입력에 필요한 정보가 없으면 제한된다.

## 검토안 B: 비교 예산을 정보가 있는 결정에 배분

[Rollout Allocation, ICML 2010](https://mohammadghavamzadeh.github.io/PUBLICATIONS/icml10-rollout.pdf)은
고정 재생 예산에서 상태·행동에 예산을 어떻게 나눌지가 학습 자료의 정확도에 영향을 준다고 보인다.
항만 실증은 아니다. 우리 적용안은 먼저 시간대·크레인·작업 종류·혼잡도별 표본 분포를 재는 것이다.
차선 후보만 보는 편중이 확인되면 동일 재생 예산 안에서 대안 선택을 넓히는 한 축 대조를 한다.
난수 시드를 고정한 층별 추출도 재현 가능하다. 어려운 표본만 선택하지 않고 대표 표본을 보존한다.
신뢰구간 기반 적응 배분은 잡음 구조를 먼저 확인한다. 같은 결정론적 세계 반복은 새 정보가 아니다.
라벨에는 당시 정책 버전·미래 입력·지평을 남긴다. 정책이 바뀐 뒤 옛 라벨을 무조건 섞지 않는다.

## 조건부 구조 후보 — 앞 진단과 동시에 변경하지 않음

- **가변 작업 집합 문맥**: 예정·게이트 후 이동 중·실행 가능 목록을 각각 요약하고 후보 점수와 연결한다.
  먼저 [[YR-332-g]] 오류를 수정한다. 입력 동일성 때문에 구분 불가한 사례가 남으면 작업 종류,
  준비 상태, 도착 예상의 불확실성, 본선 마감 중 필요한 축부터 한 번에 하나 추가한다.
  [Deep Sets](https://proceedings.neurips.cc/paper/2017/hash/f22e4747da1aa27e363d86d40ff442fe-Abstract.html)는
  가변 집합의 단순 기준이다. [Set Transformer, ICML 2019](https://proceedings.mlr.press/v97/lee19d.html)는
  집합 관계와 계산 절감을 다룬다. 전체 오더 간 모든 쌍 연결은 큰 목록에서 비싸므로 자동 채택하지 않는다.
- **PPO(경험으로 행동 확률을 갱신하는 강화학습)**: 분기 교사 없이 한 궤적의 경험으로 배우는 대안.
  [L2D, NeurIPS 2020](https://github.com/zcaicaros/L2D)는 공개 구현이 있는 작업 순서 학습 기준이다.
  분기 복제를 없애도 필요한 경험량이 늘 수 있어 총 학습시간 개선은 보장되지 않는다.
  비용 증가분으로 보상을 만들 때 불규칙한 결정 간 실제 경과시간과 끝에 남은 작업을 반영하고,
  누적 보상이 기존 목적과 일치하는지 대조한다. 이 변경은 손실식 변경과 별도 비교다.
- **최신 그래프 Transformer**: [HGT-Scheduler, 2026 사전공개 논문](https://arxiv.org/abs/2603.06777)은
  선후 관계와 장비 경합을 구분한다. 작은 제조 벤치마크에선 이득이 있지만 FT10·5만 단계에서는
  관계를 구분하지 않는 모델과 성능이 비슷했다. 본문에 코드 링크가 있으나 우리 환경에서 재현하지 않았다.
  최신·복잡하다는 이유로 우선 도입하지 않는다.
- **항만 직접 관련 사례**: [Wang 등, YC 실시간 배치 PPO](https://doi.org/10.1016/j.tre.2025.104635)는
  비동기 시점·정책 공유·전역/국소 정보를 사용한다(공개 초록 기준). 크레인의 블록 간 재배치 문제라
  고정 크레인의 다음 작업 선택인 우리 문제와 다르며, 보고한 개선율을 우리 기대 효과로 쓰지 않는다.

## 재현성·효과의 채택 기준

1. 후보 보존/정확성은 [[YR-332-o]], 현실 입력·용량은 [[YR-332-f]]·[[YR-332-i]]·[[YR-332-m]]과 대조.
2. 학습/모델 선택/최종 평가 입력을 분리한다. 같은 날짜의 기존 규칙·학습 전·학습 후를 짝비교한다.
3. 최소 개선량·실험 수·중단 조건·모델 선택법을 사전 고정한다. 기존 3초기값은 진단이며 확증 표본 수의 근거가 아니다.
4. 턴타임, 본선 지연/완료, 처리량·잔여를 각각 보고한다. 한쪽 미완료를 늘려 만든 평균 개선을 채택하지 않는다.
5. 라벨 오차만으로 운영 개선을 판정하지 않는다. 같은 학습 경험량과 같은 벽시계 예산을 각각 비교한다.
6. [Agarwal 등, NeurIPS 2021](https://arxiv.org/abs/2108.13264)에 따라 초기값·평가일의 변동과
   개선 구간을 보고한다. 한 궤적의 수천 결정을 독립 학습 반복 수처럼 세지 않는다.
7. 단계별 코드·설정·입력·모델·원자료 식별값을 보존한다. 실행 순서·병렬 수·라이브러리도 고정한다.

## 증거와 상태

현재 분석은 `crane/{collect,teacher,rollout,fit,features,train,policy}.py`를 읽은 검토다.
표적 충돌의 수학적 가능성 외에 후보별 원인 기여·새 학습 효과의 실측은 없다.
검토안 A/B/구조 변경을 합쳐 한 번에 실험하지 않는다. 실패 기제를 진단한 한 축부터 진행한다.
