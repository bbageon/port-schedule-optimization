# YR-319 — v5 붕괴 원인 분리: 고르는 방식만 되돌린다

- **상태**: in-progress
- 착수: 2026-09-22. 사용자 지시 — "진행해줘" (제안 평가 뒤 1·2단계 묶음 승인).
- 종류: **진단 (REMEDIATION)**. 성능 주장 없음. 새 가설 아님.

## 왜 하나

[[YR-306]] 세 정책 30일 비교가 2026-09-22 에 끝났다. 학습을 마친 정책을 고정해
돌리니 규칙보다 **172배** 비쌌고 트럭 177,500대 중 **62,075대**가 못 나갔다.

그런데 그 비교는 **한 번에 두 가지를 바꿨다**.

1. 가중치를 얼렸다 (학습 갱신을 껐다)
2. 행동을 **최고점만 고르게** 했다 (argmax — 학습 중에는 확률로 뽑는다)

두 변화가 같은 인자 `training=False` 하나에 묶여 있어서 **어느 쪽 탓인지 귀속이
안 된다.** 같은 가중치가 추첨이면 턴타임 중앙 26분으로 한 달을 거의 완주했고
(못 나간 트럭 48대), 최고점 선택이면 평균 110시간에 6만 2천 대가 갇혔다.

## 무엇이 이미 확인됐나 (착수 근거)

- **크레인 정책은 멀쩡하다.** 학습된 망에 합성 상태 225가지를 넣어 재 봤더니
  쉬기가 1등인 경우가 **0건**이었다. 실제 일감이 있으면 실작업 점수가 9.9,
  쉬기가 3.4로 크게 벌어진다. 관측된 쉬기 93%는 **고른 것이 아니라 남은 것**이다.
- **막힌 곳은 반출이다.** 30일 반출 완료가 규칙 10만 2천 건 대 학습 정책 5만 2천 건.
  야드 재고가 1만 3천에서 2만 5천으로 늘고, 본선 작업은 **30일 내내 완료 0건**이다
  (규칙은 양하 71,760·적하 44,400 완료).
- **두 축이 다르게 움직였다.** 추첨 대비 최고점 선택에서 공간 이동은
  17,023 → 49,890 으로 **세 배**가 됐는데 시간 이연은 94,691 → 91,410 으로 거의 같다.
  거래 실패는 0 → 8,236 건.

## 이번에 하는 일

### ① 고르는 방식을 학습 때로 되돌린 30일 1회

가중치·시드·30일 명단·화물·측정창을 [[YR-306]] 원본과 **같게** 두고
**행동 선택만 확률 추첨**으로 바꾼다. 학습 갱신은 계속 끈다.

- 코드: `PPORuntime` 에 `sample_actions` 를 추가해 `training` 에서 분리했다.
  기본값은 `training` 을 따라가므로 **기존 실행 동작은 그대로다.**
- 실행: `scripts/v5/eval_sampling.py` · 체크포인트 `final.pt` · 코어 1개.
- 산출물: `outputs/v5/yr319-sampling-final/`

### ② 거래 장부를 파일로 남긴다

다리(`stage/bridge.py`)는 거래마다 종류(공간/시간)·목적지·이연량·성공여부를
이미 메모리에 쌓고 있었는데 **파일로 쓰는 줄이 없었다.** 그래서 [[YR-306]] 의
거래 실패 8,236건이 공간인지 시간인지 가를 수 없다. 한 줄 추가해 덤프한다.

- 산출물: `trade-ledger.jsonl.gz` + `report.json` 의 `trade_ledger` 집계.

## 사전등록 (결과를 보기 전에 고정)

### 중단 규칙

어느 날이든 **그날 코호트 평균 턴타임**(게이트아웃 − 게이트인, 그날 끝에서 검열)이
같은 날 규칙 팔의 **3배를 넘으면 즉시 중단**하고 `diverged` 로 기록한다.

근거 — 실측:

| 실행 | 규칙 대비 최대 배수 | 3배를 처음 넘는 날 |
|---|---|---|
| 학습 중 (추첨) | 1.95배 | 없음 (완주) |
| 학습 후 고정 (최고점) | 20.65배 | 3일차 |
| 학습 전 고정 (최고점) | 19.22배 | 1일차 |

건강한 실행은 안 죽이고 무너지는 실행은 사흘 안에 끊는다. [[YR-306]] 은 이미
무너진 실행 하나에 **131시간**을 태웠다 — 1일차에 답이 나와 있었는데도.

기준선은 규칙 팔 산출물의 30개 값을 스크립트에 박고, 실행 시작 때
원본 파일의 sha256(`036365aa…`)과 대조해 표류를 막는다.

### 판정

성과지표는 사용자 지정대로 **턴타임(게이트아웃 − 게이트인)** 하나다.

- **A 가설 (고르는 방식이 원인)**: 추첨 팔이 30일을 완주하고 턴타임이 규칙의
  2배 이내면 지지. → 172배는 정책 품질이 아니라 **운영 방식**의 산물이다.
- **B 가설 (가중치가 원인)**: 추첨 팔도 3배 규칙에 걸려 중단되면 지지.
  → 고르는 방식은 무관하고 학습된 가중치 자체가 나쁘다.
- 둘 사이(완주했으나 2~3배)면 **미확정**으로 남기고 표본을 늘리지 않는다.

### 하지 않는 것

- 성능 주장. 학습에 쓴 명단을 다시 쓰는 진단이고, 시드 9900306 은 이미 전부
  열람한 진단 대역이다. 미완료 작업도 0이 아니다.
- 유의성 검정. 한 달을 이어 돌린 1회 실행이라 28일이 독립 표본이 아니다.
- 결과를 보고 표본·조건을 늘리는 것.
