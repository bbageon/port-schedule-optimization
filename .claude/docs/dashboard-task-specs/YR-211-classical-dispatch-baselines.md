# YR-211 — 고전 배차 규칙 대조군 — 재배치 축으로 번역

- **Epic**: Exp / **Priority**: 🔴 / **등록일**: 2026-08-20 / **상태**: 🟢 **구현 완료 2026-08-25** (판정 미실시)
- **3대 게이트 보정 대상**: `performance`
- **사용자 지적 2026-08-20**: *"`greedy` 를 규칙이라고 하기엔 애매하다. RL 성능을
  비교할 때는 No Reallocation · FCFS · SPT · EDD/Least Slack · Nearest 와
  비교하는 게 맞다."*
- **1줄**: 지금 유일한 비교 상대인 `UnifiedNetGain` 은 **우리 비용식에서 유도한
  자체 휴리스틱**이다. 표준 배차 규칙군을 재배치 축으로 번역해 대조군을 세운다.

## 왜 필요한가

`UnifiedNetGain`(현행 `greedy`)의 문제는 성능이 아니라 **위치**다.

| | |
|---|---|
| 무엇인가 | `J(현 계획) − J(대안) − 전환비용 − 여유 > 0` 이면 판다 |
| 어디서 왔나 | **우리가 정의한 비용함수 `J` 에서 직접 유도** |
| 왜 애매한가 | 우리 목적함수를 그대로 쓰는 상대라 **순환적**이다. 문헌에 없는 이름이고, "RL 이 이 하나를 못 넘었다"는 문장은 **일반화되지 않는다** |

표준 규칙군과 견주면 세 가지가 생긴다.

1. **인지 가능한 좌표계** — 독자가 아는 이름으로 성능 위치를 말할 수 있다
2. **강건성** — 여러 규칙을 일관되게 넘어야 진짜다(하나짜리 대조는 스트로맨 의심)
3. **서사 B 보강** — "재배치 메커니즘의 가치"가 **배차 규칙과 무관하게** 나오면 훨씬 강하다

## ★번역이 필요하다 — 배차 규칙 ≠ 재배치 규칙

나열된 규칙은 전부 **"다음에 어느 작업을 처리할까"**(sequencing)를 정한다.
우리 학습 축은 **"어느 블록으로 / 언제"**(assignment)다. 결정 대상이 다르다.

또 재배치는 **결정이 둘**이다 — *누구를 옮길지* 와 *어디로 보낼지*. 고전 규칙
대부분은 앞의 것만 답하므로 **목적지 규칙을 짝지어야** 한 팔이 완성된다.

| 팔 | 원래(배차) 뜻 | 재배치 축 번역 | 누구를 | 어디로 |
|---|---|---|---|---|
| **No Reallocation** | — | 최초 배정 유지 | — | — |
| **FCFS** | 먼저 들어온 작업 | **먼저 통지된 트럭**부터 기회 | 통지 시각 오름차순 | Least-Loaded |
| **SPT** | 가장 빨리 끝나는 작업 | **작업시간 짧은 트럭** 우선 | 예상 작업시간 오름차순 | Least-Loaded |
| **EDD / Least Slack** | 가장 급한 작업 | **SLA 여유 최소** 트럭 우선 | `마감 − 예상완료` 오름차순 | Least-Loaded |
| **Nearest** | 이동이 가장 짧은 작업 | **주행 증가 최소** 목적지 | (트리거된 전건) | 최근접 가용 블록 |
| `NetGain`(현행) | — | 순이득 최대 | 순이득 내림차순 | 순이득 최대 목적지 |
| **Proposed RL** | — | 상태 기반 장기 누적비용 최소 | 학습 | 학습 |

### 고전 규칙에 없는 것 — "언제 옮길까"

배차 규칙은 **항상 뭔가를 처리**한다. 재배치는 **안 옮기는 것이 기본**이라 트리거가
필요하다. 트리거를 팔마다 다르게 두면 비교가 무너지므로 **공통으로 고정**한다.

```
트리거: 출발 블록의 공개 예상 대기(public_queue_at)가 상위 k% 일 때만 후보 생성
        k 는 착수 시 동결. NetGain·RL 도 같은 트리거 아래서 돈다.
```

**트리거 없이 전건을 후보로 두면** 고전 규칙들이 무차별 재배치를 해서 실제보다
훨씬 나빠 보인다 — 공정한 대조가 아니다.

### SPT 는 판별력이 거의 없을 수 있다

우리 무대의 서비스 시간은 기준 180초로 사실상 상수다(20ft/40ft 차이 정도).
**그래도 팔에 넣는다** — "이 무대에서는 SPT 가 무의미하다"도 보고할 결과다.
결과를 보고 빼지 않는다.

## 선행·관계

- **선행**: [[YR-210]] — 재배치 축이 유효한 부하 구간을 먼저 안다.
  과포화에서 재배치 자체가 무가치하면 대조군을 세워도 전부 `No Reallocation` 에 진다.
- **기존 자산**: `integrated/baselines.py` 에 `FIFOPreference`·
  `ServiceFirstSPTPreference` 가 있으나 **크레인 층 전용**이고 FIFO 는 미래정보
  누출로 진단 전용이다([[YR-107]]). 재배치 축은 새로 짜야 한다.
- **정보 경계**: 모든 고전 팔도 **공개 정보만** 쓴다. 통지 시각·공개 ETA·현재
  내부 대수만. 실현 도착·실현 완료 열람 금지 — FIFO 의 누출을 반복하지 않는다.

## 금지

- 결과를 보고 팔을 빼지 않는다(SPT 가 무의미해도 보고한다).
- 트리거 `k` 를 팔마다 다르게 두지 않는다. 결과를 보고 바꾸지 않는다.
- 학습 팔이 이긴 부하만 골라 보고하지 않는다 — 세 부하 전부 적는다.

### ★설계문서와 다르게 한 것 셋 — 전부 명시한다

**① 트리거를 고전 팔에만 건다.** 06b 는 *"NetGain·RL 도 같은 트리거"* 라 했으나
v3 의 RL 은 **`KEEP` 을 스스로 고를 수 있어** 트리거가 필요 없고 이미 그 없이
학습됐다([[YR-222]]·[[YR-230]]). 지금 걸면 재학습이 필요하고 [[YR-229]] 비교도 깨진다.
→ 이 방향은 **고전 팔에 유리**(무차별 재배치를 막아 준다)하므로 **우리 주장에 보수적**이다.

**② `SPT` 는 이 무대에서 판별력이 없다.** 코드로 확인: `Order` 에 작업시간 필드가
없고, 엔진의 서비스 시간은 **기하학**(갠트리·트롤리 주행)이며 컨테이너 규격은
**적치 슬롯 탐색에만** 쓰인다. 야적 좌표를 읽으면 기하 SPT 를 만들 수 있으나 그러면
**SPT 가 RL 보다 많은 정보**를 보게 되어 비교가 반대로 기운다 — 정보 계층을 맞췄다.
⚠️ **팔에서 빼지 않는다** (사전등록: *"무의미하다도 보고할 결과"*).

**③ 고전 팔은 공간 이동만 한다.** 번역표의 목적지가 전부 블록이라 시간 이연에
대응물이 없다. **RL(공간+시간) vs 고전(공간만)** 의 행동 폭 차이가 남는다 —
이겼을 때 *"구조가 좋아서"* 인지 *"고를 게 많아서"* 인지 안 갈린다.
→ **논문에 명시**하고, 필요하면 **RL 공간 전용 진단 팔**을 따로 돌린다.
