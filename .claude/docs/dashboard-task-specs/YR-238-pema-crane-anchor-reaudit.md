# YR-238 — PEMA 크레인 서비스시간 앵커 재감사

- **Epic**: Infra / **Priority**: 🔴 / **등록일**: 2026-08-27 / **상태**: backlog
- **3대 게이트 보정 대상**: `scenario_validity`와 Dashboard↔증거 정합
- **1줄**: PEMA IP15에 없는 `120~180초` 직접 인용을 걷어내고, 검증 가능한 문헌과
  시뮬레이션 런 실측만으로 크레인 서비스시간 앵커와 현실성 판정을 다시 계산한다.

## 발견

YR-158·`configs/anchors/external_anchors_v1.json`은 PEMA IP15 7.4절이
`2~3분/사이클`을 직접 제시했다고 기록한다. YR-237에서 공식 PDF를 다시 대조한 결과,
IP15는 고정 범위를 제시하지 않고 이동 종류·자동화 지연·외부차량·다중 크레인 간섭을
포함한 시나리오별 성능 정의를 요구한다.

한편 Farashahi, Wu, Tatham(2015)은 야드 크레인 취급시간에 삼각분포
`(1.2, 2.0, 3.4)분`을 **가정**한다. 이는 `180초`가 학술모형의 범위 안이라는 보조
근거이지, 부산항 또는 PEMA의 실측 능력 증거는 아니다.

## 할 일

1. PEMA PDF의 관련 절과 표를 페이지 단위로 다시 대조한다.
2. 등록부의 모든 크레인 시간 출처를 원문·정의·단위별로 분리한다.
3. 시뮬 런 실측 `146.7~147.3초`가 검증된 외부 범위 안인지 다시 판정한다.
4. YR-158 spec·done row·등록부·게이트 산출물에 정정 이력과 새 판정을 같은 커밋으로 남긴다.

## 완료 조건

- PEMA에 없는 숫자를 PEMA 직접 근거라고 쓰는 곳이 0건이다.
- 외부 범위의 각 숫자에 원문 위치와 `실측/가정/유도` 등급이 있다.
- `scenario_validity`를 같은 코드로 재계산하고 PASS 또는 FAIL을 결과대로 보존한다.
- 정책 성능은 실행하지 않는다.
