**[[YR-200]] 이 가설을 반증했다** — 판매량을 규칙과 맞춰도(B: 공간 718 vs 687)
졌고, 오히려 **가장 적게 판 C 가 가장 나았다.** 판매량이 아니라 **선택의 정확도**가
문제이고, [[YR-199]] 가 그 정확도의 한계를 이미 쟀다(오차의 95%가 못 줄이는 잡음).

## 진짜 원인 — 목적함수의 시야가 40분이다

지금 보상 `D_i` 가 세는 것:

```python
occupy = job_done − service_start      # 크레인이 그 트럭에 쓴 시간
own    = gate_out − gate_in            # 그 트럭의 체류
blocked_dst = 그 순간 dst 에서 기다리던 트럭 수
```

**전부 "그 트럭 한 대의 방문"(약 40분) 안에서만** 잰다. 에피소드는 24시간이다.

**놓치는 것**: 그 배치가 만들 재취급 · 이후 트럭들의 추가 대기 · 그 컨테이너를
나중에 꺼낼 때의 비용.

그리고 **규칙도 근시안이다**(`sell_gain` = 지금 순이득). 그래서 **RL 에게 구조적
우위가 없다** — 같은 질문에 규칙은 공식으로, RL 은 근사로 답하니 근사가 진다.

## 왜 시야를 못 늘렸나 — 그리고 구매가 어떻게 푸나

**[[YR-170]] 에서 하루 총비용을 보상으로 줬다가 실패했다.** 21블록이 같은 60초에
동시에 결정하는데 결과가 하나로 뭉쳐 나와 귀속이 안 됐다 — **행동 귀속 분산
0.0000038**. 그래서 "그 거래 하나의 손익"으로 좁힌 것이 지금 설계다.

| | 신용 배분 | 시야 |
|---|---|---|
| 하루 총비용 보상 | ❌ | ✅ |
| 지금 (거래별 손익) | ✅ | ❌ 40분 |
| **구매 구조** | **✅** | **✅** |

**기전**: 블록 B 가 작업 j 를 **사면**, 그 뒤에 일어나는 일이 **전부 B 의 장부에
찍힌다** — j 처리로 묶인 크레인, j 때문에 더 붐벼 밀린 트럭들, j 가 만든 재취급,
18시에 j 를 찾으러 온 트럭. **전부 B 가 산 결과이고 B 에서 측정된다.**
다른 20블록의 결정과 안 섞인다.

> **자기가 산 것의 결과만 자기 앞으로 달면, 시야를 늘려도 신용이 안 흐려진다.**

## 비용식

```
C_buy(B, j) = [ B 가 j 를 떠안아 앞으로 치를 것 ] − [ j 를 가져와 생기는 가치 ]

앞으로 치를 것 =  처리시간 × 그동안 B 에서 밀린 트럭 수
                + 본선 압력 (ρ=10)
                + ★j 가 만들 재취급
                + ★j 때문에 B 가 붐벼 이후 트럭이 더 기다린 것
                + ★j 를 나중에 꺼낼 때의 비용

가치 = 원래 블록 A 가 던 부담  (= 지금의 R_src — 터미널 관점에서 옳은 값)
```

★ 셋이 지금 없는 것이고, **구매 관점에서는 자연히 들어간다** —
"내가 떠안으면 뭘 감당해야 하나"를 세면 당연히 포함되므로.

**명시적 가격 `P_j` 는 도입하지 않는다.** 내부 전송가격은 제로섬이라 터미널
비용을 줄이지 않고, 가치는 `R_src` 로 계산하는 것이 옳다
([보상 재검토](../strategy-history/2026-08-19-보상설계-재검토-매수매도-시장.md) §2-①).

## ★단계별 진행 — 위험이 크다

미래를 넣으면 **라벨이 시끄러워져 [[YR-199]] 잡음 하한이 올라갈 수 있다.**
목적함수는 정확해지는데 학습은 어려워지는 맞바꿈이다.

| 단계 | 무엇 | 검증 |
|---|---|---|
| **0** | 재취급 예상 비용만 라벨에 추가 | **잡음 하한 재측정**(20분·학습 불필요) |
| 1 | 하한이 비슷하면 → 이후 혼잡 항 추가 | 다시 하한 측정 |
| 2 | 하한이 비슷하면 → 반출 시점 비용 | 다시 하한 측정 |
| 3 | 결정 구조를 매도 → 매수로 | 배정기 재작성 |
| 4 | 재학습·재판정 | 약 4시간 |

**각 단계마다 하한이 크게 오르면 거기서 멈춘다.**
**학습 불가능한 정확한 목적함수는 쓸모가 없다.**

## 하지 않는 것

- 0~2 단계를 건너뛰고 바로 구조를 바꾸는 것.
- 잡음 하한 선측정 없이 학습부터 돌리는 것.
- 명시적 가격·경매를 도입하는 것 — 중앙 배정기가 이미 전역 최소를 직접 계산한다.
- 이 변경으로 [[YR-170]] 이후 판정과의 비교가 끊긴다는 사실을 숨기는 것 —
  **새 대조군이 필요하다.**

## ★[[YR-204]]·[[YR-205]] 와의 관계 (2026-08-19 정리)

다른 세션이 등록한 로드맵이 **같은 문제를 더 완성도 높게** 푼다.

| | 무엇 | 이 문서와의 관계 |
|---|---|---|
| [[YR-203]] | 재배정 1회 못박기 · 동시유입 배치 공동배정 | 계약 정리 — 여기 없던 것 |
| **[[YR-204]]** | **학습 때만 장기 반사실 rollout** 으로 교사 라벨 생성 | **여기서 못 푼 "시야 vs 신용" 을 정면으로 푼다** |
| [[YR-205]] | 그 라벨을 Seller·Buyer 모델이 근사 · 운영은 즉시 추론 | **이 문서의 구매 구조가 여기 흡수** |

**YR-204 가 더 나은 이유**: 이 문서는 "구매 관점으로 바꾸면 미래가 자기 장부에
찍히므로 귀속이 깨끗하다"는 **구조적 논증**이다. YR-204 는 아예 **미래를 실제로
굴려서** 교사 라벨을 만든다 — 논증에 기대지 않고 측정한다. 그리고 rollout 을
**학습 때만** 쓰므로 운영 비용이 안 든다.

**이 문서에서 살아남는 것**: §"왜 시야를 못 늘렸나"의 [[YR-170]] 실측
(행동 귀속 분산 0.0000038)과 40분 시야 진단은 YR-204 의 **동기 근거**로 유효하다.
