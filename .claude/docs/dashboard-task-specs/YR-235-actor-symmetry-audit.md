## 2. ★A8 — 사용자 지적이 만든 항목

> *"Buyer 가 보는 창은 Seller 가 보는 창이랑 같아야지. 그래야 Seller 가 제안한
> 시간대에 Buyer 가 검토를 하지 않나"* (2026-08-26)

맞다. 지금은 이렇다:

```
Seller  bf = block_features(mbt, src, t)                    ← 지금
        af = arrival_pressure(mbt, src, eta+defer, ±30분)   ← ★제안 시각
Buyer   bf = block_features(mbt, own, t)                    ← 지금
        of = slot_load(그 칸, ±7.5분)                        ← 제안 시각 (오늘 넣음)
```

**같은 시각을 보긴 하는데 잣대가 2배 다르다.**

### ⚠️ "블록의 미래 상태" 는 아무도 모른다

미래 시각으로 블록 9칸을 계산할 수는 없다 — `inside_count` 는 `gate_in ≤ t` 인
트럭만 세므로 미래엔 거의 0 이고, 크레인 밀린 일은 음수가 된다. **시뮬레이터도
미래 상태를 모른다.** 미래에 대해 공개 정보로 알 수 있는 것은
**"그 시각에 오기로 통지된 물량"** 하나뿐이다.

## 3. 채택안 — **A** (사용자 결정)

**Buyer offer 특징에 `arrival_pressure`(±30분) 를 더한다.** 19 → **20칸**.

| 왜 A 인가 | |
|---|---|
| 대칭이 맞는다 | v3 주장이 *"독립 행위자 둘"* 인데 한쪽만 넓게 보면 대칭이 아니다 |
| **`defer_s` 를 따로 안 넣어도 된다** | 도착 압력이 *"언제 떨어지나"* 를 이미 담는다 → **A3 해결** |
| 검증된 재료 | `announced_around` · 정보 경계는 [[YR-230]] 에서 확인 |
