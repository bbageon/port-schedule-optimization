# YR-327 — 학습 기계 손보기: 저장할 가중치를 고르고, 정책을 굶기지 않는다

- **상태**: backlog
- 파생: [[YR-319]]·[[YR-324]] 원인 조사 (2026-09-22).
- 종류: 학습 절차 수정. 두 축이라 **따로 돌린다**.

## 축 A — 배포용 가중치를 고르는 절차가 없다

지금은 **학습이 끝난 날의 가중치를 그냥** 쓴다(`ppo/continuous.py:111` — 선택 기준 없이
마지막 상태를 `final.pt` 로 저장). 그런데 학습은 **수렴한 적이 없다**: 가중치가 마지막
5일에도 하루 3.5~7.9%씩 움직였고, 이는 7~11일차의 3.0~18.1%와 같은 수준이다.

즉 지금 "실패한 정책" 이라 부르는 것은 **떠도는 궤적에서 임의로 뽑은 한 점**이다.
하필 30일차는 쉬기 66.5%·본선 유휴비 규칙 대비 3.29배로 **3,500 부하 여덟 날 중
가장 나쁜 날**이었다.

디스크에 `day_01.pt` ~ `day_30.pt` 29개가 더 있는데 **한 번도 안 재 봤다** —
평가 스크립트가 아는 체크포인트는 `final`·`initial` 둘뿐이다(`scripts/v5/eval_sampling.py:46`).

**할 일**: `CHECKPOINTS` 목록을 넓히고(약 15줄) `day_05.pt`·`day_15.pt` 를 얼린 추첨으로
각각 굴린다. 체크포인트는 이미 디스크에 있다. 팔당 2~3시간·코어 1개.

**사전 해석(결과 보기 전 고정)**: 중단일을 D5·D15·D_final(=7)로 두고
D5 > D15 > 7 이면 **후반 갱신이 망가뜨렸다**, 셋이 ±2일 안이면 **얼리는 행위 자체가 문제**다.

## 축 B — 정책이 11일 동안 얼어 있었다

가치망 가중치가 33.6배 커지는 동안(0.578 → 19.93) **정책은 2~11일차 내내 사실상
안 움직였다** — 이동량 중앙값이 1e-8 대로, 한도 0.03의 약 100만분의 1이다.
12일차에 가치망이 처음 커지기를 멈추자(14.97 → 14.47) **바로 그날부터** 정책이
움직이기 시작했다(0.72 → 0.83 → 1.70).

의심되는 구조: 몸통 하나를 정책과 가치가 같이 쓰는데(`ppo/model.py` 의 `trunk`),
가치망이 감당 못 할 목표를 쫓느라 몸통을 독차지했다. 가치망은 **1시간치 자료로
17시간 앞을 예측하라**는 요구를 받는다 — 감가율 0.999/분이면 유효 지평이 약 1,000분인데
갱신 한 번이 보는 창은 60분이다(`ppo/runtime.py:26,29-31`).

⚠️ **기울기 자르기가 정책을 굶겼다는 설명은 기각됐다** — 조사에서 확인했다.

**할 일 (싼 것부터)**:
1. `update.py` 에 정책 경로와 가치 경로의 기울기 크기를 **따로 한 줄씩 기록**하고
   2~3일만 재현한다. 비율이 100배 이상이면 확정이다.
2. 확정되면 몸통을 정책용·가치용으로 나누거나 `value_coef` 를 1/100 로 낮춘 팔을
   같은 시드로 2~3일 굴린다. 정책 이동량이 2일차부터 1e-3 대로 올라오면 인과가 닫힌다.

## 주의

축 B 는 학습기를 바꾸는 일이다. 한 번에 한 축.
