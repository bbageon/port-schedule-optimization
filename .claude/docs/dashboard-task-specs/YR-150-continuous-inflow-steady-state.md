# YR-150 — 지속 유입 정상상태 시험 (도착률 고정 · 재공량 자유 · 관측시간 종료)

- **Epic**: Exp / **Priority**: 🔴 / **등록일**: 2026-08-05 / **재정의**: 2026-08-05(30차)
- **상태**: backlog — YR-151 0A(기술 계약 검사) 뒤 착수
- **3대 게이트 보정 대상**: `scenario_validity` 하나 — 착수 전 YR-153 `authorize-next` 통과 필수
- **★재정의 2회**
  - (1차) **고정 재공량(WIP 제어) 폐기** — 터미널 안 트럭 수를 일정하게 유지하면 빨리
    처리하는 정책이 트럭을 더 받아 **정책별 입력량이 달라진다**(공정 비교 파괴).
    **외부 도착률을 고정**하고 재공량은 **결과 지표**로 둔다.
  - (2차·30차) **비우기 구간은 본 성능시험의 필수 요소가 아니다.** 사전 지정한
    **관측시간에서 작업 완료 여부와 무관하게 종료**하고, 성능은 **반복 스냅샷·구간 집계**로
    잰다. 완주 가능성 감사가 필요하면 **별도 복사본**에서만 확인한다.
  - [결정 문서](../strategy-history/2026-08-05-지속유입-정상상태-시험-전환-사용자결정.md)

## 질문과 지위

- 질문: "트럭이 **계속 도착하는** 정상상태에서 Block Policy 와 TransferResolver 가 규칙보다
  **시간당 비용을 낮추고 대기·재공량을 안정적으로 유지**하는가?"
- **본 성능시험**이다. YR-149 5셀(4h 유입→2h 비우기)은 **유한 물량 처리·회복 시험**으로
  분리 보존한다 — 그 구조는 "쌓인 물량을 얼마나 빨리 비우는가"를 잰다.
- 실제 TOS 연동 제외. 작업저장소는 합성 입력 스냅샷이며 실제 도착·주행·완료는 발생 전
  비가시 실현값이다.

## 실행 구조 (동결 대상 — 착수 시)

```text
warm-up  →  [ 측정 구간: 트럭·본선 계속 유입 · 5~10분마다 상태 스냅샷 ]  →  관측시간 종료
                        └ 여러 개의 1시간/4시간 구간으로 성능 집계
(선택) 별도 복사본에서만 비우기까지 돌려 완주 가능성 감사 — 성능비용에 섞지 않음
```

1. **트럭은 관측시간 종료까지 계속 도착**한다(현 생성기는 `horizon` 안에서만 도착 생성 후
   `drain` — 계약 변경 필요).
2. **50·75·100·125·150 은 총량이 아니라 4시간당 도착 강도**(시간당 약 12.5·18.75·25·
   31.25·37.5 대)로 재정의한다.
3. **모든 정책군이 동일한 도착 흐름**(같은 master stream)을 쓴다.
4. **5~10분 간격 상태 스냅샷**을 남기고, 성능은 **여러 개의 1시간/4시간 구간 평균**으로
   집계한다(구간 간 변동으로 정상상태 도달 여부도 함께 본다).
5. **관측시간에서 종료**한다 — 진행 중·미완 작업이 남아도 그대로 종료하고 장부에 남긴다.
   미완을 제외하지 않는다.
6. **본선 작업도 관측창 전체에 분산**한다 — 후반부가 트럭 전용 실험이 되지 않게 한다.
7. 재공량(A≤t<O)은 **제어하지 않고 측정**한다. 목표 밴드·즉시 재충전·입문 보류 없음.

## 평가계약 (★30차 정정 — 주지표 교체)

지속 운영 시험에서는 "완료 트럭당 비용·처리량 증가"를 주지표로 쓰지 않는다. **미완 작업의
불리함을 반영하지 못할 수 있기 때문**이다. 주지표는 다음으로 고정한다.

| 구분 | 지표 |
|---|---|
| **주지표** | ①**시간당 누적 v2 비용** ②**시간가중 재공량·대기열** ③**backlog 증가 기울기** ④**평균 A→O** ⑤**본선 시간당 지연비용** |
| **안정성 조건** | **처리량** — "더 높아야 한다"는 성능 조건이 아니라 **유입률을 감당하는지** 확인하는 조건(처리량 < 유입률이면 그 셀은 용량 초과) |
| **보조 보고** | YC 가동률, 이송/route 비용, 안전장치 개입률, 구간 간 변동, P95(보고만) |

- 미완·검열 표본을 제외하지 않는다. raw 에피소드 총비용은 판정에 쓰지 않는다(노출 차이).
- **정상상태 도달 판정**: 측정 구간 후반부에서 재공량·대기가 발산하지 않아야 한다.
  발산하면 그 셀은 **용량 초과**로 분류하고 비용 판정 대신 처리량·backlog 기울기만 본다.

## 엔진 선결

1. 유입이 관측창 전체에 걸쳐 발생하도록 시나리오 생성 계약 확장
   (현 `horizon`+`drain` → warm-up/측정/관측종료 계약).
2. 본선 process 를 관측창 전체에 분산 배치(현재는 앞쪽 집중).
3. **5~10분 간격 스냅샷 훅**과 구간별 장부(비용 적분·검열·구간 경계 처리).
4. 동일 master job stream 을 정책군이 공유. owner/version/rollback·TransferResolver
   원자성은 현 계약 유지.
5. 결정론·사건 순서·미래정보 누출 0·구간 경계 장부 항등을 테스트로 고정한다.

## 실험 사다리

0. **엔진 계약 파일럿**: 정책 없이(SF) 도착 흐름·스냅샷·구간 집계·정상상태 도달 여부만
   확인. warm-up 길이·측정 구간·관측시간을 결과 열람 전 동결한다.
1. **정책 비교**: `SF-SPT / PPO C0 / PPO C0 + 계산견적 TransferResolver` — 블록 내부 정책
   이득과 블록 간 이송의 추가 이득을 분리한다. learned SELL 은 YR-151 통과 뒤 별도 군.
   안전장치 ON/OFF 는 섞지 않고 별도 열로 보고한다.
2. **독립 확증**: 파일럿과 겹치지 않는 시드뱅크·정책 간 동일 master stream·계층형 짝지은
   신뢰구간. 표본 수는 파일럿 MDE 로 사전 동결·top-up 금지.

## 되돌릴 조건

- 정상상태에 도달하지 못하는 셀은 용량 초과로 분류(비용 판정 제외).
- 지속 유입 구조에서 이송 효과가 없으면 TransferResolver 군은 닫고 SF/PPO 의 정상상태
  처리능력 진단으로 범위를 축소한다.
