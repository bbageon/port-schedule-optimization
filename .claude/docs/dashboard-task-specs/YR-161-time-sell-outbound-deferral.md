# YR-161 — 반출 "시간 판매"(재예약 요청) 행동 확장

- **Epic**: RL / **Priority**: 🟠 / **상태**: **backlog** / **등록**: 2026-08-08 (사용자 제안 검토)
- **한 줄**: 반입(SELL = 목적지 변경)과 대칭으로, **반출 트럭에는 "다른 시각에 와 달라"는
  재예약 요청**(시간 축 판매)을 행동으로 준다. 1차 실험은 **기사 100% 수락 가정**.
- **★판매 축 확정 (사용자 결정 2026-08-08)**: **반입 = 공간 · 반출 = 시간 · 양하·적하 =
  판매 제외**. 적하 제외 사유 = 본선 지연 직결·기사 없음·기존 크레인 행동과 중복.
  양하 시간축도 같은 이유. 양하 **공간축**은 원리상 유효하나(박스를 어느 블록에 쌓을지는
  선택) 반입 실증·블록 간 양하 운반 배선 전에는 열지 않는다 — 확장 후보로만 보존.
  이 결정으로 검토 단계에 만들었던 **적하 embargo 기술 계층은 제거**했다(정책에 편입되지
  않는 계층을 코드에 남기면 대시보드↔코드 정합이 깨진다).

## 제안 원문 요지 (사용자 2026-08-08)

블록 PPO 의 판매 요청을 반입·양하만이 아니라 **트럭 반출·적하**에도 연다. 반출·적하의
판매 = "지금은 작업이 오래 걸리니 다른 시간을 예약해서 들어와 주세요" — 이번 연구에서는
모든 기사가 수락한다는 기준으로 실험한다.

## 검토 결과 — 전제 정정 1건 + 타당성

**전제 정정**: 현재 코드의 판매 대상은 **반입(GATE_IN)뿐**이다. 양하는 포함되어 있지
않고, YR-151 계약 5항이 "**양하 확대 금지**"를 명시한다(`reassignable` =
`flow == GATE_IN` — `multiblock.py`). 반출·적하가 공간 판매(목적지 변경)에서 빠진
이유는 구조적이다 — **컨테이너가 이미 특정 블록에 물리적으로 있으므로** 트럭·본선은
그 블록으로 갈 수밖에 없다.

**제안의 핵심 가치**: 반출은 목적지를 못 바꾸지만 **시각은 바꿀 수 있다**. 즉
- 반입 = **공간 축** 판매(어느 블록으로) — 기존 설계
- 반출 = **시간 축** 판매(언제 올지) — 본 제안. 실제 항만의 VBS 재예약 관행과 대응.

커버리지 논거가 강하다: 현 계약 `gate_out_share = 0.6` — **트럭의 60%가 반출**이라
공간 판매만으로는 물량의 40%만 정책 대상이다. 시간 축을 열면 나머지 60%가 열린다.

고정 WIP 계약과의 결합도 자연스럽다: 이연된 트럭 자리에 컨트롤러가 다른 트럭을
투입하므로, 시간 판매의 실효 = **"지금 어느 블록행 트럭을 받을지"의 순서 선택**
(블록 간 부하 균형을 시간축으로 달성 — 공간 판매와 상보적).

## 필수 계약 (이것 없이는 착수 금지)

1. **이연 비용 은닉 금지 — 최대 위험**: 100% 수락 + 이연 비용 0 이면 정책이 트럭을
   무한정 미뤄 혼잡을 장부에서 지워버린다(YR-052/119 WAIT 퇴화의 재판). **비용 원점은
   최초 통지(원 예약) 시각으로 보존**하고, 이연량 Δ 를 기사 외부 대기와 등가의 비용으로
   계상한다. 이연 횟수·총량 상한(이송 1회 상한과 대칭·엔진 fail-closed).
2. **100% 수락은 D5 가정으로 박제**: 실제 수락률·보상 비용은 Level 3 자료 없이 알 수
   없다 — 주장 범위를 "전원 수락 가정 하의 상한 효과"로 한정.
3. **선결 = 사전 통지 lead>0 설계**: walk-in(lead 0)에서는 진입 전에 요청할 창이 없다.
   공간 판매 0B 와 같은 선결이므로 **lead 설계는 한 번만 해서 두 축이 공유**한다.
4. ~~적하는 1차에서 제외 권고~~ → **적하·양하 제외 확정 (사용자 결정 2026-08-08)**:
   ①기사가 없어 재예약 서사가 성립하지 않고 ②적하 시점 선택은 기존 크레인 행동(작업
   순서·DEFER)이 이미 갖고 있으며 ③이연이 본선 마감(ETD) 지연으로 직결된다.
5. **단일축 원칙**: 공간 판매(0B-H)가 미실증 상태다. 시간 축을 같은 학습에 동시 투입하지
   않는다 — 공간 축 실증 후 별도 축으로 학습·판정(순서는 사용자 결정).

## 관통 기준 — 순이득(NetGain) 하나로 두 축 통일 (사용자 질문·확정 2026-08-08)

    순이득 = J(현 계획) − J(대안 계획) − 전환 실비용 − 안전여유(κ_T 1σ) > 0 이면 판다
    반입: 대안 = (다른 블록, 같은 시각) · 전환비용 = 주행 차이(음수 가능)
    반출: 대안 = (같은 블록, t+Δ) · 전환비용 = 기사 외부 대기 Δ (터미널 안 대기와 동일 단가)

작업의 계획 = (블록, 시각) 좌표쌍 — 반입은 블록, 반출은 시각 좌표를 바꿀 뿐 같은 식이다.
이득의 원천은 **v2 비용의 볼록성**(SLA 꼬리 누진): 같은 총 대기라도 몰리면 더 비싸므로
부하를 공간·시간으로 펴면 총비용이 내려간다(선형 비용이면 시간 판매는 원리상 이득 없음).
K/Q30/S 는 이 같은 양의 서로 다른 추정기다(K = 항상 0 이하 가설, Q30 = 공개정보 계산,
S = 실현 반사실 보상으로 학습). 구현: `sell_gain.UnifiedNetGain`(공개정보 결정론 예측 —
내부 대수 + 통지 도착 − 서비스 배수). 성능 판정에 쓰려면 0B 사전등록에서 동결.
