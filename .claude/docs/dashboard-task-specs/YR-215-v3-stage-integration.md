## 1. 무엇을 했나

[[YR-214]] 가 만든 v3 코드는 **혼자 돌았다** — `Market.step()` 을 불러 주는 곳이
없었고, 확정된 거래를 엔진에 반영할 경로도 없었다. 이 row 가 그 배선을 만들었다.

새 패키지 `src/yard_rl/v3/stage/` (4모듈 926줄):

| 모듈 | 하는 일 |
|---|---|
| `orders.py` | 무대를 세우고 명단 → `Order`·`ExecutionRecord`. **트럭마다 다른 통지 리드**(분포 추출) · `V3Announcer` |
| `bridge.py` | `review_fn` 본체 — ① 사건 수집 ② 시장 ③ 원자 확정. 순서가 계약이다 |
| `rollout.py` | 스냅샷 복제 + H=1시간 재생 · `RolloutBudget` · 동일성 불변식 |
| `episode.py` | `run_episode(load, dispatcher, arm, seed)` — 판정 셀 하나 |

꽂는 자리는 이미 있던 `MultiBlockTerminal.run(policy_fn, review_fn=…)` 이다
(v2 는 여기에 `UnifiedSellOrchestrator` 를 꽂았다). **엔진은 한 줄도 안 고쳤다.**

거래 확정은 엔진의 기존 원자 트랜잭션을 그대로 쓴다 — 공간은
`try_pre_gate_transfer`, 시간은 `try_time_sell`. 물리가 거부하면 그 건만 KEEP 이다.

## 2. ★동일성 불변식이 결함 넷을 잡았다

이 row 의 실질 산출물이다. "굴린 factual == 실제" 를 검사하니 **연달아 네 개**가 나왔다.

| # | 증상 | 원인 | 고침 |
|---|---|---|---|
| ① | 창 Φ 가 하루 Φ (86M vs 276K, **312배**) | `censored_turn_time_s` 가 완료차를 `O−A` 그대로 계상 — 창을 안 자름 | `min(O, T) − A` |
| ② | 재조작·본선 항이 창과 무관하게 커짐 | 항2·항3·항4 는 **검열 불가능한 누적 계수기**인데 기록에서 합산 | 터미널 계수기를 **시간대장**에 찍어 그 시점 값을 읽음 |
| ③ | 강제한 세계 셋의 Φ 가 **전부 같음** | 스냅샷을 **결정 뒤**에 뜸 → 이미 `decided` 라 분기가 다시 결정 안 함 + 거래도 이미 확정 | 분기점을 `market.step()` **앞**으로 |
| ③b | 〃 | 엔진이 `review_fn` **직전에** park 을 비워, 복제본은 t 를 건너뜀 | 분기 epoch 을 **손으로 한 번** 연다 |
| ④ | 분기 세계가 `TIME@8` 대신 `TIME@2` 를 고름 | `end_s` 를 rollout 지평(t+H)으로 줘서 **선택지가 잘림** | `end_s` 는 **하루의 끝**, 절단은 `sim.end` 로만 |

넷을 다 고친 뒤 **표본 4건 전부 통과** — 판매 행동·좌표·구매 응답이 모두 일치한다.

```
통과  판매 SELL→SELL ✓ · 좌표 TIME@8→TIME@8 ✓ · 구매 BUY→BUY ✓
통과  판매 KEEP→KEEP ✓ · 좌표 None→None ✓ · 구매 None→None ✓   (×3)
```

같이 찍은 **절단 폭**은 +61.1%(t=0h) · +4.97% · +2.75% · +0.87% 로, 창 안 Φ 가
작을수록 크다. 절대량은 비슷한데 분모가 작아서다 — 이 값이 크다는 것이 곧
**factual 도 같이 굴려야 하는 이유**다(§3-(1)).

## 3. ★설계 정정 둘 (문서 반영 완료)

### (1) 세계는 셋이다 — factual 도 굴린다

한때 *"factual 은 실제 궤적에서 읽으면 공짜"* 로 짰다가 **폐기**했다. 분기 세계는
`t+H` 에서 세상이 끝나 경계 근처 서비스가 실제와 다르다. 실측 절단 폭:

| t | 0.0h | 11.1h | 13.9h | 16.7h |
|---|---|---|---|---|
| 굴림 vs 실제창 | **+15.74%** | +0.31% | +0.05% | +0.08% |

창 안 Φ 가 작은 새벽에 비율이 크다. 지평을 15·30·60분 더 주면 대기 항 차이가
15,369 → 2,456 → −127 → **0** 으로 수렴하므로 원인은 절단이 맞다. 셋을 **같은
방식으로** 굴리면 절단분이 공통 상수로 상쇄된다 → 04b §3 갱신.

### (2) 불변식은 Φ 가 아니라 **결정**을 본다

위 이유로 Φ 동일성은 원리상 성립할 수 없다. 문서의 *"비트 단위로 같아야"* 를
**"같은 결정을 내야"** 로 정정했다. 절단 폭은 진단으로 병기한다.

## 4. ⚠️ 연산량 실측 — 전수 라벨링은 불가능하다

| | 값 |
|---|---|
| 스냅샷 복제 | 0.55~0.66초 (컨테이너 19,656 · 작업 3,742) |
| H=1시간 재생 | 1.4초(t=6h) · 3.2초(10h) · 7.9초(14h) — 하루가 갈수록 비쌈 |
| **세계 1개** | **≈ 4.8초** |
| 결정 3,500건 × 3세계 | **회차당 14시간** |
| 결정 7,500건 × 3세계 | **회차당 30시간** |

→ `RolloutBudget` 으로 **회차마다 K건만 등간격 표본**한다(기본 64). 메커니즘은
그대로 두고 표본 수만 줄이므로 우회가 아니다. 복제 자체를 아끼려고 `peek()` 로
**뜨기 전에** 그 epoch 을 라벨링할지 먼저 판단한다.

## 5-2. ★재현성 결함 — 같은 시드가 다른 하루를 냈다

사본 검증 중 **같은 셀이 실행마다 다른 Φ** 를 내는 것을 발견했다:

    부하 3,500 · RL · 같은 시드 →  102,913,359  ↔  136,388,850

원인은 **망 초기화에 시드가 안 걸린 것**이다. 학습 전 팔은 `SellerNet()` 을
그냥 만들었고, torch 전역 난수 상태가 실행마다 달라 **매번 다른 정책**이 됐다.
판정이 날 단위 짝비교라 이대로면 두 팔의 격차가 정책 차이인지 잡음인지 못 가른다.

`run_episode` 가 기본 망을 만들 때 `torch.manual_seed(seed)` 를 건다.
검사는 `tests/v3/test_episode_repro.py` — 같은 시드 두 번이 **모든 항까지 일치**해야
한다. 안 만든 팔이 조용히 대체되지 않는지, 판정 경로에서 교사가 안 불리는지도
같은 파일이 본다.
