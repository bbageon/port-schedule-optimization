# YR-215 · v3 무대 결합 — Market 을 실제 엔진 루프에 꽂는다

> Epic Infra · 우선순위 🔴 · 상태 **backlog** (등록 2026-08-22)
> 선행 [[YR-214]] ✅ · 후행 [[YR-212]] → [[YR-210]] → [[YR-211]] → [[YR-213]]

## 1. 무엇을 하는 작업인가

[[YR-214]] 가 `src/yard_rl/v3/` 를 전부 만들었지만 **혼자 돈다.** `Market.step()` 을
불러 주는 곳이 없고, 확정된 거래를 엔진의 작업 목록에 반영하는 경로도 없다.
이 row 가 그 배선을 만든다.

## 2. 왜 지금인가

**v3 는 지금 문법상 완성이지만 실행 가능하지 않다.** 이 배선이 없으면
[[YR-210]] 부하 스윕도 [[YR-211]] 대조군도 **한 셀도 못 돈다.**

## 3. 범위 — 다섯 조각

| | 무엇 | 지금 상태 |
|---|---|---|
| ① | epoch 마다 `Market.step()` 호출 | `MultiBlockTerminal` 루프에 호출부 없음 |
| ② | `Trade` → 엔진 반영 (공간=재배정 · 시간=슬롯 이연) | `relocate()`/`defer()` 는 있으나 엔진과 안 이어짐 |
| ③ | 터미널 전송 이벤트를 `ExecutionRecord.stamp()` 로 수신 | `stamp()` 는 있으나 호출부가 스모크뿐 |
| ④ | 반사실 교사의 `rollout_fn` 실체화 | **비어 있다** — snapshot 복제 + H=1시간 재생 |
| ⑤ | 동일성 불변식 검사 | `strict_identity` 훅만 있고 실제 대조가 없음 |

## 4. ★위험 지점은 ④ 다

반사실은 **같은 snapshot 에서 갈라 굴려야** 성립한다. 엔진 상태를 정확히 복제하지
못하면 "행동만 다르고 나머지는 같은 세계" 가 아니게 되고, 라벨 전체가 무의미해진다.

검사 방법은 통계가 아니라 **동일성**이다 — 반사실의 factual 가지가 실제 궤적과
**비트 단위로 같아야** 한다. 한 번만 어긋나도 잡힌다. 이 검사를 먼저 세우고 ④ 를 짠다.

## 5. 비용 주의

결정 1건당 rollout 1회이고 H = 1시간이다. 7,500대 부하에서 하루 결정 건수를
**먼저 세어보고** 총 소요를 추정한 뒤 착수한다 — 감당 안 되면 H 를 줄이는 게 아니라
학습 회차당 표본 수를 줄인다(H 는 사용자 결정 사항).

## 6. 완료 기준

- 하루 1일치 에피소드가 **v3 경로로 끝까지** 돈다 (부하 3수준 각 1회)
- `check_cell` 하드가드 전부 통과 — 특히 `traded_edges > 0` 과
  판정 구간 `rollout_calls == 0`
- 동일성 불변식 검사 통과
- **판정은 아직 하지 않는다** — 시드 대역은 [[YR-210]] 에서 처음 쓴다
