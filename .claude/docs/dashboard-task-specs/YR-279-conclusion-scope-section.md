# YR-279 — 결론의 한계 절을 "연구 범위와 확장 방향" 으로 교체 + 깨진 참조 발견·정정

- **Epic**: Paper / **Priority**: 🟠 / **등록·완료일**: 2026-08-30

## ① 6.1 절 교체 (사용자가 직접 쓴 문장)

`\subsection{한계}`(여덟 가지 열거) → **`\subsection{연구 범위와 확장 방향}`**.
사용자가 준 국문 문장을 그대로 넣고, 영문은 같은 내용으로 옮겼다
(`Scope of the Study and Directions for Extension`).

새 절이 담는 것: 합성환경의 위치(성능 추정이 아니라 조건 규명) · 실제 자료 적용 시
일반화 평가 · 혼잡 집중 → 선택적 개입으로의 확장 · 예약 정원·변경 절차·배차 규칙 ·
수락 거부권 비교 · 3시간 지평과 비용계수 민감도 · 기본 구조는 그대로 두고 확장한다는 정리.

⚠️ **여덟 가지 한계 열거는 사라진다.** 주제는 대부분 새 절이 흡수했지만(일반화·혼잡
날 수·정원·거부권·지평·비용계수·배차 규칙), "확정하지 못했다" 는 형태의 명시적 한계
목록을 원하는 심사자도 있다. 필요하면 §6.2 로 짧은 한계 목록을 되살릴 수 있다.
문단 나눔은 [[YR-273]] 규칙대로 **절 안에서 없앴다** (사용자가 준 다섯 문단을 이어 붙임).

## ② ★깨진 참조를 발견해 고쳤다

새 절 렌더를 눈으로 보다가 국문 결론에 **`efsec:env절의 합성환경에서`** 가 찍혀 있는 것을
발견했다. [[YR-277]] 에서 heredoc 로 편집할 때 `\ref` 의 `\r` 이 **캐리지리턴으로 바뀌어**
원고에 `ef{sec:env}` 만 남은 것이다. 영문도 같은 자리에 같은 손상이 있었다.

**빌드로는 안 잡힌다** — 명령이 아니라 그냥 글자가 되므로 오류도, 미정의 참조도 없다.
그래서 `scripts/v3/tex_escape_scan.py` 를 만들어 원고 전체를 훑었다: 제어문자(TAB·CR·FF
·BEL·VT·BS)와 `ef{`·`extbf{`·`ite{` 같은 **명령 조각**을 찾는다. 전수 검사 결과 이 두 곳
외에는 없었고, 고친 뒤 **이상 0건**이다.

교훈: 원고 편집에 heredoc 파이썬을 쓰지 않는다. Edit 도구나 파일로 뺀 스크립트를 쓴다.

## 검증

- 국·영문 각 2회 빌드 — Overfull **0** · Underfull **0** · 오류 **0** · 미정의 참조 **0**.
- PDF 에서 `efsec` **0건**, 새 절 제목이 국문 17쪽·영문 19쪽에 정상 표기.
- 원고 전수 escape 검사 **이상 없음**.
