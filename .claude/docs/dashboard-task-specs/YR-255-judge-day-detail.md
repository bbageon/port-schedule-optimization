# YR-255 — 판정이 하루치 값을 버리고 있었다

## 무엇이 문제였나

`run_month` 는 날마다 `DayReport` 를 만든다. 거기에는 이미 이런 값이 들어 있다.

```
phi_krw  c_wait  c_move  c_rehandle  c_vessel
n_trucks  n_censored  mean_turn_time_s  p90_turn_time_s  over_ratio
truck_skipped  traded  n_space  n_time
```

그런데 `month_judge._run_arm` 이 팔 결과를 만들 때 **`phi_krw` 하나만** 꺼내 갔다.

```python
phi_by_day={d.index: d.phi_krw for d in res.days},   # ← 나머지는 여기서 사라진다
```

그 결과 논문이 다음 셋을 쓸 수 없었다.

1. **비용 4항 분해** — Φ 를 네 항으로 정의해 놓고 결과에서는 한 번도 나누지 않았다.
   *"어느 항이 줄었나"* 는 심사자가 반드시 묻는 질문이다.
2. **트럭 회전시간** — 항만 운영의 표준 지표인데 논문에 아예 없었다. 계산은 되고
   있었다.
3. **비용 계수 민감도** — `c_move` 60,000원/시간과 `c_rehandle` 2,000원/회는 문헌값이
   아니라 설계값이다. *"계수를 두 배로 하면 결론이 뒤집히나"* 를 답하려면 항별 값이
   있어야 한다.

셋 다 **달을 통째로 다시 굴려야만** 얻을 수 있었다. 30일 판정 한 번이 5시간이 넘는다.

## 고친 내용

`ArmMonth` 에 `days` 필드를 더하고, 팔 단위 중간저장(`ckpt_dir`)에도 함께 남긴다.

```python
DAY_KEEP = ("index", "load", "phi_krw", "c_wait", "c_move", "c_rehandle",
            "c_vessel", "n_trucks", "n_censored", "mean_turn_time_s",
            "p90_turn_time_s", "over_ratio", "truck_skipped",
            "traded", "n_space", "n_time")
```

**한 번 굴리면 셋이 한꺼번에 나온다.** 민감도는 저장된 항을 다시 가중하기만 하면
되므로 재실행조차 필요 없다 — 이것이 이 작업의 실제 값어치다.

## 지금 논문에 들어간 값의 출처 (⚠️ 중요)

판정 28일치는 **아직 이 저장이 없던 실행**이라 위 값이 없다. 그래서 논문 §3.6 의
비용 구성과 체류시간은 **학습 달 30일 원자료**(`outputs/v3/month-02/days.json`)로
채웠고, 본문에 *학습 30일 실행에서 측정했다* 고 출처를 명시했다.

| 항목 | 값 (학습 달 30일) |
|---|---|
| 대기 `c_wait` | **96.4%** |
| 재취급 | 2.2% |
| 선박 유휴 | 1.2% |
| 크레인 추가 이동 | 0.1% |
| 평균 체류시간 | 0.89시간 |
| 90분위 체류시간 | 2.01시간 (한산 0.79 → 혼잡 7.49, **9.5배**) |
| 미완료 | 10,380 / 206,904 = 5.0% |

**대기가 96.4%라는 사실이 그 자체로 강건성 논거다** — 문헌값이 아닌 두 설계 계수
(`c_move`·`c_rehandle`)가 합쳐 2.3%뿐이라, 그 값을 몇 배로 바꿔도 결론이 흔들리지
않는다. 논문 §3.6 이 이 논거를 그대로 적는다.
