# YR-332-ca — 한 달 학습 데이터 점검: 관측 범위 밖 물량·보정 누락·예정 시각 정확도

- **상태**: backlog
- 상위 [[YR-332]], 2026-11-26 등록. 관련: [[YR-332-bt]](예정 시각 실험) · [[YR-332-bi]](짧은 작업 우선 우위) · [[YR-332-ap]](고물량 몰림) · [[YR-332-f]](트럭 정보 현실성).
- **3대 게이트 보정 대상**: `scenario_validity`. 한 달 학습·시험 입력이 실제 자료 범위와 보정을 따르는지 본다.
- 정책 학습은 하지 않는다. 진행 중인 bt·br 실행과 그 등록 파일은 건드리지 않는다.

## 발단

- 2026-11-26 사용자: "지금 혹시 학습 데이터에 대한 우려사항은 없는지 한번 검토해줄래?"

## 사전 확인 (2026-11-26, 읽기 전용 · 판정 아님)

자료: bl이 만든 학습 달(시드 12104101, 241,000건)과 시험 달(12204201, 206,500건)의 저장 입력, bt 첫 조건 마지막 물결 한 달의 학습 표본 82,880개,
실제 자료 요약(예약·통지 쌍 보정 2일, 개발용 관측 13일). 집계 수치만 쓴다.

### 1. 학습 표본의 42%가 관측 범위 밖 물량의 날에서 나온다

| 하루 물량 | 학습 달 날 수 | 학습 표본 비율 | 시간당 최대 방문(하루 입력 기준, [[YR-332-ap]]) |
|---:|---:|---:|---|
| 3,500 | 6 | 15.2% | 216~237 (관측 최대 245 이내) |
| 5,000 | 6 | 12.8% | 미측정 |

| 15,000 | 4 | 20.1% | 917~997 (72시간 중 60시간 초과) |

- 개발용 실제 13일은 33,703오더(하루 평균 약 2,600)·최대 245방문/시간이다. 터미널 전체 포함률은 미상이다.
- 7,500건 이상인 날의 오더가 학습 달 79%, 시험 달 61%다. 학습·평가가 혼잡 해소 상황에 치우친다([[YR-332-bi]]와 같은 구조).

### 2. 하루 단위 실제 자료 보정이 한 달 입력에 빠졌다

- `stage/month.py`의 `build_month`가 `build_stage`에 `demand_profile`·`information_profile`을 넘기지 않는다. 저장 입력도 그렇다.
  - 여러 컨테이너 방문 연결이 없다(실제 방문의 20.3%, [[YR-332-al]]). 시간 안 몰림도 기본 간격이다.
  - 반출 비율 60.1%(관측 53.8%). 시간대 모양은 가깝다(총변동거리 0.052).
  - 예약 오차는 합성 정규 σ 600초·±2σ 절단(`empirical_calibration: false`, 코드 주석 '보정된 예약 과정이 아닌 통제 실험')이다.
- 하루 단위 학습(aq 등)은 실제 예약·통지 쌍과 관측 수요 모양을 썼다. 두 무대의 정보·수요 조건이 다르다.

### 3. 예정 시각이 실제보다 훨씬 정확하다 (bt 해석에 직접 영향)

- 트럭 블록 ETA − 실제 블록 도착: 학습·시험 달 모두 5·95분위 −16.5·+16.4분, 평균 절대 7.8분, 60분 초과 0%.
- 실제 자료(보정 2일, 흐름별 약 1만 건): 실제 진입 − 공개 예약의 중앙값 반입 +101분·반출 +67분, 60분 넘게 어긋남 65%·53%, 꼬리는 며칠이다.
  보정 자료가 2일뿐이고 예약 문서 상태를 해석하지 않아 실제 오차의 크기도 불확실하다.
- 본선은 엔진이 계획 시작 시각에 시작 사건을 넣는다(`world/integrated/engine.py` VESSEL_START). 본선 작업 시작 예정 시각 오차가 0이다.
- 따라서 bt 결과는 '정보가 이만큼 정확하다면'의 상한으로 읽는다. 작업 시간을 미리 정확히 아는 문제([[YR-332-bi]] 5)와 같은 종류다.

### 4. 학습 달 하나, 시험 달 반복 사용

- 조건마다 16번의 월 재생이 같은 학습 달(같은 배·트럭)이고 정책 표본 난수만 다르다.
- 같은 시험 달로 지금까지 8번 평가했다(bl 4·bp·bw·bt 2). 그 결과를 보고 다음 설계를 정했으므로 깨끗한 보류 자료가 아니다.

### 5. 연결용 날·월말 정리 기간이 표본에 들어간다

- 입력은 첫날·마지막 날을 `train: false`로 표시한다. 그러나 `short_window_train.py`의 `rollout`은 전체 기간의 결정에서 무작위로 고른다.
- 첫날 2.0%·마지막 날 4.3%·월말 정리(30일 이후) 2.5%, 합 8.8%. 30일 무대의 사용자 설계는 '첫날·마지막 날은 연결용'이다([[YR-239]]).

### 6. 시뮬레이터 안 개선 여지는 크지만, 한가한 날도 실제보다 느리다

- 시험 달 트럭 진입→완료 평균(끝난 정책 6개, 진행 중인 bt 결과 제외). 물량 5,000건 이하이고 전날도 5,000건 이하인 날의 트럭 46,000건 기준이다.
  짧은 작업 우선(24분 승격) 36.3분, bp 모델 40.1분, 오래 기다린 작업 우선 54.4분, bl 모델 59.1분이다. 규칙끼리도 50% 차이가 난다.
- 실제 기록(개발용 13일, 세 시각이 연결된 표본): 진입→완료 평균 반입 20.67분·반출 31.33분([반입 현실성](../../../outputs/reports/yr332_inbound_realism/README.md)).
  가장 좋은 규칙도 한가한 날 실제보다 길다. 한 달 무대가 한가한 날에도 실제보다 붐빈다.
- 실제 보정을 넣은 하루 무대에서는 3,500건 날 규칙 간 차이가 2.4%였다([[YR-332-bi]] 1). 한 달 무대의 큰 개선 여지 일부는 과밀에서 생겼을 수 있다.

### 문제없음 확인

- 학습·시험 달은 시드가 다르고 날별 시드도 겹치지 않는다. 시험 달로 중간 모델을 고르지 않는다(마지막 갱신 모델만 평가).
- 예정 시각은 실현 도착을 직접 읽지 않는다(예약 기반). 다만 예약이 실제 도착에서 작은 오차만 빼 만들어져 정확하다(3절).

## 할 일 (사전등록 후 한 축씩)

1. **예정 시각 오차 민감도**: bt 최종 모델을 실제 자료 수준의 예약 오차와 본선 시작 지연을 넣은 시험 달에서 재학습 없이 다시 평가한다. 이득이 남는지 본다.
2. **한 달 입력 보정 경로**: `build_month`가 수요·정보 보정을 받게 한다. 기존 bl·bp·bt·br 결과와 비교가 끊기므로 사용자 확인 뒤 한다.
3. **물량 구성 분리**: 관측 범위 안 물량 위주의 달과 혼잡 시험 달을 나누어 학습·판정 범위를 분리한다([[YR-332-bi]] 할 일 1과 연결).
4. **새 시험 달**: 최종 확증용 시험 달(들)을 미리 정해 두고 다른 용도로 쓰지 않는다.
5. **연결일 표본**: `train: false` 날과 정리 기간을 표본에서 뺄지 정한다.
