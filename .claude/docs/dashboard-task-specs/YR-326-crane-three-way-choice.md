# YR-326 — 크레인을 3지선다로 줄인다: "본선이냐 트럭이냐"

- **상태**: backlog
- 출처: **사용자 제안 2026-09-22** — "크레인층을 간소화해서 특수한 경우는 고려하지 않고,
  현재 블록 작업 후보 중에 본선 작업을 할까 트럭 작업을 할까 고르게 하자."
- 종류: 행동 집합 축소. 단일축 변경.

## 명세

행동 집합 = **{본선 묶음 1등, 트럭 묶음 1등, 쉬기}** 세 개.

1. 선제 파내기를 발행하지 않는다 — `CandidateGenerator(block_pre_rehandle=True)`
   (`world/integrated/candidates.py:231`). **기존 스위치라 새 코드가 아니다.**
2. 미리 자리잡는 빈 이동을 발행하지 않는다 — `safety_only=True` (`candidates.py:376`).
   **교착 탈출용 빈 이동은 남긴다** — 두 크레인이 서로 막았을 때 비켜서는 유일한 수단이다.
3. 남은 실작업 후보를 본선·트럭 두 묶음으로 가르고 **각 묶음의 규칙 1등만** 정책에 보인다.
   묶음 안 순서는 규칙(실작업 우선 → 최단 소요)이 정하고 정책은 **묶음만** 고른다.
4. **예외** — 오래 기다린 트럭(필수 등급) 후보는 묶음 1등이 아니어도 보존한다.
   안 그러면 가장 오래 기다린 트럭을 보호하는 계약이 통째로 사라진다
   (`candidates.py:463-465`·`504-516`).
5. 실작업이 하나라도 살아 있으면 쉬기를 가린다. **단 공동 제약 마스크 계산 뒤에** 가린다 —
   원본 후보 기준으로 가리면 형제 크레인이 통로를 먼저 가져간 순간 예외로 죽는다.
6. 후보 줄의 종류 칸 4개는 **그대로 둔다**(두 칸은 항상 0). 줄 폭 24를 유지해야
   기존 가중치를 이어 쓸 수 있다.

## ★왜 "이지선다" 가 아니라 3지선다인가

쉬기는 **뺄 수 없다.** `ppo/crane.py:34-35` 가 실행 가능한 후보가 하나도 없으면
`RuntimeError` 를 던지고, `:81` 주석이 *"숨은 쉬기 대체경로 없음"* 을 의도적으로
못박아 뒀다. 쉬기를 지우면 그 순간 에피소드가 죽는다. 대신 *"일할 수 있으면 반드시
일한다"* 는 가능하다.

## 좋은 점

- **정보를 더하지 않고 행동만 좁힌다.** 본선/트럭 구분은 이미 후보 줄에 있다
  (`ppo/crane.py:45-46` 의 `is_vessel`·`is_external`). 연구 원칙 "핵심 정보 먼저" 에 맞는다.
- 빼는 둘 다 **기존 스위치**라 새 메커니즘을 더하지 않는다.
- 사용자 선행 결정(2026-08-28, [[YR-248]]) *"본선 가중치와 트럭 가중치를 구분"* 과 같은 방향.

## ★선행 조건 셋 — 지금 하면 답이 미리 정해져 있다

**1. [[YR-325]] 먼저.** 성과지표인 턴타임은 **트럭 기록만 센다**(`reward/phi.py:89-104` —
게이트 기록을 돌며 트럭 대기만 쌓는다. 배는 한 줄도 안 들어간다). 총비용에서도 본선은
규칙 팔 1.7%·학습 팔 0.18% 뿐이다. **"본선이냐 트럭이냐" 를 물어도 채점표가 항상
트럭이라고 답한다.** 이 상태로 돌리면 효과 0 이 나오고, 그게 *"이지선다는 쓸모없다"* 는
**잘못된 기각으로 박제된다.** ([[YR-143]] 계약: 유의하지 않다는 이유만으로 행동을
제거하지 않는다 — 그 엄격함은 **기각할 때도** 적용해야 한다.)

**2. [[YR-324]] 먼저.** 가중치를 얼린 30일 평가가 **한 번도 완주한 적이 없다.**
판정대가 없는데 새 팔을 올리면 무너진 게 행동 집합 탓인지 얼린 탓인지 못 가른다.

**3. 단계 0 — 기회 빈도 실측.** 아래.

## 단계 0 — 고를 기회가 실제로 있나

가장 한가한 부하(하루 트럭 3,500대) 하루치 크레인 결정 **8,711건**을 실측했다
(`scripts/v5/probe_crane_candidate_mix.py` · 코어 1개 · 68초):

- 본선과 트럭이 **둘 다** 후보에 있는 결정: **19%**
- 트럭만: 49% · 본선만: 32%
- **결정의 70% 는 할 수 있는 일 자체가 하나뿐이다.**

뒤집어 보면 고를 거리가 있는 30% 중에서는 그 선택이 본선 대 트럭인 경우가 **셋 중 둘**이다.
**틀 자체는 좋다. 문제는 쓸 기회가 드물다는 것이다.**

한 걱정은 반증됐다 — *"후보칸 12개를 임박 트럭이 다 먹어 본선이 안 보인다"* 는 이 부하에서
**0건**이었고 자르기 전후 비율 차이가 0.4%포인트였다.

**다시 재야 하는 것** (위 수치는 그대로 쓰면 안 된다):
- 붐비는 날(5,000·7,500·12,500). 30일 계획은 3,500 이 9일·5,000 이 10일·7,500 이 5일·
  12,500 이 6일인데 **가장 흔한 5,000·7,500 을 아무도 안 쟀다.**
- **학습 팔이 만든 야드**에서. 위 측정은 규칙 팔 세계이고, 규칙 팔은 밀린 본선 일감이
  30일에 4건뿐이라 본선 점수가 늘 0 인 세계다. 학습 팔은 본선 완료 0건인 세계라
  지형이 완전히 다르다.
- **형제 크레인 공동 제약 이후**. 측정 지점이 후보 생성 직후라 19% 는 **상한**이다.

**기준선**: 다시 재서 둘 다 있는 결정이 **20% 에 못 미치면 접는다** — 그건 고르게
하는 것이 아니라 고를 게 없는 결정을 만드는 것이다.

## 비교 상대

**주판정 = 같은 폭으로 좁힌 규칙 팔.** 보조 = 기존 전체 규칙 팔.
두 규칙의 차이가 곧 **"좁힌 대가"** 다 — 이 값 없이는 성적이 좁힌 덕인지 학습 덕인지 못 가른다.

⚠️ *"규칙의 선택이 늘 후보에 있으니 폭 문제가 원천 봉쇄된다"* 는 **성립하지 않는다.**
블록마다 크레인이 2기이고 규칙은 둘을 함께 푼다. 두 크레인의 1등이 같은 일감이면 진 쪽은
2등을 잡는데 그 2등은 축소 후보에 없다. 봉쇄되는 것은 **축소 규칙에 대해서만**이다.

## 판정

성과지표는 **턴타임(게이트아웃 − 게이트인)**. 중단규칙은 [[YR-319]] 와 같은
"같은 날 규칙의 3배". [[YR-143]] 계약대로 **허용손실을 결과 전에 숫자로 못박고**
비열등을 증명한다. 효과 0 이 나와도 *"채점표가 트럭 편이었다"* 를 배제하기 전에는
기각으로 쓰지 않는다.

## 비용

1시드에 코어 1개로 대략 7시간 — 학습 3시간·축소 규칙 평가 1.8시간은 실측,
축소 학습 팔 고정평가 2시간은 **추정**이다(건강하게 완주한 전례가 없다).

## 위험

- 좁히는 것 자체가 손해일 수 있다 — 실측에서 선제 파내기가 실행 가능했던 후보가 5,181건,
  빈 이동이 5,977건 있었다. *규칙이 거의 안 골랐다* 와 *있어도 쓸모없다* 는 다른 말이다.
- 재배정층까지 함께 얼리면 축을 둘 동시에 바꾸는 셈이다 — 행동 집합 한 축만 바꾼다.
