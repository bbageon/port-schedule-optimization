- **Epic**: RL / **Priority**: 🔴 / **등록일**: 2026-07-30
- **상태**: ready — YR-135의 구 비용계약 진단 종료 뒤 착수
- **근거**: [사용자 결정 이력](../strategy-history/2026-07-30-YR-136-점증비용곡선-v2-사용자결정.md)

## 배경

완료된 YR-123 v1은 트럭 비용률을 SLA 전 `1/h`, 초과 후 `2/h`로 갑자기 바꾸고,
본선 지연의 최대 가중치를 `33/h`로 사용한다. 사용자 결정에 따라 앞으로 사용할
정책용 한계비용은 다음처럼 바꾼다.

- 트럭: SLA에 가까워질수록 `1/h → 2/h`로 연속 증가
- 본선 적하: 계획 완료시각에 가까워질수록 `0/h → 10/h`로 연속 증가
- 끝점 비용률을 곱하지 않고 지연구간 전체를 적분

YR-123 v1 코드·결과는 재현 이력으로 보존하고, 새 계약은 opt-in v2로 구현한다.

## 공통 완화함수

```text
S(x) = 0                  (x ≤ 0)
     = 3x² - 2x³          (0 < x < 1)
     = 1                  (x ≥ 1)
```

`S`는 양쪽 경계에서 값과 기울기가 이어지는 smoothstep이다. 따라서 비용률이 특정
시각에서 갑자기 뛰지 않는다.

## 트럭 비용률

기호:

- `w`: 현재까지의 블록 체류시간 `현재시각 - 실제 블록도착 B`
- `L`: 장기대기 SLA, 현재 앵커 `30분`
- `W_T`: SLA 접근 점증구간, 초기 앵커 `10분` (`assumed`)

```text
u_T(w) = (w - (L - W_T)) / W_T
r_T(w) = 1 + S(u_T(w))                         [numeraire / truck-hour]

ΔC_T(w, Δt) = (1/3600) × ∫[w,w+Δt] r_T(x) dx
```

의도된 값:

| 블록 체류 | 한계비용률 |
|---|---:|
| 20분 이하 | 1.0/h |
| 25분 | 1.5/h |
| 30분(SLA) | 2.0/h |
| SLA 초과 | 2.0/h 유지 |

`escalation_start`는 기존의 “SLA까지 남은 시간”이 아니라 **점증이 시작되기까지 남은
시간** `max(0, L-W_T-w)`으로 정의한다. 미도착 트럭은 실제 미래 블록도착을 읽지 않고
공개 ETA와 gate-in→block-in 예측으로 기준 `w`를 만든다.

## 본선 적하 비용률

기호:

- `F`: 공개정보 공급경로로 계산한 예상 본선 완료시각
- `P`: 계획 작업완료시각 `planned_completion_s`
- `W_V`: 완료 접근 점증구간, 초기 앵커 `30분` (`assumed`)

```text
u_V(F) = (F - (P - W_V)) / W_V
r_V(F) = 10 × S(u_V(F))                        [numeraire / vessel-hour]

ΔC_V(F0, F1) = (1/3600) × ∫[F0,F1] r_V(x) dx
```

의도된 값:

| 예상 완료시각 | 한계비용률 |
|---|---:|
| 계획완료 30분 전 이하 | 0/h |
| 계획완료 15분 전 | 5/h |
| 계획완료시각 | 10/h |
| 계획완료 초과 | 10/h 유지 |

후보가 STS 완료예상 `F`를 바꾸지 않으면 본선 한계비용도 0이다. 따라서 “본선 작업이면
무조건 우선”이 아니라, 실제 공급병목을 바꾸는 후보만 비용을 갖는다. 최초 범위는 공급
인과가 구현된 `VESSEL_LOAD`이며, 양하는 별도 역압력 계약 검증 전 0을 유지한다.

## 정책비용과 평가 KPI 분리

- **정책·견적용**: 위 곡선의 후보 전후 차이만 사용한다.
- **본선 평가 KPI**: 실제 계획완료 초과시간을 그대로 보고하되 환산 최대 가중치는
  `33 → 10`으로 낮춘다.
- **트럭 평가 KPI**: 평균 `B→C`, 평균 `A→O`, SLA 초과 건수·시간은 원형 그대로
  보고한다. 기존 계단형 `long_wait`를 새 점증항과 다시 더하지 않는다.
- P95는 기존 결정대로 보고용이며 reward·채택 veto로 사용하지 않는다.

## 구현 계약

1. 기존 `TERMINAL-COST-NUMERAIRE-V1`과 YR-123 v1 골든은 바이트 불변으로 보존한다.
2. 새 비용 설정·곡선은 명시적 v2 opt-in으로만 활성화한다.
3. YR-123 공통 API, YR-100 본선 공식, 엔진 평가비용, Q 라벨 생성기가 같은 v2 계약을
   사용해야 한다. 곡선만 바꾸는 이중 계약은 금지한다.
4. `ρ_vessel=10`은 정확히 한 번만 적용한다.
5. `W_T=10분`, `W_V=30분`은 실자료가 아닌 초기 가정이다. 같은 판정런 안에서 결과를
   보고 조정하지 않는다.
6. 불확실성은 smooth/hard 식 차이가 아니라 공개 ETA·YT 공급시간 오차에서 계산한다.
   오차모형이 없으면 정직하게 `lo=cost=hi`로 둔다.

## 단일축 검증 순서

1. **계약·골든**: smoothstep 적분, 단조성, 경계 연속, 구간 가법성, v1 불변.
2. **트럭 단일축**: 본선 계약은 v1로 두고 트럭 점증곡선만 비교.
3. **본선 단일축**: 트럭 계약은 v1로 두고 본선 `33→10+점증`만 비교.
4. **결합판**: 앞의 두 축이 각각 의도대로 작동한 뒤에만 함께 평가.
5. **재라벨**: YR-135 구조가 유효할 때만 v2 비용으로 신규 라벨을 생성해 다시 평가.

## 수용 기준

- 트럭 비용률 `20/25/30분 = 1/1.5/2`, 이후 2 유지.
- 본선 비용률 `P-30/P-15/P = 0/5/10`, 이후 10 유지.
- 비용과 1차 기울기가 경계에서 연속.
- `C(t,d1+d2)=C(t,d1)+C(t+d1,d2)` 구간 가법성.
- 지연이 늘수록 비용이 감소하지 않음.
- 엔진 에피소드 비용과 작업별 적분 합이 일치하고 미완료 회피가 없음.
- 실제 미래 도착·고장·계획변경 정보 누출 0.

## 범위 밖

- 점증구간 `W_T/W_V`를 같은 실험에서 튜닝하지 않는다.
- 성능 검증 전 하드가드·예약·자동실행을 추가하지 않는다.
- YR-133의 판매·수용 견적 집계와 원자 이송 자체는 이 작업에서 구현하지 않는다.
