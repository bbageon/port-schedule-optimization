# YR-156 — 게이트 증거를 "작업트리 현재 파일"이 아니라 "commit 시점 내용"에 고정

- **Epic**: Infra / **Priority**: 🟠 / **등록일**: 2026-08-06 / **상태**: **backlog**
- **3대 게이트 보정 대상**: `reliability` 하나 — 착수 시 YR-153 `authorize-next` 통과 필수
- **발견 경위**: 2026-08-06 하루에 **같은 원인으로 두 번** 다음 작업이 막힘

## 무엇이 문제인가

`authorize-next` 는 저장된 게이트 JSON 의 `PASS` 를 그대로 믿지 않고
`revalidate_pass_evidence()` 로 다시 계산한다(좋은 설계다). 그런데 그 안의
`audit_dashboard` 는 증거 파일과 board·spec 이 **지정 commit 이후 한 글자도 바뀌지 않았을 것**을
요구한다(`git diff --quiet <commit> -- <path>`).

문제는 board row 와 spec 이 **계속 갱신되는 살아있는 문서**라는 점이다. 그래서
판정과 무관한 정당한 편집만으로도 과거 판정이 무효가 된다. 실측 2회:

1. YR-151 row 를 `ready → backlog` 로 재정리 → `저장된 dashboard PASS 재계산 실패`
2. YR-150 0단계 결과를 YR-151 spec 에 교차 기록 → 같은 실패 재발
3. 재발행 커밋에 board 파일(backlog.md)을 **같이 담아** → 그 커밋 이후 board 가 또 달라진
   셈이 되어 재계산이 다시 실패. **재발행 커밋에는 게이트 JSON 만 담아야** 고정점에 닿는다
   (임시 운용 규칙은 `research-gates.md` §2 에 박제).

두 번 다 **0A 실험 자체는 아무것도 변하지 않았다.** 깨끗한 커밋에서 돌았고 수치도 그대로다.
무효가 된 것은 "그때 board 가 이랬다"는 스냅샷뿐이다.

## 왜 완화가 아니라 설계 문제인가

지금 조치는 매번 게이트 보고를 재실행해 evidence 를 현재 진실에 맞추는 것이다. 이것은
**임계 완화가 아니라 재계산**이므로 규율 위반은 아니다. 그러나 ①문서를 고칠 때마다 판정을
다시 돌려야 하고 ②재실행을 잊으면 다음 작업이 이유 없이 막히며 ③"게이트가 자주 깨진다"는
경험이 쌓이면 완화 압력이 생긴다.

## 무엇을 하는가

- `audit_dashboard` 가 **작업트리 파일 대신 `git show <commit>:<path>` 로 그 commit 시점
  내용을 읽어** 검사하도록 바꾼다. 판정은 여전히 **불변 commit** 에 고정되므로
  증거 강도는 그대로이고, 이후의 문서 갱신에 흔들리지 않는다.
- 현재 작업트리와 판정 시점이 다르면 **실패가 아니라 `drift` 정보로 기록**한다
  (감사자가 "그 뒤 문서가 바뀌었다"는 사실은 볼 수 있어야 한다).
- board row 존재·spec 상태 일치 검사도 같은 commit 시점 기준으로 본다.

## 완료 조건

- board·spec 을 판정 이후에 편집해도 `authorize-next` 가 통과하고, 그 결과에
  `dashboard_drift` 가 사실대로 기록된다.
- 회귀: 증거 commit 자체가 없거나 push 되지 않았거나 그 시점 내용이 요구와 다르면
  여전히 **실패**한다(fail-closed 유지).
