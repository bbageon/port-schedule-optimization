# YR-195 — 문턱: 눈금에 오차가 있는 자를 쓰는 법

- **Epic**: RL / **Priority**: 🔴 / **등록일**: 2026-08-19 / **상태**: backlog
- **3대 게이트 보정 대상**: `performance`
- **선행**: [[YR-189]] 판정 완료 ✅ (WORSE · +211.41)
- **1줄**: `Q < 0` 은 **예측 오차만큼 과잉 판매를 만든다.** 규칙에는 있는 안전
  여유(`gain_margin`)가 Q 설계에 없다.

## 실측 (YR-189 판정 · 16일)

| 팔 | Φ | 일평균 판매 | 제안 |
|---|---|---|---|
| K | 2,383.9 | 0 | 0 |
| **greedy** | **2,258.8** | **957** | 1,458 |
| q | 2,470.3 | **2,167 (2.26배)** | 2,457 |

`q − greedy` = **+211.41** [+167.79, +255.02] · **16일 전부 규칙 승**.
`q − K` = +86.32 — **안 팔기보다도 나쁘다**.

## 기전 — ★실측됨 (2026-08-19 · 관측 8 / D-1)

배포 모드에서 **고른 좌표의 예측과 실제를 직접 대조**했다(4시드 × 22시간 ·
비판정 대역 9,900,040~ · 10,046 표본).

| 축 | n | 예측 평균 | 라벨 평균 | **편향(예측−라벨)** | 라벨>0 |
|---|---|---|---|---|---|
| 공간 | 5,702 | −0.2347 | −0.0595 | **−0.1752** | 42.9% |
| 시간 | 4,344 | −0.1079 | +0.0538 | **−0.1617** | 44.2% |
| 전체 | 10,046 | −0.1799 | −0.0105 | **−0.1694** | — |

**대조군과 부호가 뒤집힌다** — 탐색을 켜 선택을 무작위화하면 편향이 **+0.04**
(약간 비관)인데, 배포 모드(21개 좌표 중 argmin)에서는 **−0.17**(낙관)이다.

같은 망·같은 무대다. **모델이 나쁜 게 아니라 "가장 싼 것을 고르는 행위" 자체가
편향을 만든다** — 참값이 낮은 것이 아니라 **오차가 낙관 쪽으로 난 좌표**가 뽑힌다
(승자의 저주 / optimizer's curse).

**크기가 결정적이다**: 실제 라벨 평균 −0.0105 vs 편향 −0.1694 →
**편향이 진짜 이득의 16배**. 판 것의 **43%가 실제로는 손해**였다.

여기에 원래 알던 것이 겹친다 — 모델 오차가 신호의 **82%**(RMSE 0.019 /
목표RMS 0.023)라 참값이 0 근처인 건들은 오차의 부호로 팔린다. 비용이 볼록해
잘못 판 손해가 잘 판 이득보다 크다.

규칙의 `gain_margin`(κ_T 1σ)이 정확히 이 보정이다. **Q 설계에는 없었다.**
문헌도 "최고 후보 하나만 쓰면 채점 잡음에 민감"하다고 경고했다(YR-189 spec §5).
사전등록에 적어두고도 대비를 넣지 않았다.

## 설계 후보 (하나씩 · 단일축)

| # | 무엇 | 성격 |
|---|---|---|
| **A** | 문턱을 `Q < −m` 으로. `m` 은 **선택 편향에서 유도** — 실측 **−0.1694** 가 직접 추정치다 | 가장 직접적 · 규칙과 대칭 |
| B | 평균 대신 **하위 분위 회귀**(pinball loss) — "웬만하면 이득"인 것만 판다 | 원리적 · 눈금 재해석 |
| C | 예측 **불확실성**을 함께 내고(앙상블·MC dropout) 상한이 0 미만일 때만 판매 | 정보 많음 · 비용 큼 |

**권장은 A** — 축이 하나이고, 규칙의 `gain_margin` 과 직접 비교되며, `m=0` 이
YR-189 재현이라 대조군이 공짜다. **그리고 `m` 을 손으로 정하지 않아도 된다** —
관측 8 의 방법(고른 행의 예측 vs 라벨)을 그대로 쓰면 학습 중에 측정된다.

★**`m` 은 상수가 아니라 "비교한 좌표 수"에 걸린다.** 21개 중 고르면 −0.17,
5개 중 고르면 더 작다. 반입(공간 20 + 시간 1)과 반출(시간 1)은 비교 폭이
전혀 다르므로 **같은 `m` 을 쓰면 안 된다** — 축별·후보수별로 둔다.

## 판정 (사전등록 시 동결)

`q(문턱 m) − greedy` 짝비교. **`m` 후보를 여러 개 돌리면 다중비교**이므로
사전에 **m 격자와 선택 규칙을 동결**한다(예: 잔차의 0·0.5·1·2배 네 값, 주판정은
1배). 평가 대역은 **새로 연다** — 9,600,000~ 는 YR-189 가 썼다.

## 함께 고칠 것 — 2관문이 판단을 안 한다 (관측 8 / D-2)

같은 측정에서 배정기의 거부 내역이 나왔다.

| | 건수 | 제안 대비 |
|---|---|---|
| 판매 성사 | 8,955 | 88.3% |
| 확정 실패 `KEEP_TXN_FAIL` | 1,091 | 10.8% |
| **판단 거부** `RESOLVER_KEEP` | **95** | **0.9%** |

**2관문은 판단하는 척하면서 계산만 약 11배 더 한다.** 1관문이 이미 같은 망으로
같은 계산을 했으니 되돌릴 이유가 없다.

→ **역할을 나눈다** (사용자 제안 2026-08-19):
**1관문 = 자기 후보 중 최악 하나 지목(상대 순위, 문턱 없음) ·
2관문 = 판매 여부 결정(문턱 `m` 은 여기 하나만) + 용량·경합·혼잡 갱신.**
채점 결과는 1관문에서 **넘겨받고** 다시 계산하지 않는다 — 매칭 루프의
재채점이 사라져 배정기 계산이 약 11배 준다.

**단, 혼잡 갱신은 남긴다.** 배정이 확정될 때마다 목적지가 차오르는 것을 반영하지
않으면 21개 블록이 같은 빈 블록으로 몰린다. 그것이 배정기의 진짜 일이다.

## 왜 이것이 "규칙 베끼기"가 아닌가

`gain_margin` 은 κ_T 의 1σ 로 **손으로 정한 상수**다. 여기서는 **모델 자신의
선택 편향에서 유도**한다 — 학습이 정확해지거나 후보 수가 바뀌면 문턱이 자동으로
따라간다. 규칙이 못 하는 일이다.

## 하지 않는 것

- A·B·C 를 한꺼번에 넣는 것.
- 결과를 보고 `m` 을 고르는 것 — 격자와 주판정을 실행 전에 동결한다.
- 규칙의 `gain_margin` 을 건드려 기준선을 약화시키는 것.
