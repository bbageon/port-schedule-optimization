# YR-332-x — 본선 여유 입력이 거의 늘 상한에 걸린다

- **상태**: backlog
- 등록: 2026-11-07. 상위 [[YR-332]], 발견 작업 [[YR-332-t]].
- 정책 입력 한 축의 진단·보정 후보. 실행 전 사전등록이 필요하고, 효과 실증 전 기본값은 유지한다.

## 무엇과 왜

학습 정책의 4번째 입력은 본선 여유(계획 완료 − 지금 − 남은 작업시간)를 ±2시간에서 자른 값이다.
계획 완료가 순수 작업시간의 2배 여유(`vessel_deadline_mult = 2.0`)로 잡혀 있어 실제 여유가 대부분
+2시간보다 크다. t 감사의 69회 관측에서 최신 학습 정책의 본선 후보 중 상한에 걸린 비율은
3,500건 100.0%, 7,500건 81.6%, 15,000건 84.5%였다. 한가한 날에는 이 입력이 늘 같은 값이다.

같은 감사에서 최신 학습 정책은 최단 작업보다 본선 유휴가 많았고(비용 차이 +3.80%p),
YR-332-v에서는 26시간 본선 야드 완료가 9/9 비교에서 최단 작업보다 적었다. 배의 급함을
거의 보지 못하는 입력이 그 원인인지는 아직 판정하지 않았다. 관측된 실패와 직접 닿는 정보 축이다.

## 범위 (실행 전 사전등록)

1. 입력의 눈금 한 축만 바꾼다(예: 여유를 남은 작업시간 대비 비율로 표현, 또는 상한 확대).
   후보·비용·물리·교사·학습량·초기값은 그대로 둔다. 다른 입력을 함께 바꾸지 않는다.
2. 눈금은 평가 자료가 아닌 학습 자료의 분포로 정하고, 결과를 본 뒤 바꾸지 않는다.
3. 같은 자료·같은 갱신 예산으로 재학습해 학습 전후·기존 설정 대비를 함께 보고한다.
4. 본선 유휴·본선 야드 완료·트럭 체류·투입·미완료를 모두 보호 조건으로 둔다.
5. 운반 장비 바닥(i)·평가창(d)·필수 작업 규칙은 바꾸지 않는다. 이 변경만으로 현실 타당성을 주장하지 않는다.
