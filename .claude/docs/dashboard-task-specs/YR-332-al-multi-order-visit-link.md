# YR-332-al — 한 트럭이 여러 컨테이너를 처리하는 방문의 연결 계약

- **상태**: in-progress
- 등록: 2026-11-13. 상위 [[YR-332]], 발견 작업 [[YR-332-ak]].
- **3대 게이트 보정 대상**: scenario_validity(만든 입력이 실제 자료의 흐름과 맞는가).
- 환경 계약 한 축. 정책·보상·학습은 바꾸지 않는다.

## 무엇과 왜

ak 원자료 감사에서 실제 방문 27,415번 중 5,492번(20.0%)이 컨테이너 2~4개를 한 번에 처리했다.
합성 무대는 오더 1건을 트럭 1대로 만든다. 그래서 같은 트럭의 작업이 서로 다른 트럭처럼 따로 움직인다.
실제 오더 단위 1분 몰림 지수는 1.772, 방문 단위는 1.266이다. 이 차이는 주로 여러 컨테이너 방문 때문이다.
ak는 방문 단위 몰림만 맞췄고, 이 연결은 다른 축이라 바꾸지 않았다.

관측 사실(제약이 아니라 관측):
- 반입+반출 방문은 같은 블록 1,934·다른 블록 1,633이다. 같은 블록에서는 반입 완료가 먼저인 경우가 1,716 대 21이다.
- 다른 블록 반입+반출은 반입 뒤 반출 302, 시각 겹침 351이다. 반출 두 건의 다른 블록은 순차 203이다.
- 여러 오더 방문의 출차 시각은 4,944개가 같고, 다른 106개도 281초 이내다.

## 범위 (실행 전 사전등록)

1. 먼저 연결 의미를 정한다: 한 번 진입, 블록별 작업 순서, 한 번 출차, 지표(오더별·방문별)를 분리한다.
   관측 순서를 물리 제약(예: 차대가 비어야 반출 적재)과 구분하고, 근거 없는 순서를 의무화하지 않는다.
2. 연결을 끈 기본 경로는 기존 결과·해시와 같아야 한다(전후 동일성 검사).
3. 연결 축만 바꾸고 시간대별 물량·작업 구성·방문 몰림·물리·정책은 ak와 같게 둔다.
4. 여러 컨테이너 방문의 비율·구성·블록 관계는 개발용 13일 자료에서 정하며 독립 검증으로 부르지 않는다.
5. 오더별 진입→완료 지표를 말없이 방문 지표로 바꾸지 않는다. 두 지표를 함께 보고한다.
