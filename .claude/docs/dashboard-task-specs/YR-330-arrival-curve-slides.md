## 자료를 코드에서 읽는다

그림에 숫자를 적어 넣지 않았다. `curvedata.py` 가 매번 다시 읽는다 —
곡선은 `terminal_stream.diurnal_rate`, 계약(봉우리·바닥·부하 추첨)은 시드 은행
`manifest.json` 의 `generator_contract`, 실제 생성분은 같은 폴더 `summary.json`
(확증 캠페인 입력 20달 × 30일 = 600일). **생성기가 바뀌면 그림도 같이 바뀐다.**

## 확인한 값

- 봉우리 (10시·폭 1.5h·31.7%) · (15시·2.5h·63.3%) · (21시·1h·5.0%) · 바닥 0.38.
- 부하 추첨 3,500/5,000/7,500/12,500/15,000 에 30/30/25/10/5%.
  실제 600일 비율 27.7 / 31.2 / 23.3 / 13.2 / 4.7% (추첨 결과, 보정 없음).
- **설계 곡선과 실제 생성분이 시간당 0.1대 안에서 일치** — 부하 7,500 인 140일 평균으로 대조.
- 크레인 상한 840대/h 는 42대(21블록 × 2대) × 3분/대의 **낙관적 상한**이다.
  실제 작업시간 190~410초·본선 작업 공유를 각주로 공개했다.
