# YR-193 — 탐색 어닐링: 배포 분포를 한 번도 안 보는 문제

- **Epic**: RL / **Priority**: 🟠 / **등록일**: 2026-08-19 / **상태**: backlog
- **3대 게이트 보정 대상**: `performance`
- **선행**: [[YR-189]] 판정 완료 (설정을 동결한 채 끝까지 돌린 뒤)
- **1줄**: 학습 내내 잡음이 신호보다 커서, 모델이 **배포 모드가 만드는 상태를
  한 번도 보지 못한다**.

## 실측 (YR-189 실행 중 관측 2 · 2026-08-19)

| iter | RMSE | 목표 RMS | σ / 목표RMS | 차분신용 합 |
|---|---|---|---|---|
| 0 | 0.0693 | 0.1092 | 1.8× | −1,849 |
| 1 | 0.0496 | 0.0788 | 2.5× | −510 |
| 2 | 0.0412 | 0.0657 | 3.0× | −524 |
| 3 | 0.0359 | 0.0580 | **3.4×** | −514 |

좌표 탐색 잡음 `σ=0.20` 이 고정인데 **목표 눈금은 학습이 진행될수록 줄어든다.**
그래서 σ 의 상대 크기가 회차마다 **커진다**. 좌표 사이 Q 차이가 잡음에 묻혀
학습 중 좌표 선택이 사실상 무작위가 된다.

## 왜 문제인가 (문맥 밴딧이어도)

라벨은 직접 관측이므로 **라벨 편향은 없다**. 문제는 **상태 분포**다.

- 학습 중 상태 = "마구 파는 정책"이 만든 혼잡한 야드
- 배포 시 상태 = argmin 이 만드는 **판매가 적고 한산한** 야드

모델은 후자를 거의 본 적이 없다. 방문하지 않은 영역의 예측은 외삽이고,
그 위에서 argmin 을 하면 잘못된 좌표를 고를 수 있다.

## 설계 (사전등록 시 동결)

**축은 하나** — σ 를 회차에 따라 줄인다. 나머지는 [[YR-189]] 와 동일.

```
σ_k = σ0 · (목표RMS_k / 목표RMS_0) · decay^k     또는 단순히
σ_k = c · 목표RMS_k        (상대 크기를 고정 — 권장)
```

**권장은 상대 고정**이다. "잡음을 신호의 몇 배로 둘 것인가"를 상수(예: 0.5)로
정하면, 목표 눈금이 줄어도 탐색 강도가 자동으로 따라간다. 절대값 σ 를 손으로
정하면 이번처럼 조용히 3.4배가 된다.
