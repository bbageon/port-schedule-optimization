# YR-317-n — 독립 학습 반복 3판 (PRESERVE 계약·수정 엔진)

- **상태**: 진행 중 (2026-09-25) — n1·n3 완료, n2 **강제 종료 후 처음부터 재시작**
- 등록: 2026-09-21. parent: YR-317. 선행: [[YR-317-k]](교착 수정).
- 무엇: 학습 시드 3개로 30일 학습을 3판 돌려 "독립 반복"의 비어 있던 학습 축을 채운다. 평가는 [[YR-318]] 캠페인에서 함께 한다.
- 왜: 80건 전부가 체크포인트 하나(`50f2da2e…`, 학습 시드 9,900,700, 학습 1회)에서 나왔다. 원고도 "one model, not across training runs"라고 적는다. 또한 그 모델은 접수계약 LEGACY에서 배우고 PRESERVE에서 평가됐다 — 계약 불일치를 같이 해소한다.
- 고정: 학습 시드 3개는 진단 대역에서 규칙으로 고른다(성능으로 고르지 않는다). `--init-seed` 명시, `ckpt_init.pt`·`training_manifest.json` 보존 → **무학습 대조군을 추가 학습 비용 0으로** 얻는다.
- 비용: 30일 학습 1판 17.8시간(실측), 3판 병렬 약 1일(6코어×3).
- 완료 기준: 3판의 체크포인트·매니페스트·초기 가중치가 저장되고 지문이 기록된다. 성능 판정은 YR-318에서 한다.
- **3대 게이트 보정 대상: `reliability`** — 재현 가능한 학습 기록을 직접 복구하는 단일축 작업이다.

## 고정 (2026-09-22 · 실행 전, 성능을 보지 않고 규칙으로 정함)

- **학습 시드 3개**: 9,900,701 · 9,900,702 · 9,900,703 — 기존 학습 시드 9,900,700 바로 다음
  세 개를 순서대로. 부하·성능을 보고 고르지 않았다.
- `--init-seed` 는 환경 시드와 **같게 명시**한다. 재고 대상이 "학습 시드 효과"가 아니라
  **"학습 절차 전체를 다시 돌린 결과"** 이므로 환경과 초기화를 함께 바꾼다
  ([[YR-318]] 사전등록의 *한 학습 절차의 세 표본* 과 같은 정의).
- 계약: `PRESERVE` · `COUNT_BALANCED` · 후보 폭 `RL` · **`--candidate-pruning feasible_first`**
  (수정 엔진). 평가와 같은 계약에서 배운다 — 기존 80건의 LEGACY 학습·PRESERVE 평가
  불일치를 이번에는 만들지 않는다.
- 출력: `outputs/v3/month-n1|n2|n3`. `ckpt_init.pt` 는 실행 시작 시 자동 저장되므로
  **무학습 대조군을 추가 비용 0으로** 얻는다.

```
python -m yard_rl.v3.train --seed 9900701 --init-seed 9900701   --admission-mode PRESERVE --supply-mode COUNT_BALANCED --arm RL   --candidate-pruning feasible_first --workers 5 --out outputs/v3/month-n1
```

(9900702 → `month-n2`, 9900703 → `month-n3`. 세 판 동시 실행, 각 5코어.)

- 사전 확인 완료(`--dry`): 세 시드 모두 진단 대역 통과, 30일 계획 생성,
  학습분 트럭 144,500 / 195,000 / 160,500대. 부하 구성이 판마다 다른 것은
  **절차 재실행의 자연스러운 변동**이며 이것을 재는 것이 목적이다.

## 실행 기록과 ★관찰 (2026-09-25 · 결과를 보기 전에 적는다)

| 판 | 환경·초기화 시드 | 상태 | 걸린 시간 |
|---|---:|---|---:|
| n1 | 9,900,701 | 완료 | 54.95시간 |
| n2 | 9,900,702 | 19일째 진행 | (하루 400분 안팎) |
| n3 | 9,900,703 | 완료 | 65.12시간 |

⚠️ 예상 17.8시간 대비 **세 배** 걸렸다. 세 판을 한 기계에서 같이 돌렸고, 날이 갈수록
야드가 차서 하루가 느려진다(마지막 날들은 하루 3~6시간).

### ★같은 절차를 세 번 돌렸더니 서로 다른 정책이 나왔다

거래 중 **공간(블록) 변경이 차지하는 비중** — 초반 8일 → 최근 8일:

| 판 | 초반 | 최근 | 방향 | 최근 8일 미완 트럭 |
|---|---:|---:|---|---:|
| n1 | 30.6% | **10.0%** | 시간 조정으로 수렴 | 1,376 |
| n2 | 21.2% | **43.9%** | 공간 조정으로 수렴 | 4,282 |
| n3 | 23.9% | **37.6%** | 공간 조정으로 수렴 | 1,512 |

같은 부하(7,500)의 하루를 견주면 n1 19일째는 공간 127·시간 2,607 거래에 Φ 3.43억·미완
123대, n2 18일째는 공간 2,156·시간 1,798 거래에 Φ **13.23억**·미완 **1,423대** 다.
이는 원고가 이미 보고한 **행동 대체**(공간 허용 시 시간 조정을 포기하고 공간으로 바꾼다)와
같은 기제이며, 여기서는 **학습 판에 따라 그 정도가 갈린다**는 것이 새로 보인다.

### 이 관찰로 설계를 바꾸지 않는다

- 이것은 **진단 대역의 학습 기록**이지 판정이 아니다. 평가는 별도 대역에서 고정 가중치로 한다.
- n1 만 쓰고 싶어지는 유혹이 정확히 [[YR-318]] 사전등록이 막으려던 것이다 — 세 판의
  **평균 하나만** 확증하고, 부호가 갈리면 확증으로 쓰지 않는다.
- 오히려 이 관찰은 사전등록의 **B 경우**(평균으로는 우위가 보여도 판마다 방향이 갈림)가
  실제로 일어날 수 있음을 시사한다. 그 경우의 보고 문장은 이미 적어 두었다.
- n2 를 기다린다. 느리다는 이유로 두 판으로 줄이는 것도 결과를 본 뒤의 설계 변경이다.

## ⚠️ n2 가 21일째에서 강제 종료됐다 — 처음부터 다시 돌린다 (2026-09-25)

- 무슨 일: n2 를 띄운 배경 작업이 **신호 15(SIGTERM)** 로 끝났다. 이틀 넘게 돌던 작업이라
  실행 환경이 정리한 것으로 보인다. 학습 자체의 오류가 아니다. 22일치(0~21일) 기록과
  `ckpt_021.pt` 까지 남았다.
- **중간 재개는 불가능하다.** 30일 무대는 **이어지는 하나의 세계**이고 야드 상태를
  체크포인트로 남기지 않는다. 망 가중치만 되살려도 22일째의 야드가 없다.
  (`run_month_training` 이 `ckpt_*.pt` 가 있는 폴더를 거절하는 것도 같은 이유다.)
- 조치: 부분 기록을 `outputs/v3/month-n2-interrupted-21d/` 로 **보존**하고,
  `outputs/v3/month-n2/` 에 **같은 설정 그대로** 처음부터 다시 돌린다.
  시드 9,900,702 · 초기화 9,900,702 · PRESERVE · COUNT_BALANCED · RL · feasible_first ·
  **workers 5**.
- ★**빠르게 하려고 설정을 바꾸지 않았다.** n1·n3 이 끝나 코어가 놀고 있으니 worker 를
  늘리면 빨라지지만, 그러면 세 판이 **시드 말고도 달라진다**. 추정 대상이 *"한 학습 절차의
  세 표본"* 이므로 절차는 글자 하나 같아야 한다.
- 이번에는 `setsid` 로 완전히 떼어 내 실행 환경이 배경 작업을 정리해도 살아남게 했다.
- ⚠️ 위 §"세 번 돌렸더니 서로 다른 정책" 의 n2 수치는 **중단된 판**(`month-n2-interrupted-21d`)
  에서 잰 것이다. 같은 시드라 재시작판도 같은 궤적을 그릴 것으로 보지만, 최종 표는
  재시작판이 끝난 뒤 다시 잰다.
