# YR-331-d — 100만원 보상 눈금의 근거 조사·자료 기반 교체

- **상태**: in-progress
- 사용자 지시(2026-09-28): “왜 100만원인지 근거를 조사하고 합당한 수치 또는 저 수치를 제외한 다른 수식으로 변경해”.
- 무엇: `reward_scale_krw=1_000_000`의 유입 경위를 찾고, 별도 기준 운전의 할인 누적 비용 표준편차(변동 크기)를 쓰는 식으로 교체한다.
- 왜: 기존 수치는 단위 선택일 뿐 산정·민감도 근거가 없고, 부하 보조 항과 더할 때 상대 크기에도 영향을 준다.
- 범위: v6 CPU·배열 학습의 보상 눈금 한 축. 네 비용 단가·상태·후보·학습망은 동시에 변경하지 않는다. 기존 단가의 경제적 타당성을 이 변경으로 인정하지 않는다.
- 성능 확증과 구분: 사용자 직접 수정 지시다. 이전 b의 성능·현실성 실패는 보존하며, 이번 검증은 수식·단위·저장·실행 정합에 한정한다.

## 실행 전 동결

1. 보정 입력은 기존 9911000 기준 운전의 고정 입력 파일 그대로다. 부하 3500/5000/7500, 21블록·42크레인, KEEP+SF-SPT 규칙, 가중치 갱신 없음.
2. 60초마다 원화 비용을 기록한다. `z_t=gamma^(dt/60)*z_prev-증가비용`, gamma=0.999. 첫날은 누적값만 이어가고 둘째·셋째 날의 z로 모집단 표준편차를 계산한다.
3. `r=-증가비용/std_ref(z)`; 평균을 빼거나 큰 손해를 잘라내지 않는다. 기준 원자료·계산 범위·소스·해시를 함께 저장하고 학습/평가에서는 다시 추정하지 않는다.
4. 별도 입력의 성능을 보고 기준 시드나 계산식을 고르지 않는다. 분산 0·비유한 값·잘못된 시간/비용 장부는 임의 상수로 대체하지 않고 거부한다.
5. 부하 보조 항은 선택 설정으로 남는다. `r + eta*(discount*P_next-P_now)`에서 eta=1은 별도 실험 가정이다. 눈금 교체가 해당 보상의 성능 개선을 보장하지 않는다.
6. 이전 체크포인트의 가치 출력 단위를 조용히 새 눈금으로 해석하지 않는다. 명시적 이전 설정은 과거 결과 재현용으로만 허용한다.

## 검증

- 직접 계산과 표준편차 식 대조, 원↔천원 전체 단위 변환 불변, 할인·시간 간격·비용 보존 검사.
- CPU와 배열 경로가 같은 자료 기반 눈금을 사용하며 이전 수치로 돌아가는 숨은 기본값이 없는지 검사.
- 기존 PPO/부하 보상 관련 시험과 변경에 관련된 배열 시험을 실행한다.
- 새 진단 시드 9900628, 7500건/일 입력의 첫 6시간, 보상 외 설정 동일, 실제 학습이 갱신되는지 검사한다. 짧은 실행은 정책 우열의 증거로 부르지 않는다.
- 문헌·기존 숫자의 경위·기각한 대안·실행 결과를 상세 보존하고 Dashboard·증거를 갱신한 뒤 commit·push한다.

## 현재 결과

문헌과 코드 이력을 확인했다. v5 초기 PPO 구현 `5a9e8dd1`에서 수치가 들어왔고 v6 `c06baafb`에 복사됐다. 현재 조사 범위에서 100만원의 최적성·항만 비용 근거는 확인되지 않았다.
정규화 방식은 PPO 공개 구현의 할인 누적 보상 표준편차를 참고하되, 이번 프로젝트에서는 별도 기준 운전으로 동결한다. 이 동결 방식은 우리의 재현성 선택이다.
기존 b의 `authorize-next`는 reliability가 이미 PASS라 해당 축 보정을 허용하지 않았다. 이 판정은 기존 실행 기록 정합에 관한 것이며 100만원의 산정 근거를 검사하지 않는다. 새 사용자 직접 수정 지시에 따라 눈금의 근거·구현만 고친다. 기존 performance/scenario 실패를 PASS로 바꾸거나 정책 성능 확증에 착수하지 않는다.
