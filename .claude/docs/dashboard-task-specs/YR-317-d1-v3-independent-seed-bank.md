# YR-317-d1 — 독립 시드 구성과 기존 합성곡선 보존

- **상태**: backlog
- 요청: 2026-09-16 사용자 “독립시드구성까지 진행”, “합성곡선까지는 준수”. parent: YR-317-d.
- 무엇: 기존 v3 생성기를 그대로 호출해 30일 입력 20개를 만들고 시드·요청·본선 계획·초기 상태의 지문을 고정한다.
- 왜: 날짜 시드가 월 시드+1,000×날짜로 파생되므로 월 시작 숫자만 바꾸면 난수열이 겹칠 수 있다. 성능 평가 전에 독립 입력과 정책 간 공통 요청을 검증한다.
- 보정 축: reliability(시드·입력·코드의 정합). 입력 생성이며 정책 성능 실험이나 g의 미투입 보정 완료가 아니다.
- 새 독립 입력은 시작 20,000,000, 간격 100,000, 20개, 실행당 30일. 기존 사용 시드·날짜 및 블록 파생값을 대조한다.
- 곡선: 기존 diurnal_rate/diurnal_arrivals 그대로. 24시간 균등 성분 38%, 나머지는 10/15/21시 중심의 기존 세 봉우리다.
- 기존 하루 물량 3,500/5,000/7,500/12,500/15,000과 추첨확률 0.30/0.30/0.25/0.10/0.05를 유지한다. 물량과 곡선을 평탄화하거나 쉬운 시드를 선별하지 않는다.
- 같은 월 안에서는 운영 상태를 이어가는 기존 계약, 월 사이에서는 새로운 초기 상태를 쓰는 계약이다. 각 정책은 같은 월의 동일 입력을 받는다.
- 반출/반입 전환 등 기존 생성기의 대체 동작도 발생 수를 숨기지 않고 기록한다. 전체 요청 처리 가능성이 입증됐다는 의미는 아니다.
- 기존 실행의 초기 장치율 0.45를 유지하고 원고 표의 0.65와 구분한다. 이 입력 구성에서 환경을 임의로 바꾸지 않는다.
- 생성된 입력만으로 20개 성능 평가가 완료됐다고 보고하지 않는다. 정책 수·평가 표본수의 최종 계약은 성능을 보기 전에 별도 고정한다.
- 자원: 사용자 허용 상한 14코어 이내, 기존 v5 코어 23 유지. 생성은 기존 시뮬레이션을 실행하지 않는다.
- 완료 기준: 실제 20개 입력 생성, 파생 난수 중복 없음, 곡선·물량 규칙 일치, 동일 생성 재현·파일 무결성 검사, 원자료와 Dashboard 반영 및 push.
