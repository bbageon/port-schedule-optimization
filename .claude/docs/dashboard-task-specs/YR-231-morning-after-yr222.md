# YR-231 · YR-222 정책도 오전에 손해를 보는가

> Epic RL · 상태 ✅ **완료** 2026-08-25 · 사용자 물음 *"문제가 있는데 이득이라고 나왔다는 거야?"*
> [[YR-227]] 을 **새 정책**으로 반복 · 같은 시드·같은 창

## 1. 왜 이 측정인가

[[YR-227]] 의 *"오전 라벨 부호가 반대"* 는 **[[YR-220]] 정책**을 잰 것이다.
그런데 [[YR-229]] 에서 기준선을 이긴 것은 **[[YR-222]] 정책**이다. 안 재고
*"라벨이 문제다"* 라고 말한 것은 성급했다.

## 2. 결과 (같은 4일 · 같은 창 · 8코어 44분)

## 3. ★그런데 라벨은 하나도 안 고쳐졌다

| 정책 | 오전 라벨 부호 틀림 | 라벨 평균 | 실제 평균 |
|---|---|---|---|
| [[YR-220]] | **8/8** | −282,114원 (이득이라 함) | **+13,107,911원 (손해)** |

**라벨은 여전히 오전을 "이득" 이라고 말한다 — 실제와 28배 반대다.**

## 4. 판정 — 사용자 물음에 답한다

> *"문제가 있는데 이득이라고 나왔다는 거야?"*

**그렇다. 문제는 그대로 있고, 이득은 문제를 우회해서 났다.**

| | |
|---|---|
| 라벨이 오전에 반대를 가르치나 | **여전히 그렇다** (6/8 · 28배) |
| 그런데 정책은 왜 좋아졌나 | 표본 5배로 **오후의 옳은 신호가 더 잘 잡혀** 오전 오류를 눌렀다 |
| 근본 원인은 고쳐졌나 | **아니다** — 부하 5,000 오전 손해 **+5,546만원**이 그대로다 |
| 그래서 부하 5,000 은 | **여전히 손해** (+6,273,522원 · [[YR-229]]) |

**표본 확대는 증상 완화이지 원인 제거가 아니다.**

## 5. 다음 축의 우선순위를 정한다

라벨이 안 고쳐졌는데 정책이 오전 거래를 줄인 것은, 망이 **다른 특징으로 우회**해
배웠다는 뜻이다. 그 우회는 부하 3,500 에서만 통했다.

| 축 | 판단 |
|---|---|
| **[[YR-230]] 정보** | 오전 이연의 목적지 혼잡을 볼 칸이 **없다**. 우회 학습이 한계에 부딪힌 이유일 수 있다 |
| **[[YR-227]] 라벨** | 여전히 28배 반대다. 고치면 우회가 필요 없어진다 |

**둘 다 살아 있다.** 다만 정보 축이 없으면 라벨을 고쳐도 배울 수단이 없으므로
**[[YR-230]] → [[YR-227]] 순서**를 권한다.
