# YR-317-f — 실제 사용자와 상호작용 맥락

- **상태**: backlog
- 무엇: 터미널 운영자·운송사 배차 담당자·운전자 역할과 검토·수정·거절 흐름을 원고에 명시한다.
- 왜: 소프트웨어 정책끼리의 동의는 인간의 의사결정 지원이나 HCI 검증을 대신하지 않는다.
- [사용자 설계 전체](../strategy-history/2026-09-14-v3-review-hci-reproducibility.md).
- 현재 구현, 제안한 사용 시나리오, 사용자 평가 결과를 구별한다. 외부 운영 시스템 연동은 범위 밖이다.
- 제안 화면은 기존·변경 배정, 알려진 혼잡·정원·통지 시간, 수정·거절 권한을 제시한다.
- 개별 후보의 미보정 점수를 정확한 원화 절감액·신뢰확률로 표시하지 않는다.
- 최소 개정은 사용자·권한·맥락 설명이다. HCI 효과 주장이 필요하면 실제 역할의 과업 평가를 설계한다.
- 역할별 2~3명 형성적 평가는 제안 규모일 뿐이며 정량 효과 확증을 보장하지 않는다.
- 완료 기준: 사용자 흐름·권한 표·사례와 평가 여부/한계 명시, 필요한 경우 사용자 평가 근거.
- 이번에는 사람에게 연락하거나 모집하지 않는다. 정책에 새 사람 승인 레이어를 구현하는 작업도 아니다.
- [현행 범위 §6](../strategy-history/2026-09-14-v3-review-refined-strategy.md): 이번 필수 대응은 사용자·권한·사용 맥락 서술이다.
- 사용자 과업 평가는 선택적 후속연구다. HCI 효과를 주장할 때만 필요 수준을 다시 정한다.
- 그림에서 현재 내부 정책 흐름과 향후 사람·제약층 연동을 구분한다. 사람의 동의·새 정원이 현재 구현됐다고 쓰지 않는다.
