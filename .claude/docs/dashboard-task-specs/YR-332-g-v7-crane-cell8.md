# YR-332-g — v7 크레인 ⑧ 칸 처리 (사용자 결정)

- **상태**: backlog
- 상위: [[YR-332]]. 파생: [[YR-332-b]] 이식 중 발견(2026-11-04). [[YR-332-c]] 학습 전에 정한다.

## 무엇이 문제인가

⑧ `n_cands` 는 이름이 *지금 고를 수 있는 후보 수* 인데 v4 부터 실제로는 다른 것을 쟀다.
없는 속성(`gc._siblings`)을 읽어 늘 대안 계산 `_live_cands` 로 떨어지고, 그 계산은 상태가
`WAITING` 인 일감 = **블록에 도착해 기다리는 트럭 수**를 센다(`src/yard_rl/v4/crane/features.py:93,99-110`).

즉 ⑧ = min(줄 길이/18, 1). 새로 넣은 ⑨(줄 길이/10)와 18대 이하에서 같은 정보다.

**[[YR-315]] 의 전제 *"크레인이 줄 길이를 못 본다"* 는 반만 맞다** — v4 크레인은 18대까지 보고 있었고,
18대를 넘으면 구분하지 못했다. 붐비는 날 줄이 18대를 자주 넘는지는 아직 재지 않았다.

## 선택지

1. **원래 뜻대로 고친다 — 지금 고를 수 있는 실작업 수(권장).** 크레인 결정의 70%가 할 일이 하나뿐이었다
   ([[YR-326]] 단계 0 실측). 이 칸이 *진짜 고르는 순간인가* 를 알려 준다. v7 은 이전 세대와 비교하지 않으므로
   v4 연속성을 지킬 이유가 약하다.
2. **뺀다 — 8칸.** ⑨ 가 줄 길이를 이미 본다.
3. **그대로 둔다.** v4 와 같은 식을 유지한다.

## 함께 재야 할 것

붐비는 날 블록 줄 길이 분포 — 18대를 넘는 결정이 얼마나 되는지. 넘는 경우가 드물면 ⑨ 의 추가 정보도 작다.
