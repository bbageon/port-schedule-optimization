## 고정할 생성 규칙 — fixed-cargo-v2

1. 진단 시드 9900306·30일. 원래 날짜 계획·트럭 수·종류·블록·통지·도착·주행을 유지한다.
2. 본선의 기존 종류·작업량·시작·간격·블록을 유지한다. 초기 적재·컨테이너 규격도 유지한다.
3. 초기 재고, 트럭 반입, 본선 양하에서 고유한 컨테이너 명단을 만든다. 번호는 엔진 생성 규칙과 같다.
4. 재입고 이력 없는 같은 컨테이너의 출고는 최대 한 번이다. 출고 없는 기말 재고는 허용한다.
5. 반출 트럭의 계획 블록 도착, 선적 작업의 계획 해제 시각 순으로 고정 대상을 배정한다.
   동시각은 작업 키 순서. 블록별 별도 난수 `v5:fixed-cargo-v2:<seed>:<block>`를 쓴다.
6. 그 시각까지 계획상 유입된 미배정 컨테이너 중 균등 추첨한다. 위치·꺼내기 쉬움은 보지 않는다.
   없으면 가장 먼저 유입될 미배정 상자를 고르고 대기 예정으로 기록한다. 주문 시각은 바꾸지 않는다.
7. 배정 즉시 후보에서 제거한다. 미래 상자도 다른 반출·선적에 중복 배정하지 않는다.
8. 해당 블록의 전체 공급도 부족하면 생성 실패와 부족 수를 기록한다. 물량 삭제·종류 전환·가짜 공급 금지.
9. 바뀔 수 있는 트럭 필드는 `target`, `con_no`, 반출의 내부 규격 `size_ft40`뿐이다.
   반출 규격은 새 고정 상자와 일치시킨다. 공개 오더 6항목은 늘리지 않는다.
10. 본선 선적의 `targets` 목록을 전부 지정한다. 양하 규격은 기존 엔진의 난수·비율과 동일하게 재현한다.
11. 화물 수출·수입 구분 자료는 없으므로 초기/트럭/본선 공급을 같은 블록 재고로 다룬다.
    트럭→트럭·본선→본선 연결도 금지하지 않는다. 연결 수·규격·계획 체류 분포를 보고하고 실측 분포라 주장하지 않는다.
12. 생성기는 정책·실행 이력을 읽지 않는다. 예정 공급 시각은 실제 도착·적치 완료 시각이 아니다.

## 검사와 실행 범위

- "반출 트럭이 상자보다 먼저 도착"은 중복/출처 부재와 구분한다. 정적 감사에서 대기 예정으로 보고한다.
- 실제 꺼내기는 컨테이너 준비 후에만 가능하다. 실제 위치·재배치 후 후속 작업 추적은 실행기 검증 대상이다.
- 이번 작업은 생성기·파일 저장/읽기·입력 감사·시험까지다. 정책 학습과 30일 물리 완주를 주장하지 않는다.
- 기존 기본 생성기와 PPO 진입점은 새 데이터로 자동 교체하지 않는다. 실행기 수용 검증 전에 자동 학습 금지.
- 소규모 시험: 초기/반입/양하 출처, 고정 선적, 중복 방지, 공급 부족, 미래 도착 대기, 결정론·파일 훼손 검출.
- 운영 규모: 같은 원본 30일 명단의 변경 허용 필드 외 완전 일치, 모든 출고의 고정 대상·출처 확인.
- 같은 규칙을 두 번 생성하여 압축 데이터 파일 검증값까지 비교한다. 출력 경로는 매번 새로 만든다.
- 초기 물리 재고와 공개 오더 6항목을 검사하고, 실행 기록은 비어 있는지 확인한다.
- 데이터 입력 타당성, 실행기 호환성, 현실성·성능은 별도 판정한다. 정적 통과를 학습 가능으로 승격하지 않는다.
