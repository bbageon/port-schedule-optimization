# YR-317-e — 온라인 처리시간과 재현 묶음

- **상태**: 계측 구현 완료 (2026-09-22) · 측정 실행은 [[YR-318]] 캠페인에서 함께 한다
- 무엇: 후보 구성부터 제안·수락·정원 확인·확정까지 전체 경로를 실제 시간으로 잰다.
- 왜: 반사실 호출 0회와 빠른 망 추론만으로 실시간 전체 처리를 입증할 수 없다.
- [HCI·재현성 §4·5](../strategy-history/2026-09-14-v3-review-hci-reproducibility.md).
- 정본 코드 식별은 YR-317-a, 기존 평가 경로의 건전성은 YR-317-g와 연결한다. 새로운 정원 경로는 추가하지 않는다.
- 대표·혼잡·최대 후보 상태를 나누고 중앙/P95/P99/최대 시간과 60초 주기 초과율을 보고한다.
- P95는 100번 중 느린 5번이 시작되는 값이다. 외부 통신·사람의 응답은 별도 구간이다.
- 하드웨어·스레드·초기 구동·예열을 기록하고 상태 진행용 시뮬레이터 비용과 정책 비용을 구분한다.
- 공개 묶음: 설정·시드·가중치 해시·명령·의존성·특징·학습식·후보·원자료·표 재생성 명령.
- 완료 기준: 재현 가능한 계측 표와 실행 명세, 실제로 측정한 범위와 한계 표시.
- 문서 준비는 가능하나 이번 전략 작성에서는 벤치마크를 실행하지 않는다.
- [현행 전략 §6](../strategy-history/2026-09-14-v3-review-refined-strategy.md)와 [평가 설계 §8](../strategy-history/2026-09-14-v3-review-evaluation-detail.md)을 우선한다.
- review 전체를 직접 재고 step·망·resolver의 중첩 시간을 이중 합산하지 않는다. 빈 주기/제안 있는 주기를 나눠 보고한다.
- 9/15 [개정 전략의 시간·재현성 절](../../../docs/paper/v3/paper-revision/01-독립반복-부하별효과.md)에 60초 검토 주기·3시간 학습 관찰·30/90일 평가를 구별해 기록했다.
- 원고 §4·재현 자료에 실제 초기 장치율·설정·가중치 지문을 실행과 대조해 싣는다. 이번에는 문서 작성만 했으며 처리시간 측정값을 새로 생성하지 않았다.

## 9/22 — 계측을 실제로 넣었다 (측정은 아직)

- `MarketBridge(measure_latency=True)` 로 **옵트인**. 끄면 기존 경로와 완전히 같고,
  `MonthResult.online_latency` 는 빈 표다. 시험이 껐을 때·켰을 때 **일별 비용이 같음**을
  확인한다 — 계측이 결과를 바꾸면 계측이 아니다.
- **무엇을 재나**: 60초 검토 주기 하나에서 후보 구성·채점·경합 해소(`decide_s`)와
  확정(`commit_s`). `latency_summary()` 가 평균·p50·p90·p95·p99·최대·60초 초과 건수·
  결정이 차지한 비율·장부 정리 누계를 돌려준다.
- **무엇을 뺐나**: ①시뮬레이션 진행 자체 ②학습 전용 스냅샷 복제 — 평가 시점에 존재하지
  않는 비용이라 넣으면 이중 계산이 된다. 이 범위를 `scope` 문자열로 결과에 같이 박는다.
- 표본은 주기마다 하나씩 그대로 모은다(30일이면 43,200개, 메모리 수 MB). 백분위를
  누적 통계로 근사하지 않는다.
- ⚠️ **아직 측정값이 없다.** `NO_REALLOC` 은 결정 주기 자체가 없어 표본이 0이다.
  실제 수치는 정책 팔이 도는 [[YR-318]] 에서 나온다(사전등록에 `measure_latency=true` 명시).
- 원고 §5.6 은 여전히 *"온라인 처리시간은 측정되지 않았다"* 로 둔다 — 장치만 만든 것과
  측정한 것을 구분한다.
