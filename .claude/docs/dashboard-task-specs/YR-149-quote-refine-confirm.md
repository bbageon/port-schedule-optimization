# YR-149 — 견적·평가 정렬 → 파급 원인 진단 → 이송 효과 확증

- **Epic**: RL / **Priority**: 🔴 / **등록일**: 2026-08-04 / **범위 정정**: 2026-08-05
- **상태**: backlog
- **선행 근거**: YR-133은 2블록·반입·SF 실행정책에서 견적 교환과 시뮬레이터 내부
  원자 이송을 기능 실증했다. 이송 14건·완주 전판·KEEP 이송 0이었지만, 8개 에피소드
  쌍의 `QUOTE−KEEP` 총비용은 `−15.58~+19.11`로 흔들려 비용효과는 미확증이다.

## 연구 범위

- 외부 TOS는 **최초 블록 배정이 이미 끝났다는 배경·입력 스냅샷**으로만 둔다.
- 실제 TOS/ECS API, ACK/NACK, route lock 동기화, 운영 배포 가능성은 구현·평가하지 않는다.
- `TransferResolver`가 설정된 허용 블록 안에서 시뮬레이터 owner·queue·event·시간장부를
  원자 변경하는 연구 추상만 사용한다.
- 1차 효과 주장은 SF-SPT 실행정책·2블록·반입 조건으로 한정한다. 채택 PPO 정책과의 결합은
  견적 원리가 확증된 뒤 별도 통합축에서만 검토한다.

## 선결 정렬 — 결과 열람 전 고정

1. 견적과 실현 주지표를 YR-136의 **v2 실현 총비용**으로 통일하고 v1은 참고로만 보고한다.
2. YR-109의 달성 가능한 본선 마감을 켠다. 물리적으로 불가능한 `deadline_mult=0.5`를
   효과 판정에 쓰지 않는다.
3. `0.107`은 기능 발화를 위한 보정값으로만 보존한다. `κ_T=383.7초`는 잔차 1σ가 아니므로,
   최종 여유폭은 미열람 자료의 `예측 NetGain−실현 한계효과` 오차에서 별도로 동결한다.
4. source 이름순 첫 양수 선택이 아니라 같은 epoch의 허용 제안 중 최대 NetGain을 고르고,
   quote 발행 version과 commit version 일치를 직접 검사한다.

## 단계 — 각 단계는 별도 동결

### 1. 결정시점 반사실 진단

- YR-133의 이송 결정시점 상태를 복제해 같은 난수로 `KEEP`과 **그 이송 1건만** 각각 실행한다.
- 이후 이송은 끄거나 같은 행동으로 고정해 해당 결정의 효과를 분리한다.
- `truck / vessel / move / other`, source 기존 작업 이득, receiver 기존 작업 손실,
  완주·backlog를 나눠 기록한다.
- 14건은 진단 상태 수이지 독립 통계표본 14개가 아니다. 같은 에피소드의 여러 결정은 묶고,
  최종 통계 단위는 에피소드 seed 쌍으로 둔다.
- 사후 실현정보는 진단 라벨에만 쓰며 배포 견적 입력에는 넣지 않는다.

### 2. 누락항 하나만 보정

- 1단계 전에 판정 규칙을 고정하고, 괴리를 가장 많이 설명한 `source / receiver / vessel`
  파급 중 **한 축만** 선택한다.
- 현재처럼 receiver 기존 트럭 지연을 결과 전에 원인으로 확정하지 않는다.
- 목표식은 다음 양측 한계비용 계약을 유지한다.

```text
OutRelief(A,j) = J_A(KEEP j) - J_A(REMOVE j)
InBurden(B,j)  = J_B(ADD j) - J_B(NO ADD)
NetGain        = OutRelief - InBurden - TransferCost - uncertainty_margin
```

### 3. 보정 파일럿

- 비교군은 `KEEP / OLD_QUOTE / REFINED_QUOTE`이며 실행정책·시나리오·본선 가드·이송 상한은
  동일하게 둔다.
- 기능 가드와 함께 실제로 서로 다른 결정을 충분히 냈는지 `NO_EXPOSURE`를 검사한다.
- 파일럿 분산으로 운영상 최소 의미 절감폭 `δ`와 필요한 확증 표본 수를 결과 전에 동결한다.

### 4. 독립 확증

- 파일럿과 겹치지 않는 신규 시드뱅크를 사용하고 top-up은 금지한다.
- 표본 단위는 에피소드 seed 쌍, 주판정은 v2 실현 총비용의 짝지은 차이다.
- 완주 100%, backlog 0, 정책 예외 0, epoch당 이송 1건, 작업당 1회, owner·version·rollback
  연속성, route 비용 포함, 미래정보 미열람을 하드 가드로 둔다.
- 트럭 평균 A→O와 본선 초과는 사전 허용손실 안이어야 한다. P95는 보고만 한다.
