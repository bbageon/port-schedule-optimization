## 트럭의 게이트 체류시간과 추가 점수

트럭이 게이트에 들어와 작업을 끝낼 때까지 경과한 시간을 분 단위 `t`로 잰다. 모든 구간에서 기본 비용은 분당 1점이다. ③에서만 추가 비용률을 60분부터 90분까지 직선으로 높인 뒤 일정하게 유지한다. 누적 비용은 계속 증가한다.

- 그 시점의 분당 비용률은 `1 + a × min(1, max(0, (t − 60) / 30))`점이다.
- `t`분까지 누적 비용은 `C(t) = t + a × H(t)`점이다. `H(t)`는 60분 이하에서 0, 60~90분에서 `(t − 60)² / 60`, 90분 이상에서 `t − 75`다.
- 결정 뒤 30분의 학습 비용은 해당 블록의 각 트럭에 대해 구간 시작과 끝의 누적 비용 차이를 합산한다. 두 시각은 해당 트럭의 게이트 진입과 완료 사이로 잘라 계산한다. 예를 들어 55분에서 85분까지 관측한 트럭은 `C(85) − C(55)`점만 보탠다. 기본 시간과 추가 점수를 합치고 기존 본선 항을 더한 비용에 음의 부호를 붙인다.
- 부두 대기료는 20·40피트 공통으로 1시간 초과 시 30분당 20,000원이다. 고시 시계는 도착요청 시각에서 상·하차 및 송장 발급 완료까지다. 연구는 60분 기준과 30분 단위를 참고했다. 가중치를 부드럽게 올리는 방식과 크기는 연구 가정이다. 원화 평가는 방문별 시각·증빙을 대조하는 [별도 과제](YR-332-bk-truck-turnaround-krw-valuation.md)를 따른다. [국토교통부 고시 제2026-595호 별표 1 제24호](https://www.law.go.kr/LSW/flDownload.do?flSeq=171123011#page=25)

## 학습용 원장으로 정한 곡선 강도

첫 실험의 강도는 기존 정책으로 굴린 첫 학습 월에서 추가 점수 합계가 트럭 기본 점수 합계의 10%가 되게 정했다. 10%는 트럭 쪽 비중을 소폭 높이는 실험자의 선택이다. 다른 월의 가산 비율은 실제 경과시간에 따라 달라진다.

- [학습 월 실행 기록](../../../outputs/reports/yr332_short_window/runs/wave-0-0.json)의 완료된 트럭 작업 241,000건을 썼다. 입력 시드 12104101, 배차 표집 시드 9961101. 시험 월 성적은 계수 계산에 쓰지 않는다.
- 트럭 시간 합계 53,180,672.9536분, 가중치 적용 전 `H(t)` 합계 43,407,407.8014분. 따라서 `a = 0.10 × Σt / ΣH(t) = 0.1225152011`이다. 75분의 비용률은 1.0613점/분, 90분 이후는 1.1225점/분이다.
- 다음 코드는 프로젝트 루트에서 학습 원장이 있는 경우에 재현할 수 있다. 압축 원장의 SHA-256은 `f8cc495c8551321b5772877a8ee6f5a18df412a05da214f6f568a32ba8cea013`이다.

```python
import gzip
import json
from math import fsum

path = "build/yr332_joint_turnaround/short-window/wave-0-0/trucks.jsonl.gz"
with gzip.open(path, "rt", encoding="utf-8") as stream:
    rows = (json.loads(line) for line in stream)
    minutes = [(row["finish"] - row["gate"]) / 60 for row in rows]

def extra_minutes(t):
    ramp = min(30.0, max(0.0, t - 60.0))
    return ramp**2 / 60.0 + max(0.0, t - 90.0)

assert len(minutes) == 241_000 and min(minutes) >= 0
print(0.10 * fsum(minutes) / fsum(map(extra_minutes, minutes)))
```

## 판정

같은 30일 입력을 마지막 물량까지 모두 처리한 뒤 트럭당 평균 턴타임과 척당 평균 본선 작업시간을 각각 비교한다. 두 평균이 모두 낮아질 때 공동 개선으로 판정한다. 반입·반출별 상위 5% 경계, 같은 트럭 중 더 오래 걸린 비율, 60분 초과 비율과 미완료 수도 함께 본다. 월 가중합과 ③의 곡선 점수는 모든 방식의 원장에 동일한 식을 적용해 비교한다. 이미 살펴본 BP 시험 월의 결과는 탐색 비교로 표시한다.

## 시험 월과 현장 자료의 시간 대조 (2026-11-25)

기존 보류는 하루 단위 규칙 비교의 [선행 판정](../../../outputs/reports/yr332_short_job_audit/current-gates.json)을 읽은 결과다. 해당 파일은 두 시간 항목을 ‘미수집’으로 기록했다. 이번에 13일의 현장 요청 메시지와 30일 BP 시험 월을 동일한 시각 경계로 직접 비교했다. 기존 원본 600개는 모두 파일 지문이 같았다. 추가된 부산항만공사 통계 CSV 4개는 연·월별 집계다. 공개 산출물은 컨테이너 오더별 시간을 묶은 통계다. 90% 경계는 100건 중 90건이 그 시간 안에 끝나는 지점이다. 현장 표본은 같은 컨테이너·트럭·방향의 명시 시각이 연결된 경우에 해당한다. 확인된 게이트 오더는 반입 15,620건·반출 18,083건이고, 이 중 블록→완료를 비교할 수 있는 표본은 6,358건·12,074건이다. 시험 월 206,500건의 게이트→블록 시간은 각각 시험 입력의 이동시간과 일치했고 전부 3~7분이었다. 현장 반출은 2,526건이 7분을 넘겼다. 이 차이에는 이동 중 정체, 방문 내 작업 순서, 신고 시각 차이가 기여할 수 있으며 비중은 분리되지 않았다.

방문 구성도 확인했다. 기존 차량·게이트 시각 묶기 규칙으로 오더가 한 건이고 재스캔이 없는 방문만 남기면, 현장 반출 7,784건의 중앙값은 4.43분, 90% 경계는 **7.08분**, 7분 초과는 799건(10.26%)이다. 단독 반입 7,535건의 90% 경계는 7.47분이다. 반출 전체의 14.93분을 단독 트럭 주행시간에 일괄 적용하면 방문 구성의 차이까지 주행에 반영할 수 있다. 이 분류는 보유 오더에 근거한다.

현장 자료의 `work_min`은 블록 도착→작업 완료다. 작업 시작을 기록하는 사건이 없어 이 구간에 섞인 대기와 실제 크레인 작업을 나눌 수 없다. 특히 반출의 블록→완료 상위 구간 차이는 크지만 표본 포함률·혼잡도·운영 조건도 달라 원인을 크레인 속도로 단정할 수 없다. 협회가 제시한 ‘2~3분’은 대기를 제외한 장비 한 사이클의 전형적 평균이다. [PEMA 원문 대조](YR-238-pema-crane-anchor-reaudit.md)

**판정**. 게이트 기준 보상 계산은 검산을 통과했다. 현장 반출과 시험 월의 차이는 방문 구성을 맞추면 작아지고, 시험 월의 7분 상한을 넘긴 단독 방문도 남는다. 크레인 단독 시간은 확인할 현장 자료가 부족하다. 30일 재학습 보류를 유지한다. 이 과제의 남은 근거는 복수 오더·재스캔 사례의 실제 방문 내 작업 순서와 오더에 연결되는 장비 작업 시작·완료 기록이다. 정책을 비교할 시험 월에 맞춰 입력 계수를 조정하지 않는다.
