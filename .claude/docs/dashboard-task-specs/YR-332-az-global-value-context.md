# YR-332-az — 비용 예측망에 전역 대기 요약 한 칸을 제공하는 비교설계

**상태**: done
완료: 2026-11-18. 예측 진단은 완료했으며 사전 기준 미달로 조건부 PPO 단계는 실행하지 않았다.
등록: 2026-11-17. 사용자: “그럼 지금 어떻게 수정할껀지 검토해서 알려줄래?”
관련: ax 저장 경험 진단, ay 비용 예측 목표 정규화 비교. 보정 대상은 performance다.

## 무엇·왜

- 21블록·42크레인에서 같은 Transformer 정책을 쓰지만, 현재 비용 예측망도 해당 블록 후보와 시각만 본다.
  목표는 터미널 전체의 남은 24시간 비용이므로 관찰 범위와 예측 대상 사이에 차이가 있다.
- ax에서 물량·시각별 예측 오차가 남았다. ay의 PopArt(예측 단위를 보존하는 목표 정규화)는
  기존 대비 총비용을 7.55% 줄였지만 새 검증 예측 정확도의 전반 개선은 미확인이다.
  반출 +1.98%, 본선 지연비용 +0.74%로 보호 조건도 미달이다. 정규화를 해결책으로 채택하지 않았다.
- 가설: 같은 블록 상태에서도 터미널의 현재 대기 규모를 알면 비용 예측 기준이 개선될 수 있다.
  전역 정보 부족이 성능 손실의 확정 원인이라는 주장이 아니며, 음수 신호 비율을 성공 기준으로 삼지 않는다.
- 11월17일 요청은 수정안 검토였고, 11월18일 “이거 한번 검토해서 진행해볼래?”로 실행을 요청했다.
  두 단계 합성 진단을 승인한 것으로 기록한다. 기본 정책 채택·현실성 통과를 의미하지 않는다.

## 변경 한 축

- Transformer의 작업 선택 입력 10칸·두 갈래 구조·너비32/헤드4/층2는 유지한다.
- **비용 예측망에만 전역 대기 오더 수 요약 1칸을 추가**한다. 정책 선택 점수 경로에는 연결하지 않는다.
- 대기 오더는 `block_arrival <= snapshot_time < service_start`인 외부 트럭 작업이다.
  `sum(sim.kpis.waiting_count())`를 사용한다. 실제 줄 선 차량 수·방문 수와 같다고 주장하지 않는다.
  같은 시각에 review와 도착/작업시작이 겹치면 기존 사건 순서를 따른 처리 완료 상태를 기준으로 한다.
  타임스탬프만 같고 아직 처리하지 않은 사건을 사후 대기값으로 끌어오지 않는다.
- 추가 입력은 `log1p(total_waiting_orders) / log1p(21 * 10)`이다.
  21블록과 기존 블록 대기 눈금10을 기준으로 고정하며 상한 절단·평가자료 보정은 하지 않는다.
- 기존 후보 수·대기시간 상한, 작업 종류 정보, 행동 선택 규칙, 보상·비용 단가·24/26시간 창은 유지한다.
- COMA(선택별 반사실 기여 평가), 짧은 보상창, 전체 작업 공동 배정, 추가 정책망은 결합하지 않는다.

## 같은 시각의 관측 계약

- `MultiBlockTerminal.run`은 블록을 결정까지 따로 전진시킨다. 결정 중 다른 블록 객체를 직접 읽으면
  그 블록의 시계가 앞서 있을 수 있다. resolver에서 임의로 전 블록의 현재 값을 합산하지 않는다.
- `stage/episode.py`의 기존 `review(m, t)`에서 전 블록이 같은 시각에 정지한 것을 확인한 뒤
  공개 접수·원장 동기화와 같은 경계의 대기 요약을 불변 스냅샷으로 저장한다. 결정 주기를 추가하지 않는다.
- 시작 시각0에도 명시적으로 스냅샷을 만든다. 누락 값을 대기0으로 조용히 대체하지 않는다.
- 결정 시각보다 늦지 않은 마지막 스냅샷만 사용한다. 다음 경계 값·하루 총수요·미래 도착·최종 비용은 입력 금지다.
- 원자료에는 시각·블록별 대기 수·합계·결정 블록·스냅샷 경과시간을 기록한다.
  이 감사용 값들을 새 신경망 입력으로 함께 늘리지 않는다. 값의 지연 분포를 결과에 보고한다.
- 초기화·동기화 후에는 모든 활성 블록의 시각, 합계 일치, `snapshot_time <= decision_time`을 검사한다.

## 코드 변경 지점

| 위치 | 수정 내용 |
|---|---|
| `src/yard_rl/v7/stage/episode.py` | 기존 초기화·review 경계에서 읽기 전용 전역 요약 전달 |
| `src/yard_rl/v7/crane/on_policy.py` | 마지막 관측 보관·정보 시점 검사·결정 표본에 관측 근거 저장 |
| `src/yard_rl/v7/crane/actor_critic.py` | 상태 묶음에 전역값 추가, 비용 예측 입력만 1칸 확장; 구형 설정 호환 |
| `src/yard_rl/v7/crane/value_normalization.py` | 양쪽에 동일한 기존 정규화 경로 적용; 정규화 식·계수 변경 없음 |
| 신규 수집·학습·평가 스크립트 | 전역 관측 포함 저장 형식·전체 체크포인트·공통 비교 설정 별도 동결 |

- 과거 av/ay 실행 소스·해시는 과거 커밋에서 보존한다. 변경된 현재 코드로 예전 소스 검사 통과를 주장하지 않는다.
  이전 실험 재현은 해당 커밋의 별도 체크아웃을 사용하고, 신규 결과·명세·해시는 별도 경로에 저장한다.
- 구형 `encode_sample/decode_sample`에는 전역값이 없다. 신규 형식을 명시하고 필드 유실·조용한 기본값을 금지한다.
- 작업 선택과 비용 예측은 Transformer 표현 일부를 공유한다. 전역값은 선택 입력에 직접 들어가지 않지만
  비용 손실이 공유 표현의 학습을 바꿀 수 있다. actor/critic 분리까지 동시에 시험하지 않는다.

## 비교를 성립시키는 조건

- 대조군과 변경군 모두 같은 확장 구조를 사용한다. 대조군은 추가 칸에0, 변경군은 실제 전역 요약을 넣는다.
  두 군 모두 원래 요약을 감사용으로 저장하되, 대조군 신경망이 읽지 못하는지 검사한다.
- 같은 시작 가중치를 복사하고 새 입력 열은0으로 초기화한다. 초기 정책 점수·행동은 같아야 하며
  초기 비용 예측도 수치 허용오차 안에서 같아야 한다. 새 Adam으로 시작하고 완전 이어학습이라 부르지 않는다.
- PopArt는 양쪽에 동일하게 고정한다. 비교 대상은 ay 정규화 조건에서의 전역 정보 추가 효과다.
  이것은 PopArt의 기본 정책 채택이나 그 방법의 일반적 우월성을 뜻하지 않는다.
- 기존 학습 표본 파일만으로 전역 대기 이력은 복원되지 않는다. 평가 원장을 학습용으로 바꿔 쓰지 않는다.
- 첫 예측 진단은 동일한 고정 정책이 만든 공통 경험으로 두 가치 예측기를 비교한다.
  작업 선택과 공유 표현은 고정하고 비용 예측 부분만 같은 예산으로 맞춰, 입력 정보의 추가 설명력을 본다.
  날짜 전체로 학습/검증을 나눈다. 같은 날의 결정들을 무작위로 나눠 독립 검증이라 부르지 않는다.
- 이 진단이 실패하면 전체 재학습으로 자동 확대하지 않는다. 통과 기준·표본 수·고정 행동 정책은
  수치 관측 전에 별도 실행 사전등록과 campaign.json으로 동결했다.
- 조건이 갖춰진 정책 비교의 제안 예산은 같은 초기값3쌍, 모델당12합성일·6갱신,
  갱신당2048표본·4반복이다. 새 입력 날짜·물량·난수·계산 예산·최종 모델 사용을 실행 전에 동결한다.
- 각 정책의 새 경험은 달라진다. 서로 다른 정책의 관측 결과를 같은 상태의 인과 비교로 해석하지 않는다.
  비용 예측의 공통 경험 진단과 각 정책의 실제 운영 성능을 분리해 보고한다.

## 검증·판정

1. 전역 관측을 기록만 할 때 기존 고정 정책의 후보·행동·사건·비용·난수 흐름이 재현되는지 확인한다.
2. 고정 가중치에서 전역값만 바꾸어도 작업 점수와 선택 확률이 불변인지 확인한다.
3. 미래 시각·합계 불일치·관측 누락은 실패시킨다. 표본 저장/복원·초기 확률 재현을 검사한다.
4. 새 날짜의 비용 예측 오차와 물량·시간대별 오차를 평가한다. 양수 신호50% 같은 임의 목표를 두지 않는다.
5. 정책 비교의 1차 지표는 터미널 총비용이다. 반입·반출·양하·적하 시간, 24/26시간 미완료,
   본선 지연비용을 병기하고 기존 보호 기준을 완화하지 않는다. 평균 트럭 시간만으로 성공 처리하지 않는다.
6. 짧은 실작업 우선 규칙도 같은 새 입력에서 다시 실행한다. 과거62.125분이나88.770분과 직접 대조하지 않는다.
7. 결정·원장·모델·설정·코드 증거를 일치시키고 성능·신뢰성·현실성을 각각 판정한다.

## 착수 조건과 한계

- 별도 [실행 사전등록](../../../docs/research/v7-discharge/global-value-context-prereg.md)을 결과 관측 전에 동결한다.
- 운반 흐름i·대기열 정의f의 현실성 선결은 유지한다. 과거 ay 승인을 승계하지 않고 이번 새 요청을 근거로 한다.
- 게이트의 현실성 선결 거절은 [authorization](../../../outputs/reports/yr332_global_value_context/authorization.json)에 보존한다.
  공통 경험 예측 기준을 통과한 경우에만 PPO 비교로 확장하며 기본 정책은 유지한다.
- 전역 대기 한 칸이 충분한 상태라는 보장은 없다. 이 결과로 전역 상태의 효과 전체를 기각/입증하지 않는다.
- 중앙 비용 예측은 배경 난이도를 설명하는 방법이다. 개별 선택의 인과 기여 분리나 블록 간 공동 제어를 보장하지 않는다.

## 실행 결과와 판정

- 같은 고정 행동 정책의 12학습일·9검증입력에서 30,720개 결정(학습12,288·검증18,432)을 모았다.
  비용망만 200회 전수 반복한 3쌍 비교다. Transformer 표현·작업 선택 가중치는 바꾸지 않았다.
- 전체 예측 오차 1.412691→1.307982(−7.41%). 세 시작 모델은 각각 −7.48/−6.92/−7.82%다.
  물량3,500/7,500/15,000건에서는 −5.95/−6.01/−7.78%였다.
- 00~06/06~12/12~18/18~24시 변화는 −9.97/−6.20/−3.82/+5.42%였다.
  마지막 시간대가 사전 악화 허용치5%를 넘어 예측 진입 조건은 미통과다. 기준을 바꾸지 않았다.
- 5%는 추가 정책 실험을 결정하는 실용적 기준이다. 작은 경계 차이를 통계적 확증으로 부르지 않는다.
  예측 오차 개선을 트럭·본선 시간 개선으로 해석하지 않는다. 기본 정책·비용·음수 신호는 유지했다.
- PPO 재학습·규칙 재평가·새 정책의 트럭/본선 성능 비교는 미실행이다. holdout9입력도 사용하지 않았다.
- 관련 시험20건, 6개 예측 학습의 가중치·Adam 상태 완전 재현, 공통 경험1회 재현을 통과했다.
  트럭182,000오더·블록 대기 스냅샷4,271,442개·결정 관측152,797개를 원자료와 대조했다.
  저장 표현189건 재계산과 모든 목표·전역 입력·저장 모델 예측값을 검산했다.
- 관측 지연은 24시간 전 평균9.14초·95%가32.13초 이내·최대59.99초다.
  24시간 뒤에는 마지막 관측을 유지하며 이 구간은 학습에서 제외했다. 관측 시점의 미래 누출은 없었다.
- 운반i·대기열f의 외부 자료가 없어 현실성 미통과는 유지한다. 새로운 가설·정책 채택으로 자동 확대하지 않는다.
