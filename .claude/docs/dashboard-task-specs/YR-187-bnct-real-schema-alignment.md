BNCT TOS(Oracle `HITOPS3_TSS_OPR`/`HITOPS3_VBS_OPR`) 중계 서버의 **프로시저

## ★정정 2건 (제공 문서의 매핑 오류 — 코드로 확인)

### ① `travel_base_s` ≠ `blockAvgTT`

```python
"travel_base_s": layout.gate_to_block_s(bid)   # = 거리 ÷ 속도
"travel_s":      _clamp_travel(그 값, resid)   # 오차 붙은 실현
```

`travel_base_s` 는 **게이트→블록 주행 기준시간**이지 블록 체류가 아니다.
올바른 대응은 `travel_s` 의 **블록별 집계값**이다.
`blockAvgTT` 는 오히려 `blockInTime→jobDoneTime`(재배치가 줄이려는 값)일
가능성이 크다 — **실제 정의 확인 필요**.

### ② `fallback_reason` ≠ `conSwapReason`

```python
"fallback_reason": "no_free_target" if (want_out and not out) else None
```

이건 재배정 사유가 아니라 **합성 생성기가 반출 대상을 못 찾은 흔적**이다.
`requested_flow` 와 함께 **실데이터로 가면 통째로 사라진다**.
`conSwapReason`(컨테이너 위치 변경 사유)은 **새 필드**로 따로 받아야 한다.

## ★결손 재평가 — "작업 시작 시각 하나"가 아니라 셋

| 결손 | 서사 B 영향 | 비고 |
|---|---|---|
| 작업 시작 시각 | 낮음 | 대기·작업 분리 불가. Φ 계산에는 불필요(블록도착→완료로 충분) |
| **크레인 개별 배정** | 없음 | 재배치는 블록 단위 결정. 단 **크레인 층 실측 검증은 영구 불가** |
| **본선 접안·하역 스케줄** | **중간** | Φ 의 7.5% + **크레인 경쟁의 원천**. 없으면 2단계 재구성이 왜곡된다 |

제공 문서는 본선을 "범위 밖"으로 처리했으나 **협의 대상으로 올려야 한다**.

## 추가로 필요한 것 (우선순위)

1. **본선 접안·하역 스케줄**(ETB/ETD·본선별 작업량) — 크레인 경쟁 재구성
2. **`VBS_RES_AVL` 실제 값**(`RES_TIME`·`YARD_CAPA`·`RES_AVL_CNT`) —
   [[YR-176]] 슬롯 용량의 **정본**. 우리 유도값(크레인 처리량)을 대체한다
3. **`blockAvgTT` 정확한 정의** — 정정 ①
4. **`REMAIN_TIME` 이력 보존 여부** — 스냅샷만이면 "도착 전 정보" 재구성 불가
5. **`expWaitingMin` 산출식** — 우리 견적식과 대조하려면 필요

**확인만 하면 되는 것**: `conLocFilter` 정규화 후 **블록이 몇 개인가**(21 아니면
무대 규모 재검토) · `inOutReserveTime` 이 구간인가 한 점인가.

### 목표 스키마 (11필드 → 13필드)

```python
{"doc_key": jid,                  # docKey/pinNo — 블록명 제거(Y08:D-… 는 합성 산물)
 # ── 블록: 1개 → 3개 + 사유
 "block_assigned": bid,           # conLoc          최초 배정
 "block_worked":   bid,           # moveLoc         실제 작업
 "block_previous": None,          # previousConLoc  변경 이력
 "swap_reason":    None,          # conSwapReason   ★새 필드
 # ── 시각: 1개 → 2개  (최우선)
 "reserved_s":     …,             # inOutReserveTime  예약 (정책 가시)
 "gate_in_s":      …,             # gateInTime        실현 (정책 비가시)
 # ── 유지 (정의·타입만 변경)
 "flow":       "GATE_IN"|"GATE_OUT",   # inOut (I/O)
 "target":     conNo,                  # 반입도 값 있음 → 60% → 100%
 "size_class": ("40","GP","42G1"),     # 불리언 → 범주형 (CNTR_SIZ·CNTR_TYP·ISO_TYP)
 "travel_s":      …,              # gateInTime→blockInTime      (실측 파생)
 "travel_base_s": …,              # 위 값의 블록별 집계          (정의 변경)
 "exit_travel_s": …}              # jobDoneTime→gateOutTime     (실측 파생)
 # ── 삭제: requested_flow · fallback_reason (합성 생성기 인공물)
```

### 변경 5종

| 성격 | 대상 | 왜 |
|---|---|---|
| **쪼개기** | `arrival_s` → `reserved_s`+`gate_in_s` | **최우선.** 둘의 차 = **예약 준수 오차**. 지금 σ=600초 가정을 실측으로 대체 |
| 쪼개기 | `block` → 배정/실제/이전 + 사유 | 재배치가 실제로 일어나는지·왜 |
| **삭제** | `requested_flow` · `fallback_reason` | 실제 오더에 없는 개념. 반입/반출은 화주가 정한다 |
| 타입 | `size_ft40`(bool) → `size_class`(범주) | 실제는 ISO 4자리. 냉동·탱크·오픈탑이 작업시간이 다르다 |
| 정의 | `travel_s`·`travel_base_s`·`exit_travel_s` | 이름 유지, **출처만 난수 → 실측** |
| 채움 | `target` 60% → 100% | 반입 트럭도 특정 컨테이너를 싣고 온다 |

## RL 개선과의 관계 — 주의

"터미널에 정보가 더 있으니 RL 상태에 넣자"는 **지금 하지 않는다**
(AGENTS.md 연구 설계 원칙 2 — 핵심 정보 먼저, 실증 후 한 축씩).
[[YR-185]] 가 진단한 병목은 **정보 부족이 아니라 보상 희소·critic 붕괴**였다.

다만 **다른 쓰임 셋은 값어치가 있다**:

- `expWaitingMin`·`blcWaitingCarCount` → 우리 견적식의 **정답지**.
  [[YR-175]]·[[YR-177]](견적망 결함)을 **우회**할 수 있다.
- `VBS_RES_AVL` → [[YR-176]] 슬롯 용량 정본.
- `restrictedEntryDateTime` → 시간 이연이 **제도적 통로를 갖는다**는 근거.
  단 우리 실측은 시간 이연이 1건당 +14.28분 **손해**였다 — 레버 존재가
  이득을 뜻하지 않는다. **"왜 실제로는 쓰는가"가 새 질문**이 된다.

## 하지 않는 것

- 규격만 보고 "실측 보정 완료"라 적는 것 — **분포·결측률 미확인**이다.
- 실데이터 확보 전에 시뮬레이터 상수를 바꾸는 것.
- 차량번호·기사 연락처·화주명을 받는 것(솔트 해시로 동일성만).
