# YR-332-bu · 학습 갱신 단계에 CPU 스레드 더 쓰기

- **상태**: done

- 분류: Infra — 학습 방법·설정·결과는 바꾸지 않는다. 계산 속도만 다룬다.

## 왜

- 사용자가 GPU 대신 CPU를 쓰는 이유를 물었다. 한 달 굴리기 시간의 약 83%가 파이썬 시뮬레이션이다(bl 시험 월: 규칙만 53분, 학습 모델 64분). 이 저장소의 GPU 이식(YR-327)은 단일 터미널에서 8~9배, 학습 경로에서 71~286배 느렸다. 그래서 굴리기는 CPU가 맞다.
- 반면 갱신 단계는 bp에서 결정 331,520개 갱신이 한 번에 약 1시간 반, 4회에 약 6시간이었고 1스레드였다. 굴리기 4개와 CPU를 나누려던 설정이지만, 갱신 중에는 굴리기가 쉬고 있다.

## 한 일

- `src/yard_rl/v7/crane/update_threads.py`: 블록 안에서만 스레드를 늘리고 끝나면(오류가 나도) 되돌리는 장치. 기본 16스레드. 시험 1건.
- bt가 지문을 고정한 학습 파일(`short_window_train.py`, `value_normalization.py` 등)은 고치지 않았다. bp와 bt는 1스레드 그대로이고, br 등 새 학습부터 쓴다.
