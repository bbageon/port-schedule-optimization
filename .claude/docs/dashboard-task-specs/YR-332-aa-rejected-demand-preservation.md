# YR-332-aa — 접수 실패 주문 보존과 실제 게이트 진입 장부

- **상태**: in-progress
- 등록: 2026-11-08. 상위 [[YR-332]], 근거 [[YR-332-m]].
- 환경·장부의 주문 보존 한 축. 정책·보상·공간 용량을 동시에 바꾸지 않는다.
- **3대 게이트 보정 대상**: `scenario_validity` — 고정 외생 도착의 전건 등록·물리 대기·사건 장부 보존.

## 무엇과 왜

m의 42회 재생에서 접수 실패 주문은 다시 검토되지 않았다.
기존 최초 입력은 3,500건 중 201건, 혼잡 입력은 최신 학습 3모델 평균 15,000건 중
573.33건이 빠졌다. 실제 빈 칸은 있었지만 양하 예정분의 공간 예약 때문에 접수가 막혔다.
정책별로 접수 집합이 달라지므로, 체류 평균의 감소를 전체 입력의 처리 개선으로 읽을 수 없다.

## 수정·평가 계약

1. 고정 도착 실험에서는 유효한 주문을 통지 시점에 전건 등록한다. 기존 작업 목록의
   PLANNED→WAITING 상태로 보존하고, 실제 적재 공간은 작업 실행 때 검사한다.
   이는 이미 CargoTerminal이 쓰는 계약이다. 별도 재시도나 임의 도착 지연은 추가하지 않는다.
2. 예약·도착 의사·실제 게이트 진입·블록 도착·작업 완료·출차를 구분한다.
   이 실험의 외생 실제 진입 시각을 고정하고, 아직 일어나지 않은 사건은 관측 기록에 넣지 않는다.
   예약과 실제 도착의 분포 분리는 f의 별도 보정이며, 현재 예약의 현실성을 확보했다고 주장하지 않는다.
3. 턴타임은 사용자 정의인 실제 게이트 진입부터 출차까지로 유지한다.
   미접수·미출차 수와 게이트 밖 보류 시간은 별도 장부에 보고한다. 임의 비용을 보상에 더하지 않는다.
4. 양하 예약은 먼저 물리적 필요성과 중복 여부를 확인한다. 안전 근거 없이 예약을 없애거나
   용량을 늘려 통과시키지 않는다. 다른 물리 보정은 [[YR-332-i]]에서 수행한다.
5. 동일 입력·동일 저장 모델·동일 규칙으로 기존 접수 방식과 짝비교한다. 입력 수는
   미접수 보류 + 접수 후 미출차 + 출차로 전건 보존하고, 중복 접수·초과 적재가 없어야 한다.
6. 정책마다 처리량이 달라지면 미접수·잔여 보호 조건과 체류를 함께 판정한다.
   접수된 공통 부분집합만 고른 평균을 공정한 인과 효과로 주장하지 않는다.
7. 본 수정으로 예전 학습 환경이 바뀌므로 기존 모델의 재평가는 진단이다.
   재학습은 환경·장부 계약 확정 후 별도 사전등록한다.

## 선행과 완료 기준

m의 원자료를 보존하고, 수정 전후 입력 보존·실제 사건 시각·안전 용량을 전건 대조한다.
평가창 연장은 [[YR-332-d]], 본선 용량 보정은 [[YR-332-i]]와 순서를 맞추되 한 실행에 섞지 않는다.
성능·현실성 미통과 상태이므로 먼저 이 장부 결함을 직접 보정한다.
