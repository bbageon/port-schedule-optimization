- 상위 [[YR-332]]. 2026-11-24 사용자 요청에 따라 BP가 끝난 뒤 합성 환경에서 순차 실행한다. 현장 타당성 미통과와 기존 성능 판정은 보존한다.
- 보정 대상: performance. 실제 지연을 한 선택에 연결하기 어려웠던 문제를 겨냥해 결정 시점에 공개된 시간 정보만 바꾼다. 기존 필수 작업과 서비스·준비·대기 순서는 유지된다. 같은 우선 단계에 선택지가 남은 경우의 효과를 잰다.
- `training=performance`. 대조군은 BP(기존 입력)와 연속 30일을 마친 짧은 작업 우선 규칙이다.

## 실행 전 가설과 기준

| 비교 | 검증할 내용 |
|---|---|
| ETA 대 BP | 통지된 외부 트럭의 블록 도착 예정까지 남은 시간을 주면 준비 작업을 더 적절히 선택하는가 |
| ETW 대 BP | 본선 작업 시작 예정까지 남은 시간을 주면 본선 시작을 앞두고 트럭을 한 건 더 처리할 여유를 구별하는가 |
| 둘 다 대 단독 각각 | 두 종류의 시각을 함께 주면 단독 입력보다 시간이 더 줄어드는가 |
| 둘 다 + 상자 필요 예정 대 둘 다 | 이미 시작한 본선에서 안벽 작업 순번과 현재 진척으로 추정한 해당 상자 작업 예정시각에 추가 가치가 있는가 |
| 같은 상태에서 첫 배정만 바꾸기 | 두 시각을 쓰는 최종 모델과 규칙이 다르게 고른 첫 배정을 각각 실행해 월말까지의 실제 차이를 잰다 |

트럭 1건당 게이트 진입~야드 완료 분과 본선 1척당 하역 가능~마지막 안벽 작업 완료 시간을 따로 낸다. **두 평균 모두 짧아지면 공동 목표 달성**이다. 안전운임과 분리해 트럭 총 분 + 67 × 본선 총 분, 느린 트럭 5%의 경계도 기록한다. 시험 월은 기존 연구와 공유하는 합성 월 하나이며 정책 채택 판정은 하지 않는다.

## 데이터와 실행

- 정보는 관측 시각까지 접수된 오더와 공개된 본선 계획만 사용한다. 미도착 오더에는 해당 트럭의 블록 ETA를, 다른 후보에는 그 블록에서 아직 도착하지 않은 통지 트럭 중 가장 이른 ETA를 쓴다. ETW는 해당 미개시 작업 줄의 시작 예정, 그 외에는 블록에서 가장 이른 미개시 작업 줄의 시작 예정이다. 결측과 지금 도래를 구분한다.
- 상자별 시각은 현장 ETW 측정값과 구별한다. 해당 작업의 공개된 순번·계획 작업 간격에 안벽의 관측 진척 지연을 더한 추정치다. 대응하는 진행 중 작업 줄이 없는 후보에는 미상으로 표시한다. 평가에서 시각별 실제 관측 횟수를 함께 낸다.
- BP와 같은 원본 가중치·입력 명단·4 × 4회 월 재생·표본 수(갱신당 331,520)·난수·30분 보상·모델 갱신 방식을 쓴다. 새 입력의 시작 가중치는 0이다. 모든 조건은 동일한 시작 정책에서 독립 학습한다. 예측값과 보상에 실제 미래 도착 시각을 제공하지 않는다.
- BP의 4개 모델 지문과 갱신 기록, 최종 시험 월 입력 지문과 완료를 검증한 뒤 3일 축소 점검 → ETA → ETW → 둘 다 → 둘 다 + 상자 필요 예정 순으로 한 조건씩 실행한다. 월 비교는 저장된 입력·가중치에서 최고 점수 선택으로 한다. 완료 건수와 진입 명단도 대조한다.
- 첫 선택 비교는 시험 월 3·10·17·24일차 각각 첫 규칙 불일치 한 건이다. 같은 결정까지의 선택 지문·시각·양쪽 배정을 대조하고 이후는 두 갈래 모두 같은 모델을 쓴다. 일치만 있는 날은 그대로 남긴다. 일어난 불일치 몇 건을 전체 결정의 평균 효과로 일반화하지 않는다.
- 실행 상태는 `outputs/reports/yr332_planned_times/queue-status.json`, 조건별 평가 뒤 `comparison.json`, 첫 선택 대조는 `paired/summary.json`이다. 진행 중 BP 기록을 수정하거나 중간 모델로 시험 월 성적을 미리 재지 않는다.
