# YR-216 · 반사실 지평(H)과 이연 칸 지평이 어긋난다

> Epic RL · 우선순위 🔴 · 상태 **backlog** (등록 2026-08-22)
> 선행 [[YR-215]] ✅ (여기서 실측으로 발견) · 관련 [[YR-204]] · [[YR-190]]

## 1. 무엇이 문제인가 — 한 줄

**2시간 뒤로 미루는 결정을 1시간짜리 창으로 채점하면 "아무 일도 안 일어났다"** 가
나온다. 라벨이 0 이라 학습은 *"그 행동은 무의미"* 로 배운다.

## 2. 실측 (2026-08-22 · [[YR-215]] 배선 확인 중 발견)

부하 3,500 · `arm=RL` · H=1시간. 표본 4건 중 t=0.00h 의 D-00000:

| | 값 |
|---|---|
| 판매 실제 행동 | `SELL` · 좌표 **`TIME@8`**(2시간 뒤 칸) |
| 구매 응답 | `BUY` (거래 성립) |
| Φ(factual) | 269,968원 |
| Φ(대안 = KEEP) | **269,968원 — 정확히 같다** |
| 라벨(이득) | **+0** |

거래가 실제로 성립했는데도 라벨이 0 이다. 이연이 창 밖으로 밀어낸 비용은
**창 안에서 보이지 않기** 때문이다.

## 3. 왜 생겼나 — 두 지평이 따로 정해졌다

| 지평 | 값 | 정한 곳 |
|---|---|---|
| 반사실 창 `H` | **1시간** | 사용자 결정 2026-08-20 (연산량 근거) |
| 이연 칸 후보 | **15분 · 30분 · 1시간 · 2시간** | [[YR-215]] 구현 (`bridge._time_slots`) |

둘이 독립적으로 정해져 **2시간 칸은 구조적으로 라벨이 0** 이다. 공간 재배치는
효과가 즉시(주행 차이·목적지 혼잡) 나타나 이 문제가 없다 — **시간 축만** 걸린다.

## 4. 어느 쪽을 고치나 — 세 안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 칸을 H 안으로** | 이연 후보를 15·30·45분으로 제한 | 연산량 그대로 · 즉시 적용 | 긴 이연이라는 **선택지 자체를 없앤다** — 그게 이득인 상황을 못 배운다 |
| **B. H 를 늘린다** | H = 3시간 | 선택지 보존 | 연산량 **×4.5**. 이미 회차당 14시간인데 63시간이 된다 |
| **C. 축별 H** | 공간 1시간 · 시간 3시간 | 필요한 곳만 늘림 | 두 축 라벨의 **눈금이 달라진다** — 같은 Φ 로 비교 못 함 |

**권장은 A 로 시작**한다. 연구 설계 원칙("단일 메커니즘을 더 잘 최적화")에 맞고,
*"긴 이연이 이득인가"* 는 [[YR-190]] 창 스윕이 **별도 축으로** 답할 문제다.

## 5. 판정 기준

- 이연 거래의 라벨 중 **정확히 0 인 비율**이 착수 전 대비 유의하게 준다
- 공간 축 라벨 분포는 **안 바뀐다**(건드리지 않은 축이 흔들리면 배선 오류)
- 표본 ≥ 200 라벨 · 비판정 대역 시드(9,900,0xx)

## 6. 하지 말 것

`H` 를 결과 보고 조정하지 않는다 — 사용자 결정 사항이고 사전등록 동결 대상이다.
바꾸려면 **바꾸기 전에** 근거와 새 연산량을 적고 사용자 확인을 받는다.
