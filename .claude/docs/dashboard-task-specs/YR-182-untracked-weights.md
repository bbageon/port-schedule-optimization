## 왜 심각한가

`code_dirty` 보다 무겁다. dirty 트리는 "어떤 코드였는지 모른다"이지만
이쪽은 **"그 파일이 사라지면 아무도 재현할 수 없다"** 이다.

- 판정 재현이 **한 대의 컴퓨터 디스크**에 걸려 있다. 백업·검증 대상이 아니다.
- 다른 작업공간(git worktree)에서 같은 실험을 돌릴 수 없다 — 실제로 오늘
  막혔다.
- 논문 심사나 외부 재현 요청에 응할 수 없다.
- 게이트 `reliability` 는 **이걸 검사하지 않는다** — commit 의 원격 반영만
  본다. PASS 를 주고 있었다.

| 분류 | 처리 |
|---|---|
| **판정에 인용된 가중치** (done row 의 evidence 가 가리키는 것) | 커밋 — 재현 필수 |
| 현행 코드가 경로로 참조하는 가중치 | 커밋 — 없으면 실행 불가 |
| 폐기·무효 판정의 중간 산출 | 커밋하지 않음. 대신 **어디에 있었는지와 sha256 을 목록으로** 남긴다 |

분류 근거를 기계로 뽑는다 — `grep` 으로 코드가 참조하는 경로를 모으고,
done.md 의 evidence 링크를 파싱해 인용된 산출물을 모은다. 눈으로 고르지 않는다.

**3단계**: 게이트 `reliability` 에 검사 항 추가 —
"판정에 인용된 산출물이 참조하는 가중치 파일이 전부 추적 상태이고 원격에
반영돼 있을 것". 지금은 사각지대다.

## 판단이 필요한 지점 (사용자 결정 요청)

50 MB 를 git 에 넣는 것은 되돌리기 어렵다(히스토리에 영구 잔류). 선택지:

1. **선별 커밋** — 위 분류대로 필요한 것만. 아마 5~10 MB. **권장.**
2. **전량 커밋** — 단순하지만 저장소가 50 MB 무거워지고 죽은 실험도 영구 보존.
3. **git-lfs 도입** — 정석이나 도구 의존이 늘고 clone 절차가 바뀐다.
