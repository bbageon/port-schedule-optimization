# YR-103 — 게이트→블록 3~7분·동적 블록 혼잡도 관측 계약

- **Epic**: Sim / **Priority**: 🟠 / **등록일**: 2026-07-27
- **상태**: 설계·검증 대기. 기존 결과는 바꾸지 않고 opt-in 새 계약으로 구현한다.
- **상위 목적**: YR-099의 블록 간 반입·양하 재배정과 YR-102의 비용 quote가
  결정 시점에 실제로 알 수 있는 도착·혼잡정보를 사용하게 한다.
- **결정 원본**:
  [사용자 시간·혼잡 계약](../strategy-history/2026-07-27-YR-103-게이트블록-이동-블록혼잡도-사용자결정.md)

## 한 줄 결론

> 게이트 진입→블록 진입은 180~420초(3~7분)로 모델링하고, 블록 혼잡은 전체
> 트럭 대기열·평균 대기·절대 YC 부하·현재 장치율·진입지연을 각각 0~1로 만든 뒤
> 합성한다. 첫 단계에서는 비용이나 보상이 아니라 관측·진단값으로만 쓴다.

## 현재 코드 감사

현재 “혼잡”이라는 이름 아래 서로 다른 값이 섞여 있다.

| 현재 값 | 실제 의미 | 이번 지표와의 차이 |
|---|---|---|
| `CongestionSpec` | 트럭 강도·피크·초기 장치율·본선압력 시나리오 다이얼 | 실시간 상태가 아님 |
| `lane_congestion_*` | 활성 크레인 작업이 예약한 자기·인접 레인 점유 | 도로 차량 혼잡이 아님 |
| `backlog_external` | WAITING/RELEASED 외부작업 수 | 단일 블록에서는 대기열 원료로 사용 가능 |
| `queue.wait_mean_s` | 크레인별 pruning 뒤 외부 SERVE 후보 평균 | 전체 블록 평균대기가 아님 |
| `load_imbalance` | 크레인 부하의 불균형 | 모든 크레인이 바쁜 절대부하가 아님 |
| 생성기의 `fill_ratio` | 초기 장치율 | 실행 중 현재 장치율이 state에 없음 |

게이트→블록 시간도 경로가 갈린다. `TerminalGenParams` 직접 기본값은 600초이고,
현실 보정·혼잡 프리셋은 평균 210초·σ=12%·±2σ 절단이라 약 160~260초다.
어느 쪽도 새 180~420초 계약과 같지 않다.

## 시간 계약

### 시뮬레이션 지원범위

```text
gate_to_block_min_s = 180
gate_to_block_max_s = 420
gate_to_block_mean_s = 300       # 실측 전 assumed 중심값
gate_to_block_sigma_s = 60       # 3~7분 전체를 ±2σ 범위로 만드는 assumed 값
```

- 외부 ETA가 있으면 그 값을 우선 사용하고 3~7분은 물리 검증·fallback 범위로 쓴다.
- 생성기는 전용 난수열의 절단정규분포를 사용하고 같은 seed에는 같은 값을 만든다.
- 기존 v2·골든·박제 결과는 수정하지 않는다. 새 옵션을 켠 실험만 이 계약을 쓴다.

### 시간지식 경계

```text
예약 시점: appointment + 예상 준수오차 + 예상 게이트→블록 시간
실제 gate-in 뒤: actual_gate_in + 현재 정보의 갱신 이동시간
실제 block-in 뒤: actual_block_arrival은 장부·학습 label·보정에만 사용
```

미래의 `actual_gate_in`, `actual_block_arrival`, 실제 도로 소요시간을 미리 읽지 않는다.
재배정 review는 최초 배정·ETA 갱신·실제 gate-in·유의한 혼잡변화 때 열되,
`transfer_lock_at` 뒤에는 열지 않는다.

## 블록 혼잡도 원료

모든 항은 raw count·초를 그대로 더하지 않고 먼저 `[0,1]`로 만든다.

```text
Q = clip(전체 WAITING 외부트럭 수 / queue_ref, 0, 1)
W = clip(전체 WAITING 외부트럭의 평균(now − actual_block_arrival)
         / wait_ref_s, 0, 1)
L = clip((모든 YC의 실행 잔여초 + 대기작업 예상 서비스초)
         / (YC 수 × workload_horizon_s), 0, 1)
F = 현재 적재 컨테이너 수 / (bay × row × tier 물리용량)
D = mean_i clip((작업 i의 현재 예상 gate→block 시간 − 180) / 240, 0, 1)
```

- `queue_ref`, `wait_ref_s`, `workload_horizon_s`는 결과를 보기 전에 고정한다.
- 시작값 후보는 기존 계약과 맞춰 `wait_ref_s=long_wait_sla_s`,
  `workload_horizon_s=900`초로 두되 민감도 결과 전에는 확정값으로 주장하지 않는다.
- `W`는 후보 pruning과 무관한 전체 블록 대기열로 다시 계산한다.
- `L`은 `load_imbalance`를 재사용하지 않는다. 절대 작업량을 새로 계산한다.
- `F`는 초기 `fill_ratio`가 아니라 실행 중 실제 stack 상태를 사용한다.
- `D`의 집합 i는 해당 블록에 배정됐지만 아직 block-in하지 않은 공개정보 작업이다.
  해당 작업이 없으면 `D=0`으로 두고, 미래의 실제 이동시간은 읽지 않는다.

## 사용자 제안 합성식

```text
C_internal = 0.30Q + 0.25W + 0.20L + 0.15F
C_user     = clip(C_internal - 0.10D, 0, 1)
```

양의 항 가중치 합은 0.90이므로 이 값은 `[0,1]` 안에는 있지만 이론상 최대가 1은 아니다.
첫 검증에서는 사용자 가중치를 보존하고, 성능을 본 뒤 임의로 1에 맞춰 재척도하지 않는다.

`−0.10D`는 “진입도로가 느리면 트럭 유입이 늦어져 당장 블록 내부 압력이 낮아진다”는
**유입완화 가설**일 때만 맞다. 전체 터미널 혼잡·수신 블록 매력도를 뜻한다면 도로지연은
비용을 높이므로 `+0.10D`가 자연스럽다.

따라서 첫 실험은 아래 세 값을 함께 보고 부호를 사전등록한다.

```text
C_minus = clip(C_internal - 0.10D, 0, 1)  # 사용자 유입완화 가설
C_zero  = clip(C_internal,         0, 1)  # 도로항 분리
C_plus  = clip(C_internal + 0.10D, 0, 1)  # 전체 혼잡비용 가설
```

TransferResolver의 실제 추가 이동시간·도로비용은 항상 **양의 비용**으로 별도 계산한다.
따라서 `C_minus`를 쓰더라도 지연도로가 값싼 목적지처럼 보이는 오류를 막는다.

## 정책 연결 원칙

- 첫 단계: state·로그·진단·단순규칙 비교에만 사용한다.
- 금지: 이 점수를 terminal total cost나 reward에 다시 더하는 것. 대기·부하·장치율
  비용과 중복되어 과거 interference proxy 지배 문제가 재발할 수 있다.
- YR-099/102에는 기존 상태 대비 `+동적 도착정보`, `+블록 혼잡도`를 각각 분리한
  ablation으로 연결한다. 추정기와 상태를 한 실험에서 동시에 바꾸지 않는다.
- 단일 블록 실행 Q에 넣을 때는 schema 버전과 기존 checkpoint 호환성을 명시한다.

## 검증 게이트

### G0 계약

- 생성된 `B−A`가 전 표본 180~420초이고 `A≤B≤S≤C≤O`를 지킨다.
- 같은 seed·공개 snapshot은 동일하고 실현 난수를 바꿔도 정책 관측은 누출되지 않는다.
- Q/W/L/F 증가 시 `C_internal`이 단조 증가하고 모든 점수가 `[0,1]`에 있다.
- W는 전체 WAITING 집합, F는 runtime stack, L은 절대 YC 부하를 실제로 반영한다.
- 기능 off이면 기존 시나리오·골든이 바이트 동일하다.

### G1 정보 충분성·부호

- 같은 공개 snapshot을 고정하고 숨은 도착을 반복 생성해 공개정보 기대 상금을 잰다.
- `C_minus/zero/plus`가 다음 15~30분의 실제 블록 처리비용과 혼잡을 얼마나 예측하는지
  신규 seed에서 비교한다.
- 선택용 표본과 평가용 표본을 분리해 다후보 winner's curse를 막는다.

### G2 재배정 기여

- YR-099 기준 quote와 `+도착갱신`, `+혼잡`, `+둘 다`를 짝지어 비교한다.
- terminal total cost·평균 B→C/A→O·본선·완주를 주판정하고 P95는 보고만 한다.
- 공개정보 기대 상금이 0이면 네트워크를 키우지 않고 결정시점·추가정보 한계로 판정한다.

## 의존·범위

- 선결 원료: YR-089 시간장부, YR-099 소유권·TransferResolver, YR-093 정보안전.
- **YR-102 선결 진단**: G1에서 현재 공개정보에 회수 가능한 상금이 있는지 먼저 확인한다.
- 범위 밖: 상세 도로 그래프·교차로 신호·TOS 수정·실측 없는 터미널별 교통 성능 주장.
- 실측 Level 3 로그가 들어오면 3~7분·정규화 기준·도로 부호를 다시 보정한다.
