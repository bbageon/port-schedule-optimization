**재개 조건**: 다음 학습·평가 실행 때 훅만 켜서 동승 수집.

## 왜 미리 쌓는가

YR-171(당일 30분 슬롯 최적화)의 BUY 견적을 **시뮬레이션 가상 실행**으로 하면
계산량이 이렇게 된다:

| | 값 |
|---|---|
| OFFER 1건당 후보 | 수신 20 × 슬롯 48 = **960** |
| 하루 OFFER (관찰 실측) | 60초 격자 1,441 × 후보 보유 블록 평균 10.5 ≈ **14,400** |
| 하루 총 가상 실행 | **약 1,380만 회** |
| 실측 결정 1회 비용 | 45ms → **약 173시간/에피소드** (현재 9분) |

→ 그대로는 실행 불가다. 대안 사다리는 ①굴려보는 범위 축소 ②현행 계산식 직접 개선
③**견적 예측 모델**이고, ③으로 가게 되면 학습 데이터가 필요하다. **그 데이터는
실험을 돌리는 김에 공짜로 나온다** — 그래서 지금부터 남긴다.

## 왜 지도학습이 유리한가

지금 막힌 것은 강화학습(정답 없음)이지만 **견적은 정답이 있다** — 굴려보면 실제
값이 나온다.

| | 강화학습(현재 난제) | 견적 예측(지도학습) |
|---|---|---|
| 정답 | 없음 | **있음(시뮬레이션 결과)** |
| 검증 | 어려움(잡음에 묻힘 — YR-168 POWER_FAIL) | **예측 대 실제 직접 대조** |
| GPU | 무익(병목이 find_slot·순수 파이썬) | **유익**(960 후보 일괄 질의) |

## ★ 데이터의 지위 (사용자 명시 2026-08-13)

> **시뮬레이션 산출물이지 실제 터미널 운영 기록이 아니다.**

여기서 학습한 모델은 **이 시뮬레이터의 근사**이며, 실제 항만 성능을 예측한다고
주장할 수 없다. 산출물 첫 줄(`_header`)에 이 문구를 함께 기록한다.

## 구현 (2026-08-13 · `1ff6cf9`)

- `DecisionRecorder` — 60초 격자마다 블록 상태(내부 대수·통지 pipeline·여유칸·φ)를
  찍고, 에피소드 끝에서 판매 원장·시간 장부와 조인해 **실현 결과**(체류·벌금·비용
  시간)를 붙인다. 결정 1건 = 표본 1개.
- 입력은 **결정 시점 공개 정보만** — 실현 미래값 미열람(정보경계 유지).
- `run_episode_diurnal(_extra_review=)` — 관측 전용 훅. Φ 기록 뒤·판매 확정 앞에
  끼워 결정 직전 상황을 찍는다. **결정에 개입하지 않는다.**
- 기본 꺼짐 — 학습 경로는 이 훅을 쓰지 않아 **바이트 불변**.

## 하지 않는 것

- 이 데이터로 학습한 모델을 **검증 없이** 견적에 투입하는 것.
- 시뮬레이션 데이터를 **실측 운영 데이터로 표기**하는 것.
- 수집을 학습 실행에 붙여 학습을 느리게 하거나 산출물을 부풀리는 것
  (수집은 별도 실행으로 돌린다).
