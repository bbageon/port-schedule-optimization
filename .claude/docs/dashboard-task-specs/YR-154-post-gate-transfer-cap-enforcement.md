# YR-154 — 기존(게이트 진입 후) 이송 경로의 이송 상한 엔진 강제

- **Epic**: Infra / **Priority**: 🟠 / **등록일**: 2026-08-06 / **상태**: **backlog**
- **3대 게이트 보정 대상**: `reliability` 하나 — 착수 시 YR-153 `authorize-next` 통과 필수
- **발견 경위**: YR-151 0A 계약 검사(C5)에서 확인 —
  [report](../../../outputs/reports/yr151_pre_gate_0a/report.md)

## 무엇이 문제인가

작업 하나를 블록 사이로 옮길 수 있는 횟수 상한(현재 1회)이 **후보를 고르는 쪽에만** 있었고
**실제로 옮기는 엔진에는 없었다**. 즉 후보 생성기를 거치지 않고 엔진을 직접 부르면 같은 작업을
몇 번이고 옮길 수 있다. 0A 에서 새로 만든 게이트 진입 **전** 경로(`prepare_pre_gate_transfer`)에는
막는 검사(fail-closed)를 넣었지만, **기존 게이트 진입 후 경로(`prepare_transfer`)에는 그대로 남아 있다**.

0A 에서 같이 고치지 않은 이유는 하나다 — 그 경로는 이미 판정이 끝난 실험들(골든)이 쓰는
경로이고, 계약 검사 단계에서 판정 코드를 함께 바꾸면 어느 변경이 결과를 바꿨는지 분리할 수 없다.

## 무엇을 하는가

1. `MultiBlockTerminal.prepare_transfer` 에 `transfer_count >= max_transfers` 거절을 추가한다
   (PRE_GATE 경로와 대칭. `src/yard_rl/integrated/multiblock.py`).
2. **골든 불변 확인이 판정이다** — 상한을 넘긴 이송이 과거 실험에 실제로 있었는지 먼저 로그로
   센다. 0건이면 기존 결과는 그대로 유효하고 이 변경은 순수 안전장치다.
   1건 이상이면 **완화 없이** 해당 결과의 해석을 정정 표기로 박제한다.
3. 회귀 테스트: 게이트 진입 후 경로에서도 2회째 이송이 거절되는지 1건 추가.

## 완료 조건

- 두 경로 모두 엔진에서 상한이 강제되고, 골든 결과(총비용·A→O)가 비트 단위로 동일하거나
  차이가 있으면 그 원인이 상한 위반 이송이었음을 수치로 제시.
