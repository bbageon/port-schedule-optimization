# YR-332-bd — 반입 시간 감소의 실제 기록·정책 선택 대조

**상태**: in-progress
등록: 2026-11-20. 사용자: “왜 반입건이 감소가 많은지 혹시 실제 환경을 토대로 검증해줄수있어?”
**3대 게이트 보정 대상**: `scenario_validity` — 실제 작업 기록과 합성 환경의 비교 가능 범위 확인.
새 학습·모형 변경 없이 기존 bc 결과, 저장 모델·경험, 제공된 원자료와 공식 운영 문서를 분석한다.
현재 bc 판정으로 현실성 직접 보정 착수 허가를 받았다. [허가](../../../outputs/reports/yr332_inbound_realism/authorization.json).

## 확인할 질문

1. 반입−29.43%는 추가 학습 전 대비인가, 전역 정보 없는 모델 대비인가? 물량별로 같은가?
2. 같은 오더의 진입→블록→작업시작→완료를 나누면 어느 구간이 줄었는가?
3. 미완료를24시간에 자르는 집계와 두 모델 모두 완료한 오더 비교가 어떻게 다른가?
4. 같은 후보 상태에 저장 모델을 적용하면 반입 선호가 달라지는가?
5. 실제 원본에서 확인되는 반입·반출 구간과 기록 누락률은 어떠하며 합성 환경과 같은 정의인가?
6. 실제 장비 배치·복화 작업 절차를 해당 터미널 공식 자료와 대조하면 어떤 한계가 남는가?

## 고정 범위

- 운영 결과는 bc 최종시험3곡선×3물량×3초기값의 전역 없음/있음27쌍 전수를 쓴다.
  초기 모델과 짧은 실작업 우선 규칙도 같은 시험 입력의 저장 기록으로 비교한다.
- 기간은24시간 관측과26시간 마무리 실행을 구분한다. 미완료를 제외해 주 평균을 낮추지 않는다.
- 기록된 구간은 관측 종료까지 각각 절단해 합계가 기존 진입→작업완료 평균과 맞는지 검사한다.
  두 모델 모두 완료한 공통 오더 분석은 선택 편향이 있는 보조 진단으로 표시한다.
- 선택 진단은 bc의 저장된 검증 경험을 전수 사용한다. 동일 후보에 같은 초기값의 초기/최종 모델을 대조한다.
  두 정책의 경험을 합쳐 특정 정책의 상태만 유리하게 고르지 않는다.
  단일 크레인의 첫 유효 선택을 별도 집계해 앞선 공동 배정의 영향을 섞지 않는다.
  선택 확률 차이를 개별 결정의 인과 효과나 실제 항만에서의 선택이라고 해석하지 않는다.
- 실제 자료는 기존600파일 원본의 해시를 확인하며, 원본 사건 시각과 로그 시각을 구분한다.
  관측된 기록을 임의 시각으로 채우지 않는다. 유형별 전체 건수·관측 구간 건수·시각 역전·누락을 공개한다.
- 실제 자료에 작업 시작이 없으면 블록→완료를 순수 대기 또는 순수 크레인 작업시간이라고 부르지 않는다.
  같은 차량의 여러 오더·재전달·후속 작업이 구간과 표본에 미치는 한계를 구분한다.
- 개인·차량·컨테이너 식별자는 메모리에만 사용하고 공개 결과는 익명 집계·원본 파일 해시로 제한한다.
- 공개 문서는 터미널 운영사·항만공사의 원문을 쓴다. DGT와 HJNC의 배치를 동일하다고 가정하지 않는다.

## 산출물과 검증

- 별도 분석 스크립트와 `outputs/reports/yr332_inbound_realism/`에 구간·선택·실기록 분석을 저장한다.
- 저장 운영 보고의 평균·오더수·미완료와 독립 재계산 일치, 두 군의 입력·오더 대응을 확인한다.
- 원본 필드 존재·확인된 시각 연결·기존 기록 보존을 검사한다. 실제 처리시간 개선율을 새로 주장하지 않는다.
- 해석은 확인된 수치, 코드에 있는 기제, 실제 환경에서 아직 검증되지 않은 가설을 구분한다.
- 성능·기록 정합·현실성을 구분하며 이번 감사로 기존 정책을 채택하거나 실패 판정을 지우지 않는다.
