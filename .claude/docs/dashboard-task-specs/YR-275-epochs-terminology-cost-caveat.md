# YR-275 — 회차·시간 사실 정정 · "제안 정책" 중의성 해소 · 비용구조 단서

- **Epic**: Paper / **Priority**: 🔴 / **등록·완료일**: 2026-08-30

전달받은 피드백 ⑨~⑫ 중 **대역과 무관한 ⑩·⑪·⑫를 반영**하고 ⑨는 미룬다.

## ⑪ 회차·시간 — 두 숫자 다 틀렸다 (실측으로 확인)

| | 논문 §3.6 | 실제 |
|---|---|---|
| 학습 회차 | 24 | **30** (`month-02/history.json` 30행 · 체크포인트 30개) |
| 학습 시간 | CPU 4.7시간 | **약 18시간**(벽시계) |

- `24 · 4.71시간` 은 **다른 실행**의 값이다 — `outputs/v3/train`(24행)의 `secs` 합이
  정확히 4.7075시간이다. 논문이 그림·§5.6 에 쓰는 실행은 `month-02`(시드 9,900,700)다.
- ⚠️ **시간은 내가 다시 쟀다**: `month-02` 에는 소요시간 필드가 없어 체크포인트 30개의
  파일시각으로 잰다 — `ckpt_000` 08-27 19:10 → `ckpt_029` 08-28 12:12 = **17.04시간**,
  첫 회차(회차 간격 평균 35.3분)를 더하면 **≈17.6시간**. 전달받은 17.79시간은 재현하지
  못했으나 같은 범위다. 그래서 논문에는 **"약 18시간"** 으로 적었다.
- 또한 "CPU 시간" 이라는 표현을 **"벽시계 시간"** 으로 바꿨다. 반사실 분기를 여러 코어에
  병렬로 돌리므로 CPU 시간은 이보다 훨씬 크다 — 측정한 값은 벽시계다.
- 이 정정으로 §3.6(24회차)과 §5.6·그림(30회차)의 **논문 내 충돌**이 사라졌다.

## ⑫ "제안 정책" 이 두 뜻 — 국문이 특히 심각

§3 은 `제안 정책` = **파는 쪽 망**, §5 는 `제안 정책` = **시스템 전체**로 썼다.
국문은 글자가 완전히 같아 구분이 불가능했다.

- 전체 시스템 → **학습 정책** / **learned policy** (§5·§6, 국문 16곳·영문 15곳)
- 파는 쪽 망 → `제안 정책` / `proposal policy` 유지 (§3)
- §5.3 첫머리에 **정의 문장**을 넣었다 — "이 절에서 학습 정책은 아키텍처 전체(제안·수락·
  중앙 확정)를 가리키며 두 망 중 하나인 제안 정책과 구별한다."
- 표 라벨도 함께: `Proposed, time only` → `Learned, time only`,
  `Proposed lower days` → `Learned lower days`.

## ⑩ 해석 범위 — 문장 둘 (실험 불필요)

- §5.4: 도착시각 조정이 91.3% 를 설명한다는 값 뒤에 **비용 구조와 잇는 문장**을 넣었다.
  이 환경은 트럭 대기가 총비용의 96.4%(§4.5)라 대기시간을 옮기는 행동이 지배 항에
  직접 작용한다 — 비용 구성이 다르면 공간·시간의 우열도 달라질 수 있다.
- 한계: **여덟째 한계**로 비용계수 민감도 분석 필요를 추가 (일곱 → 여덟).

## ⑨ 미룸 — §4.6·§4.7 신설과 §5.1 이동

비교 정책·평가 프로토콜을 §4 끝으로 옮기는 구조 개편은 **§5.1 의 시드가 바뀌는**
판정 대역 전환과 같이 하는 것이 효율적이다 ([[YR-274]] 의 205개 이전과 한 묶음).
