# YR-332-n — 큰 야드에서 후보 생성 계산이 늘어나는 원인 확인

- **상태**: backlog
- 상위: [[YR-332]], 파생: [[YR-332-l]], 2026-11-05.
- 정책·보상·후보 범위를 유지하는 계산 경로 보정 한 축이다.

## 무엇과 왜

기본 하루 환경 7,500건·시드 9,913,320에서 전체 시간이 개별 144.53초→개선 148.98초였다.
점수/선택은 9.86초→3.39초로 줄었지만 후보 생성은 58.30초→69.39초로 늘었다.
3,500건 세 입력에서도 느린 결정의 경계가 개선 후 높아졌다. 특정 하위 함수 원인은 미확정이다.
작은 빈 야드의 이득을 큰 적재 상태에 일반화하기 전에 실제 병목을 확인해야 한다.

## 완료 기준

1. 동일 입력·모델에서 상태 목록, 물리 상태 대조, 계획 캐시, 슬롯 탐색의 시간을 구분한다.
2. 프로파일링 비용이 포함된 시간과 최종 순수 실행 시간을 구분해 원인을 재현한다.
3. 확인된 계산 한 축만 보정하고 후보·선택·사건·완료·비용이 동일한지 대조한다.
4. 세 기본 물량의 전체 시간과 느린 결정, 메모리를 함께 보고한다. 평균 이득으로 악화를 숨기지 않는다.
5. 입력·물리 용량·학습·보상은 동결한다. 실현 결과를 보고 편한 입력만 선택하지 않는다.
