# YR-332-af — 트럭 비용의 종료점을 작업 완료로 변경

- **상태**: in-progress
- **3대 게이트 보정 대상**: scenario_validity
- 사용자 지시(2026-11-10): 출차는 늦어질 수 있으므로 게이트 진입 / 작업 완료 / 게이트 진출을 구분한다.
- 목적: 크레인 작업이 끝난 뒤의 체류를 크레인 정책의 손실로 계산하지 않는다.

## 변경하는 한 축

- 실제 진입 A, 실제 작업 완료 C, 실제 출차 O를 각각 보존한다.
- 트럭 비용·학습의 물리 시간은 `max(0, min(C,T)-A)`다. C가 없으면 평가 끝 T로 자른다.
- 주 지표는 게이트 진입→작업 완료다. 작업 완료→출차와 전체 게이트 체류는 별도로 보고한다.
- 예약부터의 시간을 더하지 않는다. 본선 비용, 크레인 이동·재취급 계수, 정책·입력·물리는 고정한다.
- 기존 `turn_time`·미출차 수의 뜻은 유지하며, 작업 미완료 수를 명시적으로 추가한다.
- CPU·배열 비용, 교사의 미래 비용, 통화 없는 PPO 보상에 동일한 종료점을 적용한다.
- 정규화의 고정 수치는 이번에 다시 맞추지 않는다. 기존 출차 기준 참조의 눈금을 유지한 사실과
  새 비용 종료점을 계약에 함께 기록한다. 새 분포로 정규화를 재보정했다는 주장은 하지 않는다.
- 이전 비용으로 만든 라벨·모델을 새 목적함수의 학습 결과로 재해석하지 않는다.
  새 체크포인트에는 계약을 남기고 다른 계약의 학습 재개를 차단한다. 동결 모델의 진단 평가는 가능하다.

## 결과 열람 전 검증 계획

1. 작업 완료는 같고 출차만 늦춘 반례: 주 지표·비용·물리 보상 불변, 출차 지표만 증가.
2. 작업 완료 지연·미완료·미진입·창 경계·완료했지만 미출차인 경우를 별도로 검증한다.
3. 비용의 CPU/배열 동등성, 실행 보상, 교사 비용 창, 하루·월 결과 전달을 검사한다.
4. ad의 저장된 전건 예약 장부를 새 정의로 독립 재계산한다. 과거 산출물은 덮어쓰지 않는다.
5. 시드 9915101, 오차 600초, 부하 3,500/7,500/15,000의 하루 실행을 같은 규칙으로 재실행한다.
   후보·선택·사건·작업·실행 기록은 ad와 같아야 한다. 7,500건을 한 번 더 반복한다.
6. 관측 창 24시간 / 엔진 26시간을 유지한다. 전건 대상 평균에 미완료의 관측 시간도 포함하고,
   작업 완료 건수·출차 건수·종료 후 체류의 분모를 공개한다.

## 완료 기준과 후속

코드·별도 장부·실행 결과가 일치하고 출차 지연 반례를 통과하면 계약 변경은 완료한다.
수치가 줄어도 정의 변경 효과이며 학습 성능 개선이 아니다. 본선 양하/적하에는 트럭 게이트 지표를 적용하지 않는다.
새 목적함수의 학습·고전 규칙 비교는 별도 사전등록 작업으로 남긴다.
실측 운반(i)·예약/통지(f) 보정과 기존 성능 게이트는 자동 통과시키지 않는다.
