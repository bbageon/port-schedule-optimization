# YR-223 · RUDDER 자격시험 — 시간대별 기여도가 의미를 갖는가

> Epic RL · 우선순위 🟠 · 상태 **backlog** (등록 2026-08-24 · 사용자 설계 검토·수정)
> 선행 [[YR-222]] (진행중 — 결과가 이 row 의 전제를 바꾼다) · 후행 [[YR-224]]

## 1. 왜 이 축인가

[[YR-221]] 이 확인한 것 — **라벨의 65% 가 하류 결정 몫**이고, 그걸 걷어내면
(A안) 남는 신호가 망 오차보다 작아진다. 즉 **하류 연쇄를 버릴 수도, 그대로 둘 수도
없다.** [RUDDER](https://arxiv.org/pdf/1806.07857) 는 세 번째 길이다 — 연쇄를 **버리지 않고
시간축에 재분배**한다.

## 2. 사용자 설계에서 그대로 가져가는 것

| | 왜 맞나 |
|---|---|
| **학습 단위 = 1분 시장 epoch** | 코드가 실제로 60초 격자로 열린다(`EPOCH_S = 60.0`). 같은 시각 오더에 임의 순서를 붙이면 모델이 **가짜 순서**를 학습한다 |
| **3시간 유지** | 바뀌는 축을 RUDDER 하나로 제한한다(설계 원칙 2) |
| **Y = 정책 − 안팔기** | 같은 시드 짝비교 = 공통난수. 이미 쓰는 분산 감소 기법 |
| **causal mask** | 미래를 보면 라벨이 아니라 정답지가 된다 |
| **focal / follow-up 분할** | 창 끝 결정의 효과를 0 으로 잘못 처리하는 문제를 줄인다. 겹치는 창으로 모든 결정이 한 번은 focal 이 된다 |
| **자격시험 A~E** | 특히 **B(행동 제거)** 와 **D(순서 섞기)** 는 "시간대만 외운 것" 을 잡는 정확한 검사 |
| **§7 한계 인식** | epoch 기여도 ≠ 개별 행동. 이걸 스스로 짚은 것이 이 설계의 가장 큰 미덕이다 |

## 3. ★고칠 다섯 가지

### ① Transformer 를 먼저 쓰지 않는다 — **데이터가 먼저**

원 논문은 **LSTM** 이다. Transformer 도 되지만 우리 데이터 규모가 문제다.

```
같은 회차 예산(182 코어·분)으로
   지금 반사실 방식   세계 96개  = 결정 40건
   RUDDER 방식        궤적 202개 × 180토큰 = 36,360 토큰
```

**36,360 토큰은 Transformer 에게 적다.** 우리는 방금 [[YR-222]] 에서 5,761 파라미터
MLP 가 표본 70행에 과적합하는 것을 발견했다. Transformer 는 그보다 수십 배 크다.

→ **소형 LSTM 또는 1~2층 소형 Transformer 로 시작**하고, **held-out 예측 오차를
첫 관문**으로 둔다. 크기는 관문을 통과한 뒤에만 키운다.

### ② `Y` 의 정의가 논문 그대로가 아님을 명시한다

RUDDER 는 **한 궤적 안**의 리턴을 그 궤적의 토큰에 분해한다. 우리는 **두 궤적의
차이**를 정책 궤적의 토큰에 분배한다. 정당화는 된다 — 안팔기 세계가 시작 상태의
**결정론적 함수**라 `ΔΦ` 는 `(시작상태, 정책 궤적)` 의 함수다.

**다만 논문의 보증("최적 재분배 = 기대 미래보상 0")이 그대로 성립하지 않는다.**
변형임을 문서와 논문 초고에 명시한다. 성립 여부는 자격시험 E·F 로 실증한다.

### ③ 비정상성 — RUDDER 모델도 낡는다

정책이 회차마다 바뀌면 궤적 분포가 바뀌고 RUDDER 모델이 낡는다. 지금 반사실
라벨을 회차마다 버리는 것과 **같은 문제**다.

→ **RUDDER 재학습 주기를 사전등록**한다(예: 4회차마다). 재학습 없이 몇 회차까지
쓸 수 있는지는 자격시험 A 를 **지난 회차 정책의 궤적**에 적용해 잰다.

### ④ ★자격시험 F 를 더한다 — **우리에게만 있는 무기**

다른 RUDDER 연구는 못 하는 검증이 우리에겐 가능하다. **반사실 시뮬레이터가 있다.**

```
RUDDER 가 "10:31 epoch 가 −8만원 기여" 라고 하면
   → 실제로 10:31 에 개입해 반사실을 굴린다
   → 측정값과 부호·크기가 맞는가
```

| 결과 | 뜻 |
|---|---|
| 부호 일치율 높고 크기 상관 있음 | **기여도가 진짜 인과를 가리킨다** |
| 부호는 맞는데 크기 안 맞음 | 순위 용도로만 쓴다(표본 추출기) |
| 부호도 안 맞음 | **사용 불가** |

이게 A~E 보다 강한 검사다. A~E 는 "모델이 뭔가를 학습했다" 를 보지만,
F 는 **"그게 우리가 재려던 그것이냐"** 를 본다.

### ⑤ §7 의 두 선택지 대신 — **분업**

사용자 설계의 선택지 1(epoch 공동행동 학습)은 **v3 의 연구 주장을 포기**한다.
"독립 행위자 + 거부권 시장" 이 v3 의 핵심인데, 공동 보상으로 학습하면 그 구조가
학습에서 사라진다. 축을 바꾸는 게 아니라 **연구 질문을 바꾸는 것**이다.

대신 **역할을 나눈다:**

```
시간 축 신용   RUDDER      어느 epoch 가 비용 차이를 만들었나
행위자 신용    반사실       그 epoch 안에서 누구 몫인가   ← 지금 쓰는 것 그대로
```

### ★그리고 여기서 진짜 값이 나온다 — RUDDER 를 **표본 추출기**로

지금 [[YR-222]] 의 병목은 *"신호가 오차보다 작다"* 이고, 라벨 40건을 **균등 간격**
으로 뽑고 있다(`RolloutBudget.stride`). 대부분이 아무 일도 안 일어난 epoch 다.

RUDDER 가 중요한 epoch 을 짚어주면 **같은 예산으로 신호 큰 표본**을 뽑는다.

| | 지금 | RUDDER 추출 |
|---|---|---|
| 표본 선택 | 균등 간격 | **기여도 상위 epoch** |
| 예산 | 세계 96개 | 세계 96개 (동일) |
| 라벨 차이 중앙값 | 50,824원 | (기대) 더 큼 |

**이 쓰임은 자격시험 F 만 통과하면 된다** — 크기가 안 맞아도 **순위만 맞으면**
쓸 수 있다. 정책 학습에 기여도를 직접 넣는 것보다 **문턱이 훨씬 낮다.**

## 4. 다시 쓴 적용안

```
0단계  [[YR-222]] 결과 확인          ← 전제가 바뀐다 (§6)
         ↓
1단계  궤적 수집       정책/안팔기 3시간 × N궤적 · 1분 epoch 토큰 기록
         ↓
2단계  RUDDER 학습     소형 LSTM · causal · held-out 20%
         ↓
3단계  자격시험 A~F    F 가 결정적 (반사실 개입과 대조)
         ↓
4단계  ★표본 추출기로만 투입 (문턱 낮음)   → 효과 확인
         ↓
5단계  통과하면 그때 정책 학습에 기여도 연결 → [[YR-224]]
```

**4단계와 5단계를 반드시 나눈다.** 4단계는 지금 병목을 직접 치고 실패해도 잃는 게
적다. 5단계는 학습 구조를 바꾸는 일이라 위험이 크다.

## 5. 사전등록 (착수 시 동결)

```
궤적            200 (정책/안팔기 각 3시간)
토큰            1분 epoch · 창당 180
모델            소형 LSTM (은닉 ≤128) — Transformer 는 관문 통과 후
검증            궤적 20% held-out
focal/follow-up 0~1시간 focal · 1~3시간 관찰
재학습 주기     4회차
시드            비판정 대역
```

| 관문 | 기준 |
|---|---|
| **A** 예측 | held-out 궤적의 ΔΦ 예측 상관 ≥ 0.5 |
| **B** 행동 제거 | 행동 특징을 지우면 예측 오차가 **유의하게 나빠진다** |
| **C** 반복성 | 초기값 3개에서 상위 epoch 순위 상관 ≥ 0.5 |
| **D** 순서 섞기 | 섞으면 예측 오차가 **나빠진다** |
| **E** 보존 | Σ기여도 ≈ ΔΦ (상대오차 ≤ 10%) |
| **★F** 개입 | 상위 20 epoch 에 실제 반사실 개입 · **부호 일치 ≥ 70%** |

**A·B·D·F 는 필수.** C·E 는 미달이면 "순위 용도만" 으로 제한한다.

## 6. ⚠️ [[YR-222]] 결과가 전제를 바꾼다

| YR-222 결과 | RUDDER 에 미치는 영향 |
|---|---|
| 과적합이 원인이었다 | RUDDER 는 **더 큰 모델**이라 위험이 커진다 — 궤적 수를 먼저 늘려야 |
| **특징이 상황을 설명 못 한다** | RUDDER 도 **같은 특징**을 쓴다 → 같은 벽. 정보 축([[YR-198]])이 먼저 |
| 라벨은 맞는데 목표가 틀렸다 | RUDDER 가 **가장 유망**해진다 |

**그래서 YR-222 가 끝나기 전에는 착수하지 않는다.**
