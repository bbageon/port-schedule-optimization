미예약·예약 누락은 이번 합성 조건에서 제외한다. 예약 존재와 정시 도착은 구분한다.

## 실자료가 말하는 것 (사용자 제공 요약, 11/03 하루)

- 트럭 오더에서 미래 시각은 **예약 시각(`inOutReserveTime`) 하나뿐**이다. 기사가 신고한 값이지 예측이 아니다.
- 예약 시각 채움: 코피노 24,655건 중 65.3%, 방문 2,947건 중 87.9%.
- **게이트 진입이 예약보다 중앙값 93분 늦고, ±30분 안에 맞은 비율은 23.5%.**
- 유효기간 필드는 있지만 0건 채움. 블록 대기 차량 수는 실시간 값으로 있다.
- 예상 대기·도착 예정 같은 값은 없다 — 실측에서 직접 만들어야 한다.

⚠️ 위 숫자는 다른 세션의 분석 요약이다. 원자료로 다시 재서 확인한다.

    공개 예약 필드는 장부에 따로 없어 매핑은 코드로 대조했다. 주행 오차와 구분한다.
  - 기존 “약 10분·±20분” 설명은 다른 생성기의 설정을 현재 경로로 오인한 것이다.
  - 30일 무대: `net_schedule_orders` 가 **예약 시각 = 실제 도착 시각**으로 채운다.
- 정책은 공개 예상값을 읽지만 환경이 예약을 실제 진입과 같게 만든다. 현실적인 예약 오차 근거가 없다.

## 할 일

1. 예약 시각과 실제 진입 시각을 **따로** 뽑는다. 차이는 실측 분포(늦는 쪽 치우침, 긴 꼬리를 자르지 않음).

2. 리드타임(통지 → 진입) 표본을 DGT 1시간 71건에서 실자료로 바꾼다. 예약 오차와는 다른 축이다.

   실현값은 여전히 읽지 않는다.
