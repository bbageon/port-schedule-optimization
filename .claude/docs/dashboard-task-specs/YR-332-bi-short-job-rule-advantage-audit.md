# YR-332-bi — 짧은 작업 우선 규칙 우위의 원인 분리 (시뮬레이터 구성 점검)

- **상태**: in-progress
- 상위 [[YR-332]], 2026-11-22 등록.
- **3대 게이트 보정 대상**: `scenario_validity`. 규칙 비교 결론이 시뮬레이터 설정에서 나왔는지 확인한다.
- 정책 학습은 하지 않는다. 환경·평가 계약만 한 축씩 확인한다.

## 발단

- 2026-11-21 사용자: "합성 데이터는 실제 데이터를 분석해서 만들었지만, 시뮬레이터가 제대로 구성됐는지 확인해야 할 것 같다."
- 2026-11-22 사용자: "짧은 작업 우선 규칙이 비용 절감이 가장 크다는 결과는 실제로는 말이 안 된다. 규칙과 산정식을 검토해서 이유를 해석해 달라."

## 사전 확인 (2026-11-22, 읽기 전용 재집계 · 판정 아님)

자료: [aq 평가](../../../outputs/reports/yr332_linked_retraining/README.md)의 규칙 실행 45회(규칙 5종 × 물량 3개 × 날짜 3개),
[v 평가](../../../outputs/reports/yr332_classical_eval/README.md)의 규칙 실행 15회. 새 시뮬레이션은 하지 않았다.

### 1. 1위는 관측 범위 밖의 과부하 물량에서 정해졌다

| 하루 오더 | 짧은 작업 우선(SPT) | 짧은 실작업 우선(SF_SPT) | 통지순(FIFO) | 최장 대기 우선(LWKR) |
|---:|---:|---:|---:|---:|
| 3,500 | 18.99분 | 19.21분 | 19.28분 | 18.83분 |
| 7,500 | 34.75분 | 34.78분 | 32.57분 | 33.11분 |
| 15,000 | 130.15분 | 130.62분 | 189.16분 | 186.51분 |

- 트럭 시간은 게이트 진입→작업 완료이고 24시간에서 끊는다. 3,500건에서는 규칙들이 거의 같다. 7,500건에서는 통지순이 가장 짧다.
- 세 물량 합산 비용 가운데 15,000건이 짧은 실작업 우선은 83%, 통지순은 87%를 차지한다. 합산 순위는 사실상 15,000건의 순위다.
- 15,000건 입력의 최대 시간당 방문은 917~997번이다(bc 입력 기준). 실제 관측 최대는 245번이다([[YR-332-ap]]).

### 2. 과부하에서는 반입을 살리고 반출을 굶긴다

- 15,000건 반입 중앙값: 짧은 실작업 우선 33분, 통지순 139분이다. 내려놓기는 파내기가 없어 짧다.
- 15,000건 반출 90분위: 짧은 실작업 우선 611분, 통지순 441분이다. 반출 10대 중 1대는 10시간 넘게 기다린다.
- 과부하에서는 시간당 처리 건수가 결과를 정한다. 짧은 일부터 하면 처리 건수가 가장 많다.

### 3. 비용식이 대기 시간의 합을 센다

- 원화 비용([`reward/krw.py`](../../../src/yard_rl/v7/reward/krw.py)): 트럭 40,000원/시간(1시간 초과분은 2배), 크레인 추가 이동 60,000원/시간,
  재조작 2,000원/회, 본선 유휴 35.88원/GT·시간.
- 일이 모두 와 있는 기계 하나에서 대기 시간의 합을 최소로 만드는 순서는 짧은 일부터 하는 순서다(Smith 1956 정리).
  도착이 이어지는 실제 무대에서 최적은 아니지만, 이 비용식에서는 이 규칙이 구조적으로 유리하다.
- 누가 너무 오래 기다리는지는 비용에 따로 드러나지 않는다. 24시간 검열 때문에 남은 트럭의 대기 비용도 잘린다.

### 4. 24분 넘은 트럭은 본선보다 먼저 처리된다

- 외부 트럭의 누적 대기가 `0.8 × long_wait_sla_s(1,800초)` = 24분을 넘으면 필수 작업이 된다
  ([`candidates.py`](../../../src/yard_rl/v7/world/integrated/candidates.py) `_is_mandatory`). 해결기는 필수 작업을 규칙 순서보다 앞에 둔다.
  본선 작업도 그 뒤로 밀린다.
- v 평가 3,500건 본선 비용: 본선 우선·도착순 65.4백만 원, 도착순 65.9백만 원, 최단 작업 55.4백만 원이다(날짜 1개). 본선을 먼저 하라는 규칙도 본선 비용을 줄이지 못했다.
- aq 3,500건에서 최단 작업이 통지순보다 싼 25.3백만 원 가운데 19.2백만 원(76%)이 본선 비용이다. 트럭은 4.7백만 원, 재조작은 1.4백만 원이다.
- 해석(미검증): 밀린 필수 트럭을 가장 빨리 치우는 규칙이 크레인을 본선에 가장 빨리 돌려준다.

### 5. 작업 시간을 미리 정확히 안다

- 엔진은 완료 시각을 `계획 시작 + 계획 소요`로 정한다([`engine.py`](../../../src/yard_rl/v7/world/integrated/engine.py)). 실제 소요에 변동이 없다.
- 최단 작업 규칙은 이 계획 소요를 그대로 정렬 키로 쓴다([`dispatch.py`](../../../src/yard_rl/v7/dispatch.py) `SPT`). v 보고서도 "현실의 시간 추정 오차는 검증하지 않았다"고 적었다.
- 크레인 속도·잠금 시간 등은 문헌으로 정한 가정값이다(설정 파일 `assumed: true`, 실측 아님).

### 6. 실제와의 출력 대조가 비어 있다

- 현실성 게이트가 요구하는 외부 대조 5종이 v7 판정에서 모두 미수집이다: 게이트→블록 시간, 초기 장치율, 트럭 도착률, 크레인 서비스 시간, 본선 작업량.
  최근 판정 파일([bc](../../../outputs/reports/yr332_global_policy/current-gates.json)·[aq](../../../outputs/reports/yr332_linked_retraining/current-gates.json))의 `anchors`가 비어 있다.
  aq 판정에서는 본선 마감 달성 가능성 내부 검사도 실패다.
- 구 등록부 [`external_anchors_v1.json`](../../../configs/anchors/external_anchors_v1.json)은 이전 무대 기준이다. 크레인 시간 근거는 [[YR-238]] 재감사 대기다.

## 할 일 (사전등록 후 한 축씩)

1. **물량별 판정**: 보고와 판정을 물량별로 나눈다. 관측 범위 밖 물량은 과부하 시험으로 표시하고 합산 순위를 주 판정에서 뺀다. 기존 결과 재집계만 한다.
2. **필수 작업 순서**: 24분 기준의 근거를 확인한다. 본선 작업을 필수 트럭보다 앞에 두는 변형과 현행을 같은 입력·규칙 5종으로 비교한다.
3. **작업 시간 오차**: 실제 소요에 근거 있는 변동을 넣는다. 규칙이 보는 추정에도 오차를 넣는다. 짧은 작업 우선의 우위가 남는지 확인한다.
4. **장기 대기**: 24시간 검열 밖 대기의 처리 방법과 꼬리 지표(반출 90·99분위, 최장 대기)를 정한다. 주 지표 변경은 사용자 확인 뒤에 한다.
5. **실측 대조 5종**: v7 저장 결과에서 다섯 항목을 계측한다. 실제 자료·공개 근거와 범위를 대조한다(크레인 시간은 [[YR-238]]과 함께).

## 완료 조건

- 짧은 작업 우선의 우위가 어느 설정에서 생기고 사라지는지 축별 전후 수치로 분리한다.
- 바꾼 설정과 근거 등급(실측·공개·가정)을 함께 남긴다. 결과를 보고 기준을 바꾸지 않는다.
- 학습 정책 비교와 채택 판정은 이 작업 뒤에 다시 한다.

## 이번 조사 사전등록 (2026-11-22)

직전 본선 턴타임 실험과 동일한 3개 시험 날짜·3개 물량을 사용한다. 모델 재학습과 현장 기준 변경은 범위 밖이다.
기본 비교 규칙은 짧은 실작업, 실제 블록 도착순, 최근접, 본선 우선 도착순, 최장 대기다.
각 규칙에 현행·본선과 24분 트럭이 한 크레인에서 경합할 때 본선 실작업 선행을 각각 적용한다.
짧은 실작업·실제 도착순에는 24분 우선순위 해제도 적용해 두 규칙 간 격차 변화를 분해한다.
짧은 실작업에는 계획시간에 고정 오차 ±30% 범위(서로 반대 부호 2회)를 둔 민감도와 소요시간 항 완전 제거(보호 켬·끔)를 더한다.
시간 오차는 작업·크레인·날짜로 고정한 가정이다. 실행시간·장비 안전·후보·초기재고·도착·비용은 고정한다.
주 지표는 24시간 내 트럭 진입→완료 평균이다. 반입/반출 각각의 긴 대기·미완료와 본선 하역시간·총비용을 함께 낸다.
실제 도착률 범위의 3,500건을 먼저 해석한다. 나머지는 혼잡 시험이다. 고정 규칙 간 차이와 학습 모델과의 기존 격차를 구분한다.
실측 오차분포와 내부 우선배정 기록을 확보하지 못하면 현장 효과는 미확정으로 남긴다.

## 측정 결과와 남은 범위

같은 입력 144회. 3,500건 최단 규칙의 보호 해제 +6.09분, 시간 오차 +0.07분. 15,000건 도착순−최단 +59.94분.
첫 날짜 세 물량의 단독 크레인 선택을 별도 관찰하고 기존 원장과 일치함을 확인했다. [수치·현장 근거](../../../outputs/reports/yr332_short_job_audit/README.md)
