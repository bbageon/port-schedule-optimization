- **Epic**: Exp / **Priority**: 🟠 / **등록일**: 2026-08-09 (외부 감사 권고)
- **상태**: backlog — 선결: YR-150 최종 재자격(lead 30분 환경)
- **1줄**: 고정 WIP walk-in 은 **완전 예측 조건**(예약·ETA 오차 0)이다 — 오차를 주입해
  방어 경로 발화(A·0B 전)와 결론 안정성(B·0B 후)을 확인한다.
- **★A/B 분할(32차)**: 0B 결과가 없는데 "결론이 뒤집히는가"를 먼저 검사할 수 없다.
  - **YR-162A (0B 전)**: 오차 주입 시 **버전 갱신·재견적·거부(stale/이연) 경로가 실제
    발화**하는지만 검사 — 죽은 방어 경로 해소. 결론 비교 없음.
  - **YR-162B (0B 후·잠금평가 포함)**: 무오차에서 얻은 GO/STOP 방향이 오차 조건에서
    유지되는지 + **K/Q30/S 잠금평가에 오차 조건 축 포함**. 뒤집히면 그대로 박제.

## 왜 지금 등록하는가 (시드 사실성 검토 2026-08-09)

고정 WIP 의 트럭은 투입 시각 = 통지 = gate-in 이라 **공개 예측이 실현과 1초도 안
틀린다**. 실제 항만과 다른 점이자 두 가지 위험이 있다:

1. **예측 기반 계산 기준선(Q30 등)에 유리한 편향** — 예측이 항상 맞는 세상에서는 계산
   견적의 성적이 실제보다 좋게 나온다. 성능 주장은 "예측 무오차 조건 한정"으로 달아야
   하며, 이 한정을 풀려면 본 probe 통과가 필요하다.
2. **죽은 방어 경로** — stale 후보 검출·version 검사·이연 재예약의 오차 대응 코드가
   한 번도 발화하지 않아, 거기 결함이 있어도 지금은 보이지 않는다.

## 무엇을 하는가

1. **오차 주입 스위치**: 통지 시각(notified)과 실현 gate-in 을 분리하는 준수오차
   `ε ~ N(0, σ)` (±2σ 절단) — `notified + ε = 실현`. 공개 예측은 계속 통지 기반
   (실현 미참조 — 정보경계 불변).
2. **σ 동결**: 오차 크기는 **결과 열람 전** 동결한다. 후보: 기존 유입량 계약의
   준수오차 σ=600초(1~3차 시절 값) vs 문헌 재조사 값 — 등록 시점에 하나로 확정하고
   결과를 보고 바꾸지 않는다.
3. **판정 2축 (A/B 로 시점 분리 — 32차)**:
   - **A(0B 전) 방어 경로 발화**: stale/version/이연 각 경로가 ≥1회 실제로 발화하고
     fail-closed 동작이 원장에 남는가 (죽은 경로 해소).
   - **B(0B 후) 결론 안정성**: 무오차 조건의 0B GO/STOP 방향이 오차 조건에서
     뒤집히는가 — 뒤집히면 그 사실을 판정으로 박제(완화 금지). 잠금평가 축 포함.
4. **범위 아님**: 오차 하 성능 최적화·σ 튜닝·예측기 개선. 여기는 probe(감사)다.

## 완료 조건

- σ 와 시드가 결과 열람 전 동결·박제되고, 방어 경로 발화 원장과 결론 안정성 비교표가
  보고서로 남는다. 성능 주장 없음.
