# YR-187-B — 스키마에 **실측 값**을 꽂는다 (데이터 수령 후)

- **Epic**: Data / **Priority**: 🔴 / **등록일**: 2026-08-18 / **상태**: backlog
- **선행**: [[YR-187]] A단계 완료 ✅ (2026-08-18) · **BNCT 실데이터 수령** ❌ (외부 대기)
- **1줄**: A 는 **그릇**을 맞췄다. B 는 그 그릇에 **실제 값**을 붓는다.

## A 가 끝난 지점

`order_schema.attach()` 가 스케줄 항목마다 실규격 필드 9개를 더한다. 값은 아직
**합성**이다 — `reserved_s == gate_in_s`(준수 오차 0), `block_assigned ==
block_worked`(재배정 없음), `size_class` 는 불리언에서 유도한 2종.

## B 가 할 일

| # | 무엇 | 왜 |
|---|---|---|
| 1 | `reserved_s` ↔ `gate_in_s` 를 **실측 분포**로 분리 | 지금 σ=600초는 **가정**이다. 둘의 차가 예약 준수 오차이고, [[YR-190]] 이 이 축의 민감도를 미리 잰다 |
| 2 | `size_class` 를 ISO 4자리 실측 범주로 | 서비스 시간·적치 제약이 규격에 걸린다 |
| 3 | `target` 을 60% → **100%** | 실데이터는 반입도 `conNo` 를 갖는다 |
| 4 | `travel_s`·`travel_base_s`·`exit_travel_s` 출처를 난수 → 실측 | 이름은 유지, 출처만 교체 |
| 5 | `requested_flow`·`fallback_reason` **삭제** | 합성 생성기 인공물 — 실제 오더에 없는 개념이다 |
| 6 | `record_swap()` 을 **판매 확정 경로에 연결** | 지금은 함수만 있고 호출되지 않는다. 재배정 이력이 실데이터와 대조 가능해진다 |
| 7 | 블록 목록·거리 대조 | 개수 21 은 확인됐으나 **배치가 다르면** `gate_to_block_s()` 가 어긋난다 |

## 착수 전 확인이 필요한 것 (회신본 §추가요청)

`docs/data-handover/2026-08-18-BNCT-스키마-회신.md` 의 5건이 답을 받아야
B 의 절반이 성립한다. 특히:

- **본선 접안·하역 스케줄** — Φ 의 7.5% + 크레인 경쟁의 원천. 없으면 2단계 재구성이 왜곡된다.
- **`VBS_RES_AVL` 실제 값** — [[YR-176]] 슬롯 용량의 **정본**(우리 유도값을 대체).
- **`blockAvgTT` 정의** — 제공 문서의 `travel_base_s` 대응은 오류였다(A 단계에서 정정 기록).

  합성이라는 표시만 지운 것이다.
