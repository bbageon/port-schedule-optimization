## 무엇이 문제인가

Dashboard 는 **채택 배포 구성**을 "C0(전략적 위치조정 없음) + 유한 DEFER + 대기 허가증
안전장치, PREPOSITION 제거"라고 적는다. 그런데 **코드에는 그런 이름의 구성이 없다.**

행동 정의는 `integrated/candidates.py` 의 **모듈 전역 플래그**로만 존재하고, 기본값이
**채택된 쪽이 아니라 기각·구판 쪽**이다.

| 플래그 | 코드 기본값 | 채택 판정 |
|---|---|---|
| `SAFETY_ONLY` | `False` (전략적 위치조정 **발행**) | YR-143/148 — 위치조정 **제거**가 우월 |
| `WAIT_MODE` | `"WAIT"` (무기한 대기) | YR-147 — 유한 `DEFER_ALL` |
| `BOUND_REPO` | `False` | 결속 계약(B2)에서 `True` |
| `PREPO_ONE_SHOT` | `False` | B2 계약에서 `True` |

실험들은 매번 `cand_mod.WAIT_MODE = "DEFER_ALL"` 처럼 **전역을 직접 갈아끼우고 되돌린다**
(yr143·yr146·yr147 등 10여 곳). 그래서 다음 두 사고가 구조적으로 가능하다.

1. **플래그를 안 켜면 조용히 기각된 정책이 돈다.** 실제로 YR-150 1단계 자격 파일럿의 규칙
   기준선이 기본값(위치조정 살아있음·무기한 WAIT)으로 돌았다 — 자격 확인이 목적이라 판정에
   영향은 없지만, 2단계 정책 비교에서 같은 실수가 나면 **비교 자체가 무의미해진다.**
2. 전역 가변 상태이므로 **한 프로세스에서 두 구성을 동시에** 다룰 수 없다(병렬·중첩 실행 불가).

## 무엇을 하는가

1. `PolicyConfig` 같은 **불변 값 객체 하나**로 행동 정의를 모으고, `ADOPTED`(YR-148 채택)와
   `LEGACY_DEFAULT`(구판 재현용)를 **이름 붙은 상수**로 둔다.
2. 후보 생성기가 전역 대신 **주입받은 config** 를 읽게 한다. 전역 플래그는 한 릴리스 동안
   deprecated 로 남기되 값을 읽지 않는다.
3. **골든 보존이 판정이다** — 기존 판정 실험들이 `LEGACY_DEFAULT`/각자 조합으로 바이트 동일
   결과를 내는지 회귀로 확인한다. 달라지면 어디서 갈라졌는지 수치로 제시한다.
4. 결과 JSON 재현 스탬프에 **사용한 config 이름과 전 항목 값**을 박제한다(지금은 남지 않는다).
5. 성능 판정 하네스(YR-150 2단계·YR-151 0B)는 `ADOPTED` 를 **명시적으로** 받도록 강제하고,
   미지정이면 실행을 거절한다(fail-closed).

## 완료 조건

- "채택 배포 구성"을 코드 한 곳에서 가리킬 수 있고, 결과 JSON 만 봐도 어떤 구성으로 돌았는지
  알 수 있다.
- 전 회귀가 기존과 동일하거나, 차이의 원인이 정확히 설명된다.

## 하지 않는 것

- 이 정정을 계기로 행동 정의 자체(임계·행동 종류)를 바꾸는 것. 이번 범위는 **배선과 기록**뿐이다.
