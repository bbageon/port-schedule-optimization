# YR-190 — 리드타임 두 팔 실험: 고정 vs 분포

- **Epic**: Exp / **Priority**: 🔴 / **등록일**: 2026-08-18 / **재설계**: 2026-08-20
- **3대 게이트 보정 대상**: `performance`
- **사용자 지시 2026-08-20**: *"리드타임이 같게 실험 한번, 리드타임이 다르게 실험 한번"*
  → 기존 σ 4점 스윕(0·300·600·1200초)을 **두 팔 대조**로 단순화한다.
- **아키텍처 축**: v3 축 ① — [02 무대](../architecture/02-무대.md) §4
- **1줄**: 모든 트럭이 똑같이 30분 전 통지되는 지금 무대와, 실측 분포에서 뽑은
  제각각 리드를 쓰는 무대에서 **규칙 대비 격차가 달라지는가**를 잰다.

## 왜 이 축인가

리드가 전부 같으면 **정보 격차라는 축이 없다.** 도착 시각·반입출·이력은 여전히
다르므로 고를 것은 있지만, "어느 트럭을 더 일찍 알았나"로는 구분할 수 없다.

그 축이 **규칙이 못 다루는 유일한 종류의 질문**을 만든다.

> 5시간 전에 아는 트럭을 지금 배정할까, 정보를 더 모으고 나중에 결정할까?

규칙(`sell_gain`)은 창 안의 정보로 순이득을 내는 **공식**이라 "기다리면 더 나은
선택지가 올 확률"이라는 개념이 없다. 학습은 경험에서 배울 수 있다.

## ★설계 함정 — 창을 안 고치면 두 팔이 같아진다

후보 자격이 **창** 기준이다.

```python
iter_pre_gate_candidates(mbt, src, horizon_s=WINDOW_S)   # WINDOW_S = 1800
    → 공개 ETA 가 30분 안에 든 트럭만 후보
```

5시간 전에 통지해도 **후보가 되는 건 도착 30분 전**이다. 리드만 늘리면 정책이
할 수 있는 일이 한 줄도 안 늘어나 **B 팔이 A 팔과 동일 동작**이 된다.

**해소**: 창을 **리드와 분리해 파라미터로** 만든다. `ANNOUNCE_LEAD_S` 하나가 지금
두 역할을 겸하므로 먼저 갈라야 한다 → [03 결정층](../architecture/03-결정층.md) §5.

**⚠️ 정정 2026-08-22** — 구 판은 여기에 뚜껑(`WINDOW_CAP = 7200초`)을 두고 근거를
*"후보 수가 리드에 비례해 늘어 계산량이 터진다"* 로 적었다. 그건 **v2**(60초마다 창
안 전부 재검토) 기준이고, [[YR-203]] 의 **최초 통지 1회** 계약에서는 성립하지 않는다
(§② 참조). **뚜껑을 없애고 창을 스윕 축으로 승격**한다.

## 두 축 — 리드(분포 여부) × 창(길이)

### ① 리드 두 팔

| | A 팔 (고정) | B 팔 (분포) |
|---|---|---|
| 통지 리드 | **전 트럭 1,800초** | **트럭마다 추출** (아래 분포) |

**A 팔은 현행 무대**다. 코드 변경 없이 재측정한다(대조군 역할).

### ② 창 길이 스윕 (사용자 지시 2026-08-22)

*"30분뿐 아니라 1시간·2시간·4시간·24시간 다 테스트해봐야 할 것 같다."*

```
창 = 30분 · 1h · 2h · 4h · 24h        (48h 는 제외 — 에피소드가 24h 다)
```

**★계산량 걱정은 없다.** [[YR-203]] 의 **최초 통지 1회** 계약에서 한 epoch 배치는
그 60초에 자격을 얻은 건수(7,500대 기준 **평균 5.2건·피크 17건**)이고 **창 길이와
무관**하다. 하루 결정 수도 오더 수로 고정된다. (v2 의 "60초마다 창 안 전부 재검토"
였다면 창 24h 에서 동시 후보가 7,500건이 됐다 — 그건 옛 계약이다.)

**창이 바꾸는 것은 "언제 결정하나"다.**

| | 정보 | 선택지 |
|---|---|---|
| 창이 **길수록** | 적다 — 그 사이 상황이 변한다 | **넓다** — 아직 멀리 있어 어디로든 |
| 창이 **짧을수록** | 정확하다 | **좁다** — 곧 도착해 먼 블록은 무리 |

**이 맞바꿈이 규칙이 못 다루는 종류다** — *"지금 정할까, 정보를 더 모을까"* 는
공식으로 답이 안 나온다. RL 이 이길 자리가 있다면 여기다.

### ⚠️ 창은 리드를 넘을 수 없다

**통지 안 된 트럭은 후보가 될 수 없다.** A 팔(리드 30분 고정)에서 창을 2시간으로
늘려도 볼 게 30분치뿐이라 **아무것도 안 바뀐다.**

| 팔 | 유효한 창 |
|---|---|
| A (리드 30분 고정) | **30분 하나뿐** — 스윕이 성립하지 않는다 |
| B (리드 실측 분포·중앙 1.27h) | 30분 · 1h · 2h · 4h · 24h **전부** |

**그래서 창 스윕은 B 팔에서만 한다.** A 팔은 리드 고정의 대조군으로 30분 한 점만.

### B 팔 리드 분포

DGT 1차 표본(100건) 실측: 중앙값 **1.27h** · 사분위폭 **2.36h** · 음수 **14.1%**.

| 항목 | 처리 |
|---|---|
| 분포 형태 | 실측 분위수에 맞춘 **로그정규** (모수는 착수 시 적합·동결) |
| **음수 리드** | **0 으로 절단** — [00 라이프사이클](../architecture/00-라이프사이클.md)이 `copinoNotice ≤ gateIn` 을 요구한다. 통지 즉시 도착이므로 공간 판매 불가·시간 이연만 |
| 추출 | 시드에서 미리(재현성) — `random.Random(f"h21:lead:{seed}")` |

**분포는 가정이 아니라 실측 적합**이다. 다만 표본이 100건뿐이라 **8일치가 오면
재적합**한다(재실행 불필요 — 곡선 위 위치만 바뀐다).

## 판정

| | |
|---|---|
| **주판정** | 각 팔에서 `학습 − 규칙`. **두 격차의 차**가 관심량 |
| 모드 | argmin 결정론 (ε=0·σ=0) |
| 팔 | A(창 30분) + **B × 창 5수준** × {규칙, 학습} = **12셀** |
| 독립단위 | 날 (n=16) · 같은 날 짝지어 |
| 유의 | \|t\| ≥ 2.13 (df=15 양측 95%) |
| 대역 | **새 대역** — 재사용 금지 |

### 세 결과의 대응을 **미리** 적는다

| 결과 | 뜻 | 다음 |
|---|---|---|
| B 에서 격차가 **유의하게 줄어듦** | **"학습이 규칙을 이기는 조건은 정보 격차"** — 정량 조건을 얻는다 | 리드 분포를 무대 정본으로 채택하고 v3 축 ②③ 로 |
| 두 팔이 **구분 불가** | 리드는 원인이 아니다 | 이 축 종료. 남은 원인은 시야(축 ②)·정보(축 ④) |
| B 에서 격차가 **커짐** | 긴 창이 오히려 해롭다(선택지가 늘어 승자의 저주 악화) | 문턱([[YR-195]])을 창 길이에 연동해 재검 |

**결과를 보고 서사를 고르지 않기 위해 실행 전에 적는다.**

## 금지

- 리드 분포 모수를 **결과를 보고** 바꾸지 않는다.
- **창 격자(30분·1h·2h·4h·24h)를 결과를 보고 바꾸지 않는다** — 착수 시 동결하고
  유리한 창만 골라 보고하지 않는다. 다섯 수치를 다 적는다.
- A 팔에서 창을 스윕하지 않는다 — 리드가 30분이라 **정의상 무효**다.
- 유리한 팔만 보고하지 않는다. **12셀 전부** 보고한다.
- 판정 대역 재사용 금지: 9,200,000 · 9,300,000~ · 9,600,000~ · 9,700,000~ ·
  9,800,000~ · 비판정 9,900,0xx

  "언제 결정하나"를 바꾸는 축**이다. 48h 는 에피소드(24h)를 넘어 제외.
