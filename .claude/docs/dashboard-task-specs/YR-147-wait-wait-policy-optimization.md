# YR-147 — WAIT-WAIT 정책 최적화: 금지 없이 진행·대기 구분 학습

> 상태: **in-progress** (2026-08-03 착수 — board 정합 정정, 21차) · 사용자 결정 2026-08-03
> 후속: YR-143 행동공간 비교 → YR-146 배포 안전장치
> 결정이력: [정책 최적화 우선 결정](../strategy-history/2026-08-03-YR-146-WAIT-WAIT-정책최적화-우선-사용자결정.md)

## 무엇을 왜

YR-145에서 안전한 `SERVE+WAIT`·`WAIT+SERVE`가 있었지만 PPO가 `WAIT+WAIT`을 가장
싸다고 오평가했다. 연구 단계에서 전원 대기를 하드 마스크하면 정책이 스스로 고쳤는지 알 수
없다. 따라서 원시 WAIT를 유한하고 이유가 있는 대기로 바꾸고, 진행과 대기의 실제 비용 차이를
정책에 직접 학습시킨다.

## 용어 계약

- **구조적 대기**: 처리 가능한 작업이 없거나 설비·하류가 막혀 엔진이 다음 외부사건까지
  시간을 진행하는 상태. 정책 행동으로 세지 않는다.
- **전략적 대기**: 안전한 진행 공동행동이 있는데 정책이 대기를 선택하는 상태.
- **회피 가능한 전원 대기**: `SERVE+WAIT` 또는 `WAIT+SERVE` 등 안전한 진행 후보가
  하나 이상 있는데 `WAIT+WAIT`을 선택한 경우.
- **진행 행동**: 실제 작업을 시작하거나 교착 통로를 확실히 여는 행동. 목적 없는
  PREPOSITION/REPOSITION은 진행으로 세지 않는다.

## 단일축 사다리

한 번에 여러 축을 바꾸지 않는다. 각 단계는 신규 시드에서 자기 효과가 확인될 때만 다음으로
간다.

1. **재현·기준 측정**: YR-145 실패 snapshot과 신규 교착 상태에서 세 공동행동의 실제
   짝지은 후속비용을 재고, 현재 PPO의 회피 가능 전원대기율을 동결한다.
2. **행동 의미 축 — 3군 분해 (★21차 감사 보정 2026-08-03)**: 원안의 "유효 trigger 가
   없으면 DEFER 후보를 만들지 않는다"는 **조건부 행동 마스크**라서, 결과가 좋아져도
   정책이 기다림을 배운 것인지 코드가 나쁜 후보를 없앤 것인지 구분되지 않는다. 분해:
   - **A**: 현재 무기한 WAIT (YR-145 B2 체크포인트 그대로 — 재학습 없음)
   - **B**: 후보 삭제 없이 **모든 WAIT 을 유한 DEFER 로 교체** — 만료(최대 지속시간)가
     항상 있어 wake 가 보장되는 대기. 관측 가능 trigger 가 있으면 min(trigger, 만료),
     없으면 만료만. (신규 학습)
   - **C**: **유효한 관측 가능 trigger 가 있을 때만 DEFER 발행**(없으면 대기 후보 부재).
     (신규 학습)
   - **B−A = 무기한→유한 교체 효과 / C−B = trigger 부재 시 후보 삭제 효과** 를 분리.
   - trigger 는 공개 정보만(provided_eta·release_time·공개 예약·진행 중 작업 완료
     예정) — **실현 미래시각 비누출**. trigger 종류·잔여시간·만료·버전 변경을 기록.
   - 보상·상태·PPO 구조 불변. YR-050 결정시각 엄격 증가 회귀 고정.
   - 2단계 전 고정(21차): ①짝 계측은 셀·에피소드 **층화**(셀별 할당·에피소드당 상한)
     ②진행 후보 **top-K(≥2) 실비용** 비교 ③완주·backlog 를 비용보다 **먼저** 비교
     ④trigger 기록 ⑤미래시각 비누출 ⑥WAIT 감소 → 위치조정 증가 이동 검사
     ⑦체크포인트 sha256·재실행 명령 박제.

3. **순위 신호 단일축(2단계 미달 시)**: 같은 상태·같은 난수에서 전원 대기와 top-K 진행
   후보의 비용 차이를 만들고 PPO에 보조 순위손실만 추가한다.

```text
D_wait(s) = C_H(s, WAIT+WAIT) - min_a C_H(s, a),  a = 안전한 진행 후보
```

`D_wait>0`이면 진행 후보 확률을 높이고, `D_wait<0`이면 실제로 유리한 전략적 대기를
보존한다. 모든 전원 대기에 고정 벌점을 주지 않는다.

4. **희귀상태 노출 단일축(3단계 미달 시)**: 동시 SERVE 불가·한 대 SERVE 가능·미래
   사건 없음·본선 RELEASED 잔여 등의 상태만 학습 분포에 추가한다. 판정 상태·시드는
   학습에서 완전히 분리한다.

## 연구 판정 — 하드 마스크 없음

- 학습·평가 모두 `WAIT+WAIT` 하드 마스크와 강제 progress fallback을 끈다.
- 자연분포와 교착 스트레스셋을 분리 판정한다.
- 1차: 회피 가능한 전원대기율과 progress-vs-wait 순위 정확도. “0건” 목표의 표본수·허용
  상한은 파일럿 뒤 결과 열람 전 동결한다.
- 공동지표: v2 실현 지연비용, 평균 A→O, 본선 초과시간.
- hard guard: 완주 100%, backlog 0, 물리·안전위반 0, 종단 정지 0.
- 정상 대기 보존: 실제 짝지은 비용상 대기가 유리한 상태에서의 선택 정확도를 별도 보고한다.
- WAIT 감소가 PREPOSITION/REPOSITION 장악으로 이동하는지 반드시 함께 검사한다.

## 범위 밖

정책 성능 검증 전에 `WAIT+WAIT` 금지, resolver 강제 대체, 엔진 강제 탈출을 성능 arm에
넣지 않는다. PPO는 확률 정책이므로 운영상 0건 보장은 별도 YR-146이 담당하며, 그 결과를
YR-147의 학습 성과로 합산하지 않는다. 이는 YR-052/119의 자유 WAIT 재개가 아니라,
사유·만료·재검토시각을 가진 새 DEFER 행동의 최초 검증이다.
