# YR-147 — WAIT-WAIT 정책 최적화: 금지 없이 진행·대기 구분 학습

> 상태: **in-progress** (3단계 실행 전 계약 보정 — 23차 검토 반영) · 사용자 결정 2026-08-03
> 후속: YR-143 행동공간 비교 → YR-146 배포 안전장치
> 결정이력: [정책 최적화 우선 결정](../strategy-history/2026-08-03-YR-146-WAIT-WAIT-정책최적화-우선-사용자결정.md)

## 무엇을 왜

YR-145에서 안전한 `SERVE+WAIT`·`WAIT+SERVE`가 있었지만 PPO가 `WAIT+WAIT`을 가장
싸다고 오평가했다. 연구 단계에서 전원 대기를 하드 마스크하면 정책이 스스로 고쳤는지 알 수
없다. 따라서 원시 WAIT를 유한하고 이유가 있는 대기로 바꾸고, 진행과 대기의 실제 비용 차이를
정책에 직접 학습시킨다.

## 용어 계약

- **구조적 대기**: 처리 가능한 작업이 없거나 설비·하류가 막혀 엔진이 다음 외부사건까지
  시간을 진행하는 상태. 정책 행동으로 세지 않는다.
- **전략적 대기**: 안전한 진행 공동행동이 있는데 정책이 대기를 선택하는 상태.
- **회피 가능한 전원 대기**: `SERVE+WAIT` 또는 `WAIT+SERVE` 등 안전한 진행 후보가
  하나 이상 있는데 `WAIT+WAIT`을 선택한 경우.
- **진행 행동**: 실제 작업을 시작하거나 교착 통로를 확실히 여는 행동. 목적 없는
  PREPOSITION/REPOSITION은 진행으로 세지 않는다.

## 단일축 사다리

한 번에 여러 축을 바꾸지 않는다. 각 단계는 신규 시드에서 자기 효과가 확인될 때만 다음으로
간다.

1. **재현·기준 측정**: YR-145 실패 snapshot과 신규 교착 상태에서 세 공동행동의 실제
   짝지은 후속비용을 재고, 현재 PPO의 회피 가능 전원대기율을 동결한다.
2. **행동 의미 축 — 3군 분해 (★21차 감사 보정 2026-08-03)**: 원안의 "유효 trigger 가
   없으면 DEFER 후보를 만들지 않는다"는 **조건부 행동 마스크**라서, 결과가 좋아져도
   정책이 기다림을 배운 것인지 코드가 나쁜 후보를 없앤 것인지 구분되지 않는다. 분해:
   - **A**: 현재 무기한 WAIT (YR-145 B2 체크포인트 그대로 — 재학습 없음)
   - **B**: 후보 삭제 없이 **모든 WAIT 을 유한 DEFER 로 교체** — 만료(최대 지속시간)가
     항상 있어 wake 가 보장되는 대기. 관측 가능 trigger 가 있으면 min(trigger, 만료),
     없으면 만료만. (신규 학습)
   - **C**: **유효한 관측 가능 trigger 가 있을 때만 DEFER 발행**(없으면 대기 후보 부재).
     (신규 학습)
   - **B−A = 무기한→유한 교체 효과 / C−B = trigger 부재 시 후보 삭제 효과** 를 분리.
   - trigger 는 공개 정보만(provided_eta·release_time·공개 예약·진행 중 작업 완료
     예정) — **실현 미래시각 비누출**. trigger 종류·잔여시간·만료·버전 변경을 기록.
   - 보상·상태·PPO 구조 불변. YR-050 결정시각 엄격 증가 회귀 고정.
   - 2단계 전 고정(21차): ①짝 계측은 셀·에피소드 **층화**(셀별 할당·에피소드당 상한)
     ②진행 후보 **top-K(≥2) 실비용** 비교 ③완주·backlog 를 비용보다 **먼저** 비교
     ④trigger 기록 ⑤미래시각 비누출 ⑥WAIT 감소 → 위치조정 증가 이동 검사
     ⑦체크포인트 sha256·재실행 명령 박제.
### 2단계 구현 계약 (2026-08-03 동결 — 학습·계측 전)

- **DEFER_T_MAX = 600s** (평가창 21600s 의 1/36 — 유한성 보장 vs 과잉 재결정의 자릿수

- trigger 원천(공개 정보만): 외부트럭 provided_eta(정보수준 가시성 규칙 재사용)·내부작업
  release_time. 실현(actual) 미래시각 비열람.
- wake 통로: `engine.schedule_defer_wake`(opt-in — WAIT 계약에서 미호출 = 골든 불변),
  `_apply` 가 defer_until 있는 대기 실행 시 예약. 구조적 대기(resolver WAIT)·busy 경로
  불변. 창 밖·과거 시각 예약 무시(평가창 계약 정합).
- C 전략 제외: trigger 없는 DEFER 포함 조합은 공동 열거에서 제외하되, 그런 조합밖에
  실행가능이 없으면 전체 유지(구조 fallback 보존 — forbid_strategic_wait 동일 패턴).
- 상태·보상·PPO 불변: defer 필드는 인코딩·망 입력 금지(관측 불변 — 시간 의미만 변경).
- 학습: B·C × 3초기화(결속+one-shot 유지 — 유일 변경 = 대기 의미), A = YR-145 B2
  체크포인트 재사용. 계약 테스트 5(모드 불변·유한화·trigger 구분·재개방·범위) + 전체 골든.

### 2단계 감사 발견과 해소 (2026-08-03, 22~23차 — 3단계 선결)

1. **유한 DEFER의 재개방 증거는 유지**: wake 예약·소비가 작동했고 A의 미완주 6판은 B의
   같은 초기화에서 완주했다. 단 B:99000에 신규 미완주 4판이 생겨 완주 해결 주장은 금지한다.
2. **C≡B 원인 정정**: C의 무trigger 제외는 기존 `FORBID_WAIT=True`와 겹친다. ETA
   충분성 해석을 철회하고 **C는 중복 구현군으로 종료**하며 trigger를 바꿔 차이를 만들지 않는다.
3. **C 원자료 정정 완료**: 현재 코드 재실행으로 공동결정 분모 1633/1764/1502를 복구했고
   B와 요약·에피소드·짝 자료가 일치함을 확인했다(재학습 없음).
4. **반사실 라벨 계약 위반**: 총비용을 먼저 골랐고 backlog를 저장하지 않았다. B:99000
   32짝 중 7짝은 한쪽 이상 미완주라 기존 D_wait는 3단계 라벨로 재사용 금지한다.
5. **표본 범위 정정**: B:88000은 31짝(80.6%)·99000은 32짝(75.0%)이나 123000은
   1짝뿐이다. 두 초기화의 조건부 관찰로 한정하고 top-2 보장 주장도 금지한다.
6. **evidence 부분 보완**: B=C 체크포인트 hash는 manifest와 실제 파일이 전부 일치한다.
   단 모델은 untracked이고 manifest의 계측 명령이 placeholder라 실행 가능한 전체 명령·환경·
   원자료 hash는 3단계 실행 전에 보완한다. 로컬 B=C hash는
   88000 `CA1D601B55C4F9334251F124A919836E06D6D5DF05B4CDA42C73AC884C3C2C28`, 99000
   `3927D52562B49776C249BC8143C165298A4D2938483D7FF05D1844F74FE2ED35`, 123000
   `CBF69BE0CD8C112CCCA7ECD9F22FA168773F62157C45D09634435116DCD5114B`이며 이 값은 manifest에 박제됐다.

허용 결론은 “유한 DEFER가 무기한 대기의 재개방 문제를 고쳤지만 정책의 진행/연기 선택
오류는 남았다”까지다. 개발셋 평균비용 2/3 개선은 신규 시드·신뢰구간 판정 전 성능 주장이
아니다.

3. **순위 신호 단일축(22차 정정본)**: C를 제외하고 B(유한 DEFER)와 R(B+반사실
   순위손실)을 같은 신규 학습 대역·학습예산·초기화·체크포인트 선택규칙으로 각각 재학습해
   비교한다. A와 SF-SPT는 참고군이다.

   - 라벨 순서는 공동행동별 `(미완 비율, backlog, 에피소드 종료까지 v2 비용)`의
     **사전식 최소화**다. 앞 항이 다르면 뒤 비용으로 뒤집지 않는다.
   - 가능한 안전 진행 공동후보를 전부 평가한다. 계산상 K개만 가능하면 PPO 점수 top-K를
     금지하고, 결과 열람 전 고정한 `SF-SPT 후보 + 행동유형 층화 + 무작위 후보`로 뽑는다.
   - 같은 상태·같은 사건 난수·같은 후속정책으로 에피소드 종료까지 진행한다. 반사실 미래는
     학습 라벨 생성에만 쓰고 정책 관측에는 넣지 않는다.
   - 거의 동점인 상태는 보조손실을 주지 않는다. 동점폭·손실계수·표본수·허용 상한·체크포인트
     선택기준은 결과 열람 전에 동결하고 B/R에 동일 적용한다.
   - 1차 판정은 독립 시드·에피소드 단위 신뢰구간의 R−B v2 비용이다. 완주 100%·backlog 0·
     종단 정지 0을 하드 가드로 두고, 잘못된 연기 감소·유효한 연기 보존·위치조정 장악 미이동을
     함께 본다. 자연분포와 교착 스트레스는 분리 판정한다.

### 3단계 실행 전 계약 (2026-08-03, 23차 검토 — 결과 미열람)

- **완료된 보정**: C 원자료와 B=C hash를 확인했고, `lex_label`은 미완 비율→backlog→v2
  비용의 사전식 순서를 구현했다. 후보는 PPO 점수 대신 계획시간·행동유형·무작위 잔여로
  최대 4개를 뽑는다. 단 새 helper의 전용 계약 테스트와 R 학습 배선은 아직 없다.
- **비용 동점폭** `epsilon_cost=0.1`은 v2 비용 단위의 assumed 파일럿 값으로만 유지한다.
  신경망 점수는 비용 단위가 아니므로 같은 0.1 margin을 쓰지 않고, margin 없는 pairwise
  logistic 순위손실을 쓴다. `lambda_rank=0.1`은 상태별 평균→미니배치 평균 뒤 적용하고
  PPO/순위 손실과 gradient 크기를 함께 기록한다(동일 실험 안 튜닝 금지).
- **단일축·난수 계약**: B와 R의 유일한 차이는 보조손실이다. 라벨 후보 난수는
  `(학습초기화, 반복, 에피소드, 결정)`에서 만든 별도 스트림으로 PPO 행동·셔플 난수를
  소비하지 않는다. 같은 상태 재현, 사전식 순서, PPO 점수 비의존을 테스트로 고정한다.
- **노출·후보 가드**: 초기화·셀별 라벨 상태 수, 진행/연기/동점 수, 실제 순위 갱신 수와
  K=4의 전수최선 포함률을 dev에서 기록한다. 최소 노출량은 학습 전에 동결하며 미달은
  `효과 없음`이 아니라 `조작 노출 부족`이다. 주장은 “표본화 후보 중 최선”으로 제한한다.
- **비교군**: B와 R을 같은 신규 대역·예산·초기화·체크포인트 규칙으로 재학습한다.
  A·SF-SPT는 참고군이며 C는 종료한다.
- **판정 보정**: 현재 12 시나리오×3초기화의 36행을 독립 표본처럼 쓰지 않는다. dev 분산으로
  MDE(이 표본으로 검출 가능한 최소 차이)를 먼저 계산해 필요하면 잠금 시드를 늘린다. 각
  시나리오의 3초기화 평균을 독립 단위로 삼아 셀 층화 CI를 만들고, 초기화별 평균도 공개한다.
  통과는 `초기화 개선방향 ≥2/3 ∧ 전체 평균 R−B<0 ∧ CI 상한<0 ∧ B/R 하드가드`다.
- **하드가드·진단**: 양 군 완주 100%·backlog 0·종단 정지 0·물리위반 0·위치조정 장악 0.
  진행이 싼데 연기한 비율과 연기가 싼데 진행한 비율을 같은 고정 상태셋에서 함께 잰다.
  알려진 정지 3판은 dev 회귀검사일 뿐 일반화 증거로 쓰지 않는다.

4. **희귀상태 노출 단일축(3단계 미달 시)**: 동시 SERVE 불가·한 대 SERVE 가능·미래

   학습에서 완전히 분리한다.

## 1단계 측정 이력

개발셋 기준 공동결정 중 진행 가능 전원대기는 초기화별 17.35%·7.50%·2.71%였고, 진행과
연기의 실제 우열은 상태마다 달랐다. 이는 성능 판정이 아니라 “일괄 금지 대신 구분 학습이
필요하다”는 진단이다. 프로토콜·검열 한계·전체 표는 [결정이력 §6-b·§8~10](../strategy-history/2026-08-03-YR-146-WAIT-WAIT-정책최적화-우선-사용자결정.md)에 보존한다.

## 연구 판정 — 하드 마스크 없음

- 학습·평가 모두 `WAIT+WAIT` 하드 마스크와 강제 progress fallback을 끈다.
- 자연분포와 교착 스트레스셋을 분리 판정한다.
- 1차: 회피 가능한 전원대기율과 progress-vs-wait 순위 정확도. “0건” 목표의 표본수·허용
  상한은 파일럿 뒤 결과 열람 전 동결한다.
- 공동지표: v2 실현 지연비용, 평균 A→O, 본선 초과시간.
- hard guard: 완주 100%, backlog 0, 물리·안전위반 0, 종단 정지 0.
- 정상 대기 보존: 실제 짝지은 비용상 대기가 유리한 상태에서의 선택 정확도를 별도 보고한다.
- WAIT 감소가 PREPOSITION/REPOSITION 장악으로 이동하는지 반드시 함께 검사한다.

## 범위 밖

정책 성능 검증 전에 `WAIT+WAIT` 금지, resolver 강제 대체, 엔진 강제 탈출을 성능 arm에
넣지 않는다. PPO는 확률 정책이므로 운영상 0건 보장은 별도 YR-146이 담당하며, 그 결과를
YR-147의 학습 성과로 합산하지 않는다. 이는 YR-052/119의 자유 WAIT 재개가 아니라,
사유·만료·재검토시각을 가진 새 DEFER 행동의 최초 검증이다.
