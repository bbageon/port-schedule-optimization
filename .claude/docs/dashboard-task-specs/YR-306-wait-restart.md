## 이번에 고정하는 조건

1. 기존 22일차 실패를 이어 붙이지 않는다. 수정본의 깨끗한 별도 작업 폴더에서 처음부터 실행한다.
2. 이전 실패·정책·원자료는 보존하고 새 결과 폴더를 쓴다. 단기 검사 정책도 가져오지 않는다.
3. 시드 9900306, 30일 명단은 `outputs/reports/yr306_seed_regeneration/seed-9900306/seed-data.json.gz`다.
   SHA256 `efdb45e2ec8feafed6987cf48dfe022ca2959dad8c4f1d56bee680456081af7a`를 실행기가 검사한다.
   트럭 177,500건·본선 작업 묶음 288개로, 주문·상자 번호와 시간은 다시 만들지 않는다.
4. 준비 1일 + 학습 28일 + 정리 1일, 추가 정리 2시간. 정책·보상·통지창·본선 마감을 바꾸지 않는다.
5. 공유 블록 PPO 기본값과 전일 추첨 행동을 유지한다. 실제 60초 비용 증가분으로 학습하며 반사실 세계는 0개다.
6. 바뀐 축은 유효한 반입의 등록뿐이다. 공간 부족이면 주문은 남고 실제 적치가 대기하며 기존 비용이 누적된다.
   실제 적치 한도·작업 안전·번호/출처/시간 검증은 유지한다. 공간 재배정 실패와 외부 주문 삭제를 혼동하지 않는다.
7. 사용자가 알고 있는 다른 세션의 v4 10-worker 실행은 변경하지 않는다. 이번 재실행은 CPU 23 하나,
   계산 스레드 1개로 제한한다. 장비는 논리 CPU 24개, 시작 전 가용 메모리 약 49 GB다.
   이는 v5의 기존 1개 제한을 유지하는 재실행이며, 10코어 초과 확장을 하지 않는다.
