# YR-322 — 본선 ETA(입항 예정)·ETB(접안 예정)를 무대에 넣을까

## 무엇을 묻는 작업인가

공식 본선 작업 스키마는 다섯 칸이다:

    ETA 입항 예정 → ETB 접안 예정 → ETW 작업 시작 예정 → ETC 작업 완료 예정 → ETD 출항 예정

v4 에는 **ETW·ETC·ETD 만** 있다 (`VesselPlan.planned_start_s` · `planned_completion_s` ·
`etd_s`). ETA·ETB 를 넣을지 결정한다.

## 왜 지금 없나 — 설계 결정이다

정박 대기와 접이안은 **야드 정책이 어찌할 수 없는 구간**이라 "구조적 유휴" 로 묶어
Φ 에서 뺐다 (`c_vessel_structural` — 진단 열로만 남긴다). 크레인이 아무리 잘해도
배가 언제 붙는지는 안 바뀌므로, 그 비용을 정책 성적에 넣으면 **정책과 무관한 잡음**이
성적을 흔든다.

## 넣는다면 먼저 답해야 할 것

1. **야드가 늦어 접안이 밀리는 경로가 실제로 있나?** 앞 배의 작업이 안 끝나면 다음 배가
   못 붙는다 — 그 사슬이 우리 무대에 있는지 확인해야 한다. 있다면 ETB 는 정책의 결과이지
   외생이 아니다.
2. **없다면 진단 열로만 둘 것인가?** 정책이 못 바꾸는 값을 Φ 에 넣을 이유가 없다.

## ⚠️ 넣으면 기존 판정과 비교가 끊긴다

Φ 의 정의가 바뀌므로 [[YR-316]] 판정 수치와 **나란히 놓을 수 없다**. [[YR-307]]
(본선 단가 2.99 → 35.88)과 같은 성격의 변경이다 — 그때도 v3 와 비교 불가를 명시했다.

## 예산

조사(위 ①) 반나절 · 넣기로 하면 무대 수정 + 3대 게이트 재통과 + 재판정.
