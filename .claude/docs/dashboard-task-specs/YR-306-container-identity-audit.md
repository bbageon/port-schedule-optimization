# YR-306 — 오더와 실제 컨테이너 연결 점검

- **상태**: in-progress
- 상위: [연속학습 검증](YR-306-v5-first-continuous-training.md).
- 사용자 요청(2026-09-12): v3 스키마 재사용 여부 검토, 필요한 수정·검증, 가능하면 재학습.
- 단일 보정축: 신뢰성 — 오더 번호와 실제 작업 대상의 일치. 성능·현실성 통과를 주장하지 않는다.

## 확인된 출발점

- v3와 v5의 `schema/order.py`는 동일하다. 6개 필드 중 `con_no`가 이미 있다.
- `orders_from_schedule`은 번호가 없으면 `CN{doc_key}`를 만들지만 반출 엔진은 `target`을 쓴다.
- 반입 엔진은 `IN_{job_id}`를 만든다. 공개 오더의 번호와 연결을 검사하지 않았다.
- 30일 입력은 하루 명단의 반출 대상을 재사용하고, 런타임 대체 선택으로 부족을 우회했다.
- 기존 첫 실패는 10일째 10:37, Y16. 29개 모두 미완료 반출에 예약, 완료 작업 점유는 0개.
- 같은 첫 실패를 재현했으며 학습 갱신 202회·일별 모델 9개가 원래 실행과 일치했다.

## 이번 수정·검증 계약

1. v3·v4 및 v5의 고정 물리 엔진 사본은 수정하지 않는다.
2. v5 오더 6필드는 유지한다. 합성 오더 번호를 실제 엔진의 고정 대상 번호와 연결한다.
3. 명시된 오더 번호와 실행 대상이 다르면 덮어쓰거나 다른 상자로 대체하지 않고 거부한다.
4. 같은 컨테이너의 중복 출고, 초기 재고·유입과 연결되지 않은 출고, 본선 대상 미지정을 검사한다.
5. 검사는 학습 전 원자료로 저장한다. 실패 입력은 실행하지 않고 이유·예시·수를 남긴다.
6. 테스트는 번호 일치, 날짜 경계, 재배치 시 번호 보존, 대체 금지, 검사 실패 시 갱신 0회를 포함한다.
7. 기존 실행기·보상·물리 장치 검증은 구분해서 유지한다. 시험용 우회는 유효한 학습 입력 증거가 아니다.
8. 원본 30일 입력을 무수정으로 검사한다. 이름만 바꿔 중복을 감추거나 없는 상자를 생성하지 않는다.
9. 본선·트럭의 고정 운송 연결이 확보되고 검사와 짧은 실행이 통과한 경우에만 새 폴더에서 학습한다.
10. 원래 입력이 이 조건을 충족하지 못하면 장기 학습을 보류하고 부족한 입력 계약을 명시한다.

## 자원·범위

- 최대 10코어. 다른 v4 학습이 10개 작업자로 실행 중이므로 이 점검은 1코어에서 수행한다.
- 기존 결과는 보존한다. 정책·비용·학습률·본선 마감·통지창은 변경하지 않는다.
- 컨테이너 운송 연결을 새로 합성하는 것은 원래 30일 명단의 단순 재실행과 구분한다.
- 본선 전체 계획을 하나의 트럭 `Order`로 바꾸지 않는다. 본선 작업은 기존 별도 명세로 감사한다.
- 결과·코드·문서 정합과 원격 반영을 확인한 뒤 검증 범위와 남은 한계를 보고한다.
