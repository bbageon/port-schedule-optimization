# YR-171 — 시간 판매를 **당일 30분 슬롯 최적화**로 교체 (YR-161 대체)

- **Epic**: Exp / **Priority**: 🔴 / **등록일**: 2026-08-13 / **상태**: ready
- **3대 게이트 보정 대상**: `scenario_validity` 하나 — 정보 계약이 바뀌므로 **재자격 필수**
- **1줄**: 고정 +15분 이연을 **오늘 48개 30분 슬롯 중 최저비용 슬롯 선택**으로 바꾼다.

## 왜 — 실측으로 급소가 특정됐다 (2026-08-13)

축 분리 진단(`yr170_axis_probe`, SF 집행·시드 8,400,000·판정 아님):

| 조건 | Φ | 기준선 대비 | 판매 1건당 |
|---|---|---|---|
| 전건 KEEP | 2,346.2 | — | — |
| 반입 지명(공간 위주) | **2,273.3** | **−72.9 (−3.11%)** | **−2.29분(이득)** |
| **반출 지명(시간축만)** | 2,784.5 | **+438.3 (+18.68%)** | **+14.28분(손해)** |
| 둘 다 | 2,784.0 | +437.8 (+18.66%) | +7.29분 |

**공간 판매는 이득이고 손해는 전부 시간 판매에서 나온다.** 학습 전 정책이
기준선보다 21% 나빴던 것의 정체가 갈렸다.

### 왜 구조적으로 손해인가

비용 계약상 **기사의 터미널 밖 대기가 안 대기와 같은 단가**로 계상된다
(`yr151_transfer_ppo.py:196`). 따라서 +15분 이연의 손익은

```
순이득 = (터미널 안 대기 절약분) − 15분
```

**절약분이 15분을 넘을 때만 이득**이고, 그건 혼잡 첨두를 정확히 비껴갈 때만
생긴다. 그런데 **고정 +15분은 고를 수가 없다** — 15분 뒤가 더 붐비면 그냥 손해다.
실측 +14.28분/건은 이 구조가 그대로 나타난 값이다.

## 설계 (42차 피드백 · 실행 전 동결 필요)

30분은 "보는 범위"가 아니라 **"예약 슬롯 크기"**로 쓴다.

| 구분 | 현재 | 변경 |
|---|---|---|
| 미래 가시 범위 | 30분 | **같은 작업일 전체** |
| 선택 가능 시간 | 무조건 +15분 | **오늘의 30분 단위 슬롯(48개)** |
| 날짜 변경 | 해당 없음 | **금지** |
| 임박 구간 | 없음 | **잠금**(변경 마감) |

- 블록마다 **오늘 슬롯별 예상 부담표**를 만든다(예약 트럭 수·공개 ETA·크레인 처리
  가능량·본선 작업계획·밀린 작업·이미 옮겨진 수).
- 슬롯 총비용 = 예상 터미널 체류비 + 본선 영향 + **기사 일정 변경 부담** + 예측 불확실성.
- **한 슬롯에 몰리는 것을 막는다** — 1건 배정마다 그 슬롯 잔여 용량을 줄이고 다음 건을
  다시 계산(문헌의 블록×시간슬롯 용량 제한 방식).
- 크레인 집행 정책에는 3,600건을 직접 보이지 않는다 — **시간대별 예상 혼잡 곡선**처럼
  압축된 정보만 판매 정책(TransferHead)에 준다.

근거: 부산항 체인포털 VBS 가 적용시간 00~24시·슬롯 30분/1시간·예약 변경 가능시간과
마감시간 분리 구조를 쓴다. 하루 단위 가시성·슬롯 용량·임박 잠금은 실제 구조와 정합.

## 반드시 붙일 단서

- **예약 최적화 ≠ 재예약**: 최초 예약 전 추천은 최적화, 확정된 시간 변경은 재예약이며
  **기사 동의가 필요**하다. 현 시뮬레이션은 **전원 수락**을 가정하므로 결과는 실제 운영
  성과가 아니라 **"모두 수락할 때의 최대 가능 효과"**로만 읽는다.
- 이 변경은 **정보 계약을 바꾼다**(30분 전 공개 → 하루 명단 공개) → YR-167 자격이
  무효가 되므로 **재자격이 선행**이다. 상수 하나 교체가 아니다.

## 진단의 한계 (정직 고지)

- SF 집행 기준이다. 채택 PPO 집행 헤드에서는 비용 곡선이 다를 수 있다.
- **시드 1개**다. 방향은 크지만(+18.7% vs −3.1%) 크기는 재확인이 필요하다.

  줄 수 있어 축 분리가 완전하지 않다. **"시간축만"(n_space=0)은 깨끗하다.**
