## 부수 확인 — `h`(문단 바로 뒤)가 왜 안 먹었나

**본문이 쪽을 끝까지 채우기 때문**이다. 본문 영역 바닥이 y=665 인데 9·10쪽 마지막
글줄이 **y=666.4** 다. 빈 자리가 없으니 `h` 가 실패한다. 폭 0.55 까지 줄여도,
`flafter` 를 꺼도 동일했다 (`figflow.py`·`figfit.py`).

## 3. 그림 2도 높이 축소 (4.80×2.86 → 4.80×**2.15** in)

사용자 물음: *"본문 내용을 조금 줄이면 가능하지않아?"*
→ **줄일 필요가 없었다.** 그림 2 높이만 낮추면 됐다.

그림 3만 줄였을 때는 10쪽이 **그림만 있는 쪽**이 됐다 — 두 그림이 위·아래 띠를
다 먹어 본문이 한 줄도 못 들어간 것이다. 그림 2를 25% 낮추자 둘이 갈라졌다.

| | 그림 3만 줄였을 때 | 그림 2도 줄인 뒤 |
|---|---|---|
| 그림 2 | 10쪽 y=333 (위 띠) | **9쪽 y=592** (본문 아래) |
| 그림 3 | 10쪽 y=609 (아래 띠) | **10쪽 y=610** (본문 아래) |
| 본문 없는 쪽 | 10, 12 | **12만** |
| 결론 / 사사 | 11쪽 y=185 / y=509 | 11쪽 y=161 / y=485 |

**★그림 2는 자기 인용과 같은 쪽(9쪽)에 있고, 바로 위 줄이
`...general property of spatial reallocation.` 로 문장이 끝난다** — 요청대로
"관련 문단이 끝난 뒤"에 놓였다.

## 확인한 것 둘 (실측)

1. **`\floatpagefraction` 은 원인이 아니었다** — 0.75 → 0.95 → 0.99 로 올려도
   배치가 그대로였다. 10쪽은 float page 가 아니라 두 그림이 위·아래 띠를 다 먹은
   상태였다.
2. **본문을 줄여도 그림 3은 안 움직인다** — §5.3 을 1·2·3단계로 줄여 빌드했지만
   그림 3이 같은 자리(10쪽 y=601~610, 문장 중간)에 앉는다. §5.3 이 이제 **한 문단**
   이라 그 안에 문단 경계가 없고, 쪽 나눔이 마침 문장 끝에 떨어져야 하는데 그건
   글자 수로 맞히는 일이다. → 내용을 깎아 봐야 얻는 게 없어 본문은 그대로 뒀다.
