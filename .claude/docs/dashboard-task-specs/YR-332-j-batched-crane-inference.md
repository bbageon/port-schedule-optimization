# YR-332-j — 크레인 정책 일괄 추론과 공통 정보 재사용

- **상태**: in-progress
- 상위: [[YR-332]]. 파생: [[YR-332-h]], 2026-11-05.
- 2026-11-05 사용자 직접 요청: 상태별 목록 관리·작업 계획 재사용까지 구현하고 결과 평가.
- 계산 경로 최적화 한 축이다. 입력 의미·보상·기본 후보 상한·작업 우선규칙은 유지한다.

## 무엇과 왜

오더별 점수를 같은 신경망으로 한 번에 계산하고, 같은 상태의 대기열 수는 한 번만 센다.
진단에서 1,000개 후보 선택은 개별 호출 263.282ms, 일괄 시제품 52.121ms였다.
운영 정책에 적용하려면 점수·강제 선택·안전 제약의 동작이 보존되는지 더 넓게 확인해야 한다.

## 범위와 완료 기준

1. 전역 함수 교체 없는 운영용 구현으로 후보 입력을 묶는다. 추가 오더를 기다리지 않는다.
2. 한 결정 안에서만 공통 정보를 재사용하고 상태 변경 시 갱신한다.
3. 후보를 메모리에 맞게 나누더라도 누락 없이 전부 평가할 수 있게 한다.
4. 여러 모델·혼합 작업·복수 크레인·동점 근처·강제 선택에서 기존 계약과 대조한다.
5. 실제 후보 생성부터 안전 검사까지 측정하고, 동시 요청·연동 시간의 별도 예산을 명시한다.
6. 삽입·상태 변경·취소·삭제·블록 이동·복제/저장 복원 시 오더 상태 목록이 일치해야 한다.
7. 작업 계획은 야드·크레인·예약·작업 속성이 같을 때만 재사용한다. 시각은 매번 갱신한다.
8. 생성 중의 슬롯 탐색도 재사용하되 실제 공동 배정·실행 검사는 기존 경로로 다시 수행한다.

## 사전 고정 평가

- 진단 seed 9,903,321. CPU 1스레드, 12/100/1,000 오더, 각 조건 20회.
- 기존 개별 / 일괄+공통 정보 / 상태 목록 추가 / 계획·슬롯 재사용 추가를 같은 후보 수로 비교.
- 차가운 캐시, 동일 상태 반복, 신규 도착, 취소, 크레인 이동, 야드 변경, 예약 변경을 구분한다.
- 원시 시간·후보 수·계획 계산/재사용 횟수·최종 선택을 저장한다. 같은 후보·계획·선택을 대조한다.
- 혼합 작업·복수 크레인·사전 준비·강제 선택·작은 연속 실행의 작업/비용 장부도 검사한다.
- 전체 터미널 동시 처리·현장 통신·학습 성능 향상은 이번 결과로 주장하지 않는다.

## 착수 근거

과거 게이트 authorize-next는 `저장된 scenario PASS 재계산 실패`로 허용되지 않았다.
그 PASS를 승계하지 않고, 이후 사용자의 명시적 구현·평가 요청에 따라 계산 최적화와
동등성·지연 진단만 수행한다. 새 연구 가설·보상 변경·재학습으로 확장하지 않는다.

최초 변경에서는 입력·보상·후보 상한·우선규칙을 함께 바꾸지 않는다.
향후 가변 길이 목록을 읽는 정책의 속도는 그 구현에서 다시 측정한다.
