# YR-316 — 하루 무대의 반입 배정을 용량 인식으로 + 크레인 재판정

## 무엇을 하는 작업인가

하루 무대(`build_stage`)가 반입 트럭을 블록에 배정할 때 **그 블록에 자리가 있는지 보게**
고친다. 그 뒤 크레인 판정([[YR-314]])을 **새 대역**에서 다시 한다.

## 왜 지금 하나 — [[YR-314]] 가 이것 때문에 실격됐다

28일 중 13일에서 안내자가 반입 트럭을 **`용량 부족`** 으로 거절했다(합계 1,945대 · 1.18% ·
최대 하루 5.3%). 스케줄은 멀쩡한데 생성기가 용량을 안 보고 배정해서,
장치율 0.65 인 하루 무대에서 몰린 블록이 넘친다. 판정 가드(전건 투입)에 걸려 **판정 미성립**.

이건 정책 문제가 아니라 **무대 문제**다 — 모든 팔이 같은 날 같은 정도로 미달했다.

## 어떻게 (단일축 — 무대만 건드린다)

`terminal_stream.py` 의 반입 블록 배정에서, 블록별 **예상 잔여 용량**(초기 채움 + 그날 반입
− 그날 반출 예정)을 넘기면 다른 블록으로 돌린다. 반출·본선·도착 시각은 안 건드린다.

⚠️ **무대 3대 게이트**를 다시 통과해야 한다(`scripts/v4/gate_stage_check.py`): 신뢰성 ·
현실성 · 성능. 특히 *"트럭이 블록에 고르게 가는가"* 가 바뀌므로 현실성 항목을 본다.

⚠️ 처음엔 망을 그대로 두려 했으나(수정이 트럭 1% 안팎이라 봄), 실측 이동이 5% 라
**재학습한다**(사용자 지시). 아래 재학습 사전등록 참조.

## ★수정 결과 (2026-09-15)

`stage/vessels.py::build_diurnal_v3` 의 트럭 배정 루프에 **블록별 반입 상한**을 넣었다:

    cap[b] = 물리 − 초기 적재 − 배경 양하 − CAPACITY_MARGIN(2)

엔진의 거절 조건(`free_slots <= margin`, `free = 물리 − 적재 − 계획된 반입·양하 − 예약`)을
그대로 뒤집은 식이다. 반출·적하가 자리를 되돌려주는 것은 **안 센다(보수적)** — 그래서 하루
반입이 상한 안이면 어느 순간에도 거절이 안 난다. 넘친 반입은 **여유가 가장 큰 블록**으로
(같으면 배치 순서 — 결정론). 난수 소비는 그대로라 **넘치지 않는 날은 바이트 동일**하다.

### 얼마나 돌리나 — ⚠️ 거절됐던 것보다 4배 많이

| | 돌린 트럭 | |
|---|---|---|
| 판정 28일 | **8,356 / 164,500 (5.08%)** · 돌린 날 21/28 | 실제 거절은 1,945 (1.18%) · 13일이었다 |
| 진단 평가일 3,500 | 0 | 바이트 동일 |
| 진단 평가일 7,500 | 245 | (거절은 1대였다) |
| 진단 평가일 15,000 | 1,644 | (거절은 563대였다) |

상한이 보수적이라(반출이 비워 주는 자리를 안 셈) **실제로 넘쳤을 트럭보다 4배쯤 더**
돌린다. 대신 어떤 팔·어떤 날에도 거절이 0 이고, 모든 팔이 **같은 명단·같은 블록**을
받는다(짝비교의 전제). 정확히 넘칠 트럭만 돌리려면 반출 완료 시각을 무대 생성 때 알아야
하는데 그건 정책에 따라 달라서(붐비면 몇 시간 뒤) 불가능하다 — 투입 시점에 엔진 상태로
돌리는 대안은 정확하지만 **팔마다 다른 블록**을 주게 되어 짝비교를 흐린다. 보수적 상한을
택하고 그 크기를 여기 남긴다.

## ★재학습 사전등록 (사용자 지시 2026-09-15 "무대를 수정하고 학습을 진행")

### 읽는 법 — 결론은 바뀌지 않았다

한가한 날은 이기고(3,500 에서 −4.6% 로 더 커짐) **붐비는 날은 진다**(12,500 · 15,000 에서
+7.8% · +10.5%). 새 망이 붐비는 날에 옛 망보다 나쁜 것은 (a) 학습 실행 간 편차(체크포인트 하나의
값이 ±4% 로 흔들린다) (b) 새 무대가 붐비는 날의 블록 부하를 고르게 만들어 크레인이 보는 상황이
달라진 것 — 둘 중 어느 쪽인지 진단 날 4개로는 못 가른다. **28일 판정이 그 답을 준다.**
