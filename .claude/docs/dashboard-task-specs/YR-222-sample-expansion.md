# YR-222 · 표본을 늘려 오차를 신호 밑으로 — 그리고 진짜 오차부터 잰다

> Epic RL · 상태 🟢 **진행 중** (등록·착수 2026-08-24) · 사용자 결정 2026-08-24
> 선행 [[YR-220]] · [[YR-221]] · 이 row 가 [[YR-218]] 계열 실패의 **세 번째 축**이다

## 1. 왜 이 축인가

[[YR-221]] 측정이 A(직접·간접 분리)를 탈락시키면서 **남은 원인**을 가리켰다.

```
YR-218   오차 4,400,000원  vs  라벨 차이 100,000원   →  44배 초과    ❌
YR-220   오차    27,500원  vs  라벨 차이  50,824원   →  0.54배      ⚠️ 겨우
A        오차    27,500원  vs  라벨 차이  20,341원   →  1.35배 초과  ❌
```

문제가 *"신호가 오차보다 작다"* 라면 길은 둘뿐이다 — **신호를 키우거나 오차를 줄이거나.**
신호는 이미 다 담고 있으므로(그래서 하류 375건이 섞인다) **오차를 줄이는 쪽**이다.

## 2. ★그 전에 — 지금 보는 오차는 **학습 손실**이다

이걸 먼저 바로잡아야 한다. `0.275 눈금(27,500원)` 은 **망이 이미 본 표본**의 오차다.

| | |
|---|---|
| 망 파라미터 | 5,761 (Seller) · 5,505 (Buyer) |
| 회차당 학습 표본 | **판매 70행** (라벨 35건 × 2) |

**파라미터가 표본의 80배**다. 이 상태에서 학습 손실이 작은 것은 당연하고,
**처음 보는 상황에서의 오차는 훨씬 클 수 있다.** argmin 이 실전에서 마주하는 것은
처음 보는 상황이므로, 판단 근거는 **검증 손실**이어야 한다.

지금까지 모든 판정을 학습 손실로 했다 — [[YR-220]] 관문 통과도 마찬가지다.
**그 판정은 다시 봐야 한다.**

### 구현

`v3/train/loop.py` — 회차마다 라벨의 20% 를 떼어 학습에 안 쓰고 오차만 잰다.
**결정 단위로** 자른다: 같은 결정의 두 행(사실·대안)은 중심화라 부호만 반대여서
행 단위로 자르면 검증 답을 학습에서 본 셈이 된다.

## 3. 사전등록 (착수 전 동결)

```
회차          16
라벨/회차     200          (YR-220 의 40 에서 5배)
검증 비율     20%          (회차당 40건은 학습에 안 쓴다)
시간 예산     14시간
학습 부하     3,500 · 5,000 교대
시드          9,900,6xx    (YR-218·220 과 동일 — 짝비교 유지)
탐색 ε        0.50 → 0.05
작업자        16 프로세스
```

**회차를 24 → 16 으로 줄인다.** 라벨이 5배라 회차당 시간이 그만큼 늘기 때문이고,
시간 예산 14시간 안에 넣으려는 것이다. 회차 수 감소가 결과에 미치는 영향은
**판정 때 명시**한다(YR-218·220 은 24회차였다).

### 판정 기준

| | 기준 |
|---|---|
| **① 진짜 오차** | **검증 손실**이 라벨 차이의 **절반 미만** (오차 < 신호/2) |
| ② 과적합 진단 | 검증 손실 ÷ 학습 손실 — 표본 5배로 이 비율이 **줄어드는가** |
| ③ 개선 방향 | 마지막 4회차 평균 격차 < 첫 4회차 평균 |
| ④ 중단 없음 | 표본 0 회차가 없다 |

①이 이 축의 핵심이다. ②는 "표본을 늘린 게 효과가 있었나"를 직접 잰다.

## 4. ⚠️ 예상되는 결과와 그 뜻

| 관측 | 뜻 | 다음 |
|---|---|---|
| 검증 손실 ≪ 학습 손실의 몇 배 · 개선 | 과적합이 원인이었다 | 표본을 더 늘린다 |
| 검증 손실이 크고 안 줄어듦 | **특징이 상황을 설명 못 한다** | 정보 축([[YR-198]] 크레인 예상 서비스 시각) |
| 검증은 좋은데 성능은 여전히 나쁨 | 라벨은 맞는데 **라벨이 가리키는 목표가 틀렸다** | 목표 재정의 |

- 회차 수·ε·H·부하를 **결과 보고 조정하지 않는다.**
- 실패해도 [[YR-218]]·[[YR-220]] 기록을 지우지 않는다.
