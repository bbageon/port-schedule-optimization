생겼는지 디버깅할 수 없다(사용자 지시 2026-07-26). 효과가 실증되면 한 축씩 더한다.

## ★죽은 칸을 하나 잡았다

처음엔 `backlog_h = available_at − clock`(이미 잡힌 일감)을 넣었다. **구조적으로 항상 0**
이었다 — 결정은 크레인이 **놀 때만** 일어나므로 `available_at ≤ clock` 이 항상 참이다
(실측 10,651회 호출 중 예외 0회).

`test_features_are_not_all_dead` 가 잡았다. **후보 수**(중앙 3 · 최대 18)로 바꿨다 —
고를 게 많다 = 밀린 일이 많다 는 뜻이라 혼잡의 대리지표다.
[[YR-235]] 가 재배치층에서 같은 이유로 6→3 칸으로 줄인 선례가 있다.

## ⚠️ 실작업 우선 울타리를 남겼다

`serve_first=True` 가 기본이다. 초기 망은 무작위라 `rank` 가 잡음인데, 울타리가 없으면
**일은 안 하고 자리이동만 고르는** 퇴화로 무너진다([[YR-039]] — 결정의 54~81%가
REPOSITION 이었다). 망은 **실작업 안에서 순서만** 정한다.

이 울타리를 걷는 것은 **효과가 실증된 뒤**에 별도 축으로 한다.
