# YR-331-e — 원화 없는 운영 지표 정규화·학습

- **상태**: done
- 사용자 지시: “정규화를 어떻게 적용할지 기존 연구를 검토하고 적용해서 학습까지 진행해봐”.
- 무엇: 트럭 체류초·본선 중단초·빈 이동초·재취급 횟수를 직접 정규화해 PPO(경험으로 행동 확률을 갱신하는 학습)의 보상으로 쓴다.
- 왜: 앞선 d는 원화 합계의 눈금만 바꿨다. 이번 요청은 단가 환산 자체를 보상에서 제거하는 것이다.
- 범위: 보상 목적 한 축. 물리·입력·행동 후보·신경망·갱신 설정은 유지하고 부하 보조 항은 끈다.
- 연구 상태: d의 정합 통과·성능 미확정·현실성 미통과를 승계한다. 새 사용자 지시에 따른 진단 학습이며 확증·실제 항만 성능 주장을 하지 않는다.

## 실행 전 계약

1. 기존 네 비용 항의 원료만 사용한다. 트럭은 진입부터 출차/현재까지 누적 체류초, 본선은 기존 선박별 중단초의 합(GT 가중 제거), 빈 이동초와 재취급 횟수는 기존 누적 계수기를 읽는다.
2. 각 지표 x마다 기준 운전에서 `z_t=0.999^(dt/60)*z_prev+Δx_t`, `s_x=std(z)`를 구한다. 보상은 `−Σ(0.25×Δx/s_x)`다. 원화 단가·원화 분모·추가 전체 보상 정규화·평균 제거·절단은 없다.
3. 0.25씩 동일 비중은 초기 설계 가정이다. 정규화가 객관적인 중요도를 정해 준다고 주장하지 않는다. 시간 단위를 바꿔도 해당 기준을 함께 바꾸면 보상이 같아야 한다.
4. 기준 입력은 기존 9911000, 3500/5000/7500건의 고정 파일 그대로. KEEP+SF-SPT 규칙·가중치 갱신 0회, 60초 경계, 첫날 연결 후 `86400<t≤259200`의 2880개 값으로 기준을 고정한다.
5. 학습·평가 자료로 기준을 재추정하지 않는다. 비유한 수·음의 증가량·기준 분산 0은 중단하며 임의값으로 대체하지 않는다.
6. 학습은 초기화 시드 202609281/202609282/202609283의 세 쌍. 이미 보존된 9931000/9941000/9951000 고정 입력의 앞 3일(3500/5000/7500), 첫날 연결·둘째 날 학습·셋째 날 고정 관측, 각 모델 24회 갱신. 원본은 5일 계획 전체로 검증·복원하고 실행은 259200초에 중단한다. 학습창은 `[86400,172800)`으로 명시하며 원본 입력은 수정하지 않는다.
7. 각 쌍은 새 운영 보상과 d의 원화 보상(37,620,956.31299437원 눈금)을 같은 초기 가중치·입력·행동 난수로 학습한다. 서로 다른 보상 체계를 섞어 재개하지 않는다.
8. 각 최종 모델을 별도 고정 입력 9961000/9971000/9981000의 앞 3일에서 동결 평가한다. 동일 행동 추첨을 유지하고 학습 갱신은 0이다. 동일 입력의 KEEP+SF-SPT 규칙도 평가한다. 시드 선택과 추가 반복을 결과를 본 뒤 바꾸지 않는다.
9. 주 비교는 같은 측정창의 정규화된 운영 손실이며, 네 원료 지표·최초 요청~완료 누적시간·트럭/본선 잔여도 함께 보고한다. 미완료는 현재까지 시간을 포함한다. 기존 진입시각 이연의 장부 한계는 별도 원요청 시각 지표로 감시하며 이번에 시계 정의를 함께 바꾸지 않는다.
10. 진단 성공은 세 쌍의 평균 운영 손실이 이전 보상 및 규칙보다 작고, 각 쌍의 원요청 시간·트럭/본선 잔여가 비교군보다 늘지 않으며 입력/물리/정보 경계 검사가 통과하는 경우로 한정한다. 통계적 확증·최적 가중치·현실 상한 확정과 구분한다.
11. 입력 계약 실패를 주문 삭제·새 상자 생성·임의 시드 교체로 숨기지 않는다. 실패를 저장하고 해당 비교는 미완료로 판정한다.
12. Windows 별도 검증 환경·스레드 1개, 동시에 최대 2개 실행. 코드·사전등록을 커밋한 깨끗한 작업 폴더에서 실행한다. 현재 Windows torch 실행은 확인됐으므로 과거 WSL 전용 환경 가정을 적용하지 않는다.
