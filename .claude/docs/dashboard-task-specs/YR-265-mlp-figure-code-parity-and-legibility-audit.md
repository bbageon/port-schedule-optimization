## ① MLP 그림 — 초안은 GELU, 구현은 ReLU

`src/yard_rl/v3/actors/nets.py` 는 `Linear → ReLU → Linear → ReLU → Linear` 다.
제공된 `MLP-draft.png` 는 **GELU** 로 적혀 있다(상자 두 곳 + 아래 수식 두 곳).

### 앞선 방식(LaTeX 오버레이)의 문제 셋

원고가 `\begin{picture}` + `\put` 으로 "ReLU" 상자를 그림 위에 덧그렸다. 확대해 보니

1. 회색 상자 안에 **밝은 사각형 자국**이 보인다 (`\colorbox` 회색이 그림과 안 맞는다)
2. 덧글씨가 **검정**이라 원본의 남색 `Layer 1/2/3` 과 색이 어긋난다
3. 좌표를 `1448pt × 610pt` 픽셀로 박아 둬서 그림을 다시 내보내면 **조용히 어긋난다**

### 고침 — 그림 파일이 스스로 옳은 말을 하게

`scripts/v3/fig_mlp_relu.py` 신설. 제공 원본(`MLP-draft.png`)은 **손대지 않고**
`MLP-relu.png` 를 만든다:

- 원본에서 실측한 글자색(`#001F52`)과 상자 바탕(`#F1F1F1`)을 그대로 써서
  `GELU` 를 지우고 `ReLU` 를 **같은 대문자 높이**로 다시 그린다
- 아래 **수식 띠는 잘라낸다.** 래스터에서 글자를 갈아끼우면 폭이 달라져 식이 밀린다.
  대신 원고가 진짜 LaTeX 수식으로 조판한다 — 벡터라 확대해도 깨지지 않는다
- GELU 를 2곳 못 찾으면 **스크립트가 멈춘다** (초안이 바뀌면 조용히 지나가지 않게)

원고에서는 `picture`/`\put` 블록과, 그것만 쓰던 `\usepackage{xcolor}` 를 걷어냈다.

## ② ★그림 글자 크기 감사 — 아키텍처 그림은 본문폭에서 못 읽는다

본문폭 4.80 in(345.6 pt)에 넣었을 때 **가장 작은 글자의 실제 크기**를 쟀다.

| 그림 | 원본 폭 | 작은 글자 | 판정 |
|---|---|---|---|
| System Concept | 1,619 px | **4.7–5.6 pt** | 아슬아슬 |
| **System Architecture** | 1,535 px | **3.2–3.6 pt** (일부 2.0) | **못 읽는다** |
| MLP-relu | 1,448 px | 5.7 pt | 통과 |

집 규칙의 하한은 도식 6 pt · 자료 그림 8 pt 다. 여백을 잘라도 폭 이득이 1~3% 뿐이라
(잉크 bbox 실측) 소용이 없다 — **내용 밀도 자체가 원인**이다.

### 왜 손대지 않았나

셋 다 사용자가 만들어 넣으라고 준 그림이고, 배치도 사용자가 지정했다. 읽히게 만들려면
**그림을 다시 그리거나 배치를 바꿔야** 하는데 둘 다 사용자 판단이 필요하다.

### 고를 수 있는 길 (보고용)

1. **가로 전면 배치** — 90° 돌려 한 쪽을 통째로 쓰면 폭이 345.6 → 547 pt(×1.58),
   작은 글자가 **3.4 → 5.4 pt**. 여전히 6 pt 미만이지만 크게 낫다.
   다만 그림이 자기 쪽을 차지하고 캡션도 함께 돌아간다
2. **다시 그리기** — 라벨을 줄이고 4.80 in 에 맞춰 벡터로. 예전 `fig-arch.pdf` 가
   그렇게 그려져 6 pt 를 지켰다. 지금 그림의 구조는 유지하면서 세부 문구만 덜어내면 된다
3. **그대로 두기** — "전체 조망" 그림으로 두고 세부는 본문이 설명한다.
   심사자가 짚을 여지가 있다
