# YR-133 — Block Q 발의 판매·양방향 견적 (TransferQuoteQ — 중앙 일괄 검토 폐지)
> 상태: backlog · 등록 2026-07-30 (사용자 설계 정정 박제)
> 근거: [로드맵 — 사용자 정정 절](../strategy-history/2026-07-30-BlockQ-v2-로드맵-10단사다리.md)
> — "게이트 진입 순간 모든 건을 중앙이 일괄 검토하는 것은 잘못. 각 단일 블록 큐가
> 해당 컨테이너를 판매하고 싶다고 **계산해서 계산 정보를 같이 넘긴다**."

## 목표 구조 (정본 — 사용자 정정 2 반영: 2026-07-30)

0. **결정 단위**: 블록 큐는 작업 하나하나에 대해 "할지 안 할지"를 **견적 계산으로
   판단**한다 — 유형(본선/트럭) 무지는 유지하되 **작업별 구분은 필수**. 행동 추상화는
   "지금 크레인이 실행할 작업 1개"가 아니라 **미래정보(공개 ETA)를 고려한 작업 후보들의
   선택(보유/판매)** 이다. **SELL 은 물리 행동이 아니어도 블록 큐의 행동 공간에 포함**
   (사용자 확정 — 실행 의미 = 견적 동반 발의).
1. 판매 창(게이트 진입~블록 도착) 안에서 **원소유 Block Q 가 판매 의사를 계산·발의**.
   동반 정보 = **판매효과(OutRelief)**: 빠지면 절약되는 내 블록 비용.
2. 리조버는 발의 건에 한해 수신 후보 Block Q 들에 **수용부담(InBurden)** 조회 —
   받으면 늘어나는 비용 (용량·규격은 집행층이 재검).
3. 판정: OutRelief − InBurden − 이전비용 > 0 인 최선 수신처가 있으면 TRANSFER, 없으면
   KEEP. 집행 = 현행 MultiBlockTerminal 2단계 커밋 그대로 (실패 = KEEP).
4. 정보 경계: 견적 계산은 각 블록의 자기 관측·공개 계획만 (YR-107 오라클 금지 승계).

## 선결 (등록 시점 명시)

- Block Q 의 후보 비용·순위 능력 (BlockQ-v2 사다리 — YR-131/132 진행 축): 견적의
  실체가 이 능력이다.
- [YR-123](YR-123-common-cost-curve-api.md) 공통 비용 계산기: 판매효과·수용부담이
  **같은 numeraire 단위**로 계산되어야 비교가 성립.
- 초기 구현 후보(사다리 6단과 접속): 학습 전이라도 계산식(CALC — vessel_cost 계열 +
  트럭 한계비용)으로 견적을 채우는 규칙판 선행 가능 — 착수 시 사전등록에서 결정.

## 판정 (착수 시 동결할 것)

기존 확증(창중 이송 +0.820/+0.841 유의)과 같은 대역 규약으로, 중앙 혼잡 규칙(임계
0.10) 대비 총비용+A→O 공동 지표 비교. 임계·표본은 착수 시 동결.
