# YR-332-h — 양하 적체 연결과 크레인 정책 지연 측정

- **상태**: done
- 요청: 2026-11-05 사용자 — 문헌에 따라 양하 연결을 추가하고 오더별 신경망 지연을 검토.
- 상위: [[YR-332]]. **3대 게이트 보정 대상: scenario_validity**.
- 환경 보정 한 축. 속도 측정은 진단이며 정책·보상·후보 제한의 운영 변경은 포함하지 않는다.

## 범위와 완료 기준

1. CPU v7 하루·연속 크레인 경로에서 유한 양하 인계 용량을 켠다.
2. 용량은 실행 프로파일의 운반차 대수에서 가져온다. 현재 H21은 3대이며 문서의 6대와 다르다.
   이 값은 기존 모형의 가정이다. 문헌이 이 숫자를 실측으로 입증한 것으로 쓰지 않는다.
3. 기존 집계 모형의 STS 인출→이송→야드 적재 완료 간 미완료 수를 제한한다.
   용량은 같은 블록/운반 fleet의 모든 양하 선박이 공유한다. 적재 완료 때 막힌 다른 배도 재개한다.
4. OFF 대조, ON 느린/빠른 야드, 용량 변화, 두 배 공유, 저장·복원, 비용 연결을 검사한다.
5. 후보 12/100/1,000/10,000개 신경망 호출과 12/100/1,000개 실제 후보 생성·선택을 계측한다.
   개별 호출과 일괄 호출 시제품을 비교하고 입력·점수·선택 정합도 확인한다.
6. 문헌·명세·원자료·시험 결과를 보존하고 commit/push 및 Dashboard 정합 감사를 수행한다.

## 경계

- 완전한 개별 운반차 궤적 모형이 아니다. 이송 지연은 기존 왕복 환산시간을 유지하고,
  슬롯은 야드 적재 완료까지 점유한다. 차에서 상자를 드는 중간 시점·귀환 구간 분리는 미구현.
- 집계 근사는 양하 지연의 인과 연결을 복구하며, 특정 터미널의 생산성을 확증하지 않는다.
- GPU 배열 세계와 구 PPO 경로는 새 기본 환경과 동등하다고 주장하지 않는다.
- 신경망 속도 측정은 현재 9입력 공유망 기준이다. 예정/확정 집합 인코더·통신/TOS는 미포함.
- 일괄 추론은 측정용 시제품이다. 운영 정책의 후보 상한/특징/보상/우선규칙은 바꾸지 않는다.
- 실제 기록 부족, 본선 마감 현실성, 정책 성능은 이번 완료 판정과 구분한다.

## 사전 고정 검증

- 진단 시드: 9,903,320 및 fixture seed 0. 성능 판정 대역과 분리.
- 지연: CPU 1 thread, 준비 실행 후 30회(전체 경로 10회), 원시 시간 저장.
- 같은 시작 상태·같은 오더로 비교한다. 새 정책 학습은 하지 않는다.
- 느린 야드에서 ON 본선 대기·비용 증가, 처리 복구 시 재개·잔여 0을 요구한다.
- 실패·미확정도 보고한다. 정책 개선·현장 배포 가능성을 진단에서 PASS로 판정하지 않는다.
