# YR-331-a — v6 크레인 능력·부하 장부와 상한 보정

- **상태**: backlog
- 파생: YR-331 문헌·보상 설계(2026-09-26).
- 무엇: 크레인별 필요한 작업시간과 실효 처리 능력을 중복 없이 측정하고, 대기·본선·미완료 조건을 지키는 수용량을 구한다.
- 왜: 문헌에는 공통 최적 가동률이 없으며 v6의 두 크레인 간섭·본선 공유를 반영한 목표값이 아직 없다.
- 선행: 현재 코드·원자료의 연구 게이트 정합 복구. 실행할 v6 CPU/GPU 경로를 명시하고 미완성 30일 GPU 경로를 완료로 취급하지 않는다.
- 정본: [07 설계](../../../docs/구현계획/07_v6_적정부하_비용보상.md), [보정 계약](../../../docs/research/v6-workload-reward/calibration.md).

## 범위

정책 학습·보상 가중치 변경 없이 작업분량·가용 능력을 측정한다.
원래 요청·공개시점·유효 완료·필수 본선 업무·크레인 간섭·작업 분담 합을 감사한다.
5·15·30분 관측과 부하 0.4–1.1의 계획 격자는 진단 가정이며 성능 사전등록 완료가 아니다.
실행 전에 입력 시드·반복 수·기간·허용 큐 대기·선정 기준을 고정한다.

## 완료 조건

1. 작업 한 건의 크레인별 분담 합이 1이고 이연·거절·미완료로 원래 물량이 사라지지 않는다.
2. 평균 서비스시간·변동·유효 처리량·본선 점유·간섭과 부하의 관계를 기록한다.
3. 각 상한을 단일 최적 정답이 아닌 가정·불확실성과 함께 제시한다.
4. 선택 자료와 별도 입력에서 상한·관측창을 확인하고 조건을 동결한다.
5. 세 연구 게이트·Dashboard·실행 증거를 갱신하고 commit·push 한다.

## 현재 결과

미실행. YR-331의 13.83건/h·72.81%는 문헌 입력과 큐 대기 5분 가정의 계산 예시이며 이 작업의 결과가 아니다.
