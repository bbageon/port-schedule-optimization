# YR-332-u — 실제 도착순 대비 저장된 v7 학습 정책 재평가

- **상태**: backlog
- 상위: [[YR-332]], 파생: [[YR-332-t]]. 2026-11-06 사용자: “다시 그러면 학습 정책 테스트 해볼래?”
- 단일 변경: 비교 규칙에 실제 작업 대기열 진입순을 추가한다. 모델·물리·비용·입력은 고정한다.
- 현재 저장 모델의 평가 요청이며 재학습·최고 모델 재선정은 하지 않는다.

## 무엇과 왜

이전 비교는 최단작업 우선만 사용했다. 그것으로 도착순 대비 학습 효과를 결론낼 수 없다.
기존 `FIFO`의 통지순과 별도로 `FCFS_ARRIVAL`을 추가해 이미 일어난 작업 해제 사건으로 정렬한다.
기존 후보·제약·실작업 우선 처리는 동일하다. 현실 단가·시간 보정 미완료를 통과로 바꾸지 않는다.

## 도착순 계약

- 외부 트럭: 실제 처리된 `BLOCK_ARRIVAL`(블록 도착) 사건 시각.
- 본선 적하 등 내부 작업: 처리된 `JOB_RELEASED`(작업 해제) 사건 시각.
- 본선 양하: 물리 인계 후 처리된 `VESSEL_RELEASED` 사건 시각.
- 현재 실행 가능한 후보 사이에서 이 시각이 빠른 것을 우선한다. 동시각은 작업 ID로 고정한다.
- 안전·필수 작업·두 크레인의 공동 예약 제약은 기존과 같고, 불가능한 선두 작업 때문에 정지하지 않는다.
- 실작업이 없는 경우 사전 준비 후보의 기존 공개 통지순을 사용한다. 숨은 미래 도착은 읽지 않는다.
- 과거 사건을 증분 집계하며 세계마다 별도 보관한다. 원본 사건·작업·후보 생성은 변경하지 않는다.
- 이 혼합 작업 규칙은 연구용 정의다. 특정 부산항 터미널의 실제 운영을 재현했다고 주장하지 않는다.

## 실행 사전등록

- 6단계와 같은 21블록·42크레인, 24시간 관측+2시간 추가 처리, 재배정 없음, 전체 후보.
- 평가 입력: (3,500건, 9913900), (7,500건, 9913910), (15,000건, 9913920).
  예전에 본 세 날짜의 추가 대조이며 새로운 독립 확증 표본이 아니다.
- 저장 모델 9913501/9913502/9913503 각각 초기값과 pointwise/pairwise/coverage/flow의 마지막 모델.
  4종 학습 방식·총 12개 학습 모델 모두 포함한다. 결과를 보고 모델을 고르지 않는다.
- 도착순 세 입력을 새 실행하고 3,500건을 한 번 반복해 결정·사건·결과 재현을 검사한다.
- 기존 결과 재사용 전 다음 8개를 새 실행해 원자료와 정확히 대조한다:
  최단작업 우선 세 입력, initial/9913501/3500, pointwise/9913502/7500,
  pairwise/9913503/15000, coverage/9913501/7500, flow/9913503/15000.
- 기존 원자료 51개·모델·입력 해시를 전수 확인하고, 공통 소스의 변경은 dispatch의 새 규칙뿐인지 검사한다.
  재현 대조가 불일치하면 해당 결과의 재사용을 중단하고 원인을 분리한다.
- 새 평가 총 12회, 저장 결과 재사용을 명시한다. 새 51회 실행이라고 보고하지 않는다.
- CPU 1스레드·새 프로세스, 최대 2개 평가 동시 실행. 실행 속도의 우열은 이번 판정 대상이 아니다.
- 관측 지표: 트럭 체류시간·비용 네 항·투입/미투입·24시간 미완료·26시간 본선 완료(양하/적하 분리).
- 짝별 변화율 후 세 모델·세 물량을 같은 비중으로 평균한다. 도착순 기준과 최단작업 기준을 함께 표기한다.
- 비용 감소만으로 채택하지 않는다. 투입 감소·미완료 증가·본선 완료 감소를 별도로 표시한다.
- 기존 게이트 명령 결과를 저장한다. 최신 사용자의 제한된 재평가 지시를 적용하되,
  기존 현실성 미통과와 기존 최단작업 우선 대비 미통과를 보존한다.

## 완료 기준

1. 통지순과 도착순의 역전·양하의 실제 해제·미래 비노출·세계 분리·실제 엔진 배선을 검사한다.
2. 새 평가·정확 재현 대조를 완료하고 원자료·실행 커밋·설정·모델 해시를 저장한다.
3. 모든 학습 방식의 물량별·전체 비교와 보호 지표를 보고한다. 누락/잔여 원인 해결과 혼동하지 않는다.
4. 관련 검사·Dashboard·명세·증거를 갱신하고 commit·origin push한다.
