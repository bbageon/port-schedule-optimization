## 왜 분리하는가

"터미널 안에 항상 50~150대가 있게 유지한다"(**고정 재공량**)는 방식은 본 성능시험에 쓸 수 없다.
빨리 처리하는 정책일수록 빈 자리가 빨리 생겨 **트럭을 더 받게 되고**, 결과적으로 정책마다
처리한 물량이 달라진다. 그러면 "누가 더 싸게 했는가"를 같은 조건에서 비교할 수 없다
(YR-150 1차 재정의에서 폐기된 이유).

그렇다고 이 방식이 쓸모없는 것은 아니다. **"터미널이 꽉 찼을 때 어떻게 버티는가"** 를 보려면
오히려 이쪽이 맞다. 다만 그것은 **성능 비교가 아니라 포화 내성 진단**이므로 본 시험과 섞지
않고 따로 연다.

## 무엇을 하는가

1. 재공량 목표 밴드를 두고 빈 자리가 생기면 대기 트럭을 즉시 투입하는 **포화 유지 모드**를
   별도 옵션으로 구현한다(본 성능시험 경로와 코드에서 분리 — 기본값 OFF).
2. 판정 지표를 **성능이 아니라 내성**으로 바꾼다: 포화 유지에 필요한 대기열 길이, 블록별
   최대 재공량, 크레인 가동률 상한, 안전장치 개입률, 실패(교착·미완 폭증) 발생 여부.
3. **정책 간 비용 비교를 하지 않는다.** 이 모드에서 나온 수치는 어떤 정책 채택 근거로도
   쓰지 않는다 — 정책마다 처리 물량이 달라 비교 자체가 성립하지 않기 때문이다.
4. 결과는 "이 구조가 어느 재공량까지 버티는가"의 **한 줄 진단**으로만 보고한다.

## 완료 조건

- 포화 모드가 본 성능시험 경로를 바꾸지 않음을 테스트로 잠근다(OFF 시 바이트 동일).
- 각 구조(H-21·V-21)의 포화 한계 재공량이 보고되고, 그 수치가 성능 판정에 쓰이지 않았음이
  결과 JSON 에 박제된다.

## 하지 않는 것

- 포화 모드 수치를 "정책 A 가 B 보다 낫다"의 근거로 쓰는 것.
- 본 성능시험(YR-150/157)의 부하 정의를 고정 재공량으로 되돌리는 것.
