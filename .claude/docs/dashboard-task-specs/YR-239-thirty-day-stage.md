### 3-1. ★왜 "새로운 엔진" 이 필요했나 — 본선을 t=0 에 못 박는다

사본 `engine._validate` 는 **모든 job 의 대상 컨테이너가 t=0 야드에 있을 것**을
강제한다. 하루면 맞지만 30일은 산수가 안 맞는다:

```
초기 적재   21블록 19,656상자   (실측)
하루 소모   본선 적하 ~3,207 + 반출 트럭 ~2,500  =  ~5,700/일
```

⇒ **사흘 반이면 바닥난다.** 5일차 배가 실어 갈 상자는 3일차에 들어온 상자여야
하는데, 그 상자는 무대를 세우는 시점에 **존재하지 않으므로 지정할 수 없다.**

그래서 **배를 그날 아침에 붙인다**(`inject_vessel`). 사본이 트럭에 대해 이미 하는
일(`admit_external_job`)과 **같은 계약**이다 — 검사 먼저, 통과하면 원자적으로 수술,
실패하면 아무것도 안 바꾸고 조용히 넘기지 않는다. 적하 대상은 **그 순간 야드에
실제로 있는 상자**에서 고른다.

`MonthTerminal.run()` 은 사본 `MultiBlockTerminal.run()` 을 **그대로 옮긴 것**이고
`guard > 2_000_000` 한 줄만 다르다 —
`test_month_run_differs_from_clone_only_by_the_guard` 가 기계로 대조한다.

### 3-2. ★비용 벽 — 정리를 안 하면 30일이 안 돌아간다

30일이면 트럭 20만 대·본선 job 20만 건이 쌓인다. 네 곳이 함께 부푼다:

| 부푸는 곳 | 누가 훑나 | 30일 비용 |
|---|---|---|
| `sim.jobs` | `announced_around`·`inside_count` — 결정마다 | 특징 계산 20배 |
| `time_ledger.records` | ★`bridge._sync` — **60초마다 전량** | **86억 회** |
| `time_ledger._a_sorted` | `admit_external_job` 의 삽입 (O(n) memmove) | 320GB memmove |
| `ledger.records` | `check_invariants` 가 `sim.jobs` 와 1:1 요구 | 메모리 |

→ **하루가 끝나면 끝난 것을 네 곳에서 함께 치운다**(`prune_completed`).
치우는 조건은 하나다: 트럭은 게이트를 나갔고(`gate_out ≤ t`) 본선 작업은 `DONE`.
적분 상태(`_in_block`·`_o_heap`·`_n_inside`)는 `records` 와 독립이라 **안 건드린다.**
끝난 배도 치운다(`retire_done_vessels`) — `_advance` 가 매 적분마다 전량을 훑기
때문이다. 치우기 전에 유휴 적립값을 `archive` 로 옮기므로 손실이 없다.

**Φ 의 원료인 v3 기록(`records`)은 안 지운다.**

⇒ 정책은 *"이 블록이 바쁘다"* 는 알지만 *"왜 바쁜지"* 는 모른다.

## 6-3. ★A11 정정 — `vessel_slack` 은 30일로도 안 살아났다

30일 무대에서 실측(부하 800 · 2일 · 표본 2,723건):

```
천장(+2h)에 붙은 비율  100.0%   ·  서로 다른 값 1가지  ·  음수 0건
```

**원인 진단이 틀렸었다.** *"접안이 하루를 넘어 늘 미완이라 결측"* 이 아니라,

```
planned_completion = start + moves × cadence × 2.0     ← 여유 배수 dmult = 2.0
slack(t)           = pc − t − 남은작업 ≈ moves × cadence  (= 14시간)
```

**계획 완료시각이 순수 작업시간의 2배**라 배는 늘 넉넉하다. 창 밖이라 결측인 게 아니라
**여유가 늘 크다.** `slack` 은 배가 일정의 **50% 이상 밀려야** 0 근처로 내려온다.

⇒ 이 칸은 **혼잡 부하(12,500·15,000)에서만 살아날 수 있다.** 거기서도 천장이면
죽은 칸이므로 [[YR-235]] C 처럼 **제거 후보**다. 학습 뒤 `probe/audit.dead_columns`
로 부하별로 재고 판정한다. **지금 지우지 않는다** — 안 재고 지우면 "혼잡에서 쓸모
있었을지도" 를 영영 못 본다.

## 6-2. 어떻게 돌리나 (실행 명령 박제)

```bash
# ① 달 계획만 먼저 본다
PYTHONPATH=src python -m yard_rl.v3.train --seed 9900700 --dry

# ② 28일 학습 (하루가 곧 한 회차 · 날마다 중간보고·체크포인트)

# ③ 부하별 판정 — 같은 달을 팔만 바꿔 다시 굴린다 (**새 대역에서 한 번만**)

```

`--dry` 를 둔 이유: 전에는 `python -c` 로 띄워서 **무엇으로 돌렸는지가 원자료에
안 남았다.** 시드·작업자 수·라벨 예산이 셸 히스토리에만 있었다.
