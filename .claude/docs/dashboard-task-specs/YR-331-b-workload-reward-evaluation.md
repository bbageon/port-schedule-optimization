## 구현 범위

`ppo/runtime.py:boundary`에 동결한 부하 스냅샷과 잠재함수 차분을 연결한다.
원화 비용·기본 보상·보조 항·현재/다음/말단 점수를 구분해 기록한다.
실제 종료와 60구간 수집 종료를 구분한다. CPU 검산 후 필요할 때 GPU 동등성을 따로 확인한다.
신경망·후보·정보 특징·PPO(행동 확률 갱신 학습) 설정·세계 엔진·단가를 함께 변경하지 않는다.

## 비교와 판정

- 기존 보상 대 동일 조건+부하 차분. 보조 세기·학습 반복·평가 시드를 실행 전에 고정한다.
- 구매 결정 호출·수락·거래 확정·유효 완료를 분리한다.
- 공유 비용의 공로 희석·가치 추정 오차·부분 관측 문제는 해결됐다고 전제하지 않는다.
- 터미널 원화 비용, 원래 요청 기준 완료율, 본선 지연/잔여, 미완료 누적과 물리 제약을 함께 판정한다.
- 구매 수나 부하 점수만 상승하면 채택하지 않는다. 외부 지연·미완료를 숨긴 개선도 기각한다.
- 결과가 학습 실패여도 보존하고 관련 단일 원인만 후속으로 등록한다.

## 현재 결과

2026-09-27 사용자 직접 지시: “학습하고 잘되는지 확인해봐 그럼”.
[사전등록](../../../docs/research/v6-workload-reward/training-prereg.json): 기존/새 보상 각각 3초기화, 5일 연속 중 3일 학습, 새 3일 주문의 가운데 날 평가, 같은 평가 주문의 기준 규칙 비교. 세기는 1, 관측창은 15분으로 고정한다.
원래 요청 시점은 **최초 예약 게이트 시간**이다. 통지 시간을 비용 원점으로 쓰면 정상 사전 통지까지 지연으로 잘못 청구하므로 쓰지 않는다. 이 감사는 학습 비용 단가를 바꾸지 않는다.
잠재함수는 학습기에만 opt-in 연결하며 원화 비용·기본 보상은 별도 보존한다. 기존 회귀 25개·새 수식/정보/장부 검사 8개 통과 후 clean source 실행을 준비한다.
3쌍은 첫 진단이며 최종 확증·기본 정책 채택으로 부르지 않는다. 이전 게이트의 재검 실패는 보존하고 본 실행의 타당성·증거를 새로 판정한다.
