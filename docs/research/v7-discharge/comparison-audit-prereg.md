# 비교 기준·비용 수치의 타당성 감사 — YR-332-t 사전등록

2026-11-07. YR-332-s 보고 뒤 사용자가 “이거 참고해서 다음 실험 진행해줄래?”라고 지시했다.
보고의 예정 순서(t → m → w)에 따라 비교 기준 감사(t)를 먼저 수행한다.
정책·보상·물리·후보·학습·평가 입력을 바꾸지 않는 감사이며 새 학습은 없다.
착수 전 `authorize-next`는 종료 2(저장된 scenario PASS 재계산 실패)였다. 원문을
`authorization.json`에 보존하고 PASS로 덮어쓰지 않는다. 현실성 미통과는 그대로다.

## 감사가 답할 질문

“학습 효과가 없다·규칙보다 못하다”는 판단에 쓴 수치가 무엇으로 만들어졌고,
그 수치를 근거 범위 안에서 바꾸면 판단이 바뀌는지 확인한다. 근거 부족과 구현 오류를 구분한다.

## 고정할 것

- 기준 코드: 이 문서를 담은 커밋. v7 원화 네 항, 관측 24시간+정리 2시간, 21블록·42크레인,
  초기 적재율 0.65, 후보 수 제한 없음, 재배정 없음, 교사 없음.
- 대상: YR-332-v의 69회 = 7규칙×3일 + 기존 SF_SPT×3일 + 학습 전·4학습 방식×초기값 3개×3일.
  반복 2회는 제외한다. 입력일은 3,500/7,500/15,000건(seed 9913900/9913910/9913920).
- 15개 체크포인트와 69개 기존 결과의 sha256을 실행 전에 대조한다.

## 재실행과 정확 재현

- 69회를 현재 코드로 다시 실행한다(최대 8개 독립 프로세스, 프로세스당 1스레드).
- 후보·선택·사건·작업·기록·결과 해시 6종, 결과 원값, 입력 메타, 운영 집계가 YR-332-v
  저장본과 모두 같아야 한다. 하나라도 다르면 분석하지 않고 원인을 보고한다.
- 읽기 전용 추가 관측(정책 입력·결정에 쓰지 않음, 해시 일치로 무간섭 확인):
  1. 트럭별 게이트 진입(A)·블록 도착(B)·작업 시작(S)·완료(C)·게이트 출차(O)·흐름·블록.
  2. 비용 계산과 같은 24시간 계수기의 선박별 유휴, 스트림별 안벽 대기, 빈 주행, 재조작.
  3. 실행 가능한 실작업(SERVE) 후보의 원값(소요·빈 주행거리·재조작·누적 대기·본선 여유)과
     학습 입력이 상한에 걸린 빈도.
  4. 실작업 후보가 둘 이상일 때 실제 선택이 그 크레인의 최단 소요 후보와 같은 비율.
- 기록과 계수기로 다시 계산한 Φ가 저장 Φ와 같아야 한다(같은 함수, 상대 1e-9).

## 분석 1 — 수치 목록

실행 경로의 값마다 단위·코드 위치·코드가 주장하는 근거·변환식·분류·적용 범위를 적는다.
분류는 `법정`, `문헌·시장`, `설계`, `미확정` 네 가지다. 원문을 다시 대조하지 못한 인용은
“인용 주장, 원문 미대조”로 남긴다. 근거가 없는 값을 다른 값으로 보충하지 않는다.

## 분석 2 — 네 항의 원래 단위와 정의

- 트럭·시간(기본분과 1시간 초과분), YC 빈 주행 시간, 재조작 횟수, 선박 GT·유휴시간.
  선박 유휴는 양하·적하 스트림으로도 나눈다(원인 판정 아님).
- 트럭 체류를 게이트→블록, 블록 줄서기, 작업, 블록→게이트, 24시간 검열분으로 나눈다.
- 핵심 비교의 Φ 차이를 네 항으로 분해하고 미투입·미완료·본선 완료와 나란히 둔다.
- 분모(평균 대상 트럭), 관측 종료, 이중 계상 규칙을 코드로 확인해 명시한다.
  투입 누락·잔여의 원인 복구는 YR-332-m의 범위다.

## 분석 3 — 규칙과 학습 정책의 정보·표현 대조

후보 생성·필수 작업·안전 제약·동률 처리·정보 시점·작업시간 표현을 코드 기준 표로 만든다.
상한 도달 빈도와 최단 소요 일치율은 서술 통계이며 성능 원인으로 판정하지 않는다.

## 분석 4 — 고정 궤적 재채점(점수 민감도)

사전 고정 비교:
- K1 학습 전후: 4학습 방식 각각 대 같은 초기 모델, 9쌍(초기값 3×3일).
- K2 규칙 대비: 학습 전과 4학습 방식 각각 대 8규칙(7규칙+SF_SPT), 9쌍.

지표는 날짜별 Φ 변화율의 평균(모델·날짜 동일 비중)과 개선 쌍 수다. 기준 계수의 판정 대비
평균 부호가 뒤집히거나 개선 쌍 과반(5/9 이상) 여부가 바뀌면 ‘판정 변화’로 센다.

(A) 문서로 근거가 남은 대안값만 하나씩 바꾼다.
