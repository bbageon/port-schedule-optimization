# ReSched 참고 PPO 작업 순서 진단 — 본실행 전 고정

등록: 2026-11-17. 작업 YR-332-av. 사용자 명시적 적용 요청에 따른 합성 환경 진단이다.
결과를 보고 본 문서의 입력·예산·평가 대상을 바꾸지 않는다. 실패 실행도 보존한다.

## 질문

현재 실행한 작업의 실제 비용을 이용하는 PPO(정책을 조금씩 갱신하는 강화학습)로 학습할 수 있는가?
같은 PPO 안에서 작업 간 정보를 주고받는 Transformer가 후보별 MLP보다 나은가?
최종 정책이 기존 짧은 실작업 우선 규칙과 저장된 누적자료200회 모델보다 나은가?

## 논문과 적용 경계

- [ReSched, ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/file/467e109270678b3e2b3c2e7fa6b3d575-Paper-Conference.pdf).
- [공식 코드](https://github.com/XiangjieXiao/ReSched), 고정 commit `4d1fda8ab4d78d1cd9664de28f3f77d88620f309`, MIT.
- 본편은 REINFORCE 학습이며 PPO는 부록 E.3·공식 구현에 있다. 논문 목표는 제조 공정의 전체 완료시각이다.
- 이번 구조는 작업 self-attention·작업–장비 edge 조건부 attention·장비 self-loop·pair 선택을 참고한 독립 구현이다.
- 크레인·작업 쌍에 기존10칸을 넣고, 같은 작업/크레인끼리 초기 임베딩을 평균한다.
  작업·크레인 둘을 따로 표현하는 작은 망(폭32, 4head, 2block, feedforward64)을 쓴다.
- 작업 순서 RoPE와 아직 공개되지 않은 미래 작업을 넣지 않는다. 블록 간 그래프·방문 연결 입력도 추가하지 않는다.
  따라서 ReSched 원논문의 재현이나 온전한 이식으로 부르지 않는다.
- MLP actor는10→64→64→1, critic은 후보 평균10칸+경과시간으로 반환을 예측한다.
  Transformer critic은 작업·크레인 평균 표현+같은 경과시간을 쓴다. actor에는 추가 시간 입력이 없다.

## 공통 환경·행동·보상

- 기존 방문 연결·반입/반출 비율·날짜별 합성 곡선·수식 기반 분별 도착을 사용한다. 입력 생성 방식은 바꾸지 않는다.
- 현재 블록의 후보 전부를 유지한다. 후보 수에 따른 절단·상위 일부 선택을 하지 않는다.
- 기존 필수 작업 우선, 실작업 우선, 중복 작업 금지, 물리적 공동 실행 제약을 유지한다.
- 남은 실행 가능 쌍 가운데 조건부 categorical 선택을 반복해 공동 배정을 만든다.
  이 **순서 있는 구성 행동 전체**의 확률 곱을 학습에 쓴다. 최종 배정의 주변확률이라고 부르지 않는다.
- 모든 남은 행동이 WAIT이면 정해진 크레인 순서로 채운다. 아무 변화가 없는 WAIT 순서를 학습 표본으로 만들지 않는다.
- 실행 결과를 바꾸는 사후 점수 보정·규칙 대체·실패 시 자동 WAIT를 허용하지 않는다. 오류는 중단한다.
- 24시간의 기존 터미널 비용 네 항을 유지한다. 트럭은 게이트 진입→작업 완료이며 원 단가도 바꾸지 않는다.
- 60초 전체 블록 동기화 뒤 누적 비용을 기록한다. 행동 반환은 `−(24시간 비용−직전 동기화 누적 비용)/고정 눈금`이다.
  직전 경계까지만 뺀 action-independent 과거 기준이며 정확한 초단위 후속 비용이라고 주장하지 않는다.
- 할인1, Monte Carlo 반환, TD 부트스트랩 없음. critic을 과거 기준을 뺀 미래 비용에 맞추고 advantage를 배치 정규화한다.
- 눈금은 앞 단계 **학습용** 곡선0~2×3물량의 SF_SPT 비용9개 중앙값이다. 경로·해시·원값을 campaign에 고정한다.
  학습·평가 중 재추정하지 않으며 목표의 비용 비중을 바꾸지 않는다.
- 24시간 이후 행동은 같은 정책으로26시간까지 실행하되24시간 목표의 학습 표본에서는 제외한다.

## 고정 예산

| 항목 | 설정 |
|---|---|
| 구조·초기값 | MLP, Transformer ×9951101/9951102/9951103 |
| 모델별 학습 | 6회 갱신, 갱신마다 새 하루2개, 총12일 |
| 하루 입력 | train 곡선0~11, 입력시드9951200~9951211, 물량3500/7500/15000 반복 |
| 행동 탐색 시드 | 모델시드+1000+곡선번호 |
| 표본 선택 | 모든 선택 가능한 결정을 수집, 갱신당 최대2048개 균등 비복원 추출 |
| 표본 시드 | 모델시드+2000+갱신번호 |
| PPO | 표본4순회, minibatch64, Adam0.0003, clip0.2, value0.5, entropy0.01, gradclip1 |
| PPO 순서 시드 | 모델시드+3000+갱신번호 |
| 모델 선택 | 마지막6회 갱신 결과, 평가를 보고 checkpoint를 고르지 않음 |

2048개는 실행 후보 제한이 아니라 CPU 진단의 갱신 표본 예산이다. 원 수집 수와 실제 사용 수를 모두 보고한다.
두 구조의 표본 수·갱신 횟수는 같게 한다. 매 회차 갱신된 정책으로 새 경험을 얻으며 이전 정책의 경험을 재사용하지 않는다.
원논문보다 매우 작은 예산이다. 작은 예산의 실패로 Transformer/PPO 일반의 한계를 주장하지 않는다.

## 평가

- 새 holdout 곡선3/4/5를 물량3500/7500/15000과 각각 연결하고 입력시드9951300/1301/1302를 사용한다.
  같은 부모 생성기에서 나온 개발용 합성3일이다. 물량마다 한 곡선이므로 물량과 하루 모양의 영향을 분리하지 못한다.
- 새 모델: 구조2×초기값3×학습 전후2×하루3=36회.
- 저장 모델: `yr332_context_learning/model-9917101~3/point_steps.pt`×3일=9회.
- 규칙 SF_SPT/FIFO/LWKR×3일=9회. 총54회 + 새 각 구조 최종 첫 모델3,500건 정확 반복2회.
- 규칙·저장 모델은 기존 결정 방식, 새 두 구조는 같은 새 확률 결정 방식이다.
  새 두 구조 비교만 표현 구조 효과에 가깝다. 저장 모델과의 비교는 자료량·학습법·결정 방식이 함께 다른 시스템 비교다.
- 매번 argmax 한 번으로 평가한다. 여러 미래를 돌려 가장 좋은 답을 고르지 않는다.
- 주 지표: 동일24시간 창의 계산상 비용·게이트 진입→작업 완료 오더 평균. 미완료도 관측된 경과시간을 포함한다.
- 반입·반출·양하·적하를 별도 보고하고24/26시간 미완료, 실제 방문 통계, 물리 불변식을 확인한다.
  본선은 스트림 계획 시작→개별 야드 완료로, 선박 접안 시간과 다르다.
- 3일 오더 수로 가중한 전체 평균, 물량별 평균, 모델 초기값별 평균을 모두 보고한다.
- 실제 후보 생성+정책 선택의 중앙·상위5% 경계·최댓값 지연을 보고한다. CPU 동시 실행 부하를 명시한다.
- 작업 순서 그림은 평가3,500건 입력의 Y01 블록 09:00~11:00를 고정한다. 정책별 실제 서비스 작업을 표시한다.
  구간에 작업이 없으면 빈 구간으로 그대로 보고하며 개선 사례를 찾아 고르지 않는다.

## 검증·판정

- 신규 부품시험, 기존 정책 시험, 기존 SF_SPT 3,500건 실행의 결정·사건·장부 정확 재현.
- 학습 매 갱신에서 저장한 실행 행동 확률 재계산, 비용 증분 합과 최종 비용 일치, 예외·누락·분기세계0.
- 구조별 첫 모델의 저장된 행동 표본으로6회 optimizer를 재실행해 가중치 전부를 비교한다.
  이는 optimizer 재현이며 독립적인 학습 환경 재실행과 구분한다.
- 모든 평가 오더 장부에서 시간·미완료를 다시 계산하고 정책별 원본 입력 동일성을 확인한다.
- 성능은 작은 진단 표본·본선 보호·잔여 작업을 고려한다. 개선 평균만으로 채택하지 않는다.
- 운반·대기열 현실성 게이트는 미통과 유지. 기본 정책 변경·실항만 개선·논문 확증 주장 없음.
- 구현·계산 예산 smoke는 본평가와 입력시드·곡선을 분리한다. smoke 결과로 최종 모델을 고르지 않는다.
