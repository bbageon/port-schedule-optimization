# 신경망 설계 전략 검토 — 2026-11-15

**결론: 관계를 학습하는 방향은 타당한 후보지만 GAT+PPO를 바로 기본안으로 정할 근거는 아직 없다.**
현재 문제를 'MLP가 낡았다'로 설명할 수 없다. 입력·관계 표현·학습 알고리즘·표본량을 분리한다.
이 문서는 코드·문헌 검토다. 정책 구조나 학습법은 바꾸지 않았다. 실행 명세는 [as](../../../.claude/docs/dashboard-task-specs/YR-332-as-network-learning-design.md).

## 1. 현재 코드가 하는 일

- `src/yard_rl/v7/crane/policy.py`: 최신 설정은 10→64→64→1. 후보마다 같은 망으로 비용 점수를 낸다.
  `rank_many`는 가변 개수 후보를 일괄 평가한다. MLP라서 후보 12개까지만 처리하는 구조가 아니다.
- 점수 외에 실작업 우선 순위와 실행 가능성·공동 배정기가 작동한다. 낮은 점수만으로 모든 실행을 결정하지 않는다.
- `crane/fit.py`: 두 점수의 차이와 두 정답 비용의 차이에 SmoothL1(큰 오차의 영향을 줄이는 회귀 손실)을 적용한다.
  이진 승패만 배우는 선호 분류와도 다르다. 비용 차이의 크기를 사용하는 비교 회귀다.
- `scripts/v7/retrain_linked_environment.py`: 최대 3시간 반사실 실행(종료 경계에서 절단), 회차당 최대 24쌍·50회 갱신·모델당 6회차.
  질문을 모으는 행동 정책은 초기값으로 고정한다. 이번 실행은 학습된 정책으로 새 자료를 수집하는 반복도 아니다.
- 모델별 수집 쌍 92/105/86, 실제 학습 분할 76/87/72. 50회 갱신은 새로운 경험 50개가 아니다.
- 위 학습 쌍 수는 6회차 합계다. 회차마다 **그 회차 자료만** 학습하고 앞 회차 자료를 재사용하지 않는다.
  마지막 50회 갱신에 쓰인 쌍은 16/16/12개다. 망을 바꾸기 전에 이전 조건을 잊는지도 진단할 이유가 있다.
  자료 누적 재사용의 효과는 아직 실험하지 않았으며 성능 저하의 확정 원인이라고 부르지 않는다.

따라서 최신 실행을 **시뮬레이션 반사실 비용을 이용한 지도형 정책 학습**으로 기술하는 것이 정확하다.
넓은 의미의 모델 기반 정책 개선과 연결되지만 PPO·DQN을 구현했다고 쓰면 틀린다.
강화학습 전체를 TD·정책 경사만으로 정의할 수도 없다. 방법 이름보다 실제 자료 수집·목적함수를 명시한다.
교사가 비교하는 두 후보는 정답 생성 예산이며 실행 가능한 작업이 두 개라는 뜻이 아니다.

## 2. 제시된 문헌 확인

| 문헌 | 확인한 방법 | 우리에게 주는 근거와 한계 |
|---|---|---|
| [2026년 4월 리뷰](https://www.sciencedirect.com/science/article/pii/S0278612525003140) | 2018~2025년 143편, 그래프·Attention 증가, 확률 환경·실자료 검증 부족 | 인용은 확인됨. MLP가 열등하다는 직접 비교 근거는 아님 |
| [여러 블록 야드 크레인](https://www.sciencedirect.com/science/article/pii/S136655452500657X) | **CNN+MLP**, 전역·지역 상태, 공유 정책 다중 에이전트 PPO | 최신 연구도 MLP 사용. 블록 간 크레인 배치 문제라 우리 작업 순서 문제와 동일하지 않음 |
| [쌍둥이 자동 크레인](https://link.springer.com/article/10.1007/s40747-025-02174-3) | 다중 헤드 자기 Attention+PPO, 작업 관계·간섭 표현 | 후보 간 관계 표현의 직접 근거. 2025-12-29 온라인 공개, 2026년 권호. 우리 환경 개선율로 이식 불가 |
| [AGV·야드 크레인 적하 통합](https://www.sciencedirect.com/science/article/pii/S0952197625029434) | 가중 다중 그래프와 **관계별 그래프 합성곱(RGCN)** | 장비·작업 관계 표현 근거. GAT와는 다른 망이며 적하 중심 통합 문제 |

GAT는 연결된 이웃의 비중을 학습하는 그래프망, PPO는 실행 경험으로 선택 확률을 갱신하는 학습법이다.
둘은 서로 다른 축이라는 제안은 맞다. GNN·Attention·Transformer를 최신성 순위로 채택하지 않는다.
관련 선행 기준: [Zhang 등, Learning to Dispatch, 2020](https://proceedings.neurips.cc/paper/2020/file/11958dfee29b6709f48a9ba0387a2431-Paper.pdf)
도 그래프 표현+PPO와 합성 인스턴스를 사용한다. 오래전부터 존재한 조합 자체를 연구 기여로 삼기는 어렵다.

## 3. 관계 정보가 도움이 될 구체적 상황

예: 트럭 A의 반입 뒤 반출이 열리고, 트럭 B에는 반출 한 건만 남아 있다.
현재 작업만 보면 두 작업이 비슷해도, A를 처리하면 후속 작업과 다음 블록의 부하가 달라진다.
이 관계가 지금 특징에서 구분되는지, 교사 비용에서 재현 가능한 차이가 나는지가 먼저다.

- 노드: 공개된 오더·방문·관련 크레인. 한 방문의 선후관계, 같은 자원 경쟁 등을 연결한다.
- 예약/게이트 진입 후 이동/블록 도착 상태는 맥락에 쓸 수 있지만 실제 실행 후보는 실행 제약을 만족해야 한다.
- 미공개 미래 오더, 실제 미래 도착·완료, 시뮬레이터의 숨은 정답을 그래프에 넣지 않는다.
- 시간대에 따른 후보 수 변화는 현재 공유 MLP도 지원한다. 그래프의 추가 목적은 관계에 따른 점수 변화다.
- 모든 오더를 서로 연결하는 자기 Attention은 후보 수의 제곱에 비례하는 관계 계산이 필요하다.
  필요한 관계만 연결하는 그래프를 우선 검토하되, 혼잡하면 연결 수도 커질 수 있음을 측정한다.
- 안전한 후보를 숫자 제한으로 버리지 않는다. 후보 보존율과 생성·특징·망·배정을 합친 결정 시간을 재야 한다.

| 순서 | 바꾸는 것 | 비교가 답해야 할 질문 |
|---|---|---|
| 0 | ao의 합성 입력, 현재 망·학습 고정 | 다양한 하루가 입력·운영 계약을 지키는가? |
| 1 | 323-d의 표본 수·갱신 횟수·이전 자료 재사용 중 하나씩 | 현재 MLP가 정답을 맞추고 이전 조건도 유지하는가? |

| 2b | 같은 정보·같은 정답에서 MLP와 작은 관계망 비교 | 관계망의 표현이 추가로 도움이 되는가? |
| 3 | 망을 고정하고 비교 회귀와 PPO를 별도 비교 | 실행 경험의 이용 방식이 효과가 있는가? |

2a/2b는 구체적 정보 계약을 등록한 뒤 하는 후보 실험이다. 지금 정보를 한꺼번에 추가하지 않는다.
MLP에도 동등한 공개 정보와 관계 요약을 제공한다. 그래프에만 방문 연결을 주고 이기면 정보 효과와 구조 효과가 섞인다.
망 크기·학습 예산·같은 초기 조건/합성 입력을 기록하며, 연산량과 표본 수를 모두 완전히 같게 만들 수 없으면 별도 보고한다.
새 입력별 결과·초기값별 변동·4종류 작업·미완료·본선 지연과 후보 보존·전체 지연을 함께 비교한다.

GAT가 비교 회귀에서 이겨야 PPO를 연구할 수 있다는 뜻도 아니다. 데이터 부족이 학습 병목이면
**MLP+PPO**가 더 작은 변경일 수 있다. 현재 망과 GAT에 PPO를 각각 적용하면 망×학습법 효과도 분리할 수 있다.
큰 Graph Transformer와 다중 에이전트는 작은 모델에서 해결되지 않는 구체적 관계·협력 문제의 증거가 있을 때 검토한다.

## 5. PPO 전환은 단순한 loss 교체가 아니다

현재는 후보 점수를 낸 뒤 여러 크레인의 실행 가능성을 공동으로 맞춘다.
후보별 확률로 뽑은 선택을 뒤의 배정기가 바꾸면, 기록한 확률과 실제 실행한 행동이 달라질 수 있다.

필요 계약:

1. 실행 가능한 행동을 먼저 정하고, 실제 실행 행동의 당시 확률을 저장한다.
   순차 배정이라면 앞선 선택으로 남은 후보를 갱신하고 각 조건부 확률을 기록한다.
2. 정책이 확률을 정하는 범위와 공동 배정기의 범위를 일치시킨다. 강제 작업은 자유 선택처럼 학습시키지 않는다.
3. 사건 간 시간이 다를 때 비용 누적·할인·에피소드 종료·남은 작업 비용을 일관되게 정의한다.
4. 가치 추정망이 보는 정보와 정책이 보는 정보의 범위를 명시하고 보상 귀속을 검증한다.
5. 미니 환경에서 선택 확률·보상·상태 전이 회계를 확인한 후 일일 규모로 간다.

PPO가 자동으로 다른 크레인에 미친 영향을 정확히 나누어 주지는 않는다. 그래프도 보상 설계 오류를 고치지 않는다.
원문: [PPO, Schulman 등 2017](https://arxiv.org/abs/1707.06347).
