# YR-332-aa — 고정 도착 주문 보존 사전등록

2026-11-08. 사용자 승인: 예정 작업 순서대로 진행. 먼저 환경·장부의 주문 누락만 수정한다.

## 실행 계약

- 하루 환경의 유효한 외부 주문은 통지 시점에 전건 등록한다. 기존 PLANNED/WAITING 목록을 쓴다.
- 야드 적재 가능성은 실제 작업 때 검사한다. 기존 공간·크레인·공동 예약·이송 제약은 유지한다.
- 최초 입력 ID·블록·외생 진입시각·컨테이너·보상·정책·후보 설정은 고정한다.
- 과거 고정 재공량 투입은 별도 사용처가 있으므로 MultiBlockTerminal 기본 계약을 바꾸지 않는다.
  run_episode만 preserve_external_demand=True를 기본으로 쓰며 False는 과거 비교용이다.
- CargoTerminal의 기존 수요 보존은 유지한다. 새 재시도 주기·게이트 밖 지연·대기 보상은 추가하지 않는다.
- 안내/예약과 관측 사건을 구분한다. 예정 진입이 미래이면 관측 기록의 gate_in은 None이다.
- 분기는 터미널 속성과 대기 주문을 함께 복제한다. 이미 등록한 주문을 다시 등록하지 않는다.
- 배열 GPU 경로와 고정 재공량 경로는 이번 보정 범위 밖이다. 현재 판정·교사는 CPU 하루 경로다.

## 동결된 비교

- m 감사의 기존 3일 입력 3,500/7,500/15,000건, 시드 9913900/9913910/9913920을 재사용한다.
- 고전 규칙 7개×3일 21조건, 최신 flow 저장 모델 3개×3일 9조건.
- 최초 누락 입력(3,500건, 9913320)의 reference/optimized 2조건도 유지한다.
- 합계 32조건을 기존 방식/주문 보존 방식 양쪽으로 실행한다: 64회.
- flow 9913501·15,000건의 보존 방식을 한 번 더 재현한다: 총 65회.
- 기존 방식 32회는 m 원자료와 결과·후보·선택·사건·작업·기록을 정확 대조한다.
  결과 환경 표시에 추가한 preserve_external_demand만 제거한 뒤 과거 결과 해시를 대조한다.
- 전후 입력 해시·모델 해시가 같아야 한다. 재학습·모델 선택은 하지 않는다.
- 평가창 24시간과 엔진 종료 26시간 장부를 분리한다. 본선 완료 평가창의 부족을 유지한다.
- smoke: 별도 시드 9914509·80건. 최대 6 프로세스, 각 1스레드. 중간 결과에 따라 표본을 늘리지 않는다.

## 판정과 산출물

1. 모든 보존 조건에서 입력=등록, skip=0, ID 중복=0, 실제 진입시각 변경=0이어야 한다.
2. 각 시점의 입력=미진입+진입 후 미출차+출차를 전건 맞춘다. 미완료가 장부에서 사라지면 실패다.
3. 사건 순서·물리 불변식·야드 용량·반출의 실제 공간 확보 후 반입을 확인한다.
4. 비용·체류·미출차·야드 미완료·본선 잔여는 전후 모두 보고한다.
   분모가 늘었으므로 체류 평균 감소만으로 정책 개선을 주장하지 않는다.
5. 고전 규칙 대비 정책 채택은 기존 미통과를 유지한다. 본선 i·예약 f·교사 ab는 별도 후속이다.
6. 코드·사전등록을 커밋한 뒤 실행한다. 원자료·전체 조건·실행 커밋·해시·독립 재계산을 남긴다.
