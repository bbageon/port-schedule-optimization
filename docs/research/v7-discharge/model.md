# 양하 연결의 근거와 적용 범위

2026-11-05 · YR-332-h. 실행 계약: `shared-handover-wip-v1`.

## 문헌에서 가져온 것

Abouelrous, Dekker, Bliek, Zhang (2025), *Real-time policy for yard allocation of
transshipment containers in a terminal*, Transportation Research Part B 192, 103138.
[출판사](https://doi.org/10.1016/j.trb.2024.103138) ·
[저자 소속기관 원문](https://pure.tue.nl/ws/portalfiles/portal/351367343/1-s2.0-S0191261524002625-main.pdf).

논문은 운반 자원의 수, 주행시간, 야드 대기가 안벽크레인의 생산성에 미치는 연결을 다룬다.
야드에서 오래 기다린 차량은 안벽에 늦게 돌아오고, 받을 차량이 없으면 양하도 기다린다.
우리 적용의 근거는 이 **유한 자원과 지연 전달 관계**다. 논문의 성능 수치나 차량 대수를
우리 터미널의 보정값으로 옮기지 않는다.

논문 부록 F는 차량이 상자를 내려놓은 뒤 야드 최종 적재 전에 떠날 수 있음을 구분한다.
현재 엔진은 그 중간 시점이 없으므로 슬롯을 적재 완료까지 점유하는 집계 근사를 쓴다.
이는 인과 연결 복구이며 해당 논문 시뮬레이터의 동일 구현은 아니다.

## 코드에서 복구한 연결

기존에는 양하 상자가 야드에 도착하면 운반 자원이 다시 사용 가능해졌다.
그 후 야드 적재가 아무리 밀려도 본선에 지연이 전달되지 않았다.

새 기본 크레인 경로는 블록의 미완 양하 수를 제한한다.

    W(t) = 본선 인출을 마쳤지만 야드 적재를 마치지 않은 양하 상자 수
    W(t) < C 일 때 다음 본선 양하 가능
    본선 인출: W += 1
    야드 인계/도착: W 유지
    야드 적재 완료: W -= 1, 막힌 본선의 실행 가능 여부 재검사

`C`는 해당 실행 프로파일의 `transfer.n_units`다. 같은 블록의 여러 본선이 하나의
운반 자원을 쓰므로 **선박별 C가 아니라 합계 C**다. 다른 선박이 슬롯을 돌려줘도 재개한다.
같은 시각 여러 선박을 깨워도 각 사건이 다시 용량을 확인하므로 초과 점유하지 않는다.

기존 안벽 버퍼 조건도 함께 유지한다. 이송 중인 상자와 야드에서 기다리는 상자 모두
W에 포함되므로, 후보 개수를 제한하는 것과는 별개의 물리적 수용 제약이다.

## 수치와 시간의 한계

- 현재 실행의 `build_h21_profile()`은 **3대, 왕복 환산 470초**다.
- `vessel.py`의 `YT_PER_STREAM=6` 및 과거 설계 문서의 6대는 이 경로에 연결되지 않았다.
  새로운 숫자를 골라 결과를 유리하게 만들지 않고 현재 실행값 3을 따른다.
- 차량 대수·야드 서비스시간·왕복시간·버퍼 규모의 실자료 보정이 없으므로 외부타당성 미확정.
- 이송시간은 기존 왕복 환산 지연 그대로다. 출발→야드 도착→상자 인수→빈차 귀환을
  각각 추적하지 않는다. 전 과정을 세밀한 차량 물리 모델로 해석하면 안 된다.
- 기존 달성가능 본선 마감 계산은 새 병목을 모두 반영하지 않는다. 보정 전 마감 초과를
  정책의 실패라고 단정하면 안 된다.

## 적용 경로

- `stage.episode.run_episode` 기본 ON.
- `stage.month_run.run_month`의 크레인 경로 기본 ON.
- `discharge_backpressure=False`는 구 환경 대조이며 결과에 `legacy-off`로 기록된다.
- 분기 학습은 실제 세계의 deepcopy라 ON/OFF와 미완 양하 장부를 그대로 보존한다.
- 구 PPO 경로는 기본 OFF이고 명시적으로만 ON으로 바꿀 수 있다.
- GPU 배열 세계는 이 연결을 구현하지 않았다. CPU의 새 환경과 동등하다고 주장하지 않는다.
- v6 파일은 보존했다. v7 원본 복사 매니페스트도 보존하고 engine.py의 수정만 별도 등록했다.

## 비용과 정책

기존 `sts_wait_accum_s`가 늘면 기존 본선 비용 계산으로 전달된다. 보상 단가나 가중치는
이번에 바꾸지 않았다. 실제 선박 완료 지연을 중심으로 바꾸는 설계는 별도 작업이다.
현재 신경망의 9입력, 실작업 우선 규칙, 후보 12개 규칙은 유지된다.
따라서 이번 검증은 **환경 연결**이고 새로운 강화학습 정책의 성능 검증은 아니다.

재현 명령·숫자는 `outputs/reports/yr332_discharge_latency/report.md`를 참조한다.
