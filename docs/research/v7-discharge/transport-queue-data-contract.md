# 운반 흐름·대기 수를 보정하기 위해 필요한 정의

2026-11-18 · YR-332-i(운반 흐름 보정), YR-332-f(트럭 정보 현실화)의 자료 확인표.
현재 원자료의 경로는 확보돼 있다. 필요한 것은 아래 필드의 뜻과 일부 운반 사건 기록이다.
실제 자료는 합성 입력의 타당성을 확인하는 근거이며, 합성 실행을 실제 터미널 재생으로 부르지 않는다.

## 1. 먼저 문서나 짧은 답변으로 확인할 내용

| 질문 | 왜 필요한가 |
|---|---|
| `atw`는 안벽 인양 시작·완료, 야드 작업 시작·완료 중 어느 사건인가? | 양하·적하 시간을 같은 단계끼리 비교하기 위해 |
| `firstYardInTime`·`lastYardInTime`는 최초 반입·최근 위치 변경·운반 인수 중 무엇인가? | 장치 기간과 내부 운반 시간을 혼동하지 않기 위해 |
| 각 시간의 시간대·기록 단위·사건 발생 시각/서버 수신 시각 구분은? | 로그 시각으로 채운 값을 실제 도착으로 사용하지 않기 위해 |
| `blcWaitingCarCount`는 차량·트럭 방문·컨테이너 오더 중 무엇을 세는가? | 현재 모형의 작업 대기 오더 수와 단위를 맞추기 위해 |
| 블록 도착 전 이동 차량·작업 중 차량·해당 메시지의 본인 차량을 포함하는가? | 대기열에 들어오고 나가는 기준을 맞추기 위해 |
| 대상 블록 필드와 측정 시각은 무엇이며, 사건마다 갱신하는가? | 게이트 메시지의 시각과 대기 수의 관측 시각을 구분하기 위해 |
| `gateInTime`가 비고 `error=true`인 GateIn 메시지는 입장 거절·재처리·정상 입장 중 무엇인가? | 오류 응답을 실제 도착으로 잘못 세는 것을 막기 위해 |

블록 진입·작업 완료·출차만으로는 순수 대기를 재구성할 수 없다.
**작업 시작 시각**이 있어야 ‘블록 도착부터 작업 시작까지’의 대기 오더 수를 독립 검산할 수 있다.
공식 필드 정의가 확보되면 먼저 같은 정의로 원자료를 묶고 그다음 합성 입력과 비교한다.

## 2. 운반 보정에 필요한 최소 익명 기록

원본 차량번호나 컨테이너번호는 필요 없다. 동일 사건끼리 연결할 수 있는 익명 키면 된다.

| 구분 | 최소 항목 |
|---|---|
| 작업 연결 | 익명 작업 키, 양하/적하, 익명 안벽크레인 키, 블록 |
| 차량 연결 | 익명 운반차 키, 배정 시작·해제 시각, 전용/공동 배정 범위 |
| 운반 단계 | 적재 출발, 목적지 도착, 인수 시작·완료, 빈차 출발·복귀 시각 |
| 가용량 | 시각별 실제 투입 대수, 충전·정비·휴지 여부 |
| 인계 조건 | 직결 인계/분리 샤시/버퍼 여부와 용량, 차량이 풀려나는 사건 |

일부 단계만 제공된다면 관측되는 합계 구간만 검증한다. 관측하지 않은 단계를 임의로 나누지 않는다.
장비 보유량이나 안벽별 명목 배정 대수는 시간별 실제 가용량을 대신하지 못한다.

## 3. 지금 확정하면 안 되는 대응

| 원자료/공개 설명 | 현재 모형 | 판정 |
|---|---|---|
| DGT 공식 소개: 안벽크레인 1기당 운반차 5대 | H-21 합성 환경: 블록당 3대 | 배정 단위·터미널 구조가 달라 숫자 교체 불가 |
| 양하 `atw`→최초 야드 시각 중앙 13분 | 요청→화물 도착·차량 재사용 470초 | 사건 정의·편도/왕복·대기 포함 여부가 달라 대체 불가 |
| 적하 마지막 야드 시각→`atw` 중앙 24분 | 위와 같은 운반 점유 모형 | 순수 운반 주기로 해석 불가 |
| 블록 대기 차량 수 | 블록 도착 후 작업 시작 전 외부 트럭 **오더 수** | 집계 대상·시점 정의를 먼저 확인 |

따라서 현재 3대·470초는 명시된 합성 가정으로 유지한다. 이 문서는 그 값의 현실성을 승인하지 않는다.

## 4. 공개 근거와 한계

- [DGT 장비 소개](https://www.dgtbusan.com/DGT/terminal/equipment): 안벽별 운반차 배정과 블록 양측의 크레인 분리를 설명한다. 특정 날짜의 실제 운반 이력은 제공하지 않는다.
- [부산항만공사 ChainPortal 앱 매뉴얼](https://www.chainportal.co.kr/manual/download?filename=ChainPortal_APP_Manual.pdf) §4-1-3: 게이트 진입 후 인수도증에 해당 블록의 대기 차량과 시간 정보를 표시한다. 집계 대상·작업 중 포함 여부에 관한 세부 정의로는 부족하다.
- [재확인 결과](../../../outputs/reports/yr332_transport_queue_recheck/README.md): 원본 대조 수치와 미확인 사항.

이 문서는 자료 요청 초안이며 외부 기관에 발송하지 않았다.

## 5. 2026-11-20 재확인과 고물량 자료 범위

공식 앱 매뉴얼 PDF23쪽의 게이트 진입→상·하차 지표는 현재 시간 지표와 방향이 같다. 대기 집계 정의까지 확인된 것은 아니다.
[정보서비스 매뉴얼](https://www.chainportal.co.kr/manual/download?filename=Chainportal-TIS-Manual.pdf) PDF34~35쪽은
OpenAPI 사용 가이드와 신청·승인 절차를 설명한다. 기존 사용자 측 API 명세가 있다면 위 필드 정의 확인에 우선 사용한다.

고물량(YR-332-ap)은 추가로 **자료의 터미널 전체 포함률**, 날짜·시각·익명 방문 키·연결 오더·블록이 필요하다.
현재 확인된13일·27,395방문의 최대245방문/시간보다 붐비는 날을 포함해야 고물량 합성 가정을 확인할 수 있다.
누락·중복·오류 처리 규칙과 시간대도 함께 확인한다. 원자료를 직접 학습에 넣기 위한 요구가 아니라 합성 분포의 근거 확인이다.
