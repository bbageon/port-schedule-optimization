# 날짜별 변화를 갖는 합성 항만 학습 데이터 설계

2026-11-15 · YR-332-ao(날짜별 도착 모양·작업 비율 변동).
**상태: 문헌 검토와 설계 완료, 숫자 범위 산정·생성기 구현·새 학습은 미실행.**
현재 코드의 기본 입력과 기존 실험 결과를 변경하지 않는다.
근거는 [선행연구 대조](synthetic-demand-literature.md), 구현 작업 정본은
[ao 명세](../../../.claude/docs/dashboard-task-specs/YR-332-ao-day-shape-mix-variation.md)다.

## 1. 목표와 판단 범위

목표는 한 가지 하루를 기억하는 대신 여러 합성 운영 조건에서 작업 순서를 개선하는 것이다.
다양한 입력을 만드는 것, 그 입력이 목적에 맞는 것, 정책이 더 잘 배우는 것은 별도로 판정한다.
합성 조건에서의 효과를 실제 부산항 운영의 개선율이나 전역 최적성으로 확대하지 않는다.

기존 코드 `diurnal_arrivals`는 같은 곡선의 누적 확률을 나눈 칸 안에서 시각만 조금 바꾼다.
`hourly_arrivals` 역시 고정된 24개 비중을 사용한다. 시드가 달라도 하루 모양 자체는 거의 같다.
최근 입력은 `observed_visit_minutes`에서 관측 분당 방문 수를 재사용한다.
따라서 현재 전체 입력을 수식만으로 만든 독립 합성 입력이라고 부르지 않는다.

이미 본 13일 자료의 근거: 시간대 모양 차이는 고정 분포에서 생길 우연 변동의 중앙값 1.525배,
일별 반출 비율은 45.38~69.33%, 표준편차 6.73%p다. 전체 반출 비율은 53.7517%다.
같은 시각대 방문 **건수**의 변동 3.005배는 하루 총량 차이도 포함하므로 모양 변동 1.525배와 구분한다.
이 자료는 개발용이며 전체 터미널을 대표하는지는 확인되지 않았다.

## 2. 생성 순서와 단위

1. **하루 조건**을 뽑는다: 총 오더 수, 도착 모양, 반출 비율. 조건은 그 하루 동안 고정한다.
2. **운송 흐름과 방문**을 구성한다: 컨테이너의 공급·반출 관계, 차량에 묶인 작업, 예약 정보를 연결한다.
3. **실제 시각**을 만든다: 하루 곡선과 시간대 안 도착 과정으로 방문 시각을 뽑는다.
4. **입력 명세를 저장**한다: 조건, 시드, 오더·방문·컨테이너 연결, 생성기 버전과 해시를 남긴다.
5. 모든 정책에 같은 외생 입력을 넣고 작업 완료·다음 정차 도착은 시뮬레이션으로 결정한다.

위는 최종 입력 계약이다. 첫 구현은 기존 `build_stage`·방문 연결을 유지하고 **날짜별 모양만** 바꾼다.
현재 오더를 먼저 만든 뒤 방문으로 묶는 경로를 방문 우선 생성기로 동시에 교체하지 않는다.
시간대 비중을 방문 단위에서 정했다면 방문→오더 확장 뒤의 오더 비중도 별도로 검사한다.

## 3. 곡선의 형태

기존 오전·오후·작은 저녁 봉우리와 24시간 기저를 출발점으로 둔다.
시간 t는 시간 단위(0~24), 하루 총량은 N_d, φ는 정규분포 밀도다.

```text
g_d(t) = b_d / 24 + (1 - b_d) × Σ_k w_dk × φ(t; μ_dk, σ_dk)
p_d(t) = g_d(t) / ∫_0^24 g_d(u) du
λ_d(t) = N_d × p_d(t)                 # 시간당 기대 오더 수 또는 방문 수: 단위를 명시
Σ_k w_dk = 1, 0 ≤ b_d ≤ 1, σ_dk > 0
```

하루마다 중심 시각 μ, 집중 폭 σ, 봉우리 비중 w, 기저 b 중 사전 지정한 조건을 뽑는다.
처음부터 전부 독립적으로 흔들지 않는다. 작은 수의 설명 가능한 모양 변수로 시작하고,
자료가 뒷받침하는 상관을 보존하거나 조합별 별도 시험이라고 명시한다.
기저 0.38은 **22~06시 물량 38%가 아니다**. 실제 야간 비중은 곡선을 그 구간에서 적분해 계산한다.
점심 감소를 이 식이 표현하지 못하면 잔차를 공개하고, 입력 자료만으로 형태를 재검토한다.
정책이 이기는지를 보고 봉우리·감소항을 추가하지 않는다.

## 4. 변화 범위를 정하는 근거

| 항목 | 첫 실험 | 이후 범위를 정하는 방법 |
|---|---|---|
| 하루 총량 | 기존 3,500·7,500·15,000건을 별도 조건으로 유지 | 터미널 전체 자료가 없으므로 관측 일 총량을 그대로 이식하지 않음 |
| 피크 시각·폭·오전/오후 비중 | 날짜별 모양 축에서 변화 | 날짜별 정규화 시간대 분포에 같은 저차원 식을 맞추고 적합 오차·경계 부착 확인 |
| 야간 비중 | 모양의 일부로 관측·보고 | 기저 상수와 야간 적분을 구분하고 두 값의 대응을 검사 |
| 반출 비율 | 첫 모양 비교에서는 같은 값으로 고정 | 일별 비율과 표본 크기를 함께 사용해 우연 변동을 구분한 뒤 별도 축으로 추가 |
| 시간대 안 몰림 | 현재 방법을 고정 | 수식 기반 도착 과정으로 대체할 때는 별도 비교로 분리 |
| 여러 상자 방문·예약 오차·선박·서비스시간 | 현재 계약 고정 | 날짜 모양 효과와 함께 바꾸지 않음 |

변화 폭을 관행적인 ±10%로 정하지 않는다. 날짜별 적합값의 범위·중앙값·산포를 먼저 저장한다.
개발용 날짜를 하나씩 제외해 적합했을 때 범위가 얼마나 흔들리는지도 확인한다.
이는 작은 표본에서의 내부 진단이며, 이미 본 날짜를 미사용 검증 자료로 다시 부르지 않는다.
주말 4일만으로 정확한 주말 확률분포를 확정하지 않는다. 근거가 약하면 이름 있는 조건별 시험으로 남긴다.
관측 최소·최대가 미래의 절대 한계는 아니다. 그 밖은 별도 부담 시험이며 현실 대표 확률을 부여하지 않는다.
숫자와 분포 가족, 함께 뽑을 변수, 판정 허용치는 **정책 성능 실행 전에** 설정 파일로 동결한다.

## 5. 실측 통계의 활용과 공개 가능한 생성기

- **통계 보정 합성 경로**: 허용되는 집계 통계로 매개변수 범위를 산정하고 새 오더를 생성한다.
  논문에는 통계의 활용 범위와 합성한 물리·배치 부분을 명시한다. 원본 오더 재생은 필요하지 않다.
- **공개 근거 경로**: 공개 문헌·운영 자료와 명시적인 연구 가정만으로 설정을 정의한다.
  비공개 실제 날짜 벡터·분별 형판을 사용한 결과를 이 경로로 재명명하지 않는다.
  비공개 자료를 비교 검증에 썼다면 그 사용도 실제로 설명할 수 있는 범위를 지킨다.
- 각 매개변수에 `근거 유형 / 출처 / 단위 / 적용 범위 / 확정 또는 가정`을 기록한다.
  현재로서는 실제 통계 활용 사실도 공개할 수 없는지 확인되지 않았으므로 두 경로를 구분해 둔다.

## 6. 시간대 안 도착과 연결 제약

매일의 평균 곡선과 그 곡선에서 실제 도착을 뽑는 과정은 별개다.
고정 N개의 독립 난수를 누적분포의 역함수에 넣으면 조건부 도착 과정이다.
총량 자체도 무작위인 일반 포아송 과정이라고 부르지 않는다. 기존 `poisson` 옵션 역시 시간대 건수 고정 방식이다.
몇 분씩 몰리는 정도는 방문 수·분별 분산·연속 구간의 상관으로 검사한다.
몰림이 확인될 때만 시간대 안 강도가 변하는 수식 후보를 비교하고, 날짜 변화와 동시에 채택하지 않는다.

전건 예약 가정을 유지하되 예약 시각과 실제 도착은 구분한다. 접수·예약의 공개 시점 이후에만 정책에 보인다.
하루 전체 정답 도착표, 이후 작업 완료, 비공개 선박 실제 시각을 정책 입력으로 넘기지 않는다.
같은 트럭의 오더는 한 방문·차대 용량·정차 선후관계를 보존하며, 뒤 정차 도착은 앞 작업 완료에 의존한다.
반입→적하, 양하→반출의 연결은 초기 재고·기간 밖 작업까지 포함해 검사한다.
하루 안에서 반입=적하, 양하=반출을 강제로 맞추거나 네 종류를 각각 독립적으로 생성하지 않는다.
예상 완료시간을 외생 정답으로 넣지 않는다. 게이트 진입→작업 완료→게이트 진출을 따로 기록한다.

## 7. 한 축씩 비교하는 순서

0. **표현 검사**: 기존 수식 곡선·현재 고정 시간대 벡터·새 평균 곡선의 차이를 입력 통계만으로 확인한다.
   곡선 표현을 바꾼 효과와 날짜별 다양성의 효과를 섞지 않는다.
1. **모양 변화**: A는 평균 곡선 반복, B는 여러 하루 모양. 물량·작업 비율·방문 연결·시간대 안 방식은 같다.
   A의 곡선은 B의 **학습용 곡선 집합을 같은 가중치로 평균**해 만든다. 최종 평가 입력은 평균 계산에 쓰지 않는다.
   비선형 식에서는 평균 매개변수를 넣은 곡선이 평균 곡선과 다르므로 이를 구분한다.
2. **작업 비율 변화**: 1이 검증된 뒤 반출 비율 변화만 추가하고 시간대와의 관계도 확인한다.
3. **도착 과정 대체**: 원본 분별 형판을 제거한 공개 가능한 합성 경로는 별도 비교로 검사한다.
   ao의 날짜 모양 구현과 구분해 [ar](../../../.claude/docs/dashboard-task-specs/YR-332-ar-parametric-within-hour-arrivals.md)로 등록했다.

0~2는 ao, 시간대 안 방식의 기존 근거는 ak, 방문 제약은 al에 연결된다.
물량이 큰 조건의 관측 근거는 ap, 학습 표본·맞추기 진단은 323-d, 최종 평가 분리는 323-e가 맡는다.
새 도착 과정의 구현을 이 설계 완료나 과거 ak 완료에 포함해 보고하지 않는다.

## 8. 학습 데이터와 평가 데이터

- 학습: 고정한 조건 분포에서 새로운 하루를 생성한다. 새로운 시드와 새로운 모양을 각각 기록한다.
  대표 조건별 빈도는 사전 지정하고, 많은 반출·피크 조건만 성능을 보고 더 뽑지 않는다.
- 선택용 검증: 학습 전에 만든 입력을 고정하고 학습량·설정 선택에만 사용한다.
- 최종 평가: 선택에 사용하지 않은 시드 및 조건 조합을 미리 잠근다. 일반 범위와 범위 밖 부담 시험을 따로 집계한다.
  연속 운영에서는 연결된 방문·컨테이너·항차가 분할을 넘지 않도록 완전한 기간 단위로 분리한다.
- 하루 조건, 도착, 방문·작업 구성, 선박·재고, 정보 오차의 난수를 분리하고 입력 해시를 저장한다.
  A/B와 규칙 비교에는 가능한 외생 난수를 공유한다. 정책별로 달라지는 완료시각은 공유 입력으로 고정하지 않는다.
- 비교 학습은 같은 초기 가중치·같은 모델 수·같은 교사 질문 예산·같은 갱신 규칙으로 한다.
  버려진 질문과 실제 남은 비교 쌍이 다를 수 있으므로 시간·유효 쌍 수도 함께 보고한다.

**입력 다양성만 늘려서는 충분하지 않다.** aq는 모델당 86~105개 수집 쌍이며 실제 학습 분할은 더 작다.
후보 2개 이상인 결정 수, 유효 비용 차이, 유형별 쌍 수, 같은 자료를 맞추는 정도,
새 하루의 순위 정확도·운영 비용을 함께 본다. 기존 자료를 반복 읽은 횟수는 새 경험 수가 아니다.
라벨 수 증가와 최적화 반복 증가를 한 실험에서 함께 바꾸지 않는다.
필요 예산은 323-d의 개발용 학습 곡선으로 정하고 최종 평가를 열기 전에 동결한다.
하루 조건은 생성기 내부 값이다. 정책에 공개된 예약·현재 작업으로 알 수 없는 조건을 정답 정보로 넘기지 않는다.
같은 관측 상태에서 서로 다른 미래 때문에 교사 선호가 갈리는지도 검사한다. 다양성 확대가 학습 성공을 보장하지 않는다.

## 9. 타당성 검사와 판정

입력 단계: 총량·시간대 평균·날짜별 산포·유형 비중·야간 비중·몰림·방문 구성을 검사한다.
재현 단계: 같은 설정·시드의 입력 해시 일치, 분할 간 중복 없음, 모든 유형·재고·선후관계 보존을 검사한다.
물리 단계: 블록 도착은 게이트 시각으로 대체하지 않고 실제 블록 사건에서 잰다.
고정 규칙 단계: 한산/혼잡/과부하는 설정 N 이름이 아니라 대기·완료율·잔여 작업 증가로 확인한다.
재고·시간 선후관계 위반과 의도한 과부하를 구분한다. 과부하이거나 정책이 불리하다는 이유로 유효 입력을 버리지 않는다.
학습 단계: A/B를 같은 새 입력에서 비교하고 입력별 차이와 초기값별 차이를 함께 보고한다.
반입·반출은 게이트 진입→작업 완료, 본선은 기존 작업별 시작점·마감 정의를 명시한다.
트럭 평균뿐 아니라 유형별 시간, 본선 지연, 미완료·기간 밖 잔여, 비용을 함께 보고한다.
완료 오더만 골라 긴 미완료를 지우지 않는다. 입력 일/연속 시나리오와 초기값 단위로 불확실성을 계산한다.
관측 범위 밖 7,500·15,000건을 실제 하루 대표값으로 판정하지 않는다.
정책이 좋아진 결과로 생성기 타당성을 대신 증명하지 않는다. 운반·대기열(i/f) 미확정도 그대로 남는다.

## 10. 다음 구현의 완료 조건

매개변수 근거표·날짜별 적합 진단·동결 설정·생성기·입력 검사·고정 정책 민감도를 ao 증거로 남긴다.
처음에는 입력만 생성해 평균과 변화 폭이 목표대로인지 확인한다. 그 뒤 고정 정책으로 물리·혼잡 상태를 검사한다.
기본 경로를 보존하는 선택형 적용으로 시작하고, 실패한 조건·숫자 범위 변경 경위도 보존한다.
새 학습은 입력 검사와 학습 예산 진단 뒤 별도로 실행한다. 이 설계 문서는 학습 효과나 현실성 통과 증거가 아니다.
