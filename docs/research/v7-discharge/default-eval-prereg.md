# 기본 하루 환경 평가 속도 사전등록 — 2026-11-05

YR-332-l. 사용자 요청: 평가 속도 개선을 적용하고 기본 연구 환경에서 테스트.
학습 구조·보상·정보·후보 선택 범위·물리 설정은 변경하지 않는다. 새 학습은 하지 않는다.

## 범위와 기준

- 기존 하루 실행 `run_episode`, 21블록·42크레인, 관측 24시간·배수 2시간.
- 초기 적재율 기본 0.65, 트럭 3,500 / 7,500 / 15,000건, 본선 물량은 기존 시드 생성기.
- 입력 시드 9,913,320 / 9,913,330 / 9,913,340, 모델 초기값은 각각 입력 시드+2.
- 현재 v7에 호환되는 학습 체크포인트가 없어 고정 무작위 9입력 모델 3개를 사용한다.
  v4 8입력 망을 임의 변환하지 않는다. 학습 모델의 성능·일반성은 이번에 주장하지 않는다.
- 개별 신경망·전체 목록 탐색·계획 재사용 끔(reference)과 전체 개선(optimized)을 비교한다.
  공동 배정기 정렬키 재사용은 양쪽 공통이다. 개선 전 저장소 전체를 되돌리는 비교가 아니다.
- 후보 기본값 12와 필수 후보 초과 보존을 양쪽 유지한다. 전체 후보 제한 해제 시험은 아니다.
- 재배정·교사·학습 갱신 없음. 모델 가중치 해시가 실행 전후 같아야 한다.
- 3부하×3입력/모델×2계산방식 = 18회. 각 쌍의 순서는 시드로 섞는다.
- CPU 1스레드, 매 실행 별도 새 프로세스, 한 번에 한 실행. 다른 계산 시험을 겹치지 않는다.

## 계측과 동등성

- 후보 생성·점수 및 공동 안전 검사 시간: 결정마다 기록. 적용·해시 기록 시간은 제외한다.
- 전체 시간: 준비부터 최종 장부와 해시까지. 실행 시간은 준비·최종 해시를 제외하고 따로 기록한다.
- 두 전체 시간 모두 실행 중 관측·해시 기록 비용이 포함된다. 현장 통신·모델 로딩은 제외한다.
- OS 최대 실제 메모리: 파이썬·PyTorch·시뮬레이터·계측 버퍼를 포함하는 프로세스 전체 값.
- 결정 중앙값·95백분위(100번 중 느린 5번의 경계)·최대, 시간대별 분포·대기열·후보 수.
- 입력·모델·모든 후보 계획·선택·사건·완료 상태/시각·오더 기록·운영 비용 해시를 쌍별 대조한다.
- 작업 잔여·투입 거절·예외도 기록한다. 두 계산이 같다고 미완료를 성능 통과로 바꾸지 않는다.
- 후보/선택/결과가 다르면 중단하고 원인을 고친 후 재등록한다. 성능 우열로 해석하지 않는다.
- 작은 300건 실행은 연결 검사이며 본 성능 표본에 합치지 않는다.

## 해석

같은 입력에서 같은 계산 결과를 더 빨리 얻는지 확인한다. 속도 변화는 쌍별·부하별 모두 보고한다.
현장 허용 응답시간과 메모리 예산은 제공되지 않았으므로 절대적인 실시간 적합 판정을 하지 않는다.
시뮬레이터는 여러 블록을 순차 처리한다. 42개 장비의 동시 서버 요청 부하 시험으로 부르지 않는다.
양하 운반 용량·마감 현실 보정은 YR-332-i, 학습 여부는 YR-332-c의 별도 과제다.
일반 기본값은 개선 경로이며 reference/batch는 평가 전용 대조 설정이다.
