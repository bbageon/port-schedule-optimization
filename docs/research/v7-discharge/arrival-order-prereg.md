# 실제 도착순 대비 저장 모델 재평가 — 실행 전 고정 조건

2026-11-06, YR-332-u. 사용자 지시: “다시 그러면 학습 정책 테스트 해볼래?”
기존 최단작업 우선 비교에 도착순을 추가하는 제한된 진단이다. 재학습은 하지 않는다.

## 규칙

현재 실행 가능한 실작업 사이에서 다음 **이미 처리된 사건**의 시각으로 정렬한다.
외부 트럭은 `BLOCK_ARRIVAL`, 적하 등 내부 작업은 `JOB_RELEASED`, 양하는 `VESSEL_RELEASED`다.
동시각은 작업 ID순이다. 미래 실제 도착이나 통지 시각으로 실작업 순서를 정하지 않는다.
필수 작업·안전·공동 예약 제약은 기존과 같다. 준비 행동은 실작업보다 뒤이며 공개 통지순을 쓴다.
단일 터미널 전체의 전역 줄이 아니라, 해당 크레인의 실행 가능 후보 중 도착순이다.
현장 운영 자료로 확인한 특정 부산항 터미널 정책이라는 주장은 하지 않는다.

## 고정 조건

- 21블록·42크레인, 초기 적재율 0.65, 관측 24시간+추가 처리 2시간.
- 트럭 (물량, 입력 시드): (3500,9913900), (7500,9913910), (15000,9913920).
- 재배정 없음, 후보 제한 없음, 기존 물리·원화 네 항 비용·정보 범위 유지.
- 기존 계산 단축 켬(`decision_probe_shortcircuit=True`), 재취급 자리 재사용 끔.
- 모델 초기값 9913501/9913502/9913503. 초기 모델과 네 학습 방식의 마지막 저장본 전체 사용.
  방식은 pointwise/pairwise/coverage/flow, 각 3회 갱신이며 최고 성적 모델을 고르지 않는다.
- 새 프로세스·CPU 1스레드, 평가 최대 2개 동시 실행. 속도 성과는 판정하지 않는다.

## 새 실행 12회와 저장 자료 재사용

1. 도착순 세 입력 + 3500건 반복 1회 = 4회.
2. 기존 결과의 정확 재현 대조 8회:
   최단작업 우선 세 입력, initial/9913501/3500, pointwise/9913502/7500,
   pairwise/9913503/15000, coverage/9913501/7500, flow/9913503/15000.
3. 기존 평가 51개와 모델 15개의 해시를 전수 대조한다.
   과거 source manifest와 공통 소스를 비교해 새 규칙 추가 파일 외 변경이 없는지 확인한다.
4. 대조 8회에서 후보·선택·사건·작업·트럭 장부·결과 해시와 원래 수치가 모두 같아야
   기존 45개 모델 평가와 규칙 결과를 새 도착순 결과와 비교한다.
   불일치하면 재사용을 중지하고 원인을 기록한다.
5. 도착순 반복 1회도 같은 해시와 수치가 나와야 한다.

## 보고와 판정

- 같은 입력의 짝별 변화율을 낸 후 세 모델·세 물량에 같은 비중을 둔다. 물량별 결과도 표시한다.
- 트럭 체류시간, 비용 네 항, 투입/미투입, 24시간 미완료, 26시간 본선 완료를 함께 보고한다.
  본선 양하/적하 완료를 별도로 표시한다. 미완료 체류는 관측 종료까지이며 이후 대기는 포함하지 않는다.
- 기존 최단작업 우선 기준을 보존하고 도착순 기준을 추가한다. 합계 비용으로만 성공 판정하지 않는다.
  투입 감소·미완료 증가·본선 완료 감소를 각각 표시한다.
- 이전에 본 세 날짜의 진단이며 독립 확증 표본 추가가 아니다. 현장 단가·물리의 타당성도 미해소다.
- 새 실행 12회·기존 원자료 재사용·모델 재학습 없음이라는 범위를 명시한다.
- 기존 게이트 실행 결과를 보존한다. 최신 사용자 실행 지시에 따른 제한된 진단으로만 보고하고
  이전 현실성 미통과 및 최단작업 우선 대비 채택 미통과를 해제하지 않는다.
