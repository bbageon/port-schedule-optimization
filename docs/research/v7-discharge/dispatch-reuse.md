# 상태 목록·계획 재사용·일괄 평가 구현

2026-11-05 · YR-332-j. 계산을 줄이는 변경이며 입력 의미·보상·기본 후보 제한은 유지한다.

## 오더 상태 목록

`IndexedJobs`는 기존 jobs 사전과 같은 인터페이스를 제공하고 상태별 ID 집합을 유지한다.
삽입·삭제·취소·교체·블록 이동·직접 `job.status` 변경에도 목록을 갱신한다.
`PLANNED`, `WAITING`, `RELEASED`, `RUNNING`, `DONE`, `CANCELLED` 등 기존 상태를 따른다.
새로운 게이트 단계나 정책 입력을 만든 것은 아니다. 예정 정보의 가시성 검사도 유지한다.

현재 작업 후보는 WAITING/RELEASED 목록, 사전 준비 후보는 PLANNED 목록에서 찾는다.
완료 기록이 많아져도 현재 후보를 찾기 위해 완료 기록까지 훑지 않는다.
ID 정렬 순서를 보존한다. 삭제 후 다른 블록에 넣으며, 소유 중 ID 변경은 거절한다.
복제와 저장 복원 때는 새 사전에 상태 알림을 다시 연결하므로 분기 세계가 서로 영향을 주지 않는다.

## 작업 계획 재사용

각 시뮬레이터가 자기 캐시(이미 계산한 결과의 임시 저장소)를 갖는다. 프로세스 전역 교체는 없다.
후보 생성 시작 때 다음을 한 번 대조한다.

- 야드 컨테이너의 위치·규격·가용 여부와 적재 순서, 야드 형상.
- 해당 크레인의 위치·제원, 현재 예약된 적재 슬롯.
- 각 작업의 ID·유형·반출 대상·반입 규격, 후보가 가리키는 작업.

야드가 바뀌면 블록 전체, 크레인 위치가 바뀌면 해당 크레인의 계획을 무효화한다.
예약 슬롯 변경도 재계산한다. 아직 특정 스택만 갱신하는 세밀한 의존성 추적은 하지 않는다.
변경 확인은 현재 적재 상태를 한 번 훑는 보수적 방식이며 공짜가 아니다.

야드·크레인·예약이 같고 새 오더만 들어왔다면 기존 계획을 재사용한다.
계획의 시작 시각은 현재 시각으로 바꾸고 대기·마감·혼잡도·후보 우선순위는 다시 계산한다.
후보 생성 중 같은 조건의 적재 슬롯 탐색도 공유한다. 계획을 처음 만드는 경우에도 이 이득은 있다.
사용자 정의 위치 선택 함수는 시간·외부 상태 의존성을 알 수 없어 재사용하지 않는다.

완료·취소·삭제돼 더 이상 생성하지 않는 후보의 계획은 제거한다. 복제·저장에는 캐시를 승계하지 않는다.
최종 공동 배정의 계획 계산·충돌 검사와 실제 예약은 **캐시 밖의 기존 경로**를 실행한다.
동일 시뮬레이터를 여러 스레드가 동시에 수정하는 실행은 지원 범위가 아니다.

## 신경망 평가

결정마다 공통 정보 한 번, 서로 같은 입력 행 한 번을 계산한다.
모든 후보는 점수를 받는다. 1,024행씩 나눠도 후보를 버리지 않는다.
미래/실행 가능성 구분, 실작업 우선·필수 작업·강제 선택·충돌 해소 순서는 유지한다.
점수는 결정마다 새로 계산하므로 오래된 혼잡도의 점수를 재사용하지 않는다.
근접한 점수는 기존 개별 호출로 다시 계산한다. 부동소수 오차로 순서가 바뀌는 위험을 줄이는 장치이며,
모든 미래 모델에 대한 수학적 동등성 증명은 아니다. 같은 입력·행동의 실증 검사를 함께 수행한다.

## 비교 방법과 한계

기본 CandidateGenerator의 후보 상한은 그대로다. 진단은 비교 양쪽 모두 모든 후보를 포함하도록 설정한다.
현재 9입력 정책에서 계산 방식만 비교하며, 새 예정/현재 목록 인코더를 학습한 결과가 아니다.
처음 계산·같은 상태·신규 도착·취소·크레인 이동·야드 변경·예약 변경을 나눠 평가한다.
최초 계획이 필요한 경우와 이전 계산을 쓸 수 있는 경우를 섞어 하나의 운영 속도로 주장하지 않는다.
