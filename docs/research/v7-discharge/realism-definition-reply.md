# 운반·대기·고물량 정의 회신 항목

2026-11-21 · 기존 과제 YR-332-f/i/ap의 외부 근거 확인용. 외부 기관에 발송하지 않았다.
기존 명세서나 기록이 있다면 **파일 경로와 해당 절**만 알려줘도 된다. 모르는 항목은 ‘미확인’으로 남긴다.
비밀번호·인증 토큰·실제 차량번호는 필요 없다. 실자료는 합성 입력의 보정·타당성 확인에 사용한다.

## 1. 대기 수 — f

- `blcWaitingCarCount`의 단위: 차량 / 트럭 방문 / 컨테이너 오더 / 그 외:
- 포함 대상: 블록으로 이동 중인 차량 / 블록 도착 후 대기 / 작업 중 / 해당 응답을 받은 본인 차량:
- 기준 블록 필드와 값이 측정된 시각 필드, 갱신 주기:
- 작업 시작을 나타내는 필드나 사건 기록의 유무·위치:
- 정의의 출처: 문서 경로·페이지, 또는 제공처 설명의 날짜와 적용 터미널:

확인되면 먼저 같은 단위·같은 시각으로 대기열을 재구성한다. 정의만 맞는 것과 수치까지 맞는 것은 따로 판정한다.

## 2. 본선 시각과 내부 운반 — i

- `atw`의 정확한 사건: 안벽 작업 시작/완료, 야드 작업 시작/완료, 그 외:
- `firstYardInTime`·`lastYardInTime`의 사건, 시간대와 기록 정밀도:
- 익명 내부 운반차 ID별 배정·적재 출발·도착·인계·빈차 복귀 기록의 유무·위치:
- 시각별 실제 투입 대수 및 차량이 배정에서 해제되는 조건:
- 정의의 출처와 적용 터미널:

외부 트럭 ID를 내부 운반차 ID로 대체하지 않는다. 일부 합계 시간만 알면 그 구간까지만 보정한다.

## 3. 고물량 자료 — ap

- 현재13일 자료가 전체 터미널을 포함하는지, 특정 고객·차량·서비스 이용자만 포함하는지:
- 누락·오류·중복 제거 방식과 집계 시간대:
- 더 붐비는 날의 자료 위치와 기간. 필요한 최소 열은 시각·익명 방문 키·연결 오더 키·작업 종류·블록:
- 전체 일일 방문 수나 시간당 방문 수를 대조할 별도 집계의 유무·위치:

일일 컨테이너 건수와 트럭 방문 수는 구분한다. 현재 표본 최대245방문/시간은 처리용량 상한을 뜻하지 않는다.

## 회신 뒤 적용 순서

1. 출처·적용 터미널·시간대·집계 단위를 기록한다.

3. 같은 단위의 관측 범위를 만든 뒤 합성 입력과 비교한다.
4. 필요한 가정 한 축을 보정하고 환경 검증을 먼저 수행한다. 정의 확인만으로 재학습 성공이나 현장 개선을 선언하지 않는다.
