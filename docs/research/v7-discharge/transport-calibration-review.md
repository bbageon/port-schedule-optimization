# YR-332-i — 본선 운반 설정의 근거·단위 재검토

2026-11-08. aa 주문 보존 비교 중 선행 자료를 확인했다. 물리 설정·정책·보상 변경은 아직 없다.

## 결론

현재 **3대·470초를 실측 보정 완료값으로 사용할 근거는 확인되지 않았다**.
서로 다른 사건인 야드 도착·컨테이너 인수·차량 귀환이 한 시각에 묶여 있어 숫자 교체만으로
보정할 수 없다. 공개자료와 논문 원문으로 모형의 구조는 확인했지만 해당 터미널의 시간 분포는 없다.

## 11/08 보정 전 코드에서 확인한 것

| 항목 | 실제 실행 | 근거와 의미 |
|---|---|---|
| 운반 대수 | 블록마다 3 | `build_h21_profile`이 DGT 근사 프로파일의 값을 승계. HJNC의 블록별 실측 배치가 아님 |
| 운반 시간 | 470초 | `YT_ROUND_TRIP_S`. 과거 공급 병목 목표에 맞춘 설계값 |
| 시간 필드 정의 | 왕복 | `TransferFleetSpec.move_time_s` 주석 |
| 시간 필드 사용 | 요청+470에 화물 도착·차량 재사용 | `TransferFleet.request`·`engine._transfer_arrive`; 도착과 귀환을 따로 세지 않음 |
| 양하 제한 | 야드 최종 적재까지 블록 합계 3상자 | `_discharge_pipeline`과 `yard_handover_cap`; 차량을 개별 추적하는 계약은 아님 |
| 본선 마감 하한 | 운반시간/대수·안벽 작업 간격 | `phys_min_completion_s`; 새 양하 인계 대기 전체를 반영한 달성 가능 마감이 아님 |

470초의 과거 논리는 470/3=156.67초 공급 간격과 3600/27.5=130.91초 안벽 간격을 비교해
약 16.4% 유휴를 만드는 것이다. 유휴를 목표로 역산한 설계이며 직접 측정한 주행시간이 아니다.
더구나 `.claude/docs/references/본선-야드-병목-문헌.md`의 과거 0.84%는 **비용 비중**이고,
10~20%는 **생산성 손실** 주장이다. 분모가 달라 이 둘을 같은 보정 지표로 비교할 수 없다.

## 1차 자료 대조

### HJNC 공식 설명 — 2026-11-08 열람

[장비현황](https://www.hjnc.co.kr/terminal/equipment)은 야드트랙터 96대, 안벽크레인 12기,
야드크레인 42기, 21블록을 제시한다.
[운영시스템](https://www.hjnc.co.kr/terminal/operation)은 작업 상황에 따른 트랙터 공동 운용을 설명한다.
따라서 96/21이나 96/12를 각 블록·안벽의 실제 동시 가용 대수로 대입할 수 없다.
보유량·근무 투입량·현재 작업 배정량은 다른 값이다. H-21 합성 구조를 HJNC 재현으로 부르지 않는다.

### Abouelrous 외(2025) — 원문 확인

[원문](https://pure.tue.nl/ws/portalfiles/portal/351367343/1-s2.0-S0191261524002625-main.pdf),
Transportation Research Part B 192, 103138. DOI 10.1016/j.trb.2024.103138.

- §3은 안벽크레인별 전용 트럭을 가정한다. 터미널 공동 운용의 동일 모형이 아니다.
- §6.1은 실자료 없이 합성 입력을 만들었다고 명시한다. 운반 속도·시간은 이 실험의 가정이다.
- PDF 14쪽: 대칭 경로·333.3m/분, 편도 0.6~9분. 우리 470초를 검증한 값이 아니다.
- PDF 15쪽 표2~4: 안벽크레인별 트럭 7·8·9대를 비교한다. 블록당 3대와 적용 단위가 다르다.
- PDF 23쪽 부록 F: 양하 차량은 야드 작업 시작 0.5분 뒤 상자를 넘기고 떠날 수 있다.
  최종 적재까지 기다리는 이론식과 시뮬레이터가 다름을 각주8이 명시한다.
- 30초는 그 논문의 인계 가정이다. 모든 터미널의 관측된 고정 인계시간으로 승계하지 않는다.

### Stojaković·Twrdy(2021)

[원문](https://link.springer.com/article/10.1186/s12544-021-00482-6)은 작은 가상 터미널에서
장비 배치와 생산성을 비교한다. 특정 환경에서 얻은 트럭 대수의 최적값을 우리 블록에 옮기는
근거로 쓰지 않는다. 차량 대수만이 아니라 배치·운반·처리 능력의 결합을 봐야 한다.

## 보정에 필요한 계약과 현재 남은 정보

실측값을 적용할 경우 다음을 연결해야 한다.

1. 자원의 적용 단위: 안벽크레인 전용 / 블록 전용 / 공동 운용, 시각별 실제 투입 대수.
2. 시간의 구분: 적재 주행 → 야드 대기 → 상자 인수 → 빈차 귀환. 최종 적재는 별도 사건.
3. 인계 조건: 차량 직결 / 분리 샤시 / 버퍼 유무와 용량. 같은 대기식을 그대로 쓸 수 없다.
4. 본선 마감: 위 자원과 실제 물량으로 가능한 계획인지 확인. 관측창 밖 마감을 실패 0으로 세지 않는다.

사용자에게 위 자료의 파일 경로를 비동기로 요청했다. 답이 없다는 이유로 수치를 임의 확정하지 않는다.
자료가 없으면 현재 값은 명시된 합성 가정으로만 남으며, 현실성 통과나 실제 터미널 성능을 주장할 수 없다.
정책을 유리하게 만들기 위한 대수 확대·이동시간 단축은 하지 않는다.

## 11/09 양하 하한 보정

시간 관계를 실제 실행하니 1·2·3박스가 기존 계산 하한보다 먼저 본선 인출을 마쳤다.
양하 완료를 마지막 안벽 인출로 정의한 현재 엔진에서 평균 운반 간격을 처음부터 곱할 수 없다.
버퍼 상태를 받지 않는 하한 함수는 양하에 안벽 작업 간격의 필요조건만 쓰도록 고쳤다.
하한 이상의 계획이 달성 가능하다는 뜻은 아니며, 적하 추정식도 이번 수정으로 검증한 것이 아니다.

8회씩 전후의 실제 사건·완료·유휴가 같고, 같은 3개 하루 입력의 본선 계획 30건도 유지됐다.
운반 대수·시간·인계 모형의 실측 보정은 여전히 미확정이다.
