# 적정부하 보상의 보정·검증 계약

## 무엇이 확정됐고 무엇이 아직 비어 있나

| 항목 | 이번 결정 | 근거·한계 |
|---|---|---|
| 최종 목표 | 터미널 원화 비용 절감·서비스 유지 | 가동률 자체를 최대화하지 않음 |
| 보조 신호 | 크레인별 부하 편차 합의 잠재함수 차분 | 원래 할인 목적 유지, 학습 개선은 미검증 |
| 부하 기간 H | 최초 장부 진단 15분, 5·30분 감도 확인 | 연구 가정, 문헌 최적값 아님 |
| 크레인별 상한 | 아직 미보정 | 보편 70%·80%를 기본값으로 넣지 않음 |
| 허용 큐 대기 | 아직 미동결 | 문헌 예시의 2·5·10분은 설명용 |
| 신호 세기 η | 검산 1, 실행 미연결 | 학습 세기와 실제 금전 단가를 구분 |
| 기존 보상 설정 | S=1,000,000, γ=0.999, 60초 간격 | 부하 신호 외 축을 고정하기 위한 기준 |

따라서 **현재 v6 크레인당 최적 수용량을 측정했다는 주장은 할 수 없다.** 설계와
산정 방법은 수정됐고, 실행에 쓸 숫자는 장부·환경이 맞는지 확인한 뒤 정한다.

## 1. YR-331-a — 능력과 부하 장부부터 확인

- 목적: 같은 작업을 두 크레인에 중복 계산하지 않고, 본선이 쓰고 남은 능력과 수용 가능 분량을 측정한다.
- 착수 조건: 현 v6 실행 경로·원자료·게이트의 정합을 복구한다. 기존 GPU 30일 경로 미완성을
  가정으로 덮지 않는다. CPU 경로를 쓰면 명시하고 GPU 학습 결과로 부르지 않는다.
- 로그: 주문 ID/최초 요청/통지/재예약/배정/시작/완료, 원래·현재 블록, 고정/이동 가능 분류,
  추정 작업초·분담 합, 실제 서비스초, 유효 완료/빈 이동/재취급/본선/고장 시간.
- 능력은 고정 규칙의 별도 보정 실행에서 추정한다. 후보 정책의 느린 작업·WAIT로 능력이
  떨어져 보이고 그 덕에 상대 부하가 바뀌는 자기참조를 차단한다.
- 작업 종류별 평균과 분산, 도착 변동, 짝 크레인 간섭을 함께 저장한다. 원문의 서비스율과
  우리 엔진의 작업시간 정의가 같은지 먼저 대조한다.
- 기존 외생 도착 시각·작업 종류·본선·장치율·고장 구조를 유지한다. 희석/증가한 부하 셀은
  진단용임을 표시하고 원본 시드와 섞어 개선율을 내지 않는다.
- 최초 시험 격자는 능력 대비 입력 부하 `0.4, 0.55, 0.7, 0.8, 0.9, 1.0, 1.1`이다.
  이는 문헌 권고 대역이 아니라 한산함부터 과부하까지 보는 **미실행 진단 격자**다.
- 시드 목록·본선 일정·관측 기간·반복 수·허용 대기는 실행 전에 별도 사전등록한다.
  현 문서는 숫자가 비어 있는 성능 사전등록을 대신하지 않는다.

### 상한의 판정

가동률 최고점을 선택하지 않는다. 후보 상한마다 다음을 함께 본다.

1. 들어온 원래 요청 대비 유효 완료율과 미완료 작업 증가 추세. 이연·거절을 분모에서 삭제하지 않는다.
2. 평균 큐 대기, 전체 턴타임, 오래 기다린 트럭의 시간, 본선 지연과 잔여 작업.
3. 시간당 유효 완료량과 기존 네 항 비용. 반출·반입·본선 구성비도 함께 기록한다.
4. 서비스 조건을 만족하는 상한 안에서 비용이 낮은 범위를 선택하고 별도 입력으로 다시 확인한다.

고부하에서 처리량은 그대로인데 대기가 늘면 상한을 낮춘다. 한산한 조건의 가동률 부족은 실패가 아니다.
상한 보정과 H 선택은 **정책 학습 전에** 끝내며, 잠금 평가 자료로 다시 고르지 않는다.

## 2. YR-331-b — 보상 항 하나만 연결해 비교

- 선행: YR-331-a의 상한·작업량 계약, YR-328의 게이트 전 지연 장부 판정, 현재 연구 게이트.
- 비교: 기존 공유 비용 보상 대 같은 보상+부하 잠재함수 차분. 신경망·후보·시드·단가·
  할인율·수집 간격은 동일하다. 별도 critic, COMA, 모방 학습, 새로운 상태 특징을 동시에 넣지 않는다.
- η 후보는 보정 자료에서 미리 고정하고 선택용 자료와 평가용 자료를 나눈다.
  학습 중 보상 크기를 보고 η를 자동 조정하지 않는다. 가장 좋은 시드만 선택하지 않는다.
- BUY율은 목표가 아닌 진단이다. 제안/거절/수락/거래 확정/서비스 완료를 구분하고,
  수락 당시 양쪽 부하와 이후 실제 비용·본선·완료 여부를 연결해 저장한다.
- 대표 사례: 한쪽 과부하·한쪽 여유 / 모두 한산 / 모두 과부하 / 능력이 다른 두 대 /
  본선 의무가 큰 수신처 / 전혀 없는 신규 수요 / 거래 실패 / 반복 거래 / 창 끝 미완료.
- 변경 보상·기본 비용·보조 항·P·말단 P·전체 설정을 각각 저장해 합계를 다시 계산한다.

## 3. 채택·기각

원화 비용 감소와 작업 보존·완료·본선 기준을 모두 만족해야 채택한다.
P만 좋아지거나 거래가 늘어도 비용·서비스가 나빠지면 기각한다.
원래 비용이 누락된 채 이연으로 좋아진 결과도 기각한다.
정책 순위 보존 수학은 유한 표본의 학습 향상을 보장하지 않으므로 이 비교가 필요하다.

이번 YR-331은 위 시험을 **실행하지 않았다**. 결과를 보고 격자·허용치를 바꾸는 사후 선택을 피하려고
계약과 미결 입력을 분리했다. 수식 검산은 [design_checks.json](../../../outputs/reports/yr331_workload_reward/design_checks.json)에 한정된다.
