# v6 보상에서 100만원을 제거한 근거와 새 계산식

2026-09-28 · [YR-331-d](../../../.claude/docs/dashboard-task-specs/YR-331-d-reward-normalization.md)

**100만원 고정 기본값을 제거했다.** 별도 기준 운전에서 얻은 할인 누적 비용의 표준편차(변동 크기)로 나눈다.
기준 자료는 합성 시뮬레이션의 비용 기록이다. 실제 터미널의 지출 자료나 권장 비용 단가가 아니다.

## 1. 100만원은 어디서 왔나

- v5 최초 PPO(실행 경험으로 정책을 갱신하는 학습 방법) 구현 `5a9e8dd1`의 `ppo/runtime.py`에 `reward_scale_krw=1_000_000.0`이 들어 있다.
- v6 복사 `c06baafb`가 이 기본값을 이어받았다. 그 변경에는 100만원 산정식·인용·값 비교 시험이 없다.
- 앞선 v4의 `actors/nets.py`에도 `PHI_SCALE=1_000_000.0`이 있고, YR-218·YR-220 문서는 이를 **눈금**으로 설명한다.
- 확인한 코드·문서·공개 구현에서는 **항만 연구에서 100만원을 써야 한다는 근거를 찾지 못했다.**

따라서 100만원은 손해가 발생할 때 부과하는 벌금이나 크레인 한 대의 실제 비용이 아니었다.
`손해 100만원 → 보상 −1`로 바꾸는 숫자 단위였다. 단위 선택 자체가 잘못인 것은 아니지만,
공유 신경망의 가치 예측 오차와 부하 보조 신호의 상대 크기에 영향을 주므로 근거 없이 최선이라고 둘 수 없다.

채택한 근거는 **자료로 숫자의 크기를 맞추는 방법**이다. 자료를 미리 고정하는 선택은 이번 연구의 재현성 설계이며, 문헌의 항만 권고가 아니다.

## 3. 새 수식

`ΔC_t`는 직전 결정 경계부터 지금까지 비용 장부에 추가된 금액이다.
`d_t=γ^(Δt/60초)`, 기본 `γ=0.999`는 시간에 따라 먼 결과의 비중을 줄이는 기존 할인 설정이다.

```text
기준 운전에서: z_0 = 0
               z_t = d_t × z_(t−1) − ΔC_t
기준 눈금:     S_ref = std(z_t; 미리 정한 기준 구간)
학습 보상:     r_cost,t = −ΔC_t / S_ref
```

`std`는 모집단 표준편차다. 기준 구간의 평균은 이 통계를 계산하는 데만 쓰며 **각 보상에서 평균을 빼지 않는다**.
비용이 발생하면 비용 보상은 음수이고, 비용이 0이면 0이다. 큰 손해도 잘라내지 않는다.
원화 보고는 원래 비용 장부를 사용한다. 나눈 값에 S_ref를 곱하면 증가 비용이 복원된다.

보상 계산은 기존처럼 60초마다 한다. 1시간은 모은 기록으로 학습을 갱신하는 간격이며 새 보상 계산창이 아니다.

부하 보조 점수를 켰을 때만 다음을 더한다.

```text
r_train,t = r_cost,t + η × [d_t × P(s_next) − P(s_now)]
```

P는 크레인 부하 배분 점수이며 원화가 아니다. η=1은 여전히 실험 가정이다.
눈금을 바꾸면 같은 η의 상대 영향도 바뀌므로 이전 부하 보상 실험의 성능을 새 식의 성능으로 옮겨 적지 않는다.
기본 경로의 부하 보조 점수는 꺼져 있다.

## 4. 실행 전에 고정한 기준 자료와 측정 결과

- 사전등록 소스: `bfae72a3`; 기준 시드 9911000, 21블록·42크레인.
- 기존 보정용 고정 화물 입력을 그대로 사용했다. 하루 트럭 물량 3,500 / 5,000 / 7,500건.
- 규칙은 거래 유지(KEEP)와 SF-SPT(기존 크레인 작업순서 규칙); 학습 가중치 갱신 0회.
- 0~259,200초를 60초 간격으로 기록: 4,321개 경계. 첫날은 누적값 연결에 쓰고 둘째·셋째 날의 2,880개 값으로 계산한다.
- 마지막 2시간 비우기 구간은 눈금 추정에서 제외한다. 다른 정책의 평가 결과로 시드·구간을 선택하지 않는다.
- 주문 16,000건 전량 접수, 접수 누락 0건, 물리 제약 검사 통과. 이것은 전건 작업 완료나 운영 성능 통과를 뜻하지 않는다.

| 항목 | 이번 기준 자료에서 나온 값 |
|---|---:|
| S_ref | 37,620,956.31299437원 |
| 할인 누적값 평균 | −73,459,930.61766416원 |
| 추정 표본 | 2,880개 |
| 100만원의 증가 비용에 대한 새 비용 보상 | 약 −0.02658 |

즉, 코드에 **3,762만원을 새 상수로 박아 넣지 않는다**. 저장한 원자료에서 같은 식으로 계산한다.
기준 파일과 계산 구간은 학습 전에 고정한다. 학습 중에는 정책 행동 때문에 분모가 바뀌지 않는다.
할인율이나 시간 단위를 명시적으로 바꾸면 같은 기준 원자료에 그 설정을 적용해 다시 계산한다.
기준 자료가 잘못됐거나 분산이 0이면 실패로 중단한다. 100만원으로 되돌아가는 대체값은 없다.

## 5. 적용·호환성·검증 범위

- CPU 정책과 배열 학습 경로 모두 자료 기반 기본값을 사용한다. 원자료를 설치 패키지에도 포함한다.
- 보고서·체크포인트에는 사용 눈금, 할인율, 자료 해시(파일 동일성을 확인하는 지문), 소스 커밋을 남긴다.
- 과거 100만원 단위의 가치망을 새 단위로 조용히 이어 학습하지 못하게 거부한다. 과거 재현은 기록된 눈금을 명시해야 한다.
- 과거 YR-331-b 사전등록 파일로 새 기본값을 실행하는 것도 거부한다. 이전 원자료와 실패·미확정 판정은 보존한다.
- 직접 계산, 원↔천원 변환, 비용 복원, 큰 손해 무절단, 저장·재로딩, CPU·배열 일치와 기존 실행 회귀를 검사한다.
- 진단 시드 9900628의 7,500건/일 입력에서 첫 6시간 학습 갱신을 확인한다. 정책 성능 비교 실험은 아니다.

실행 결과와 파일 지문은 [검증 증거](../../../outputs/reports/yr331_reward_scale/)에 보존한다.
최종 관련 검사 91개 통과, 새 시드의 6시간 실행에서 학습 6회 갱신·가중치 변화·정확한 저장 복원을 확인했다. 설치 패키지의 기준 파일도 재계산을 통과했다.

## 6. 이번 변경으로 해결되지 않은 것

트럭·본선·빈 이동·재취급의 **비용 단가와 상대 가중치의 경제적 타당성은 별도 문제**다.
이번에는 비용 장부의 네 항을 동시에 바꾸지 않았다. 새 정규화가 그 단가들의 근거를 만들어 주지 않는다.
정책망이 더 잘 학습되는지, 총비용이 줄어드는지, 부하 상한이 안전한지는 아직 별도 검증이 필요하다.
