# 요청 보존 계약 보정과 검증 진행

2026-09-16. YR-317-g(요청 미투입 원인 보정). 사용자 승인: 후속 진행·필요시 학습·CPU 20개.

## 이번에 바꾼 것과 이유

기존 실행은 요청 명단이 같아도 통지 시점에 재고나 예약 여유가 부족하면 해당 트럭을 미투입으로 끝냈다.
선박 적하도 그날 시작에 재고를 선점하고, 부족한 만큼 원래 요청 물량을 줄였다.
이 구조에서는 정책별 실제 처리 부담이 달라져 비용 차이를 그대로 비교하기 어렵다.

| 기존 경로 | 별도 보정 모드 `PRESERVE` |
|---|---|
| 반출 대상이 모두 지정돼 있으면 요청 종료 | 원래 도착시각으로 접수하고 실제 도착 이후 가용 재고가 생기면 대상 지정 |
| 미래 예약을 차감한 여유가 부족하면 반입 요청 종료 | 요청과 대기 기록은 유지하고 실제 적재 때 기존 공간·장비 제약 검사 |
| 선박 적하가 하루 시작에 재고 선점·부족 물량 축소 | 원래 요청 수를 유지하고 실제 작업 해제 이후 가용 재고에 연결 |
| 요청이 미투입이면 현재 게이트 이후 비용에 없음 | 접수된 트럭은 원래 진입시각 이후 대기·미완료 비용에 남음 |

요청 접수와 실제 컨테이너 적재를 구분한 수정이다. 컨테이너를 새로 만들거나 공간을 늘리거나 반출을 반입으로 바꾸는 수정은 없다.
아직 가용 재고가 없는 작업은 기다리며, 끝나지 않으면 잔여로 보고한다. 이미 지정된 다른 작업의 컨테이너를 빼앗지 않는다.
기존 실행은 `LEGACY` 모드로 보존했다. 새 정책 입력·보상 가중치·예약 정원·외부 일정 변경 비용은 추가하지 않았다.

## 합성곡선 보존 확인

수정 코드 `2e4caef`로 기존의 **20개 독립 월 입력 전체를 재생성**해 비교했다.
**20개월·600일·4,038,000건의 입력 전체 지문이 이전 고정 입력과 정확히 같았다.**
도착시각뿐 아니라 물량·흐름·블록·초기 재고·예정 본선 작업까지 포함한 비교다.

이는 생성 입력이 같다는 뜻이다. 접수·대상 지정 시점을 고친 만큼 실제 운영 궤적과 비용은 달라질 수 있다.
기존 20개월 입력은 새 정책 성능을 고르기 위한 자료로 사용하지 않았다.

## 완료한 검사

- 기존 월·관측 코드 검사 39개, 새 요청 보존 검사 7개 통과. 이후 관련 요청·보고 검사 28개도 통과했다. 겹치는 검사가 있어 세 수를 합쳐 독립 검사 수로 세지 않는다.
- 실제 연결 검사: 세 정책 각각 트럭 300대·본선 작업 7,022건 전부 완료. 미투입·미추적·잔여 0, 비용 장부 대조 통과.
- 물리 적재·장비 간격·자원 예약 검사 활성화 및 작업 소유권 검사 유지.
- 학습 분기 연결 검사: 시드 9,900,700·300대, 분기 3시간·탐색 확률 0.37·라벨 예산 2건. 비교용 세계 6개, 사실 결정 일치 2건·불일치 0건.
- 학습 연결 검사에서 모형 가중치는 그대로였다. **라벨 생성 연결 확인이며 새 학습 완료가 아니다.**
- 최초 실행은 별도 체크아웃에 가중치 파일이 없어 시작 전 실패했다. 원래 가중치의 실제 경로로 다시 연결했고 첫 실패 기록을 보존했다.
- 최초 학습 연결 검사에서는 결과 저장 때 특징값의 텐서 형식을 JSON으로 바꾸지 못했다. 저장 형식만 수정하고 같은 고정 검사를 다시 수행해 통과했다.

## 현재 실행과 해석의 한계

- 9/16 08:06 KST, 실제 연결 검사 통과 후 **10일 본 진단**이 시작됐다.
- 시드 9,500,000의 같은 10일, 트럭 요청 69,000건·본선 요청 44,322건, 기존 최종 가중치를 유지한다.
- 정책은 배정 변경 없음·전체 모형·수락 거절 기능 제거의 세 가지다. 마지막 정책에도 구매 점수 정렬은 남아 있다.
- 각 정책 내부 날짜는 순차로 이어지고 세 정책만 병렬 실행한다. 본 진단은 CPU 0/1/2, 입력 대조는 3~19를 일시 사용했다. v5의 CPU 23은 유지했다.

- 접수 전건 보존과 실제 전건 완료는 다른 판정이다. 종료 시 트럭·본선 잔여를 별도로 검사한다.
- 대기 공간의 실측 정원은 없고 기존 합성 환경 범위다. 현장 실행 가능성·수평/수직 구조 검증을 이 결과로 주장하지 않는다.

## 후속 순서

1. **YR-317-g**: 같은 10일의 미투입·미완료·비용을 재검산하고 기존 실행과 비교한다. 비교표를 자동 생성하도록 분석기를 준비했다.
2. **YR-317-c·d**: 처리 계약의 검증 범위가 확인되면 후보 선택 검사와 독립 월별 비교에 연결한다. 비용 차이는 하루를 독립 표본으로 세지 않고 월 단위로 평가한다.
3. **필요한 재학습은 d에서 진행**: 사용자 승인은 확보됐다. 수정 환경에서 기존 모형의 결과와 학습 연결 검사를 근거로 조건·예산을 고정하고, 갱신 전/후를 같은 평가 입력으로 비교한다.

독립 입력 준비와 작은 연결 검사 성공만으로 연구 전체의 성능·현실성 검증을 완료 처리하지 않는다. 전체 개정 목표는 9/19 KST다.
