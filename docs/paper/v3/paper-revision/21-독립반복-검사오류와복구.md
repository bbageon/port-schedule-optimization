# 독립 반복의 기록 검사 오류와 복구

2026-09-17. 담당: [YR-317-d](../../../../.claude/docs/dashboard-task-specs/YR-317-d-v3-review-independent-confirmation.md).

## 실제 경과

- 공급 진단 세 조건은 03:10 KST에 종료했다. 입력 보존·요청 전건 접수·물리 연결·비용 기록 재검산이 통과했다.
- 독립 반복은 03:11 KST에 시작했다. 20시드×3정책 중 13개를 CPU 0~12에서 병렬 실행했다. 모델·시드·합성곡선은 고정했다.
- 07:25 KST, 시드 20,300,000의 기준정책이 첫 30일 실행을 완료했다. 비용·요청·가중치·물리 연결 검사는 통과했으나 별도 대기열 재검사에서 불일치가 나왔다.
- 감독기의 즉시 전체 종료 때문에 다른 12개도 중단됐다. 이들은 9~27일분을 기록했지만 엔진 중간 상태를 저장하지 않아 월 처음부터 재실행해야 한다.
- 완료된 1개와 미시작 47개, 중단된 12개의 이력을 모두 보존한다. 실패 은폐·시드 교체·성능에 따른 표본 제외는 하지 않는다.

## 원인

대기열 표본은 같은 시각의 작업 배정 직전에 기록한다. 예를 들어 300초에 표본을 남긴 직후 작업이 시작하면 그 트럭은 해당 표본에서 아직 대기 중이다.
기존 사후 검사는 최종 사건 장부의 `service_start <= t`를 모두 제외해 시작 직후의 대기열을 계산했다.
그 결과 41개 블록·시각 조합에서 실제 표본보다 적게 계산했다. 같은 시각에 시작한 트럭은 총 43대였다.

엔진의 검토→배정 순서와 맞게 도착은 `<= t`, 서비스 시작은 `< t`로 재검산한다.
동일 시각 경계만 정확히 처리하며 대기열 오차 허용치를 늘리거나 검사를 끄지 않는다.
실제 시뮬레이터·정책·비용·원자료는 수정하지 않는다.

## 복구와 검증

- 완료된 30일의 8,641개 시각 표본을 다시 검사해 불일치 0을 확인했다. 일별 비용·요청·턴타임·파일 지문 검사도 모두 통과했다.
- 작업 시작과 표본 시각이 같은 사례, 실제 대기열 오류를 계속 거부하는 사례, 한 실행 실패 때 다른 실행이 끝까지 저장되는 사례를 포함해 코드 검사 27개 통과.
- 기존 결과의 전체 실행 계약을 현재 모델·엔진 코드·설정·입력 지문과 대조해 동일함을 확인했다. 완료된 1개는 복사 후 전수 재검산해 재사용한다.
- 중단 12개와 미시작 47개, 총 59개는 새 출력 폴더에서 원래 월 입력으로 실행한다. 부분 날짜를 이어붙여 독립 월 결과로 만들지 않는다.
- 이후 개별 작업 실패 시 새 작업 투입을 멈추되 이미 실행 중인 다른 작업은 끝까지 저장한다. 모든 활성 작업이 종료된 뒤 실패 상태를 보고한다.
- 가중치·시드 목록·일 물량·합성곡선·비용식·정책 비교·최종 통계는 원래 사전 고정을 유지한다.

## 공급 진단의 해석은 별도

보정 기준정책의 미완료 트럭은 1,367대, 전체 모델은 5,086대다. 선박 야드 작업 잔여는 각각 2,556건과 4,307건이다.
물리 연결과 기록 검사가 맞는다는 뜻이지 전체 모델의 성능 또는 지속운영 가능성이 통과했다는 뜻은 아니다.
독립 반복에서도 비용과 미완료 작업을 함께 보고한다. 이번 검사기 오류와 정책 성능 문제를 구분한다.
