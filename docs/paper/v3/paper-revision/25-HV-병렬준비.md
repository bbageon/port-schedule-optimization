# 수평·수직 환경의 병렬 준비

작성: 2026-09-19. 관련 작업: [YR-317-h — 기본 배치 검증](../../../../.claude/docs/dashboard-task-specs/YR-317-h-v3-review-basic-layouts.md).

## 1. 이번에 확인한 범위

**환경 설계와 검증 준비는 병행할 수 있지만, 현재 V3에는 수평·수직 두 구조를 선택해 실행하는 기능이 없다.**
기존 환경은 두 크레인이 작업을 공유하고 블록을 한 축에 놓은 합성 환경이다. 실제 수평 도로망이나 수직 인계 구조를 검증한 상태가 아니다.
이번 작업은 코드와 기존 시험의 내용을 읽은 점검이다. 코드를 실행해 두 구조를 검증하거나 성능을 측정하지 않았다.
진행 중인 독립 평가, 입력, 모델, 실행기, 논문 원고는 변경하지 않았다.

근거 파일의 SHA-256(파일 내용 확인용 지문)과 줄 번호는 [소스 점검 기록](../../../../outputs/reports/yr317_v3_layout_readiness/source-audit.json)에 저장했다.
그 기록은 현재 작업 폴더의 정적 점검이며, 동결된 독립 평가 실행 소스와 같다는 추가 인증은 아니다.

## 2. 구현된 것과 빠진 것

| 항목 | 현재 구현 | 두 구조를 구별하려면 필요한 것 | 코드 근거 |
|---|---|---|---|
| 환경 선택 | 월 실행기가 공유형 프로파일과 기본 배치를 고정해서 생성 | 구조 계약을 명시적으로 전달하고 실행 기록에 남기기 | [month_run.py](../../../../src/yard_rl/v3/stage/month_run.py) 205·247줄; [month.py](../../../../src/yard_rl/v3/stage/month.py) 238줄 |

| 컨테이너 인계 | 반입·반출 모두 같은 `transfer_row`를 사용 | 작업 종류별 인계 위치와 그 위치까지의 크레인 이동을 계산 | [engine.py](../../../../src/yard_rl/v3/world/integrated/engine.py) 552·602·652줄; [models.py](../../../../src/yard_rl/v3/world/domain/models.py) 110줄 |

`YT`와 `AGV`는 현재 이송 모형에서 차량 종류 이름이다. `request`와 `dispatch_pending`에는 종류에 따른 동작 분기가 없다.
[프로파일 빌더](../../../../src/yard_rl/v3/world/integrated/profiles.py) 21·59·85줄도 두 근사 프로파일의 역할 분리 미지원과 동일한 이송 역학을 설명한다.
따라서 차량 이름이나 블록 이름만 바꾸어 새 구조를 검증했다고 할 수 없다.

`yt_round_trip_s()`는 [배치 코드](../../../../src/yard_rl/v3/world/integrated/yard_layout.py) 113줄에 있지만, 이번 V3 Python 소스 검색에서는 호출을 찾지 못했다.
확인한 월 실행 경로는 [환경 생성](../../../../src/yard_rl/v3/stage/episode.py) 49~55줄에서 프로파일을 넘기고, [엔진](../../../../src/yard_rl/v3/world/integrated/engine.py) 134~136줄에서 그 이송시간을 사용한다.
이는 정적 연결 확인이다. 새 배치의 거리 변경이 실제 이송 사건의 시간까지 바꾸는지는 아래 2단계에서 실행 검증해야 한다.

## 3. 기존 시험을 재사용할 수 있는 범위

- [구조 계약 시험](../../../../tests/integrated/test_structure_compiler.py) 39~47줄은 V3 바깥 코드의 수직 역할 분리를 **미지원**으로 판정한다. 구조 계약의 참고 자료다.
- [공개 토폴로지 시험](../../../../tests/unit/test_public_topology_profiles.py) 14·28줄은 설정 파일의 구조 정보를 검사한다. 엔진이 그 정보를 사용하는지는 검사하지 않는다.
- [V3 환경 등가 시험](../../../../tests/v3/test_world_equivalence.py) 99줄은 기존 공유형과 원본 엔진의 일치를 확인하는 시험이다. 수평·수직 차이를 입증하는 시험이 아니다.
- [V3 사본 시험](../../../../tests/v3/test_world_clone.py) 63줄은 원본과의 파일 일치 계약을 검사한다. 새 구조 구현 시 의도된 확장 범위를 문서와 시험에 함께 명시해야 한다.

이번에는 이 시험들을 실행하지 않았다. 시험 코드가 있다는 사실과 현재 검증을 통과했다는 주장을 구분한다.

## 4. 장시간 실행 전 통과할 검증 5단계

아래는 [기존 환경 정의](04-수평-수직환경-정의.md)를 구현하기 위한 순서다. **모든 단계가 아직 미실행**이다.
좌표·도로 폭·속도·인계시간·버퍼 정원은 이번 문서에서 새 숫자로 정하지 않는다. 출처와 합성 가정을 명시한 실행 계약을 먼저 동결한다.

| 단계 | 무엇을 확인하는가 | 통과 근거 |
|---|---|---|
| 1. 공통 입력과 구조 계약 | 합성 도착곡선·원요청·초기 재고·본선 작업·정책 설정을 공통으로 유지하고 구조에 따라 달라지는 항목만 구분 | 원요청 지문 일치, 구조 계약과 파생 경로 기록, 실행 소스·모델 지문. 구조별 경로 때문에 달라지는 도착 필드는 별도 표시 |
| 2. 경로와 인계 위치 | 같은 요청이 측면 인계와 육·해측 끝단 인계에서 의도한 경로를 이용하는지 확인 | 작은 고정 사례의 경로·이동시간 계산과 실제 사건 시각 일치. 이름 교체만으로는 차이가 생기지 않으며, 의도한 경로 변경은 실제 처리에 반영 |
| 3. 작업 허용과 도달 가능성 | 육측/해측 크레인이 허용된 작업만 맡고 필요한 재고에 도달하는지 확인 | 후보·배정·실행·재배정 검사 일치, 금지 작업 거부, 가능한 작업 처리. 구역을 반으로 나누어 접근 불가 재고를 만드는 방식은 통과 불가 |
| 4. 인계 대기와 물량 보존 | 인계 정원이 차면 대기가 발생하고, 필요한 크레인 간 인계가 이동·시간 없이 생략되지 않는지 확인 | 정원 초과 없음, 대기 발생·해제, 컨테이너 신원과 요청·재고·본선 장부 일치, 중복 처리·작업 유실 없음 |
| 5. 작은 통합 실행 | 앞 단계가 연결된 상태에서 양 구조의 요청 처리와 비용 기록이 맞는지 확인 | 공급이 확보된 시험 요청의 예상 완료, 잔여 작업과 대기의 원인 기록, 모델 지문 불변. 이 검증의 성능 수치를 월 단위 평가 결과로 사용하지 않음 |

기존 80개 독립 평가를 이 검증용으로 고치거나 재시작하지 않는다. 새 구현·출력·실행 계약을 분리한다.
현재는 설계와 검사 항목 정리가 가능한 단계다. 작은 실행도 구현과 해당 연구 게이트 판정 이후에 하며, 이번 문서는 새 실행을 시작했다는 기록이 아니다.

## 5. 학습과 성능 비교의 구분

**기존 모델을 고정한 재생**은 새 구조에서 기존 정책이 어떻게 행동하는지 보는 전이 진단이다. 구조별로 학습한 모델의 성능이나 학습 안정성을 입증하지 않는다.
**구조별 별도 학습**은 같은 알고리즘과 학습 예산을 적용한 뒤 각 구조 안에서 기준정책과 비교하는 별도 실험이다. [현재 h 명세](../../../../.claude/docs/dashboard-task-specs/YR-317-h-v3-review-basic-layouts.md)의 주비교 설계가 여기에 해당한다.
학습 초기값 반복과 평가 환경 시드 반복도 서로 다른 검증이다. 두 구조의 비용을 평균내어 한 구조의 손해를 가리지 않는다.

논문의 중심을 시간 조정으로 바꾸기로 결정한다면, 새 구조의 주요 비교를 **기준정책 대 Time-only** 두 정책으로 사전등록하는 안을 검토할 수 있다.
Full·Block-only를 추가할지는 공간 조정의 기여를 새 구조에서도 주장할지에 따라 정한다. 기존 확정 비교와 진행 중인 실행은 유지한다.
따라서 과거 설계의 `2구조 × 20시드 × 4정책 = 160개 실행`을 자동으로 시작하지 않는다. 연구 질문·정책 수·학습 여부·자원 예산을 확정한 뒤 별도로 등록한다.
본 문서는 그 변경을 확정하거나 승인한 문서가 아니다.

## 6. 리뷰 대응에서 말할 수 있는 범위

지금 말할 수 있는 것은 “두 기본 구조의 구현 차이와 검증 절차를 구체화했다”까지다.
역할·인계·경로를 함께 바꾸므로 이후 결과도 배치 방향 하나의 효과로 해석하지 않는다.
수평·수직 모두에서 개선됐다는 주장, 특정 실제 터미널 재현, 현장 실행 가능성은 아직 근거가 없다. 혼합 배치는 이번 범위에서 제외한다.

이번 산출물은 이 준비 문서와 소스 지문 기록 두 개다. 실행 가능한 두 구조·추가학습·구조별 성능표는 후속 검증의 산출물이다.
