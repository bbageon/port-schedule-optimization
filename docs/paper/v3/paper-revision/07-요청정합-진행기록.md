# 첫 후속 작업: 같은 요청을 비교하는지 확인

2026-09-15, YR-317-g(요청·본선 작업 기록 정합).
**세 정책의 요청 진단을 정리하고, 본선 완료·미투입 시점의 기록 공백을 보정했다. 작은 실제 실행으로 기존 결과를 바꾸지 않음도 확인했다.**

## 1. 진행한 이유

리뷰 1-1은 여러 독립 실행을, 1-4는 공간 조정과 수락망의 기여를 요구한다.
이 비교에 들어가기 전에 같은 요청량을 처리했는지 확인해야 한다. 작업이 빠져서 낮아진 비용을 정책 개선으로 해석하면 반복 실험도 잘못된 결론을 강화한다.
따라서 전략의 첫 순서인 요청 처리 정합을 먼저 진행했다. 이 작업이 전체 후보 순위나 독립 반복 실험을 대신하는 것은 아니다.

## 2. 기존 10일 진단에서 확인한 것

앞선 보고에는 비용 표를 빠뜨렸다. 아래는 완료된 실행의 관측 비용이며, [전체 성능표](08-성능비교표.md)에 비용 항목별 분해·기존 논문 28일 결과·재계산 근거를 함께 정리했다.

| 정책 | 총비용(억 원) | 배정 변경 없음 대비 절감률 |
|---|---:|---:|
| 배정 변경 없음 | 46.533 | 기준 |
| 전체 모형 | 38.494 | 17.28% |
| 수락 거절 기능 제거 | 39.432 | 15.26% |

전체 모형은 거절 기능 제거보다 기록된 비용이 0.938억 원(2.38%) 낮았다. 다만 아래와 같이 처리된 물량이 달라 수락 기능만의 효과로 확정하지 않는다.
이는 재사용한 시드 한 번의 10일 진단이다. 기존 논문의 28일·14.72%와 다른 비교이며, 추가학습에 따른 개선으로 해석하지 않는다.

| 정책 | 요청 트럭 | 완료 | 미투입 | 요청보다 줄어든 본선 투입 작업 |
|---|---:|---:|---:|---:|
| 배정 변경 없음 | 69,000 | 68,830 | 170 | 928 |
| 전체 모형 | 69,000 | 68,820 | 180 | 1,027 |
| 수락 거절 제거 | 69,000 | 68,864 | 136 | 1,055 |

요청 기록의 합계는 맞지만 실제 처리 대상으로 들어간 작업량은 다르다. 이 상태로 비용 절감의 우위를 확정하지 않는다.
코드에서 반출 대상이 없으면 트럭 요청을 미투입으로 끝내고, 본선 적하는 재고가 부족하면 요청량을 줄여 생성하는 경로를 확인했다.
용량 검사에 쓰는 여유는 실제 빈 공간에서 미도착 작업·예약량을 뺀 값이다. 음수라는 이유만으로 물리적 과적이라고 단정할 수 없다.

## 3. 바꾼 부분

- 미투입 순간의 실제 재고, 이미 지정된 재고, 미지정 재고와 예약량을 구분해 남긴다.
- 본선 투입이 완전히 실패해도 원래 요청한 작업 수가 사라지지 않게 기록한다.
- 완료된 본선 작업을 일별 메모리 정리 전에 보존하고, 요청·투입·완료·잔여·미추적 수를 대조한다.
- 안벽 크레인 완료와 야드 연계 작업 완료를 구분한다.

이 보정은 관측 기록에 한정한다. 정책의 판단이나 기존 미투입 처리 규칙을 바꾸지 않았으므로, 미투입 자체의 해결 여부는 별도 확인이 필요하다.

## 4. 실제 검증 결과

관련 검사 46개를 통과한 뒤 같은 동결 정책·시드의 300대 실행에서 새 기록 기능을 끈 경우와 켠 경우를 비교했다.
두 실행 모두 300대가 완료됐고, 비용·행동·요청별 사건·기존 본선 투입 결과가 정확히 같았다.
기록 기능을 켠 실행에서는 본선 14개 묶음의 작업 7,022회가 요청·투입·완료로 모두 맞았고 잔여·미추적 작업은 0이었다.

의미: 새 관측 도구가 기존 결과를 바꾸지 않으면서 본선 작업 완료까지 추적할 수 있음을 확인했다.
이 작은 실행에서 기존 10일 미투입 문제가 해결됐거나, 정책 성능이 좋아졌다고 판단한 것은 아니다. 추가학습도 수행하지 않았다.

## 5. 다음 순서

YR-317-g에서 기존 실패 시점의 재고·예약 구성과 본선 완료를 새 기록으로 확인하는 작업이 남는다.
같은 요청을 비교할 수 있는 조건을 확인한 뒤 YR-317-c(후보 선택 검증), YR-317-d(독립 반복 평가)로 이어간다.
수평·수직 환경은 YR-317-h의 별도 구조 검증이며 이번 실행에는 포함하지 않았다.
