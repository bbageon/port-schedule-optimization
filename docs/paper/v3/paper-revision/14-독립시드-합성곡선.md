# 독립 시드 입력 구성 — 기존 합성곡선 유지

2026-09-16, YR-317-d1(독립 평가에 사용할 입력 준비).
**기존 생성기로 20개 시드 × 30일 = 600일, 트럭 요청 4,038,000건을 생성·고정했다.**
이는 입력 구성 결과다. 정책 시뮬레이션·추가학습·새 절감률 계산은 이번에 실행하지 않았다.

## 유지한 조건

| 항목 | 기존 규칙과 이번 구성 |
|---|---|
| 하루 도착곡선 | 24시간 균등 성분 38% + 기존 세 봉우리 성분 62% |
| 봉우리 중심 | 10시 / 15시 / 21시 |
| 봉우리 폭 | 표준편차 1.5 / 2.5 / 1시간 |
| 세 봉우리 내부 비중 | 31.7% / 63.3% / 5.0% |
| 도착시각 추출 | 기존 60초 간격 누적분포에서 구간별로 추출, 밀리초 반올림 유지 |
| 하루 물량 | 3,500 / 5,000 / 7,500 / 12,500 / 15,000건 |
| 위 물량의 추첨 확률 | 30% / 30% / 25% / 10% / 5% |
| 월 내부 상태 | 30일 연속 운영, 날짜가 바뀌어도 초기화하지 않는 계약 |
| 월 사이 상태 | 각 월의 새 초기 재고·작업 계획으로 시작하는 계약 |
| 비용·정책·투입 규칙 | 이번 입력 구성에서 변경 없음 |

38%는 하루 전체에 깔린 균등 성분이며, 밤에만 도착하는 비율을 뜻하지 않는다.
곡선 모양과 물량 추첨 규칙을 보존하면서 날짜별 물량·세부 도착시각·배정·초기 재고를 새 시드로 생성했다.
기존 실제 월 실행의 초기 장치율 0.45도 유지했다. 원고 표의 0.65와 차이가 있어 개정에서 실행 조건과 맞춰야 한다.

## 독립성과 정책 간 공정한 비교

- 월 시드는 20,000,000부터 21,900,000까지 100,000 간격으로 사전에 정했다.
- 월 시드뿐 아니라 날짜·블록 초기화에 파생되는 난수 번호도 다른 월 및 기존 기록과 겹치지 않게 검사했다.
- 기존 기록의 시드 93개와 그 파생 범위를 대조했다. 날짜 시드 600개는 모두 다르다.
- 같은 월을 비교하는 모든 정책에는 동일한 요청·초기 재고·예정 본선 작업을 제공해야 한다. 파일별 지문으로 연결을 확인할 수 있다.
- 월의 마지막 상태를 다음 시드로 넘기면 독립 반복이 아니므로, 후속 실행기는 매번 새 엔진을 만들어야 한다.
- 결과가 좋거나 혼잡이 적은 시드만 고르지 않았다. 20개 모두 보존했다.
- 후속 평가의 통계 단위는 **하루가 아니라 독립 월 1회**다. 각 월의 가운데 28일 비용을 합산해 정책 간 차이를 비교한다.
- 최종 정책 수·평가 월 수·통계 규칙은 YR-317-d에서 성능을 보기 전에 고정한다. 예산상 일부만 쓰면 고정 명단의 앞 N개처럼 결과와 무관한 선택 규칙을 쓴다.

## 검증과 해석 범위

- 의미 있는 변경·오염을 탐지하는 검사 14개를 통과했다: 시드 중복, 도착시각 변경, 곡선 설정 변경, 월 길이, 파일 손상 등.
- 600일 모두 생성 결과의 도착시각을 기존 `diurnal_arrivals` 함수 결과와 전수 대조했다.
- 20개 월의 요청·초기 상태 지문은 각각 다르며, 저장 후 다시 읽어도 입력 전체가 같다.
- 첫 번째 고정 시드의 월을 한 번 더 생성해 입력 전체 지문이 같음을 확인했다.
- 고정 코드 `3292645`의 별도 깨끗한 실행 폴더에서 CPU 14개로 생성했다. 생성·원래 검증·첫 월 재생성에 약 58초가 걸렸다. **정책의 온라인 처리시간이나 30일 시뮬레이션 시간은 아니다.**
- 저장 파일에서 요청 수·날짜별 시간대 집계·구성 요소 지문 등을 독립 재검산해 13개 항목을 통과했다. 검증 결과는 아래 파일에 보존한다.
- 첫 별도 감사에서는 물량 설정에 포함된 이름 열을 예상 형식에서 빠뜨려 1개 항목이 실패했다. 감사의 형식 비교만 수정했고 첫 실패 기록·생성 입력은 보존했다.
- 기존 생성기의 반출→반입 대체가 106,657건(전체 요청의 약 2.64%) 발생했다. 초기 생성용 반출 대상 부족 때의 기존 동작으로, 원래 희망 흐름과 대체 이유도 그대로 저장했다.
- 이 대체는 [기존 실행 중 미투입](13-재관측-종료결과.md)과 다른 단계다. 입력 파일 생성 성공이 모든 요청의 실제 처리 가능성을 뜻하지 않는다.
- **입력·기록의 일치만 이번 완료 범위다. 성능 개선은 미확정이며 전체 요청 처리·물리 타당성은 별도 검증이 남는다.**
