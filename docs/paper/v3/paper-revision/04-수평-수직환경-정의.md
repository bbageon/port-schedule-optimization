# 수평·수직 두 기본 환경과 운영 상황의 정의

대상: 리뷰 2와 리뷰 1-5. **배치가 달라도 효과가 나타나는지를 보되, 혼합 배치와 실제 특정 터미널의 재현은 이번 검증 범위에서 제외한다.**
이 문서는 환경 정의와 검증 전략이다. 두 환경의 구현·새 학습·평가는 아직 수행하지 않았다.

## 1. 현재 환경을 먼저 정확히 부르기

원고 §4는 합성 21블록 환경을 설명하지만 안벽에 대한 블록 장축 방향과 인계 지점으로 수직 환경을 정의하지 않는다.
현재 [yard_layout.py](../../../../src/yard_rl/v3/world/integrated/yard_layout.py)는 블록 중심을 한 축에 놓고 게이트와 안벽을 반대 끝에 둔다.
코드 주석에는 수평 배치라는 표현이 있으나, 2차원 블록 방향·도로·측면/양끝 인계 구조를 모두 표현한 모델은 아니다.
이 파일의 마지막 변경은 원고보다 앞선 2026-08-22의 `38d0d3a`다.

21개 블록에 대해 게이트 이동시간은 190~410초, 안벽 이동시간은 반대 순서다. 블록 간 이동도 한 축의 거리 차로 계산한다.
이것만으로 기존 실험을 “수직 배치에서 검증 완료” 또는 “실제 수평 터미널을 재현”했다고 부르기는 어렵다.
개정에서는 기존 환경을 **단일 축으로 단순화한 기준 환경**으로 설명하고, 새 두 구조의 차이를 별도 명세로 만든다.

## 2. 문헌의 기본 구분

안벽을 기준으로 블록의 긴 방향이 나란하면 수평·평행 배치, 직각이면 수직 배치로 정의한다.
문헌의 대표 구조는 평행 배치에서 블록 측면의 인계, 수직 배치에서 육측·해측 끝의 인계를 구분한다. [Budiyanto 등, 2021](https://www.nature.com/articles/s41598-021-84958-4).
그 논문의 서로 다른 터미널 비교 결과를 우리 환경의 비용 효과나 부산항 성능으로 옮겨 쓰지 않고 구조 정의의 근거로만 사용한다.

아래 자원 공유 방식은 두 이상화된 운영 구조를 비교하기 위한 연구 정의다. 모든 수평·수직 터미널이 반드시 이 방식이라는 뜻은 아니다.
저장소의 [2026-08-06 두 합성 구조 결정](../../../../.claude/docs/strategy-history/2026-08-06-H21-V21-두-합성구조-고정.md)의 공유형/역할분리형 구분을 참고한다.
그 이전 실험의 성능·정책·수요 숫자를 v3 결과로 가져오지는 않는다.

## 3. 비교할 두 기본 구조

| 항목 | 수평·평행 공유형 | 수직 역할분리형 |
|---|---|---|
| 블록 장축 | 안벽과 평행 | 안벽과 직각 |
| 외부 트럭 인계 | 블록 측면 도로의 지정 인계점 | 블록의 육측 끝 인계점 |
| 본선 연계 인계 | 측면의 지정 인계점·접근 경로 | 블록의 해측 끝 인계점 |
| 블록당 크레인 2대 | 외부 트럭·본선 연계 작업을 공유 | 육측/해측 역할과 허용 작업을 구분 |
| 주요 경쟁 | 같은 크레인·인계 자원의 작업 경쟁 | 역할별 처리 여력과 공유 적재 공간·연결 작업의 영향 |
| 도로 표현 | 게이트·안벽에서 측면 인계점으로 연결 | 게이트에서 육측, 안벽에서 해측으로 연결 |

수직형에서 내부 이동·크레인 간 인계가 필요하면 그 서비스와 대기를 명시적으로 반영한다. 서로 다른 역할의 작업을 즉시 넘겨 처리한 것처럼 생략하지 않는다.
YT(터미널 내부 운반차량)·AGV(자동 운반차량)의 실제 기술 성능 비교는 추가하지 않는다. v3의 운반 자원 추상화로 표현할 수 있는 범위를 먼저 확인한다.
표의 변경은 방향·인계·역할의 구조 묶음이다. 결과를 **블록을 90도 돌린 방향 하나의 인과효과**로 주장하지 않는다.

## 4. 공정 비교를 위한 환경 계약

- 공통 자원은 21블록, 블록당 크레인 2대와 1,440칸 용량으로 둔다. 초기 재고·요청 목록·컨테이너 속성·본선 계획은 같은 원본에서 생성한다.
- 정책이 보는 정보, 합법 행동의 의미, 비용 계수, 검토 주기, 라벨 관찰 길이, 평가 기간은 동일하게 둔다.
- 수직형의 역할 제한과 두 환경의 인계 자원 제약은 실제 처리 후보와 사건 순서에 영향을 주어야 한다.
- 한쪽에서 요청을 조용히 미투입하거나 본선 작업을 덜 생성해 비용을 줄이지 않도록 요청·완료·실패·잔여 작업을 대조한다.
- 실제 블록 길이·폭·차로 자료가 없으면 문헌 기반 합성 값임을 명시하고 좌표·도로 폭·속도·인계 시간을 성능을 보기 전에 고정한다.
- 두 배치의 블록 수·적재면적·자원 수를 맞추고 도로를 포함한 부지 크기와 경로 길이의 차이는 표에 공개한다.
- 각 배치에서 유리한 결과가 나오도록 이동시간을 사후 조정하지 않는다. 기존 190~410초에 맞춰 새 경로 효과를 강제로 지우지도 않는다.

실행 명세에 필요한 필드는 블록 `x,y`, 장축 방향, 길이·폭, 게이트·안벽·인계점 좌표, 연결 도로와 방향, 이동 속도, 공유 자원·대기 위치다.
블록 간 이동시간은 유효한 도로 경로로 계산한다. 단순히 환경 이름만 바꾸거나 게이트·안벽까지 함께 회전해 동일 거리표를 만들지 않는다.
구체적인 좌표·서비스 수치는 구현 작업에서 출처와 함께 동결할 값이며, 이번 문헌 검토에서 실측값을 확보했다고 간주하지 않는다.

## 5. 비교 실행 순서

1. [YR-317-h](../../../../.claude/docs/dashboard-task-specs/YR-317-h-v3-review-basic-layouts.md)에서 두 환경의 경로·인계·작업 허용을 명세화한다.
2. 같은 시험 요청을 넣어 이동 경로, 크레인 후보, 인계 대기가 의도대로 달라지는지 검증한다. 전체 요청·재고 장부와 완주도 확인한다.
3. 각 구조에 **같은 코드와 학습 예산으로 별도 가중치**를 학습한다. 기존 가중치를 새 구조에서 재생하는 경우는 전이 진단으로 별도 보고한다.
4. 각 구조 안에서 변경 없음/전체/시간만/공간만의 4정책을 같은 독립 월 20개로 비교하는 안을 기본으로 둔다.
5. 구조별 전체 대 시간만과 전체 대 변경 없음의 비용 차이를 보고한다. 두 구조의 원비용을 평균내어 한쪽 실패를 가리지 않는다.
6. 고정 모형의 평가 시드 반복과 학습 초기값 반복을 구별한다. 학습 안정성을 주장하려면 각 구조의 독립 학습 반복도 별도 설계한다.

두 새 구조를 모두 검증하면 평가만 **2구조 × 20개월 × 4정책 = 160개 정책-월**이다. 학습 비용은 별도다.
기존 단일 축 환경의 160개 구성요소 비교와 자동으로 같은 실험이라고 간주하지 않는다. 하나가 새 구조와 같은 계약임이 입증되면 공통 실행만 재사용한다.
수락망 추가 비교는 우선 기준 환경에서 수행하고 두 구조 모두의 필수 비교를 무조건 8정책으로 늘리지 않는다.

## 6. 리뷰의 “다른 상황”을 어떻게 해석하는가

리뷰 2는 합성 환경과 단일 30일 실행을 지적한다. 리뷰 1-5는 수요 패턴·비용 가정·시뮬레이션 길이를 구체적으로 요구한다.
따라서 “시각만 오전에서 오후로 바꾸라”는 해석은 좁다. 다음 질문들을 구별해 답한다.

| 상황의 차이 | 실제로 바꾸는 것 | 무엇을 알 수 있는가 |
|---|---|---|
| 공간 구조 | 수평/수직 인계·경로·자원 공유 | 특정 운영 구조에만 유리한가 |
| 물량과 빈도 | 낮은/높은 하루 물량, 혼잡일 수 | 어느 부하에서 공간·시간이 도움이 되는가 |
| 혼잡의 이어짐 | 같은 혼잡일 수를 분산/연속 배치 | 전날 잔여 작업의 영향에 견디는가 |
| 일중 도착 모양 | 같은 하루 총량에서 도착 집중 폭 | 피크 모양이 달라져도 결과가 유지되는가 |
| 운영 길이 | 연속 30일/90일 | 비용·잔여 작업을 끝난 뒤로 미루는 효과인가 |

주 검증은 기본 구조 두 개와 독립 반복, 기존 부하 분해다. 추가 상황은 [민감도 계획](01-독립반복-부하별효과.md)의 한 축 비교로 수행한다.
혼합 배치·특정 실항만의 디지털 복제·모든 장비 유형을 포함한다는 주장은 하지 않는다.

## 7. 원고 범위 문안

> The planned validation covers two idealized operational structures: a parallel layout with shared service resources and a perpendicular layout with separated landside and waterside interfaces. Hybrid layouts are outside the present scope. These comparisons assess sensitivity to basic terminal structures; they do not establish performance in a particular operating terminal.

이 문안은 계획 상태다. 실제 실행을 마친 뒤에만 planned를 제거하고 구조별 결과·한계를 붙인다.
합성 환경의 두 구조에서 성공해도 실제 운송사 행동·예약 제약·현장 데이터 검증이 남는다는 점을 결론에 유지한다.
