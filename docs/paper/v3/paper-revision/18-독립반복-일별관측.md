# 독립 시드 반복의 일별 운영 기록

2026-09-16 사용자 요청. 월 전체 절감률뿐 아니라 전날 잔여 작업과 실제 혼잡 상태를 함께 남긴다.
이 기록은 정책의 입력이나 보상을 바꾸지 않는다. 독립 성능 실험은 공급 검증 뒤에 시작한다.

## 저장 단위와 해석

- 각 행은 `seed + policy_label + index`로 구별하고 실제 행동 정책은 `arm`에 저장한다. 내부 관측의 날짜는 `day_index`다. 날짜는 0부터 시작하며 운영일은 `index+1`이다.
- 30일 모두 저장하고 `evaluation_day`로 가운데 28일을 구별한다. 독립 표본은 하루가 아니라 한 달 전체다.
- 하루 시작 상태는 그 시각의 새 요청 투입·시장 결정·당일 선박 등록 전이다. 전날 종료 상태와 연결된다.
- 물량에 따른 분석 구간은 실행 전에 고정한다. 정책이 만든 대기열은 기전 설명에 사용하며 외생 조건처럼 해석하지 않는다.

| 사용자 요청 | 저장 내용 | 뜻과 주의점 |
|---|---|---|
| 일일 트럭 물량 | `load`, `operational.requested_trucks`, `cohort.requested` | 최초 요청 날짜에 배정된 수요; 원래 곡선 유지 |
| 하루 시작 backlog(이월된 미완료 작업) | `operational.start.total`과 `.blocks` | 트럭·본선·기타 미완료 야드 작업을 분리; 아직 도착/해제되지 않은 작업도 별도 열 |
| 실제 트럭 대기열 | `queue.truck_queue_mean`, `truck_queue_sampled_max` | 블록 도착 후 작업 시작 전 트럭 수. 평균은 연속시간 적분, 최고값은 5분 표본 최고값 |
| 블록별 대기열 | `operational.blocks`, 시작/종료 및 상태 시계열의 `blocks` | 같은 시점의 블록별 실제 대기 대수. 모든 블록 합이 터미널 합계 |
| 남은 야드크레인 작업량 | `yard_jobs_unfinished`, `yard_jobs_released_unfinished`, `yard_jobs_not_released`, `yard_jobs_in_service` | 건수 기준. 아직 시작하지 않은 작업의 처리시간을 임의 추정하지 않음 |
| 진행 중 크레인 잔여시간 | `crane_committed_remaining_s` | 이미 계획이 확정된 크레인의 남은 초 합계; 전체 대기 작업을 끝내는 예상시간과 다름 |
| 평균/90백분위 턴타임 | `mean_turn_time_s`, `p90_turn_time_s`, `n_censored` | 최초 요청일 집합의 게이트 진입→출문. 90백분위는 100대 중 약 90대가 이 시간 안에 나간다는 뜻. 미완료는 종료 시점까지 관측한 값이며 별도 개수 표시 |
| 공간·시간 행동 비율 | `operational.actions.spatial_share`, `.temporal_share` | 그 달력 날짜에 실행 확정된 변경 중 각 비율; 분모가 0이면 null |
| 일별 비용 | `phi_krw`, `c_wait`, `c_move`, `c_rehandle`, `c_vessel` | 기존 네 비용항과 합계. 트럭 항은 최초 요청일, 나머지는 달력 날짜 누적 차이 |

공간/시간 건수와 총 의사결정 횟수도 보존한다. 비율은 0~1이며 제안 후 거절되거나 실행 실패한 변경은 분모에 넣지 않는다.
기존 `n_space/n_time`의 자정 경계 집계와 별개로, 새 `operational.actions`는 자정 결정 직전의 차이를 사용한다.
따라서 자정에 발생한 결정은 새 날짜에 포함한다. 날짜 기준이 다른 비용 집합과 행동 집합을 일대일 인과 효과로 오인하지 않는다.

## 기록 파일

- `days.jsonl`: 하루 종료 때의 잠정값. 아직 나가지 않은 트럭 때문에 이후 확정값과 다를 수 있다.
- `daily-final.jsonl`: 월 종료 후 재집계한 일별 비용·턴타임과 운영 관측. 미완료 건수 포함.
- `operating-state.jsonl.gz`: 300초 간격의 실제 대기열·작업 잔량. 30일이면 마지막 경계 포함 8,641개 행이다.
- `result.json`: 확정 일별 값, 관측 정의, 간격, 표본 수와 두 새 파일의 SHA-256(파일 지문).
- 기존 월 평가기 역시 정책별 결과의 `days[].operational`과 `daily_observation`에 요약을 보존한다.

`cohort`에는 최초 요청 집합의 실제 진입·완료·미완료·미진입 대수와 해당 달력 날짜의 실제 진입 대수를 따로 둔다.
시간을 다음 날짜로 옮긴 트럭은 원래 요청 집합에서 사라지지 않는다.
실제 외부 도로 대기열은 현재 환경에 없으므로 저장했다고 쓰지 않는다. 이 기록만으로 일정 변경 비용을 추가한 것도 아니다.
원래 28일 비용의 정의를 유지하며, 당일 발생 비용과 최초 요청일 귀속 비용을 섞어 새 절감률을 만들지 않는다.

## 검증과 적용 상태

- 관측만 추가한 코드 검사 70개 통과. 미래 도착 제외·날짜 이월·분모 0·불완전 표본 검출을 포함한다.
- 첫 파일 저장 검사는 `label` 중복으로 실패했다. 원자료를 보존하고 부하 이름과 정책 이름을 분리했다.
- 수정 소스 `e9838a3`의 기준/전체/시간만 각 2일 계측 끔/켬 6회 실행에서 요청별 결과·비용·컨테이너 이동 동일성 등 30항목 통과.
- 관측 켬의 상태 기록은 정책마다 577개다. 대기열을 요청별 도착·작업시작 기록에서 다시 구성해 모든 시각·블록에서 일치함을 확인했다.
- [실행 결과](../../../../outputs/reports/yr317_v3_daily_observation/run-e9838a3/summary.json) · [파일 검산 27항목](../../../../outputs/reports/yr317_v3_daily_observation/file-verification.json). 저장 비용·턴타임·미완료·자정 경계·파일 지문을 재검산했다.
- 검증 실행에서 관측 추가 시간은 정책별 약 1.0~2.2초였다. 하루 60대의 작은 진단이므로 고부하 실행의 비용으로 일반화하지 않는다.
- 현재 `b76f3be` 소스로 실행 중인 30일 공급 검증에는 계측을 소급 삽입하지 않는다.
- 독립 반복을 시작할 때 모든 정책에 같은 간격을 고정한다. 시드별 전체 절감률과 별도로 일별 설명 표를 생성할 수 있다.
