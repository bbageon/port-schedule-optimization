# 공급 계획 보정과 컨테이너 연결 검사

2026-09-16. 사용자가 **YR-317-g(요청·공급 검증)를 먼저, 독립 시드 반복을 그다음**으로 확정했다.
독립 반복을 먼저 시작하겠다는 직전 설명을 정정한다. 독립 정책 실행은 아직 시작하지 않았다.

## 1. 무엇이 문제인가

원래 선박 계획은 목표 잔고보다 재고가 조금 높으면 작업 묶음 전체를 적하로 정한다.
현재 재고보다 수백 건짜리 적하 묶음이 클 수 있어, 20개월 중 9개월에서 원래 배정의 기말 수급이 음수가 됐다.
또한 정책이 반입 목적지를 바꾸면 원래 블록에서 예정한 반출 공급이 줄 수 있다. 두 문제를 같은 원인으로 취급하지 않는다.

## 2. 수량 보정안과 보존 범위

| 항목 | 보정 내용 |
|---|---|
| 트럭 요청 | 4,038,000건, 도착곡선·시각·흐름·블록·초기 재고 유지 |
| 선박 작업 | 이름·블록·작업 수·시작 시각·간격 유지 |
| 바꾸는 값 | 수량이 맞지 않는 블록의 일부 적하/양하 방향 |
| 선택 방법 | 변경 작업 묶음 수 최소, 이후 초기 재고와의 차이 최소 |
| 원본 입력 | 모두 보존, 보정 계획은 별도 파일 |

최초 입력 검산에서 9개월의 작업 묶음 13개, 4,913건을 적하에서 양하로 바꾸면 월말 공급 부족 1,362개가 0개가 된다.
이는 **선박 화물 구성의 변경**이다. 같은 선박 화물을 그대로 처리한 결과로 제시하지 않는다.
원래 수급이 맞던 블록과 나머지 11개월은 변경하지 않는다. 결과가 좋은 시드만 고르는 절차도 아니다.

월말 수량이 맞아도 하루 중 재고가 늦게 도착하거나 장비가 제때 처리하지 못할 수 있다.
따라서 이 보정안만으로 현실성 전체 통과·모든 작업 완료를 선언하지 않는다.

## 3. 반출 대상 연결을 어떻게 확인하는가

새 관측기는 실제 컨테이너별로 **초기 재고/반입 완료 → 반출·적하 완료**를 연결한다.
실제로 들어오기 전에 꺼낸 상자, 두 번 꺼낸 상자, 출처가 없는 상자, 블록별 실제 재고와의 불일치를 검사한다.
하루 끝에 완료 작업을 메모리에서 지우기 전에 기록하므로 날짜를 넘어서도 연결이 남는다.
정책의 선택이나 점수·컨테이너 재고를 변경하는 기능은 아니다.

이 검사는 합성 환경의 물리적 개체 연결이다. 화주별 주문과 실제 컨테이너의 명세서 일치를 검증하는 것은 아니다.
현행 합성 모형은 반출 대상이 소진되면 같은 블록의 가용 컨테이너로 다시 지정하는 추상화를 사용한다.
실제 컨테이너 번호가 고정된 운영 시스템과 동일하다고 주장하면 안 된다.

## 4. 실행 순서와 리뷰 대응

1. 단기 300대에서 새 모드·관측기의 연결을 확인한다.
2. 진단 시드 9,900,700의 30일을 원래 기준/보정 기준/보정 전체 모형으로 비교한다.
3. 입력의 수급 문제와 정책의 배정 때문에 생긴 잔여를 분리해 YR-317-g의 통과 범위를 정한다.
4. **YR-317-d**에서 독립 20개월의 기준/전체/시간만을 우선 비교한다. 월별 비용 차이를 통계 단위로 쓴다.

리뷰 1-1·리뷰 2의 독립 반복이 다음 핵심 작업이며, 이를 후보 순위 검사 뒤로 다시 미루지 않는다.
단일 진단의 비용 우위만으로 공급 문제나 공간 조정의 기여가 해결됐다고 설명하지 않는다.
추가학습과 정책 입력 변경은 이번 공급 보정에 섞지 않는다.
