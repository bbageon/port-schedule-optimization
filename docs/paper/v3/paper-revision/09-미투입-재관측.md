# 다음 리뷰 대응: 미투입 시점과 본선 완료 재관측

2026-09-15. 작업표 YR-317-g(요청 처리 기록 검증)의 후속 실행이다.

## 진행하는 이유

기존 10일 비용표에서 전체 모형은 기준보다 17.28% 낮았지만, 트럭 170/180/136대가 정책별로 다르게 미투입됐다.
본선 요청 44,322회도 모두 투입되지 않았다. 리뷰 1-1의 독립 반복과 1-4의 구성요소 비교를 해석하려면 이 차이가 생긴 상태를 확인해야 한다.
새 기록을 켠 실행으로 실패 순간의 재고·예약과 본선 완료를 관측한다. 이 단계에서 누락의 현실 비용이나 새 제약을 임의로 추가하지 않는다.

## 실행 조건

| 항목 | 고정 조건 |
|---|---|
| 비교 정책 | 배정 변경 없음 / 전체 모형 / 수락 거절 기능 제거 |
| 작은 연결 검사 | 같은 시드 9,900,700·하루 300대, 정책별 1회 |
| 본 진단 | 기존 시드 9,500,000·연속 10일·요청 69,000대, 정책별 1회 |
| 병렬 방식 | 정책별 1코어, 총 3코어(0·1·2). 한 정책의 날짜는 연속 진행 |
| 기존 v5 평가 | 코어 23에서 계속 실행 |
| 학습·정책 변경 | 없음. 같은 동결 가중치·배차·비용식 유지 |
| 종료 뒤 기록 | 기존 2시간 추적 유지 |

정책을 각각 실행하므로 서로의 재고·예약·진행 파일을 공유하지 않는다. 작은 연결 검사가 모두 통과해야 10일 진단을 자동 시작한다.
[사전 고정 조건](../../../../outputs/reports/yr317_v3_request_audit/replay-prereg.md)에 실패 처리와 전체 실행 예산을 보존한다.

## 확인할 결과

- 실제 재고가 없는 경우와 재고가 모두 다른 작업에 지정된 경우를 구분한다.
- 실제 공간 부족과 미도착 작업·예약분에 따른 투입 제한을 구분한다.
- 본선 원 요청 = 미투입 + 투입, 투입 = 완료 + 잔여 + 미추적 수를 대조한다.
- 트럭 요청별 사건·기존 비용식을 독립된 분석 코드로 재계산한다.
- 세 정책의 비용표와 기존 10일 실행 대비 날짜별 비용·행동·처리 수 차이를 남긴다.

## 해석과 다음 순서

이는 재사용한 시드의 관측 진단이며 추가학습·독립 확증·수평/수직 검증이 아니다.
원인 분류는 실패 순간의 상태에 대한 설명이다. 정책만의 효과나 최초 원인을 확정하지 않는다.
연결 검사 실패 시 본 진단을 시작하지 않고, 실행 실패 시 해당 실행기의 자식만 중지하고 원자료를 보존한다.
결과 검토 뒤 같은 YR-317-g 안에서 재현 차이와 실패 경로를 검토해 필요한 단일축 보정 범위를 정한다.

실행 상태는 실제 프로세스 시작과 로그 생성 확인 후 이 문서에 갱신한다.
