# 독립 20개월 평가 실행 계약

2026-09-16 사용자 지시: 공급·요청 연결 검증이 끝나면 기존 학습 모델을 고정하고 독립 반복까지 이어서 실행한다.
담당은 [YR-317-d](../../../../.claude/docs/dashboard-task-specs/YR-317-d-v3-review-independent-confirmation.md)다.

## 무엇을 실행하는가

- 기존 학습 모델 하나를 고정하고 독립 환경 20개에서 각각 30일을 이어서 실행한다.
- 각 환경의 같은 입력으로 재조정 없음·전체·시간만을 비교한다. 총 60개 실행이며 새 학습은 하지 않는다.
- 날짜마다 야드를 초기화하지 않는다. 서로 다른 시드의 실행끼리는 새 프로세스와 새 엔진을 사용한다.
- 실제 엔진이 받는 트럭 명단·초기 재고·선박 계획의 파일 내용 지문을 확인하고, 가중치가 바뀌지 않았는지도 검사한다.
- 기존 합성곡선·일 물량은 유지한다. 선박 방향 보정과 요청 전건 접수는 공급 검증에서 사용한 조건을 그대로 적용한다.

## 무엇을 알 수 있는가

기존 논문의 절감 효과가 다른 합성 월에서도 반복되는지, 전체 모델에 공간 후보를 추가로 허용한 이득이 있는지 확인한다.
새 학습의 효과, 학습을 여러 번 반복했을 때의 안정성, 예약 정원·시간 변경 비용을 넣은 효과는 이번 묶음의 질문이 아니다.

## 시작 조건

1. 별도 진단 시드의 2일·세 정책 검사로 실제 입력 확인부터 결과 저장·재검산까지 확인한다.
2. 현재 공급 검증의 세 조건이 모두 종료될 때까지 독립 평가를 대기한다.
3. 요청 누락·물리 연결·이중 반출·미래 공급·비용 기록·동일 입력을 저장된 원자료로 다시 확인한다.
4. 기록 또는 물리 연결이 틀리면 오류를 남기고 멈춘다. 정책 열위나 작업 잔여를 이유로 시드를 교체하지 않는다.

종료 잔여가 있다는 사실은 기록 오류와 다르다. 미완료 트럭·선박 작업·아직 대상이 지정되지 않은 작업을 보존한다.
검산을 통과해 실행을 시작해도 지속운영·전건 완료·정책 우위까지 통과했다는 뜻은 아니다.

## 일별 자료와 최종 표

- [일별 관측 명세](18-독립반복-일별관측.md)의 물량·잔여·대기열·작업량·턴타임·행동·비용을 정책별로 모두 남긴다.
- 기존 논문과 같은 중간 28일 비용을 주 분석, 전체 30일 비용을 보조 분석으로 계산한다.
- 통계 표본은 날짜가 아니라 독립 월 20개다. 월을 통째로 재표집해 평균 절감액의 불확실성을 계산한다.
- 주 비교는 기준−전체, 시간만−전체다. 두 비교의 구간을 보수적으로 조정하고 승리한 시드 수를 함께 보고한다.
- 60개 실행이 모두 끝나고 각 짝의 입력이 같은지 확인한 뒤 비용표·시드별 표·통계 JSON을 자동 생성한다.
- 비용 감소와 완료율·종료 잔여를 함께 해석한다. 가드 미통과 결과를 논문 개선 주장으로 자동 승격하지 않는다.

- [실행 전 고정](../../../../outputs/reports/yr317_v3_independent_eval/prereg.md) · [설정·입력 지문](../../../../outputs/reports/yr317_v3_independent_eval/config.json).

- 한 실행 내부 날짜를 분리하지 않고 서로 다른 시드·정책 실행끼리 병렬 처리한다. 다른 작업의 CPU 23은 유지한다.

## 실행기 연결 검사 이력

- 첫 `961d76a` 진단은 세 정책 모두 트럭 120대 완료, 입력·가중치·기록 검사를 통과했다. 기준정책의 선박 야드 작업 5건 잔여로 감독 프로세스가 종료했다.
- 원인은 감독 단계에 사전 계약보다 강한 “진단의 모든 작업이 완료돼야 한다” 조건을 넣은 것이다. 물리 연결·기록 오류와 관측된 작업 잔여를 구분하도록 고쳤다.
- 원래 사전 계약대로 기록이 틀리면 중단한다. 잔여 5건과 초기 실패 로그는 보존하며, 진단의 지속운영 타당성이나 모든 작업 완료를 통과로 보고하지 않는다.
- 같은 진단 시드·모델·입력으로 재실행한다. 독립 평가 시드를 사용하거나 바꾸지 않았고 통계·성능 판정 기준도 변경하지 않았다.
