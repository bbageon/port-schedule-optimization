# Block-only 독립 반복 추가

2026-09-17 사용자 지시. 담당: [YR-317-d](../../../../.claude/docs/dashboard-task-specs/YR-317-d-v3-review-independent-confirmation.md).

## 무엇을 추가하는가

- 기존 기준정책·Full·Time-only 60개 실행을 유지하고, 같은 20시드에 Block-only 20개를 추가한다.
- 전체 비교는 20개 환경×4정책, 총 80개 실행이다. 독립 표본 수는 정책마다 20개월이다.
- Block-only는 기존 모델에서 시간 변경 후보를 막는 `RL_SPACE`다. 블록 변경과 수락망은 유지한다.
- 모델·합성 도착곡선·일 물량·초기 재고·보정 선박 계획·비용·일별 관측을 동일하게 둔다. 새 학습은 없다.
- 기존 실행 소스와 설정은 수정하지 않는다. 추가 실행기와 결과 폴더를 별도로 만든다.

## 왜 필요한가

Full과 Time-only의 차이는 시간 조정에 공간 조정을 함께 허용한 추가 효과다.
Block-only와 기준정책을 비교해야 블록 조정만으로 비용이 줄어드는지도 직접 확인할 수 있다.
특히 한가한 날의 공간 효과라는 설명은 부하별 비용과 실제 잔여·대기열을 함께 봐야 한다.
낮은 계획 물량을 곧바로 실제 비혼잡으로 간주하지 않는다.

## 사전 고정과 비교

- 처음 세 정책의 사전등록은 보존한다. Block-only는 사용자 요청으로 나중에 추가한 비교임을 명시한다.
- 추가 시점에는 기준정책 한 달이 완료됐고, 다른 실행의 일부 일별 기록이 있었다. 네 정책 모두 최초부터 등록했다고 쓰지 않는다.
- 추가 비교 두 개는 기준−Block-only, Block-only−Full이며 같은 월끼리 짝을 맞춘다.
- 월 단위로 20,000회 재표집해 불확실성 구간을 구한다. 28일 두 비교는 각각 97.5%, 30일 보조 비교는 95% 구간이다.
- 원래 세 정책의 통계는 원래대로 보존하고, 추가 비교와 구분해 보고한다.
- 시드별 비용·완료율·잔여와 네 정책의 부하별 비용을 함께 정리한다. 600일을 독립 표본으로 세지 않는다.

## 실행 전 확인과 자원

- 평가 시드 밖의 짧은 실행으로 공간 변경 발생·시간 변경 0건·원자료 검산을 확인한다.
- 매 월마다 입력 지문·고정 가중치·시간 변경 0건·기록·컨테이너 연결을 확인한다.
- 실행 중인 기존 13개를 계속 두고, 메모리와 별도 실행 중인 연구 작업까지 고려해 우선 최대 2개를 추가한다. 실제 가용 메모리가 부족하면 더 줄인다.
- 전체 시뮬레이션 최대 16개, 작업당 메모리 3GiB와 부모 프로세스 여유를 예약한다. 이 작업의 CPU는 0~19 안에서만 사용한다.
- 기존 60개가 끝나면 반환된 자원을 남은 Block-only 실행에 쓴다.
- 개별 실패는 새 투입을 멈추되 다른 활성 실행을 강제로 종료하지 않는다.
- 전체 80개가 완료되고 실행 조건이 같은지 확인한 뒤 통합표를 만든다.

## 실제 시작과 진단 결과

- `ea9164b` 고정 소스에서 11:04 KST 본 실험을 시작했다. 기존 13개는 유지하며 Block-only 1개 실행·19개 대기다.
- 짧은 진단에서 공간 변경 19건·시간 변경 0건·트럭 120대 완료를 확인했다. 선박 야드 잔여 5건은 숨기지 않고 보존했다.
- 입력 동일성·일별 대기열·물리 컨테이너 연결·비용 기록 검사가 통과했다. 이는 정책 성능이나 전건 완료의 확증과 다르다.
- 첫 독립 월의 실제 실행 계약을 기존 Full과 대조해 정책명 외 입력·모델·엔진·관측·비용 조건이 같음을 확인했다.
- 현재 가용 메모리에 따라 추가 병렬 수는 1개다. 기존 작업 종료 등으로 자원이 확보되면 남은 실행에 자동 배분한다.
