# 도착시간 변경 부담: 과거 코드와 현재 v3의 연결 확인

2026-09-15. 담당: YR-317-a(원고·코드·증거 대조). 새 비용이나 정책을 구현한 작업이 아니다.

## 결론

**외부 대기를 비용에 더하던 과거 구현은 실제로 있다. 그러나 현재 v3의 학습·평가 총비용에는 그 합산이 연결되지 않는다. 논문에서만 빠진 설명이 아니다.**
현재도 원래 예약과 미룬 시간의 기록 기능은 남아 있다. 기록의 존재와 목적함수 반영을 구분해야 한다.

엔진 주석에는 외부 대기가 비용에 잡힌다는 과거 설명이 남아 있다. 현재 합산 함수는 해당 장부를 받거나 더하지 않으므로 주석만으로 포함됐다고 판단할 수 없다.

## 실제 계산 확인

현재 비용 함수를 직접 호출하고, 세 정책의 기존 10일 기록 각 69,000건을 재계산했다.

- 원래 예약 14:00, 실제 진입 14:00, 출문 14:10: 트럭 비용 6,666.67원.
- 원래 예약 14:00, 실제 진입 16:00, 출문 16:10: 트럭 비용도 6,666.67원.
- 같은 예시의 엔진 진단 함수는 미룬 7,200초를 기록한다. 그 시간이 현재 총비용에는 더해지지 않는다.
- 예시는 함수 연결 확인이며, 두 가지 완전한 터미널 시뮬레이션을 비교한 성능 결과가 아니다.
- 실제 저장된 전체 모형의 한 요청은 진입이 900초 미뤄졌고, 진입 이후 790.348초에 대한 비용 8,781.65원만 기록됐다.
- 전체 모형 31,446건, 거절 기능 제거 모형 43,920건에서 실제 진입이 원래 요청보다 늦었다. 기준 정책은 0건이다.
- 세 정책의 요청별 비용과 총 트럭 비용이 모두 현재 게이트 진입 기준 식과 일치했다.

의미: 비용 계산 경로가 추가 변경 부담을 합산하지 않는다는 것은 확인했다. 시간 차이 전체가 실제 기사 유휴시간이라는 의미는 아니며, 그 금전 부담은 이번 감사에서 산정하지 않았다.

핵심 비용 파일 3개는 원고 준비 커밋 `9715cc6`, 기존 진단 `3279b7f`, 현재 재관측 `1b601c0`과 내용이 같다. 원고 준비 시점의 코드 대조가 원래 실험 실행파일의 완전한 식별을 대신하지는 않는다.

## 리뷰 대응에 반영할 해석

- 사용자 기억은 과거 비용 함수와 현재 엔진 기록 기능에 부합한다. 이를 현재 v3 비용에 포함됐다는 근거로 사용하지 않는다.
- “재예약 비용도 이미 포함했다”는 답변은 쓰지 않는다. 현재 비용 범위는 터미널 내부 체류 중심이다.
- 새 비용을 넣으면 논문 설명 수정뿐 아니라 평가 기준이 달라진다. 재합산은 기존 정책의 비용 민감도이고, 새 비용으로 최적화한 정책 성능과 구분한다.
- 원래 예약과 변경 진입의 차이를 실제 기사 외부 대기와 자동으로 동일시하지 않는다. 사전 통지·다른 운송 업무 가능성에 따라 실제 부담은 달라진다.
- 이번 확인은 기존 a의 기록 정합 작업이다. b의 현실 제약·경제적 부담 실험 범위를 자동 변경하지 않는다.

## 4일 마감 반영

- 사용자 지시: 현재부터 4일 안에 개정을 완료한다. 달력상 목표는 2026-09-19 KST이며 정확한 제출 시각은 지정되지 않았다.
- 작업표의 a·g 기록 확인을 마치고 c 후보 선택 검사 → d 독립 실행·구성요소 비교를 핵심 경로로 유지한다.
- b 현실 제약 서술·f 사용자 맥락과 e 처리시간 준비는 독립적으로 병행한다. h 기본 수평·수직 검증도 기존 등록 범위로 관리한다.
- 기존 20개월×8정책은 예산 제안이다. 남은 시간·실측 실행량으로 최종 실행 계약을 시작 전에 고정하며 결과를 보고 표본 수를 바꾸지 않는다.
- 마지막 날은 성능표·답변서·원고 통합과 검증 시간을 확보한다. 완료하지 못한 실험을 완료 또는 통과로 표기하지 않는다.
