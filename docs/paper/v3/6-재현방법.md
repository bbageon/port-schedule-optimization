# 6 — 재현방법

## 6.1 재현 원칙

재현 실행은 학습과 평가의 난수시드를 분리하고, 같은 평가일의 정책들이 트럭 수요,
선박 투입과 서비스 난수를 공유하게 한다. 정책 가중치와 비교 조건은 평가 전에 고정한다.
각 날짜에는 총비용뿐 아니라 비용 항목, 수요수준, 거래 유형, 미완료 작업과 긴 대기를
함께 저장한다.

## 6.2 실험 설정 확인 순서

1. [실험환경](3-실험환경.md)의 터미널·도착·선박·비용 상수를 확인한다.
2. [정책과 학습](4-정책과-학습.md)의 입력 차원, 모형, 반사실 구간과 최적화 설정을 확인한다.
3. 30일 수요계획을 먼저 출력해 첫날·마지막날이 연결용인지 확인한다.
4. 진단 난수 대역에서 정책을 학습하고 날짜별 체크포인트와 손실을 저장한다.
5. 학습과 겹치지 않는 난수로 가중치를 고정한 정책별 30일 실행을 수행한다.
6. 가운데 28일을 날짜별로 짝지어 총비용, 중앙 차이와 부호검정을 계산한다.
7. 블록·시간 행동을 한쪽씩 제한해 비용 변화의 출처를 분해한다.

## 6.3 실행 예시

```powershell
$env:PYTHONPATH = "src"
python -m yard_rl.v3.train --seed 9900700 --days 30 --labels 64 --workers 20 --dry
python -m yard_rl.v3.train --seed 9900700 --days 30 --labels 64 --workers 20 `
       --out outputs/v3/repro-month
python -m yard_rl.v3.eval  --seed 9900950 --workers 8 `
       --ckpt outputs/v3/repro-month/ckpt_029.pt `
       --ckpt-early outputs/v3/repro-month/ckpt_000.pt `
       --out outputs/v3/repro-judge
```

첫 명령은 실행 전에 수요 구성과 학습일 수를 확인한다. 두 번째 명령은 날마다 반사실
라벨을 만들고 정책을 갱신한다. 세 번째 명령은 정책별 연속 실행을 수행하며 평가 중
탐색과 반사실 학습은 사용하지 않는다. 정책별 결과는 팔 단위로 저장되므로 중간에
끊겨도 끝난 정책은 다시 계산하지 않는다.

## 6.5 자동 검증 항목

| 검증 | 통과 조건 |
|---|---|
| 상호 동의 | 제안 또는 수락이 빠진 확정 0건 |
| 한 작업 한 번 | 이미 검토한 작업의 재검토 0건 |
| 정보 경계 | 미래 실제 도착·완료시각의 정책 입력 0건 |
| 분기 동일성 | 행동을 바꾸지 않은 분기가 본 실행의 행동·비용과 일치 |
| 날짜 비용 | 네 비용 항이 같은 날짜 경계를 사용 |
| 운영 분리 | 고정정책 평가의 반사실 호출 0회 |
| 연속성 | 날짜 경계에서 재고·대기열·미완료 작업 초기화 0회 |

## 6.6 보고해야 할 값

재현 보고서는 다음 값을 함께 제시한다.

- 난수시드, 체크포인트, 코드 커밋과 실행 명령
- 날짜별 수요수준과 정책별 총비용
- 트럭 체류·추가 이동·재취급·선박 유휴 비용
- 확정 거래 수와 블록·도착시각 행동 수
- 미완료 작업 수와 장시간 대기 분포
- 날짜별 승패, 중앙 비용 차이와 양측 부호검정 `p` 값
- 학습 전 모형, 학습된 모형과 재배치 없음의 동일 조건 비교

이 구성을 따르면 특정 총액만 재현하는 데서 끝나지 않고, 어떤 수요와 행동이 결과를
만들었는지까지 같은 기준으로 확인할 수 있다.
