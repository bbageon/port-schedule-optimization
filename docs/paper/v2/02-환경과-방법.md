# 02 — 환경과 방법

## 1. 시뮬레이션 환경

본 연구의 H-21은 실제 터미널을 그대로 복제한 것이 아니라 공개자료와 설계값으로
보정한 합성 환경이다. 21블록·자동화 야드 크레인 42기는 HJNC 공개 규모를 기준점으로
삼았지만, 1차원 배치·도착분포·서비스시간은 연구용 계약이다
([R13](06-관련연구와-참고문헌.md#r13)).

| 항목 | 현재 계약 |
|---|---|
| 야드 | 21블록, 블록당 야드 크레인(YC) 2기, 총 42기 |
| 배치 | 게이트와 안벽이 반대쪽에 있는 1차원 수평 배치 |
| 시간 | 24시간 도착창 + 종료 처리 구간 |
| 트럭 부하 | 3,500·5,000·7,500·12,500·15,000대/도착창 |
| 도착 | 24시간 바닥 38% + 오전 10시·오후 15시·저녁 21시 봉우리 |
| 본선 | 소형 2척·중형 1척·대형 1척은 30% 확률, 기항량은 TEU의 15~30% |

“하루”는 터미널이 자정에 닫힌다는 뜻이 아니라 정책을 같은 길이로 비교하기 위한
평가 절단면이다. 다만 다음 날 도착을 이어 붙인 진정한 정상상태 시뮬레이션은 아직
아니므로, 공개자료의 24시간 ON-DOCK 운영을 완전히 재현했다고 주장하지 않는다
([R13](06-관련연구와-참고문헌.md#r13)).

### 크레인 능력의 단위

`180초/이동(move)`은 크레인 1기의 기준 서비스시간이다. 이를 42기에 곱하면
이론상 `840 move/h`지만 **840 truck/h가 아니다.** 트럭 한 건은 재취급 때문에 여러
move를 요구할 수 있고 실제 엔진 서비스시간도 좌표·작업에 따라 달라진다. 따라서
도착률을 840과 직접 나눈 기존 “트럭 가동률”은 잠정 지표이며 본 논문의 성능 근거로
쓰지 않는다. PEMA도 자동화 크레인 성능은 이동 종류·자동화 지연·외부 차량·다중
크레인 동기화에 좌우되며, 서로 다른 운영을 단일 KPI로 단순 비교하지 말라고 설명한다
([R6](06-관련연구와-참고문헌.md#r6)). 즉 PEMA는 `180초`나 `840 move/h`의 직접
출처가 아니라, 그 수치를 보편적 현장 처리량으로 해석하면 안 된다는 근거다.
별도 야드 크레인 스케줄링 연구는 취급시간을 `(1.2, 2.0, 3.4)분` 삼각분포로
**가정**한다 ([R16](06-관련연구와-참고문헌.md#r16)). 따라서 180초는 공개 학술모형의
범위 안에는 있지만, 특정 터미널의 실측 능력으로 확정된 값은 아니다.

## 2. 비용함수

하루 총비용은 원화 네 항의 합이다.

```text
Φ = C_wait + C_move + C_rehandle + C_vessel
```

| 항 | 뜻 | 단가 |
|---|---|---|
| `C_wait` | 게이트인부터 게이트아웃까지 트럭 턴타임 + 1시간 초과 할증 | 기본 40,000원/트럭·시간, 초과분 추가 40,000원 |
| `C_move` | 재배치·재취급 때문에 생긴 YC 추가 이동 | 60,000원/시간 |
| `C_rehandle` | 컨테이너 재취급 | 2,000원/회 |
| `C_vessel` | 야드 공급 지연으로 생긴 선박 유휴 | 2.99원/GT·시간 |

트럭 기본 단가만 2026년 적용 화물자동차 안전운임 고시를 기준점으로 삼았고, 이를
시간당 40,000원으로 바꾼 방식과 나머지 단가는 연구용 설계값이다
([R15](06-관련연구와-참고문헌.md#r15)). 따라서 고시가 본 연구의 시간당 비용식을
그대로 규정한다고 해석하지 않는다.
본선의 구조적 유휴처럼 정책이 바꿀 수 없는 시간은 목적함수에서 제외하고 진단 열에
남긴다. 현재 감사에서 트럭 항은 24시간, 나머지 항은 26시간까지 누적되는 창 불일치가
발견됐으므로 최종 성능 판정 전에 바로잡아야 한다.

## 3. 결정 구조

각 검토 시점에 아직 도착하지 않은 공개 오더를 대상으로 두 종류의 대안을 만든다.

- **공간 판매**: 원래 블록 A에서 다른 블록 B로 보낸다.
- **시간 판매**: 블록은 유지하거나 바꾸면서 공개 도착시각을 뒤로 미룬다.

Seller는 `KEEP/SELL`, Buyer는 `REJECT/BUY`를 독립적으로 결정한다. Resolver는
`SELL ∧ BUY`인 후보만 용량과 충돌 제약 아래에서 묶어 확정한다. 한쪽만 원한 거래를
중앙이 강제로 만들 수 없다. 이 구조는 터미널과 운송사가 제한된 정보를 교환하면서
각자 비용을 고려하는 분산 협상 연구에서 문제 설정의 근거를 얻었다
([R2](06-관련연구와-참고문헌.md#r2)·[R3](06-관련연구와-참고문헌.md#r3)). 다만 기존
논문의 당사자와 수리모형을 복제한 것은 아니며, 본 연구의 Seller·Buyer는 오더별
비용 예측 행위자다.

학생 모델은 작은 MLP 두 개다. 고정 길이의 자기 블록 상태, 오더 특징, 제안 시각의
공개 도착 압력을 입력으로 받아 행동의 예상 비용 차이를 낸다. 현재 YR-235에서 Buyer의
미래 도착 압력과 시간 이연 격자를 Seller와 맞추는 수정이 진행 중이므로 최종 입력
차원과 행동 격자는 아직 동결되지 않았다.

## 4. 반사실 교사

표본으로 고른 결정마다 같은 스냅샷과 난수에서 세 세계를 굴린다.

```text
사실 세계             실제 Seller·Buyer 결정을 유지
Seller 반사실 세계    해당 Seller만 KEEP으로 강제
Buyer 반사실 세계     해당 Buyer만 REJECT로 강제
```

3시간 지평 `H`에서 두 학생의 정답은 다음과 같다.

```text
c_S = Φ_H(SELL) − Φ_H(KEEP)        SELL if predicted c_S < 0
c_B = Φ_H(BUY)  − Φ_H(REJECT)      BUY  if predicted c_B < 0
```

두 비용을 더해 하루 비용으로 쓰지 않는다. 같은 혼잡 효과가 양쪽 라벨에 겹칠 수 있기
때문이다. 실제 평가는 사실 세계에서 일어난 비용 `Φ`를 한 번만 센다.

한 행위의 책임을 “그 행위만 바꾼 세계”와 비교하는 생각은 차이 보상과 COMA의
반사실 기준선에 닿아 있다
([R7](06-관련연구와-참고문헌.md#r7)·[R8](06-관련연구와-참고문헌.md#r8)). 그러나
본 연구는 COMA의 중앙 critic을 쓰지 않고, 이산사건 시뮬레이터가 만든 원화 비용
차이를 두 개의 회귀망에 직접 가르친다.

모든 결정을 반사실로 만들면 계산량이 너무 크다. 한 세계가 약 5초이므로 결정
3,500건을 전수 라벨링하면 회차당 약 14시간이 든다. 그래서 결정을 표본 추출하고,
세계들은 CPU 여러 코어에서 병렬 실행한다. GPU는 작은 MLP 학습에는 쓸 수 있지만
병목인 이산사건 시뮬레이션을 크게 줄이지 못한다.

## 5. 학습과 평가의 분리

학습 중에는 반사실 교사가 비용 라벨을 만들고 두 MLP가 이를 회귀한다. 평가 때는
가중치를 고정하고 탐색을 끄며, 교사 호출이 0인지 기계 검사한다. 즉 운영 비용은
평행세계 수와 무관하다.

성능 비교는 같은 날·같은 부하의 난수를 공유하는 짝비교다. 고전 대조군은
No Reallocation, FCFS, SPT, Least Slack, Nearest, NetGain이며, 정책을 고정한 뒤
날 단위 부호검정을 사용한다. 최종평가는 결과를 보지 않은 새 시드 대역에서 한 번만
수행해야 한다. 같은 난수를 쓰는 시뮬레이션 비교는 차이의 잡음을 줄이는 전통적
실험설계와 맞닿아 있다 ([R12](06-관련연구와-참고문헌.md#r12)). 6차 무대용 시드·팔·
부하 계약은 YR-233에서 다시 사전등록할 예정이다.

## 6. 구현 독립성

v3는 옛 `integrated/` 엔진을 실행 중 불러오지 않는다. 엔진 사본 62파일을
`src/yard_rl/v3/world/`에 두고, 바이트·하루 실행 동일성 검사로 출발점이 같음을
확인했다. 이는 v3 수정이 이미 끝난 v1·v2 결과를 뒤에서 바꾸지 않게 한다.
