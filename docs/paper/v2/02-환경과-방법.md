# 02 — 환경과 방법

## 1. 시뮬레이션 환경

본 연구의 실험 대상은 실제 터미널을 그대로 복제한 것이 아니라 공개자료와 설계값으로 보정한
21블록 수평 배치 합성 환경이다. 자동화 야드 크레인 42기는 HJNC 공개 규모를 기준점으로 삼았지만,
1차원 배치·도착분포·서비스시간은 연구를 위해 설정한 가정이다([R10](06-관련연구와-참고문헌.md#r10)).

| 항목 | 시뮬레이션 설정 |
|---|---|
| 야드 | 21블록, 블록당 야드 크레인(YC) 2기, 총 42기 |
| 배치 | 게이트와 안벽이 반대쪽에 있는 1차원 수평 배치 |
| 시간 | 30일 완전 연속, 첫날·마지막날은 연결용, 가운데 28일을 실험일로 사용 |
| 일일 트럭 수요 | 3,500·5,000·7,500·12,500·15,000대, 추첨 비중 30·30·25·10·5% |
| 도착 | 24시간 바닥 38% + 오전 10시·오후 15시·저녁 21시 봉우리 |
| 본선 | 소형 2척·중형 1척·대형 1척은 30% 확률, 기항량은 TEU의 15~30% |
| 크레인 작업순서 | 실작업 우선, 예상 처리시간이 짧은 작업 우선의 규칙 기반 배차 |

“하루”는 터미널이 자정에 닫힌다는 뜻이 아니라 중간보고와 짝비교를 위한 비용 절단면이다.
시뮬레이션 상태는 자정에 초기화하지 않고 다음 날로 이어진다. 첫날은 인공 초기 재고와 다음 날을 연결하고, 마지막날은 앞선 작업의 잔여 효과를 관찰하는 데 쓴다.
학습 실행은 가운데 28일만 정책을 갱신하고 날마다 중간값을 남긴다. 최종평가는 같은 30일 구조를
새 시드로 다시 만들고, 가중치를 고정한 별도 실행에서 수행한다. 현행 재배치 학습에 쓰는 크레인 작업순서는 학습 신경망이 아니며, 모든 비교 정책은 같은 규칙 위에서 짝지어 평가한다.

### 30일 연속 환경이 필요한 이유

하루 단위 초기화 환경은 매일 같은 초기 적재에서 시작하고, 하루 끝에 새 작업이 끊겨 야간이 인위적으로
한가해진다. 그러면 조금씩 쌓이는 재고 오차, 다음 날로 넘어간 본선 일감,
야드 고갈을 볼 수 없다. 30일 연속 환경은 트럭과 본선 작업을 매일 새로 투입하되 야드
재고, 대기열, 크레인 상태와 미완료 작업은 그대로 넘긴다.

이 환경은 정책 성능을 높이기 위한 장치가 아니라, 오늘의 재배치가 다음 날의 재고와
대기열에 미치는 영향을 유지하기 위한 평가 조건이다. 따라서 28일 결과는 서로 독립인
하루 28개가 아니라 하나의 연속 운영 구간으로 해석한다.

### 크레인 능력의 단위

`180초/이동(move)`은 크레인 1기의 기준 서비스시간이다. 이를 42기에 곱하면
이론상 `840 move/h`지만 **840 truck/h가 아니다.** 트럭 한 건은 재취급 때문에 여러
move를 요구할 수 있고 실제 엔진 서비스시간도 좌표·작업에 따라 달라진다. 따라서
도착률을 840과 직접 나눈 기존 “트럭 가동률”은 잠정 지표이며 본 논문의 성능 근거로
쓰지 않는다. PEMA도 자동화 크레인 성능은 이동 종류·자동화 지연·외부 차량·다중
크레인 동기화에 좌우되며, 서로 다른 운영을 단일 KPI로 단순 비교하지 말라고 설명한다
([R6](06-관련연구와-참고문헌.md#r6)). 즉 PEMA는 `180초`나 `840 move/h`의 직접
출처가 아니라, 그 수치를 보편적 현장 처리량으로 해석하면 안 된다는 근거다.
별도 야드 크레인 스케줄링 연구는 취급시간을 `(1.2, 2.0, 3.4)분` 삼각분포로
**가정**한다 ([R13](06-관련연구와-참고문헌.md#r13)). 따라서 180초는 공개 학술모형의
범위 안에는 있지만, 특정 터미널의 실측 능력으로 확정된 값은 아니다.

## 2. 비용함수

하루 총비용은 원화로 환산한 네 비용 항목의 합이다.

```text
Φ = C_wait + C_move + C_rehandle + C_vessel
```

| 항 | 뜻 | 단가 |
|---|---|---|
| `C_wait` | 게이트인부터 게이트아웃까지 트럭 턴타임 + 1시간 초과 할증 | 기본 40,000원/트럭·시간, 초과분 추가 40,000원 |
| `C_move` | 재배치·재취급 때문에 생긴 YC 추가 이동 | 60,000원/시간 |
| `C_rehandle` | 컨테이너 재취급 | 2,000원/회 |
| `C_vessel` | 야드 공급 지연으로 생긴 선박 유휴 | 2.99원/GT·시간 |

트럭 기본 단가만 2026년 적용 화물자동차 안전운임 고시를 기준점으로 삼았고, 이를
시간당 40,000원으로 바꾼 방식과 나머지 단가는 연구용 설계값이다
([R12](06-관련연구와-참고문헌.md#r12)). 따라서 고시가 본 연구의 시간당 비용식을
그대로 규정한다고 해석하지 않는다.
본선의 구조적 유휴처럼 정책이 바꿀 수 없는 시간은 목적함수에서 제외하고 보조지표로
남긴다. 하루 비용은 연속 시뮬레이션의 두 날짜 경계에서 기록한 누적값의 차이로
계산한다. 과거 감사에서
트럭 항과 나머지 항의 누적구간 불일치가 발견됐으므로, 최종 성능평가는 네 항이 같은
날 경계를 쓰는지 자동 검사를 통과한 뒤에만 수행한다.

## 3. 결정 구조

### 3-1. 결정 단위

작업 `i`의 공개 상태를 다음처럼 적는다.

```text
o_i = (b_i, τ_i, d_i, x_i)
```

`b_i`는 원래 블록, `τ_i`는 공개 도착예정시각, `d_i`는 반입·반출 방향, `x_i`는
컨테이너와 작업 속성이다. 후보 `j`는 목적 블록 `b'_j`와 이연시간 `Δ_j`의 쌍이다.
블록 재배치는 `b'_j ≠ b_i`, 도착시각 조정은 `Δ_j > 0`이며 두 값이 함께 바뀔 수도 있다.
반출 작업은 꺼낼 컨테이너 위치가 이미 정해져 블록 재배치 후보에서 제외한다.

각 검토 시점에 아직 도착하지 않은 공개 트럭 작업을 대상으로 두 종류의 대안을 만든다.

- **블록 재배치**: 원래 블록 A에서 다른 블록 B로 보낸다.
- **도착시각 조정**: 블록은 유지하거나 바꾸면서 공개 도착시각을 뒤로 미룬다.

제안 정책은 원배정 유지 또는 재배치 제안을, 수락 정책은 거절 또는 수락을 독립적으로
결정한다. 중앙 매칭 절차는 `제안 ∧ 수락`인 후보만 용량과 충돌 제약 아래에서 묶어
확정한다. 한쪽만 원한 재배치를 중앙이 강제로 만들 수 없다. 이 구조는 터미널과 운송사가 제한된 정보를 교환하면서
각자 비용을 고려하는 분산 협상 연구에서 문제 설정의 근거를 얻었다
([R2](06-관련연구와-참고문헌.md#r2)·[R3](06-관련연구와-참고문헌.md#r3)). 다만 기존
논문의 당사자와 수리모형을 복제한 것은 아니며, 본 연구의 두 정책은 작업별 비용을
예측하는 독립 의사결정 모듈이다.

### 3-2. 한 번의 재배치가 확정되는 순서

1. 60초 결정 시점에 처음 자격을 얻은, 아직 게이트에 들어오지 않은 작업을 모은다.
2. 제안 정책이 원배정 유지 또는 블록·시간 변경 후보를 고른다. 한 작업은 한 번만 검토한다.
3. 목적 블록 또는 목표 시간대의 수락 정책이 각 제안을 독립적으로 수락·거절한다.
4. 중앙 매칭 절차는 양쪽이 동의한 후보만 모아 용량과 소유권을 확인하고 일괄 확정한다.
5. 확정 뒤 원래 블록·시각을 기록하고 새 블록·시각으로 실행 명단을 한 번에 바꾼다.

따라서 중앙 매칭 절차는 새로운 제안을 만드는 중앙 배정기가 아니다. 양쪽이 동의하지
않은 후보는 확정할 수 없고, 한 작업을 연속으로 여러 번 옮기거나 이미 도착한 작업을
뒤늦게 바꾸는 것도 금지한다. 도착시각 조정에서 수락 주체는 사람이 아니라 목표
예약 시간대다. 다만 현행 합성 환경에는 실제 예약 시간대별 정원이 입력되지 않아 용량 제한이 사실상
비활성화돼 있다.
따라서 예비 시나리오의 도착시각 조정 성능은 무제한 예약 정원이라는 단서를 가지며,
실제 예약 가능량을 확보하기 전에는 현장 성능으로 일반화하지 않는다.

### 3-3. 정책이 아는 것과 모르는 것

| 구분 | 예 | 이유 |
|---|---|---|
| 입력 가능 | 현재 대기·재고·크레인 잔여, 공개 ETA, 목표 시간대 주변의 통지 작업 수, 계획 본선시각 | 결정 순간 관측 가능 |
| 입력 금지 | 실제 미래 도착·주행·완료시각, 다른 수락 정책의 동시 응답 | 운영 순간에는 알 수 없는 미래 |
| 라벨 생성에만 사용 | 분기 뒤 3시간의 실제 비용 | 사후 학습 정답이며 운영 입력은 아님 |

운영 정책에 미래 실현값을 주지 않는 이유는 좋은 점수를 얻기 위해 실제 운영에서 알 수
없는 정보를 보는 일을 막기 위해서다. 반면 반사실 라벨은 과거 결정 시점에서 “다른
행동을 했다면”을 재생해 만들므로 미래 비용을 학습 목표에 쓸 수 있다.

운영 정책 모형은 작은 MLP 두 개다. 고정 길이의 자기 블록 상태, 작업 특징, 제안
시각 주변에 통지된 예상 도착 건수를 입력으로 받아 행동의 예상 비용 차이를 낸다.
두 정책은 같은 도착예정 정보와 목표 시간대 주변의 통지 물량을 사용한다. 입력 차원과
행동 간격은 학습 전에 고정하며, 평가 중에는 바꾸지 않는다.

## 4. 반사실 비용 라벨 생성

표본으로 고른 결정마다 같은 상태·난수·탐색률·크레인 작업순서에서 세 개의
시뮬레이션 분기를 실행한다.

```text
관측 행동 분기        실제 제안·수락 결정을 유지
제안 반사실 분기      해당 결정만 원배정 유지로 변경
수락 반사실 분기      해당 결정만 거절로 변경
```

3시간 평가구간 `H`에서 두 정책 모형의 학습 목표는 다음과 같다.

```text
c_P = Φ_H(제안) − Φ_H(원배정 유지)       제안 if predicted c_P < 0
c_A = Φ_H(수락) − Φ_H(거절)               수락 if predicted c_A < 0
```

두 비용을 더해 하루 비용으로 쓰지 않는다. 같은 혼잡 효과가 양쪽 라벨에 겹칠 수 있기
때문이다. 실제 평가는 관측 행동 분기에서 발생한 비용 `Φ`를 한 번만 센다.

관측 행동 분기는 본 실행을 그대로 재현해야 한다. 이를 위해 분기 직전 상태뿐 아니라
탐색률과 크레인 작업순서를 실행 문맥에 저장하고, 일부 표본에서 행동·비용 동일성을
자동 검사한다. 이 조건이 깨지면 행동을 바꾸지 않은 분기도 다른 정책으로 진행하므로
비용 차이를 해당 결정의 효과라고 부를 수 없다.

한 행위의 책임을 “그 행위만 바꾼 시뮬레이션 분기”와 비교하는 생각은 차이 보상과 COMA의
반사실 기준선에 닿아 있다
([R7](06-관련연구와-참고문헌.md#r7)·[R8](06-관련연구와-참고문헌.md#r8)). 그러나
본 연구는 COMA의 중앙 가치모형을 쓰지 않고, 이산사건 시뮬레이터가 만든 원화 비용
차이를 두 개의 회귀모형에 직접 학습시킨다.

모든 결정을 반사실로 만들면 계산량이 너무 크다. 반사실 분기 하나가 약 5초이므로 결정
3,500건을 전수 라벨링하면 학습 반복 1회에 약 14시간이 든다. 그래서 결정을 표본 추출하고,
반사실 분기들은 CPU 여러 코어에서 병렬 실행한다. GPU는 작은 MLP 학습에는 쓸 수 있지만
병목인 이산사건 시뮬레이션을 크게 줄이지 못한다.

## 5. 학습과 평가의 분리

학습 중에는 반사실 시뮬레이션이 비용 라벨을 만들고 두 MLP가 이를 회귀한다. 평가
때는 가중치를 고정하고 탐색을 끄며, 반사실 계산 호출이 0인지 기계 검사한다. 즉
운영 계산량은 학습 때 사용한 반사실 분기 수와 무관하다.

성능 비교는 같은 날·같은 수요수준의 난수를 공유하는 짝비교다. 고정정책용 30일
시뮬레이션의 가운데 28일을 날짜별로 보고하고, 현실 비중 전체와 다섯 수요수준별
결과를 함께 낸다.
비교 정책은 재배치 없음, 선착순(first-come-first-served, FCFS), 최단 처리시간(shortest
processing time, SPT), 최소 여유시간과 순이득 기준이다. 최근접 블록
규칙은 목적지가 한 블록으로 집중되는 구조 결함 때문에 주 비교에서 제외하되, 결과를
본 뒤 발견했다는 사실과 포함 결과를 별도로 보고한다. 정책을 고정한 뒤 날 단위
부호검정을 사용한다. 최종평가는 결과를 보지 않은 새 시드 대역에서 한 번만 수행해야
한다. 같은 난수를 쓰는 시뮬레이션 비교는 차이의 잡음을 줄이는 전통적
실험설계와 맞닿아 있다 ([R9](06-관련연구와-참고문헌.md#r9)). 현행 30일 연속
시나리오의 난수시드·비교 정책·수요수준은 최종평가 전에 다시 사전등록한다.

같은 크레인 작업순서를 공유한 짝비교는 그 규칙 안에서의 재배치 효과를 검증한다.
다른 크레인 규칙에서도 효과가 유지되는지는 각 규칙에서 재학습하고 새 시드로 평가해야
하는 별도의 일반성 질문이다.
