# YR-317-g — 기존 수요 장부 진단 사전 고정

2026-09-15. 사용자 지시: 실험 진행. 실행 전에 코드·이 명세를 커밋하고 원격에 반영한다.
신뢰성의 기록 누락 보정으로 착수 허가를 받았다. 성능 확증·새 제약 실험·추가학습은 아니다.

## 질문과 고정 조건

같은 최초 요청을 받은 세 정책에서 어떤 트럭이 투입되지 않으며, 그 사유와 비용 집계가 어떻게 다른가?

- 가중치: `outputs/v3/month-02/ckpt_029.pt`. 재학습·초기화·체크포인트 선택을 하지 않는다.
- 동작 검사: 시드 9,900,700, 하루 300대, RL 1회. 기록 불일치·정책 예외·교사 호출 발생 시 중단한다.
- 본 진단: 기존 수락 비교 시드 9,500,000의 `plan_month` 앞 10일을 사용한다.
- 정책: NO_REALLOC → RL → RL_NOVETO, 각 1회, 같은 최초 요청 명단. 최종 모형을 모두 그대로 쓴다.
- 연속 야드 상태·기존 SF_SPT 배차·기존 비용 4항·탐색 0·기존 시공간 후보를 유지한다.
- 종료: 10일 + 기존 2시간 배수. 원래 30일의 완전 재현이나 독립된 새 평가라고 부르지 않는다.
- 이유: 과거 최초 미투입 날짜 번호는 NO_REALLOC 8, RL 5, RL_NOVETO 4였다. 앞 10일은 모두 포함한다.
- 모든 날짜를 진단 장부에 남긴다. 가운데 날짜만 고른 유의성 검정이나 성능 채택을 하지 않는다.
- CPU 작업자 1개·망 스레드 1개·낮은 실행 우선순위. 이미 실행 중인 v4·v5는 건드리지 않는다.
- 예산: 동작 검사 1회 + 각 정책의 10일 재생 1회. 이득이나 미투입 수를 보고 횟수·기간을 늘리지 않는다.

## 기록과 판정

- 최초 요청별 ID·날짜·반입/반출·블록·예정시각·리드·원래 대상·이동시간을 보존한다.
- 투입 시도 결과·사유·선택 대상과 종료 시점의 사건 시각을 연결한다.
- 투입 전 대기·진입 후 미완료·완료·미투입·미처리를 구분한다. 미투입은 기존 비용식상 비용 0인 사실을 그대로 기록한다.
- 새로운 외부 대기·일정 변경 비용을 만들지 않는다.
- 요청 수 분할, 중복·미기록·모순, 안내자 계수, 트럭 비용 재합산을 대조한다.
- 기존 본선 투입 장부도 저장한다. 본선의 모든 작업 완료를 검증했다는 주장은 하지 않는다.
- 각 날짜 종료 시 진행 상황을 저장하고 각 정책 완료 시 요청 장부·결과·해시를 저장한다.
- 정책 간 최초 요청 해시가 다르면 중단한다. 손실·실패·검열된 표본을 삭제하지 않는다.
- 기술적 기록 검사가 통과해도 전건 투입이 실패하면 성능 비교 자격은 충족되지 않는다.
