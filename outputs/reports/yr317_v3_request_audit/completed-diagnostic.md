요청별 기록·일별 합계·기존 비용식·가중치와 파일 지문 대조는 모두 통과했다.

기존 기록에는 본선 작업의 최종 완료와 잔여 수가 없어 본선 처리 완료를 검증할 수 없다.

따라서 이번 결과를 기존 논문 실행의 완전 재현이라고 표현하지 않는다. 끝을 10일로 줄였다는 사실만으로 첫날 차이의 원인을 확정하지도 않는다.

## 2. 코드에서 확인한 직접 경로

| 현상 | 확인한 경로 | 현재 말할 수 있는 범위 |
|---|---|---|
| 반출 대상 없음 | `make_retarget`이 해당 블록의 미지정 컨테이너를 찾지 못하면 `V3Announcer`가 요청을 SKIPPED로 종료 | 블록이 완전히 비었거나 기존 작업이 모두 지정한 경우를 기존 기록만으로 구별할 수 없음 |
| 용량 검사 거절 | `free_slots`는 물리 여유에서 미도착 반입·양하 작업과 이전 예약을 뺀 값, 여유 기준 이하면 투입 거절 | 음수 free 값만으로 실제 장치량이 물리 용량을 초과했다고 단정할 수 없음 |
| 본선 적하 물량 감소 | `inject_vessel`은 요청 수보다 미지정 재고가 적으면 재고 수만큼만 작업을 생성 | 요청 물량 감소가 코드에 포함돼 있으며 정책별 재고가 다르면 실제 작업량도 달라짐 |
| 본선 전체 투입 실패의 기록 공백 | 기존 예외 기록에는 요청 작업 수가 없었음 | 이번 10일 실행에는 전체 실패가 없지만 다른 시드에서는 원래 요청량까지 집계에서 빠질 수 있음 |
| 본선 완료 기록 공백 | 일별 `prune_completed`가 완료된 작업을 지워 다음 날 원장에 남지 않음 | 별도 완료 기록 없이 투입 수를 완료 수로 대신할 수 없음 |

트럭 반출 대상 없음과 본선 적하의 재고 부족은 “아무 작업에도 지정되지 않은 컨테이너”를 찾는 과정과 연결된다.
하지만 실제 10일 실패 시점의 재고 구성·예약 경합까지 보존된 것은 아니므로 전체 재고 고갈·특정 정책의 혼잡 유발로 원인을 확대하지 않는다.

## 3. 이번 보정의 범위와 검사

- `diagnose_admissions=True`일 때 미투입 시점의 실제 재고·지정된 재고·미지정 재고·예약량·물리 여유를 기록한다.
- 본선 계획의 원 요청량을 별도 보존하고 완전 투입 실패에도 요청 수·블록·작업 종류를 남긴다.
- 완료 작업을 지우기 전에 본선별 완료 작업 ID를 보존한다. 반복 관측해도 같은 완료 작업을 중복 집계하지 않는다.
- 안벽 크레인이 끝났는지와 야드 연계 작업이 모두 끝났는지를 나누어 기록한다.
- 요청량 = 미투입 + 투입, 투입 = 완료 + 잔여 + 미추적의 두 관계를 검사한다.
- 정책 입력·후보 선택·예약 정원·비용·미투입 처리 규칙은 변경하지 않는다. 불리한 요청을 제거하는 문제의 해결과 기록 보정을 구분한다.
- 관련 검사 46개가 통과했다. 작은 상태에서 ‘재고는 있지만 모두 지정됨’, ‘물리 여유가 있지만 예약분 때문에 free가 음수’도 재현했다.
- 실제 300대 실행에서 기록 기능 OFF/ON을 비교하는 [사전 계약](admission-probe-prereg.md)을 작성했다. 실제 실행 결과는 별도 증거로 연결한다.

## 5. 판정과 다음 순서
