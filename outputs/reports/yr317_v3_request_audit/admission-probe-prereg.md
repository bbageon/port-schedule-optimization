# 본선 작업·미투입 상태 관측 보정의 실행 전 계약

- 등록일: 2026-09-15. YR-317-g(요청·작업 기록 정합)의 단일축 보정이다.
- 목적: 미투입 시점의 재고·예약을 구분하고, 일별 메모리 정리 뒤에도 본선 작업 완료 기록이 남게 한다.
- 이번 비교는 기록 기능을 켜도 기존 정책 선택·작업 처리·비용이 바뀌지 않는지 확인한다.
- 외생 시드 9,900,700, 하루 트럭 300대, RL 정책과 동결 가중치 `outputs/v3/month-02/ckpt_029.pt`를 사용한다.
- 비교 두 개: `capture_requests=True`는 공통, `diagnose_admissions=False/True`만 다르게 실행한다.
- 새 학습·정책 변경·예약 정원·외부 대기 비용·요청 재시도 규칙은 추가하지 않는다.
- CPU 1개·학습망 내부 스레드 1개, 두 실행을 순서대로 한다. 다른 실험을 중단하지 않는다.
- 깨끗한 커밋의 별도 체크아웃에서 실행하며 소스·가중치·설정·날짜 시드·이 계약의 지문을 저장한다.
- 기존 일별 모든 결과·요청별 사건·미투입·재배정·기존 본선 투입 결과를 정확히 비교한다. 새 관측 필드만 비교에서 제외한다.
- 본선은 요청 수 = 미투입 수 + 투입 수, 투입 수 = 완료 야드 작업 + 잔여 야드 작업 + 미추적 작업으로 검산한다.
- 안벽 크레인 완료와 야드 연계 작업 완료는 별도로 확인한다. 안벽만 끝났다고 전체 본선 작업 완료로 세지 않는다.
- 검사: 기존 결과 완전 동일, 요청 기록 일치, 본선 기록 일치, 정책 예외 0, 온라인 학습용 분기 호출 0.
- 작은 실행에서 미투입이 없더라도 해당 검증 결과를 10일 실험의 미투입 원인 확정으로 확대하지 않는다.
- 별도 단위 재현으로 재고가 있지만 이미 다른 작업이 지정한 경우, 물리 여유는 있지만 예약분이 넘치는 경우, 완료 작업 삭제·이중 집계·본선 전체 투입 실패를 검사한다.
- 10일 진단의 170/180/136건 미투입과 본선 물량 감소는 원자료 그대로 보존한다. 이번 기록 코드가 이를 해결했다고 보고하지 않는다.
- 종료 기준: 위 검사 결과와 원자료 저장, Dashboard/spec 갱신 및 커밋·원격 반영.
