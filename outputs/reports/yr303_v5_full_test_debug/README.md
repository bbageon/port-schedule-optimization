## 진행사항

기존 179건을 중단 없이 완주했고, 새 회귀 시험 20건을 더했다.
수정 후 재실행까지 합쳐 **서로 다른 199건 모두 통과**를 확인했다.
실패 원자료도 보존하며, 고친 뒤의 통과 결과와 구별한다.

| 재현한 문제 | 수정 |
|---|---|
| 정책 변화가 너무 커 갱신을 중단해도 변화량을 0으로 보고 | 중단시킨 변화량과 `early_stopped`를 기록. 무한대 등 잘못된 수치는 실패 처리 |
| 반복 횟수에 소수·참/거짓을 넣어도 시작 | 실행 전에 양의 정수인지 확인 |
| 잘못된 시각을 상태 수집기에 전달 | 음수·무한대·정의되지 않은 시각은 상태를 읽기 전에 거부 |
| 끊긴 구간·서로 다른 블록 수를 미래 보상 계산에 연결 | 시간 연속성·배열 크기·유한값 확인. 실제 종료는 다음 에피소드와 보상 연결을 끊음 |
| 독립 사본을 복사 당시가 아닌 개발 중인 최신 v4와 비교 | 복사 기준 커밋의 파일 목록과 물리 엔진 62개 파일 내용 식별값에 고정 |
| 옛 하루·월 학습에서 지정 시드가 모델 초기값에 적용되지 않음 | 두 경로 모두 모델 생성 전에 시드를 적용. 같은 시드의 재현성과 다른 시드의 차이를 각각 검증 |

즉 비용식·정책 구조·새 PPO의 정상 계산은 그대로 두고 입력·보고·초기화 오류를 고쳤다.
v4에 동시에 추가되던 `crane` 파일을 v5에 가져와 검사를 통과시키지 않았다.
옛 학습 초기화 문제는 v5에서도 독립적으로 재현했다. 기존 시드만으로 옛 결과를
완전 복원할 수 있었다고 주장하지 않는다. 새 PPO 초기화에는 이 결함이 없었다.

  새 PPO 34건과 옛 학습 초기값 4건이다. 초기값 시험은 세계 실행 전에 멈춘다.

누락·중복은 0건이다. **수정 완료 후 전체를 한 프로세스에서 재실행했다는 뜻은 아니다.**
초기화 수정은 옛 학습 진입점 두 곳뿐이며, 32건의 무대·배우·반사실 코드는 무수정이다.

## 재현 방법

WSL의 기존 `yard-rl` 가상환경, CPU 1스레드.

```bash
export PYTHONPATH=src OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
python -m pytest tests/v5 -vv --durations=15 --junitxml=outputs/v5/new-full.xml
bash scripts/v5/debug_ppo.sh --seconds 43200 --rollout-intervals 120 --epochs 1 \
  --output outputs/v5/new-debug
bash scripts/v5/debug_ppo.sh --eval --checkpoint outputs/v5/new-debug/policy.pt \
  --seconds 43200 --output outputs/v5/new-replay
```

옛 반사실·규칙 정책 시험은 실제 하루 실행을 여러 번 비교하므로 수십 분 걸릴 수 있다.
출력 경로는 기존 결과를 덮어쓰지 않도록 새 이름을 사용한다.
