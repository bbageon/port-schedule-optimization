# 수직형 기존 모델 적용 사례 — 실행 전 고정

2026-09-19 사용자 지시: 기존 독립 실험의 기준을 재사용하고 수직형 두 정책을 병렬 실행한다.
담당: [YR-317-h](../../../.claude/docs/dashboard-task-specs/YR-317-h-v3-review-basic-layouts.md).

## 목적과 허용 주장

- 기존 고정 모델의 시간 조정이 새 수직 끝단 인계 환경에서도 비용·처리량·잔여를 어떻게 바꾸는지 확인한다.
- 현재 미통과한 환경 현실성의 직접 보완 사례다. 독립 반복 확증·현장 성능·순수 배치 방향의 인과효과가 아니다.
- 새 학습, 모델 선택, 비용 단가 조정, 성능에 따른 시드 교체는 하지 않는다.
- 원래 독립 평가와 이전 수직형 실패 기록은 보존한다. 진행 중인 실행의 코드·입력·가중치는 변경하지 않는다.

## 고정 입력과 실행

- 원래 독립 명단의 첫 시드 **20,000,000**을 사용한다. 성능이나 완료 속도로 선택하지 않는다.
- 시드 선택 시 기존 결과 일부가 이미 관측되었다. 이번 사례를 사전 미관측 독립 확증이라고 표현하지 않는다.
- 기존 `yr317_v3_independent_eval/config.json`의 지문으로 고정된 합성 도착곡선·30일 물량·초기 재고·공급 보정 선박 계획을 사용한다.
- 모델은 기존 `outputs/v3/month-02/ckpt_029.pt`; 지문 `50f2da2e8b3070dbba48273f0de5debdf5514fe96f0fa1f5a8f25b8a830cba99`.
- 정책은 `NO_REALLOC`(재배정 없음)와 `RL_TIME`(도착시간만 조정). 각 정책은 새 프로세스·새 엔진으로 실행한다.
- 30일 상태 연속 운영과 마지막 2시간의 잔여 처리 구간을 유지한다. 날짜별로 초기화하지 않는다.
- 중간 28일 비용을 주 분석, 전체 30일 비용을 보조 분석으로 보존한다. 기존 요청일 귀속·계수기 집계 방식을 그대로 사용한다.
- 트럭 대기·크레인 이동·재조작·본선 비용의 기존 네 항과 단가를 유지한다. 예약 슬롯 제한이나 새 일정 변경 비용을 추가한 시험이 아니다.
- 300초마다 운영 상태를 저장하고 요청·컨테이너 연결·일별 관측·정책 행동을 원자료로 보존한다.

## 수직형에서 바뀌는 조건

- [구현 명세](../../../docs/paper/v3/paper-revision/26-수직형-구현검증.md)의 끝단 인계·크레인 역할·도로·양하 정원·가능 후보 보존 규칙을 사용한다.
- 원본 입력을 먼저 확인하고 이동시간 세 필드만 파생한다. 두 수직형 정책은 파생된 실행 일정까지 같아야 한다.
- 내부 차량은 블록별 3대이며 기존 180초 대신 경로별 왕복시간을 적용한다. 추가된 블록 전체 양하 흐름 정원 3은 선박별 안벽 버퍼 3과 구분한다.
- 원래 선박 계획 완료·출항 시각을 유지한다. 새 구조의 물리 하한 초과·종료 잔여·자원 부족을 결과에 공개한다.
- 두 환경의 원비용 차이를 방향 자체의 효과로 해석하지 않는다. 각 환경 안에서 기준정책 대비 시간정책의 차이를 제시한다.

## 짧은 연결 검사와 본 실행

- 본 실행 전 별도 시드 99,194,001의 기존 60대/60대 입력으로 두 정책을 병렬 검사한다. 외부 트럭은 적지만 본선 작업까지 저부하인 것은 아니다.
- 연결 검사와 본 실행 모두 요청 누락·이중 반출·미래 공급·물리 제약·비용 장부·모델 변경·입력 불일치는 오류로 남기고 중단한다.
- 작업 잔여·본선 마감 초과·정책 손실은 실행 기록 오류와 분리해 저장한다. 이를 이유로 시드를 버리거나 결과를 덮어쓰지 않는다.
- 이전 수직형 자격 검사의 전량 완료 실패는 유지한다. 이번 운영 사례는 기존 독립 평가의 기록 검사 기준을 사용한다.
- 연결 검사 두 정책의 기록과 동일 입력이 통과한 뒤에만 본 실행 두 개를 시작한다.
- 한 실행이 실패해도 다른 실행의 결과는 끝까지 보존한다. 자동 재시작·시드 교체는 하지 않는다.

## 자원과 결과 보고

- 새 실행은 CPU 18·19에 각 1개, 계산 스레드 1개씩 배정한다. 기존 실험·다른 세대 작업을 중지하지 않는다.
- 새 실행에 메모리 6GiB를 따로 예약하고 기존 대기 작업의 증가·운영 여유까지 확인한다. 총 사용은 사용자 허용 20코어 안에서 관리한다.
- 기존 환경의 같은 시드 기준/시간 결과는 완료·입력·원자료 지문을 검증한 뒤 재사용한다. 아직 실행 중이면 기다리며 다른 시드로 바꾸지 않는다.
- 수직형 두 정책의 총비용·네 비용 항·완료량·종료 잔여·대기열·턴타임·행동 비율을 함께 보고한다.
- 한 시드의 날짜를 독립 표본으로 세지 않는다. 유의성 검정·독립 반복 신뢰구간·일반적 우위 주장은 하지 않는다.
- 비용이 줄어도 처리량 악화나 잔여 증가가 있으면 운영 개선의 근거로 자동 채택하지 않는다. 종료 이후 전체 해소 비용은 이번 고정창 비용과 구분한다.
- 실제 실행 소스·설정·모델·원본 및 파생 입력의 지문과 시작·완료·실패를 기록한다.
