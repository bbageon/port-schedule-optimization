## 무엇을 고쳤나

1. 트럭 누락 시 오더 번호·블록·시각·종류·사유·블록 상태·투입 수를 저장한다.
2. 본선은 투입한 작업량과 실패 사유를 저장한다. 첫 실패 이후 계속 학습하지 않는다.
3. 트럭 검사는 해당 시각의 정책 갱신보다 먼저, 본선 검사는 당일 투입 직후에 한다.
4. 월 실행 반환값은 최종 검증보다 먼저 저장한다. 실패해도 결과가 통째로 사라지지 않는다.
5. 실패 시 최근 모델과 마지막 정책 경계의 부분 보고서를 보존한다. 저장 오류가 원래 실패를 가리지 않는다.

공간 부족·반출 대상 없음·시간 밖 도착·본선 물량 0의 **인위적 실패 검사**가 통과했다.
이는 오류 처리 검증이지 원본 30일 실패의 원인을 재현했다는 뜻이 아니다.
본선 물량의 일부 축소는 원래 허용하던 동작이다. 이를 기록하되 이번에 새 금지 조건으로 바꾸지 않았다.

## 현재 설계 — 실행되는 순서

### 1. 입력 계획과 야드를 만든다

트럭 방문과 날짜별 본선 계획을 같은 시드(재현용 난수 번호)로 만든다.
21블록의 야드를 한 번 만들고 날짜가 넘어가도 남은 작업·재고·비용을 이어 간다.
30일 기본 실행은 초기 적재 45%, 기존 날짜별 물량 추첨을 유지한다.
전체 계획이 시뮬레이터에 있다고 정책이 미래의 실현 도착을 미리 보는 것은 아니다.

### 2. 통지 시각에 오더를 투입한다

트럭 오더에는 번호, 반입/반출, 통지 시각, 예약 시각, 블록, 컨테이너 번호가 있다.
실제 도착·작업 시작·완료 시각은 별도 실행 기록에 사건이 일어날 때 채운다.
본선 계획은 해당 날짜에 붙이고 개별 크레인 작업으로 만든다.
투입이 거부되면 새 기록 장치가 상세 사유를 저장하며 실행을 멈춘다.

### 3. 판매 역할이 제안한다

자기 블록의 혼잡·예약 상황과 오더 후보를 보고 유지, 다른 블록으로 보내기,
뒤 시간으로 미루기 중 하나를 고른다. 다른 블록 이동은 반입 오더만 가능하다.
현재 시간 이동 후보는 최대 120분이며 기존 통지·예약 자격 검사를 유지한다.

### 4. 구매 역할이 수락 여부를 고른다

공간 이동이면 받는 블록, 시간 이동이면 같은 블록의 뒤 시간대 관점에서 판단한다.
받는 쪽의 상태와 제안된 작업의 부담을 보고 수락/거절한다.
판매·구매가 동의해도 실제 용량·시간 장부 검사를 통과해야 재배정이 확정된다.

### 5. 크레인 역할이 실제 작업을 고른다

작업 처리, 대기, 위치 이동, 미리 상자를 옮기는 재조작 후보에서 고른다.
작업 종류·소요시간·현재 대기·위치를 보고, 충돌하는 후보는 선택 전에 물리 검사로 가린다.
크레인은 사건이 생길 때 결정한다. 60초는 모든 작업 시간을 고정하는 간격이 아니다.

### 6. 실제로 늘어난 비용을 기록한다

60초 경계마다 트럭 체류, 크레인 빈 이동, 재조작, 본선 유휴 비용을 합산한다.
`보상 = −(지금 누적비용 − 직전 누적비용) / 1,000,000`.
비용을 적게 늘리는 선택을 배우게 하는 신호이며, 21블록에 같은 협력 보상을 준다.
판매 손익·구매 손익을 각각 미래 세계로 다시 계산하지 않는다.

### 7. 하나의 모델을 갱신하며 같은 세계를 이어 간다

판매·구매·크레인은 **별도 모델 3개가 아니라 하나의 모델을 공유하는 역할 3개**다.
입력의 역할 표시와 후보가 달라지고, 행동 점수와 앞으로의 보상 추정값을 출력한다.
PPO(실제 경험을 이용해 정책이 한 번에 크게 바뀌지 않도록 갱신하는 방법)는
기본 60개 구간, 즉 시뮬레이션 약 1시간의 경험을 모아 기본 2회 반복해서 학습한다.
행동 점수는 판매·구매별 원화 견적이 아니다. 여러 선택 뒤의 실제 비용으로 공동 학습한다.
30일이면 첫날 준비·2~29일 학습·마지막날 정리·마무리 2시간이다.
매일 모델을 저장하지만 **물리 세계를 이어서 재개하는 저장 파일은 아니다**.

## 해석·한계·예정사항

- 정상 실행 경로를 유지하면서 실패 기록과 조기 중단을 보정했다. 통합형의 성능 우위는 검증하지 않았다.
- 본선 마감 임박에 따라 급증하는 새 비용, 통지창 6시간 확대는 **아직 구현하지 않았다**.
- 기존 30일 실행은 672회 갱신 후 투입 누락 최종 검사에서 실패했다. 날짜별 모델 30개는 보존된다.
- 당시 개별 사유가 저장되지 않아 현재 자료만으로 원인을 확정할 수 없다.
  원본 첫 3일 경계 재현에서 누락이 없었던 사실도 30일 전체 성공을 뜻하지 않는다.
- 연구 판정: 기록 장치의 단기 검증은 통과. 장기 실행 신뢰성은 미통과, 현실성은 미통과, 성능은 미측정.
- 다음은 **같은 YR-306 안에서 원래 30일 입력의 첫 누락을 재현하고 직접 원인을 보정**하는 일이다.
  그래야 빠진 일감을 비용 감소로 오인하지 않고 장기 학습이 정상인지 판정할 수 있다.
  별도 v4 학습이 진행 중이므로 이번에는 무거운 장기 재현을 중복 시작하지 않았다.
