# YR-306 — 공간 부족 시 주문 거절 대신 대기

## 진행사항

- 사용자 지시: "주문 등록 거절 없이 대기를 하게 되니까 비용이 발생하는거야".
- 반입 등록에 기존 용량 거절을 연결했던 판단을 정정했다. 사전등록 `4937302`, 수정 코드 `415e3e7`.
- 이전 실행은 22일차 00:47에 중단됐다. 학습 갱신 480회·정상 등록 125,269건 뒤 반입 1건이 거절됐다.
  당시 Y15 실제 적재 934개, 예약 포함 여유 −36개였다. [중단 기록](failed-run/status.json)을 보존했다.
- 새 고정 명단 실행 경로에서는 이 용량 값으로 주문을 거절하지 않는다.
  번호·출처·시간·장부 검사는 유지하며, 실제 적치 한도와 재배정 확정 제약도 그대로다.
- 최종 관련 검사 **156건 통과**, 실패·건너뛰기 0건, 99.60초. 전체 v5 검사는 아니다.
- 기존 3일 새 파일→실행→학습 갱신→저장 검사도 포함했다. 새 데이터 생성이나 30일 재학습은 하지 않았다.
- 실제 만재 1,440개 시험에서 주문은 대기로 남고 적재량은 한도를 넘지 않았다.
- 같은 트럭의 누적 대기 비용: 실행 600초에 6,000원 → 1,200초에 12,666.67원.
  **10분 더 기다린 비용 6,666.67원이 사라지지 않고 학습 보상에도 반영됐다**는 뜻이다.
- 반출로 자리가 생긴 뒤 같은 번호·같은 최초 도착 시각의 반입이 처리되는 것도 확인했다.
- 934개 적재와 향후 양하 542개로 여유 −36을 재구성해도 반입이 등록됐다.
  이는 해당 계산 조건의 작은 재현이며, 22일차 세계 전체를 다시 실행한 것은 아니다.

## 해석

- 주문 등록은 컨테이너 적치를 뜻하지 않는다. 공간이 없으면 실제 작업이 기다리고 비용이 증가해야 한다.
- 수정 전에는 통지 단계에서 주문을 거절해 정책이 다루기 전에 누락됐다. 지금은 그런 용량 거절을 하지 않는다.
- 적치 가능한 공간·규격·크레인 안전 검사는 없애지 않았다. 공간 부족을 대기로 표현하도록 연결만 바꿨다.
- 대기 비용은 기존 진입 이후 시간 기준이다. 미래 예약 주문에 진입 전 대기비를 임의로 더하지 않는다.
- 시드·정책망·관측 특징·비용 계수·본선 마감·고정 물리 엔진 사본·v3/v4는 변경하지 않았다.
- 검사 도중 오류 1건은 테스트 비교식의 부호 표기 문제였고 수정했다. 개발 실패 XML은 보존했다.
- 정책 비용 개선, 실제 항만의 운송 흐름, 수정 후 30일 전체 실행은 검증하지 않았다.

## 예정사항 — 같은 YR-306 작업

- 다음은 같은 30일 고정 명단으로 주문 누락 없이 끝까지 실행되는지 확인하는 것이다.
  이번 수정이 장기 적체에서도 대기·비용·물리 제약을 유지하는지 알아야 하기 때문이다.
- 이전 단기 실행의 반입 1건 잔여와 장기 잔여 원인도 같은 작업에서 확인한다.
- 다른 세션이 10코어 장기 학습 중이므로 이번에는 CPU 1개 제한 단기 검사만 했다.
  v5 장기 실행은 재시작하지 않았고, 중단된 물리 세계를 이어 실행한 것도 아니다.
