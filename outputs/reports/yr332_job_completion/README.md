# 트럭 비용 종료점을 작업 완료로 변경 — YR-332-af

실제 게이트 진입→작업 완료를 주 지표와 트럭 보상에 적용했다.
작업 완료→게이트 진출은 별도 진단이다. 작업 순서나 실제 사건을 바꾸어 얻은 성능 개선은 아니다.

## 사용자 결정과 구현

2026-11-10: “출차는 늦게 할 수도 있으므로 출차가 아닌 작업 완료로 구분한다.”
기존 코드에도 진입·완료·출차 기록은 있었지만 비용은 출차까지 늘어났다.
이제 작업 완료 C에서 비용 증가를 멈춘다. 관측 끝 T에 미완료이면 T까지 계산한다.
예약 시각을 진입으로 대신 쓰거나 예약 오차를 작업 처리시간에 더하지 않는다.

- 비용·교사의 미래 비용: `reward/phi.py`의 트럭 항을 C 기준으로 전환.
- 통화 없는 PPO 보상: `operational.py`의 물리 시간도 C 기준으로 전환.
- 배열 비용과 월/학습 경계의 입력 전달에 완료 시각을 포함한다.
- 하루·월 결과, 크레인 판정 보고서와 학습 기록에 명확한 완료 기준 열을 추가한다.
- 기존 `mean_turn_time_s`·`n_censored`는 출차 기준 진단으로 보존한다.
- 새 라벨·체크포인트 계약은 `gate-in-to-job-done-v1`; 과거 목적함수의 학습 재개를 차단한다.

PPO 정규화의 고정 눈금은 그대로다. 그 원자료가 과거 출차 기준이라는 사실을 계약에 명시했다.
새 목적함수의 분산으로 눈금을 재보정한 것은 아니다. 다른 비용 계수·정책·입력·물리는 유지했다.
본선 양하/적하의 비용·완료 정의도 이번 트럭 게이트 변경에 포함하지 않았다.

## 같은 작업 기록으로 계산한 결과

시드 9915101, 모든 트럭 예약 존재, 예약 오차의 합성 설정 600초, 최단 실작업 우선 규칙.
관측 창은 24시간이며 엔진은 배수 구간을 포함해 26시간까지 실행한다.
주 평균은 24시간까지 진입한 전건을 분모로 하며 미완료도 그때까지의 관측 시간을 포함한다.

| 하루 주문 | 이전: 진입→출차 평균 | 현재: 진입→작업 완료 평균 | 작업 미완료 | 완료 후 미출차 |
|---|---:|---:|---:|---:|
| 3,500 | 22.3080분 | 17.3283분 | 12건 | 8건 |
| 7,500 | 45.7039분 | 40.7618분 | 73건 | 17건 |
| 15,000 | 153.8324분 | 149.5981분 | 2,276건 | 42건 |

7,500건 조건에서 기존 미출차 90건은 작업 미완료 73건과 완료 후 미출차 17건으로 갈린다.
평균이 약 5분 줄어 보이는 것은 출차 구간을 뺀 정의 변경이다. 학습을 개선한 결과가 아니다.
15,000건은 작업 미완료가 2,276건이므로 위 평균을 전건 완료까지의 평균으로 읽으면 안 된다.

| 하루 주문 | 반입: 진입→완료 평균 | 반출: 진입→완료 평균 | 완료→출차 평균 |
|---|---:|---:|---:|
| 3,500 | 9.6397분 | 22.0808분 | 4.9968분 |
| 7,500 | 16.9955분 | 56.6148분 | 4.9907분 |
| 15,000 | 29.6055분 | 230.5085분 | 4.9916분 |

반입·반출 평균의 분모는 각각 해당 유형의 진입 전건이다.
완료→출차 평균의 분모는 **작업이 완료된 건수**이며, 미출차는 관측 끝까지 계산한다.
두 구간의 평균은 분모가 달라 단순 합산하지 않는다. 동일 진입 집단의 누적 시간으로는
`전체 게이트 체류 = 작업 처리시간 + 완료 후 체류`가 일치함을 확인했다.

## 검증과 재현

- 기존 예약 계약 실험 10회의 장부 85,500행을 새 정의로 독립 재계산했다.
- 세 부하 및 7,500건 반복, 총 4회·33,500건을 실제 재실행했다. 투입 누락 0.
- 모든 실행에서 기존 후보·선택·사건·작업·실행 기록이 정확히 같다.
  원본 전체 출차 지표와 다른 비용 항도 같다. 새 완료 지표·트럭 비용은 별도 장부와 일치한다.
- 7,500건 반복의 결과·주문 기록·다섯 궤적 해시가 정확히 같다.
- 고유 검사 **184개 통과**, 기존 배열 월 실행 불일치 **1개 미해결**이다. 전체 시험 통과라고 하지 않는다.
- 실행 소스 **384개 commit/파일 조합**을 원격에 올라간 commit의 실제 파일과 대조했다.

개발 검사 중 완료 시각이 없던 옛 입력 예제와 “예약은 통지보다 늦다”는 옛 가정의 시험이 실패했다.
전자는 세 시각을 분리한 예제로, 후자는 실제 진입과 통지의 순서를 검사하도록 수정해 재통과했다.
초기 실패 XML도 보존했다. 예약 가정 실패는 변경 전 코드에서도 확인했다.

배열 월 실행 불일치는 변경 전 `a2595188`에서 따로 재현했다.
수정 전후 모두 첫날 배열/CPU 이동 비용 13,257.29/13,663.54, 재취급 268,000/264,000,
본선 유휴 269,553.03/737,257.01로 갈린다. 이번 비용 종료점이 만든 차이가 아니다.
[별도 작업 ah](../../../.claude/docs/dashboard-task-specs/YR-332-ah-array-month-trajectory-parity.md)에 등록했다.
같은 기록의 CPU/배열 비용 계산·완료 시각 전달은 검증했으나 배열 월 실행의 물리 동등성은 미검증이다.
