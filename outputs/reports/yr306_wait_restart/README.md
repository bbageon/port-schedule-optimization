# YR-306 — 주문 보존 수정본 30일 학습 재시작

## 진행사항

- 2026-09-12 사용자 지시로 `4549ae9`의 깨끗한 별도 작업 폴더에서 처음부터 실행했다.
  실제 학습 코드는 주문 보존 수정 `415e3e7` 및 156검사를 통과한 코드와 동일하다.
- 실제 명령행 3일 연결 검사 완료: 트럭 180건·본선 작업 묶음 24개 전부 등록,
  학습 갱신 24회, 반사실 시뮬레이션 0회. 실행 기록 기준 69.09초다.
- 같은 30일 명단의 트럭 177,500건·본선 작업 묶음 288개를 다시 사용했다.
  시드·정책 설정·비용·통지창을 유지했고, 초기 정책 파일도 이전 실행과 바이트 단위로 같다.
- **저장 시점**: 시뮬레이션 2일차 05시, 준비 1일 완료, 학습 갱신 5회,
  주문 5,435건 등록·누락 0건·본선 등록 실패 0건. 첫날 물리 검사 통과.
  이는 현재값이 아니라 `startup/status.json`에 보존한 착수 확인값이다.
- CPU 23 하나·계산 스레드 1개. 다른 세션의 v4 실행은 변경하지 않았다.
- 실행 폴더: `outputs/v5/yr306-wait-30d-4549ae9/`.
  Windows 실행기 번호 39620, WSL 학습 프로세스 번호 2228은 착수 시점 값이다.

## 해석

- 주문 등록과 실제 적치를 분리한 수정본이 명단 읽기부터 학습 갱신까지 연결됐다.
  공간 부족은 주문 삭제 사유가 아니며, 처리 전 대기와 비용이 남는다. 실제 적치 한도는 그대로다.
- 이전 실패 세계나 22일차 정책을 이어 쓰지 않았다. 이전 실패 자료와 새 결과는 별도 보존한다.
- 짧은 검사에서 출고 대상 4,055개는 처리됐으나 반입 1건은 남았다. 그 원인은 아직 미검증이다.
- 시작 확인은 **30일 완주·잔여 작업 없음·성능 개선·실제 항만 타당성**을 입증하지 않는다.
  연구 점검상 기록을 서로 맞춘 착수 증거는 확보했지만, 장기 완주와 현실성은 미통과,
  규칙 대비 성능은 판단 불가로 유지한다. 따라서 현재 허용 범위는 같은 실행의 직접 검증이다.

## 예정사항

- 같은 YR-306에서 22일차 기존 중단 지점 통과와 30일 최종 결과를 확인한다.
  주문 누락·일별 물리 검사·잔여 작업을 함께 확인해야 수정본의 장기 유효성을 판단할 수 있다.
- 실행기는 시간별 상태와 날짜별 정책을 자동 저장한다. 가중치 저장은 물리 세계 재개 기능이 아니다.
