# 여러 컨테이너 트럭 방문 연결 (YR-332-al)

## 결론

한 트럭이 컨테이너 여러 개를 한 번에 처리하는 방문을 합성 입력에 넣었다.
관측 범위 안인 3,500건에서는 정책 대부분의 트럭 시간이 **약 6~16% 늘었다**. 늘어난 몫은 주로 반출이다.
반입을 먼저 내린 뒤 반출을 싣기 때문에, 반출 오더 시간에 앞 정차 시간이 들어간다.
정책 비교 결론은 그대로다. 저장된 학습 모델은 짧은 실작업 우선 규칙(SF_SPT)보다 여전히 느리고, 학습 전보다는 빠르다.

## 진행사항

1. **원자료 정의**(개발용 13일, 블록을 아는 실제 방문 26,501번): 여러 컨테이너 방문 20.3%, 오더의 34.9%.
   같은 유형 2개는 99% 이상 20피트 둘이고, 반입을 먼저 처리한다(같은 블록 1,716 대 21, 다른 블록 반출 먼저 0).
2. **연결 계약**: 차대에는 40피트 1개 또는 20피트 2개, 반입 정차를 마친 뒤 반출 정차, 정차 사이 블록 간 거리만큼 주행,
   마지막 작업 뒤 한 번 출차. 시간대별 오더 수·유형·블록·반출 대상은 ak와 같다.
3. **엔진**: 앞 정차의 마지막 작업이 크레인에 배정되는 순간 다음 정차 도착을 넣는다. 늦게 들어간 도착·출차는 0건이다.
4. **입력 판정**(정책 실행 전, 3,500건): 기준 6개 모두 통과.

| 입력 통계(3,500건) | 실제 | 연결 전(ak ③) | 연결 후 | 20개 시드 평균 |
|---|---:|---:|---:|---:|
| 여러 컨테이너 방문의 오더 비율 | 0.349 | 0 | 0.333 | 0.332 |
| 블록별 오더 1분 몰림 지수 | 1.232 | 0.996 | 1.242 | 1.216 |
| 트럭 방문 1분 몰림 지수 | 1.266 | 1.309 | 1.268 | 1.293 |
| 트럭 방문 10분 몰림 지수 | 1.182 | 1.184 | 1.159 | 1.164 |

몰림 지수 = 같은 길이 구간별 도착 수의 분산÷평균(무작위면 약 1). 크레인이 보는 블록별 몰림이 실제 수준으로 올라왔다.
7,500·15,000건은 시간당 방문이 실측 최대(245번)를 넘어 민감도 조건이다.

5. **정책 비교 44회**: 연결 후 39회, 연결 전 재실행 3회(ak 저장 결과와 비트 일치), 반복 2회(비트 일치).
   연결 전 나머지 36회는 ak 저장 결과를 그대로 썼다.

## 결과

오더별 게이트 진입→그 작업 완료 평균(분, 24시간 검열). 학습 전·후는 모델 3개 평균이다.

| 정책 | 3,500건 연결 전→후 | 7,500건 | 15,000건 | 세 물량 합산(오더 가중) |
|---|---|---|---|---|
| 짧은 실작업 우선(SF_SPT) | 19.702→22.510 (+14.25%) | +7.83% | +1.55% | 81.065→83.158 |
| 학습 전 | 24.603→26.829 (+9.05%) | +2.20% | −1.99% | 111.045→109.592 |
| 학습 후(ag 저장 모델) | 23.044→25.133 (+9.07%) | +4.76% | +1.38% | 96.223→98.102 |
| 먼저 도착 우선(FIFO) | 19.357→21.051 (+8.75%) | +4.63% | +0.61% | +1.07% |
| 남은 작업 적은 것 우선(LWKR) | 19.335→20.504 (+6.05%) | +7.82% | −0.84% | −0.09% |

3,500건 SF_SPT는 반입 +6.56%, 반출 +16.63%가 늘었다. 정책 9개의 양하·적하 변화는 3,500건에서 −1.19~+1.13%로 거의 같다.

| 학습 후 모델 비교 | 연결 전 | 연결 후 |
|---|---:|---:|
| SF_SPT 대비(세 물량 합산) | +18.70% | +17.97% |
| SF_SPT 대비(3,500건) | +16.96% | +11.65% |
| 학습 전 대비(세 물량 합산) | −13.35% | −10.48% |

양수는 더 오래 걸린다는 뜻이다. 7,500건에서는 연결 후 학습 후 모델이 학습 전보다 +1.26% 느렸다.

방문 단위로 보면 연결 후 SF_SPT의 진입→마지막 작업 완료는 평균 92.921분, 진입→출차는 97.435분이다(세 물량 합산).

## 해석

- **블록별 몰림이 실제 수준이 되자 트럭이 실제로 느려졌다.** ak에서 게이트 몰림만 바꿨을 때는 블록으로 흩어져 영향이 작았다.
  이번에는 같은 트럭의 컨테이너가 한 블록에 함께 도착하고, 다른 블록 방문은 앞 블록 작업이 끝나야 출발한다.
- **반출이 가장 크게 늘었다.** 반입+반출 방문은 반입을 먼저 내리므로, 반출 오더 시간에 반입 정차가 더해진다.
  주 지표(오더별 진입→완료)의 정의는 그대로이므로, 이 증가는 측정 정의가 아니라 환경 변화다.
- **정책 순위는 거의 그대로다.** 합산 1위는 SF_SPT, 3,500건 1위는 LWKR(연결 전후 같음)이다. 물량별 입력이 하나라 우열로 쓰지 않는다.
- **학습 모델의 격차가 줄어든 것을 학습 개선으로 읽지 않는다.** 저장 모델은 연결 없는 입력으로 학습했다.
  규칙이 더 많이 느려져서 격차가 줄었다. 연결 입력으로 다시 학습하는 비교는 YR-332-aq에서 한다.
- 게이트 판정: 신뢰성은 검산으로 확인한다. 현실성은 운반(i)·대기열 정의(f)·날짜 변동(ao)·고물량 몰림(ap)이 남아 미통과이고,
  성능은 새 학습이 없어 판단 보류다.

## 검증

- 트럭 691,000행·전체 작업 964,472행을 시각에서 다시 계산했다. 방문 57,125개의 정차 도착 118,093건이
  "앞 정차 마지막 완료 + 이동"과 같고, 끝난 방문 48,790개의 출차가 하나다. 늦은 도착·출차 0건.
- 연결 전 재실행 3회는 ak 결과·트럭 행·후보·선택·사건·작업·기록 해시가 같다. 반복 2회도 같다.
- 시험 188건 통과. 실행 코드 `3f1caa0b`, 동결 `720e43c0`.
- 실행 중 정정 1회: 24~26시간 공통 시각이 기록 동기화까지 불러 장부 검사에서 멈췄다. 시계 맞춤만 하도록 고치고 재동결했다(정의·기준 불변).

## 한계

- 물량별 입력 하나, 개발용 13일로 만든 분포다. 독립 검증이 아니다.
- 20피트 반입 1개+반출 1개는 실제로는 동시에 실을 수 있는데 반입 먼저로 처리했다.
- 다른 블록 방문의 블록 쌍(가까운 블록끼리 묶이는 경향)은 반영하지 않았다.
- 블록 대기 수 특징은 트럭이 아니라 기다리는 오더 수를 센다(f와 겹침).
