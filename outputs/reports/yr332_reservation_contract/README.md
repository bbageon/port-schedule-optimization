# 전건 예약 합성 시드·예약/실제 진입 분리 검증

2026-11-10 · 작업 YR-332-ad. **모든 트럭 오더에 예약이 있다는 합성 연구 조건을 적용했다.**
예약 정보의 정확도만 바꾸었고, 물량·실제 도착·본선 계획·정책·비용 수식은 유지했다.
새 학습이나 현장 효과 검증은 아니다. [검산 원값](verification.json) · [생성 검사](generation.json).

## 지금 시드는 어떻게 만드는가

- 트럭 실제 진입은 24시간 합성곡선에서 뽑는다. 10시·15시 중심 봉우리와 21시 보정 봉우리,
  전 시간대 기본 물량이 있다. 본선 적하·양하는 별도 본선 계획을 따른다.
- 모든 트럭 오더에 유효한 예약 시각을 저장한다. 새 규격의 누락·비정상 시각은 거절한다.
- 실제 진입 A를 고정하고 공개 예약 R = A − 오차를 생성한다. 오차는 시드로 한 번만 뽑는다.
  이 방식은 실제 물량을 그대로 두고 예약 정보의 정확도만 비교하기 위한 합성 설계다.
- 기본 오차의 표준편차(흩어짐의 설정)는 10분, 범위는 ±20분이다.
  기존 `TerminalStreamParams.appt_adherence_sigma_s=600`을 명시적으로 적용한 것이며 **실측값이 아니다**.
  정규 표본을 양끝에서 제한하므로 실제 표본 표준편차가 정확히 10분이라는 뜻도 아니다.
- 정책에 알려 주는 블록 도착 예상 = 예약 + 기준 주행시간.
  실제 블록 도착 = 실제 게이트 진입 + 실제 주행시간. 실제 실행 기록은 사건 이후에만 채운다.
- 트럭 체류 비용은 계속 실제 게이트 진입→출차로 계산한다. 예약 오차를 대기 비용에 더하지 않는다.
- 새 하루 경로와 이를 잇는 월 경로, 고정 입력의 저장·복원이 같은 계약을 보존한다.
  기존 무표식 저장 입력은 예전 완전 예측 조건으로 재현한다. 기존 입력을 몰래 새 조건으로 바꾸지 않는다.

## 검증 결과

| 검사 | 결과 | 뜻 |
|---|---:|---|
| 3부하 × 3시드의 서로 다른 물리 오더 | 78,000건 | 원본 수요를 고정했다 |
| 오차 0/10/30분 조건의 생성 검사 | 27조건·234,000행 | 예약은 전건 존재, 실제 도착·주행·본선·적재 계획 불변 |
| 같은 조건 재생성 | 27조건 정확 일치 | 각 조건을 다시 만들어도 같은 명단이다 |
| 하루 실제 실행 | 10회·85,500건 투입 | 변경 전 3회 + 변경 후 6회 + 반복 1회, 누락 0 |
| 오차 0으로 과거 조건 재현 | 3부하 전부 정확 일치 | 후보·선택·사건·완료 상태·실행 기록·비용 보존 |
| 오차 10분의 7,500건 반복 | 정확 일치 | 선택·사건·기록·비용이 다시 같았다 |
| 관련 검사 | 고유 218건 최종 통과 | 예약 분리·시각·복제·저장·날짜 연결·기존 경로 확인 |
| 실행 소스 대조 | 373개 commit/파일 조합 일치 | 실행 때 기록한 코드가 push된 각 commit의 내용과 같다 |

생성 검사에서 30분은 예약 오차 설정만 바꾼 민감도 조건이다. 하루 전체 실행은 0분·10분만 비교했다.
10분 조건의 평균 절대 오차는 7.779분이었다. 원본 78,000건 중 예약이 관측창 전인 88건,
관측창 뒤인 82건도 보존했다. 원시 통지보다 예약이 먼저인 7,732건도 버리지 않았다.
예약·통지 관계는 기존 통지→실제 도착 표본을 유지한 합성 가정이며 실측 결합분포는 아니다.

## 같은 규칙에서 정보 조건을 바꾼 결과

최단 실작업 우선 규칙과 시드 9915101을 고정했다. 모델을 학습하지 않았다.
평균은 **24시간 끝까지 관측한 체류**이며, 그때 미출차인 트럭은 24시간까지만 합산했다.
따라서 모든 트럭이 최종 출차할 때까지의 평균보다 작거나 같다.

| 하루 물량 | 기존 평균(분) | 변경 평균(분) | 평균 변화 | 24시간 미출차: 기존→변경 |
|---:|---:|---:|---:|---:|
| 3,500 | 22.2001 | 22.3080 | +0.4860% | 19→20 |
| 7,500 | 45.8501 | 45.7039 | −0.3187% | 56→90 |
| 15,000 | 153.8325 | 153.8324 | −0.0001% | 2,374→2,318 |

변화는 작고 방향도 일정하지 않다. 7,500건에서 평균이 조금 줄어도 미출차가 늘었으므로
“운영이 좋아졌다”고 판단할 수 없다. 목적은 정보 계약의 교체와 수요·장부 보존 확인이다.

## 확인 범위와 남은 항목

- 신규 예약 계약과 실행 기록 정합성은 통과했다. **실제 항만 보정·강화학습의 규칙 대비 우위는 미확인**이다.
- 사용자 가정에 따라 미예약·예약 누락·노쇼는 합성 시드에서 제외한다.
- 실제 지각의 치우침·긴 꼬리, 예약과 통지의 관계 보정은 부모 YR-332-f에 남는다.
- 기존 통지 처리의 60초 내림 격자도 유지했다. 원시 접수 시각보다 최대 60초 일찍
  작업이 생성될 수 있는 근사는 f의 별도 정보시점 보정이며, 정확한 통지 시각을 검증했다고 주장하지 않는다.
- 기존 양하 운반 실측 보정(YR-332-i)은 그대로 남는다. 연구 전체의 현실성·성능 게이트를 통과시키지 않는다.
- 현재 CPU 연구 경로에 적용했다. 별도의 배열/GPU 경로는 오차 있는 예약을 지원하지 않아
  명시적으로 거절한다. 오차를 0으로 지정한 과거 동등성 조건은 유지·검사했다.
- 초기 회귀 검사에서 기존 시험이 예약을 실제 진입으로 찍는 가정을 발견해 고쳤다.
  최초 실패 XML을 보존했으며 해당 시험은 후속 실행에서 통과했다.
- 별개 v5 생성 명령 검사 1건은 Windows에 `os.sched_getaffinity`가 없어 실행 실패했다.
  현재 연구 경로의 기능 실패와 분리해 YR-332-ae에 등록했다. v7 입력 직접 생성·저장·복원 검사는 통과했다.

- `tests-*.xml`: 테스트 원기록. `verification.json`은 최종 통과 상태와 최초 실패를 함께 기록한다.

```powershell
$env:PYTHONPATH='src;scripts/v7'
$env:PYTHONIOENCODING='utf-8'
..\yr331-env\Scripts\python.exe scripts/v7/verify_reservation_contract.py --operation verify
```

`verify`는 저장 자료를 읽어 체류·비용 합계·미출차·정확 재생·소스 commit을 다시 대조한다.
새 실행은 별도 checkout에서 `generate`/`evaluate`를 사용한다. 현재 실행기는 기존 원자료 덮어쓰기를 거절한다.
과거 기준의 신규 실행은 기준 commit에서 `baseline`을 사용한다. 수정 후 코드에서 기준 실행을 사칭하지 못하게 거절한다.
