# 운반 흐름·대기 수 원본 재확인

2026-11-18 · YR-332-i(운반 흐름 보정), YR-332-f(트럭 정보 현실화).

**값은 원본까지 추적됐지만 시간·집계 정의는 아직 미확정이다. 특히 게이트 진입 시각 601건은 원본 사건 시각으로 확인되지 않았다.**
이번 작업은 자료 감사다. 운반·정책·보상·기존 보정값을 변경하거나 새 학습·성능 평가를 실행하지 않았다.

## ① 진행사항

### 원본 전달 검증

| 대조 대상 | 결과 | 의미 |
|---|---:|---|
| 사용자 제공 원본 | 600파일·452,795,529바이트, 이전 hash와 모두 일치 | 새 운반 자료는 추가되지 않음 |
| 원본 로그 | 444,429줄, 대기 수가 있는 메시지 54,245개 | 여러 전달 경로가 같은 사건을 중복 기록함 |
| 사건 표의 대기 수 | 48,620/48,620건 원본 값 확인 | 값이 가공 중 달라졌다는 증거 없음 |
| 방문 표의 게이트 대기 수 | 34,301/34,301건 사건 표와 일치 | 컨테이너 오더 단위 행이며 실제 트럭 대수와 구분 |
| 본선 목록 | 263개 CSV/JSON 쌍·291,499행의 5개 필드 일치 | 작업 구분·컨테이너 키·세 시각의 전달 검증 |
| 기존 예약 보정 자료 | 반입·반출 표본 빈도 전체 재현 | 새 감사가 기존 보정 자료를 정확히 재구성함 |

대기 수가 있는 사건은 게이트 진입 34,301, 블록 진입 9,048, 작업 완료 4,785, 위치 변경 486건이다.
따라서 ‘게이트에서만 측정한 대기 수’라고 단정할 수 없다. 어느 집단을 센 값인지는 별도 문제다.

### 새로 확인한 시간 근거 문제

- 대기 수 원본 메시지에 사건 시각이 없는 600개 사건은 CSV의 사건 시각이 로그 시각과 맞는다.
  그중 2건은 별도 GateIn 요청의 실제 시각으로도 확인된다. 남은 **598건**은 해당 근거가 없다.
  대기 수가 없는 3건도 원본 사건 시각으로 확인되지 않았다. GateIn 34,304건 전체에서 **601건**이다.
- 이 601행에는 이후 블록 진입·작업 완료·출차 기록도 없다. 물리적 입장이 있었다고 확정하면 안 된다.
  원자료 오류 응답과 재처리 여부의 뜻을 확인해야 한다. 사건을 임의 삭제하거나 실제 진입으로 승격하지 않았다.
- 사건 표 로그 시각과 대기 수를 담은 원본 메시지의 로그 시각이 다른 경우는 617건이다.
  616건은 원본 대기 메시지가 1초 늦고, 1건은 21초 늦다. 관측값의 실제 생성 시각을 입증하지는 않는다.
- 같은 사건 키에 서로 다른 대기 값이 붙은 원본도 있다. 서로 다른 시점의 재전달일 수 있으므로
  이번 검사는 원본 값의 존재를 확인하며, 최초 공개 시각·최신값 선택 규칙까지 검증했다고 주장하지 않는다.

중앙값 변화가 작아 보여도 학습 성능 변화가 작다는 뜻은 아니다. 위 표는 표본 제외의 기술통계이며 재학습 결과가 아니다.
도착 몰림에 쓰는 기존 방문 묶기에서는 601행 중 578행이 앞선 재처리 기록으로 이미 묶였고,
23행은 27,415개 방문 중 23개 방문에 남아 있었다. 날짜·분별 입력도 영향을 따로 확인해야 한다.

### 본선·운반 시간

양하 `atw`→최초 야드 시각은 150,992건, 중앙 13분이다. 음수 1건도 그대로 남겼다.
적하 마지막 야드 시각→`atw`는 136,571건, 중앙 24분이다. 이전 감사 수치와 일치한다.
`atw` 287,603건 모두 초 부분이 0이다. 이 자료로 개별 크레인의 초 단위 서비스시간을 추정하지 않는다.
이 간격은 운반·대기·작업이 섞일 수 있으며 `atw`의 물리적 단계가 미확정이다.

## ② 해석

현재 정책의 대기 수는 **블록 도착 후 작업 시작 전 외부 트럭 오더 수**다.
[ChainPortal 공식 매뉴얼](https://www.chainportal.co.kr/manual/download?filename=ChainPortal_APP_Manual.pdf) §4-1-3은 지정 블록의 대기 차량을 표시한다고 설명하지만,
차량/방문/오더의 구분, 작업 중 포함 여부, 관측 시각을 정의하지 않는다. 작업 시작 기록도 없어 동일성 검증이 남는다.

[DGT 공식 장비 소개](https://www.dgtbusan.com/DGT/terminal/equipment)는 안벽크레인 1기당 운반차 5대,
블록당 야드크레인 2기의 육측·해측 분리를 설명한다. H-21 합성 모형은 블록당 운반차 3대다.
서로 다른 터미널·자원 배정 단위이므로 3을 5로 바꾸는 보정은 타당하지 않다.
현재 470초도 요청→화물 도착·차량 재사용을 묶은 합성 설정이며 위 13분/24분으로 대체할 수 없다.

- **기록 대조**: 원본 값 연결과 기존 보정 재구성은 확인. 시간 근거 한계 601건을 명시한다.
- **현실성**: 미통과 유지. 실제 진입 시각, 대기 수 집계 정의, 내부 운반 연결 기록이 남는다.
- **성능**: 이번에는 측정하지 않음. 이전 모델 성능 악화의 원인을 이 감사로 확정하지 않는다.

이 결과는 이전 az의 예측 시험 기준을 변경하거나 PPO 재학습을 허용하는 판정이 아니다.

## ③ 예정사항

- **YR-332-ba(실제 진입 시각 근거를 확인한 표본으로 보정 분리)**: 미확인 시각을 로그 시각과 구분하는 입력 검사를 만들고,
  기존 보정을 덮어쓰지 않는 새 자료로 비교한다. 기존 보정에 미확인 344건이 들어간 것이 직접 근거다.
- **YR-332-f(대기 수 정의 확인)**: 자료 제공처의 집계 대상·작업 시작 시각을 확인한다. 같은 대기열끼리 비교하기 위해 필요하다.
- **YR-332-i(운반 흐름 보정)**: 작업 시각의 단계와 차량별 적재·인계·귀환 기록을 확인한다. 운반 숫자만 바꾸는 오류를 막기 위해 필요하다.

[필요한 최소 정의·자료](../../../docs/research/v7-discharge/transport-queue-data-contract.md)를 작성했다. 외부 발송은 하지 않았다.
