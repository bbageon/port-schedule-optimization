# 실제 트럭 방문 단위와 시간대 안 도착 몰림 보정 후 고정 정책 비교

시간대 안 도착을 실제 트럭 방문처럼 몰리게 바꿔도 평균 트럭 시간은 정책마다 +0.20~+2.56%만 변했다(전체 평균).
학습 후 모델은 SF_SPT보다 +17.93% → +18.70% 길고, 학습 전보다 -14.21% → -13.35%이다. 결론은 바뀌지 않았다.
게이트에서 몰린 트럭은 21개 블록으로 흩어져 각 크레인에 거의 무작위로 도착한다(블록별 1분 몰림: 합성 0.94~1.05, 실제 트럭 방문 0.99).
실제 블록별 오더 몰림(1.23)은 한 트럭이 같은 블록에 컨테이너 여러 개를 가져오는 효과로, 별도 연결 축(al)이다.
저장 모델과 규칙을 고정한 환경 민감도 진단이며, 새 학습·현장 성능 주장이 아니다. 백분율의 +는 시간이 더 길다는 뜻이다.

## 1. 원자료에서 확인한 단위

| 항목 | 확인 결과 | 이번 처리 |
|---|---|---|
| `visit_id` | 진입 34,304건 모두 `진입시각_트럭_컨테이너_방향` = 오더 키 | 트럭 지표는 오더별 진입→작업 완료 유지 |
| 게이트 재처리 기록 | 사건 없는 기록 뒤 30분 안 재진입 850개(같은 컨테이너 716) | 뒤 기록에 붙여 실제 방문 27,415번 |

합성 트럭 한 대를 실제 방문 한 번에 대응시켰다. 실제 오더 단위 몰림에는 한 트럭의 여러 컨테이너가 같은 시각에 찍힌 효과가 들어 있다.

## 2. 도착 몰림: 실제와 합성 입력

몰림 지수는 각 시각 안 같은 폭 구간 건수의 분산/평균이다. 1이면 무작위 도착, 클수록 몰린다.
간격 변동계수는 시간당 물량으로 나눈 도착 간격의 들쭉날쭉함이다(무작위 1).

| 실제 방문 | 13일 | 1.266 | 1.182 | 1.176 | 0.336 |
| 실제 오더(참고) | 13일 | 1.772 | 1.788 | - | - |

③의 3,500건은 1분·10분 몰림을 맞췄고, 간격 변동계수는 기준(1.176±0.10)을 0.003 넘겨 공개한 한계다.
7,500·15,000건은 실제 날짜를 여러 개 겹쳐 몰림이 실측보다 커진다. 실측 보정이 아니라 강한 몰림의 민감도 시험이다.
실제 반입·반출 상관에는 한 트럭의 반입+반출이 들어 있어 이번 축으로 맞추지 않았다.

## 3. 크레인이 보는 도착: 블록별 몰림

같은 지수를 날짜·시각·블록별로 나눠 쟀다. 무작위로 흩어지면 1분 0.983, 10분 0.833이 기대값이다.

|---|---:|---:|
| 실제 오더 | 1.232 | 1.013 |
| 실제 트럭 방문 | 0.991 | 0.805 |
| ① 고른 간격(aj) (3,500/7,500/15,000) | 0.954/0.956/0.942 | 0.795/0.818/0.857 |
| ② 무작위 간격 (3,500/7,500/15,000) | 0.988/0.984/0.986 | 0.823/0.865/0.877 |
| ③ 실제 방문 몰림 (3,500/7,500/15,000) | 0.996/1.016/1.054 | 0.851/0.869/0.937 |

합성 무대는 블록을 도착 시각과 무관하게 정하므로 게이트 몰림이 블록마다 묽어진다.
실제 자료도 트럭 방문 단위로는 블록별 도착이 무작위 수준이다. 남은 차이는 같은 트럭의 여러 컨테이너다.

## 9. 사전등록 정정 경위

- 처음 등록한 무작위 날짜 순서는 3,500건 간격 변동계수에서 0.003 미달했다.
- 수정안(방문이 가장 많은 날짜부터)은 몰림이 컸던 시각을 고르는 선택 편향으로 1분·10분 몰림이 미달했다(10분 1.577).
- 두 결정 모두 정책 실행 전, 입력 통계만 보고 내렸다. 수정안을 기각하고 원래 방법으로 되돌렸다.

## 10. 검증과 한계

- 평가 120회(고유 117·반복 3), 조건 ① 39회는 aj 저장 결과와 비트 단위로 같다.
- 트럭 장부 1,036,500행·전체 작업 1,446,708행을 저장 시각에서 다시 계산했다. 관련 시험 84건 통과.
- 실행 코드 `639c34bf`, 코드·설정·가중치 212개 해시 확인. 본선 계획은 세 조건에서 같다.
- 물량별 입력이 하나다. 통계적 확증·실제 터미널 성능을 주장하지 않는다. 13일은 개발용 자료다.
- 남은 축: 여러 오더 방문의 연결, 날짜 간 물량 변동, 반입/반출 시간대 결합, 본선 운반(i), 대기열 정의(f).
- CPU 하루 실행의 명시적 옵션이다. 월/배열 경로에는 연결하지 않았다.
