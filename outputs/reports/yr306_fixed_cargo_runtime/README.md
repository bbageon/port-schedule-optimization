## 연결 구조와 해석

1. 고정 파일에서 초기 상자와 전체 주문을 읽는다. 파일 검증값·시드·날짜를 먼저 검사한다.
2. 모든 출고는 지정 상자 번호를 유지한다. 아직 적치되지 않았으면 주문을 등록하고 기다린다.
3. 실제 적치가 끝나야 크레인이 그 상자를 반출·선적할 수 있다. 다른 상자로 대체하지 않는다.
4. 반입 배정 블록이 바뀌면 같은 상자의 후속 작업도 따라간다. 이미 온 트럭은 추가 주행을 기다린다.
   최초 도착 시각과 누적 비용은 보존한다. 날짜별 검색 기록 정리 후 이동도 검사했다.
5. 다른 블록에서 선적 상자를 처리해도 원래 본선의 운반 자원으로 연결한다. 배나 비용을 복제하지 않는다.
6. 블록 간 물리 사건을 시간순으로 처리하되 정책 학습은 기존 60초 경계를 유지한다.

이는 새 학습 규칙이 아니라 고정 컨테이너의 실제 실행 연결이다. 30일 동안 준비 1일·학습 28일·정리 1일을
하나의 물리 세계에서 이어 간다. 마지막에는 기존 2시간 잔여 처리 구간을 둔다.

물리 연결 검사가 통과했다고 비용 개선이 입증된 것은 아니다. 작은 시험의 미완료 반입 1건도 남겼다.
실제 거리별 본선 운반시간, 수입·수출별 화물 흐름, 장기 점유율의 실측 보정도 미완료다.

- 새 30일 실행의 일별 저장·누락·실제 재고·잔여 작업을 확인한다. 긴 실행에서 같은 계약이 유지되는지 보기 위해서다.

- 기록 일치·현실성·성능 판정이 모두 통과하기 전 새 정책 가설로 넘어가지 않는다.
