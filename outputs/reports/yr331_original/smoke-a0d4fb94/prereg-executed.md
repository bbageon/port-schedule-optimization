# YR-331-f — 원본 배정 유지 대비 재배정 효과 재평가

- **상태**: in-progress
- 사용자 지시(2026-09-29): “아니 재배정 전 원본기준으로 해야지”.
- 무엇: 최초 위치·예약 시각을 유지한 운전과 판매·구매를 허용한 운전을 같은 크레인 정책으로 비교한다.
- 왜: e의 KEEP+SF-SPT 비교는 재배정과 크레인 작업 선택 방식이 함께 달라, 재배정 효과만 보여 주지 않는다.
- **3대 게이트 보정 대상: reliability** — 사용자 의도·비교 계약·결과 설명의 정합을 바로잡는다.
- 범위: 저장된 운영 보상 모델의 평가만 수행한다. 재학습·보상·원입력·환경 물리 변경은 없다.

## 원본의 의미와 한계

현재 `fixed_cargo_seed.v2`는 최초 블록·예약 시각·컨테이너·본선 계획·초기 재고를 보존한 입력이다.
실제 크레인 작업 순서와 완료 시각은 저장하지 않으며 `ExecutionRecord`는 빈 상태로 시작한다.
따라서 원본 비용을 파일에서 바로 읽거나 예약 시각을 완료 시각으로 간주하지 않는다.
별도 실행 이력이 확인되지 않는 한 **원본 배정 유지 + 동일한 학습 크레인 정책**을 대조군으로 사용한다.
이는 실제 TOS 원본 실행 기록 재생·정책 전체 개선의 증거가 아니라 같은 크레인 정책 아래 재배정 효과의 진단이다.
외부 원본 실행 기록의 의미인지 사용자에게 확인 질문을 전달했으며, 기본 해석은 현재 시드의 최초 배정이다.

## 실행 전 고정 계약

1. e의 운영 보상 최종 모델 3개를 그대로 쓴다: 학습 입력 9931000/9941000/9951000.
2. 평가 입력 9961000/9971000/9981000의 기존 파일·원래 전체 3일을 그대로 복원한다.
3. 모델별 `original`(판매 KEEP·구매 REJECT), `reallocated`(동일 모델의 판매·구매 허용) 두 실행, 총 6회다.
4. 두 실행 모두 같은 학습 크레인 정책·가중치·추첨 선택을 유지하고 학습 갱신은 0회다. SF-SPT는 부르지 않는다.
5. 첫날 `[0,86400)`은 두 실행 모두 원본 배정을 유지하는 공통 연결 구간이다. 첫날 물리 기록이 같아야 한다.
6. 둘째 날부터 처리 끝까지 `reallocated`만 재배정을 허용한다. 주 측정창은 `[86400,172800]`, 잔여는 259200초다.
7. 판매 추첨 유무가 크레인 추첨 난수까지 바꾸지 않도록 역할별 고정 난수열을 두 실행에 동일하게 적용한다.
   이는 평가의 난수 결합 방식만 고정하는 장치이며, 가중치·행동 확률·학습 알고리즘 변경이 아니다.
8. 원본 배정 유지 실행은 최종 원본 오더 6필드 일치·공간/시간 거래 0건을 실제 기록으로 검사한다.
9. 입력·모델·보상 기준의 파일 지문을 양쪽에서 비교한다. 전건 투입·물리 제약·모델 동결을 검사한다.
10. e의 고정 정규화 네 항을 동일하게 사용한다. 주 결과는 `100×(1−재배정 점수/원본 유지 점수)`다.
11. 네 물리 지표·최초 요청부터의 누적시간·트럭/본선 잔여도 함께 보고한다. 미완료는 현재까지 포함한다.
12. 진단 개선은 평균 점수 감소 및 각 쌍의 요청시간·잔여 비악화가 모두 필요하다. 3쌍으로 통계적 확증을 주장하지 않는다.
13. e의 과거 규칙 대비 −16.47% 결과는 해당 비교의 역사적 사실로 보존하고, 원본 대비 재배정 효과로 재해석하지 않는다.
14. 과거 수치를 재사용하지 않고 양쪽을 다시 실행한다. 결과를 보고 시드·모델·반복 수·가중치를 바꾸지 않는다.
15. 관련 단위 검사 후 깨끗한 코드 커밋에서 CPU·스레드 1개·동시 최대 2개로 실행한다. 실패 기록도 보존한다.

## 증거와 후속

- 기존 e 판정에 `authorize-next --target reliability`를 실행했으나, 당시 신뢰성은 통과로 저장돼 있어 허용되지 않았다.
  그 판정은 과거 규칙 비교의 재현성이고 이번 사용자의 원본 비교 요구에 대한 판정은 아니다.
  사용자 직접 지시에 따라 비교 계약 정정·진단 평가만 수행하며, 기존 현실성 실패나 성능 채택 상태를 통과로 바꾸지 않는다.
- 실행 계획·코드·원자료·결과는 `outputs/reports/yr331_original/`에 보존한다.
- 기존 공용 성능 판정은 원화·SF-SPT를 요구하므로 이 원본 기준 진단에 그대로 적용해 통과시키지 않는다.
- 현실성 미통과와 검증 입력 공급 부족은 승계한다. 작업 후 다음은 c(공급 부족 복구)→a(독립 수용 상한 확인)다.
