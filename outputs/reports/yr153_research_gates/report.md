# YR-153 — 연구 진행 3대 게이트 하네스 보고

## ① 진행사항

앞으로 모든 판정 실험에 공통으로 붙일 세 게이트를 구현했다.

- **성능**: 후보−규칙의 반올림 전 신뢰구간, 검정력, 완주·본선 보호 가드를 함께 판정한다.
- **신뢰성**: 실행 commit·시드·설정·파일 hash를 남기고, 완료 후 Dashboard·spec·각 증거 파일이
  실제 원격 commit에 들어 있는지 다시 대조한다.
- **현실성**: 물리·정보누출·장부와 지속 유입 흐름, 실제자료 등급을 분리한다.
- **진행 통제**: 미통과가 있으면 관련 보정만, 전부 통과하면 목표 확증만 허용한다.

코드 감사에서 기존 공용 평가기가 표시용 3자리 신뢰구간으로 판정하던 결함도 찾아 원정밀도로
수정했다. YR-149의 row·spec·코드 경로·원격 commit은 일치했지만, 실행 원자료에
`git_dirty=true`, 전체 설정 `{}`, 사전등록 파일 경로 누락이 남아 있어 **신뢰성 전체는 실패**로 판정했다.

### 2026-08-06 갱신 — YR-151 0A 보고로 신뢰성 **실패 → 통과**

0A 원자료(`yr151_pre_gate_0a/contract_0a.json`)를 `yr151_gate_report.py` 로 하네스에 올려
신뢰성 축 셋을 다시 돌렸다: 실행 재현 사슬(`judge_runtime_evidence`) **통과**,
board·spec·증거 대조(`audit_dashboard`) **통과**, 보고 수치 ↔ 원자료 대조
(`judge_claim_alignment`, 12개 값 절대차 0) **통과** → `combine_reliability` = **PASS**.
위 세 실패 사유는 각각 clean commit(`87d5688`, `git_dirty=false`), 구체 설정값
(창 1800초·이송 상한 1·주행 300초·route delta 0·셀 5종), 사전등록 **파일 경로+sha256** 으로 닫혔다.

**재발행(2026-08-06 후반)**: 사용자가 board 를 21블록 계약으로 재정리하며 YR-151 row 가
`ready → backlog` 로 이동하자, 저장돼 있던 신뢰성 PASS 가 `authorize-next` 재계산에서
**`저장된 dashboard PASS 재계산 실패`** 로 막혔다. 저장 JSON 의 PASS 를 그대로 믿지 않고
판정 당시 board 상태에 고정해 다시 계산하는 fail-closed 설계가 의도대로 작동한 것이다.
임계를 낮추지 않고 **같은 검사를 새 board 상태(`backlog`)·새 commit(`24f3fc8`)으로 재실행**해
PASS 를 다시 받았다. 절차는 `research-gates.md` §2 에 박제.

정직 기록 하나: 0A 원자료의 `self_sha256` 은 그 필드를 써넣기 **전** 파일의 해시라
자기검증이 되지 않는다(기록 `4862ae71…` vs 실제 파일 `c287a9d5…`). 게이트에는 실제
커밋된 파일 해시를 고정했고, 스탬프 규약 자체는 후속 정정 대상으로 남긴다.

## ② 해석

현재 세 항목의 답은 다음과 같다.

| 질문 | 현재 판정 | 쉬운 뜻 |
|---|---|---|
| 성능이 증가했나 | **미확정** | 사전 이동을 빼는 개선은 확인했지만, 최종 정책 전체가 지속 운영에서 SF-SPT보다 싼지는 아직 안 재봄 |
| Dashboard와 코드가 맞나 | **통과**(2026-08-06) | 0A 는 깨끗한 커밋에서 돌았고 설정·시드·사전등록·산출물 해시가 다 남았으며 board·spec·증거가 원격 commit 과 일치 |
| 시드가 실제 가능한가 | **미확정** | 유한 물량 시드는 내부적으로 가능하지만, 계속 들어오는 정상 운영과 실제 운영자료 대조가 아직 없음 |

따라서 현재는 여전히 성능 개선을 주장할 수 없다. YR-149 숫자는 자격 진단 참고로 보존하되,
앞으로의 판정런도 0A 와 같은 재현 스탬프를 남겨야 한다. 또한 50·75·100·125·150을 곧바로 실제 항만의
양호·보통·혼잡 등급이라고 부를 수도 없다. 지금 확정된 것은 문헌 보정 시뮬레이션에서 부하
불균형을 만들 수 있다는 것까지다.
