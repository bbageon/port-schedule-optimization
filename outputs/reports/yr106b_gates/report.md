# YR-107·108·110 + YR-105-b 착수 4게이트 (2026-07-28)

사용자 피드백 순서대로 전부 집행했다. 7축 병렬 정찰(읽기 전용) → 구현 → 판정런.
**정찰이 브리핑을 반증한 곳이 여러 곳**이라 그때마다 설계를 고쳤다 — 아래에 함께 남긴다.

## 1. YR-107 — 오라클을 배포 가능 정책으로 표기한 문제

**확증**: `_rollout_cost`(baselines.py:163)는 sim 을 deepcopy 해 실제 엔진으로 굴린다.
그 사본의 큐에는 엔진이 `actual_block_arrival`(**진짜** 도착)로 넣은 이벤트가 그대로 있다.
실측(high-tight/830700): 1800초 창의 트럭 9대를 전부 정확한 시각으로 실현했고,
같은 순간 정책이 볼 수 있는 공개 ETA 는 평균 447초·최대 1234초 어긋나 있었다.

**브리핑보다 나빴던 것 3가지**
1. **규칙 결손** — YR-100-[3]에서 학습 arm 6개가 전부 healthy 에 걸려 탈락하자,
   사전등록 규칙("guard 통과 arm 중 Δtotal 최소")이 **다른 선택지가 없어 오라클을 후보로
   자동 지명**했다. 라벨만 고치면 재발한다.
2. **없는 arm** — "공개정보 rollout 참고군"의 실체(`PredictiveRollout`)는 판정 하네스에
   **한 번도 등록된 적이 없다**(사용처가 테스트 1개).
3. **자기모순** — `yr075c_rollout_headroom.py:6-7` 은 같은 기법을 "완벽 미래·배포 금지"로
   정확히 규정하면서, 바로 윗줄에서 그 실험의 중앙정책을 같은 오라클로 두고 무라벨이었다.

**조치**: `uses_future_information()` / `is_deployable()` 신설 → `yr041_locked` 의
`adopt` 와 `yr100_candidate_eval` 의 verdict 에 배선. 오라클은 세 게이트를 다 통과해도
채택 불가이며, 통과 여부는 `adopt_if_deployable` 로 따로 남긴다(정보 손실 없음).
docstring·prereg 문구 정정.

**좋은 쪽 반전**: RL arm(CONTROL/CALC)은 오염되지 않았다 — 조합 열거만 쓰고
`_rollout_cost` 를 호출하지 않는다. **새 누출 1건 발견**: `FIFOPreference.rank` 가
`actual_block_arrival` 을 `now` 게이트 없이 정렬키로 읽는다 → 표기만 하고 거동 수정은
별건(고치면 과거 골든이 전부 바뀐다).

## 2. YR-108 — 실현 독립성

**정찰이 기전을 정정**했다. "셀 BASE 간격 100 < offset 200" 이 아니다 — 인접 셀은 부하수준이
달라 애초에 충돌하지 않는다. 진짜 원인은 **같은 부하수준을 공유하는 두 셀의 BASE 가 정확히
200 떨어져 있고 대역 offset 도 200씩 벌어져 공명**하는 것이다. 뿌리는 `vessel_deadline_mult`
와 정합 플래그가 **난수를 한 번도 소비하지 않는다**는 사실이다.

핵심 원칙(정찰이 확립): **실현 정체성은 시드로도 설정으로도 결정되지 않고, 오직 생성물
내용으로만 결정된다.** 그래서 시드 산술이 아니라 **생성해 보고 지문을 비교**한다.

`seedbank.py`: `realization_hash`(확률적 추출 결과만 해시 — 마감·ETD 처럼 설계에서
결정론적으로 나오는 값은 제외) · `assign_band`(지문이 겹치지 않는 시드를 찾아 배정) ·
`independence_report`(대역 내부 중복 + 다른 대역과의 교집합). 회귀 테스트가 **사고를 그대로
재현**한다: 배율×정합 10조합 → 고유 지문 1개, YR-041-a 명목 24행 → 고유 16개.

## 3. YR-110 — guard 기계화

계약(0순위: 안전·물리 0 / 완주 1.0 / backlog 0 / 검열 회피 0) 중 `check_guards` 가 덮는 건
2항이고, **부르는 하네스가 yr105 하나뿐이었으며 그마저 중단시키지 않았다**.
`yr099-mid`·`yr100`·`yr041` 은 backlog 를 수집조차 안 했다. `yr099-mid` 의 채널 분해 블록은
`chan` 키를 만들지 않아 **조건이 항상 False 인 영구 죽은 코드**였다(코드만 읽으면 붙은 것처럼
보였다). 또 정책 예외를 WAIT 로 삼키면서 세지 않아, 정책이 매 결정 실패해도 결과 JSON 이
조용히 완성됐다.

**조치**: 채널 분해를 실제로 계산 · backlog 수집 · `policy_exceptions` 계수 · guard 실패 시
**INVALID 표기 + 종료코드 2**(원자료는 보존 — 시드 제외는 계약이 금지한 "검열 회피"다).

## 4. 게이트 A — YC→YT→STS 전체 물리 하한

YR-109 초판(STS cadence 만)은 **적하(LOAD)에서 불충분**했다. 적하는 첫 박스가 야드크레인
1사이클 + 야드트랙터 편도를 거쳐야 첫 STS move 가 가능하다. 실측(852000): dmult=1.0 클램프
뒤에도 **145.1초** 초과 잔존. 양하(DISCHARGE)는 안벽 버퍼로 뽑아내므로 STS 단독 하한이 정확.

`phys_min_completion_s = start + max(M·cad, lead + (M−1)·max(cad, 야드간격))`,
`lead = min(YC 1사이클) + YT 편도`(적하만). 클램프를 **배율 → 완료시각 max()** 로 승격
(배율은 가산 항을 표현할 수 없다). 정찰 지적대로 **클램프 미발동 시 원래 식을 그대로 유지**해
OFF 경로의 부동소수점 결합순서를 보존했다(골든). 결과: 구조적 초과 전 시드 **0**.

## 6. 게이트 C — 통계

세 결함을 고쳤다(자세한 규칙표는 `evalkit.py` docstring).

| 결함 | 구판 | 정정 |
|---|---|---|
| t 값 | df 21·22·24~28 결측 → 0.920(df=5) 대체, df≥30 고정 | `statfuncs` 정확 계산(공개표와 4자리 일치) |
| 필요 표본수 | 상수 z(1.96+0.84) 1회 계산, sd 불확실성 무시 | 목표 df **반복 수렴** + sd 상측한계(파일럿 df) |
| 동등성 | `MDE ≤ δ`(설계 감도만 봄) | **TOST**(90% CI ⊂ ±δ) |

- **필요 n 정정**: 보드가 인용하던 "트럭 17"은 df=7 을 목표 n 에 그대로 쓴 값이었다.
  올바른 값은 **점추정 14 / sd 불확실성 반영 24**(파일럿 n=8 의 sd 상한 배수 1.353).
  → 사용자 제안(선택 21)보다 **24**가 필요하다. 실행비용은 무시 가능(1 arm 1 시드 0.8초).
- **5번째 상태** 신설: "유의하나 δ 미만" — 실제 데이터(move 채널)에 이미 있었는데 라벨 4종에
  자리가 없어 사람이 손으로 처리하던 것을 규칙에 넣었다.
- **퇴화 채널** 차단: `other` 는 4항 가중치가 전부 0이라 항상 sd=0 → 구 규칙이 자동으로
  "효과 없음" 증명서를 발행했다(구조적 거짓 주장). 이제 "판정 대상 아님".
- **1차 판정 채널을 결과에 박제**(`role`) — 산문 규약이 아니라 파일에 남아야 다중비교
  무보정 논리가 성립한다.

## 7. 게이트 D — 브리지 원자성

**핵심 결함**: `commit` 이 소스에서 job·큐·장부를 **먼저 지우고 나서** 정합 검사를 했다.
검사가 실패하면 `try_transfer` 가 조용히 False 를 돌려주고, 작업은 **어느 블록에도 없는
고아**가 됐다(`rollback` 은 예약 해제 한 줄뿐이라 아무것도 되돌리지 않았다).

조치: ①닫힌 txn 거절 ②validate ③`_precommit`(실패 가능 검사를 **변경 전에** 전부 소진)
④변경 구간(예외 시 스냅샷 복구 후 재발생). 추가로 정찰이 찾은 3건 —
txn 고유 id(구판은 (job,dst,시각) 키라 같은 시각 재-prepare 시 예약 영구 누수 + rollback 한
txn 재-commit 가능) · `provided_eta` 동반 이동(정책이 실제로 읽는 필드인데 구판은
`estimated_block_arrival` 만 밀어 두 필드가 어긋났다). 회귀 6건 추가.

### 확증 대역 n=48 — ❌ **하드 guard 실패 → 판정 무효**

3개 시드(902013·902017·902045)에서 완주율 0.994·backlog 1. 계약상 판정에 쓸 수 없다.

이송량 감소 때문**이라는 방향이다. 그러나 **guard 실패 런이므로 판정으로 인용하지 않는다.**

### 무효의 원인 — 새 엔진 결함 (YR-112 등록)

seed 902013 을 추적한 결과: **결정 스트림이 t=15682.8초에 끊기는데 평가창은 36000초까지

## 종합 판정

- **본선 악화 방지 필터(VGUARD)는 채택하지 않는다.** 선택 대역에서 1차 판정 채널(트럭)이
  **유의하게 악화**됐고, 본선은 δ=10 안에서 **효과 없음**(TOST)으로 나왔다. 즉 "본선을 지키려
  이송을 막는다"는 축은 **비용을 지불하고 아무것도 얻지 못한다**.
- 단, **확증 대역이 무효**이므로 이 판정은 "선택 대역 단독"이다. 확증은 YR-112 해결 후 재실행.

  같은 결함이 표본의 6%를 조용히 오염시킨다.
