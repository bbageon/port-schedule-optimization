# 운반·대기 정의 확인과 물량별 결과 후속 분석

2026-11-21 · YR-332-f(대기열 정의), i(내부 운반), ap(고물량 근거).

**관측 최대 도착량 안의 3,500건 조건에서도 전역 대기 정보를 추가한 모델은 대조 모델보다 비용이 10.23% 높았다.**
저장된 평가를 물량별로 다시 읽은 사후 분석이다. 대기·운반 정의나 새로운 실측 자료를 확보한 결과는 아니다.

## ① 진행사항

- 사용자 후속 지시에 따라 기존 세 작업의 현실성 보정 허가를 받았다. [기록](authorization.json).
- 저장된 최종 평가·학습 전·규칙 결과 90개를 읽어, 물량별 12개 집단의 비용·작업시간·미완료를 독립 집계했다.
  기존 보고서의 물량별 원값과 모두 일치했다. 최종 모델 27쌍의 입력 명단 해시도 일치했다.
- 현재 입력의 시간당 방문 수는 11/20에 재생성 검증한 9개 입력의 값을 사용했다.
  원자료600파일과 보정·기존 평가·판정 파일은 바꾸지 않았다. 새 학습·시뮬레이션은 0회다.
- 본선 원본 JSON 263개는 모두 같은 터미널 코드 `DGTBC050`을 담고 있었다.
  공식 DGT 화면·연결 코드, ChainPortal 공개 화면·연결 코드와 로컬 인계 문서의 정의를 추가 확인했다.
  [공개 근거 검토](official-sources.json) · [검산](verification.json) · [원값과 해시](volume-results.json).

### 전역 대기 정보 추가 효과를 물량별로 비교

비교는 **같은 시작 모델·학습량의 ‘전역 정보 있음’ 대 ‘없음’**이다. 양수는 비용·시간 증가다.
각 물량은 합성 하루3개 × 모델 시작값3개, 총9쌍이다. 시간당 방문 수의 관측 최대는245번이다.

|---:|---:|---|---:|---:|---:|---:|
| 3,500 | 216~237 | 최대값 이내 | +10.23% | +8.52% | +4.04% | +154.22건 |
| 7,500 | 461~503 | 범위 초과 | +6.17% | +6.79% | +0.58% | +58.11건 |
| 15,000 | 917~997 | 범위 초과 | −0.64% | −0.56% | +0.08% | +174.67건 |

3,500건에서 트럭 시간은17.27→18.75분이다. 모델 시작값별 비용 변화도+20.67%, +10.64%, +0.76%로 세 개 모두 늘었다.
이 조건에서 전역 모델은 짧은 실작업 우선 규칙보다 비용29.33%, 트럭 시간20.71%가 높다.
전역 없는 모델도 같은 규칙보다 비용이 높아, 이번 분리로 학습 정책을 채택할 근거가 생긴 것은 아니다.

트럭 시간은 게이트 진입→작업 완료, 본선 시간은 작업 묶음의 계획 시작→개별 야드 작업 완료이며 준비 전 대기도 포함한다.
두 시간 모두 기존24시간 관측 규칙을 유지하고 미완료를 포함한다. 크레인만의 순수 작업시간과는 구분한다.
표의 평균 미완료 건수는 여러 실행을 평균했으므로 소수가 나올 수 있다.

## ② 해석과 판정

3,500건의 **시간당 도착량 최대가 관측 범위 안**이라는 제한된 분류다. 전체 수요·본선·장비·대기열까지 현실적이라고 승인하지 않는다.
245방문/시간은 이 표본의 최대이며 터미널 처리 한계가 아니다. 자료의 전체 터미널 포함률도 아직 모른다.
3,500·7,500건의 악화와15,000건의 작은 비용 감소가 전체 평균에 함께 들어 있다. 평균만으로 모든 물량에서 개선됐다고 읽으면 안 된다.
사후 재집계이므로 새 독립 검증이나 통계적 확증으로 사용하지 않는다. 결과를 보고 학습·평가 표본을 다시 고르지 않는다.

- 기록 정합: 저장 평가90개·12집단·27짝 입력·원자료600파일 검증 통과.
- 현실성: 대기·운반 정의·고물량 포함 범위가 남아 미통과 유지.
- 성능: 기존bc의 채택 미달 판정을 유지한다. 기본 정책·보상·합성 입력 변경 없음.

## ③ 예정사항 — 같은 등록 작업을 이어간다

- **f:** 대기 수의 ‘단위·포함 대상·측정 시각’과 작업 시작 자료를 확인한다. 실제와 모형의 같은 구간을 비교하기 위해서다.
- **i:** `atw`의 사건 단계와 내부 운반차의 배정·인계·복귀·투입 기록을 확인한다. 3대·470초 가정을 보정하기 위해서다.
- **ap:** 전체 자료 포함률과 고물량 날짜의 분별 방문 수를 확인한다. 범위를 넘는 합성 조건의 타당성을 판단하기 위해서다.

필요한 항목은 [자료 확인표](../../../../docs/research/v7-discharge/transport-queue-data-contract.md),
짧게 답할 수 있는 형식은 [정의 회신 항목](../../../../docs/research/v7-discharge/realism-definition-reply.md)에 정리했다.
추가 API 명세나 기록의 로컬 경로를 사용자에게 문의한 상태다. 세 작업 전체의 완료 처리는 하지 않는다.

기존 연구 Python 환경에서 `python scripts/v7/summarize_realism_followup.py`로 저장 평가를 다시 집계한다.
