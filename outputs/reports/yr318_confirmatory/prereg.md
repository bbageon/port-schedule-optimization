# YR-318 — 확증 캠페인: 수정 엔진·새 시드 대역·규칙 대조군

2026-09-22 작성. 이 문서는 **어떤 결과도 보기 전에** 고정한다. 실행 후 수정하지 않는다.
선행: [[YR-317-k]](후보 가지치기 수정) · [[YR-317-n]](학습 3판).

## 왜 다시 도는가

1. **규칙 대조군이 0개다.** 이 저장소의 동결 규약은 주판정 축이 *규칙 대비*이고
   *안 팔기 대비는 판별력이 없다*고 못박는다(`.claude/docs/architecture/06-학습과-판정.md:103`).
   기존 80건에는 규칙 팔이 하나도 없어, 지금 원고에는 "학습이 규칙보다 낫다"는 증거가 없다.
2. **엔진이 바뀐다.** 실행 가능 후보 우선 가지치기는 교착만 푸는 것이 아니라 **후보 예산이
   찬 모든 순간**에 후보 집합을 바꾼다. 따라서 수정 엔진의 결과는 기존 80건과 직접 비교할
   수 없고, 새 사전등록 없이는 어떤 수치도 판정으로 쓸 수 없다.
3. **학습 축이 비어 있다.** 기존 80건은 체크포인트 하나에서 나왔고, 그 모델은 접수계약
   LEGACY 에서 배워 PRESERVE 에서 평가됐다. 학습 3판으로 두 구멍을 같이 막는다.
4. 기존 20시드는 이미 판정에 썼다. 같은 시드로 다시 판정하면 사전등록이 무의미하다.

## 실행 계약

- **시드 대역**: 22,000,000 부터 100,000 간격으로 23,900,000 까지 **20개월**. 교체·추가·성능별
  제외 없음. 기존 판정 대역(20,000,000~21,900,000)·진단 대역(9,900,0xx)과 겹치지 않음을
  실행기가 기계로 확인한다(`campaign_specs`).
- **엔진**: `candidate_pruning="feasible_first"`. 설정에 명시하고 결과 파일에 기록한다.
- **열(팔) 8개** — 열 하나가 결과표의 한 줄이다.

| 열 이름 | 엔진 팔 | 가중치 | 무엇을 답하는가 |
|---|---|---|---|
| `NO_REALLOC` | 재배정 없음 | — | 하한 참조 (판별력 없음, 기존 표와의 연결용) |
| `SLOT_LL` | 규칙·시간만 | — | **주 대조군** — 시간정책과 행동 폭이 같은 비학습 규칙 |
| `SPACE_TIME_LL` | 규칙·블록+시간 | — | 전체정책과 행동 폭이 같은 비학습 규칙 |
| `RL_TIME_n1` | 시간정책 | 학습 1판 | 주 주장 |
| `RL_TIME_n2` | 시간정책 | 학습 2판 | 학습 시드 안정성 |
| `RL_TIME_n3` | 시간정책 | 학습 3판 | 학습 시드 안정성 |
| `RL_n1` | 전체정책 | 학습 1판 | 공간 행동 허용의 추가 효과 |
| `RL_NOVETO_n1` | 거부권 없음 | 학습 1판 | 수락망의 기여 (R1-4b) |

- 블록전용(`RL_SPACE`)은 기존 캠페인에서 −150%로 결론났으므로 넣지 않는다. 이 제외는
  **지금 선언**하는 것이며 새 결과를 보고 고르지 않는다.
- 160개 정책-월을 **전부 보존**한다. 실패·열위·미완료도 버리지 않는다.
- 접수 `PRESERVE`, 공급 `COUNT_BALANCED`. 학습 3판도 같은 계약에서 학습한다 —
  기존 80건의 학습·평가 계약 불일치를 이번에는 만들지 않는다.
- 평가 중 모델 갱신·탐색·교사 분기 없음. 실행 전후 가중치 지문 일치를 검사한다.
- 한 실행 = 30일 연속 + 기존 2시간 종료 구간. 날짜마다 초기화하지 않는다.
- 일별 300초 상태 표본·확정 일별 파일·요청별 사건·컨테이너 연결·선박 완료 장부를 보존한다.
- **온라인 처리시간**을 같이 잰다(`measure_latency=true`) — 결정 주기당 후보 구성·채점·경합
  해소·확정 시간. 시뮬레이션 진행과 학습 전용 복제는 제외한다.

## 통계

- 독립 표본 = 월 하나, n=20. 짝비교는 같은 월의 같은 입력끼리만 한다(요청 지문 일치 검사).
- **주 분석**은 2~29일의 28일 비용(기존 논문과 같은 창). 보조는 전체 30일.
- 월 묶음 **20,000회 재표집**. 통계 난수 **9,900,727** (기존 9,900,721·9,900,723·9,900,725 와 구분).
- **주판정은 하나다**(규약 `06-학습과-판정.md:103` — 다중비교 방지). 학습 3판은 세 개의
  주장이 아니라 **한 학습 절차의 세 표본**이므로, 월마다 세 판의 비용을 평균한 파생 열
  `RL_TIME_mean` 을 만들어 그 하나만 확증한다: **`28d:SLOT_LL-RL_TIME_mean`, 95% 구간.**
  이렇게 하면 "잘 나온 판만 고르기"가 구조적으로 불가능하다.
- **확증 조건**: 위 구간이 0을 넘고, **동시에** 세 판의 점추정 부호가 모두 같아야 한다.
  부호가 갈리면 구간이 0을 넘어도 주장을 **확증으로 쓰지 않는다**.
- 기술 비교(95%, 확증 아님): 학습 판별 `28d:SLOT_LL-RL_TIME_n1|n2|n3` ·
  `28d:SLOT_LL-SPACE_TIME_LL` · `28d:SPACE_TIME_LL-RL_n1` · `28d:RL_TIME_mean-RL_n1` ·
  `28d:RL_n1-RL_NOVETO_n1` · `28d:NO_REALLOC-*` · 30일 창 전부.
- 평균 짝 차이, 월별 절감률 평균·중앙, 비용 합계 비율, 승/패/동률을 모두 보고한다.
- 비용표 옆에 **완료율·미완료 트럭·선박 잔여**와 **완료 트럭 1대당 비용**을 같이 둔다.
  미완료가 있으면 비용 감소만으로 개선을 확증하지 않는다.
- 600일을 독립 표본 600개로 취급하지 않는다. 부하별·날짜별 자료는 기전 설명용이다.

## 결과별로 미리 정한 문장

결과를 보고 해석을 고르지 않기 위해, 네 경우의 보고 문장을 **지금** 정한다.

- **A. 주 구간이 0을 넘고 세 판의 부호가 같다** → "시간 조정 학습 정책이 같은 행동 폭의
  규칙 기준선보다 싸다. 학습 절차를 세 번 반복해도 방향이 유지된다." 주 주장으로 쓴다.
- **B. 주 구간이 0을 넘지만 판마다 부호가 갈린다** → "평균으로는 우위가 보이나 학습 판에
  따라 방향이 뒤집힌다. 학습 시드 안정성이 확보되지 않았다." 주 주장을 **확증으로 쓰지
  않고**, 세 판을 모두 표로 싣는다. **좋은 판만 고르지 않는다.**
- **C. 주 구간이 0을 포함한다** → "이 환경·이 비용 모형에서 학습 정책은 같은 행동 폭의
  규칙 기준선을 이기지 못했다." 그대로 싣고, 안 팔기 대비 절감은 판별력이 없음을 명시한다.
- **D. 규칙이 유의하게 더 싸다** → "학습 정책이 규칙보다 비싸다"를 그대로 보고하고,
  기여를 *학습 성능*이 아니라 *반사실 라벨 구조와 계측 방법*으로 다시 쓴다.

또한: `RL_NOVETO` 가 `RL` 과 구간이 겹치면 "수락망의 기여를 이 설계로는 분리하지 못했다"를
싣는다. `SPACE_TIME_LL` 가 `RL` 보다 싸면 "공간 조정은 규칙으로도 충분하다"를 싣는다.

## 자원

- 동시 실행 **최대 16개**(설정 `workers_max`), CPU 지정 범위 0~19(`cpu_limit`), 나머지는 v4/v5 에 남긴다. 한 실행 = CPU 1개 · Torch 1 스레드.
- 실측 기준 한 실행 6.49시간(**수정 전** 엔진의 교착 없는 실행 평균) → 160실행 ≈
  1,038 CPU-시간, 동시성 9.2 기준 약 4.7일.
- ⚠️ **수정 엔진의 실행시간은 아직 모른다.** 두 방향이 다 있다 — 잘리던 일을 실제로
  실행하므로 느려질 수도 있고, 정지한 블록이 매 주기 수백 후보를 다시 채점하는 낭비가
  사라져 빨라질 수도 있다. [[YR-317-k]] 대조 재생에서 잰 하루당 시간으로 이 추정을
  갱신한 뒤 착수하고, **추정이 아니라 실측값을 적는다.**
- 실패·부분 자료도 남긴다. "실행기 준비 / 대기열 등록 / 160건 종료 / 논문 주장 확정"을
  서로 다른 사건으로 기록한다.
