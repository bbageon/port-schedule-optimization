## 해석 — 연결 규칙과 한계

1. 먼저 초기 재고·트럭 반입·본선 양하의 상자 명단을 만든다.
2. 반출·선적 순서대로 같은 블록의 미배정 상자를 추첨한다. 꺼내기 쉬운 상자를 골라주지 않는다.
3. 한 번 배정한 상자는 다른 출고에 다시 배정하지 않는다. 모든 반입에 반출을 강제로 붙이지도 않는다.
4. 먼저 도착하는 반출 트럭은 고정 상자를 기다린다. 공급 자체가 부족하면 데이터를 만들지 않고 실패한다.

이 규칙은 "모든 반입과 반출을 짝짓기"가 아니라 **모든 출고 대상에 출처를 보장하기**다.

| 공급 출처 | 트럭 반출로 배정 | 본선 선적으로 배정 |
|---|---:|---:|
| 초기 재고 | 10,585 | 3,023 |
| 트럭 반입 | 49,367 | 20,274 |
| 본선 양하 | 42,341 | 21,373 |

수입·수출 화물 구분 자료가 없어 공급을 같은 블록 재고로 섞었다. 따라서 트럭→트럭 연결도 있으며,
이 표를 실제 항만의 수입·수출·환적 비율이라고 주장하지 않는다.

- 상자보다 트럭이 먼저 오는 주문 11건, 공급 예정과의 최대 차이 11,740.4336초(약 3시간 16분).
  삭제하거나 예약을 늦추지 않았다. 실제 크레인 적치까지 끝나야 처리할 수 있어 **실제 대기는 더 길 수 있다**.
- 공급 예정→출고 예정 시각 차이의 중앙은 148,754.1365초(약 41.3시간), 최대 약 24.9일.
  초기 상자의 과거 입고일은 없으므로 이 값도 실제 체류시간이 아니다.
- 규격 명단: 20피트 55,518개, 40피트 105,853개. 반입·양하의 원래 크기 생성 규칙은 유지했다.
- 같은 코드·시드로 두 번 새로 생성했고 압축 파일의 바이트까지 완전히 같았다. 생성은 각각 27.87초·27.88초였다.
  파일 SHA-256(내용 변경을 확인하는 검증값):
  `efdb45e2ec8feafed6987cf48dfe022ca2959dad8c4f1d56bee680456081af7a`.
- 데이터 생성 자체는 CPU 1개만 사용하며 시뮬레이션 진행·정책 갱신은 각각 0회다.
  부품 검사에서 돌린 작은 학습 연결 시험과 실제 새 30일 데이터 실행은 구분한다.

## 예정사항 — 같은 YR-306의 실행 연결 검증

- 새 파일을 읽어 **상자 미도착 대기와 재배정 후 실제 위치 추적**을 실행기에 연결·검사한다.
  정적 명단이 맞더라도 실제 투입 순서에서 다시 누락될 수 있기 때문에 먼저 필요한 작업이다.
- 이번에는 기본 생성기·학습 명령을 자동 교체하거나 장기 학습을 시작하지 않았다.
- [현재 진행 판정](gate-after-seed.json): 입력 번호·중복 검사는 통과했으나,
  기록과 실제 실행이 맞는지의 장기 검증, 실제 항만 같은 흐름인지의 검증, 비용 개선 판정은 남아 있다.
  따라서 "새 데이터 생성 완료"이지 "학습 준비 완료"가 아니다.
