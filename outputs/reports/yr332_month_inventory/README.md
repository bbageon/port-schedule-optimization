# 월 계획 재고 감소 진단 — 2026-11-21

**검사 기준의 불일치와 월 중간 공급 점검 누락을 확인했다. 시뮬레이터의 실제 재고가 음수가 됐다는 결과는 아니다.**
고정 시드 9,400,777의 30일 합성 명단 176,500건을 계산했다. 정책·학습 실행은 하지 않았다.

## ① 진행사항

- 동일 입력을 두 번 생성해 정확히 일치함을 확인했다.
- 날짜30개×블록21개×조건3개의 수지 1,890행을 별도 누적 합산으로 검산했다.
- 수정 전 검사 값인 첫날 말20,148개·최저9,544개를 그대로 재현했다.
- 실제 생성 초기재고는13,686개로 검사의 명목13,608개와 다르다. 블록별로도620~767개다(검사는 전부648개).

| 계산 기준 | 첫날 말 총재고 | 월 중 최저 총재고 | 월말 총재고 | 음수인 블록·날짜 조합 | 블록별 최저 잔고 |
|---|---:|---:|---:|---:|---:|
| 기존 검사: 명목 초기재고 | 20,148 | 9,544 | 9,998 | 14 | −325 |
| 실제 초기재고·동일 계획 | 20,226 | 9,622 | 10,076 | 14 | −209 |
| 실제 초기재고를 기존 공급 보정기에 전달 | 20,226 | 9,622 | 10,076 | 14 | −209 |

실제 초기재고를 공급 보정기에 전달해도 바뀐 본선 작업은0건이었다. 월말에는 모든 블록의 잔고가 양수이기 때문이다.
현재 보정기는 월말 부족 여부를 확인하므로 중간 부족을 잡지 못한다.

## ② 원인과 해석

**첫째, 전체 감소율의 기준이 첫날 말의 높은 재고다.**
첫날은 계획 양하7,218개·적하0개다. 트럭 순반출678개를 빼도 재고가6,540개 늘어난다.
그래서 월 중 최저9,622개는 첫날 말20,226개의47.57%이지만, 최초13,686개의70.31%다.
이 비율만으로 입력이 불가능하다고 판단할 수 없으므로 기존50% 유지 조건의 의도도 별도로 확인해야 한다.

**둘째, 중간에 공급이 모자라는 블록이 있다.**
Y01·Y05·Y15·Y20·Y21의 총14개 블록·날짜 조합이 해당한다.
첫 사례는6일차 Y20: 전날 잔고175 + 반입267 − 반출447 = −5개다. 10일차에는 최대209개가 부족하다.
이14개 조합은 모두 그날 계획된 본선 작업이0건이다. 트럭 순반출이 이어지는 동안 보충 본선이 없는 구간이다.
반면 월말 블록별 잔고는 최소78개로 모두 양수여서 기존 월말 보정은 작동하지 않는다.

**셋째, 명목 초기재고를 사용한 검사가 혼잡 가능성을 작게 표시한다.**
기존 검사에서는 블록 최고1,292개로 용량1,440개의90%보다 작다.
실제 초기재고를 쓰면 최고1,411개(97.99%)여서 같은90% 조건에도 미달한다. 물리 용량을 넘은 계획 일말 잔고는0건이다.
50%와90%를 통과하도록 값을 바꾸지 않았으며, 실제 재고·공급 검증과 기존 보조 기준을 구분해야 한다.

월 전체 수지: 반입70,421 + 양하75,022 − 반출106,079 − 적하42,974 = −3,610개.
초기13,686 −3,610 = 월말10,076개로 장부 합은 일치한다. **총량의 합산 오류가 아니라 시간·블록별 공급 확인의 빈틈이다.**

### 해석 범위

- 각 본선의 작업 전량을 계획 날짜에 반영한 수지다. 실제 본선 완료는 다음 날로 넘어갈 수 있다.
- 음수는 해당 계획 날짜까지 예정 물량을 모두 처리하려면 공급이 부족하다는 뜻이다.
  실제 실행에서는 작업이 기다리거나 이월될 수 있으므로 실제 음수 재고·물리 위반·정책 실패로 단정하지 않는다.
- 명단의 개별 컨테이너 소유권·공급 시각까지 확인해야 실행 가능성을 판단할 수 있다.
- 하나의 고정 월 입력 진단이다. 최근 하루 단위 학습 모델의 개선·악화 원인을 증명하지 않는다.
- 이번 진단은 코드·물량·작업 종류·검사 임계를 변경하지 않았다. 기존 월 재고 검사는 계속 실패한다.
