# v5 학습 시작 전 확인·현재 구성

2026-09-10 요청: "시작하고, 지금 구성이 어떻게 되어있는지 설명해줘".

## 진행사항

**학습 프로세스는 시작하지 않았다.** 연구 시작 검사에서 거부되어 준비 단계에 남겼다.
기존 검증 자료의 줄바꿈 문제와 v5 적용 범위 차이를 구분했다.
검사 원자료: [preflight.json](preflight.json).

- `authorize-next`: `allowed=false`, "저장된 scenario PASS 재계산 실패".
- 직접 원인: 외부 기준 자료 1개 파일을 참조하는 5항목의 내용 식별값 불일치.
- 현재 파일의 Windows 줄바꿈을 LF로 계산하면 기록된 식별값과 정확히 같다.
  **자료 수치가 달라진 것은 아니다.** 실제 파일·검사 기준은 고치지 않았다.
- 별도 적용 범위 문제: 옛 판정은 초기 야드 점유율 65%, 현재 v5 연속 무대는 45%다.
  줄바꿈 문제만 해결해도 옛 판정이 v5의 검증 결과가 되지는 않는다.
- 현재 v5 명령은 최대 하루의 디버깅용이다. 30일 준비·학습·정리 구간,
  날짜별 저장·보고 및 중단 복구 계약을 갖춘 장기 실행기는 아직 연결하지 않았다.
- 다른 v4 코드와 사용자 미추적 파일을 변경하지 않았다.

## 현재 구성

21개 블록이 **하나의 신경망**을 함께 쓴다. 판매·구매·크레인은 역할만 나뉜다.
공유 계산층 뒤에 행동 점수와 미래 보상 추정 출력이 하나씩 붙는다.

| 역할 | 선택 | 주요 정보 |
|---|---|---|
| 판매 | 유지 / 다른 블록으로 제안 / 도착시각 이연 제안 | 자기 블록 혼잡·작업·후보 목적지/시각의 통지 물량 |
| 구매 | 수락 / 거절 | 수신 블록 상태·제안·도착 예정시각 주변 통지 물량 |
| 크레인 | 실제 작업 / 대기 / 위치 이동 / 선행 재조작 | 블록 상태·본선/트럭 구분·작업 시간·현재 대기·앞 크레인의 선택 |

두 역할이 모두 동의한 재배정만 실행된다. 크레인 충돌·작업 중복·용량 등
실행 불가능한 선택은 물리 검사로 막지만, 별도 규칙이 선택을 몰래 대체하지 않는다.

```text
같은 실제 세계에서 판매·구매·크레인 선택
  → 60초 뒤 누적비용 증가분 확인
  → 경험을 60구간 모음(기본: 시뮬레이션 1시간)
  → PPO로 신경망 갱신 → 같은 세계에서 계속
```

PPO는 실제 선택 결과로 행동 확률을 조금씩 바꾸는 학습 방식이다.
별도 미래 세계는 굴리지 않는다. 수집 구간 뒤의 영향은 신경망의 가치 추정으로 연결한다.

- 보상 = `−(이번 누적비용 − 직전 누적비용) / 1,000,000`.
- 비용은 트럭 체류·크레인 빈 이동·재조작·본선 유휴의 네 항이다.
- 21블록 모두 같은 터미널 보상을 받는다. 블록별 보상 21개를 다시 합산하지 않는다.
- 기본 설정: 60구간 수집, 데이터 2회 반복 사용, 작은 학습 묶음 크기 64,
  학습률 0.0003, 확률비 제한 0.2, CPU 1스레드.
- 신경망: 입력 37칸(특징용 최대 32칸+역할 4칸+구매 구분 1칸), 중간층 64칸씩 2층.
- 시험에 사용한 120구간·1회 반복 설정과 현재 명령의 기본 60구간·2회는 구분한다.

## 아직 구현하지 않은 설계

- 본선 마감이 가까워질수록 급증하는 새 비선형 비용: 미적용.
  현재 본선 비용은 선박 톤수와 유휴시간에 비례한다.
- "6시간치 오더를 일괄 공개": 미적용.
  오더마다 통지 시각이 다르고, 기본 재배정 결정창은 예약시각 30분 전 이내다.
  상태의 '곧 올 물량'도 통지된 다음 30분 물량이며, 후보 도착시각 주변은 앞뒤 30분을 센다.
- 옛 반사실 3시간 설정은 사본 코드에 남아 있지만 새 PPO가 미래 세계를 3시간 굴린다는 뜻은 아니다.
- 장기 학습 성능·현실타당성: 이번 디버깅 통과만으로 인정하지 않는다.

## 예정사항

작업판 YR-306(이번 학습 시작 요청)은 backlog에 두었다.
v5 전용 시작 조건을 정리하고 연속 학습 실행 범위를 확정해야 한다.
기존 30일 틀을 사용할 경우 첫날·마지막날을 제외한 28일 학습을 연결할 수 있으나,
현재 디버깅 명령에 일수만 크게 넣어서 같은 계약이라고 주장하지 않는다.
규칙 예외나 환경 값 변경을 임의로 적용하지 않고 사용자 방향 확인 후 이어간다.
