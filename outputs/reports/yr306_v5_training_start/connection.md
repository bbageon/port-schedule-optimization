# v5 연속 학습 연결·검증 (2026-09-10)

## 진행사항

사용자 "응 연결해서 진행해볼래?" 승인 후 30일 실행기를 연결했다.
이 보고서는 승인 전 [시작 점검](README.md)의 후속 기록이다.

- 사전등록 `98b84c8`: 실행 기록의 신뢰성을 고치는 단일축 작업으로 착수 허가.
- 첫날 준비, 2~29일 학습, 마지막 날 정리, 이후 2시간 배수. 세계는 한 번만 만든다.
- 60초마다 실제 비용 증가분 수집, 60구간마다 PPO(실제 경험으로 정책을 갱신하는 방법) 갱신.
- 날짜별 정책 저장·달력 구간 비용·물리 검사, 시간별 진행, 실패 상태 기록을 연결했다.
- 초기 점유율 45%·기존 비용·통지창·정책 구조는 바꾸지 않았다.

| 검증 | 결과 | 의미 |
|---|---:|---|
| 연속 실행·PPO 단위/회귀 | 47건 통과, 57.86초 | 학습 경계·저장·실패 기록 검사 |
| 기존 실제 실행·물리 사본·월 무대 | 102건 통과, 64.35초 | 새 연결이 기존 동작을 깨지 않음 |
| 합계 | 서로 다른 149건 통과 | 이번 변경의 관련 범위 검사이며 전체 재실행은 아님 |

원자료: [첫 묶음 XML](tests-unit.xml), [둘째 묶음 XML](tests-integration.xml).

3일·일일 트럭 60대 실제 실행 시험에서는 첫날 0회, 학습일 24회, 마지막날 0회 갱신했다.
가중치도 학습일에만 바뀌었다. 학습 보상의 합은 해당 날짜 실제 비용 증가분과 일치했다.
21블록의 물리 세계는 교체되지 않았고 반사실 세계(다른 선택을 시험하는 복제 세계)는 0회였다.

## 해석

연속 학습의 연결은 검사됐지만 성능 우위를 보인 것은 아니다.
규칙 대비 성능은 미확정, v5 외부 보정·지속 운영 현실타당성은 미통과 상태를 유지한다.
단위 시험의 코드 출처 확인은 시험용 대체다. 운영 시범 실행에서는 실제 clean commit을 확인한다.

중간 저장은 정책·최적화 상태 보관이다. 물리 세계를 중간부터 재개하지 않는다.
실패하면 기록을 남기고 같은 코드·시드로 새 폴더에서 처음부터 재실행해야 한다.
날짜별 비용은 그날 실제 발생 비용이다. 도착일별 트럭 비용 집계와 구분한다.
