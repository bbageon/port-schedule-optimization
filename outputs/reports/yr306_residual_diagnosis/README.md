# YR-306 — 30일 완료 결과와 잔여 작업 진단

## 진행사항

- 원 실행 `yr306-wait-30d-4549ae9`는 30일 + 정리 2시간을 완료했다.
  갱신 672회, 트럭 177,500건·본선 288묶음 등록, 주문 누락·본선 실패·반사실 복제 0.
- 30일 물리 검사와 최종 모델 검증값 일치. 실제 실행 10,674.32초(약 2시간 58분).
- 완료하지 못한 작업은 반출 48·선적 1,200·양하 1,729, 합계 2,977건이다.
  실제 재고와 입출고 장부상 재고는 13,927개로 일치한다.
- 고정 명단의 보수적인 공급/해제 하한이 종료 이상인 작업은 **0건**이다.
  재배정으로 이동 경로가 짧아질 수 있어 트럭 이동시간은 하한에 넣지 않았다.
- 출문 미확인 집계는 29일차 1건·30일차 47건이다. 개별 잔여 작업 목록과 같은 자료로 취급하지 않는다.
- 경계·중복·공급 의존·경로 변경 검사 **9건 통과**. 초기 7건 검사와 계산도 이력으로 보존한다.
- 별도 코드 `5e3cdce`에서 3일 재현을 완료했다. 원본 결과(코드 출처만 제외), 날짜별 기록,
  초기·날짜별·최종 모델 파일 **5개 전부 정확히 일치**했다. 기존 파일도 변하지 않았다.
- 같은 방식으로 `outputs/v5/yr306-residual-30d-5e3cdce/`에서 30일 진단 재현을 시작했다.
  저장된 착수 확인은 2일차 09시·갱신 9회·7,862건 등록·누락 0이다. 현재 진행값은 아니다.
  CPU 23 하나, Windows 실행기 24648·WSL 프로세스 344는 착수 시점 번호다.

## 해석과 한계

- 이전 22일차 주문 거절은 수정본에서 재발하지 않았지만, 완주가 작업 소진을 의미하지는 않는다.
- 공급/해제 예정이 종료 전이라는 사실은 실제 처리 가능성을 보장하지 않는다.
  운반·상자 준비·크레인·안벽 대기가 더해지므로 모든 잔여를 버그 또는 정상 대기로 단정할 수 없다.
- 원 저장물에는 작업별 종료 상태와 물리 세계가 없다. 모델 파일은 그 세계를 복구할 수 없다.
- 이번 재현은 새 정책 개선 실험이 아니다. 정책·명단·종료 시각·학습을 그대로 재현한 뒤에만
  상자 준비·위치·작업 상태·크레인/본선 상태·다음 사건을 읽어 저장한다.
- 짧은 재현의 반입 1건은 기본 처리 조건을 만족하는 상태로 남았다. 이는 30일 잔여의 증거가 아니며,
  동시 작업 제약을 포함한 실제 배차 가능성 또는 정책 실패를 확정한 것도 아니다.
- 원 실행 완료 증거는 확보했지만 잔여 상태 재현 검증은 아직 미완료다. 성능·실측 현실성 주장도 하지 않는다.

## 예정사항

- 같은 YR-306에서 30일 진단 재현 완료 후 원본 결과·30일 기록·모델 파일 전부의 일치를 확인한다.
- `residual-diagnosis.json`이 `verified`인지 확인한 뒤 `residual-state.json.gz`의 작업별 원인을 분석한다.
  일반 `status.json`의 `completed`만으로 진단 완료를 보고하지 않는다.
- 코드·정책·입력을 바꾸거나 처리 시간을 늘려 기존 결과를 덮어쓰지 않는다.
