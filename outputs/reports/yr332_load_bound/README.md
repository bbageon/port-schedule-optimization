# 적하 최소 완료시각 보정 — 2026-11-21

**실제 완료보다 늦었던 하한 5건을 수정했다. 작업 실행·비용은 같고 최신 9입력의 마감도 그대로다.**
하한은 '이 시각보다 빨리는 끝날 수 없다'는 뜻이며, 그 시각에 실제로 끝낼 수 있다는 보장이 아니다.

## ① 진행사항

- 사전 고정한 18조건과 마지막 조건 반복 1회: 수정 전 반례 5건 → 수정 후 0건.
- 수정 전 하한은 실제 완료보다 최대 45.3652초 늦었다.
  3작업 예: 실제 완료 855.5793초, 옛 하한 900.9444초.
- 차량의 장기 평균 간격을 첫 화물부터 적용하던 식을, 여러 차량이 처음에 동시에 운반하는 묶음 식으로 바꿨다.
- 별도 사건 계산 144조합에서 보정식과 완료시각이 1e-8초 이내로 일치했다.
  이 비교는 야드 경합을 없앤 완화 모형이며 실제 항만 표본은 아니다.
- 19회 전후 비교에서 작업 시작·완료, 운반·본선 사건, 사건 해시, 비용, 잔여 작업이 모두 동일했다.
- 최신 정책 비교의 9입력을 다시 생성했다. 본선 계획 72건 중 하한 보조값 24건만 25.76~51.52초 앞당겨졌다.
  트럭 일정·작업·물리 조건·본선 마감·출항 예정시각은 같았다. 전체 시나리오 해시는 보조값 때문에 달라진다.
- 관련 검사 177건 중 172건 통과, 5건 실패. 새 실패는 0건이나 **전체 검사 통과는 아니다**.

## ② 해석과 남은 실패

운반차 3대가 처음에는 함께 움직일 수 있는데, 옛 식은 이미 모든 차량이 계속 바쁘게 순환하는 것처럼 계산했다.
그 결과 실제로 가능한 완료를 '물리적으로 불가능하다'고 잘못 판단할 수 있었다. 이 산술 모순을 제거했다.
새 학습이나 정책 평가를 실행한 것은 아니므로 기존 성능 수치를 새로운 실험 결과로 재발행하지 않는다.
9입력의 실행 조건 불변은 확인했지만 모든 다른 설정에서도 마감이 같다는 보장은 아니다.

기존 실패는 수정 전 코드 `06d56e71`을 별도 폴더에 꺼내 재검사해 동일하게 확인했다.

| 남은 실패 | 확인 내용 | 후속 |
|---|---|---|
| 복제 기준 기록 4건 | engine·multiblock·order_schema·time_contract의 현재 코드와 등록 해시 불일치 | YR-332-be: 변경 이력과 승인된 범위를 대조 |
| 월 단위 재고 검사 1건 | 하루 말 총재고 20,148개에서 최저 9,544개로 내려가, 첫날 절반을 유지하는 기존 조건 미달 | YR-332-bf: 물량 수지와 검사 전제 진단 |

이번에 바꾼 scenario_gen의 해시는 변경 근거를 붙여 갱신했다. 다른 4개 해시를 통과 목적으로 덮어쓰지 않았다.
월 재고 실패만으로 재고가 음수이거나 실제 오더 누락이 발생했다고 단정하지 않는다.
수정 전 비교의 첫 준비 실행은 설정 파일 누락으로 실패했고, 설정을 포함한 재실행 결과를 최종 근거로 삼았다.
두 기록을 모두 보존했다.

현재 운반 3대·470초는 그대로이며 실제 투입·인계·귀환 자료로 확인된 값이 아니다.
본선 시각의 사건 단계, 실제 작업 시작, 대기 집계 정의와 고물량 자료의 미확정도 남아 있다.
이번 하한 검증 통과가 환경 전체의 현실성 통과나 정책 채택을 뜻하지 않는다.
공통 판정은 성능 미통과 유지, 코드 변경 근거 4건의 미정리로 신뢰성 미통과, 운반 실측·월 재고가 남아 현실성 미통과다.
이번 결과·작업 목록의 일치 검사는 별도로 기록하며, 그것만 통과했다고 저장소 전체 신뢰성 통과로 읽지 않는다.
