# 초기 반출 공급 보존과 하루 곡선 민감도

2026-11-16. YR-332-at(반출 공급 보존) 완료. 뒤이은 ao(하루 곡선)의 고정 규칙 54회 결과는
[곡선 민감도 보고서](shape-sensitivity.md)에 따로 기록했다.

## ① 진행사항

- v7 하루 생성기의 재고 부족 때 반출을 반입으로 바꾸는 처리를 기본 경로에서 제거했다.
- 당일 작업 대상이 아닌 상자를 부족한 블록의 **초기 재고**로 배치한다. 실행 중 무료 운송이 아니다.
  배치할 수 없으면 원본을 바꾸지 않고 명시적으로 실패한다. 과거 재현에는 `initial_stock_mode='legacy'`를 쓴다.
- 기존 배경 41개 + 새 배경 20개 × 물량 3단계, **183개 입력**을 검사했다.
  11개에서 생기던 **1,288건 전환 → 0건**. 기존 실패에서 734건, 새 배경에서 554건이었다.
- 원래 정상 입력 **172개**는 명단·초기 상태가 정확히 같다. 반복 생성도 동일하다.
- 전체 상자 수 **19,656개**, 규격별 수·본선 계획·기존 작업 대상과 위치를 보존했다.
  바뀐 입력의 블록 재고는 **904~1,065개**다. 종전에는 블록당 936개였다.
- 단위·회귀 검사 **82건 통과**: 초기 재고·하루 곡선·수요·방문 연결·접수 42건,
  컨테이너 계약·본선 40건. 초기 재고 5건은 42건에 포함되며 중복 합산하지 않았다.
- 하루 실행 4회도 원자료와 대조했다. 정상 3,500건 입력의 legacy/preserve는
  후보·선택·사건·작업·기록·결과 해시 6종과 원자료가 모두 같다.
- 원래 36개 배경 시드를 그대로 쓰는 [새 은행](bank-stock-preserved.json)을 저장했다.
  기존 조건부 은행과 거절 기록은 덮어쓰지 않았다.

|---|---|---:|---:|---:|

| 부족했던 15,000건, 수정 후 | 작업 대기에 들어온 순서 | 186.087분 | 3,824 | 2,762 |

평균은 미완료 오더도 24시간 경계까지 기다린 시간을 포함한다. 최종 완주 평균이 아니며,
고물량 실행이 끝났다는 것은 모든 작업이 끝났다는 뜻이 아니다. 작업 종류가 다른 과거 팔과 개선율을 계산하지 않는다.

## ② 해석

고쳐진 것은 **요청과 재고의 일치**다. 정상 입력이나 정책을 유리하게 바꾸는 수정은 아니다.
그러나 보정된 11개 입력에서는 방해 상자 수·블록 장치율·방문 묶음이 달라질 수 있다.
새 대상이 상단 쪽에 배치되는 효과도 있으므로, 이 실험만으로 실제 초기 적재의 현실성을 주장하지 않는다.

- 내부 공급 보존: 검사한 183개 입력에서 통과. 모든 부하·배경의 생성 성공을 보장하지 않는다.
- 기록 신뢰성: 고정 코드·사전등록·시드·해시, 원자료 재계산·정상 실행 동등성을 확인했다.
  Dashboard와 원격 증거의 최종 대조는 `current-gates.json`에 기록한다.
- 현실성 전체: 운반·대기열·초기 적재 외부 근거와 지속 운영 판정이 남아 미통과다.
- 학습 성능: 이번에 새 정책이나 학습을 실행하지 않았다. 이전 모델의 규칙 대비 열세를 뒤집는 결과가 아니다.
- 7,500·15,000건은 부담 시험이다. 실제 터미널 총물량으로 검증된 값이 아니다.

## ③ 다음 순서

ao의 곡선 민감도는 54회 실행·원자료 검산을 마쳤고, 반출 비율 변동은 별도 축으로 남는다.
ar(분별 실제 형판을 수식으로 대체)은 완전한 수식 기반 합성 입력을 위해 필요하다.
323-d(학습 표본·갱신·망각 진단)는 저장 모델 재집계를 했으며 새 학습 비교는 별도 작업이다.
