# YR-150 0단계 — N블록 엔진 계약 검사(N=3): ★전 항 통과

> **범위 한정**: 이 단계는 **엔진 계약 검사 전용**이다. 성능 비교·정책 학습·21블록 본시험을
> 하지 않았고, **여기 나오는 어떤 수치도 "비용이 줄었다"는 근거가 아니다.**
> 이 통과만으로 현실성(scenario_validity) 게이트가 닫히지 않는다 — 그 판정은 1단계
> **21블록 지속 유입 자격 파일럿**에서만 한다.
> 게이트 인가: `authorize-next` → `allowed=true` (REMEDIATION · target=`scenario_validity`).

- 실행: 구현 동결 커밋 `5be10ad`(**깨끗한 트리 — `git_dirty=false`**).
- 대상: 21블록 배치의 **양 끝과 중앙**인 `Y01·Y11·Y21` 3블록, 블록당 4시간 유입 50대.
  인접 3블록을 쓰면 주행 차이가 최소가 되어 "목적지가 달라도 사실상 같다"는 구판 상태를
  그대로 재현하게 되므로 일부러 멀리 떨어진 셋을 골랐다.
- 산출물: `contract_n3.json` (+ 해시 sidecar `contract_n3.json.sha256`).

## 무엇이 문제였고 무엇을 고쳤나

0A 가 남긴 발견 ②는 **"현 모형에는 블록별 게이트 거리 차이가 없다"** 였다. 게이트→블록
주행을 계산하는 함수가 **목적지를 인자로 받지 않았고**(`travel_fn(src, job)`), 블록 간 우회는
상수 180초였다. 그래서 어느 블록으로 보내든 주행 대가가 똑같았다 — 즉 **"가까운 블록으로
보내면 이득"이라는 축이 모형에서 구조적으로 사라져 있었다.**

이번에 단일 야드축 위에 21블록을 등간격으로 놓은 **합성 배치**를 도입했다. 게이트는 축의
한쪽 끝에 있고, 게이트에서 각 블록까지의 거리가 다르다.

**기존 보정을 건드리지 않았다는 점이 중요하다.** 게이트 오프셋은 자유롭게 고른 값이 아니라
**전 21블록 평균 게이트주행이 기존 계약 중심값 300초가 되도록 결정**된다. 실측 평균 300.0초,
블록별 범위 190~410초로 기존 지원범위 180~420초 안에 있다. 벗어나면 조용히 자르지 않고
예외를 던진다. 즉 **평균은 그대로 두고 블록 간 차이만 새로 생겼다.**

## 계약 9종 (전 항 통과)

| 계약 | 내용 | 결과 |
|---|---|---|
| N1 | 주행 matrix 가 **비영**·대각 0·대칭·삼각부등식, 앵커(평균 300초·범위 180~420초) 보존 | ✅ |
| N2 | 수신 후보가 둘일 때 **부담+주행이 최소인 목적지**를 고르고 후보 전량을 원장에 남김 | ✅ |
| N3 | 한 epoch 에 **여러 소스가 동시에** 확정될 수 있음(2블록 터미널 1건 상한이 아님) | ✅ |
| N4 | 소스당 1건·작업당 이송 1회 상한 유지 | ✅ |
| N5 | 수신 블록 용량 부족이면 **엔진이 거절**(fail-closed) | ✅ |
| N6 | rollback 완전 복원 + 닫힌 트랜잭션 재commit 거절 | ✅ |
| N7 | 결정론 — 같은 입력 2회 실행의 견적 원장 지문·주행비용 동일 | ✅ |
| N8 | 소유권 정확히 1·최초배정 이력 보존·A→O 장부 등록 수 보존 | ✅ |
| N9 | **게이트 진입 전 재배정의 주행 차이가 더 이상 0 이 아님**(0A 발견 ② 해소) | ✅ |

### 검사가 실제로 발화했는가 (빈 통과 방지)

| 항목 | 실측 |
|---|---|
| 견적 결정 수 / 그중 후보가 2개였던 수 | 69 / 69 |
| 그중 두 후보의 **주행이 서로 달랐던** 결정 | **40건** |
| 원장에 남은 목적지별 주행값 | 110초·220초 (구판은 전부 180초 상수) |
| 최소(부담+주행) 목적지를 골랐는가 | 69/69 일치 |
| 한 epoch 에 두 소스가 동시 확정된 epoch | **2건** (`t=0` Y11·Y21, `t=6226.8` Y01·Y21) |
| 결정론 2회 실행 | 원장 지문·주행비용 완전 동일 |

N3 는 자연 시나리오에서 두 블록의 게이트 진입 시각이 정확히 겹치는 일이 사실상 없으므로,
**계약 검사 전용으로 진입 시각을 맞춘 상태**를 만들어 동시 확정 경로를 발화시켰다. 경로
도달 여부만 보며 이때 쓴 발의 임계값은 성능 판정에 쓰지 않는다.

## 게이트 진입 전 재배정의 주행 차이 (N9)

| 이동 | 주행 차이 |
|---|---|
| Y01 → Y11 | +110초 |
| Y01 → Y21 | +220초 |
| Y11 → Y01 | −110초 |
| Y21 → Y01 | −220초 |

**음수가 나온다는 것이 핵심이다.** 트럭이 아직 게이트에 있을 때 더 가까운 블록으로 목적지를
바꾸면 주행이 실제로 **줄어든다**. 0A 에서는 이 값이 전부 0 이라 이 이득이 존재할 수 없었다.

## 골든 보존

기존 2블록 실험(YR-133·YR-149 계열)은 **목적지를 의도적으로 무시하는** 주행 함수를 주입해
난수 키까지 구판 그대로 두었고, 터미널 전체 epoch당 1건 상한도 구판과 **완전히 같게**
남겼다 — 첫 제안이 실패해도 다음 제안을 대신 올리지 않는 동작까지 테스트로 잠갔다.

전체 회귀 **742 통과 / 1 실패**이며, 그 1건은 이미 board 에 등록된 기존 실패
(YR-111 `test_update_regresses_toward_residual_target`, −2.22 vs 목표 −2.5±0.15)로
수치까지 이전과 동일하다. 이번 변경으로 깨진 것은 없다.

## 남은 한계 (정직 기록)

1. **배치는 합성이다.** 블록 좌표·도로망 공개자료가 없어 단일 축 등간격을 가정했다.
   21이라는 숫자만 공개 규모에서 빌렸을 뿐 실제 터미널 배치의 재현이 아니다.
   주행 차이의 **크기**는 이 가정에 딸린 값이므로 성능 해석 시 반드시 함께 밝혀야 한다.
2. **게이트 진입 후 재배정의 우회비용**은 "원 블록까지 간 뒤 이동"이라는 **가장 불리한
   경우**로 잡았다. 실제 전환 시점을 모르므로 상한을 쓴 것이며, 구판 상수 180초를 대신한다.
3. **N=3 은 본 환경이 아니다.** 1단계에서 하나의 터미널 유입 흐름을 배분벡터로 21블록에
   나누고, 관측시간 종료·구간 스냅샷 계약까지 갖춰야 현실성 판정을 시작할 수 있다.
4. 이 단계는 **현실성 게이트를 닫지 않는다.** 현재 3대 게이트는 성능 미확정 · 신뢰성 통과 ·
   현실성 **미확정** 그대로다.
