# YR-332-ba — 원본 진입 시각이 확인되는 자료로 보정 분리

## ① 진행사항

**예약·통지 보정에서 근거가 없는 진입 시각을 분리했고, 새 파일의 입력 적용을 검증했다.**
미확인 시각 **601건**은 원본을 그대로 보존한 별도 비공개 파일로 옮겨 집계했다.
그중 기존 보정에 들어가던 344건을 제외해 보정 표본은20,936→20,592건이다.
새 보정은 [profile-confirmed.json](profile-confirmed.json), 기존 보정 파일은 변경하지 않았다.

‘확인’은 같은 컨테이너·차량·방향·시각을 원본 GateIn(게이트 진입) 요청의 명시 시각과 연결했다는 뜻이다.
원본에 시각이 없는데 서버 로그가 찍힌 시각으로 대신 채운 경우는 사용하지 않는다.
다른 메시지에서 같은 명시 시각이 확인된2건은 남겼다. 오류 표시만으로 포함·제외하지 않았다.
확인된 진입 오더33,703건, 미확인601건, 애초에 진입 시각이 비어 있는1,831건으로 구분한다.

|---|---:|---:|---:|---:|---:|

예약 오차는 **실제 진입으로 기록된 시각 − 공개 예약 시각**이다. 게이트 진입 후 작업 완료까지 걸리는 시간이 아니다.
보정 중앙값 변화는 반입+2초·반출+27.5초다. 보정 날짜10/28~11/05와 분포 확인 날짜11/06~09는 유지했다.
통지부터 진입까지의 중앙값도 반입3,713.5→3,727초, 반출1,339→1,351초로 바뀌었다.
전체 빈도와 긴 꼬리, 예약보다 일찍 온 음수 오차를 그대로 보존했다. [전수 비교](calibration-comparison.json)

수요에 미치는 영향도 별도로 계산했다.

- 진입 오더 기록34,304→33,703건. 전체 반출 비율은0.09777%p 감소, 시간대별 구성비의 최대 변화는0.06523%p다.
- 기존30분 방문 묶기 규칙으로 다시 계산하면27,415→27,395번이다. 중복 묶기 전 행을 제외했으므로601을 방문 수에서 바로 빼면 안 된다.
- 분별 방문 수가 바뀐 칸은22개다. 분 단위 몰림 지표는1.265651→1.266236으로 바뀌었다(1은 무작위 도착 수준).
- 블록이 확인되고 용량 조건을 만족하는 방문 패턴은26,501→26,502개다. 단독 반출 패턴1개 증가 외 패턴별 횟수는 같다.
- 새 분별 방문 템플릿과 방문 패턴은 **후속 보정 후보**로 저장했다. 이번 합성 입력의 도착곡선·분별 강도·방문 패턴에는 적용하지 않았다.

검증 결과:

- 관련 시험 **32개** 통과: 원본 시각 연결·오류 표시·예약 통지·날짜 분리·기존 정보 계약을 검사했다.
- 합성 입력 **18개**와 반복 생성 **2개** 통과. 3개 기존 곡선×3,500/7,500/15,000건×이전/새 보정이다.
- 본 비교의 합성 오더156,000건, 반복 생성7,000건이다. 실제 시뮬레이터의 오더 접수 변환까지 확인했다.
- 쌍별 실제 도착·작업량·방문 연결·블록·컨테이너·초기 야드·본선 계획은 동일했다.
  변경은 예약시각·통지 리드·예상시각 보정값3개 필드에 한정됐다.
- 원본600파일 불변, 기존 보정·도착 템플릿·방문 패턴 재구성 일치. 새 핵심 산출물7개는 재실행 시 바이트까지 일치했다.
- 원본을 다른 코드로 읽어 표본을 다시 고른 뒤 **기존 보정 코드**로 재계산해도 새 빈도표와 날짜별 표본 수가 같았다.

## ② 해석

이번 수정은 **입력 시각의 근거를 바로잡는 일**이다. 중앙값이나 방문 수의 변화가 작다는 사실만으로 학습 영향도 작다고 판단하지 않는다.
확인된 표본만 써도 자료에 있던 긴 예약 오차가 남으며, 이 작업에서 임의로 잘라내지 않았다.
명시 시각이 있다는 것이 센서로 실제 진입을 입증했다는 뜻은 아니다. 오류 응답의 운영상 의미도 아직 자료 제공처 확인이 필요하다.

- **기록 정합**: 새 표본·집계·입력 경로·재현 검사 통과. 최종 Dashboard·원격 증거도 공통 검사로 대조한다.
- **현실성**: 전체 통과가 아니다. 대기 수 정의·내부 운반 흐름이 남았고, 이번에는 실행 중 크레인 안전·완료 장부를 새로 측정하지 않았다.
- **성능**: 새 정책 평가·재학습을 하지 않았으므로 판단 보류. 기존 모델의 개선율을 갱신하지 않는다.

새 보정은 [입력 묶음](input-bundle.json)의 `information_profile`로 명시해서 사용한다.
기존 실험은 기존 경로를 유지한다. 새 예약 보정과 아직 이전 표본을 쓰는 물리 수요 보정을 혼동하지 않아야 한다.

## ③ 예정사항

- **YR-332-bb(수요 보정에도 확인된 진입 시각 적용)**: 날짜별 곡선·분별 몰림·방문 연결의 보정 출처를 같은 기준으로 맞춘다.
  이번에 세 의존 자료의 변화가 확인됐으므로, 적용 순서와 전후 입력 검사를 고정해 한 축씩 연결한다. 재학습은 범위 밖이다.
- **YR-332-f(대기 수 정의 확인)**: 무엇을 세는 값인지와 작업 시작 기록을 확인한다. 모형과 실제 자료가 같은 대기열을 세게 하기 위해 필요하다.
- **YR-332-i(운반 흐름 확인)**: 본선 시각이 나타내는 단계와 차량별 적재·인계·귀환을 확인한다. 근거 없는 운반 대수·시간 교체를 막는다.
