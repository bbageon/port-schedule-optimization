# v6 적정부하 보상 학습·독립 평가 결과

2026-09-27 · YR-331-b(기존 보상에 부하 변화 신호를 더하는 비교)

**학습과 평가는 완료했지만, 이번 조건에서는 새 보상을 채택할 근거를 얻지 못했다.**
기존 보상보다 비용이 줄어든 경우는 세 쌍 중 한 쌍이고, 그 경우에도 남은 본선 작업이 늘었다.
기본 보상 설정은 유지한다. 아래 금액은 시뮬레이터의 원화 환산 비용이며 실제 항만 회계비용이 아니다.

## ① 진행사항

### 같은 조건에서 보상만 바꿔 학습

- 한 터미널, 21블록·42크레인의 CPU v6 경로에서 기존 보상 3개·새 보상 3개 모델을 학습했다.
- 각 세계를 5일 연속 진행하고 가운데 3일만 학습했다. 하루 입력은 3,500→5,000→7,500→12,500→3,500건이다.
- 모델마다 경험 수집·갱신 72회, 총 432회를 완료했다. 가중치가 실제로 바뀌었고 실행 실패·주문 누락은 없었다.
- 같은 쌍의 초기 가중치·주문·행동 난수·학습 설정이 일치함을 [대조 검사](paired-controls.json)로 확인했다.
- 학습 시드(입력과 난수를 다시 만들기 위한 번호)는 9931000·9941000·9951000이다.
- 새 보상은 기존 비용 보상에 부하 점수의 할인 차분만 더했다. 보조 세기 1, 부하 관측 기간 15분을 미리 고정했다.
- 상태 정보·행동 후보·비용 단가·신경망 구조·세계 엔진은 비교 중 변경하지 않았다.

학습 후에는 가중치를 고정하고 새 주문 세 묶음으로 평가했다. 평가 시드는 순서대로 9961000·9971000·9981000이다.
각 평가는 3,500→7,500→3,500건의 3일 입력을 받고, **가운데 날의 24시간(86,400–172,800초)**을 비용 측정 구간으로 썼다.
이후 3일 끝+2시간(266,400초)까지 처리해 측정일 주문의 완료 여부를 확인했다. 두 학습 정책 모두 행동을 확률로 선택했다.
각 주문 묶음에서 KEEP+SF-SPT(재배정 없이, 실제 작업을 우선하고 그중 짧은 작업부터 처리하는 규칙)도 평가했다.

새 보상에서 구매 수락이 일관되게 늘지도 않았다.

## ② 해석과 한계

### 비용 감소만 보고 성공으로 부르지 않은 이유

세 쌍의 평균 감소율은 **1.05%**지만, 표본이 세 쌍뿐이고 방향도 섞였다.
짝별 감소율의 표본 표준편차로 계산한 서술용 95% 구간은 **−9.49%~+11.60%**다.
즉 이번 표본으로 일관된 개선을 확정할 수 없다. 사후에 학습량·시드·보조 세기를 바꿔 유리한 결과를 고르지 않았다.

게이트 진입을 늦춰 비용이 작게 보이는지 확인하려고, 최초 예약 게이트 시점부터 출문까지 같은 시간비용식으로도 계산했다.
통지 시점은 정상적인 사전 통지까지 지연으로 셀 수 있으므로 비용 원점으로 사용하지 않았다.

원래 예약 기준으로도 둘째는 악화하고 셋째는 개선한다. 셋째의 본선 잔여 증가 때문에 최종 보호 조건은 여전히 미통과다.
이 표는 비용 정의에 따른 민감도 확인이며, 재예약 시간이 모두 실제 기사 유휴나 청구금액이라는 주장은 아니다.
학습 보상의 원래 비용 정의를 동시에 바꾸지는 않았다.

### 적정 수용 상한은 아직 확정하지 못함

별도 기준 규칙 실행에서 유효 작업 26,962건의 서비스시간을 측정했다.
평균은 반입 152.42초, 반출 326.42초, 본선 양하 133.52초, 적하 214.58초였다.
평균 큐 대기 5분을 허용한다는 가정과 단일 크레인 대기행렬 근사식으로 얻은 **67.02%는 이번 진단의 잠정 값**이다.
모든 크레인의 최적 가동률, 권장 혼잡도, 보장되는 안전 수용량으로 해석하면 안 된다.

독립 보정 시드 9921000은 Y08의 컨테이너 원천 971개보다 반출 요구 976개가 많아 세계 생성 전에 거부됐다.
주문을 지우거나 없는 컨테이너를 추가하거나 다른 시드로 바꾸지 않았다.
학습·평가의 고정 입력 여섯 묶음은 검사를 통과했지만, 독립 상한 검증은 미완료다. [보정 감사](calibration-audit.json)

### 기록과 코드 검증

- 관련 시험 **64개 통과**: 보조 항을 껐을 때 기존 실행과 동등함, 미래 정보 차단, 작업량 중복 방지, 종료·수집 경계 등을 확인했다. [시험 로그](pytest.txt)
- 여섯 학습 평가와 마지막 규칙 평가의 트럭 사건 101,500행을 다시 계산했다. 기록과의 최대 비용 차이는 약 0.00000012원, 사건 순서 오류는 0건이다. [사건 감사](event-audit.json)
- 초기 규칙 평가 두 개에는 트럭별 사건 내보내기가 없어 이 검사를 소급 통과시켜 표시하지 않았다. 집계 보고·완료 작업 기록은 보존했다.
- 학습은 `e5bd8e24`, 여섯 학습 모델 평가와 마지막 규칙 평가는 사건 저장을 추가한 `db493e43`의 변경 없는 소스로 실행했다. 최초 두 규칙은 `e5bd8e24`다.
- 다섯 평가는 마지막 학습일의 `day_04.pt`로 먼저 시작했다. 평가에 쓴 여섯 모델 모두 실행 종료 `policy-final.pt`와 가중치가 정확히 같았다. 좋은 중간 모델을 고른 것이 아니다. [가중치 감사](checkpoint-audit.json)
- 실행 실패가 없는 것과 정책 성능이 좋은 것은 다르다. 3일 학습·3개 새 입력의 CPU 진단이며 30일 확증, GPU 학습, 실제 부산항 성능 검증은 아니다.

기록 정합·성능·현실성의 공식 검사 결과는 [gates.json](gates.json)에서 확인한다.
성능 보호 조건은 미통과이며, 외부 운영 자료와 독립 수용 상한 검증 등 현실성 증거가 남아 있다.
