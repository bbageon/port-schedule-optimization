# 월 중간 공급과 재고 검사 — 2026-11-21

**기존 14개 부족 구간 모두에서 자정에 기다릴 반출과 그 화물의 후속 공급을 찾았다.**
고정 화물 실행기는 상자가 실제로 적치될 때까지 반출을 기다린다. 이번 결과는 합성 명단에서 그 대기가 생기는 시점과 규모다.

## 진행사항

시드(입력을 재현하는 난수 시작값) 9,400,777에서 트럭 오더 176,500건과 본선 작업 묶음 288개를 복원했다.
수정 전후 초기 재고, 작업 종류·물량·배정, 시간, 화물 번호, 공개 오더까지 전체 입력 지문이 같았다.
생성·저장·복원 시 공통으로 쓰는 고정 화물 검사에 실제 초기 슬롯과 시각별 검사를 연결했다.
초기 슬롯 중복·공중 적재·범위 초과, 역전된 이동 시각, 투입 전 본선 시작을 걸러낸다.

| 확인한 항목 | 수량 |
|---|---:|
| 독립 검산한 블록·날짜 조합 | 630 |
| 자정에 공급이 밀린 기존 부족 구간 | 14 |
| 요청보다 지정 화물 공급이 늦은 반출 | 2,034 |
| 14개 자정에 걸쳐 기다린 서로 다른 반출 | 1,047 |
| 시각별 계산에서 블록 용량을 넘긴 구간 | 0 |

21개 블록의 30일을 검사했다. 159,129개 공급과 149,053개 출고 요청을 화물 번호로 연결했다.
공급이 늦은 반출 중 1,409건은 뒤이은 트럭 반입에, 625건은 본선 양하에 연결됐다.
요청과 공급의 예정 시각 차이는 가장 긴 건이 23시간 58분 55초였다. 실제 대기시간은 작업 완료 기록이 있어야 잴 수 있다.

## 해석

- **계획 날짜와 작업 시각.** 본선은 투입 날짜와 각 작업 시각을 따로 읽었다. 이 입력에서 자정을 넘긴 본선 작업 하한은 0건이다.
  반면 트럭은 반입 105건·반출 138건의 블록 도착이 다음 날이었다. 마지막 자정 뒤에는 반입 2건·반출 3건이 있다.
- **가장 큰 부족.** 10일차 20번 블록은 날짜 기준으로 209개 부족하다. 반입 1건의 블록 도착이 자정을 지나 시각 기준 부족은 210개다.
  지정 화물 210개를 실제 공급 전에 꺼내지 않는 계산에서는 자정 재고 0개와 대기 210건이 된다.
  같은 등식이 다른 13개 구간에서도 성립한다. 하루 중 잠시라도 요청이 공급을 앞지른 조합은 19개다.
- **공간.** 들어온 화물을 가장 이른 시각에 적치하고 공급·수요가 모두 도착하면 즉시 꺼내는 단순 계산에서 최고는 1,411/1,440개(97.99%)였다.
  적치·재취급·반출에는 시간이 걸리고 같은 규격을 쌓을 자리가 필요하다. 실제 혼잡이나 양하 정지는 별도 실행에서 확인해야 한다.
- **기존 경보.** 90%는 과거 실험에서 약 92% 점유 때 양하가 막혀 여유 공간을 보려던 기준이다.
  50%는 본선 보충 부족으로 야드가 계속 비는지 보는 회귀 기준이다. 분모는 첫날 말 재고이며 현장 실측 하한 근거는 확인되지 않았다.
  최저 9,622개는 첫날 말 20,226개의 47.57%다. 월말 10,076개도 절반(10,113개)에 못 미친다. 기존 경보를 그대로 기록했다.
- **검사 결과.** 관련 검사 176개 중 174개 통과. 실패는 위 월 재고 경보와 이미 등록된 Windows 구형 생성 명령의 환경 정보 읽기 오류(YR-332-ae)다.
  화물 대기·실제 출고 후 빈 슬롯 재사용은 작은 실행 시험으로 확인했다. 고정 월 전체의 물리 완주나 정책 비용은 이번에 측정하지 않았다.
